Lua Produtor e Consumidor

Muitos programas têm duas partes que trabalham em dupla: uma que produz dados (lê um arquivo, recebe o que a pessoa digita, gera números) e outra que consome esses dados (mostra na tela, soma, grava). O problema clássico é: quem manda em quem? Na aula anterior, Corrotinas, você aprendeu a pausar e continuar uma função. Nesta aula, você vai usar isso para resolver esse problema de um jeito elegante: o produtor e o consumidor escritos cada um como um laço simples, conversando por yield e resume.

Você vai aprender
  • O que é o padrão produtor/consumidor e por que ele é difícil de escrever sem corrotinas.
  • Como fazer um produtor que entrega um item por vez com coroutine.yield, e um consumidor que pede com coroutine.resume.
  • As funções de apoio receber e enviar, que deixam o código fácil de ler.
  • Como pôr um filtro no meio, montando uma linha de produção.
  • O erro mais traiçoeiro desse padrão, e como evitá-lo.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), na pasta pessoal dela, com lua arquivo.lua. Leia antes a aula Corrotinas.

A ideia: o padeiro e o balconista

Na padaria, o padeiro faz pães lá no fundo, e o balconista entrega aos clientes. Os dois trabalham num ritmo próprio, e cada um tem a sua rotina, que é um laço:

  • Padeiro: "enquanto houver massa: faço um pão, ponho na janelinha".
  • Balconista: "enquanto houver cliente: pego um pão na janelinha, entrego".

Num programa comum, uma função tem de chamar a outra, e só uma delas pode ter o laço. Ou o padeiro chama o balconista a cada pão ("toma, entrega este"), ou o balconista chama o padeiro a cada cliente ("me dá um pão"). Quem é chamado perde a sua rotina e vira um pedaço da rotina do outro.

Com uma corrotina, os dois mantêm o seu laço. O padeiro vira uma corrotina: ele faz um pão e pausa (yield), deixando o pão na janelinha. O balconista, quando precisa de um pão, retoma o padeiro (resume), que continua de onde estava e faz o próximo.

1. O primeiro produtor: pedidos de um arquivo

A Ana tem um arquivo com os pedidos do dia, pedidos.txt:

3 pães
1 bolo
2 cafés

O produtor lê o arquivo e entrega um pedido por vez. O consumidor numera e mostra cada um:

local function produtor()
  return coroutine.create(function ()
    for linha in io.lines("pedidos.txt") do
      coroutine.yield(linha)
    end
  end)
end
local function receber(prod)
  local ok, valor = coroutine.resume(prod)
  return valor
end
local function consumidor(prod)
  local n = 0
  while true do
    local pedido = receber(prod)
    if pedido == nil then break end
    n = n + 1
    print("Pedido " .. n .. ": " .. pedido)
  end
  print("Total de pedidos: " .. n)
end
consumidor(produtor())
produtor()
Cria e devolve a corrotina do padeiro. O corpo é um laço comum, for linha in io.lines(…) (aula io.lines), com um yield dentro: a cada linha lida, ele entrega a linha e pausa.
receber(prod)
"Me dá o próximo": retoma o produtor e devolve o que ele entregou no yield. Quando o produtor termina o laço e o corpo acaba, o resume devolve só true, sem valor, e receber devolve nil.
consumidor(prod)
O balconista, também com o seu laço: pede, e se veio nil é porque acabou; senão, numera e mostra.
consumidor(produtor())
Liga os dois: cria o produtor e o entrega ao consumidor.
$ lua pc1.lua
Pedido 1: 3 pães
Pedido 2: 1 bolo
Pedido 3: 2 cafés
Total de pedidos: 3

Repare: o produtor nunca leu o arquivo inteiro de uma vez. Ele leu a linha 1, pausou; o consumidor mostrou; o produtor leu a linha 2, pausou… Se o arquivo tivesse um milhão de pedidos, só um estaria na memória por vez. E nenhum dos dois sabe como o outro funciona: o consumidor só sabe "pedir o próximo"; o produtor só sabe "entregar o próximo".

2. O produtor pode ler o teclado

Trocar de onde vêm os dados é trocar só o produtor. Este lê o que a pessoa digita, até acabar a entrada (io.read() devolve nil; veja io.read):

local function produtor()
  return coroutine.create(function ()
    while true do
      local linha = io.read()
      if linha == nil then break end
      coroutine.yield(linha)
    end
  end)
end
local function receber(prod)
  local ok, valor = coroutine.resume(prod)
  return valor
end
local prod = produtor()
while true do
  local item = receber(prod)
  if item == nil then break end
  print("- " .. string.upper(item))
end

3. A linha de montagem: um filtro no meio

Agora o mais bonito: um filtro é, ao mesmo tempo, consumidor (do produtor) e produtor (para o consumidor). Ele recebe de um lado, decide, e envia para o outro. É uma esteira de fábrica: o padeiro põe os pães, o fiscal tira os que não servem, o balconista entrega os que sobraram.

local function receber(prod)
  local ok, valor = coroutine.resume(prod)
  return valor
end
local function enviar(valor)
  coroutine.yield(valor)
end
local function produtor(lista)
  return coroutine.create(function ()
    for _, item in ipairs(lista) do
      enviar(item)
    end
  end)
end
local function filtro(prod, minimo)
  return coroutine.create(function ()
    while true do
      local p = receber(prod)
      if p == nil then break end
      if p.preco >= minimo then
        enviar(p.nome .. " (R$ " .. p.preco .. ")")
      end
    end
  end)
end
local function consumidor(prod)
  while true do
    local texto = receber(prod)
    if texto == nil then break end
    print(texto)
  end
end
local vendas = {
  { nome = "pão", preco = 1 },
  { nome = "bolo", preco = 25 },
  { nome = "café", preco = 6 },
  { nome = "torta", preco = 40 },
}
consumidor(filtro(produtor(vendas), 10))

$ lua pc3.lua
bolo (R$ 25)
torta (R$ 40)
enviar(valor)
Só um nome mais claro para coroutine.yield(valor): "ponha na esteira". Junto com receber, deixa o código parecido com a frase em português.
filtro(prod, minimo)
Uma corrotina que recebe do produtor e envia só as vendas de minimo reais ou mais, já transformadas em texto.
consumidor(filtro(produtor(vendas), 10))
Lê de dentro para fora: o produtor alimenta o filtro, que alimenta o consumidor. É o consumidor que puxa tudo: cada receber dele retoma o filtro, que retoma o produtor quantas vezes precisar até achar uma venda que passe.

Para pôr mais uma etapa (por exemplo, numerar as linhas), basta escrever outra corrotina no mesmo formato e encaixá-la: consumidor(numerar(filtro(produtor(vendas), 10))). Nenhuma das outras partes muda.

4. Ao contrário: o produtor manda

Nos exemplos acima, quem manda é o consumidor: ele pede, e o produtor entrega. Dá para inverter: o consumidor vira a corrotina, e o produtor o retoma a cada item, mandando o item no resume:

local function consumidor()
  return coroutine.create(function (primeiro)
    local item = primeiro
    while item do
      print("embalando " .. item)
      item = coroutine.yield()
    end
    print("caixa fechada")
  end)
end
local function produtor(cons)
  for _, pao in ipairs({ "francês", "doce", "de queijo" }) do
    coroutine.resume(cons, pao)
  end
  coroutine.resume(cons, nil)
end
produtor(consumidor())

$ lua pc7.lua
embalando francês
embalando doce
embalando de queijo
caixa fechada

O primeiro resume entrega "francês" como parâmetro do corpo (primeiro); os seguintes entregam o pão como resultado do yield (veja a seção 2 da aula Corrotinas). O resume(cons, nil) do fim avisa "acabou", e o consumidor fecha a caixa. As duas direções funcionam; a mais comum é a da seção 1, em que o consumidor puxa.

Formas diferentes de fazer a mesma coisa

O mesmo programa da seção 1 sem corrotina nenhuma: o produtor recebe uma função e a chama para cada pedido (uma "função de retorno", em inglês callback):

local function produtor(entregar)
  for linha in io.lines("pedidos.txt") do
    entregar(linha)
  end
end
local n = 0
produtor(function (pedido)
  n = n + 1
  print("Pedido " .. n .. ": " .. pedido)
end)
print("Total de pedidos: " .. n)

$ lua pc8.lua
Pedido 1: 3 pães
Pedido 2: 1 bolo
Pedido 3: 2 cafés
Total de pedidos: 3

Mais curto, e funciona. Mas aqui quem manda é o produtor: o consumidor perdeu o seu laço e virou um pedaço de código chamado de fora. Se o consumidor precisasse de dois produtores ao mesmo tempo (juntar os pedidos de duas lojas, um de cada vez), ou parar no meio e voltar depois, ficaria difícil. Com corrotinas, cada um continua com o seu laço.

SituaçãoQual usar
Um produtor simples, e o consumidor só precisa "fazer algo com cada item"Função de retorno (callback)
O consumidor tem a sua própria lógica de laço (pedir quando quiser, parar no meio, misturar fontes)Produtor como corrotina, consumidor puxando com receber
Várias etapas em sequência (ler, filtrar, transformar, mostrar)Uma corrotina por etapa, encaixadas como esteira
Escrever o produtor com menos códigocoroutine.wrap (próxima aula: coroutine.wrap e Geradores)

Quando dá errado

O produtor deu erro, e o erro virou "pedido"

Este é o erro mais traiçoeiro do padrão. O receber da seção 1 ignora o primeiro valor do resume (o ok). Veja o que acontece se o produtor tiver um defeito no segundo pedido:

local function produtor()
  return coroutine.create(function ()
    coroutine.yield("3 pães")
    local x = nil
    coroutine.yield(x.nome)
    coroutine.yield("2 cafés")
  end)
end
local function receber(prod)
  local ok, valor = coroutine.resume(prod)
  return valor
end
local prod = produtor()
while true do
  local pedido = receber(prod)
  if pedido == nil then break end
  print("Pedido: " .. pedido)
end
print("acabaram os pedidos?")

$ lua pc4.lua | head -4
Pedido: 3 pães
Pedido: pc4.lua:5: attempt to index a nil value (local 'x')
Pedido: cannot resume dead coroutine
Pedido: cannot resume dead coroutine

O programa não para nunca (o | head -4 mostrou só as 4 primeiras linhas e encerrou; sem ele, só Ctrl+C; no editor do guia, ele é parado sozinho pelo limite de saída, com (o programa escreveu demais: …)). O que aconteceu:

  1. O produtor deu erro na linha 5 e morreu. O resume devolveu false e a mensagem de erro.
  2. O receber jogou fora o false e devolveu a mensagem, como se fosse um pedido.
  3. Daí em diante, cada resume devolve false e "cannot resume dead coroutine", que também não é nil. O laço nunca acaba.

Como consertar: o receber precisa olhar o ok e transformar a falha num erro de verdade:

local function receber(prod)
  local ok, valor = coroutine.resume(prod)
  if not ok then error("o produtor falhou: " .. valor, 2) end
  return valor
end

O consumidor não parou no fim 
local prod = coroutine.create(function ()
  coroutine.yield("3 pães")
end)
for i = 1, 4 do
  print(coroutine.resume(prod))

O produtor tinha um pedido. A 2ª chamada não trouxe pedido (true e nada: o corpo chegou ao fim), e a partir da 3ª ele já estava morto. Um consumidor que pede um número fixo de vezes, sem olhar se veio nil, recebe lixo. Como consertar: pare o laço no primeiro nil, como em todos os consumidores desta aula.

Mandou um nil no meio dos dados

O nil é o sinal de "acabou". Se o produtor tiver um item que é nil de verdade (um campo vazio, uma conta que deu nil), o consumidor vai achar que a produção acabou ali e parar antes da hora, sem erro nenhum. Se os dados podem ter buracos, envie outra coisa no lugar (false, "", uma tabela) ou use coroutine.status(prod) == "dead" para saber o fim.

Resumo

  • No padrão produtor/consumidor, uma parte gera dados e a outra os usa. Com corrotinas, as duas ficam escritas como laços simples.
  • O produtor é uma corrotina que entrega cada item com coroutine.yield; o consumidor pede o próximo com coroutine.resume (dentro de um receber).
  • Quando o corpo do produtor termina, o receber devolve nil: é o sinal de fim.
  • Um filtro recebe de um lado e envia do outro; as etapas se encaixam: consumidor(filtro(produtor(dados))).
  • Sempre confira o ok do resume: sem isso, um erro no produtor vira um "item" e o consumidor entra num laço infinito de cannot resume dead coroutine.
