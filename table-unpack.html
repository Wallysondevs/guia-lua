Lua table.unpack e table.pack

Uma lista guarda vários valores numa caixa só. Às vezes você precisa do contrário: tirar tudo da caixa e entregar os itens soltos, um ao lado do outro, para uma função ou para várias variáveis. É o que faz o table.unpack (em inglês, unpack = "desempacotar"). E o table.pack (pack = "empacotar") faz a viagem de volta: pega vários valores soltos e guarda numa tabela, anotando quantos eram.

Você vai aprender
  • A tirar os itens de uma lista com table.unpack(lista) e guardar em várias variáveis de uma vez.
  • A passar os itens de uma lista como argumentos: math.max(table.unpack(notas)).
  • A pegar só um pedaço: table.unpack(lista, 2, 4).
  • Por que o table.unpack no meio de uma lista de valores entrega um valor só.
  • A guardar valores soltos com table.pack(...) e a usar o campo n, que conta até os nil.
  • Os erros reais: o unpack do Lua 5.1, a lista que é nil, o valor que falta e o "too many results".

A ideia: a sacola de compras

A Ana chega da feira com uma sacola. A sacola é uma coisa só: dá para carregar, passar para alguém, guardar no armário. Mas para guardar as frutas na fruteira ela precisa tirar da sacola e pôr uma por uma em cima da mesa.

No dia a diaNo LuaO que sai

Juntar as frutas da mesa numa sacola e anotar quantas sãotable.pack("maçã", "pera", "uva")Uma tabela: {"maçã", "pera", "uva", n = 3}

"Vários valores soltos" é uma ideia que você já viu na atribuição múltipla (local a, b = 1, 2): o Lua sabe lidar com uma lista de valores separados por vírgula. O table.unpack transforma uma tabela nessa lista de valores.

1. Tirando os itens: table.unpack(lista)

local nomes = {"Ana", "Bia", "Caio"}
print(nomes)
print(table.unpack(nomes))
print(nomes[1], nomes[2], nomes[3])
print(nomes)
Mostra a tabela, a sacola fechada. O print não abre a tabela: mostra só table: e um endereço de memória.
table.unpack(nomes)
A função unpack da biblioteca table. Ela devolve nomes[1], nomes[2] e nomes[3], como três valores separados, e o print recebe três argumentos.
print(nomes[1], nomes[2], nomes[3])
O jeito "na mão" de fazer a mesma coisa. Com 3 itens dá para escrever; com 30, não.
$ lua desempacotar.lua
table: 0x555f97edb710
Ana	Bia	Caio
Ana	Bia	Caio

As duas últimas linhas são iguais: print(table.unpack(nomes)) é o mesmo que escrever cada item entre as vírgulas. O print separa os valores com um TAB, como sempre. O endereço 0x555f97edb710 muda a cada execução: no seu computador vai sair outro número (no editor do guia, um número mais curto, que costuma se repetir a cada Rodar).

Guardando em várias variáveis

Junto com a atribuição múltipla, o table.unpack distribui os itens nas variáveis, na ordem:

local ficha = {"Ana", 34, "Teresina"}
local nome, idade, cidade = table.unpack(ficha)
print(nome)
print(idade)
print(cidade)
local a, b = table.unpack(ficha)
print(a, b)
local x, y, z, w = table.unpack(ficha)
print(x, y, z, w)

$ lua variaveis_unpack.lua
Ana
34
Teresina
Ana	34
Ana	34	Teresina	nil
local nome, idade, cidade = table.unpack(ficha)
Três variáveis, três valores: nome recebe o 1º item, idade o 2º, cidade o 3º.
local a, b = …
Sobrou valor (vieram 3, só há 2 variáveis): o terceiro, "Teresina", é jogado fora, sem erro.
local x, y, z, w = …
Faltou valor (vieram 3, há 4 variáveis): a que sobra, w, fica nil. Também sem erro.

É a regra de sempre da atribuição múltipla: o que sobra some, o que falta vira nil.

2. Os itens como argumentos de uma função

O uso mais comum: uma função que aceita vários argumentos soltos, e você tem os valores numa lista. O math.max (o maior de vários números, aula A Biblioteca math) é assim: math.max(7, 9, 6). Ele não aceita uma tabela. O table.unpack faz a ponte:

local notas = {7.5, 9, 6, 10, 8}
print(math.max(table.unpack(notas)))
print(math.min(table.unpack(notas)))
local ficha = {"Ana", 34}
print(string.format("%s tem %d anos", table.unpack(ficha)))

$ lua argumentos.lua
10
6
Ana tem 34 anos
math.max(table.unpack(notas))
O Lua roda primeiro o de dentro: table.unpack(notas) vira 7.5, 9, 6, 10, 8. Fica math.max(7.5, 9, 6, 10, 8), que dá 10.
string.format("%s tem %d anos", table.unpack(ficha))
Vira string.format("%s tem %d anos", "Ana", 34): o %s recebe "Ana" e o %d recebe 34 (aula string.format).

Missão: o programa mostra Maior nota: 0. Troque o 0 por math.max(table.unpack(notas)) para ele mostrar Maior nota: 10.

local notas = {7, 9, 6, 10, 8}
print("Maior nota: " .. 0)

local notas = {7, 9, 6, 10, 8}
print("Maior nota: " .. math.max(table.unpack(notas)))

3. Só um pedaço: table.unpack(lista, i, j)

O table.unpack aceita mais dois números, opcionais: de onde começar (i) e até onde ir (j). Sem eles, ele vai do 1 até o tamanho da lista (#lista).

local semana = {"dom", "seg", "ter", "qua", "qui", "sex", "sáb"}
print(table.unpack(semana, 2, 6))
print(table.unpack(semana, 6))
print(table.unpack(semana, 1, 3))
print(table.unpack(semana, 5, 2))
print(table.unpack(semana, 6, 9))

$ lua pedaco.lua
seg	ter	qua	qui	sex
sex	sáb
dom	seg	ter

sex	sáb	nil	nil
table.unpack(semana, 2, 6)
Do item 2 ao item 6: os dias úteis.
table.unpack(semana, 6)
Só o i: do 6 até o fim (o fim é #semana, 7).
table.unpack(semana, 1, 3)
Os três primeiros.
table.unpack(semana, 5, 2)
Começo depois do fim: não devolve nada. O print sem argumentos escreve uma linha em branco.
table.unpack(semana, 6, 9)
Passou do fim da lista: o table.unpack não reclama. Ele entrega semana[8] e semana[9], que não existem, como nil.
O j diz exatamente quantos valores saem

Com i e j, saem sempre j - i + 1 valores, existindo ou não. É isso que permite tirar de uma tabela uma lista que tem nil no meio (veja a seção 5).

4. No meio, um valor só

Há uma pegadinha que pega todo mundo. O table.unpack só entrega todos os valores quando é o último de uma lista de valores (o último argumento, o último item de { }, o último depois do =). Se vier qualquer coisa depois dele, ele é cortado para o primeiro valor:

local cores = {"vermelho", "verde", "azul"}
print(table.unpack(cores), "fim")
print("início", table.unpack(cores))
local t = {table.unpack(cores), "preto"}
print(#t, t[1], t[2])
local u = {"preto", table.unpack(cores)}
print(#u, u[1], u[4])

$ lua posicao.lua
vermelho	fim
início	vermelho	verde	azul
2	vermelho	preto
4	preto	azul
print(table.unpack(cores), "fim")
Tem "fim" depois: o unpack entregou só "vermelho". O verde e o azul sumiram, sem erro.
print("início", table.unpack(cores))
Agora ele é o último: entregou os três.
{table.unpack(cores), "preto"}
Na tabela, a mesma regra: a tabela nova ficou com 2 itens, "vermelho" e "preto".
{"preto", table.unpack(cores)}
Com o unpack no fim, a tabela ficou com os 4: "preto" e as três cores.

Essa regra não é só do table.unpack: vale para toda função que devolve vários valores (aula Vários Retornos). Para juntar duas listas inteiras, não use unpack no meio: use um laço com table.insert (aula table.insert e table.remove).

5. Guardando valores soltos: table.pack(...)

O table.pack recebe quantos valores você quiser e devolve uma tabela nova com eles nas posições 1, 2, 3… e mais um campo, n, com a quantidade.

local p = table.pack("Ana", "Bia", "Caio")
print(p[1], p[2], p[3])
print(p.n)
print(#p)
local vazio = table.pack()
print(vazio.n, #vazio)

$ lua empacotar.lua
Ana	Bia	Caio
3
3
0	0
table.pack("Ana", "Bia", "Caio")
Cria a tabela {"Ana", "Bia", "Caio", n = 3}.
p.n
O campo n ("número"): quantos valores entraram. Aqui, 3.
#p
O operador de tamanho também dá 3. Então para que o n? Para quando há nil no meio.
table.pack()
Sem nada: a tabela vazia, com n = 0.

O n conta até os nil

Uma lista "comum" não guarda bem um nil: um nil no meio é um buraco, e o # fica sem saber onde a lista acaba (aula Sequências e Buracos). O table.pack resolve isso anotando no n quantos valores chegaram, nil incluído:

local p = table.pack("leite", nil, "pão", nil)
print(p.n)
for i = 1, p.n do
  print(i, p[i])
end
print(table.unpack(p, 1, p.n))

$ lua pack_nil.lua
4
1	leite
2	nil
3	pão
4	nil
leite	nil	pão	nil
p.n
Chegaram 4 valores, e o n diz 4, mesmo com dois deles sendo nil.
for i = 1, p.n do
Para percorrer uma tabela com buracos, use o n como fim do laço, nunca o #.
table.unpack(p, 1, p.n)
A volta completa: com i = 1 e j = p.n, saem os 4 valores, os nil no lugar certo.

Onde isso aparece: os argumentos de uma função

Uma função com ... (aula Funções Variádicas) recebe quantos argumentos vierem. Para saber quantos vieram, o #{...} não serve quando algum é nil. O table.pack(...).n serve sempre:

local function quantos(...)
  local t = {...}
  local p = table.pack(...)
  print("#t =", #t, "p.n =", p.n)
end
quantos("a", "b", "c")
quantos()
quantos(nil, nil)
quantos("a", nil, "c", nil)

$ lua contar_args.lua
#t =	3	p.n =	3
#t =	0	p.n =	0
#t =	0	p.n =	2
#t =	1	p.n =	4

Nas duas primeiras chamadas, os dois concordam. Nas duas últimas, só o p.n acertou: foram 2 e 4 argumentos. O #t deu 0 e 1, e numa lista com buracos o # nem tem uma resposta garantida (a aula Sequências e Buracos mostra por quê). Outra forma de contar os argumentos é select("#", ...) (aula select).

Missão: a função usa #{...} e erra a conta quando vem nil. Troque por table.pack(...).n para ela mostrar chegaram 4 valores.

local function contar(...)
  local total = #{...}
  print("chegaram " .. total .. " valores")
end
contar("arroz", nil, "feijão", nil)

local function contar(...)
  local total = table.pack(...).n
  print("chegaram " .. total .. " valores")
end
contar("arroz", nil, "feijão", nil)

Ida e volta sem perder nada

local function guardar(...)
  return table.pack(...)
end
local caixa = guardar(10, nil, 30)
print(caixa.n)
print(table.unpack(caixa))
print(table.unpack(caixa, 1, caixa.n))

$ lua ida_volta.lua
3
10
10	nil	30

O table.unpack(caixa) sem i e j usa o #caixa como fim e, com o buraco na posição 2, aqui entregou só o 10: o 30 se perdeu. Com 1, caixa.n, voltaram os três. Regra prática: o que entrou com table.pack sai com table.unpack(t, 1, t.n).

Novidade do 5.5: a tabela dos ... com nome

No Lua 5.5, uma função pode dar um nome à tabela dos argumentos extras, escrevendo ...t; ela já vem com o n, como a do table.pack:

$ lua -e 'local function f(...t) print(t.n, t[1]) end f("a", nil)'
2	a

Esse jeito é assunto da aula Funções Variádicas. Ele não existe no 5.4 nem antes; o table.pack(...) funciona do 5.2 em diante.

No Lua 5.1, LuaJIT, Neovim e LÖVE: unpack, sem table.

No Lua 5.1 a função se chamava só unpack, solta, e não existia table.pack. No Lua 5.2 ela mudou para dentro da biblioteca table, e o unpack solto foi removido (no 5.4 e no 5.5 ele não existe). Conferido no laboratório:

$ lua5.1 -e 'print(table.unpack, table.pack)'
nil	nil
$ luajit -e 'print(table.unpack, table.pack)'
function: builtin#16	function: builtin#101

O LuaJIT do Ubuntu aceita os dois nomes, unpack e table.unpack. Se você copiar um código antigo que usa unpack e rodar no 5.5, dá o erro do primeiro cenário abaixo. Um truque comum em código que precisa rodar em todos é local unpack = table.unpack or unpack. Mais em Lua 5.1, LuaJIT, 5.4 e 5.5.

Quando dá errado

Código do Lua 5.1: unpack sem table. 
local nomes = {"Ana", "Bia"}
print(unpack(nomes))

Como consertar: escreva table.unpack(nomes).

A lista é nil 
local lista
print(table.unpack(lista))

$ lua erro_nil.lua
lua: attempt to get length of a nil value
stack traceback:
	[C]: in field 'unpack'
	erro_nil.lua:2: in main chunk
	[C]: in ?

"Tentativa de pegar o tamanho de um valor nil": sem o j, o table.unpack calcula #lista, e lista é nil (a variável foi criada sem valor). Repare que a primeira linha não diz o número da linha: o erro aconteceu dentro do unpack, que é escrito em C. A linha está no rastro: [C]: in field 'unpack' (dentro do unpack), chamado de erro_nil.lua:2. Como consertar: confira se a variável tem mesmo uma tabela (um nome trocado, uma função que devolveu nil). Para não parar: table.unpack(lista or {}).

Faltou um valor para o string.format 
local ficha = {"Ana"}
print(string.format("%s tem %d anos", table.unpack(ficha)))

$ lua erro_format.lua
lua: erro_format.lua:2: bad argument #3 to 'format' (no value)
stack traceback:
	[C]: in field 'format'
	erro_format.lua:2: in main chunk
	[C]: in ?

"Argumento ruim nº 3 para format (nenhum valor)". O 1º argumento é o texto, o 2º é "Ana", e o 3º, que o %d pedia, não veio: a ficha só tem um item. Como consertar: confira se a lista tem um item para cada % do texto.

Valores demais: too many results to unpack 
local t = {}
print(select("#", table.unpack(t, 1, 100)))
print(table.unpack(t, 1, 10000000))

$ lua erro_muitos.lua
100
lua: erro_muitos.lua:3: too many results to unpack
stack traceback:
	[C]: in field 'unpack'
	erro_muitos.lua:3: in main chunk
	[C]: in ?

Pedir 100 valores (todos nil, porque a tabela está vazia) funcionou: o select("#", …) contou 100. Pedir dez milhões não: "resultados demais para desempacotar". Os valores soltos ficam numa área de memória limitada (a pilha), que não comporta milhões. Como consertar: lista grande não se desempacota; percorra com um for (aula ipairs).

Sumiram itens, sem erro nenhum 
local cores = {"vermelho", "verde", "azul"}
print(table.unpack(cores), "fim")

$ lua posicao.lua
vermelho	fim

O unpack não estava no fim da lista de argumentos e foi cortado para um valor (seção 4). Como consertar: deixe o table.unpack por último, ou junte o texto antes: print(table.concat(cores, " ") .. " fim") (aula table.concat).

Missão: a lista chegada tem os corredores na ordem em que chegaram. Use table.unpack com i e j para entregar só os três primeiros ao string.format, e o programa mostrar 1º Bia, 2º Ana, 3º Caio.

Resumo

  • table.unpack(t) tira os itens da tabela como valores soltos: serve para várias variáveis (local a, b = …) e para argumentos (math.max(table.unpack(notas))).
  • table.unpack(t, i, j) entrega do item i ao j, sempre j - i + 1 valores.
  • Só no fim de uma lista de valores ele entrega tudo; no meio, entrega só o primeiro.
  • table.pack(...) guarda valores soltos numa tabela e anota a quantidade em n, contando os nil. Volte com table.unpack(t, 1, t.n).
  • No Lua 5.1 era unpack, sem table.; no 5.5, unpack sozinho é nil.
