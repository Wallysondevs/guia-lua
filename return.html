Lua return

Até agora, as funções que você escreveu mostravam alguma coisa na tela com print. Mas muitas vezes o programa precisa do resultado para continuar trabalhando: somar a taxa de entrega ao total, comparar a nota com a média, guardar o preço numa lista. Para isso a função precisa devolver o resultado a quem a chamou. É o trabalho do return ("retornar, devolver").

Você vai aprender
  • A diferença entre mostrar (print) e devolver (return).
  • A usar o valor devolvido numa variável, numa conta, num texto, dentro de outra chamada e num if.
  • Que o return encerra a função na hora, e como usar isso para sair mais cedo.
  • O que uma função sem return devolve, e o return sem valor.
  • A regra do Lua: o return tem de ser o último comando do bloco (e o truque do return end).
  • Os erros reais: o nil de quem esqueceu o return, 'end' expected … near 'print' e o return solto que "engole" a linha de baixo.

A ideia: a calculadora da caixa

Na padaria, a Ana pede ao caixa: "quanto dá 4 pães de R$ 2,50?". O caixa pode fazer duas coisas:

  • Gritar o resultado para a loja inteira: "DEZ REAIS!". Todo mundo ouviu, mas a Ana não tem o número na mão para somar com o leite.
  • Escrever o número num papelzinho e entregar para ela. Agora a Ana pode somar, comparar, guardar.

1. O primeiro return

local function dobro(n)
  return n * 2
end

local resultado = dobro(21)
print(resultado)
print(dobro(5))

$ lua dobro.lua
42
10
return
"Devolver". Encerra a função e entrega um valor a quem a chamou.
n * 2
O valor devolvido. O Lua calcula a conta primeiro e devolve o resultado (com n = 21, devolve 42).
local resultado = dobro(21)
A chamada dobro(21) é substituída pelo valor que ela devolveu. Para o Lua, essa linha vira local resultado = 42.
print(dobro(5))
O valor devolvido também pode ir direto para outra função: o Lua calcula dobro(5), que dá 10, e passa o 10 para o print.

Repare que a função dobro não tem print nenhum. Quem decide o que fazer com o resultado (mostrar, guardar, somar) é quem chama.

2. Mostrar × devolver

As duas funções abaixo fazem a mesma conta. Uma mostra, a outra devolve:

local function mostra_total(preco, quantidade)
  print(preco * quantidade)
end

local function calcula_total(preco, quantidade)
  return preco * quantidade
end

mostra_total(2.5, 4)
local t = calcula_total(2.5, 4)
print("Com a taxa de entrega: " .. t + 5)

$ lua print_return.lua
10.0
Com a taxa de entrega: 15.0

A mostra_total escreveu 10.0 na tela, e acabou: o número sumiu. A calcula_total não escreveu nada; ela entregou o 10.0, que ficou guardado em t e pôde ser somado com a taxa. (O .0 aparece porque 2.5 é um número com vírgula, um float: aula Números.)

E se você tentar guardar o resultado da função que só mostra?

local function mostra_total(preco, quantidade)
  print(preco * quantidade)
end

local t = mostra_total(2.5, 4)
print("o que a função devolveu:", t)

$ lua print_nil.lua
10.0
o que a função devolveu:	nil

O 10.0 apareceu (foi o print de dentro), mas t ficou nil: a função não devolveu nada. É o caixa que gritou o número e não entregou o papel.

Missão: rode e veja o erro. A função triplo mostra o resultado em vez de devolver. Troque o print de dentro dela por um return, para o programa mostrar 16 (o triplo de 5, mais 1).

3. Usando o valor devolvido

Uma chamada que devolve um valor pode aparecer em qualquer lugar onde caberia esse valor: numa conta, num texto, dentro de outra chamada, numa tabela.

local function dobro(n)
  return n * 2
end

print(dobro(3) + 1)
print(dobro(dobro(3)))
print("O dobro de 7 é " .. dobro(7))
local lista = {dobro(1), dobro(2), dobro(3)}
print(lista[1], lista[2], lista[3])

$ lua expressoes.lua
7
12
O dobro de 7 é 14
2	4	6

O dobro(dobro(3)) é lido de dentro para fora: primeiro dobro(3) dá 6; depois dobro(6) dá 12.

Devolvendo true ou false

Uma função pode devolver uma resposta de "sim ou não", e aí ela cabe direto num if:

local function eh_par(n)
  return n % 2 == 0
end

print(eh_par(4), eh_par(7))
for i = 1, 5 do
  if eh_par(i) then
    print(i .. " é par")
  end
end

$ lua eh_par.lua
true	false
2 é par
4 é par

n % 2 == 0 é uma comparação (o resto da divisão por 2 é zero?), e toda comparação dá true ou false (aula Comparações). O return devolve esse resultado. Funções assim costumam ter nome de pergunta: eh_par, tem_estoque, esta_aberto.

4. O return encerra a função

Quando o Lua executa um return, a função termina ali, mesmo que existam outras linhas abaixo:

local function teste()
  print("antes do return")
  if true then
    return "valor"
  end
  print("depois do return")
end

print(teste())

$ lua depois_return.lua
antes do return
valor

O "depois do return" nunca aparece. Isso parece um defeito, mas é muito útil: uma função pode ter vários return, um em cada caminho, e só um deles roda.

local function classificar(nota)
  if nota >= 7 then
    return "aprovado"
  elseif nota >= 5 then
    return "recuperação"
  end
  return "reprovado"
end

print(classificar(8.5))
print(classificar(6))
print(classificar(3))

$ lua classificar.lua
aprovado
recuperação
reprovado
  1. Com 8.5: o primeiro if é verdadeiro, o Lua devolve "aprovado" e sai. O resto nem é olhado.
  2. Com 6: o primeiro teste falha, o elseif é verdadeiro, devolve "recuperação" e sai.
  3. Com 3: os dois testes falham, o if termina, e o Lua chega ao último return: "reprovado".

Sair mais cedo quando algo está errado

Um costume muito usado: conferir os problemas logo no começo e sair com return, para o resto da função só cuidar do caso normal:

local function preco_final(preco, quantidade)
  if quantidade <= 0 then
    return nil
  end
  local total = preco * quantidade
  if quantidade >= 10 then
    total = total * 0.9
  end
  return total
end

print(preco_final(0.80, 5))
print(preco_final(0.80, 20))
print(preco_final(0.80, 0))

$ lua guarda.lua
4.0
14.4
nil

Com 20 pães, o total ganhou 10% de desconto (16 * 0.9 = 14.4). Com quantidade 0, a função saiu na terceira linha devolvendo nil, o jeito do Lua de dizer "não tenho resposta". Quem chama pode testar: if total == nil then …. (Devolver também uma mensagem explicando o motivo é o assunto da próxima aula, Vários Retornos.)

5. Função sem return e return sem valor

Toda função do Lua termina devolvendo alguma coisa ou nada. Uma função sem return (como as da aula Funções) devolve nada. Guardado numa variável, esse "nada" vira nil:

local function nada()
end

local x = nada()
print(x)
print(nada())
print("fim")

$ lua sem_return.lua
nil
                                                   « print(nada()): linha vazia
fim

Repare na diferença: print(x) mostrou nil, mas print(nada()) mostrou uma linha vazia. É que a função não devolveu nem o nil: ela devolveu zero valores, e o print recebeu zero coisas para mostrar. Quando se guarda numa variável, o Lua completa o que falta com nil, como faz com os parâmetros (aula Parâmetros e Argumentos). A próxima aula mostra essa contagem de valores em detalhe.

return sozinho: só sair

Um return sem nada depois serve só para parar a função:

local function avisar(estoque)
  if estoque > 0 then
    return
  end
  print("Acabou o estoque!")
end

avisar(5)
avisar(0)
print(avisar(3))

$ lua return_vazio.lua
Acabou o estoque!
                                                   « print(avisar(3)): linha vazia

avisar(5) saiu pelo return sem mostrar nada; avisar(0) passou do if e mostrou o aviso; print(avisar(3)) mostrou uma linha vazia, porque esse return também devolve zero valores.

O return sozinho engole a linha de baixo

Cuidado com um return sem valor no fim de uma linha e mais código embaixo. Para o Lua, quebras de linha não separam comandos: ele lê o return e a linha seguinte como um comando só, return print(…):

local function testar()
  print("1. começou")
  return
  print("2. esta linha deveria ser pulada")
end

testar()

$ lua return_solto.lua
1. começou
2. esta linha deveria ser pulada

A linha 2 rodou! O Lua executou print("2. …") para devolver o resultado dele. Isso acontece quando alguém põe um return no meio da função para "desligar" o resto enquanto testa. O jeito certo é a seção 6.

6. O return tem de ser o último do bloco

No Lua, o return só pode aparecer como o último comando de um bloco (o fim da função, ou o fim de um if, de um for, de um do … end). Uma linha depois dele, no mesmo bloco, é erro de sintaxe:

local function dobro(n)
  return n * 2
  print("calculei")
end

$ lua return_meio.lua
lua: return_meio.lua:3: 'end' expected (to close 'function' at line 1) near 'print'

'end' expected (to close 'function' at line 1) near 'print': "esperava o end (para fechar o function da linha 1) perto do print". Depois de return n * 2, a única coisa que o Lua aceita é o fim do bloco. Faz sentido: uma linha depois do return nunca rodaria.

Por isso, nos exemplos da seção 4, cada return está no fim de um bloco: no fim do if, do elseif ou da função.

O truque do return end

E se você quiser mesmo sair no meio da função, por exemplo para testar só a primeira parte? Embrulhe o return num bloco do … end só dele. Aí ele é o último do seu bloco, e a regra está cumprida:

local function testar()
  print("1. começou")
  do return end
  print("2. esta linha deveria ser pulada")
end

testar()

$ lua return_do.lua
1. começou

Agora a linha 2 foi pulada de verdade. O do return end é coisa de teste: no programa pronto, prefira um if com return, como na seção 4.

Experimente: rode e confira as três classificações. Depois acrescente um caso novo no começo da função: se a nota for maior que 10, devolva "nota inválida". Teste com classificar(11).

local function classificar(nota)
  if nota >= 7 then
    return "aprovado"
  elseif nota >= 5 then
    return "recuperação"
  end
  return "reprovado"
end

print(classificar(8.5))
print(classificar(6))
print(classificar(3))

Formas diferentes de devolver um "sim ou não"

As duas funções abaixo devolvem a mesma coisa:

local function eh_par_a(n)
  if n % 2 == 0 then
    return true
  else
    return false
  end
end

local function eh_par_b(n)
  return n % 2 == 0
end

print(eh_par_a(4), eh_par_b(4), eh_par_a(3), eh_par_b(3))

$ lua formas.lua

if … then return true else return false endQuando você está começando e quer ver os dois caminhos escritos. Funciona, mas é comprido
return comparaçãoQuando a resposta é a própria comparação: mais curto, e é como os programadores Lua costumam escrever
Vários return com if/elseifQuando há mais de duas respostas (classificar)

Quando dá errado

Esquecer o return: a conta com nil 
local function subtotal(preco, quantidade)
  local total = preco * quantidade
end

local valor = subtotal(3, 2) + 5
print(valor)

$ lua esqueceu.lua
lua: esqueceu.lua:5: attempt to perform arithmetic on a nil value
stack traceback:
	esqueceu.lua:5: in main chunk
	[C]: in ?

A função calculou o total… e não devolveu. subtotal(3, 2) virou "nada", e nada + 5 não existe. attempt to perform arithmetic on a nil value: "tentativa de fazer conta com um valor nil". Desta vez o Lua não diz o nome da variável entre parênteses, porque o nil não estava numa variável: ele veio direto da chamada. Quando uma mensagem de nil não tem nome, desconfie de uma função que não devolveu nada.

Se o valor for guardado antes, o nome aparece, mas é o da variável de fora:

local function subtotal(preco, quantidade)
  local total = preco * quantidade
end

local valor = subtotal(3, 2)
print("Total: " .. valor)

$ lua esqueceu2.lua
lua: esqueceu2.lua:6: attempt to concatenate a nil value (local 'valor')
stack traceback:
	esqueceu2.lua:6: in main chunk
	[C]: in ?

A culpada não é a linha 6, e sim a função: como consertar: acrescente return total antes do end da subtotal.

Uma linha depois do return

É o erro da seção 6: 'end' expected (to close 'function' at line 1) near 'print'. Dentro de um if, a mensagem fala do if: com return "positivo" seguido de print("nunca") dentro de um if que começa na linha 2, o Lua respondeu 'end' expected (to close 'if' at line 2) near 'print'. Como consertar: apague a linha que nunca rodaria, ou mova-a para antes do return.

Usar print no lugar de return

Sem erro, mas com uma linha a mais e um nil na saída, como em print_nil.lua (seção 2): o valor apareceu na tela, mas o programa não ficou com ele. Se a saída mostra um número sozinho e depois nil, procure um print dentro da função onde deveria haver um return.

Um return sozinho no meio da função

Sem erro, e a linha de baixo roda (veja return_solto.lua, no aviso da seção 5). Como consertar: do return end, ou um if … then return end.

Missão final: o frete da padaria

Missão: complete a função frete(km) com return: até 5 km, o frete é 5; até 10 km, é 12; acima de 10 km a padaria não entrega, e a função devolve nil. Não mude as linhas de baixo.

local function frete(km)
  -- escreva aqui
end

print("Frete para 2 km: " .. tostring(frete(2)))
print("Frete para 8 km: " .. tostring(frete(8)))
print("Frete para 15 km: " .. tostring(frete(15)))

local function frete(km)
  if km > 10 then
    return nil
  end
  if km <= 5 then
    return 5
  end
  return 12
end

print("Frete para 2 km: " .. tostring(frete(2)))
print("Frete para 8 km: " .. tostring(frete(8)))
print("Frete para 15 km: " .. tostring(frete(15)))

(O tostring transforma o valor em texto, inclusive o nil, para o .. não reclamar: aula Conversão. Se você rodar sem mudar nada, o Lua responde bad argument #1 to 'tostring' (value expected), "argumento nº 1 do tostring inválido (esperava um valor)": a função vazia devolveu zero valores, como na seção 5, e o tostring ficou sem nada para converter.)

Resumo

  • print mostra na tela; return devolve o valor para quem chamou, que pode guardar, somar, comparar.
  • A chamada é substituída pelo valor devolvido: dobro(21) + 1 vira 42 + 1.
  • O return encerra a função na hora; vários return em caminhos diferentes são comuns, e um return no começo serve para sair mais cedo.
  • Sem return, a função devolve zero valores: numa variável vira nil; no print, uma linha vazia.
  • O return tem de ser o último comando do bloco (senão, 'end' expected … near …); para sair no meio, do return end. Um return sozinho engole a linha de baixo.
  • Esqueceu o return? Aparece attempt to … a nil value longe da função.
  • No Lua, o return pode devolver mais de um valor: próxima aula, Vários Retornos.
