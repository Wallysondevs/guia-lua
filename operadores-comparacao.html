Lua Comparações (==, ~=, <, >)

"A Ana tem 18 anos ou mais?" "A senha está certa?" "O preço passou de R$ 100?" Antes de tomar uma decisão, o programa precisa comparar dois valores. Os operadores de comparação fazem essa pergunta e respondem com um booleano: true (sim) ou false (não). São seis, quase todos conhecidos da escola. O diferente é o "diferente": no Lua ele se escreve ~=, e não != como em muitas outras linguagens.

Você vai aprender
  • Os seis operadores: == (igual), ~= (diferente), <, >, <= e >=.
  • A diferença entre = (guardar) e == (comparar).
  • Como o Lua compara números (3 == 3.0), textos (ordem alfabética, maiúsculas antes, "10" < "9") e valores de tipos diferentes.
  • Por que duas tabelas iguais não são ==, e por que floats não se comparam com ==.
  • Os erros reais: = no lugar de ==, != no lugar de ~=, 0 <= nota <= 10, e comparar texto com número.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com lua arquivo.lua (veja Rodando um Programa). Você pode rodar cada um no editor do guia.

A ideia: a balança de dois pratos

Uma balança antiga tem dois pratos. Você põe uma coisa de cada lado e olha: os pratos ficaram iguais? Um lado ficou mais pesado? A balança não diz quanto pesa cada coisa; ela só responde à pergunta. Um operador de comparação é essa balança: um valor de cada lado, e a resposta é true ou false (veja Booleanos).

1. Os seis operadores

local idade = 17
print(idade == 17, idade ~= 17)
print(idade < 18, idade > 18)
print(idade <= 17, idade >= 18)

Três detalhes de escrita:

  • O "igual" de comparar tem dois sinais: ==. Um sinal só (=) é outra coisa: "guarde este valor na variável" (veja Variáveis).
  • O "diferente" é til e igual: ~=. Lembre do ≠ da matemática, com o risquinho torto.
  • Em <= e >=, o sinal de igual vem depois, e sem espaço no meio. =<, => e < = não existem.

"Menor que" × "menor ou igual"

Na escola da Ana, a nota mínima para passar é 6: quem tira 6 ou mais é aprovado. Repare no que acontece com quem tirou exatamente 6, se o programa usar >:

local nota = 6
if nota > 6 then
  print("Aprovada")
else
  print("Reprovada")
end

$ lua nota.lua
Reprovada

6 > 6 é false: seis não é maior que seis. Para incluir o próprio 6, a pergunta certa é "maior ou igual". Esse tipo de engano (errar o limite por um) é tão comum que tem nome em inglês: off-by-one, "errar por um".

Missão: a Ana tirou 6 e o programa diz Reprovada. Troque o operador da condição para quem tira 6 ou mais ser aprovado.

local nota = 6
if nota > 6 then
  print("Aprovada")
else
  print("Reprovada")
end

local nota = 6
if nota >= 6 then
  print("Aprovada")
else
  print("Reprovada")
end

2. Igual e diferente: == e ~=

O == funciona com qualquer valor, de qualquer tipo. A regra é: primeiro o Lua olha o tipo. Se os tipos forem diferentes, a resposta é false, sem conversão nenhuma. Se forem iguais, ele compara os valores.

print(3 == 3.0, 1 == 1.0000001)
print("Ana" == "Ana", "Ana" == "ana", "Ana" == "Ana ")
print("10" == 10, true == "true", nil == false)
local a = {1, 2}
local b = {1, 2}
local c = a
print(a == b, a == c)
print(0.1 + 0.2 == 0.3)

$ lua igual.lua
true	false
true	false	false
false	false	false
false	true
false
3 == 3.0 → true
Inteiro e float com o mesmo valor são iguais (os dois são do tipo number; veja Números).
"Ana" == "ana" → false
Textos só são iguais se forem idênticos, letra por letra: maiúscula conta.
"Ana" == "Ana " → false
Até um espaço no fim faz diferença. Cuidado com o que a pessoa digita.
"10" == 10 → false
Texto × número: tipos diferentes, resposta false. O == não converte (veja Conversão).
true == "true" e nil == false → false
Também tipos diferentes.
a == b → false, a == c → true
Tabelas são comparadas pela identidade, não pelo conteúdo. a e b têm o mesmo conteúdo, mas são duas tabelas diferentes (duas caixas iguais, uma ao lado da outra). c é a mesma tabela que a (a mesma caixa, com duas etiquetas). Mais em Tabelas São Referências.
0.1 + 0.2 == 0.3 → false
Floats são aproximados, e a soma dá 0.30000000000000004. Veja a seção 5.

O ~= é exatamente o contrário do ==: a ~= b é sempre o mesmo que not (a == b).

Comparar sem ligar para maiúsculas

Se a pessoa pode digitar Sim, SIM ou sim, transforme tudo em minúsculas antes de comparar, com string.lower (aula Funções de Texto):

local resposta = "Sim"
print(resposta == "sim")
print(string.lower(resposta) == "sim")

No lab, a primeira linha deu false e a segunda, true.

3. Maior e menor com textos

Os operadores <, >, <= e >= funcionam com dois números ou com dois textos. Com textos, "menor" quer dizer "vem antes" na ordem, como no dicionário:

print("abacaxi" < "banana", "banana" < "abacaxi")
print("Ana" < "Bia", "ana" < "Bia")
print("Zebra" < "abacaxi")
print("10" < "9", 10 < 9)
print("casa" < "casaco", "" < "a")
print("árvore" < "zebra")

$ lua textos.lua
true	false
true	false
true
true	false
true	true
false
"abacaxi" < "banana" → true
O Lua compara letra por letra, da esquerda para a direita, e para na primeira diferença: a vem antes de b.
"ana" < "Bia" → false, "Zebra" < "abacaxi" → true
Surpresa: toda maiúscula vem antes de toda minúscula. Por dentro, cada letra é um número (o código dela: A é 65, Z é 90, a é 97), e o Lua compara esses números. Como 90 < 97, "Zebra" vem antes de "abacaxi".
"10" < "9" → true
Comparando como texto, o primeiro caractere decide: "1" vem antes de "9", então "10" vem antes de "9", como num dicionário. Como números, 10 < 9 é false. Se os valores vieram do teclado ou de um arquivo, converta com tonumber antes de comparar.
"casa" < "casaco" e "" < "a" → true
Um texto que é o começo de outro vem antes dele. O texto vazio vem antes de tudo.
"árvore" < "zebra" → false
Letras com acento vêm depois de todas as letras sem acento: o á é guardado com códigos maiores que o do z (veja Acentos e a Biblioteca utf8).
A ordem dos textos depende do idioma

O manual do Lua diz que textos são comparados "de acordo com o idioma atual" (locale). O Lua começa no idioma neutro (C), que é a ordem dos códigos mostrada acima. Se o programa chamar os.setlocale(""), passa a valer a ordem do português, em que o acento e a maiúscula quase não pesam:

print("árvore" < "zebra", "ana" < "Bia")
os.setlocale("")
print("árvore" < "zebra", "ana" < "Bia")

$ lua localeorder.lua
false	false
true	true

Mas o os.setlocale("") muda outras coisas também (por exemplo, o print de um float passa a mostrar vírgula; veja Conversão), então não use só para isso. Para uma ordem "sem ligar para maiúsculas", compare com string.lower dos dois lados. Ordenar listas é assunto de table.sort.

4. Comparar coisas de tipos diferentes

Com o == e o ~=, tipos diferentes simplesmente dão false (e true). Com <, >, <= e >= é diferente: eles só aceitam dois números ou dois textos. Qualquer outra mistura para o programa:

$ lua -e 'print("10" < 9)'
lua: (command line):1: attempt to compare string with number
stack traceback:
	(command line):1: in main chunk
	[C]: in ?
$ lua -e 'print(nil < 1)'
lua: (command line):1: attempt to compare nil with number
stack traceback:
	(command line):1: in main chunk
	[C]: in ?
$ lua -e 'print({} < {})'
lua: (command line):1: attempt to compare two table values
stack traceback:
	(command line):1: in main chunk
	[C]: in ?

"Tentativa de comparar texto com número", "… nil com número", "… dois valores tabela". (O lua -e '…' roda um programa de uma linha só, por isso o erro fala de (command line):1:.) O caso do texto com número é o mais comum de todos, e vem quase sempre do io.read(), que devolve texto: veja Conversão.

5. Floats e o ==

Como floats são aproximados (veja Números), comparar o resultado de uma conta com == é arriscado: 0.1 + 0.2 == 0.3 dá false. O jeito seguro é perguntar se a diferença entre os dois é muito pequena:

$ lua -e 'print(math.abs((0.1 + 0.2) - 0.3) < 1e-9)'
true

math.abs tira o sinal da diferença, e 1e-9 é 0,000000001: se a diferença for menor que isso, os números são "iguais o bastante". Com <, >, <= e >= entre floats normais não há problema. E um caso curioso: o nan (o resultado de 0/0) não é igual a nada, nem a ele mesmo:

$ lua -e 'local nan = 0/0 print(nan == nan, nan ~= nan, nan < 1, nan > 1)'
false	true	false	false

Formas diferentes de fazer a mesma coisa

Toda comparação pode ser escrita "virada": a < b é o mesmo que b > a, e a >= b é o mesmo que not (a < b) (para números). Escolha a que se lê mais natural em português:

PerguntaJeito naturalTambém funciona (mas lê pior)
"Tem 18 anos ou mais?"idade >= 1818 <= idade, not (idade < 18)
"A senha está errada?"senha ~= "pao123"not (senha == "pao123")
"Tem valor?"x ~= nil (ou só x; veja nil)not (x == nil)
"A nota está entre 0 e 10?"nota >= 0 and nota <= 100 <= nota and nota <= 10

A última linha junta duas comparações com and ("e"): é o assunto da próxima aula, and, or e not. O Lua não aceita 0 <= nota <= 10 (veja abaixo).

Quando dá errado

Um = só, no lugar de == 
local nota = 6
if nota = 6 then
  print("Nota seis")
end

$ lua atrib.lua
lua: atrib.lua:2: 'then' expected near '='

"Era esperado then perto do =", na linha 2. Depois de if nota, o Lua esperava a condição continuar ou o then ("então"); um = sozinho (que é "guardar") não pode aparecer ali. É um erro de sintaxe: o programa nem começa. Como consertar: if nota == 6 then. (Em algumas linguagens, como C, esse engano não dá erro e vira um defeito escondido; no Lua, pelo menos, ele é pego na hora.)

!= no lugar de ~= 
local senha = "abacate"
if senha != "pao123" then
  print("Senha errada!")
else
  print("Pode entrar.")
end

$ lua senha.lua
lua: senha.lua:2: 'then' expected near '!'

"Era esperado then perto do !". O != é o "diferente" de C, JavaScript, Python e muitas outras, mas não do Lua. Também não existem <> (de algumas linguagens antigas e do SQL) nem === (do JavaScript): no lab, print(5 <> 3) deu unexpected symbol near '>' e print(5 === 5) deu unexpected symbol near '='. Como consertar: ~=. A missão final é este programa.

=> e =< (o igual do lado errado) 
$ lua -e 'print(5 => 3)'
lua: (command line):1: ')' expected near '='
$ lua -e 'print(5 =< 3)'
lua: (command line):1: ')' expected near '='

"Era esperado ) perto do =": o Lua leu o 5, achou que a conta tinha acabado e esperava fechar o parêntese do print. Como consertar: o igual vem depois: >= e <=.

Comparação encadeada: 0 <= nota <= 10 
local nota = 15
if 0 <= nota <= 10 then
  print("Nota válida")
end

$ lua encadeado.lua
lua: encadeado.lua:2: attempt to compare boolean with number
stack traceback:
	encadeado.lua:2: in main chunk
	[C]: in ?

Na matemática, 0 ≤ nota ≤ 10 é uma frase só. O Lua faz uma comparação de cada vez, da esquerda para a direita: primeiro 0 <= nota, que dá true; depois, true <= 10. Aí ele reclama: "tentativa de comparar booleano com número". (O Python aceita essa escrita; o Lua, não.) Como consertar: duas comparações ligadas por and: if nota >= 0 and nota <= 10 then (aula and, or e not).

Comparou o texto digitado com um número 
local digitado = "7"
print(digitado == 7)
print(tonumber(digitado) == 7)

$ lua texto_num.lua
false
true

Com ==, nenhuma mensagem de erro: só um false que parece mentira. Com < ou >, seria o erro attempt to compare string with number da seção 4. Como consertar: converta com tonumber antes de comparar.

Resumo

  • Seis operadores de comparação: ==, ~=, <, >, <=, >=. Todos respondem true ou false.
  • = guarda; == compara. O "diferente" é ~=, nunca !=.
  • == com tipos diferentes dá false sem converter: "10" == 10 é false. Tabelas só são iguais se forem a mesma tabela.
  • < > <= >= só comparam dois números ou dois textos; misturar dá attempt to compare ….
  • Textos seguem a ordem dos códigos: maiúsculas antes de minúsculas, acentos depois do z, e "10" < "9". Para comparar números que vieram como texto, use tonumber.
  • Floats não se comparam com == depois de contas: use math.abs(a - b) < 1e-9.
  • "Entre 0 e 10" se escreve x >= 0 and x <= 10; o 0 <= x <= 10 dá erro.
