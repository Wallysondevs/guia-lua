Lua __tostring, __call e __len

Três metamétodos que deixam as suas tabelas mais "educadas": o __tostring ensina o print a mostrar a tabela de um jeito legível (em vez de table: 0x55d6312ad780); o __call deixa você chamar uma tabela como se ela fosse uma função; e o __len ensina o operador # a medir a tabela do jeito que você quiser. De brinde, o campo __name, que dá nome ao seu tipo nas mensagens de erro.

Você vai aprender
  • Por que print de uma tabela mostra table: 0x…, e como trocar isso por R$ 10,50 com o __tostring.
  • Onde o __tostring funciona (print, tostring, %s) e onde não funciona (o ..).
  • O campo __name: o nome do tipo em tostring e nas mensagens de erro.
  • O __call: uma tabela de preços que responde a tabela_precos("pao", 6), e uma máquina de senhas.
  • O __len: o # certo numa tabela só de leitura e num estoque.
  • Os erros reais: '__tostring' must return a string, attempt to call a table value e outros.

Todos os programas rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook) com lua arquivo.lua. Antes, faça Metatabelas, Metamétodos de Operadores (de onde vem o tipo Dinheiro) e __index e __newindex.

A ideia: crachá, campainha e régua

Pense nas tabelas como funcionários de uma loja. Os três metamétodos desta aula dão a eles três coisas:

  • um crachá (__tostring e __name): quando alguém pergunta "quem é você?", em vez de responder um número de matrícula sem sentido, ele mostra o nome;
  • uma campainha (__call): você "aperta" a tabela com (), como faz com uma função, e ela faz alguma coisa;
  • uma régua (__len): quando alguém mede com #, ele diz o próprio tamanho, do jeito que faz sentido para ele.

1. O print de uma tabela

local preco = { centavos = 1050 }
print(preco)
print(tostring(preco))

$ lua mostrar.lua
table: 0x55d6312ad780
table: 0x55d6312ad780
$ lua mostrar.lua
table: 0x55e3d8b6c780
table: 0x55e3d8b6c780

O print transforma cada valor em texto com o tostring. Para uma tabela comum, o texto é table: seguido do endereço da tabela na memória do computador, em hexadecimal (o 0x…). Ele serve para saber se duas tabelas são a mesma, mas não diz nada do conteúdo, e muda a cada execução (rodamos duas vezes, e o número mudou). No editor do guia, o endereço também é outro.

2. __tostring: o crachá

Quando a metatabela tem __tostring, o tostring chama essa função com a tabela e usa o texto que ela devolver:

local Dinheiro = {}

local function reais(centavos)
  return setmetatable({ centavos = centavos }, Dinheiro)
end

Dinheiro.__tostring = function (d)
  return string.format("R$ %d,%02d", d.centavos // 100, d.centavos % 100)
end

local preco = reais(1050)
print(preco)
print(tostring(preco))
print(string.format("O pão custa %s.", preco))
print("Lista:", reais(150), reais(800))
local texto = tostring(preco)
print(type(texto), #texto)

$ lua tostring.lua
R$ 10,50
R$ 10,50
O pão custa R$ 10,50.
Lista:	R$ 1,50	R$ 8,00
string	8
Dinheiro.__tostring = function (d)
Recebe a tabela que está sendo mostrada e devolve o texto que a representa. É a antiga função mostrar da aula anterior, agora no manual.
print(preco)
O print usa o tostring, que acha o __tostring: aparece R$ 10,50.
string.format("… %s …", preco)
O %s do string.format também passa pelo tostring, então usa o __tostring.
print("Lista:", reais(150), reais(800))
Com vários valores, cada um é transformado em texto (e separados por TAB, como sempre).
tostring(preco) → string, 8
O resultado é um texto de verdade ("R$ 10,50", com 8 caracteres), que você pode guardar e usar.

No modo interativo, o > também mostra o valor com o __tostring:

$ lua
Lua 5.5.0  Copyright (C) 1994-2025 Lua.org, PUC-Rio
> t = setmetatable({}, { __tostring = function () return "sou a tabela t" end })
> t
sou a tabela t
> print(t)
sou a tabela t
> os.exit()

O .. não usa o __tostring

Uma surpresa comum: o operador de juntar textos não consulta o __tostring. Ele tem o seu próprio metamétodo, o __concat (veja Metamétodos de Operadores):

local Dinheiro = {}
Dinheiro.__tostring = function (d)
  return string.format("R$ %d,%02d", d.centavos // 100, d.centavos % 100)
end
local preco = setmetatable({ centavos = 1050 }, Dinheiro)
print("Preço: " .. tostring(preco))
print("Preço: " .. preco)

$ lua concat_tostring.lua
Preço: R$ 10,50
lua: concat_tostring.lua:7: attempt to concatenate a table value (local 'preco')
stack traceback:
	concat_tostring.lua:7: in main chunk
	[C]: in ?

Com o tostring(preco) explícito, a linha 6 funcionou. A linha 7 tentou juntar o texto direto com a tabela. Os dois consertos: chamar tostring (o mais simples) ou escrever um __concat.

Missão: a Ana está desenhando figuras. O print(janela) mostra table: 0x…. Escreva um Retangulo.__tostring que devolva "Retângulo " .. r.largura .. "x" .. r.altura, para aparecer Retângulo 3x4.

3. __name: o nome do tipo

Às vezes você não quer escrever um __tostring completo, mas gostaria que o Lua soubesse como se chama o seu tipo. Para isso existe o campo __name na metatabela. Ele não é uma função: é só um texto.

local Conta = { __name = "Conta" }
local c = setmetatable({ saldo = 100 }, Conta)
print(type(c))
print((tostring(c):gsub("0x%x+", "0x...")))
print(math.floor(c))

$ lua nome.lua
table
Conta: 0x...
lua: nome.lua:5: bad argument #1 to 'floor' (number expected, got Conta)
stack traceback:
	[C]: in field 'floor'
	nome.lua:5: in main chunk
	[C]: in ?
type(c) → table
O __name não muda o tipo: para o type, continua sendo uma tabela.
tostring(c) → Conta: 0x…
Sem __tostring, o tostring usa o __name no lugar de table. (O gsub só troca o endereço, que muda a cada vez, por 0x..., para a saída ficar igual sempre; veja gsub.)
(number expected, got Conta)
"Era esperado um número, veio uma Conta". As mensagens de erro das funções do Lua passam a usar o nome do seu tipo, o que ajuda muito a achar o engano.

Outras mensagens que o lab mostrou com __name = "Conta": c + 1 deu attempt to perform arithmetic on a Conta value (local 'c'), e string.rep("-", c) deu bad argument #2 to 'rep' (number expected, got Conta).

Em outras versões

O __name é do Lua 5.3 em diante. No lab, o mesmo nome.lua mostrou Conta: 0x... e got Conta no lua5.4, mas table: 0x... e got table no lua5.1, que ignora o campo. O __tostring funciona em todas. Veja as diferenças entre as versões.

4. __call: a tabela que se chama

Os parênteses ( ) servem para chamar funções. Se você puser parênteses depois de uma tabela comum, o Lua reclama:

local precos = { pao = 150, cafe = 800 }
print(precos("pao"))

$ lua chamar.lua
lua: chamar.lua:2: attempt to call a table value (local 'precos')
stack traceback:
	chamar.lua:2: in main chunk
	[C]: in ?

"Tentativa de chamar um valor tabela (a variável local precos)". É a mesma família do famoso attempt to call a nil value, de quando você erra o nome de uma função. Com o __call na metatabela, chamar a tabela passa a chamar a função do manual:

local tabela_precos = setmetatable({ pao = 150, cafe = 800 }, {
  __call = function (self, produto, quantidade)
    local unitario = self[produto]
    if unitario == nil then
      return nil, "não vendemos " .. produto
    end
    return unitario * (quantidade or 1)
  end,
})

print(tabela_precos.pao)
print(tabela_precos("pao"))
print(tabela_precos("pao", 6))
print(tabela_precos("pizza"))

$ lua call.lua
150
150
900
nil	não vendemos pizza
__call = function (self, produto, quantidade)
O primeiro parâmetro é sempre a própria tabela que foi chamada. Por tradição, ele se chama self ("si mesmo", em inglês): você vai vê-lo o tempo todo em Métodos. Os parâmetros seguintes são o que veio dentro dos parênteses.
tabela_precos("pao", 6)
O Lua chamou __call(tabela_precos, "pao", 6): self["pao"] é 150, vezes 6, dá 900.
quantidade or 1
Se a quantidade não veio (tabela_precos("pao")), ela é nil, e o or usa 1.
return nil, "não vendemos …"
O jeito Lua de avisar que deu errado sem parar o programa: devolver nil e uma mensagem (veja Vários Retornos).
tabela_precos.pao → 150
A tabela continua sendo uma tabela: dá para ler os campos normalmente.

Uma tabela com memória: a máquina de senhas

Uma função comum não guarda nada entre uma chamada e outra (a não ser com closures). Uma tabela com __call guarda: os dados ficam nos campos dela. A máquina de senhas da padaria:

local senhas = setmetatable({ atual = 0 }, {
  __call = function (self)
    self.atual = self.atual + 1
    return string.format("Senha %03d", self.atual)
  end,
})

print(senhas())
print(senhas())
print(senhas())
print("Já chamamos", senhas.atual, "clientes")

$ lua contador.lua
Senha 001
Senha 002
Senha 003
Já chamamos	3	clientes

Cada senhas() soma 1 no campo atual da própria tabela (o self) e devolve o texto da senha. O %03d completa com zeros até 3 dígitos.

Onde o __call aparece de verdade

Muitas bibliotecas de classes usam o __call para criar objetos com Conta(100), em vez de Conta.new(100). Você vai ver as duas formas nas próximas aulas.

Missão: a última linha chama tabela_precos("pao", 6) e dá attempt to call a table value. Ponha na metatabela um __call que receba (self, produto, quantidade) e devolva self[produto] * quantidade.

local tabela_precos = setmetatable({ pao = 150, cafe = 800 }, {
})

print("6 pães: " .. tabela_precos("pao", 6))

local tabela_precos = setmetatable({ pao = 150, cafe = 800 }, {
  __call = function (self, produto, quantidade)
    return self[produto] * quantidade
  end,
})

print("6 pães: " .. tabela_precos("pao", 6))

5. __len: a régua do #

Na aula __index e __newindex, a tabela só de leitura dos dias da semana tinha um defeito: o # dava 0, porque a tabela da frente está vazia.

local function somente_leitura(original)
  return setmetatable({}, { __index = original })
end
local dias = somente_leitura({ "dom", "seg", "ter", "qua", "qui", "sex", "sáb" })
print(#dias)

$ lua len_sem.lua
0

O __len conserta: quando a tabela tem esse metamétodo, o # chama a função e usa o que ela devolver.

local function somente_leitura(original)
  return setmetatable({}, {
    __index = original,
    __len = function (tabela)
      return #original
    end,
  })
end
local dias = somente_leitura({ "dom", "seg", "ter", "qua", "qui", "sex", "sáb" })
print(#dias)
for i = 1, #dias do io.write(dias[i], " ") end
print()

$ lua len.lua
7
dom seg ter qua qui sex sáb
__len = function (tabela)
Recebe a tabela que está sendo medida (a da frente, vazia). Por isso a função mede a original, que ela enxerga por ser uma closure.
#dias → 7
Agora o # pergunta à régua, e a resposta é 7.
for i = 1, #dias do
Com o # certo, o for numérico volta a funcionar com a tabela só de leitura.

Medir do seu jeito

O # normal conta os itens de uma lista (veja O Operador de Tamanho); num dicionário, ele dá 0. Com o __len, você decide o que "tamanho" quer dizer. No estoque, a Ana quer saber quantos produtos ainda têm alguma unidade:

local estoque = setmetatable({ pao = 40, leite = 12, cafe = 0, bolo = 3 }, {
  __len = function (t)
    local tipos = 0
    for _, quantidade in pairs(t) do
      if quantidade > 0 then tipos = tipos + 1 end
    end
    return tipos
  end,
})
print(#estoque)
print(rawlen(estoque))

$ lua len_estoque.lua
3
0

Três produtos com estoque (o café está zerado). E o rawlen mede "por baixo" do manual, sem chamar o __len: para esse dicionário, o tamanho de lista é 0. Ele faz parte da família da próxima aula, rawget, rawset e rawequal.

O __len só vale para tabelas

O # de um texto conta os bytes, sempre, e não há como mudar isso com setmetatable (no lab, #"Ana" deu 3). E no Lua 5.1 o __len de tabelas é ignorado: o len.lua mostrou 0 no lua5.1 do lab (e 7 no luajit). Veja as diferenças entre as versões.

6. Os três juntos: a figura completa

Uma metatabela pode ter quantos metamétodos você quiser. O retângulo da Ana com crachá, campainha e régua:

local Retangulo = { __name = "Retangulo" }

Retangulo.__tostring = function (r)
  return "Retângulo " .. r.largura .. "x" .. r.altura
end

Retangulo.__call = function (r, nova_largura, nova_altura)
  return setmetatable({ largura = nova_largura, altura = nova_altura }, Retangulo)
end

Retangulo.__len = function (r)
  return 2 * (r.largura + r.altura)
end

local porta = setmetatable({ largura = 1, altura = 2 }, Retangulo)
print(porta)
print("perímetro:", #porta)
local janela = porta(3, 4)
print(janela, #janela)

$ lua tudo.lua
Retângulo 1x2
perímetro:	6
Retângulo 3x4	14

O __tostring mostra a figura; o __len usa o # para o perímetro; e o __call faz qualquer retângulo "fabricar" outro: porta(3, 4) criou a janela. Funciona, mas repare que "o # de um retângulo é o perímetro" não é óbvio para quem lê o código. A próxima seção fala disso.

Formas diferentes de fazer a mesma coisa

Para…Com metamétodoSem metamétodo
Mostrar a tabela__tostring, e aí print(preco)Uma função: print(mostrar(preco))
Dar nome ao tipo nos erros__name = "Conta"Não há
Fazer a tabela "agir"__call: tabela_precos("pao", 6)Uma função no campo: tabela_precos.calcular("pao", 6)
Medir__len: #estoqueUma função: produtos_disponiveis(estoque)

Qual usar? O __tostring vale quase sempre: deixa o print útil para conferir o programa, sem mudar mais nada. O __name é de graça e melhora as mensagens de erro. Já o __call e o __len, use quando o significado for óbvio: #dias ser 7 é óbvio; #porta ser o perímetro, não. Nesses casos, uma função com nome claro (perimetro(porta)) se explica sozinha.

Quando dá errado

Esqueceu o return no __tostring 
local Dinheiro = {}
Dinheiro.__tostring = function (d)
  string.format("R$ %d,%02d", d.centavos // 100, d.centavos % 100)
end
local preco = setmetatable({ centavos = 1050 }, Dinheiro)
print(preco)

$ lua tostring_nil.lua
lua: tostring_nil.lua:6: '__tostring' must return a string
stack traceback:
	[C]: in global 'print'
	tostring_nil.lua:6: in main chunk
	[C]: in ?

"O __tostring precisa devolver um texto". A função montou o texto mas não o devolveu, então devolveu nil. O rastro mostra que o erro saiu de dentro do print ([C]: in global 'print'), que foi quem pediu o texto. Como consertar: return string.format(…). (Devolver um número passou no lab: um __tostring com return d.centavos mostrou 1050, porque o Lua aceita número onde espera texto. Mas devolva sempre um texto.)

Juntou a tabela com .. esperando o __tostring

"Preço: " .. preco dá attempt to concatenate a table value (local 'preco') mesmo com __tostring (seção 2). Como consertar: "Preço: " .. tostring(preco), ou string.format("Preço: %s", preco).

Chamou uma tabela sem __call

precos("pao") com uma tabela comum dá attempt to call a table value (local 'precos') (seção 4). Muitas vezes não é falta de __call, e sim um engano: a pessoa queria precos["pao"] (colchetes, para ler um campo) ou precos.calcular("pao") (uma função guardada na tabela). Como consertar: use colchetes para ler; parênteses só para chamar.

Esqueceu o self nos parâmetros do __call 
local senhas = setmetatable({ atual = 0 }, {
  __call = function ()
    self.atual = self.atual + 1
    return self.atual
  end,
})
print(senhas())

$ lua call_sem_self.lua
lua: call_sem_self.lua:3: attempt to index a nil value (global 'self')
stack traceback:
	call_sem_self.lua:3: in local 'senhas'
	call_sem_self.lua:7: in main chunk
	[C]: in ?

"Tentativa de indexar um valor nil (a global self)". O self não é uma palavra mágica: é só o nome do primeiro parâmetro. Sem ele na lista function (), o Lua procura uma variável global chamada self, que não existe. Repare no rastro: in local 'senhas', o Lua sabe que a função rodou porque a tabela senhas foi chamada. Como consertar: function (self).

    __index = original,

      error("tabela só de leitura", 2)
    end,
  })
end

local dias = somente_leitura({ "dom", "seg", "ter", "qua", "qui", "sex", "sáb" })

  print(i, dias[i])

Resumo

  • __tostring: (t) → texto. Usado por print, tostring, %s e pelo modo interativo. Não é usado pelo ...
  • __name: um texto com o nome do tipo, que aparece em Conta: 0x… e em mensagens como got Conta.
  • __call: deixa chamar a tabela com t(…); o primeiro parâmetro é a própria tabela (o self). Bom para tabelas que "agem" e guardam estado.
  • __len: o #t passa a devolver o que a função calcular; rawlen mede sem o manual.
  • Use __tostring e __name à vontade; __call e __len quando o significado for óbvio.
  • Próximo passo: como ler e gravar sem passar pelo manual, em rawget, rawset e rawequal.
