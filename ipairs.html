Lua ipairs: Percorrendo uma Lista

Na aula Tabelas como Listas, você percorreu listas com for i = 1, #lista do e pegou cada item com lista[i]. Funciona, mas o Lua tem um jeito feito sob medida para isso: o ipairs. Com ele, o laço entrega a posição e o item a cada volta, sem precisar escrever #lista nem lista[i]. O nome vem de i (de índice, a posição) + pairs ("pares"): ele percorre os pares posição → item.

Você vai aprender
  • Como escrever for i, item in ipairs(lista) do … end e o que é cada parte.
  • O _ quando só o item interessa.
  • Somar, procurar e contar numa lista com ipairs.
  • Percorrer uma lista de fichas (tabelas dentro da lista).
  • Por que o ipairs para no primeiro nil, e o que ele ignora (a posição 0, as chaves de texto).
  • A variável de posição que não pode ser alterada no Lua 5.5, e como mudar os itens da lista.
  • Os erros reais: lista nil, esquecer o ipairs, usar uma variável só.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), com lua arquivo.lua.

A ideia: a chamada da professora

A professora pega a lista da turma e faz a chamada: "número 1, Ana; número 2, Bia; número 3, Caio…". Ela vai em ordem, do primeiro ao último, e a cada nome diz o número e o nome. O ipairs faz o mesmo com uma lista do Lua: a cada volta do laço, ele entrega o número (a posição) e o nome (o item). Com um detalhe da professora distraída: se uma linha da lista estiver em branco, ela acha que a lista acabou e para ali.

1. O primeiro ipairs

local turma = {"Ana", "Bia", "Caio", "Davi"}
for i, nome in ipairs(turma) do
  print(i, nome)
end
print("fim da chamada")
for
O mesmo for dos laços, mas na forma genérica: em vez de = início, fim, ele usa in ("em") e uma função que vai entregando os valores.
i, nome
As duas variáveis do laço, criadas pelo próprio for (elas são local do laço e somem depois do end). A primeira recebe a posição; a segunda, o item daquela posição. Os nomes são você que escolhe: i, nome, pos, aluno, n, preco.
in ipairs(turma)
"Em ipairs(turma)": percorra a lista turma, da posição 1 em diante.
do … end
O corpo do laço, que roda uma vez para cada item.
$ lua chamada.lua
1	Ana
2	Bia
3	Caio
4	Davi
fim da chamada

O resultado é o mesmo de for i = 1, #turma do print(i, turma[i]) end. A diferença é que, com o ipairs, o item já chega pronto numa variável com um nome que diz o que ele é (nome), e o código fica mais fácil de ler.

Lista vazia: zero voltas

for i, v in ipairs({}) do
  print("nunca aparece")
end
print("lista vazia: zero voltas")

$ lua vazia_ip.lua
lista vazia: zero voltas

Logo de cara, a posição 1 é nil: o corpo não roda nenhuma vez, e isso não é erro.

2. Só o item: o _

Muitas vezes a posição não interessa, só o item. Mesmo assim, a primeira variável tem de existir (é ela que recebe a posição). O costume é chamá-la de _ (o sublinhado), que quer dizer "não vou usar":

local compras = {"pão", "leite", "café"}
for _, item in ipairs(compras) do
  print("- " .. item)
end

$ lua so_item.lua
- pão
- leite
- café

Para o Lua, _ é um nome de variável como outro qualquer; o significado "não vou usar" é uma combinação entre programadores. Quem lê o código entende na hora que a posição foi ignorada de propósito.

3. Somar, procurar e contar

Somar

local precos = {4.50, 12.90, 3.25}

for _, preco in ipairs(precos) do
  total = total + preco
end
print(string.format("Total: R$ %.2f", total))

$ lua total.lua

Procurar (e parar quando achar)

Para saber em que posição está um item, compare cada item com o procurado e guarde a posição. Achou, break: não precisa olhar o resto.

local compras = {"pão", "leite", "café", "manteiga"}
local procurado = "café"
local posicao = nil
for i, item in ipairs(compras) do
  if item == procurado then
    posicao = i
    break
  end
end
if posicao then
  print(procurado .. " está na posição " .. posicao)
else
  print(procurado .. " não está na lista")
end

$ lua procurar.lua
café está na posição 3

A posicao é criada fora do laço, porque o i deixa de existir no end. Se nada for achado, ela continua nil, e o if posicao then cai no else (o nil conta como falso; veja Booleanos).

4. Uma lista de fichas

Os itens de uma lista podem ser tabelas. É assim que se guarda o estoque inteiro da padaria: uma lista em que cada item é a ficha de um produto. No laço, a variável do item é a ficha, e os campos se leem com o ponto:

local produtos = {
  {nome = "Pão", preco = 0.75, estoque = 40},
  {nome = "Leite", preco = 5.49, estoque = 0},
  {nome = "Café", preco = 18.90, estoque = 5},
}
for i, p in ipairs(produtos) do
  local situacao = "ok"
  if p.estoque == 0 then
    situacao = "ACABOU"
  end
  print(i .. ". " .. p.nome .. ": R$ " .. string.format("%.2f", p.preco) .. " (" .. situacao .. ")")
end

$ lua fichas.lua
1. Pão: R$ 0.75 (ok)
2. Leite: R$ 5.49 (ACABOU)
3. Café: R$ 18.90 (ok)

Esse formato, uma lista de fichas, aparece em quase todo programa de verdade: a lista de alunos com nome e notas, a agenda com nome e telefone, as tarefas com título e "feita ou não". Mais em Tabelas Aninhadas.

5. O ipairs para no primeiro nil

O ipairs não olha o #. Ele vai de 1 em 1 e para na primeira posição vazia. Numa lista com um buraco no meio, tudo o que vem depois do buraco fica de fora:

local t = {"pão", "leite", "café", "manteiga"}
t[2] = nil
print("#t =", #t)
for i, item in ipairs(t) do
  print("ipairs:", i, item)
end
for i = 1, #t do
  print("for:", i, t[i])
end

$ lua buraco.lua
#t =	1
ipairs:	1	pão
for:	1	pão

O café e a manteiga continuam na tabela (t[3] e t[4]), mas o ipairs parou no t[2], que é nil. E o #t? Numa tabela com buraco, o manual do Lua diz que ele pode dar qualquer das "bordas" da tabela; aqui deu 1, mas poderia ter dado 4. É por isso que listas com buraco são um problema, e é por isso que para tirar um item do meio se usa table.remove, que fecha o buraco (veja table.insert e table.remove e Sequências e Buracos).

O que o ipairs ignora

local t = {[0] = "zero", "um", "dois", nome = "Ana", [5] = "cinco"}
for i, v in ipairs(t) do
  print(i, v)
end

$ lua misto.lua
1	um
2	dois
  • A posição 0: o ipairs começa no 1.
  • A chave de texto nome: não é uma posição.
  • O [5]: depois do 2, a posição 3 é nil, e ele parou ali.

Para passar por todas as chaves de uma tabela, inclusive as de texto, existe o pairs (sem o i), assunto de Percorrendo Chaves (pairs).

6. Mudando os itens durante o laço

No Lua 5.5, a primeira variável do for (a posição) é constante: o laço não deixa você mudá-la. 5.5

local nomes = {"ana", "bia", "caio", "davi"}
for i, nome in ipairs(nomes) do
  print(i, nome)
  i = i + 1
end

$ lua const_i.lua
lua: const_i.lua:4: attempt to assign to const variable 'i'

"Tentativa de atribuir a uma variável constante i." É um erro de compilação: o programa nem começa (nenhum nome foi mostrado). Quem tenta isso normalmente quer "pular um item"; para isso existe o goto continue. No Lua 5.4, a mesma linha é aceita, mas não muda nada: o lua5.4 const_i.lua do lab mostrou os quatro nomes, de 1 a 4, como se o i = i + 1 não existisse. O 5.5 transformou esse engano silencioso num erro (veja Novidades do Lua 5.5).

A segunda variável (o item) pode ser mudada, mas ela é uma cópia do valor: mudar nome não muda a lista. Para mudar a lista, guarde na posição:

local nomes = {"ana", "bia", "caio"}
for i, nome in ipairs(nomes) do
  nomes[i] = nome:upper()
end
print(nomes[1], nomes[2], nomes[3])

$ lua mudar_lista.lua
ANA	BIA	CAIO

(O nome:upper() devolve o texto em maiúsculas; veja Funções de Texto.) Trocar o item de uma posição durante o laço é seguro. Acrescentar ou tirar itens da lista enquanto o ipairs passa por ela, não: as posições mudam debaixo dos pés do laço. A aula table.insert e table.remove mostra o que acontece e como fazer certo.

Formas diferentes de fazer a mesma coisa

local turma = {"Ana", "Bia", "Caio"}

for i, nome in ipairs(turma) do
  print(i, nome)
end

for i = 1, #turma do
  print(i, turma[i])
end

Numa lista sem buracos, as duas formas dão o mesmo resultado. Qual escolher:

SituaçãoQual usar
Passar por todos os itens de uma lista, do primeiro ao últimofor i, item in ipairs(t) (o mais comum)
Só o item interessafor _, item in ipairs(t)
De trás para frente, de 2 em 2, ou só uma parte da listafor i = #t, 1, -1 / for i = 1, #t, 2 / for i = 2, 4
Todas as chaves, inclusive as de textofor chave, valor in pairs(t) (aula)
Juntar todos os itens num textotable.concat(t, ", ") (aula), sem laço nenhum
Em outras versões

O ipairs existe em todas as versões (5.1, LuaJIT, 5.4, 5.5) e funciona igual nas listas sem buraco. Uma diferença aparece quando a lista é nil (veja o primeiro cenário de Quando dá errado): no LuaJIT, a mensagem é bad argument #1 to 'ipairs' (table expected, got nil), com o número da linha. Mais em As Diferenças entre Versões.

Quando dá errado

A lista era nil 
local compras
for i, item in ipairs(compras) do
  print(i, item)
end

$ lua ipairs_nil.lua
lua: attempt to index a nil value
stack traceback:
	[C]: in for iterator 'for iterator'
	ipairs_nil.lua:2: in main chunk
	[C]: in ?

Esta mensagem é diferente das outras: a primeira linha não tem o nome do arquivo nem o número da linha. O motivo é que o erro aconteceu dentro do ipairs, que é escrito em C (por isso o [C]), quando ele tentou abrir a posição 1 de algo que é nil. A linha do seu programa aparece só no rastro:

attempt to index a nil value
"Tentativa de indexar um valor nil": abrir uma gaveta de algo que não é tabela.
[C]: in for iterator 'for iterator'
Onde o erro aconteceu: no "iterador do for", a função em C que o ipairs entrega ao laço.
ipairs_nil.lua:2: in main chunk
Quem chamou: a linha 2 do seu programa, o for. É ali que você vai olhar.

Como consertar: a variável da lista não recebeu uma tabela. Confira o nome (um erro de digitação cria uma variável nil) e se ela foi preenchida antes do laço: local compras = {}.

Esqueceu o ipairs 
local compras = {"pão", "leite"}
for i, item in compras do
  print(i, item)
end

$ lua sem_ipairs.lua
lua: sem_ipairs.lua:2: attempt to call a table value (for iterator 'for iterator')
stack traceback:
	sem_ipairs.lua:2: in main chunk
	[C]: in ?

"Tentativa de chamar um valor do tipo tabela." O for … in espera uma função que vá entregando os valores (é isso que o ipairs(compras) devolve), e tentou "chamar" a própria tabela. Como consertar: for i, item in ipairs(compras) do.

Uma variável só: veio a posição, não o item 
local compras = {"pão", "leite", "café"}
for item in ipairs(compras) do
  print(item)
end

$ lua uma_var.lua
1
2
3

Sem erro, mas apareceram números em vez dos itens. A primeira variável do laço sempre recebe a posição, não importa o nome que você deu a ela. Como consertar: for _, item in ipairs(compras) do.

Escreveu = no lugar de in 
local compras = {"pão", "leite"}
for i, item = ipairs(compras) do
  print(i, item)
end

$ lua igual.lua
lua: igual.lua:2: 'in' expected near '='

"Era esperado in perto do =." O = é do for numérico (for i = 1, 10); com ipairs, a palavra é in. Como há duas variáveis (i, item), o Lua sabe que é o for genérico e exige o in.

Mudou a posição dentro do laço 
$ lua const_i.lua
lua: const_i.lua:4: attempt to assign to const variable 'i'

Visto na seção 6: no Lua 5.5, a variável de posição do for é constante. Como consertar: não mude o i; para pular um item, use goto continue; para mudar o item, use lista[i] = ….

Resumo

  • for i, item in ipairs(lista) do … end percorre a lista do item 1 em diante. A primeira variável é a posição; a segunda, o item.
  • Use _ no lugar da posição quando ela não interessa.
  • O ipairs para no primeiro nil: buracos cortam o laço. Ele ignora a posição 0 e as chaves de texto (para essas, pairs).
  • Com uma lista de fichas, a variável do item é a ficha inteira: p.nome, p.preco.
  • No Lua 5.5, a variável de posição é constante. Para mudar a lista, use lista[i] = novo.
  • ipairs(nil) dá attempt to index a nil value sem número de linha: procure a linha do seu programa no stack traceback.
