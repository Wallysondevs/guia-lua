Lua Estilo de Código

O Lua não liga se o seu programa está bonito ou feio: o mesmo código, todo torto ou todo arrumado, roda igual. Mas um programa é lido muito mais vezes do que é escrito, por outras pessoas e, principalmente, por você daqui a um mês. Estilo de código é o conjunto de combinados que deixa o programa fácil de ler: como indentar, como dar nomes, quando comentar. Esta aula reúne os combinados que o guia usou desde a primeira aula, com o porquê de cada um.

Você vai aprender
  • Indentação: o guia usa 2 espaços; a comunidade usa 2, 3 ou 4. O que importa é ser sempre igual.
  • local sempre, o defeito que uma global esquecida causa e dois jeitos de achar globais criadas sem querer.
  • Nomes claros: minusculas_com_sublinhado, CONSTANTES, o _ e por que sem acento.
  • Aspas simples ou duplas, espaços em volta dos operadores e uma instrução por linha.
  • Comentários que explicam o porquê, e os comentários de documentação --- que os editores entendem.

Os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), com lua arquivo.lua.

A ideia: a letra da receita

A avó da Ana tinha um caderno de receitas. Algumas eram escritas com capricho: o título em cima, os ingredientes em lista, um passo por linha. Outras eram rabiscadas na pressa, tudo emendado num parágrafo só, com abreviações que só ela entendia. As duas receitas faziam o mesmo bolo. Mas só a primeira dava para seguir sem errar.

O estilo de código é a "letra caprichada" do programa. Ele não muda o que o programa faz; muda o quanto custa entender o que ele faz, achar um defeito e mudar alguma coisa sem quebrar outra.

1. Indentação: os degraus do código

Indentar é empurrar uma linha para a direita com espaços, para mostrar que ela está dentro de outra coisa (de um if, de um for, de uma function). Olhe o mesmo programa de dois jeitos:

local notas={7,4,9,5}
for i=1,#notas do
if notas[i]>=6 then
print(i,"aprovada")
else
print(i,"reprovada")
end
end

local notas = { 7, 4, 9, 5 }
for i = 1, #notas do
  if notas[i] >= 6 then
    print(i, "aprovada")
  else
    print(i, "reprovada")
  end
end

$ lua baguncado.lua
1	aprovada
2	reprovada
3	aprovada
4	reprovada
$ lua arrumado.lua
1	aprovada
2	reprovada
3	aprovada
4	reprovada

A saída é idêntica. Para o Lua, quem diz onde um bloco começa e termina são as palavras do, then, else e end, não os espaços (veja Sintaxe e Blocos). A indentação é para você: no arrumado, cada end fica embaixo da linha que ele fecha, e dá para ver de longe que o print está dentro do if, que está dentro do for. No bagunçado, faltar um end passaria despercebido.

Quantos espaços?

Este guia usa 2 espaços por nível, em todos os programas. Na comunidade do Lua não existe uma regra oficial: você vai encontrar códigos com 2, 3 ou 4 espaços, e alguns com o caractere TAB. Todos estão certos. A regra que importa é outra:

  • Seja sempre igual dentro do mesmo arquivo (e do mesmo projeto). Misturar 2 e 4 espaços é pior do que qualquer um dos dois.
  • Num projeto dos outros, siga o estilo de lá. Se o projeto usa 4 espaços, você usa 4.
  • Não misture TAB com espaços. Um TAB aparece com tamanhos diferentes em editores diferentes, e o código que estava alinhado no seu fica torto no do colega.
Deixe o editor de texto fazer

Quase todo editor de programação tem uma configuração de "tamanho da indentação" e "usar espaços em vez de TAB". Configure uma vez (2 espaços, se quiser seguir o guia) e ele indenta sozinho quando você aperta Enter depois de um then ou de um do.

2. local sempre

Este é o combinado mais importante, e o único desta aula que muda o que o programa faz. Uma variável sem local é global: ela é a mesma para o programa inteiro, e qualquer função pode mexer nela sem avisar (veja local × Global). Olhe um defeito real que isso causa. A Ana quer desenhar um triângulo de estrelas:

local function linha(n)
  i = 1
  local s = ""
  while i <= n do
    s = s .. "*"
    i = i + 1
  end
  return s
end

i = 1
while i <= 3 do
  print(linha(i))
  i = i + 1
end

$ lua estrelas.lua
*
***

Sumiu a linha de 2 estrelas! O programa principal e a função linha usam o mesmo i global. Siga: o programa principal põe i = 1 e chama linha(1); lá dentro, o laço deixa o i valendo 2. Quando volta, o programa principal faz i = i + 1: o i vira 3, e ele chama linha(3) direto. O 2 foi pulado. Nenhuma mensagem de erro: só um resultado errado, que pode levar horas para ser achado num programa grande.

Missão: conserte o triângulo pondo local nas variáveis que devem ser só de cada parte do programa. Deve sair *, ** e ***.

local function linha(n)
  i = 1
  local s = ""
  while i <= n do
    s = s .. "*"
    i = i + 1
  end
  return s
end

i = 1
while i <= 3 do
  print(linha(i))
  i = i + 1
end

local function linha(n)
  local i = 1
  local s = ""
  while i <= n do
    s = s .. "*"
    i = i + 1
  end
  return s
end

local i = 1
while i <= 3 do
  print(linha(i))
  i = i + 1
end

Com local i nos dois lugares, cada parte tem o seu i, e uma não mexe no da outra. Por isso o guia escreve local em toda variável e em toda função (local function), a não ser quando existe um motivo claro para ser global. Além de evitar esse tipo de defeito, variável local é mais rápida para o Lua acessar.

Achando globais criadas sem querer

Jeito 1, em qualquer versão: o luac -l. O luac com -p -l mostra as instruções que o Lua gerou, sem rodar o programa. Toda vez que o programa guarda um valor numa global, aparece uma instrução SETTABUP com o nome dela:

$ luac -p -l estrelas.lua | grep SETTABUP
	3	[11]	SETTABUP 	0 0 1k	; _ENV "i" 1
	15	[14]	SETTABUP 	0 0 1	; _ENV "i"
	1	[2]	SETTABUP 	0 0 1k	; _ENV "i" 1
	13	[6]	SETTABUP 	0 0 2	; _ENV "i"

O número entre colchetes é a linha do arquivo: o programa grava na global i nas linhas 11, 14, 2 e 6. Se o seu programa é para ter zero globais, essa lista deveria sair vazia. (O _ENV é o "ambiente" onde moram as globais; veja _G e _ENV.)

Jeito 2, no Lua 5.5: a declaração global 5.5. Depois de uma declaração global, todo nome que não for local nem estiver declarado vira erro antes de o programa rodar:

global print
local function linha(n)
  i = 1
  local s = ""
  while i <= n do
    s = s .. "*"
    i = i + 1
  end
  return s
end
print(linha(3))

$ lua estrelas_global.lua
lua: estrelas_global.lua:3: variable 'i' not declared

A linha global print diz: "neste arquivo, a única global que eu uso é o print". Aí o i da linha 3, que não é local, vira o erro "variável i não declarada". Os detalhes estão em A Declaração global. (Funciona só no Lua 5.5; no 5.4 e antes, global é um nome comum e essa linha dá erro de sintaxe; veja as versões.)

3. Nomes

Um bom nome diz o que a variável guarda, sem precisar de comentário. Compare local x = 40 com local MAXIMO_DE_ALUNOS = 40. Os combinados mais comuns na comunidade, e os que o guia segue:

O quêComoExemplo
Variáveis e funçõesminúsculas, palavras separadas por _ (o estilo snake_case)nome_do_aluno, calcular_media
Valores que não mudam (constantes)MAIÚSCULAS com _MAXIMO_DE_ALUNOS, TAXA_DE_ENTREGA
"Classes" (tabelas que criam objetos)Primeira letra maiúsculaConta, Produto (veja Classes)
Verdadeiro/falsouma pergunta: tem_, esta_, pode_tem_estoque, esta_aberta
Um valor que você vai ignorarsó o sublinhado: _for _, valor in ipairs(lista)
Contadores de laço curtinhospode ser uma letrai, j, k, v
local MAXIMO_DE_ALUNOS = 40
local nome_do_aluno = "Bia"
local tem_estoque = true
for _, valor in ipairs({ "a", "b" }) do
  print(valor)
end
print(MAXIMO_DE_ALUNOS, nome_do_aluno, tem_estoque)

$ lua nomes.lua
a
b
40	Bia	true
  • Sem acento nos nomes. No Lua, local preço = 5 é erro de sintaxe (unexpected symbol near '<\195>'; veja Nomes de Variáveis). Escreva preco, acao. Dentro dos textos, acento pode à vontade.
  • Nome curto só em lugar curto. Um i num laço de 3 linhas é claro; um t que atravessa o programa inteiro, não.
  • Português ou inglês, mas um só. O guia usa português (preco, quantidade). Muitos projetos usam inglês. Misturar total_price com quantidade no mesmo arquivo confunde.
  • O MAIÚSCULAS é só um aviso para quem lê: o Lua não impede ninguém de mudar o valor. No 5.4 e no 5.5, para o Lua impedir, use local MAXIMO <const> = 40 (veja Constantes).

4. Aspas, espaços e uma coisa por linha

Aspas simples ou duplas?

No Lua, "texto" e 'texto' são exatamente a mesma coisa:

local a = "Olá, Ana"
local b = 'Olá, Ana'
print(a == b)
print('Ela disse "bom dia"')
print("It's ok")
print("Ela disse \"bom dia\"")

$ lua aspas.lua
true
Ela disse "bom dia"
It's ok
Ela disse "bom dia"

O combinado do guia: aspas duplas no dia a dia, e as simples quando o texto tem aspas duplas dentro ('Ela disse "bom dia"'), para não precisar do \" (veja Caracteres de Escape). Para textos de várias linhas, [[ … ]] (veja Textos Longos). Muitos projetos preferem as simples; de novo, o que vale é ser igual no projeto inteiro.

Espaços

  • Um espaço em volta dos operadores: total = preco * quantidade, não total=preco*quantidade.
  • Um espaço depois da vírgula: print(i, "aprovada").
  • Nas tabelas, o guia põe um espaço dentro das chaves: { 7, 4, 9 } e { nome = "Ana" }.
  • Linhas vazias separam as partes do programa, como parágrafos num texto.
  • Linhas não muito compridas (até umas 80 a 100 letras): uma linha que não cabe na tela esconde a parte do fim.

Uma instrução por linha, sem ponto e vírgula

local a = 1; local b = 2; print(a + b)
local c = 3 local d = 4 print(c + d)

$ lua pontovirgula.lua
3
7

O Lua aceita várias instruções na mesma linha, com ou sem ; entre elas. Aceitar não quer dizer que seja bom: a linha 2 é difícil de ler, e uma mensagem de erro que diz "linha 2" não diz qual das três instruções. O combinado: uma instrução por linha e nada de ; no fim (ele não faz falta no Lua).

Sair cedo

Em vez de empilhar if dentro de if, trate os casos especiais primeiro e saia com return. O caminho principal fica sem degraus:

local function situacao(nota)
  if type(nota) ~= "number" then
    return "nota inválida"
  end
  if nota >= 6 then
    return "aprovada"
  end
  return "reprovada"
end

print(situacao(7), situacao(3), situacao("dez"))

$ lua cedo.lua
aprovada	reprovada	nota inválida

5. Comentários

Comentários (-- até o fim da linha, --[[ … ]] para várias linhas; veja Comentários) são lidos por pessoas, nunca pelo Lua. Os combinados:

  • Explique o porquê, não o quê. total = total + 1 -- soma 1 no total não ajuda ninguém; o código já diz isso. -- a loja conta o pedido mesmo cancelado (pedido da contabilidade) diz algo que o código não diz.
  • Um bom nome economiza um comentário. Antes de escrever local t = 40 -- tempo em minutos, tente local tempo_em_minutos = 40.
  • Comentário velho é pior que nenhum. Mudou o código, mude o comentário.
  • Não deixe código "comentado" esquecido no arquivo: se não serve mais, apague.

Comentários de documentação: ---

Muitos projetos em Lua documentam as funções com comentários que começam com três tracinhos, num formato que os editores de programação entendem. O mais usado hoje é o do Lua Language Server (LuaLS), um programa que dá aos editores (como o VS Code e o Neovim) o autocompletar e os avisos de erro enquanto você digita. O formato se chama LuaCATS (Lua Comment And Type System, "sistema de comentários e tipos do Lua"):

--- Calcula o preço final de um produto, com desconto.
---@param preco number o preço cheio, em reais
---@param desconto number a porcentagem de desconto (0 a 100)
---@return number preco_final o preço com o desconto aplicado
local function preco_com_desconto(preco, desconto)
  return preco * (1 - desconto / 100)
end

print(preco_com_desconto(50, 10))

$ lua documentado.lua
45.0
--- Calcula o preço…
A descrição da função, em uma frase.
---@param preco number …
Um parâmetro: o nome (preco), o tipo (number) e uma explicação.
---@return number preco_final …
O que a função devolve: o tipo, um nome e uma explicação.

Para o Lua, essas linhas são comentários comuns (começam com --): o programa rodou normalmente e mostrou 45.0. Quem lê os ---@ é o editor com o LuaLS, que passa a mostrar a explicação quando você passa o mouse em preco_com_desconto e a avisar se alguém chamar a função com um texto no lugar do número. Esse comportamento do editor é ilustrativo aqui: o lab da Ana não tem um editor gráfico com o LuaLS, então não deu para mostrar a tela. As outras etiquetas mais comuns, segundo a documentação do LuaLS: ---@type (o tipo de uma variável), ---@class e ---@field (descrevem uma tabela com campos).

Ferramentas que arrumam e conferem o estilo

Existem programas que formatam o código sozinhos (o mais conhecido para Lua é o StyLua) e programas que apontam globais esquecidas, variáveis não usadas e outros deslizes (como o luacheck). Eles não vêm com o Lua e não estão no computador da Ana, por isso esta aula não mostra a saída deles. O luac -p -l e a declaração global da seção 2 fazem parte do trabalho e já estão aí.

Formas diferentes de fazer a mesma coisa

O mesmo programa, escrito "de qualquer jeito" e "com estilo":

t={4.5,12.9,7.25} s=0
for i=1,#t do s=s+t[i] end print("Total: R$ "..string.format("%.2f",s))

-- Soma os preços da lista de compras da Ana.
local precos = { 4.5, 12.9, 7.25 }

local total = 0
for _, preco in ipairs(precos) do
  total = total + preco
end

print(string.format("Total: R$ %.2f", total))

$ lua feio.lua
Total: R$ 24.65
$ lua bonito.lua
Total: R$ 24.65

O feio cria duas globais (t e s), não diz o que t guarda e esmaga três instruções numa linha. O bonito tem local, nomes que se explicam, um passo por linha e um comentário que diz para que serve o programa.

Quando dá errado

Um end a menos, escondido pela indentação torta 
local notas = { 7, 8.5, 10, 6 }
for i = 1, #notas do
  if notas[i] >= 7 then
    print(i, "aprovada")
  else
    print(i, "reprovada")
end

$ lua sintaxe.lua
lua: sintaxe.lua:8: 'end' expected (to close 'for' at line 2) near <eof>

"Era esperado um end (para fechar o for da linha 2) perto do fim do arquivo". O end da linha 7 está na coluna do for, então parece que fecha o for, mas quem ele fecha de verdade é o if. A indentação mentiu. Como consertar: o end do if com 2 espaços, embaixo do if, e mais um end na margem para o for. Com a indentação certa, a falta salta aos olhos.

Nome com acento 
$ printf 'local preço = 5\nprint(preço)\n' > acento.lua
$ lua acento.lua
lua: acento.lua:1: unexpected symbol near '<\195>'

"Símbolo inesperado perto de <\195>": o \195 é o primeiro byte do ç no computador. O Lua só aceita letras sem acento, números e _ nos nomes. Como consertar: preco.

A global esquecida

O triângulo de estrelas da seção 2: nenhuma mensagem, só uma linha a menos. Toda vez que um resultado "pula" ou muda sozinho, procure globais com luac -p -l arquivo.lua | grep SETTABUP.

Missão final: arrume o programa

Missão: este programa funciona, mas está escrito "de qualquer jeito". Reescreva no estilo da aula, sem mudar o resultado: local nas variáveis (a lista começa com local … = {), nomes claros, uma instrução por linha, e a função documentada com ---@param e ---@return.

function S(t) s=0 for i=1,#t do s=s+t[i] end return s end
t={4.5,12.9,7.25} print("Total: R$ "..string.format("%.2f",S(t)))

--- Soma todos os preços de uma lista.
---@param precos number[] a lista de preços
---@return number total a soma dos preços
local function somar(precos)
  local total = 0
  for _, preco in ipairs(precos) do
    total = total + preco
  end
  return total
end

local precos = { 4.5, 12.9, 7.25 }
print(string.format("Total: R$ %.2f", somar(precos)))

O number[] no ---@param é o jeito do LuaCATS de dizer "uma lista de números". No lab, a versão arrumada mostrou o mesmo Total: R$ 24.65 da bagunçada.

Resumo

  • Estilo não muda o que o programa faz (com uma exceção: o local); muda o quanto é fácil ler, achar defeitos e mudar.
  • Indentação: o guia usa 2 espaços; a comunidade usa 2, 3 ou 4. Seja sempre igual, siga o estilo do projeto e não misture TAB com espaços.
  • local sempre: uma global esquecida faz partes do programa mexerem nas variáveis umas das outras. Para achar: luac -p -l … | grep SETTABUP, ou a declaração global do 5.5.
  • Nomes: minusculas_com_sublinhado, CONSTANTES, Classes, _ para ignorar, sem acento.
  • Aspas simples e duplas são iguais; espaços em volta dos operadores; uma instrução por linha.
  • Comentários explicam o porquê; ---@param e ---@return (LuaCATS) documentam funções para o editor.
