Lua textos longos ([[ ]])

O menu da padaria, uma tela de ajuda, um poema, um desenho feito com letras: textos com várias linhas ficam ilegíveis com um \n atrás do outro (veja Caracteres de Escape). Para eles, o Lua tem um segundo jeito de escrever strings: entre colchetes duplos, [[ e ]]. O texto aparece no código exatamente como vai aparecer na tela.

Você vai aprender
  • Como escrever um texto de várias linhas com [[ … ]].
  • Por que a quebra de linha logo depois do [[ não conta.
  • Que dentro de [[ ]] a contrabarra é só uma letra (\n fica \n).
  • Os níveis [=[ … ]=], [==[ … ]==], para textos que têm ]] dentro.
  • O parentesco com o comentário de várias linhas, --[[ … ]].
  • Os erros reais: o texto longo que não fecha e o ]] que fecha antes da hora.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com lua arquivo.lua (veja Rodando um Programa). Você pode rodar cada um no editor do guia.

A ideia: colar uma folha inteira

As aspas comuns são como uma etiqueta: cabe uma linha. Para escrever algo maior numa etiqueta, você precisa de truques (o \n). Os colchetes duplos são como colar uma folha inteira no programa: o que estiver escrito entre o [[ e o ]], com as quebras de linha, os espaços e as aspas, vai do jeito que está. Sem truques, sem tradução.

1. O primeiro texto longo

local menu = [[
=== Padaria do Bairro ===
1 - Pão francês
2 - Pão de queijo
3 - Café
0 - Sair]]
print(menu)

$ lua menu.lua
=== Padaria do Bairro ===
1 - Pão francês
2 - Pão de queijo
3 - Café
0 - Sair
[[
Abre o texto longo: dois colchetes de abrir, colados.
(a quebra de linha logo depois do [[)
É descartada: o texto começa na linha de baixo, em ===. Isso deixa você escrever o [[ no fim da linha do local e começar o texto na linha seguinte, que é mais bonito. A seção 2 mostra a prova.
=== Padaria do Bairro === … 0 - Sair
O conteúdo, com as quebras de linha de verdade. Não precisa de \n.
]]
Fecha o texto: dois colchetes de fechar. Aqui ele está colado no Sair, então o texto termina sem quebra de linha no fim (o print põe a dele).

O resultado é uma string como outra qualquer: o type(menu) é string, e dá para guardar, juntar com .. e medir com #.

Missão: acrescente a opção 3 - Bolo de fubá no menu, numa linha nova, antes do 0 - Sair. Basta digitar a linha, sem \n.

local menu = [[

0 - Sair]]
print(menu)

2. As quebras de linha do começo e do fim

local a = [[
oi]]
local b = [[oi]]
print(a == b, #a, #b)
local c = [[oi
]]
print(#c)
print("[" .. c .. "]")

$ lua primeira.lua
true	2	2
3
[oi
]
  • a e b são iguais, com 2 letras cada: a quebra logo depois do [[ de a sumiu.
  • c tem 3 caracteres: o o, o i e a quebra de linha que vem antes do ]]. Essa não some.
  • Os colchetes em volta mostram onde o texto termina: o ] foi parar na linha de baixo.

Por isso, se você não quer uma linha em branco a mais no fim, cole o ]] na última linha do texto, como no menu. Se o texto vai para um arquivo, ou para o io.write, às vezes você quer essa quebra no fim; aí ponha o ]] sozinho na linha de baixo.

3. A contrabarra é só uma letra

Dentro de [[ ]], o Lua não interpreta nada: nem \n, nem \t, nem as aspas.

print([[Linha com \n e \t e "aspas" e 'apóstrofos']])
print([[C:\novo\tabela.txt]])

$ lua sem_escape.lua
Linha com \n e \t e "aspas" e 'apóstrofos'
C:\novo\tabela.txt

O caminho do Windows que virou bagunça na aula de Caracteres de Escape sai perfeito aqui, sem dobrar as contrabarras. E aspas dos dois tipos convivem em paz. A contrapartida: se você quiser um \n ou um \u{…} funcionando, use aspas comuns.

Um desenho feito com letras, com contrabarras e tudo, também sai do jeito que foi escrito:

print([[
  /\_/\
 ( o.o )
  > ^ <]])

$ lua desenho.lua
  /\_/\
 ( o.o )
  > ^ <

4. Os espaços também entram

"Do jeito que está" vale para os espaços do começo das linhas. Se o texto longo estiver dentro de uma função (veja Funções), a indentação do código entra no texto:

local function ajuda()
  local texto = [[
    Uso: lua padaria.lua [opção]
    -h   mostra esta ajuda]]
  print(texto)
end
ajuda()

$ lua indentado.lua
    Uso: lua padaria.lua [opção]
    -h   mostra esta ajuda

Os 4 espaços do começo de cada linha apareceram na tela. Se você não quer isso, escreva as linhas do texto encostadas na margem esquerda do arquivo, mesmo dentro da função. Repare também que o [opção], com um colchete só, não atrapalha: só ]], os dois colados, fecha o texto.

5. Textos com ]] dentro: os níveis

E se o texto precisar conter ]]? Por exemplo, um trecho de código Lua com t[a[1]]. Para isso, os colchetes aceitam sinais de igual no meio: [==[ abre um texto que só fecha com ]==], com a mesma quantidade de =. Os programadores chamam a quantidade de = de nível.

local codigo = [==[
local itens = {"pão", "leite"}
print(itens[#itens])
local x = t[a[1]]
]==]
io.write(codigo)

$ lua nivel.lua
local itens = {"pão", "leite"}
print(itens[#itens])
local x = t[a[1]]
[==[
Abre um texto longo de nível 2 (dois sinais de igual).
t[a[1]]
O ]] aqui dentro é só texto: ele não tem os dois =, então não fecha nada.
]==]
Fecha o texto: dois =, igual à abertura. Um ]=] ou um ]===] também não fechariam.
io.write(codigo)
O io.write não acrescenta quebra de linha (veja io.write()); a última quebra do texto, antes do ]==], já está lá dentro.

Pode usar quantos = quiser: [=[ … ]=], [===[ … ]===]… O [[ ]] sem nenhum é o nível 0. Escolha um nível que não apareça dentro do texto.

Missão: este programa para com um erro, porque o ]] de t[a[1]] fecha o texto antes da hora. Troque o [[ por [==[ e o ]] do fim por ]==].

local codigo = [[
local x = t[a[1]]
print(x)
]]
print(codigo)

local codigo = [==[
local x = t[a[1]]
print(x)
]==]
print(codigo)

6. O parente conhecido: o comentário --[[ ]]

Você já viu os colchetes duplos na aula de Comentários: o comentário de várias linhas é um -- seguido de um texto longo. As mesmas regras valem, inclusive os níveis:

--[[
Este programa calcula o troco.
Escrito pela Ana.
]]
print("Troco: " .. 20 - 13.5)
--[==[
print("isto não roda")
]==]

$ lua comentario.lua
Troco: 6.5

O segundo comentário "desliga" uma linha de código; se o trecho desligado tiver ]] dentro (um t[a[1]]), o nível [==[ evita que o comentário termine no meio.

7. No modo interativo

No > do Lua (veja O Modo Interativo), um texto longo de uma linha funciona normalmente. Com várias linhas, guarde numa variável: o Lua mostra o >> enquanto o texto não fecha.

$ lua
Lua 5.5.0  Copyright (C) 1994-2025 Lua.org, PUC-Rio
> [[oi]]
oi
> x = [[linha 1
>> linha 2]]
> print(x)
linha 1
linha 2
> os.exit()

Uma curiosidade: digitar o texto de várias linhas sozinho, sem x = nem print, dá erro no modo interativo. O truque do > de mostrar o valor de uma expressão só funciona quando ela cabe na primeira linha:

$ lua
Lua 5.5.0  Copyright (C) 1994-2025 Lua.org, PUC-Rio
> [[linha 1
>> linha 2]]
stdin:2: unexpected symbol near '[[linha 1
linha 2]]'
> os.exit()

Formas diferentes de fazer a mesma coisa

As três strings deste programa são idênticas:

local a = "linha 1\nlinha 2"
local b = [[
linha 1
linha 2]]
local c = "linha 1\
linha 2"
print(a == b, b == c)

$ lua igualzinho.lua
true	true

Um texto longo também combina bem com o string.format (aula string.format): você escreve o "molde" com várias linhas e preenche as lacunas depois.

local recibo = [[
Cliente: %s
Total:   R$ %.2f]]
print(string.format(recibo, "Ana", 13.5))

$ lua formatado.lua
Cliente: Ana
Total:   R$ 13.50

Contando um texto longo

As quebras de linha contam no tamanho, e acentos contam como 2 bytes (veja O Operador de Tamanho):

local poema = [[
Batatinha quando nasce
espalha a rama pelo chão]]
print(#poema, utf8.len(poema))

$ lua conta.lua
48	47

22 letras e espaços na primeira linha, 1 quebra de linha e 24 caracteres na segunda (47); o ã de "chão" ocupa 2 bytes (48).

Quando dá errado

Esqueceu de fechar o texto longo 
local texto = [[
Bom dia,
Ana
print(texto)

$ lua aberta.lua
lua: aberta.lua:5: unfinished long string (starting at line 1) near <eof>

Linha por linha:

lua: aberta.lua:5:
O Lua só percebeu o problema na linha 5, que é o fim do arquivo (o arquivo tem 4 linhas e termina com uma quebra de linha).
unfinished long string
"Texto longo não terminado": nenhum ]] apareceu até o fim.
(starting at line 1)
"(começando na linha 1)": o Lua diz onde o texto abriu. É lá que você deve olhar.
near <eof>
"Perto do fim do arquivo" (end of file).

Repare que o print(texto) virou parte do texto: tudo depois do [[ foi engolido. É erro de sintaxe; o programa nem começa. Como consertar: feche com ]] depois de Ana.

Abriu e fechou com níveis diferentes 
local texto = [==[
Bom dia
]=]
print(texto)

$ lua nivel_errado.lua
lua: nivel_errado.lua:5: unfinished long string (starting at line 1) near <eof>

A mesma mensagem: o ]=] (um =) não fecha um texto aberto com [==[ (dois). Como consertar: conte os sinais de igual dos dois lados.

O ]] do meio fechou o texto antes da hora 
local codigo = [[
local x = t[a[1]]
print(x)
]]
print(codigo)

$ lua fecha_cedo.lua
lua: fecha_cedo.lua:4: unexpected symbol near ']'

"Símbolo inesperado perto de ]". O texto terminou no primeiro ]], o de t[a[1]] (linha 2). Para o Lua, a linha 3, print(x), passou a ser código de verdade, e o ]] da linha 4 ficou sobrando, sem nada que ele feche. A mensagem aponta a linha 4, mas o problema está na linha 2. Como consertar: use um nível: [==[ … ]==] (seção 5).

Esperava que o \n funcionasse

Não é erro, é surpresa: print([[a\nb]]) mostra a\nb, com a contrabarra e o n. Dentro de [[ ]] não há escapes (seção 3). Como consertar: quebre a linha de verdade dentro do texto, ou use aspas: "a\nb".

Resumo

  • [[ … ]] escreve um texto com várias linhas, do jeito que está: quebras de linha, espaços, aspas e contrabarras entram como foram digitados.
  • A quebra de linha logo depois do [[ é descartada; a de antes do ]], não.
  • Dentro de [[ ]] não há escapes: \n fica \n.
  • Para textos com ]] dentro, use níveis: [==[ … ]==], com a mesma quantidade de = nos dois lados.
  • O comentário --[[ … ]] segue as mesmas regras.
  • Erros: unfinished long string (starting at line N) (faltou fechar) e unexpected symbol near ']' (fechou antes da hora).
