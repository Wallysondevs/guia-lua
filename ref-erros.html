Lua Mensagens de Erro Comuns

Esta é a página de consulta das mensagens de erro que mais aparecem para quem está começando no Lua 5.5. O Lua escreve as mensagens em inglês. Para cada uma, aqui estão: um programa curto que a produz, a mensagem exata que o Lua escreveu, o que ela quer dizer em português e como resolver. Todas foram colhidas rodando cada programa como main.lua no computador da Ana (lua main.lua). A aula que ensina a ler uma mensagem passo a passo é Lendo uma Mensagem de Erro.

As partes de uma mensagem

local nomes = {"Ana", "Bia"}
pirnt(nomes[1])

$ lua main.lua
lua: main.lua:2: attempt to call a nil value (global 'pirnt')
stack traceback:
	main.lua:2: in main chunk
	[C]: in ?
$ echo $?
1
lua:
Quem está falando: o programa lua.
main.lua:2:
Onde: o arquivo e a linha (aqui, a linha 2). Comece sempre por aqui.
attempt to call a nil value
O quê: "tentativa de chamar um valor nil". O programa tentou usar como função algo que não existe.
(global 'pirnt')
Qual nome: a variável global pirnt. É o print escrito errado.
stack traceback:
O "caminho" até o erro (stack traceback = "rastro da pilha de chamadas"), do mais recente para o mais antigo. in main chunk é o corpo do arquivo; [C]: in ? é o próprio programa lua, que rodou o arquivo. Quando o erro acontece dentro de uma função, aparece uma linha para cada função, como in local 'soma'.
echo $? → 1
O código de saída: 1 quer dizer "terminou com erro".
Dois tipos de erro
  • Erro de sintaxe (o texto do programa está malformado): o Lua avisa antes de rodar qualquer linha, e a mensagem vem sem o stack traceback:. Nada do programa é executado, nem as linhas antes do erro.
  • Erro de execução (o texto está certo, mas algo deu errado rodando): as linhas antes do erro já rodaram, e a mensagem vem com o stack traceback:.

No modo interativo, o lugar aparece como stdin:1: em vez de main.lua:2:.

Pule direto para o grupo que você procura:

  • Erros com nil (os mais comuns): call a nil value, index a nil value, arithmetic on a nil value, concatenate a nil value…
  • Tipo errado: attempt to add a 'string', compare number with string, call a table value, bad argument…
  • Erros de sintaxe: 'end' expected, 'then' expected, unexpected symbol, unfinished string…
  • Erros do 5.5 (for, global, <const>) e do goto
  • Arquivos e módulos: No such file or directory, closed file, module not found
  • Recursão sem fim: stack overflow, C stack overflow
  • Erros lançados pelo programa: error, assert, Ctrl+C

Erros com nil

Quase todo erro de quem está começando é um nil onde não devia: um nome escrito errado, uma variável que ficou sem valor, um campo que não existe. A parte entre parênteses no fim da mensagem diz qual nome era nil: global 'x' (variável global), local 'x' (variável local), field 'x' (campo de tabela, t.x), method 'x' (método, t:x()), upvalue 'x' (variável de fora da função).

Quando dá errado: a mensagem aparece "antes" do texto

Este programa escreve um texto com io.write (sem pular linha) e só depois dá erro:

local itens = {pao = 2}
io.write("Total de leite: ")
print(itens.leite * 3)

$ lua ordem.lua
lua: ordem.lua:3: attempt to perform arithmetic on a nil value (field 'leite')
stack traceback:
        ordem.lua:3: in main chunk
        [C]: in ?
Total de leite: $

O Total de leite: apareceu depois da mensagem de erro, colado no $. Motivo: o texto normal (a saída padrão) fica guardado na memória até a linha terminar, e a mensagem de erro (a saída de erros) é escrita na hora; o texto guardado só sai quando o lua fecha. Isso confunde: parece que o erro aconteceu antes do io.write. Quando a ordem importa, use print (que termina a linha) ou chame io.flush() depois do io.write. No editor do guia, a ordem pode sair diferente.

Experimente

Missão: rode o programa: ele para com attempt to perform arithmetic on a nil value (field '?') na linha 5. O "cafe" do pedido não está no estoque, então estoque[item] vale nil. Troque estoque[item] por (estoque[item] or 0): o que não existe conta como zero. O resultado certo é Total em estoque: 15.

local estoque = {pao = 10, leite = 5}
local pedido = {"pao", "cafe", "leite"}
local total = 0
for _, item in ipairs(pedido) do
  total = total + estoque[item]
end
print("Total em estoque: " .. total)

local estoque = {pao = 10, leite = 5}
local pedido = {"pao", "cafe", "leite"}
local total = 0
for _, item in ipairs(pedido) do
  total = total + (estoque[item] or 0)
end
print("Total em estoque: " .. total)

Livre: o pcall captura o erro sem parar o programa e devolve a mensagem. Troque o código dentro de cada função para provocar outros erros desta página e leia as mensagens.

local function testar(f)
  local ok, mensagem = pcall(f)
  print(ok, mensagem)
end

testar(function() local t = nil; return t.campo end)
testar(function() return "abc" + 1 end)
testar(function() return "Total: " .. nil end)
testar(function() return #42 end)
testar(function() return 1 < "2" end)
testar(function() error("deu ruim") end)

Resumo

  • Leia a mensagem em três partes: onde (main.lua:2:), o quê (attempt to …) e qual nome ((global 'x'), (local 'x'), (field 'x')).
  • Erro de sintaxe vem sem stack traceback: e nada roda; erro de execução vem com ele.
  • Os campeões: attempt to call a nil value (nome errado), attempt to index a nil value (tabela que não existe), attempt to perform arithmetic / concatenate a nil value (variável sem valor).
  • De sintaxe: 'end' expected (falta end), <eof> expected (sobra end), 'then' expected, unexpected symbol, unfinished string.
  • 5.5 attempt to assign to const variable 'i' (a variável do for) e variable 'print' not declared (depois de um global) são novos.
