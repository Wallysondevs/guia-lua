Lua Funções Variádicas (...)

Repare no print: ele aceita um valor, print("oi"), ou cinco, print(1, 2, 3, 4, 5), ou nenhum, print(). O math.max também: math.max(3, 9, 4) acha o maior de quantos números você mandar. Funções assim, que aceitam quantos argumentos vierem, se chamam variádicas (de "variável": a quantidade varia). Nesta aula você vai escrever as suas, com os três pontinhos ....

Você vai aprender
  • A criar uma função com ... e a passar os argumentos adiante.
  • A guardar os argumentos numa tabela com {...} e percorrê-los com ipairs.
  • A misturar parâmetros fixos com ... (e por que o ... vem por último).
  • A repassar ... para outras funções, como print e string.format.
  • O problema do nil no meio dos argumentos, e as soluções: select("#", ...) e table.pack(...).
  • A tabela com nome ...nome, novidade do Lua 5.5.
  • Os erros reais: cannot use '...' outside a vararg function e outros.

A ideia: a sacola de compras

A ficha de pedido da aula Parâmetros e Argumentos tinha um número fixo de espaços: um para o produto, um para a quantidade. Mas a sacola de compras da Ana é diferente: num dia cabem dois itens, no outro, dez. Ninguém sabe antes quantos vão entrar.

O ... é essa sacola. Na definição da função, ele diz: "pode mandar quantos argumentos quiser, eu levo todos". Dentro da função, ... é o conteúdo da sacola, tudo junto.

1. A primeira função com ...

local function ver(...)
  print("recebi:", ...)
end

ver("Ana")
ver("Ana", "Bia", 3)
ver()

$ lua ver.lua
recebi:	Ana
recebi:	Ana	Bia	3
recebi:
function ver(...)
Os três pontos no lugar dos parâmetros: a função aceita qualquer quantidade de argumentos, até zero. Os três pontos são escritos juntos, sem espaço.
print("recebi:", ...)
Dentro da função, ... vale todos os argumentos recebidos, na ordem, como uma lista de valores separados por vírgula. Aqui eles vão direto para o print: ver("Ana", "Bia", 3) vira print("recebi:", "Ana", "Bia", 3).
ver()
Sem argumentos, ... não vale nada (zero valores), e o print só mostra recebi:.

O ... se comporta como uma chamada que devolve vários valores (aula Vários Retornos): no fim de uma lista, entram todos.

2. Guardando os argumentos numa tabela: {...}

Para fazer alguma coisa com cada argumento (somar, contar, mostrar um por um), o jeito mais comum é colocar o ... dentro de uma tabela e percorrê-la:

local function somar(...)
  local total = 0
  for _, valor in ipairs({...}) do
    total = total + valor
  end
  return total
end

print(somar(1, 2))
print(somar(10, 20, 30, 40))
print(somar(5))
print(somar())

$ lua somar.lua
3
100
5
0
{...}
Uma tabela nova com todos os argumentos: somar(10, 20, 30, 40) faz {10, 20, 30, 40}. É uma lista comum (aula Tabelas como Listas).
for _, valor in ipairs({...}) do
Percorre a lista item por item (aula ipairs); o _ ignora a posição.
somar()
Sem argumentos, a tabela fica vazia, o laço não roda nenhuma vez e o total continua 0.

Missão: a função maior só olha os dois primeiros números, e por isso diz que o maior é 15. Troque os parâmetros por ... e percorra todos os números com ipairs({...}), para ela achar o 42.

local function maior(a, b)
  if a > b then
    return a
  end
  return b
end

print("Maior: " .. maior(7, 15, 42, 3))

local function maior(...)
  local lista = {...}
  local resposta = lista[1]
  for _, n in ipairs(lista) do
    if n > resposta then
      resposta = n
    end
  end
  return resposta
end

print("Maior: " .. maior(7, 15, 42, 3))

3. Parâmetros fixos antes do ...

Uma função pode ter alguns parâmetros com nome e, depois deles, o ... para o resto. Os primeiros argumentos preenchem os parâmetros fixos; o que sobrar vai para o ...:

local function anunciar(loja, ...)
  print("== " .. loja .. " ==")
  for i, produto in ipairs({...}) do
    print(i .. ". " .. produto)
  end
end

anunciar("Padaria Pão Quente", "pão francês", "sonho", "bolo de milho")
anunciar("Mercadinho da Esquina", "arroz")

$ lua fixo_e_resto.lua
== Padaria Pão Quente ==
1. pão francês
2. sonho
3. bolo de milho
== Mercadinho da Esquina ==
1. arroz

Na primeira chamada, loja recebeu "Padaria Pão Quente" e o ... ficou com os três produtos. O ... tem de ser o último da lista de parâmetros: function f(..., ultimo) é erro de sintaxe (veja em Quando dá errado). Faz sentido: se a sacola leva tudo o que sobra, não sobra nada para um parâmetro depois dela.

Pegando os primeiros: local a, b = ...

O ... também pode ir para uma atribuição. As regras de sempre valem: o que sobra é descartado, o que falta vira nil.

local function primeiros(...)
  local a, b = ...
  print("a =", a, "b =", b)
end

primeiros(10, 20, 30)
primeiros(10)

$ lua atribuir.lua
a =	10	b =	20
a =	10	b =	nil

4. Repassando o ... para outra função

Um uso muito comum: uma função que acrescenta alguma coisa e passa todo o resto, intacto, para outra. Por exemplo, um print com um prefixo:

local function log(...)
  print("[padaria]", ...)
end

log("abriu às", 6, "horas")
log("vendidos:", 120, "pães", "e", 8, "bolos")

$ lua repassar.lua
[padaria]	abriu às	6	horas
[padaria]	vendidos:	120	pães	e	8	bolos

Ou um aviso que usa o string.format (aula string.format), ele mesmo uma função variádica:

local function avisar(formato, ...)
  print("AVISO: " .. string.format(formato, ...))
end

avisar("faltam %d pães", 12)
avisar("%s pediu %d %s", "Bia", 3, "sonhos")

$ lua formatar.lua
AVISO: faltam 12 pães
AVISO: Bia pediu 3 sonhos

A função avisar não precisa saber quantos valores o formato pede: ela só repassa o que recebeu.

5. O problema do nil no meio

O {...} com ipairs funciona muito bem, menos quando um dos argumentos é nil. O ipairs para no primeiro nil:

local function mostrar(...)
  for i, v in ipairs({...}) do
    print(i, v)
  end
end

mostrar("Ana", nil, 42)

$ lua ipairs_para.lua
1	Ana

O 42 sumiu. E o # (o tamanho da lista) também não é confiável com buracos (aula Sequências e Buracos). Para saber quantos argumentos chegaram de verdade, contando os nil, existe o select("#", ...):

local function contar(...)
  local lista = {...}
  print("com #:", #lista, "com select:", select("#", ...))
end

contar(1, 2, 3)
contar()
contar(nil, nil)
contar(1, nil, 3)

$ lua contar.lua
com #:	3	com select:	3
com #:	0	com select:	0
com #:	0	com select:	2
com #:	1	com select:	3
select("#", ...)
A função select com o primeiro argumento "#" (o texto com o jogo da velha) devolve quantos valores vieram depois dele. Conta os nil também.
contar(nil, nil)
Dois argumentos, os dois nil: o # diz 0, o select diz 2.
contar(1, nil, 3)
Aqui o # deu 1 no Lua 5.5; no lua5.1, o mesmo programa deu 3. Com um buraco no meio, as duas respostas são "permitidas", e por isso não dá para confiar no #. O select deu 3, o certo.

O select tem outros usos (pegar os argumentos a partir de uma posição): eles estão na aula select e o Número de Argumentos.

table.pack: a tabela que guarda a contagem

O table.pack(...) faz uma tabela com os argumentos, como o {...}, e ainda guarda a quantidade num campo n:

local function mostrar(...)
  local args = table.pack(...)
  print("chegaram " .. args.n .. " argumentos")
  for i = 1, args.n do
    print(i, args[i])
  end
end

mostrar("Ana", nil, 42)

$ lua pack.lua
chegaram 3 argumentos
1	Ana
2	nil
3	42

Com for i = 1, args.n (um for numérico até a contagem certa), nenhum argumento se perde, nem o nil. Mais sobre ele em table.unpack e table.pack.

Experimente: rode e compare as duas contagens. Depois troque a chamada por contar("pão", false, "leite"): o false é um valor normal, não um buraco, e as duas contagens concordam.

local function contar(...)
  local lista = {...}
  print("com #:", #lista, "com select:", select("#", ...))
  local args = table.pack(...)
  for i = 1, args.n do
    print(i, args[i])
  end
end

contar("pão", nil, "leite")

6. Lua 5.5: a sacola com nome, ...nome 5.5

O Lua 5.5 trouxe um atalho: escrever um nome logo depois dos três pontos. Esse nome passa a ser uma tabela com os argumentos e o campo n, como a do table.pack, sem precisar criá-la à mão:

local function somar(...numeros)
  local total = 0
  for i = 1, numeros.n do
    total = total + numeros[i]
  end
  return total
end

print(somar(1, 2, 3))
print(somar())

$ lua nomeado.lua
6
0
...numeros
Os três pontos e, colado neles, um nome. Dentro da função, numeros é a tabela dos argumentos extras, e numeros.n diz quantos são (contando os nil). O ... continua funcionando junto.
somente leitura
O manual do Lua 5.5 diz que esse nome é uma variável local somente de leitura: numeros = {} dá erro (veja em Quando dá errado).
E nas outras versões?

O ...nome só existe no Lua 5.5. No lua5.4, o mesmo arquivo dá lua5.4: nomeado.lua:1: ')' expected near 'numeros'. Se o seu código precisa rodar em versões antigas, use table.pack(...), que existe desde o 5.2 e no LuaJIT. No Lua 5.1 puro não há table.pack (attempt to call field 'pack' (a nil value)); lá, use select("#", ...), que existe em todas. Mais em As Diferenças entre Versões.

7. O ... do programa principal

O arquivo inteiro também é tratado pelo Lua como uma função variádica. No programa principal (fora de qualquer função), ... são os argumentos da linha de comando:

print("argumentos do programa:", ...)
print("quantos:", select("#", ...))

$ lua principal.lua Ana 42 "Bia Lima"
argumentos do programa:	Ana	42	Bia Lima
quantos:	3
$ lua principal.lua
argumentos do programa:
quantos:	0

(As aspas fizeram "Bia Lima" chegar como um argumento só. A tabela arg guarda os mesmos valores: aula Argumentos da Linha de Comando.)

Usar ... numa função que não tem ... 
local function somar()

  return total

$ lua fora2.lua
lua: fora2.lua:3: cannot use '...' outside a vararg function near '...'

cannot use '...' outside a vararg function near '...': "não dá para usar ... fora de uma função variádica (vararg)". A função foi definida com () vazio, então ela não tem sacola nenhuma. É erro de sintaxe: o Lua recusa o arquivo antes de rodar, por isso não há stack traceback. Como consertar: local function somar(...).

Um parâmetro depois do ... 
local function f(..., ultimo)
end

$ lua meio.lua
lua: meio.lua:1: ')' expected near ','

')' expected near ',': depois do ..., o Lua só aceita o ). Como consertar: os parâmetros fixos vêm antes: local function f(primeiro, ...).

O ... no meio de uma lista: só o primeiro passa 
local function ver(...)
  print(..., "fim")
  print((...))
end
ver("a", "b", "c")

$ lua corte.lua
a	fim
a

Sem erro, mas o "b" e o "c" sumiram. É a regra de ajuste da aula Vários Retornos: fora do fim da lista, ou entre parênteses, o ... entrega só o primeiro valor. Como consertar: deixe o ... por último (print("início", ...)) ou guarde numa tabela antes.

O argumento depois do nil sumiu

Sem erro: ipairs({...}) parou no primeiro nil (seção 5). Como consertar: use table.pack(...) e for i = 1, t.n do, ou o ...nome do 5.5.

Trocar a tabela com nome 5.5 
local function f(...args)
  args = {}
end

$ lua nomeado_ro.lua
lua: nomeado_ro.lua:2: attempt to assign to const variable 'args'

attempt to assign to const variable 'args': "tentativa de atribuir a uma variável constante". O nome do ...args é só de leitura. Como consertar: crie outra variável: local copia = {}.

Zero argumentos numa função que precisa de pelo menos um 
print(math.max(3, 9, 4), math.min(3, 9, 4))
print(string.format("%s tem %d anos", "Ana", 30))
print(math.max())

$ lua maior.lua
9	3

stack traceback:

	maior.lua:3: in main chunk

O math.max é variádico, mas exige ao menos um número: bad argument #1 to 'max' (value expected), "faltou o argumento nº 1 (esperava um valor)". Nas suas funções, faça o mesmo cuidado: confira select("#", ...) == 0 e devolva nil, "mensagem", como em:

local function media(...)
  local n = select("#", ...)
  if n == 0 then
    return nil, "nenhuma nota"
  end
  local soma = 0
  for _, nota in ipairs({...}) do
    soma = soma + nota
  end
  return soma / n
end

print(media(7, 8, 9))
print(media())

$ lua media.lua
8.0
nil	nenhuma nota

Missão final: as vendas do dia

Missão: a função vendas recebe o nome do dia e, depois, o valor de cada venda (quantas forem). Ela deve mostrar quantas vendas houve e o total. Acrescente o ... nos parâmetros, some os valores e conte-os.

local function vendas(dia)
  local quantas = 0
  local total = 0
  -- complete aqui
  print(dia .. ": " .. quantas .. " vendas, total " .. total)
end

vendas("segunda", 10, 20, 15)
vendas("terça")
vendas("quarta", 18)

local function vendas(dia, ...)
  local quantas = select("#", ...)
  local total = 0
  for _, valor in ipairs({...}) do
    total = total + valor
  end
  print(dia .. ": " .. quantas .. " vendas, total " .. total)
end

vendas("segunda", 10, 20, 15)
vendas("terça")
vendas("quarta", 18)

Resumo

  • Uma função com ... nos parâmetros aceita quantos argumentos vierem, até nenhum.
  • Parâmetros fixos vêm antes: function f(a, ...). Nada pode vir depois do ....
  • Dentro da função, ... são os argumentos: repasse com print("x", ...), guarde com {...} ou local a, b = ....
  • {...} + ipairs é o caminho comum, mas para no primeiro nil. Para contar certo: select("#", ...); para guardar com a contagem: table.pack(...) e o campo n.
  • No Lua 5.5, function f(...args) já dá a tabela com args.n (somente leitura).
  • ... fora de uma função variádica: cannot use '...' outside a vararg function.
  • Próxima aula: as funções também são valores, que se guardam em variáveis e tabelas: Funções São Valores.
