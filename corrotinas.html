Lua Corrotinas

Uma função comum, quando é chamada, vai do começo ao fim de uma vez só. Uma corrotina (em inglês, coroutine) é uma função que pode pausar no meio, devolver o controle para quem a chamou, e depois continuar exatamente de onde parou, com todas as variáveis do jeito que estavam. É um dos recursos mais poderosos do Lua: os jogos usam corrotinas para animações que duram vários quadros, os editores (como o Neovim) para tarefas que esperam alguma coisa, e muita gente para escrever iteradores e "produtores" de dados de um jeito simples.

Você vai aprender
  • Criar uma corrotina (coroutine.create), começar e continuar (coroutine.resume) e pausar (coroutine.yield).
  • Passar valores nos dois sentidos: o que o yield entrega e o que o resume manda de volta.
  • Os quatro estados de uma corrotina (coroutine.status): suspended, running, normal e dead.
  • O que acontece com um erro dentro de uma corrotina, e como encerrá-la antes do fim com coroutine.close.
  • As mensagens reais: cannot resume dead coroutine, attempt to yield from outside a coroutine e outras.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), na pasta pessoal dela, com lua arquivo.lua. Você precisa conhecer funções e funções como valores.

A ideia: o marcador de página

A Ana está lendo um livro de receitas. No meio do capítulo de bolos, o telefone toca. Ela põe um marcador na página, atende, resolve o que precisa, e depois abre o livro no marcador: continua da mesma linha, lembrando de tudo o que já leu.

Uma corrotina é o livro com marcador:

  • coroutine.yield ("ceder", "dar a vez") é pôr o marcador e fechar o livro: a corrotina pausa ali.
  • coroutine.resume ("retomar") é abrir no marcador: a corrotina continua da linha seguinte ao yield.

Importante: só uma coisa acontece de cada vez. Enquanto a Ana lê, ela não está ao telefone, e vice-versa. As corrotinas do Lua são assim: não rodam ao mesmo tempo; elas se revezam, e cada uma decide quando dar a vez (é por isso que o manual as chama de "multitarefa colaborativa").

1. A primeira corrotina

local co = coroutine.create(function ()
  print("passo 1")
  coroutine.yield()
  print("passo 2")
  coroutine.yield()
  print("passo 3")
end)
print(type(co), coroutine.status(co))
coroutine.resume(co)
print("-- a corrotina parou; o programa principal continua")
coroutine.resume(co)
print("-- de novo")
coroutine.resume(co)
print(coroutine.status(co))
coroutine.create(function () … end)
Cria a corrotina a partir de uma função (o corpo dela). Criar não roda nada: o livro está fechado, com o marcador na primeira página. O valor devolvido é do tipo thread ("linha de execução").
coroutine.yield()
Dentro do corpo: "pause aqui e devolva o controle a quem me retomou".
coroutine.resume(co)
No programa principal: "rode a corrotina co até ela pausar ou terminar". Na primeira vez, começa do início do corpo.
coroutine.status(co)
Diz em que estado ela está: suspended (pausada, ou ainda não começou), running (rodando), normal ou dead (terminou). Os estados estão explicados na seção 4.
$ lua co1.lua
thread	suspended
passo 1
-- a corrotina parou; o programa principal continua
passo 2
-- de novo
passo 3
dead

Siga a ordem das linhas: o primeiro resume rodou o corpo até o primeiro yield (passo 1), e o controle voltou ao programa principal, que mostrou a linha --. O segundo resume continuou depois do primeiro yield (passo 2). O terceiro foi até o fim do corpo (passo 3), e aí a corrotina "morreu": dead.

O que o resume responde

O resume devolve true quando deu tudo certo, e false com uma mensagem quando não deu. Uma corrotina morta não volta:

local co = coroutine.create(function ()
  coroutine.yield()
end)
print(coroutine.resume(co))
print(coroutine.resume(co))
print(coroutine.resume(co))
print(coroutine.status(co))

$ lua co2.lua
true
true
false	cannot resume dead coroutine
dead

Primeiro resume: rodou até o yield (true). Segundo: continuou do yield até o fim do corpo (true; agora ela está morta). Terceiro: false e cannot resume dead coroutine, "não dá para retomar uma corrotina morta". Repare que isso não é um erro que derruba o programa: o resume só devolveu false, e o programa continuou até o último print.

2. Passando valores: o yield entrega, o resume responde

O yield e o resume são uma conversa. O que a corrotina passa para o yield sai no resume de quem a chamou. E o que o programa principal passa para o próximo resume sai como resultado daquele yield, dentro da corrotina:

local fornada = coroutine.create(function (sabor)
  print("assando pão de " .. sabor)
  local pedido = coroutine.yield("primeira fornada pronta")
  print("cliente pediu: " .. pedido)
  local outro = coroutine.yield("segunda fornada pronta")
  print("cliente pediu: " .. outro)
  return "padaria fechada"
end)
print(coroutine.resume(fornada, "queijo"))
print(coroutine.resume(fornada, "6 pães"))
print(coroutine.resume(fornada, "2 pães"))
print(coroutine.resume(fornada, "mais 1"))

$ lua co3.lua
assando pão de queijo
true	primeira fornada pronta
cliente pediu: 6 pães
true	segunda fornada pronta
cliente pediu: 2 pães
true	padaria fechada
false	cannot resume dead coroutine

Passo a passo:

ChamadaNa corrotinaO resume devolveu
resume(fornada, "queijo")Começa: "queijo" vira o parâmetro sabor. Roda até o 1º yield.true, "primeira fornada pronta" (o que foi para o yield)
resume(fornada, "6 pães")O 1º yield "volta" valendo "6 pães", que vai para pedido. Roda até o 2º yield.true, "segunda fornada pronta"
resume(fornada, "2 pães")O 2º yield vale "2 pães" (outro). Roda até o return.true, "padaria fechada" (o que o return devolveu)
resume(fornada, "mais 1")Nada: ela já terminou.false, "cannot resume dead coroutine"

O yield também funciona de dentro de outras funções que o corpo chamou. A pausa congela a pilha inteira:

local function ajudante(x)
  coroutine.yield("ajudante pausou com " .. x)
  return x * 2
end
local co = coroutine.create(function ()
  local r = ajudante(5)
  return "fim: " .. r
end)
print(coroutine.resume(co))
print(coroutine.resume(co))

$ lua co15.lua
true	ajudante pausou com 5
true	fim: 10

Missão: o programa chama resume 4 vezes, mas o forno só tem duas fornadas e o return, então a 4ª chamada dá false e cannot resume dead coroutine. Acrescente uma terceira fornada ("fornada 3") ao corpo, para as 4 chamadas darem certo e a última mostrar forno desligado.

local forno = coroutine.create(function ()
  coroutine.yield("fornada 1")
  coroutine.yield("fornada 2")
  return "forno desligado"
end)
for i = 1, 4 do
  print(coroutine.resume(forno))
end

local forno = coroutine.create(function ()
  coroutine.yield("fornada 1")
  coroutine.yield("fornada 2")
  coroutine.yield("fornada 3")
  return "forno desligado"
end)
for i = 1, 4 do
  print(coroutine.resume(forno))
end

No lab, o programa original mostrou true fornada 1, true fornada 2, true forno desligado e false cannot resume dead coroutine.

3. Repetindo até a corrotina terminar

Quase sempre você não sabe quantas pausas a corrotina vai fazer. Então o programa principal faz um laço: retoma, usa o valor, e para quando ela morrer:

local co = coroutine.create(function ()
  for i = 1, 3 do
    coroutine.yield(i)
  end
end)
while true do
  local ok, valor = coroutine.resume(co)
  if coroutine.status(co) == "dead" then break end
  print("recebi", valor)
end

$ lua co13.lua
recebi	1
recebi	2
recebi	3

Por que testar o status depois do resume? Porque a corrotina dá 3 pausas e depois uma 4ª volta, em que o for dela termina e o corpo chega ao fim sem yield. Esse último resume devolve só true, sem valor. Se o laço não parasse ali, mostraria recebi nil. (Esse vaivém de "pede um, recebe um" é o assunto da próxima aula, Produtor e Consumidor, e a próxima depois dela mostra um jeito mais curto de escrever este laço: coroutine.wrap.)

4. Os quatro estados

local co
co = coroutine.create(function ()
  print("dentro:", coroutine.status(co))
  print("pode pausar?", coroutine.isyieldable())
  coroutine.yield()
end)
print("antes:", coroutine.status(co))
coroutine.resume(co)
print("pausada:", coroutine.status(co))
coroutine.resume(co)
print("no fim:", coroutine.status(co))
print("principal pode pausar?", coroutine.isyieldable())
print(coroutine.running())

$ lua co4.lua
antes:	suspended
dentro:	running
pode pausar?	true
pausada:	suspended
no fim:	dead
principal pode pausar?	false
thread: 0x563c4efa0598	true

(O local co fica numa linha separada para que a função do corpo já enxergue a variável co. O número 0x563c… é um endereço e muda a cada execução; no editor do guia ele sai mais curto, como 0x80….)

EstadoQuer dizer
suspended"Suspensa": criada e ainda não começou, ou pausada num yield. Dá para retomar.
running"Rodando": é ela que está rodando agora (só aparece quando a própria corrotina pergunta).
normalEstá ativa, mas parada esperando: ela retomou outra corrotina, que está rodando.
dead"Morta": o corpo terminou, ou parou com um erro. Não volta mais.

O estado normal aparece quando uma corrotina retoma outra:

local a, b
a = coroutine.create(function ()
  coroutine.resume(b)
end)
b = coroutine.create(function ()
  print("a está:", coroutine.status(a))
  print("b está:", coroutine.status(b))
end)
coroutine.resume(a)

$ lua co5.lua
a está:	normal
b está:	running

Duas funções de apoio:

  • coroutine.isyieldable() ("pode ceder?"): true se o código que está rodando pode chamar yield. Dentro do corpo de uma corrotina, sim; no programa principal, não (ele não é uma corrotina: não há para quem devolver o controle).
  • coroutine.running(): devolve a corrotina que está rodando e um booleano que é true se ela for a principal. No programa principal, saiu thread: 0x… true: o próprio programa também é uma thread, a principal.

5. Erros dentro de uma corrotina

Um erro dentro do corpo não derruba o programa: ele para a corrotina, e o resume devolve false e a mensagem, como um pcall:

local co = coroutine.create(function ()
  print("antes do erro")
  local t = nil
  print(t.nome)
  print("nunca chega aqui")
end)
print(coroutine.resume(co))
print(coroutine.status(co))
print("o programa principal continua")

$ lua co6.lua
antes do erro
false	co6.lua:4: attempt to index a nil value (local 't')
dead
o programa principal continua

A corrotina morreu (dead), mas o programa principal seguiu. Por isso, sempre olhe o primeiro valor do resume: se for false, o segundo é a mensagem de erro.

Encerrando antes do fim: coroutine.close

E se você não quiser mais uma corrotina que está pausada no meio? Se o corpo tiver variáveis <close> (aula <close>), elas ficariam abertas para sempre, porque o bloco nunca termina. O coroutine.close encerra a corrotina e fecha essas variáveis:

local co = coroutine.create(function ()
  local porta <close> = setmetatable({}, { __close = function () print("porta fechada") end })
  print("porta aberta")
  coroutine.yield()
  print("nunca chega aqui")
end)
coroutine.resume(co)
print(coroutine.status(co))
print(coroutine.close(co))
print(coroutine.status(co))
print(coroutine.resume(co))

$ lua co10.lua
porta aberta
suspended
porta fechada
true
dead
false	cannot resume dead coroutine

O close fechou a porta, devolveu true (deu certo) e deixou a corrotina morta. Numa corrotina que já tinha morrido com erro, ele devolve false e o erro: com um corpo que faz error("forno quebrou"), o lab mostrou false co11.lua:1: forno quebrou no resume e de novo no close.

5.5 Fechar a corrotina de dentro dela

No Lua 5.5, uma corrotina pode chamar coroutine.close() nela mesma: ela se encerra ali, e quem a retomou recebe a resposta do resume (no lab, um corpo com print(coroutine.close(co)) fez o resume devolver só true, e o print de dentro nunca rodou). No Lua 5.4, o mesmo programa dá false co12.lua:3: cannot close a running coroutine ("não dá para fechar uma corrotina que está rodando").

Formas diferentes de fazer a mesma coisa

Entregar os números 1, 2 e 3, um de cada vez, de três jeitos:

-- 1) uma lista pronta: tudo calculado antes
local lista = { 1, 2, 3 }
for _, n in ipairs(lista) do print(n) end

-- 2) um iterador com closure: lembra onde parou numa variável
local function contagem(max)
  local i = 0
  return function () i = i + 1; if i <= max then return i end end
end
for n in contagem(3) do print(n) end

-- 3) uma corrotina: lembra onde parou "no meio do código"
local co = coroutine.create(function () for i = 1, 3 do coroutine.yield(i) end end)
while true do
  local ok, n = coroutine.resume(co)
  if coroutine.status(co) == "dead" then break end
  print(n)
end
SituaçãoQual usar
Poucos valores, que dá para calcular antesUma lista (tabela)
Um percurso simples, cujo "onde parou" cabe numa variávelUm iterador (aula Iteradores Próprios)
Uma tarefa longa com várias etapas, que precisa pausar e voltar (uma animação, uma conversa, uma receita passo a passo)Uma corrotina
Uma corrotina usada só para entregar valores um a umcoroutine.wrap (aula coroutine.wrap e Geradores)
E nas outras versões?

As corrotinas existem desde o Lua 5.0, e o básico (create, resume, yield, status) funciona igual: o co3.lua desta aula deu exatamente a mesma saída no lua5.1, no luajit e no lua5.4 do lab. Duas funções são mais novas: no lab, o lua5.1 não tem nem coroutine.close nem coroutine.isyieldable (nil nil); o LuaJIT tem só o isyieldable; o 5.4 tem as duas. E o exemplo do coroutine.close com <close> não roda no LuaJIT (unexpected symbol near '<'). Veja as diferenças entre as versões.

Quando dá errado

Retomou uma corrotina que já terminou 
$ lua co2.lua
true
true
false	cannot resume dead coroutine
dead

"Não dá para retomar uma corrotina morta". Ela já chegou ao fim do corpo (ou parou com erro). Não é um erro que para o programa: o resume devolve false. Como evitar: confira coroutine.status(co) ~= "dead" antes, ou pare o laço quando ela morrer (seção 3). Se precisar recomeçar, crie uma corrotina nova com coroutine.create.

Chamou yield fora de uma corrotina 
coroutine.yield()

$ lua co7.lua
lua: attempt to yield from outside a coroutine
stack traceback:
	[C]: in field 'yield'
	co7.lua:1: in main chunk
	[C]: in ?

"Tentativa de ceder de fora de uma corrotina". O programa principal não tem para quem devolver o controle. Repare que a mensagem não tem o co7.lua:1: na frente: quem dá o erro é a própria função yield (o [C]: in field 'yield' do rastro); a linha está no rastro, logo abaixo. Como consertar: o yield só pode rodar dentro do corpo de uma corrotina (ou de uma função chamada por ele).

Passou outra coisa no lugar da corrotina ou da função 
$ lua co8.lua
lua: co8.lua:1: bad argument #1 to 'resume' (thread expected, got number)
stack traceback:
	[C]: in field 'resume'
	co8.lua:1: in main chunk
	[C]: in ?
$ lua co9.lua
lua: co9.lua:1: bad argument #1 to 'create' (function expected, got number)
stack traceback:
	[C]: in field 'create'
	co9.lua:1: in main chunk
	[C]: in ?

O resume quer uma thread (o que o create devolveu); o create quer uma function. Os dois receberam o número 42 (print(coroutine.resume(42)) e coroutine.create(42)). Um engano comum é passar a função para o resume, em vez da corrotina criada a partir dela.

Tentou pausar dentro de uma função do próprio Lua 
local co = coroutine.create(function ()
  local t = {}
  table.sort({3, 1, 2}, function (a, b) coroutine.yield() return a < b end)
end)
print(coroutine.resume(co))

$ lua co14.lua
false	attempt to yield across a C-call boundary

"Tentativa de ceder através de uma fronteira de chamada C". O table.sort é escrito em C, e ele chamou a nossa função de comparação. Uma pausa ali teria de congelar o table.sort no meio, e o Lua não sabe fazer isso com funções em C. É exatamente o caso em que o isyieldable responde false: no lab, ele deu true no corpo da corrotina e false dentro da comparação do table.sort. Como consertar: não chame yield em funções passadas para table.sort, string.gsub e outras funções da biblioteca.

Referência rápida

FunçãoO que faz
coroutine.create(f)Cria uma corrotina com o corpo f (não roda nada); devolve uma thread
coroutine.resume(co, …)Começa ou continua; devolve true + valores do yield/return, ou false + erro
coroutine.yield(…)Pausa a corrotina; os valores vão para o resume; devolve o que o próximo resume mandar
coroutine.status(co)"suspended", "running", "normal" ou "dead"
coroutine.isyieldable()true se dá para chamar yield aqui
coroutine.running()A corrotina atual e true se for a principal
coroutine.close(co)Encerra uma corrotina pausada (ou morta), fechando os <close> dela
coroutine.wrap(f)Cria e devolve uma função que retoma (aula coroutine.wrap)

Missão final: as senhas da fila

Missão: o programa principal já está pronto: ele retoma a corrotina atendimento e mostra cada chamada, até ela não entregar mais nada. Escreva o corpo da corrotina: para cada nome da fila, ele deve ceder (coroutine.yield) o texto "senha 1: Ana", "senha 2: Bia"… (Dica: for i, nome in ipairs(fila) do … end.)

local fila = { "Ana", "Bia", "Caio" }
local atendimento = coroutine.create(function ()
  -- para cada pessoa da fila, ceda "senha N: NOME"
end)
while true do
  local ok, chamada = coroutine.resume(atendimento)
  if not chamada then break end
  print(chamada)
end
print("fim do atendimento")

local fila = { "Ana", "Bia", "Caio" }
local atendimento = coroutine.create(function ()
  for i, nome in ipairs(fila) do
    coroutine.yield("senha " .. i .. ": " .. nome)
  end
end)
while true do
  local ok, chamada = coroutine.resume(atendimento)
  if not chamada then break end
  print(chamada)
end
print("fim do atendimento")

Resumo

  • Uma corrotina é uma função que pode pausar (coroutine.yield) e continuar de onde parou (coroutine.resume), lembrando tudo.
  • coroutine.create(f) só cria; o primeiro resume começa o corpo, e os argumentos dele viram os parâmetros de f.
  • O que vai no yield sai no resume (depois do true); o que vai no próximo resume sai do yield.
  • Estados: suspended, running, normal, dead. Uma corrotina morta não volta: cannot resume dead coroutine.
  • Erro dentro dela não derruba o programa: o resume devolve false e a mensagem. coroutine.close encerra uma corrotina pausada e fecha os <close> dela.
  • Corrotinas não rodam ao mesmo tempo: elas se revezam, e cada uma decide quando ceder a vez.
