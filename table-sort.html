Lua table.sort: Ordenando

A professora quer as notas da menor para a maior. A Ana quer a lista de clientes em ordem alfabética. A padaria quer os produtos do mais barato para o mais caro. Ordenar (em inglês, sort) é uma das tarefas mais comuns da programação, e o Lua já traz a função pronta: table.sort. Ela arruma uma lista no lugar, e você pode dizer a ela qual ordem quer, com uma pequena função de comparação.

Você vai aprender
  • table.sort(lista): ordem crescente de números e ordem "alfabética" de textos.
  • Por que "Bia" vem antes de "ana", e "Ágata" vai para o fim.
  • A função de comparação: table.sort(lista, function(a, b) return a > b end).
  • Ordenar fichas por um campo (preço, nome) e com desempate.
  • Ordenar ignorando maiúsculas, e textos que são números.
  • Ordenar as chaves de um dicionário, para ter uma ordem fixa.
  • Os erros reais: invalid order function for sorting, attempt to compare, o sort que não devolve nada e a lista com buraco.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), com lua arquivo.lua. Para mostrar a lista numa linha, os exemplos usam table.concat.

A ideia: comparar dois de cada vez

A professora vai organizar a fila da turma por altura. Ela não mede todos de uma vez: pega dois alunos, pergunta "quem é o mais baixo?", e troca os dois de lugar se for preciso. Repetindo essa pergunta várias vezes, com pares diferentes, a fila fica em ordem.

O table.sort trabalha assim. A única coisa que ele precisa saber é responder a pergunta "o a deve vir antes do b?". Para números e textos, ele já sabe responder sozinho (usa o <, "menor que"). Para outra ordem, ou para coisas que ele não sabe comparar (as fichas de produtos), você escreve uma função que responde essa pergunta com true ou false.

1. Ordenando números

local notas = {7.5, 9, 6, 10, 8.5}
table.sort(notas)
for i, nota in ipairs(notas) do
  print(i, nota)
end

$ lua numeros_sort.lua
1	6
2	7.5
3	8.5
4	9
5	10
table.sort
A função sort ("ordenar") da biblioteca table.
(notas)
A lista a ordenar. Sem mais nada, a ordem é crescente: do menor para o maior.
(sem "=")
O sort arruma a própria lista (os programadores dizem "no lugar", in-place). Ele não cria uma lista nova e não devolve nada. Depois da linha 2, notas[1] já é a menor nota.

Como a lista original é mudada, a ordem antiga se perde. Se você ainda vai precisar dela (a ordem de chegada, por exemplo), faça uma cópia antes de ordenar, como na seção Formas diferentes.

2. Ordenando textos: a ordem dos bytes

local nomes = {"Caio", "ana", "Bia", "Ágata", "Zeca", "davi"}
table.sort(nomes)
print(table.concat(nomes, ", "))

$ lua textos_sort.lua
Bia, Caio, Zeca, ana, davi, Ágata

Não é bem a ordem do dicionário. O Lua compara textos letra por letra pelo código de cada letra (o byte; veja string.byte), e nesses códigos:

  • todas as maiúsculas (A a Z) vêm antes de todas as minúsculas (a a z). Por isso "Zeca" veio antes de "ana";
  • letras acentuadas têm códigos maiores que todas as letras sem acento (em UTF-8, o Á começa com o byte 195; veja Acentos e a Biblioteca utf8). Por isso "Ágata" foi parar no fim.

Se os nomes estiverem todos escritos do mesmo jeito (só a primeira maiúscula, sem acento na primeira letra), a ordem fica a esperada. Para ignorar maiúsculas, veja a seção 5.

3. A função de comparação: outra ordem

Para ordenar do maior para o menor, passe um segundo argumento: uma função que recebe dois itens, a e b, e devolve true quando a deve vir antes de b:

local notas = {7.5, 9, 6, 10, 8.5}
table.sort(notas, function(a, b)
  return a > b
end)
print(table.concat(notas, "  "))

$ lua decrescente.lua
10  9  8.5  7.5  6
function(a, b) … end
Uma função sem nome, escrita direto como argumento (veja Funções São Valores). O sort vai chamá-la muitas vezes, cada vez com dois itens da lista.
a, b
Os dois itens que estão sendo comparados naquele momento. Você não escolhe quais: o sort decide.
return a > b
A resposta para "o a vem antes do b?". Aqui: "sim, se a for maior". Assim, os maiores vão para a frente.

Sem a função, o sort usa a < b. Trocar por a > b inverte a ordem. Uma regra importante, que a seção Quando dá errado explica: use < ou >, nunca <= ou >=.

Missão: o programa ordena do menor para o maior. Passe uma função de comparação ao table.sort para ordenar do maior para o menor. Deve sair 10, 9, 8.5, 7.5, 6.

  return a > b
end)
print(table.concat(notas, ", "))

4. Ordenando fichas por um campo

Uma lista de fichas (tabelas) o sort não sabe comparar sozinho: qual tabela é "menor"? A função de comparação diz qual campo olhar:

local produtos = {
  {nome = "Café", preco = 18.90},
  {nome = "Pão", preco = 0.75},
  {nome = "Leite", preco = 5.49},
  {nome = "Manteiga", preco = 12.30},
}
table.sort(produtos, function(a, b)
  return a.preco < b.preco
end)
for i, p in ipairs(produtos) do
  print(i .. ". " .. p.nome .. ": R$ " .. string.format("%.2f", p.preco))
end

$ lua fichas_sort.lua
1. Pão: R$ 0.75
2. Leite: R$ 5.49
3. Manteiga: R$ 12.30
4. Café: R$ 18.90

Agora a e b são duas fichas inteiras, e a.preco < b.preco compara o preço delas. As fichas andam inteiras: o nome vai junto com o preço.

Desempate: quando o campo é igual

No ranking da turma, a maior nota vem primeiro; quem tem a mesma nota fica em ordem alfabética. A função compara a nota e, só se for igual, compara o nome:

local alunos = {
  {nome = "Caio", nota = 8},
  {nome = "Ana", nota = 9},
  {nome = "Eva", nota = 8},
  {nome = "Bia", nota = 9},
  {nome = "Davi", nota = 7},
}
table.sort(alunos, function(a, b)
  if a.nota ~= b.nota then
    return a.nota > b.nota
  end
  return a.nome < b.nome
end)
for i, al in ipairs(alunos) do
  print(i .. "º " .. al.nome .. " (" .. al.nota .. ")")
end

$ lua desempate.lua
1º Ana (9)
2º Bia (9)
3º Caio (8)
4º Eva (8)
5º Davi (7)
Por que o desempate importa: o sort não é "estável"

O manual do Lua avisa que o algoritmo do table.sort não é estável: itens que a sua função considera iguais (duas notas 9) podem trocar de lugar entre si, sem nenhuma garantia de manter a ordem em que estavam. Se a ordem dos empatados importa, diga qual é, com um desempate como o do nome. Assim, o resultado é sempre o mesmo.

5. Ignorando maiúsculas, e textos que são números

Para ordem alfabética sem ligar para maiúsculas, compare as versões em minúsculas (lower; veja Funções de Texto). A lista continua com os nomes originais; só a comparação usa as minúsculas:

local nomes = {"Caio", "ana", "Bia", "davi"}
table.sort(nomes, function(a, b)
  return a:lower() < b:lower()
end)
print(table.concat(nomes, ", "))

$ lua minusculas.lua
ana, Bia, Caio, davi

E números guardados como texto (lidos de um arquivo, por exemplo) são comparados letra por letra: "100" vem antes de "2", porque "1" vem antes de "2". Converta na comparação com tonumber:

local codigos = {"10", "9", "100", "2"}
table.sort(codigos)
print(table.concat(codigos, " "))
table.sort(codigos, function(a, b) return tonumber(a) < tonumber(b) end)
print(table.concat(codigos, " "))

$ lua textos_numeros.lua
10 100 2 9
2 9 10 100

6. Ordenando as chaves de um dicionário

Um dicionário ({pao = 40, leite = 0}) não tem ordem: o pairs passa pelas chaves numa ordem que o Lua escolhe, e ela pode mudar de uma execução para outra. Para mostrar em ordem alfabética, junte as chaves numa lista, ordene a lista e percorra a lista:

local estoque = {pao = 40, leite = 0, cafe = 5, manteiga = 3}
local nomes = {}
for nome in pairs(estoque) do
  table.insert(nomes, nome)
end
table.sort(nomes)
for _, nome in ipairs(nomes) do
  print(nome, estoque[nome])
end

$ lua chaves_sort.lua
cafe	5
leite	0
manteiga	3
pao	40

Esse é um truque que você vai usar sempre que um relatório precisar sair igual toda vez.

Formas diferentes de fazer a mesma coisa

Ordenar sem perder a ordem original

O sort muda a lista. Para ter as duas ordens, copie primeiro:

local chegada = {"Caio", "Ana", "Bia"}
local ordem_alfabetica = {}
for i, nome in ipairs(chegada) do
  ordem_alfabetica[i] = nome
end
table.sort(ordem_alfabetica)
print("chegada:    " .. table.concat(chegada, ", "))
print("alfabética: " .. table.concat(ordem_alfabetica, ", "))

$ lua copia.lua
chegada:    Caio, Ana, Bia
alfabética: Ana, Bia, Caio

Por que copiar item por item, e não local ordem_alfabetica = chegada? Porque isso não copia: as duas variáveis apontariam para a mesma tabela, e ordenar uma ordenaria a outra (veja Tabelas São Referências).

Quando dá errado

Usou >= (ou <=) na comparação 
local notas = {7, 9, 7, 10, 7, 8, 7, 9, 7, 7, 6, 7}
table.sort(notas, function(a, b)
  return a >= b
end)
print("Ordem: " .. table.concat(notas, " "))
print("Maior nota: " .. notas[1])

$ lua ranking.lua
lua: ranking.lua:2: invalid order function for sorting
stack traceback:
	[C]: in field 'sort'
	ranking.lua:2: in main chunk
	[C]: in ?

Linha por linha:

ranking.lua:2:
A linha do table.sort (não a do return): quem percebeu o problema foi o sort.
invalid order function for sorting
"Função de ordem inválida para ordenar." A sua função dá respostas que não fazem sentido juntas.
[C]: in field 'sort'
O erro aconteceu dentro do sort (escrito em C), chamado pela linha 2.

Por que "não fazem sentido"? A pergunta é "o a vem antes do b?". Com dois 7, o 7 >= 7 diz true: "o primeiro 7 vem antes do segundo". E, trocando os dois de lugar, diz true de novo: "o segundo vem antes do primeiro". Os dois não podem vir antes um do outro, e o algoritmo se perde. O manual exige que a função defina uma "ordem fraca estrita": para itens iguais, ela tem de responder false nos dois sentidos. É isso que o > e o < fazem (7 > 7 é false).

O mais traiçoeiro: com itens todos diferentes, a mesma função errada pode funcionar. No lab, {7, 3, 9, 1} com a <= b saiu certinho (1 3 7 9); só a lista com notas repetidas deu o erro. O programa passa no teste com poucos dados e quebra com os dados de verdade. Como consertar: return a > b.

Guardou o resultado do sort

O sort não devolve a lista ordenada: ele ordena a própria notas e devolve nada (nil). Como consertar: chame table.sort(notas) sozinho e use notas depois.

A lista tinha um buraco 
local notas = {7, 9, nil, 6}
print(#notas)
table.sort(notas)
print(notas[1], notas[2], notas[3], notas[4])

$ lua com_nil.lua
2
7	9	nil	6

Nenhum erro, mas o 6 não foi ordenado. O sort ordena de t[1] até t[#t], e com o buraco o #notas deu 2: ele só olhou o 7 e o 9. Como consertar: não deixe buracos na lista (use table.remove para tirar itens; veja Sequências e Buracos).

Resumo

  • table.sort(t) ordena a própria lista, do menor para o maior, e não devolve nada. Para guardar a ordem antiga, copie antes.
  • Textos são comparados pelos códigos das letras: maiúsculas antes de minúsculas, acentuadas depois de todas.
  • table.sort(t, function(a, b) return … end): a função responde "o a vem antes do b?". a > b dá a ordem decrescente; a.campo < b.campo ordena fichas.
  • Na função, use < ou >, nunca <=/>=: com itens repetidos, sai invalid order function for sorting.
  • O sort não é estável: para empates, faça um desempate.
  • Para ordenar um dicionário, ordene uma lista com as chaves dele.
