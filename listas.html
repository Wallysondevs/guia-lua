Lua Tabelas como Listas

A lista de compras da Ana, a fila do caixa da padaria, as notas de uma aluna: são coisas em ordem, uma depois da outra. No Lua, uma lista é uma tabela cujas chaves são as posições 1, 2, 3… Não existe um tipo "lista" separado: é a mesma tabela, usada de um jeito especial. E um detalhe que diferencia o Lua de muitas outras linguagens: a primeira posição é a 1, não a 0.

Você vai aprender
  • Como criar uma lista e ler o item de cada posição, a partir do 1.
  • Como saber quantos itens a lista tem (#) e pegar o último (t[#t]).
  • Como trocar um item e acrescentar no fim com t[#t + 1] = valor.
  • Como percorrer a lista com for, de frente para trás e de trás para frente.
  • Soma, média, maior e menor valor de uma lista de números.
  • Como montar uma lista dentro de um laço.
  • Por que t[0] e t[-1] não são o que quem vem de outra linguagem espera.
  • Os erros reais: começar do 0, passar do fim, procurar um .size() que não existe.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), com lua arquivo.lua. Se você caiu aqui direto, leia antes Tabelas: a Estrutura de Tudo.

A ideia: a lista de compras numerada

A Ana escreve a lista de compras num papel, um item por linha, e numera as linhas: 1. pão, 2. leite, 3. café. Ninguém começa uma lista de compras pelo "item zero". O Lua pensa igual: o primeiro item é o de número 1.

Posição (chave)Item (valor)
1"pão"
2"leite"
3"café"

É a mesma tabela "chave → valor" da aula anterior, só que as chaves são números inteiros seguidos, começando em 1 e sem buracos. Uma tabela assim o manual do Lua chama de sequência, e é com ela que o #, o ipairs e as funções table.* trabalham.

1. Criando a lista e lendo cada posição

local compras = {"pão", "leite", "café"}
print(compras[1])
print(compras[2])
print(compras[3])
print(compras[4])
print(compras[0])
print(#compras)
print(compras[#compras])
{"pão", "leite", "café"}
Valores separados por vírgula, sem chave: o Lua numera sozinho, a partir do 1. É o mesmo que {[1] = "pão", [2] = "leite", [3] = "café"}.
compras[1]
O item da posição 1, entre colchetes. Também se diz "o item de índice 1".
compras[4] e compras[0]
Posições onde nada foi guardado: nil, sem erro. A lista tem as posições de 1 a 3, e só.
#compras
O operador de tamanho: quantos itens a lista tem.
compras[#compras]
O último item: a posição de número igual ao tamanho. Aqui, compras[3].
$ lua lista.lua
pão
leite
café
nil
nil
3
café
Por que começa no 1?

Em C, Java, Python e JavaScript, a primeira posição é a 0. O Lua nasceu em 1993, na PUC-Rio, pensado também para gente que não era programadora de profissão, e escolheu contar como as pessoas contam. Para quem nunca programou, isso é uma vantagem: o terceiro item é o [3], e o último é o [#t]. Para quem vem de outra linguagem, é a pegadinha mais comum dos primeiros dias (veja Quando dá errado).

2. Trocando e acrescentando itens

Guardar numa posição que já existe troca o item. Para acrescentar no fim, guarde na posição logo depois do último: #compras + 1.

local compras = {"pão", "leite", "café"}
compras[2] = "leite sem lactose"
compras[#compras + 1] = "manteiga"
compras[#compras + 1] = "queijo"
print(#compras)
for i = 1, #compras do
  print(i .. ". " .. compras[i])
end

$ lua mudar_item.lua
5
1. pão
2. leite sem lactose
3. café
4. manteiga
5. queijo
compras[2] = "leite sem lactose"
A posição 2 já existia: o "leite" foi trocado.
compras[#compras + 1] = "manteiga"
Naquele momento #compras era 3, então isso é compras[4] = "manteiga". A lista passa a ter 4 itens.
compras[#compras + 1] = "queijo"
A mesma linha de novo, mas agora #compras é 4: o queijo vai para a posição 5. Por isso essa é a forma de "pôr no fim": ela sempre acerta a próxima posição livre.

Também dá para acrescentar com table.insert(compras, "manteiga"), que faz o mesmo e ainda sabe pôr um item no meio. Isso tem aula própria: table.insert e table.remove.

Missão: acrescente "manteiga" e depois "queijo" no fim da lista, usando compras[#compras + 1], no lugar do comentário. A última linha deve mostrar 5 itens; o último é queijo.

3. Percorrendo a lista

O jeito mais direto de passar por todos os itens é um for numérico de 1 até #lista, como no mudar_item.lua. A variável do for é a posição; lista[i] é o item. Para ir de trás para frente, comece do tamanho e ande com passo -1:

local fila = {"Ana", "Bia", "Caio", "Davi"}
for i = #fila, 1, -1 do
  print(i, fila[i])
end

$ lua reverso.lua
4	Davi
3	Caio
2	Bia
1	Ana

Há um jeito feito sob medida para percorrer listas, o for i, item in ipairs(lista), que entrega a posição e o item juntos. Ele é o assunto da próxima aula: Percorrendo uma Lista (ipairs).

4. Listas de números: soma, média e maior

Com uma lista de notas, um laço faz as contas de sempre. A soma usa um acumulador; o maior valor começa com o primeiro item e é trocado cada vez que aparece um maior:

local notas = {7.5, 9, 6, 8.5, 10}
local soma = 0
local maior = notas[1]
for i = 1, #notas do
  soma = soma + notas[i]
  if notas[i] > maior then
    maior = notas[i]
  end
end
print("soma:", soma)
print("média:", soma / #notas)
print("maior:", maior)

$ lua numeros.lua
soma:	41.0
média:	8.2
maior:	10

A soma saiu 41.0 (com .0) porque a lista tem números com vírgula (floats), e inteiro + float dá float. O maior é o próprio item 10, que foi escrito como inteiro (veja Números). Por que o maior começa com notas[1], e não com 0? Porque, se todas as notas fossem negativas (temperaturas no inverno, por exemplo), o 0 "ganharia" de todas e a resposta estaria errada. Começar com um item da própria lista sempre funciona.

5. Montando uma lista num laço

Uma lista pode começar vazia, {}, e ser preenchida aos poucos:

local quadrados = {}
print(#quadrados)
for n = 1, 5 do
  quadrados[n] = n * n
end
print(#quadrados, quadrados[1], quadrados[5])

$ lua construir.lua
0
5	1	25

A lista vazia tem tamanho 0. Depois do laço, ela tem 5 itens: 1, 4, 9, 16, 25. Aqui o quadrados[n] funciona porque o n anda de 1 em 1, sem pular posição. Quando os itens chegam de outro jeito (lidos do teclado, filtrados de outra lista), use quadrados[#quadrados + 1], que nunca pula.

Uma lista pode misturar tipos

local coisas = {"Ana", 30, true, 1.75}
for i = 1, #coisas do
  print(i, coisas[i], type(coisas[i]))
end

$ lua mistura.lua
1	Ana	string
2	30	number
3	true	boolean
4	1.75	number

O Lua deixa, mas na prática uma lista guarda coisas do mesmo tipo (só nomes, só notas). Para juntar informações diferentes de uma coisa só, como nome, idade e altura da Ana, uma tabela com campos ({nome = "Ana", idade = 30}) é muito mais clara.

Experimente: mude o laço para guardar os dobros (n * 2) de 1 a 10 e mostre o último com quadrados[#quadrados]. Depois troque o nome da lista para algo que combine com o conteúdo.

local quadrados = {}
for n = 1, 5 do
  quadrados[n] = n * n
end
for i = 1, #quadrados do
  print(i, quadrados[i])
end

6. t[0] e t[-1]: o que não é o que parece

Quem vem do Python espera que lista[-1] seja o último item. No Lua, -1 é só mais uma chave, onde ninguém guardou nada:

local compras = {"pão", "leite", "café"}
print(compras[-1])
print(compras[#compras])

$ lua negativo.lua
nil
café

E dá para guardar algo na posição 0? Dá, como em qualquer chave. Mas ela fica fora da lista: o # não a conta, e o laço de 1 a #t não passa por ela.

local t = {[0] = "zero", "um", "dois"}
print(t[0], t[1], t[2])
print(#t)
for i = 1, #t do
  print(i, t[i])
end

$ lua zero.lua
zero	um	dois
2
1	um
2	dois

Por isso, no Lua, comece suas listas sempre do 1. Todas as ferramentas da linguagem esperam isso.

Buracos na lista

Se você guardar nil no meio de uma lista (compras[2] = nil), ela fica com um "buraco", e o # passa a poder dar mais de uma resposta. Para apagar um item do meio de uma lista, use table.remove, que fecha o buraco (aula table.insert e table.remove). Os detalhes dos buracos estão em Sequências e Buracos.

Como consertar: for i = 1, #compras do.

Passou do fim

Sem mensagem de erro, porque o print aceita nil. Mas apareceu um item 4 que não existe. Com .. ou uma conta no lugar do print, seria o mesmo erro do cenário anterior, só que na última volta. Como consertar: o laço vai até #compras, exatamente.

Procurou .length ou .size() 
local compras = {"pão", "leite", "café"}
print(compras.length)
print(compras:size())

$ lua size.lua

lua: size.lua:3: attempt to call a nil value (method 'size')
stack traceback:

Para o Lua, compras.length é só a gaveta "length", que ninguém criou: nil. E compras:size() tenta chamar (call) um método size que não existe: "tentativa de chamar um valor nil (o método size)". Como consertar: o tamanho de uma lista no Lua é #compras.

Achou que um texto também era uma lista 
local nome = "Ana"
print(nome[1])
print(nome:sub(1, 1))

$ lua string_index.lua
nil
A

Em algumas linguagens, nome[1] pega uma letra. No Lua, um texto não é uma tabela, e nome[1] dá nil. Para pegar letras, use nome:sub(1, 1) (veja Pedaços de Texto).

Missão final: a menor nota

Missão: o programa já acha a maior nota. No lugar do comentário, faça ele achar também a menor: se notas[i] for menor que menor, troque o menor. A resposta certa é menor: 6.

local notas = {7.5, 9, 6, 8.5, 10}
local maior = notas[1]
local menor = notas[1]
for i = 1, #notas do
  if notas[i] > maior then
    maior = notas[i]
  end
  -- confira aqui se notas[i] é menor que o menor
end
print("maior: " .. maior)
print("menor: " .. menor)

local notas = {7.5, 9, 6, 8.5, 10}
local maior = notas[1]
local menor = notas[1]
for i = 1, #notas do
  if notas[i] > maior then
    maior = notas[i]
  end
  if notas[i] < menor then
    menor = notas[i]
  end
end
print("maior: " .. maior)
print("menor: " .. menor)

Sem mexer no código, ele mostra menor: 7.5: o menor começou com a primeira nota e ninguém o trocou.

Resumo

  • Uma lista é uma tabela com as chaves 1, 2, 3… sem buracos (uma sequência). {"a", "b"} numera sozinho.
  • No Lua, a primeira posição é a 1. t[0] e t[-1] são chaves comuns, normalmente nil.
  • #t é o tamanho; t[#t], o último item; t[#t + 1] = valor acrescenta no fim.
  • Percorra com for i = 1, #t do (ou de trás para frente com for i = #t, 1, -1 do).
  • Para o maior/menor, comece com t[1], não com 0.
  • Não existe .length nem .size(): é #t. E um texto não é uma lista: nome[1] é nil.
