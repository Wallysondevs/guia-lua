Lua Funções São Valores

Na aula Funções, o type(bom_dia) respondeu function, e o print(bom_dia) mostrou function: 0x…. Isso quer dizer uma coisa importante: no Lua, uma função é um valor, do mesmo jeito que 42 ou "Ana". E tudo o que se faz com um valor dá para fazer com uma função: guardar numa variável, colocar numa tabela, mandar como argumento para outra função, devolver com return. Esta aula mostra cada uma dessas coisas, e para que servem.

Você vai aprender
  • Que local function f é uma variável que guarda uma função, e que dá para copiá-la para outra variável.
  • A escrever funções anônimas (sem nome): function(x) … end.
  • A guardar funções numa tabela, como numa calculadora com uma tabela de operações.
  • A passar uma função como argumento: o table.sort com uma função de comparação e uma função aplicar que você mesmo escreve.
  • A devolver uma função com return.
  • Os erros reais: attempt to call a number value, chamar a função em vez de passá-la, invalid order function for sorting.

A ideia: a receita é um papel

Na aula de funções, uma função era uma receita com nome. Mas a receita, afinal, é um papel. Um papel pode ser copiado e dado a outra pessoa; guardado numa pasta junto com outras receitas; entregue a uma confeiteira com o recado "faça esta aqui"; até tirado da gaveta e devolvido a quem pediu. O papel não é o bolo: é o jeito de fazer o bolo, que alguém pode seguir quando quiser.

1. A função numa variável

Quando você escreve local function saudar(…), o Lua cria uma variável saudar e guarda a função dentro dela. Essa variável pode ser copiada para outra:

local function saudar(nome)
  print("Bom dia, " .. nome .. "!")
end

local cumprimentar = saudar
cumprimentar("Ana")
saudar("Bia")
print(type(saudar), type(cumprimentar))
print(saudar == cumprimentar)

$ lua valor.lua
Bom dia, Ana!
Bom dia, Bia!
function	function
true
local cumprimentar = saudar
Sem parênteses: não chama a função, só pega o valor guardado em saudar (a função) e guarda também em cumprimentar. Agora as duas variáveis guardam a mesma função.
cumprimentar("Ana")
Com parênteses, chama. Tanto faz chamar por um nome ou pelo outro.
saudar == cumprimentar
true: é a mesma função, não uma cópia dela.

Isso vale também para as funções prontas do Lua. O print é só uma variável que guarda uma função:

local mostrar = print
mostrar("o print também é um valor")
print(type(print), type(string.upper))
print(print == mostrar)

$ lua print_valor.lua
o print também é um valor
function	function
true
Com ou sem parênteses?

Esta é a chave da aula inteira: saudar (sem parênteses) é a função, o papel da receita. saudar() (com parênteses) é chamar a função, fazer o bolo, e o resultado é o que ela devolve. Quase todos os erros desta aula vêm de trocar um pelo outro.

2. Funções anônimas: function(…) … end

Uma função não precisa de nome. Escrita assim, ela é um valor, como um número escrito no meio de uma conta:

local dobro = function(n)
  return n * 2
end

print(dobro(21))
print((function(n) return n * 3 end)(5))

$ lua anonima.lua
42
15
function(n) … end
Uma função anônima ("sem nome"): a palavra function, os parâmetros e o corpo, sem nome no meio. O resultado é um valor do tipo function.
local dobro = function(n) … end
A função anônima é guardada numa variável, como local x = 42. É a terceira forma da aula Funções: no fundo, local function dobro(n) faz quase a mesma coisa.
(function(n) … end)(5)
Dá até para criar e chamar na mesma hora. É raro; serve para mostrar que a função é um valor que pode ser usado direto.

As funções anônimas brilham quando são usadas uma vez só, no lugar onde são necessárias: como argumento de outra função (seção 4).

3. Funções dentro de uma tabela

Uma tabela guarda valores com nome (aula Tabelas como Dicionários). Como funções são valores, uma tabela pode guardar funções:

local operacoes = {
  soma = function(a, b) return a + b end,
  subtracao = function(a, b) return a - b end,
}

function operacoes.divisao(a, b)
  return a / b
end

print(operacoes.soma(6, 7))
print(operacoes.subtracao(6, 7))
print(operacoes["divisao"](6, 4))
for _, nome in ipairs({"soma", "subtracao", "divisao"}) do
  print(nome, operacoes[nome](10, 2))
end

$ lua tabela_funcoes.lua
13
-1
1.5
soma	12
subtracao	8
divisao	5.0
soma = function(a, b) … end,
Um campo da tabela cujo valor é uma função anônima. Vírgula no fim, como qualquer campo.
function operacoes.divisao(a, b)
Um atalho para operacoes.divisao = function(a, b) … end: cria a função e guarda no campo divisao da tabela. Repare que aqui não vai local: a tabela operacoes já é local.
operacoes.soma(6, 7)
Pega a função do campo soma e chama.
operacoes[nome](10, 2)
O nome do campo pode vir de uma variável. É aqui que a ideia fica poderosa: o programa escolhe qual função chamar enquanto roda.

As bibliotecas do Lua são exatamente isso: string, math e table são tabelas cheias de funções. string.upper é o campo upper da tabela string.

Uma calculadora com uma tabela de operações

Com as funções numa tabela, a calculadora não precisa de um if para cada sinal: ela procura o sinal na tabela.

local operacoes = {
  ["+"] = function(a, b) return a + b end,
  ["-"] = function(a, b) return a - b end,
  ["*"] = function(a, b) return a * b end,
}

local function calcular(a, sinal, b)
  local op = operacoes[sinal]
  if op == nil then
    return nil, "não sei fazer " .. sinal
  end
  return op(a, b)
end

print(calcular(6, "+", 7))
print(calcular(6, "*", 7))
print(calcular(6, "^", 7))

$ lua calculadora.lua
13
42
nil	não sei fazer ^

Os sinais "+", "-", "*" não são nomes válidos, então vão entre colchetes e aspas: ["+"] = …. A função calcular pega a função certa com operacoes[sinal], guarda em op e a chama. Para ensinar uma operação nova, basta acrescentar uma linha na tabela. (O nil, "mensagem" é o costume da aula Vários Retornos.)

Missão: a calculadora ainda não sabe multiplicar nem dividir. Acrescente na tabela operacoes as funções de "*" e "/", sem mexer na função mostrar.

local operacoes = {

  if op == nil then
    print("não sei fazer " .. sinal)

4. Passando uma função como argumento

Se uma função é um valor, ela pode ir como argumento para outra função. A função que recebe decide quando chamar a que recebeu.

local function aplicar(lista, f)
  local nova = {}
  for i, valor in ipairs(lista) do
    nova[i] = f(valor)
  end
  return nova
end

local function dobro(n) return n * 2 end

local precos = {10, 4.5, 8}
local dobrados = aplicar(precos, dobro)
local com_taxa = aplicar(precos, function(p) return p + 1 end)
print(table.concat(dobrados, ", "))
print(table.concat(com_taxa, ", "))

$ lua argumento.lua
20, 9.0, 16
11, 5.5, 9
local function aplicar(lista, f)
O segundo parâmetro, f, vai receber uma função. Para o Lua, é um parâmetro como outro qualquer.
nova[i] = f(valor)
aplicar chama a função recebida para cada item e guarda o resultado na lista nova. Ela não sabe nem precisa saber o que f faz.
aplicar(precos, dobro)
Passa a função dobro, sem parênteses: entrega a receita, não o bolo.
aplicar(precos, function(p) return p + 1 end)
Uma função anônima escrita direto no lugar do argumento: útil quando ela só serve para esta chamada.

(O table.concat junta os itens com ", " entre eles: aula table.concat. O 9.0 aparece porque 4.5 * 2 é um float.)

Outro exemplo: uma função que repete uma ação qualquer:

local function repetir(vezes, acao)
  for i = 1, vezes do
    acao(i)
  end
end

repetir(3, function(i)
  print("Volta " .. i)
end)
repetir(2, print)

$ lua repetir.lua
Volta 1
Volta 2
Volta 3
1
2

Repare no jeito de escrever a função anônima ocupando várias linhas, no meio da chamada: ela começa depois da vírgula e termina no end), que fecha a função e depois os parênteses do repetir. E repetir(2, print) passou o próprio print como a ação.

O exemplo mais comum: table.sort com uma função de comparação

O table.sort (aula Ordenando) põe uma lista em ordem crescente. Para outra ordem, você entrega a ele uma função que responde a pergunta "o a vem antes do b?":

local notas = {7, 9.5, 4, 8, 6}
table.sort(notas)
print(table.concat(notas, " "))
table.sort(notas, function(a, b) return a > b end)
print(table.concat(notas, " "))

$ lua ordenar.lua
4 6 7 8 9.5
9.5 8 7 6 4

A função function(a, b) return a > b end diz: "a vem antes de b quando a é maior". O table.sort a chama várias vezes, com pares de notas, e arruma a lista conforme as respostas. Com uma lista de registros, a função escolhe o campo que manda na ordem:

local produtos = {
  {nome = "sonho", preco = 4.5},
  {nome = "pão francês", preco = 0.8},
  {nome = "bolo de milho", preco = 18},
  {nome = "café", preco = 4},
}

local function por_preco(a, b)
  return a.preco < b.preco
end

table.sort(produtos, por_preco)
for _, p in ipairs(produtos) do
  print(p.nome .. ": R$ " .. string.format("%.2f", p.preco))
end
print("---")
table.sort(produtos, function(a, b) return a.nome < b.nome end)
for _, p in ipairs(produtos) do
  print(p.nome)
end

$ lua ordenar_registros.lua
pão francês: R$ 0.80
café: R$ 4.00
sonho: R$ 4.50
bolo de milho: R$ 18.00
---
bolo de milho
café
pão francês
sonho

A mesma lista, duas ordens, e o table.sort não mudou nada: só a função entregue a ele.

Experimente: rode. Depois, troque a função anônima da segunda chamada para dar o triplo de cada preço, e crie uma terceira chamada com uma função que dê 10% de desconto (p * 0.9).

local function aplicar(lista, f)
  local nova = {}
  for i, valor in ipairs(lista) do
    nova[i] = f(valor)
  end
  return nova
end

local precos = {10, 4, 8}

print(table.concat(aplicar(precos, function(p) return p + 1 end), ", "))

5. Devolvendo uma função

Por fim, uma função pode criar e devolver outra função:

local function escolher_saudacao(hora)
  if hora < 12 then
    return function(nome) print("Bom dia, " .. nome .. "!") end
  end
  return function(nome) print("Boa tarde, " .. nome .. "!") end
end

local saudar = escolher_saudacao(9)
saudar("Ana")
escolher_saudacao(15)("Bia")

$ lua devolver.lua
Bom dia, Ana!
Boa tarde, Bia!
return function(nome) … end
O valor devolvido é uma função anônima. Quem chamou escolher_saudacao recebe uma função pronta para usar.
local saudar = escolher_saudacao(9)
Com 9 horas, recebe a função do "Bom dia" e guarda em saudar.
escolher_saudacao(15)("Bia")
Dois pares de parênteses: o primeiro chama escolher_saudacao, que devolve uma função; o segundo chama essa função com "Bia".

Funções que criam funções ficam ainda mais interessantes quando a função criada lembra das variáveis de quem a criou. Esse é o assunto da próxima aula: Closures.

Quando dá errado

Chamar algo que não é função 
local total = 10
total()

$ lua erro_numero.lua

stack traceback:

attempt to call a number value (local 'total'): "tentativa de chamar um valor do tipo número (a variável local total)". Os parênteses pedem "execute", mas total guarda um número, não uma função. É a mesma família do attempt to call a nil value da aula Funções; muda só o tipo do valor. Com um texto, local nome = "Ana" e nome("Bia"), a mensagem é attempt to call a string value (local 'nome').

Um jeito comum de chegar aqui é guardar o resultado da função, achando que guardou a função:

local function dobro(n) return n * 2 end
local f = dobro(5)
print(f(3))

$ lua erro_print_res.lua
lua: erro_print_res.lua:3: attempt to call a number value (local 'f')
stack traceback:
	erro_print_res.lua:3: in main chunk
	[C]: in ?

dobro(5), com parênteses, já chamou a função: f ficou com 10. Como consertar: para guardar a função, sem parênteses: local f = dobro.

Chamar a função em vez de passá-la 
local function por_preco(a, b)
  return a.preco < b.preco
end

local produtos = {{preco = 4.5}, {preco = 0.8}}
table.sort(produtos, por_preco())

$ lua erro_chamou.lua
lua: erro_chamou.lua:2: attempt to index a nil value (local 'a')
stack traceback:
	erro_chamou.lua:2: in local 'por_preco'
	erro_chamou.lua:6: in main chunk
	[C]: in ?

Os parênteses em por_preco() fizeram o Lua chamar a função ali mesmo, sem argumentos, antes do table.sort. Com a e b valendo nil, o a.preco falhou: attempt to index a nil value (local 'a'), "tentativa de pegar um campo de um valor nil". O rastro mostra que o erro foi dentro de por_preco, chamada pela linha 6, e não pelo table.sort (ele nem chegou a rodar). Como consertar: table.sort(produtos, por_preco), sem parênteses.

Uma função que não existe na tabela 
local operacoes = {
  soma = function(a, b) return a + b end,
}
print(operacoes.soma(1, 2))
print(operacoes.multiplicacao(3, 4))

$ lua erro_campo.lua
3
lua: erro_campo.lua:5: attempt to call a nil value (field 'multiplicacao')
stack traceback:
	erro_campo.lua:5: in main chunk
	[C]: in ?

Agora o Lua diz field 'multiplicacao': o valor nil estava num campo de tabela, não numa variável. A tabela não tem esse campo (ou o nome está escrito errado). Como consertar: confira o nome, ou teste antes, como a calcular faz com if op == nil then.

Uma função de comparação com <= 
local t = {}
for i = 1, 50 do t[i] = 5 end
table.sort(t, function(a, b) return a <= b end)
print("ordenou")

$ lua erro_ordem.lua
lua: erro_ordem.lua:3: invalid order function for sorting
stack traceback:
	[C]: in field 'sort'
	erro_ordem.lua:3: in main chunk
	[C]: in ?

invalid order function for sorting: "função de ordem inválida para ordenar". A função de comparação tem de responder "vem estritamente antes?": para dois valores iguais, a resposta tem de ser false. Com <=, ela diz que 5 vem antes de 5, e o table.sort se perde. O pior é que o erro depende da lista: no lab, a mesma função ordenou {3, 1, 2} sem reclamar, mas deu este erro com {3, 1, 2, 2}. Um programa pode funcionar nos testes e quebrar no dia em que aparecem dois valores iguais. Como consertar: use < ou >, nunca <= ou >=.

Resumo

  • No Lua, uma função é um valor do tipo function, como um número ou um texto.
  • f (sem parênteses) é a função; f() é chamá-la e ficar com o resultado.
  • function(…) … end sem nome é uma função anônima, que pode ir para uma variável, uma tabela ou um argumento.
  • Uma tabela de funções (operacoes["+"]) troca uma fila de ifs por uma busca; as bibliotecas string, math e table são assim.
  • Passar uma função como argumento deixa outra função decidir quando chamá-la: table.sort(lista, function(a, b) return a > b end). A comparação usa < ou >, nunca <=.
  • Uma função pode devolver outra função. Quando essa função "lembra" das variáveis de quem a criou, ela é uma closure, o assunto da próxima aula.
