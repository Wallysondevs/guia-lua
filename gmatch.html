Lua gmatch

O match devolve o primeiro pedaço que combina com o padrão. Mas e quando você quer todos? Todas as palavras de uma frase, todos os preços de um cupom, todos os itens de uma lista de compras separada por vírgulas. Para isso existe o string.gmatch (global match, "combinar em tudo"): ele entrega os achados um de cada vez, e um laço for passa por cada um deles.

Você vai aprender
  • Como escrever o laço for palavra in texto:gmatch(padrão) do … end, peça por peça.
  • Como separar uma lista do tipo "pão, leite, café".
  • Como usar capturas para pegar pares como nome=Ana.
  • Como contar, somar e guardar os achados numa tabela.
  • O que fazer com campos vazios ("pão;;café") e com a posição de cada achado.
  • O terceiro argumento (onde começar) e por que o ^ não funciona no gmatch.
  • O que o gmatch devolve de verdade: um iterador.
  • Os erros reais: o do esquecido, o find no lugar do gmatch, o padrão malformado.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com lua arquivo.lua. Você pode rodar cada um no editor do guia. Os padrões (%a+, [^,]+, capturas) estão explicados em Padrões.

A ideia: a esteira do caixa

No caixa do supermercado, a cliente põe as compras na esteira e a esteira vai entregando um produto de cada vez para a moça do caixa. Ela pega o produto, passa no leitor, põe na sacola, e pega o próximo. Quando a esteira fica vazia, acabou.

O gmatch é a esteira: ele vai entregando um achado de cada vez. O laço for é a moça do caixa: para cada achado, ele faz o que você mandar (mostrar, somar, guardar). E quando não há mais nada que combine com o padrão, o laço termina sozinho.

1. O primeiro laço: cada palavra de uma frase

local frase = "a padaria abre cedo"
for palavra in frase:gmatch("%a+") do
  print(palavra)
end
print("fim")

$ lua palavras.lua
a
padaria
abre
cedo
fim

Este é o seu primeiro laço for … in (os laços têm aulas próprias a partir de while e for Numérico; aqui você só precisa desta forma). Peça por peça:

for
"Para": começa um laço, um pedaço de código que se repete.
palavra
Uma variável nova, criada pelo laço. A cada volta ela recebe o próximo achado: na 1ª volta, "a"; na 2ª, "padaria"; e assim por diante. Ela só existe dentro do laço (é local a ele).
in
"Em": "para cada palavra em…".
frase:gmatch("%a+")
A esteira: o mesmo que string.gmatch(frase, "%a+"). O padrão %a+ é "uma ou mais letras".
do … end
"Faça" … "fim": o que fica entre os dois roda uma vez para cada achado. Os 2 espaços de recuo no print(palavra) não são obrigatórios, mas mostram a quem lê o que está dentro do laço.
print("fim")
Depois do end, fora do laço: roda uma vez só, quando os achados acabam.

Repare que o %a+ não pegou os espaços: o laço deu 4 voltas, uma por palavra. Se o padrão não achar nada, o laço dá zero voltas e o programa segue para depois do end, sem erro.

2. Separar uma lista por vírgulas

A lista de compras da Ana chegou num texto só. O padrão [^,]+ quer dizer "um ou mais caracteres que não são vírgula": cada pedaço entre vírgulas.

local compras = "pão, leite, café, ovos"
for item in compras:gmatch("[^,]+") do
  print("[" .. item .. "]")
end

$ lua lista.lua
[pão]
[ leite]
[ café]
[ ovos]

Os colchetes mostram um detalhe: depois de cada vírgula vem um espaço, e o espaço não é vírgula, então ele entrou no item. Para deixá-lo de fora, ponha %s* ("espaços, se houver") fora de uma captura:

local compras = "pão, leite, pão de queijo, ovos"
for item in compras:gmatch("%s*([^,]+)") do
  print("[" .. item .. "]")
end

$ lua lista2.lua
[pão]
[leite]
[pão de queijo]
[ovos]

Com uma captura no padrão, o gmatch entrega só o que está entre parênteses. E o espaço dentro de "pão de queijo" continuou, porque o [^,]+ aceita espaços; só os do começo de cada item ficaram com o %s*.

Missão: a professora digitou as notas num texto só. O programa conta e soma as notas, mas está errado: diz 5 notas, porque o %d+ partiu o 8.5 em dois. Troque o padrão por um que aceite algarismos e o ponto (um conjunto: "[%d%.]+") para mostrar 4 notas e Soma: 31.5.

local notas = "Notas: 7, 8.5, 10, 6"
local quantas = 0
local soma = 0
for nota in notas:gmatch("%d+") do
  quantas = quantas + 1
  soma = soma + tonumber(nota)
end
print(quantas .. " notas")
print("Soma: " .. soma)

local notas = "Notas: 7, 8.5, 10, 6"
local quantas = 0
local soma = 0
for nota in notas:gmatch("[%d%.]+") do
  quantas = quantas + 1
  soma = soma + tonumber(nota)
end
print(quantas .. " notas")
print("Soma: " .. soma)

O quantas = quantas + 1 e o soma = soma + … são o jeito de acumular dentro de um laço: as variáveis são criadas com 0 antes do laço, e cada volta soma um pouco. O tonumber é necessário porque o gmatch sempre entrega texto (veja Conversão).

3. Duas capturas, duas variáveis: pares chave=valor

Com duas capturas no padrão, cada volta entrega dois valores, e o for pode ter duas variáveis:

local ficha = "nome=Ana, idade=32, cidade=Recife"
for chave, valor in ficha:gmatch("(%w+)=(%w+)") do
  print(chave, valor)
end

$ lua pares.lua
nome	Ana
idade	32
cidade	Recife

Na 1ª volta, chave é "nome" e valor é "Ana"; na 2ª, "idade" e "32". Esse é o formato de muitos arquivos de configuração. Para guardar os pares numa tabela (dados[chave] = valor), veja Tabelas como Dicionários.

4. Contar, somar e guardar

local cont = 0
for _ in ("banana"):gmatch("a") do
  cont = cont + 1
end
print("letras a:", cont)

local total = 0
for preco in ("pão 8, leite 6, café 20"):gmatch("%d+") do
  total = total + tonumber(preco)
end
print("total:", total)

local lista = {}
for item in ("pão;leite;café"):gmatch("[^;]+") do
  lista[#lista + 1] = item
end
print(#lista, lista[1], lista[3])

$ lua juntar.lua
letras a:	3
total:	34
3	pão	café
for _ in …
Quando você não vai usar o achado, só contar as voltas, o costume é chamar a variável de _ (sublinhado): "este valor não importa".
total = total + tonumber(preco)
Cada preço achado (texto) vira número e entra na soma: 8 + 6 + 20 = 34.
lista[#lista + 1] = item
Põe o item na próxima posição livre da tabela lista (veja Tabelas como Listas). Depois do laço, a tabela tem os 3 itens, e você pode usá-los quando quiser.

5. Campos vazios e posições

Num arquivo do tipo "planilha" (CSV), um campo pode estar vazio: "pão;leite;;café" tem 4 campos, e o 3º está em branco. O + ("um ou mais") pula os vazios; o * ("zero ou mais") os mantém:

local linha = "pão;leite;;café"
for campo in linha:gmatch("[^;]+") do io.write("<", campo, ">") end
print()
for campo in linha:gmatch("([^;]*)") do io.write("<", campo, ">") end
print()

$ lua vazios.lua
<pão><leite><café>
<pão><leite><><café>

O io.write escreve sem pular linha (veja io.write()), e o print() vazio no fim pula a linha. Com [^;]+, o campo vazio sumiu, e o café pareceria ser o 3º campo. Com ([^;]*), ele aparece como <>: é o que você quer quando a posição do campo importa (3ª coluna = telefone, por exemplo).

Onde estava cada achado

A captura de posição () (veja Padrões) também funciona no gmatch:

for pos, nome in ("ana e bia"):gmatch("()(%a+)") do
  print(pos, nome)
end

$ lua posicoes.lua
1	ana
5	e
7	bia

6. Começar de outra posição, e o ^ que não funciona

Como no find, um terceiro argumento diz de onde começar 5.4+:

for w in ("um dois tres"):gmatch("%a+", 4) do
  print(w)
end
for w in ("um dois tres"):gmatch("^%a+") do
  print("com ^:", w)
end
print("fim")

$ lua inicio.lua
dois
tres
fim

A partir da posição 4 (o d de "dois"), o "um" ficou de fora. E o segundo laço não deu nenhuma volta: no gmatch, o ^ no começo do padrão não é âncora (o manual do Lua explica: uma âncora impediria a repetição), e o padrão não achou nada. Para pegar só o começo do texto, use match("^%a+").

Em outras versões

O terceiro argumento do gmatch existe a partir do Lua 5.4. No Lua 5.1 (e no LuaJIT, usado pelo Neovim e pelo LÖVE), ele é ignorado sem aviso: no lab, lua5.1 -e 'for w in ("um dois"):gmatch("%a+", 4) do print(w) end' mostrou um e dois. Veja As Diferenças entre Versões.

7. Por dentro: o gmatch devolve uma função

O gmatch não devolve os achados de uma vez: ele devolve uma função que, cada vez que é chamada, entrega o próximo. Esse tipo de função se chama iterador ("o que repete"), e é exatamente o que o for … in espera. Dá para chamá-lo na mão:

local proxima = ("a b c"):gmatch("%a")
print(type(proxima))
print(proxima())
print(proxima())
print(proxima())
print(proxima())
print(proxima() == nil)

$ lua iterador.lua
function
a
b
c

true

Quando os achados acabam, ele não devolve nada: o quarto print mostrou uma linha vazia. E "nada", quando se precisa de um valor, vale nil (a última linha confirma: true). É esse nil que avisa o for que é hora de parar. Você vai construir os seus próprios iteradores na aula Iteradores Próprios.

8. Acentos: a palavra partida

for palavra in ("Ana gosta de pão"):gmatch("%a+") do
  io.write(palavra, "|")
end
print()
for palavra in ("Ana gosta de pão"):gmatch("[%a\128-\255]+") do
  io.write(palavra, "|")
end
print()

$ lua acento.lua
Ana|gosta|de|p|o|
Ana|gosta|de|pão|

O %a só conhece as letras sem acento, e partiu "pão" em p e o. Com o conjunto [%a\128-\255] ("letra ou byte de letra acentuada", explicado em Padrões, seção 11), a palavra fica inteira. Outra saída, quando as palavras estão separadas por espaço, é "%S+": "tudo que não é espaço" (mas aí a pontuação vem grudada: "pão!").

Formas diferentes de fazer a mesma coisa

Contar quantas vezes um número aparece numa frase, de três jeitos:

local s = "mesa 1, mesa 22, mesa 5"
-- 1. gmatch e um contador
local n = 0
for _ in s:gmatch("%d+") do n = n + 1 end
print(n)
-- 2. gsub, usando só o número de trocas
local _, m = s:gsub("%d+", "%0")
print(m)
-- 3. find num laço, começando depois do achado anterior
local k, pos = 0, 1
while true do
  local i, j = s:find("%d+", pos)
  if not i then break end
  k = k + 1
  pos = j + 1
end
print(k)

$ lua contar.lua
3
3
3

O terceiro jeito usa o while, o if e o break, que você vai ver nas próximas aulas: é o que o gmatch faz por você, por dentro.

Você quer…Use
Fazer algo com cada achado (mostrar, somar, guardar)for x in s:gmatch(p) do … end
Só o primeiro achados:match(p)
Só a quantidade de achadoso segundo valor de s:gsub(p, "%0"), ou um contador com gmatch
Trocar cada achados:gsub(p, troca) (aula gsub)
Achados e as posiçõesgmatch("()(…)"), ou find num laço
Separar campos mantendo os vaziosgmatch("([^;]*)")

Quando dá errado

Esqueceu o do 
for palavra in ("a b"):gmatch("%a+")
  print(palavra)
end

$ lua sem-do.lua
lua: sem-do.lua:2: 'do' expected near 'print'

"Era esperado do perto de print". É erro de sintaxe: o programa nem começou (por isso não há traceback). O Lua leu a linha 1 inteira, chegou no print da linha 2 e percebeu que faltou o do antes dele. Como consertar: for palavra in ("a b"):gmatch("%a+") do.

Usou = no lugar de in 
for palavra = ("a b"):gmatch("%a+") do
  print(palavra)
end

$ lua igual.lua
lua: igual.lua:1: ',' expected near 'do'

"Era esperada uma , perto de do". O for com = é outro laço, o que conta números (for i = 1, 10 do, aula for Numérico), e ele esperava uma vírgula e o número final. Como consertar: com gmatch, é sempre for … in.

Usou o find no lugar do gmatch 
for palavra in ("a b"):find("%a+") do
  print(palavra)
end

$ lua find.lua
lua: find.lua:1: attempt to call a number value (for iterator 'for iterator')
stack traceback:
	find.lua:1: in main chunk
	[C]: in ?

Linha por linha:

attempt to call a number value
"Tentativa de chamar um valor numérico". O for … in espera uma função (um iterador) para chamar a cada volta. O find devolveu um número (a posição 1), e um número não pode ser chamado.
(for iterator 'for iterator')
O Lua diz quem ele tentou chamar: o iterador do for.
find.lua:1: in main chunk / [C]: in ?
Na linha 1 do programa principal, rodado pelo lua.

Como consertar: no for, use gmatch. O find e o match devolvem resultados prontos, não iteradores.

Chamou o iterador antes do for 
$ lua -e 'for w in ("a b"):gmatch("%a+")() do print(w) end'
lua: (command line):1: attempt to call a string value (for iterator 'for iterator')
stack traceback:
	(command line):1: in main chunk
	[C]: in ?

Os () a mais depois do gmatch(…) chamaram o iterador uma vez, ali mesmo: ele devolveu o primeiro achado, o texto "a", e o for tentou chamar esse texto. (O lua -e roda o código direto do terminal: o lugar aparece como (command line):1.) Como consertar: deixe o for chamar o iterador; escreva só gmatch("%a+").

Padrão malformado: o erro aparece na primeira volta 
$ lua -e 'for w in ("a b"):gmatch("(%a") do print(w) end'
lua: (command line):1: unfinished capture
stack traceback:
	[C]: in for iterator 'for iterator'
	(command line):1: in main chunk
	[C]: in ?

"Captura não terminada": faltou o ). Repare no traceback: o erro não foi dentro do gmatch, mas dentro do iterador ([C]: in for iterator). O gmatch só prepara a esteira; o padrão é lido quando a primeira volta pede o primeiro achado. Como consertar: feche a captura, "(%a)". As outras mensagens de padrão estão em Padrões.

O texto estava vazio (nil) 
$ lua -e 'for w in string.gmatch(nil, "%a") do print(w) end'
lua: (command line):1: bad argument #1 to 'gmatch' (string expected, got nil)
stack traceback:
	[C]: in field 'gmatch'
	(command line):1: in main chunk
	[C]: in ?

"Esperava um texto, recebeu nil". Acontece quando o texto deveria ter vindo de algum lugar (uma leitura de arquivo, um match que não achou) e não veio. Com o dois-pontos (texto:gmatch(…) e texto vazio), a mensagem seria attempt to index a nil value. Como consertar: confira o texto antes do laço.

Missão: o programa conta as palavras da frase, mas diz 9 palavras: o %a+ partiu "pão" e "açúcar" nos acentos (e ainda cortou o "café"). Troque o padrão por um que mantenha as palavras com acento inteiras, para mostrar 7 palavras. Dica: "[%a\128-\255]+", ou "%S+".

local frase = "pão de queijo e café com açúcar"
local quantas = 0
for palavra in frase:gmatch("%a+") do
  quantas = quantas + 1
  io.write(palavra, "|")
end
print()
print(quantas .. " palavras")

local frase = "pão de queijo e café com açúcar"
local quantas = 0
for palavra in frase:gmatch("[%a\128-\255]+") do
  quantas = quantas + 1
  io.write(palavra, "|")
end
print()
print(quantas .. " palavras")

O io.write(palavra, "|") mostra o que cada volta pegou, separado por |: assim você vê exatamente onde o padrão partiu as palavras. É um bom hábito para conferir qualquer gmatch.

Resumo

  • for x in s:gmatch(p) do … end passa por todos os achados de p, um por volta; se não houver nenhum, o laço não roda.
  • Com capturas, cada volta entrega uma variável por captura: for chave, valor in s:gmatch("(%w+)=(%w+)") do.
  • Os achados são sempre texto: tonumber para somar. Para contar, um contador; para guardar, lista[#lista + 1] = x.
  • [^,]+ separa por vírgulas (pulando vazios); ([^;]*) mantém os campos vazios; () dá a posição.
  • O terceiro argumento diz onde começar (5.4+; ignorado no 5.1/LuaJIT). O ^ não é âncora no gmatch.
  • O gmatch devolve um iterador: uma função que dá o próximo achado a cada chamada, e nada (nil) no fim.
