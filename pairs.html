Lua pairs

Na aula Tabelas como Dicionários, o print(precos) só mostrava table: 0x…, e o # dava 0. Para ver todos os pares de uma tabela, um por um, o Lua tem o pairs (em inglês, "pares"). Ele passa por todas as chaves, sejam nomes, números ou qualquer outra coisa. Só tem um detalhe muito importante: ele não promete ordem nenhuma.

Você vai aprender
  • A escrever o laço for chave, valor in pairs(t) do … end.
  • Que a ordem do pairs não é garantida, e pode mudar de uma execução para outra.
  • A mostrar as chaves em ordem: guardar numa lista e usar table.sort.
  • A contar e somar os pares de um dicionário.
  • A diferença entre pairs e ipairs.
  • A saber se uma tabela está vazia com next, e o que pode e o que não pode mudar durante o laço.
  • Os erros reais do pairs.

A ideia: abrir todas as gavetas

O dicionário é um armário de gavetas com etiquetas. O pairs abre todas as gavetas, uma de cada vez, e a cada uma diz a etiqueta (a chave) e o que tem dentro (o valor). Mas ele abre na ordem em que as gavetas estão arrumadas por dentro do armário, que você não controla: não é a ordem alfabética, nem a ordem em que você guardou as coisas.

1. O laço for … in pairs(t)

local estoque = {arroz = 5, feijao = 3, leite = 12, cafe = 2, pao = 40}
for produto, quantidade in pairs(estoque) do
  print(produto, quantidade)
end
for
"Para": começa um laço, como o for numérico, só que de outro tipo, o for genérico.
produto, quantidade
Duas variáveis novas, que só existem dentro do laço. A cada volta, a primeira recebe a chave e a segunda, o valor. Os nomes são escolha sua: use nomes que digam o que são (produto, quantidade é melhor que k, v).
in
"Em": "para cada par em…".
pairs(estoque)
A tabela que vai ser percorrida.
do … end
O corpo do laço, que roda uma vez para cada par.

A ordem do pairs não é garantida

O manual do Lua diz que a ordem em que o pairs passa pelas chaves não é especificada, mesmo para chaves numéricas. No Lua 5.5 do laboratório, com chaves de texto, ela muda de uma execução para outra (o Lua sorteia, a cada execução, um detalhe de como arruma as chaves por dentro). No seu computador, ou no editor do guia, vai sair outra ordem. Por isso:

  • nunca escreva um programa que dependa da ordem do pairs;
  • quando a ordem importa (uma lista para o usuário ler), ordene as chaves (seção 3).

Experimente: rode esta caixa algumas vezes e compare a ordem das linhas. Depois acrescente um produto ao estoque e rode de novo.

local estoque = {arroz = 5, feijao = 3, leite = 12, cafe = 2, pao = 40}
for produto, quantidade in pairs(estoque) do
  print(produto .. ": " .. quantidade)
end

2. Contar e somar: quando a ordem não importa

Muita coisa não depende da ordem: contar quantos pares há, somar os valores, achar o maior. Para essas, o pairs serve direto:

local estoque = {arroz = 5, feijao = 3, leite = 12, cafe = 2, pao = 40}
local produtos = 0
local unidades = 0
for _, quantidade in pairs(estoque) do
  produtos = produtos + 1
  unidades = unidades + quantidade
end
print(produtos .. " produtos, " .. unidades .. " unidades")
print(#estoque)

$ lua contar.lua
5 produtos, 62 unidades
0
for _, quantidade in pairs(estoque)
Aqui a chave não é usada. O costume é chamar a variável que você vai ignorar de _ (sublinhado): quem lê entende "isso não interessa".
produtos = produtos + 1
Uma volta por par: no fim, produtos é a quantidade de pares. É o jeito de "medir" um dicionário.
print(#estoque)
O # continua dando 0: ele só conta a parte de lista (aula Dicionários).

A soma deu 62 e a contagem deu 5, e vai dar isso em toda execução, em qualquer ordem: somar não depende da ordem das parcelas.

Só as chaves

Se você só precisa das chaves, escreva uma variável só: for produto in pairs(estoque) do. O valor é jogado fora, como na atribuição múltipla.

3. Em ordem: ordenando as chaves

O pairs não tem ordem, mas uma lista tem, e uma lista se ordena com table.sort (aula table.sort). A receita tem três passos:

  1. Passe pelo dicionário com pairs e guarde cada chave numa lista.
  2. Ordene a lista com table.sort.
  3. Percorra a lista com ipairs e, para cada chave, pegue o valor no dicionário.
local estoque = {arroz = 5, feijao = 3, leite = 12, cafe = 2, pao = 40}
local nomes = {}
for produto in pairs(estoque) do
  table.insert(nomes, produto)
end
table.sort(nomes)
for _, produto in ipairs(nomes) do
  print(produto, estoque[produto])
end

Ordenar pelo valor

Para mostrar do produto com mais unidades para o com menos, ordene as mesmas chaves, mas comparando os valores. O table.sort aceita uma função que diz quem vem antes:

local estoque = {arroz = 5, feijao = 3, leite = 12, cafe = 2, pao = 40}
local nomes = {}
for produto in pairs(estoque) do
  nomes[#nomes + 1] = produto
end
table.sort(nomes, function(a, b)
  return estoque[a] > estoque[b]
end)
for i, produto in ipairs(nomes) do
  print(i, produto, estoque[produto])
end

Outra forma de pôr no fim da lista, igual a table.insert(nomes, produto).

"a vem antes de b se o estoque de a for maior". Com >, do maior para o menor. (Se dois valores forem iguais, a ordem entre eles não é garantida; aula table.sort.)

4. pairs × ipairs

Os dois percorrem tabelas, mas de jeitos diferentes:

local cores = {"vermelho", "verde", "azul"}
for i, cor in ipairs(cores) do
  print("ipairs", i, cor)
end
for chave, cor in pairs(cores) do
  print("pairs", chave, cor)
end
local turma = {"Ana", "Bia", nome = "3º A"}
for chave, valor in ipairs(turma) do
  print("ipairs", chave, valor)
end
local quantos = 0
for chave, valor in pairs(turma) do
  quantos = quantos + 1
end
print("pairs viu", quantos)

$ lua lista_pairs.lua
ipairs	1	vermelho
ipairs	2	verde
ipairs	3	azul
pairs	1	vermelho
pairs	2	verde
pairs	3	azul
ipairs	1	Ana
ipairs	2	Bia
pairs viu	3

Numa lista, o pairs também passa pelas posições 1, 2, 3, e aqui elas saíram em ordem. Mas isso não é garantido pelo manual: para percorrer uma lista em ordem, o certo é o ipairs (ou o for i = 1, #t). Na tabela misturada, o ipairs só viu a parte de lista (Ana e Bia); o pairs viu os 3 pares, incluindo o nome.

5. Tabela vazia, e mudar a tabela durante o laço

Está vazia? next(t) == nil

Num dicionário, o # não diz se a tabela está vazia. Quem diz é o next, a função que o pairs usa por dentro: next(t) devolve "algum" par da tabela, ou nil se não houver nenhum.

local carrinho = {}
print(next(carrinho))
print(next(carrinho) == nil)
carrinho.pao = 2
print(next(carrinho))
print(next(carrinho) == nil)

$ lua vazia.lua
nil
true
pao	2
false

Com um par só, o next mostrou esse par. Com vários, ele mostra um qualquer (o primeiro da ordem interna); para a pergunta "está vazia?", só interessa se deu nil ou não.

Apagar durante o laço pode; acrescentar, não

O manual permite mudar ou apagar (guardar nil) as chaves que já existem durante o pairs. Assim, para tirar os produtos que acabaram:

local estoque = {arroz = 5, feijao = 0, leite = 12, cafe = 0, pao = 40}
for produto, quantidade in pairs(estoque) do
  if quantidade == 0 then
    estoque[produto] = nil
  end
end
print(estoque.feijao, estoque.cafe, estoque.arroz)

$ lua apagar.lua
nil	nil	5
Não acrescente chaves novas dentro do pairs

O manual diz que não se deve guardar valor numa chave que ainda não existe durante o laço. O resultado não é definido: o laço pode pular chaves, passar duas vezes pela mesma, ou parar com o erro invalid key to 'next' ("chave inválida para o next": foi o que saiu no laboratório num teste que apagava a chave atual e acrescentava 100 chaves novas a cada volta). Às vezes "funciona", o que é pior, porque o erro aparece outro dia. Se precisa criar chaves, guarde-as numa tabela nova e junte depois do laço.

Ordenar chaves de tipos diferentes 
local t = {"Ana", "Bia", turma = "3º A"}
local chaves = {}
for k in pairs(t) do chaves[#chaves + 1] = k end

$ lua erro_ordenar.lua

	[C]: in field 'sort'
	erro_ordenar.lua:4: in main chunk

As chaves são 1, 2 (números) e "turma" (texto). O table.sort usa o <, e o Lua não sabe dizer se um texto é "menor" que um número: "tentativa de comparar string com number". A primeira linha não tem o número da linha porque o erro aconteceu dentro do sort (em C); a linha 4 aparece no rastro. Como consertar: compare tudo como texto:

local t = {"Ana", "Bia", turma = "3º A"}
local chaves = {}
for k in pairs(t) do chaves[#chaves + 1] = k end
table.sort(chaves, function(a, b) return tostring(a) < tostring(b) end)
for _, k in ipairs(chaves) do print(k, t[k]) end

O programa "funcionava" e mudou de ordem

A Ana fez um programa que mostra o estoque com pairs e escreveu no relatório "o primeiro produto é o leite", porque foi o que saiu quando ela testou. No dia seguinte, o primeiro era o café. Não houve erro nenhum: o programa dependia da ordem do pairs, que não é garantida (seção 1). Como consertar: se a ordem aparece para alguém ou é usada numa conta, ordene as chaves (seção 3).

Missão final: o estoque em ordem

Missão: o programa mostra o estoque com pairs, e a ordem sai bagunçada (e pode mudar a cada Rodar). Junte as chaves numa lista, ordene com table.sort e mostre em ordem alfabética, no mesmo formato: arroz: 5, cafe: 2, feijao: 3, leite: 12, pao: 40, um por linha.

local estoque = {arroz = 5, feijao = 3, leite = 12, cafe = 2, pao = 40}
for produto, quantidade in pairs(estoque) do
  print(produto .. ": " .. quantidade)
end

local estoque = {arroz = 5, feijao = 3, leite = 12, cafe = 2, pao = 40}
local nomes = {}
for produto in pairs(estoque) do
  table.insert(nomes, produto)
end
table.sort(nomes)
for _, produto in ipairs(nomes) do
  print(produto .. ": " .. estoque[produto])
end

Resumo

  • for chave, valor in pairs(t) do … end passa por todos os pares da tabela.
  • A ordem do pairs não é garantida: no laboratório, o mesmo programa saiu em ordens diferentes em duas execuções. Não dependa dela.
  • Para mostrar em ordem: chaves numa lista, table.sort, e ipairs na lista, pegando o valor com t[chave].
  • Contar e somar não dependem da ordem: o pairs serve direto (e é o jeito de contar os pares de um dicionário).
  • ipairs é para listas (em ordem, até o primeiro buraco); pairs é para todas as chaves.
  • next(t) == nil diz se a tabela está vazia. Durante o pairs, pode apagar ou mudar pares existentes, mas não criar chaves novas.
