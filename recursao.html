Lua Recursão

Uma função pode chamar qualquer função, inclusive ela mesma. Quando isso acontece, dizemos que a função é recursiva, e a técnica se chama recursão. Parece um truque de mágica (como a função pode usar a si mesma se ela ainda nem terminou?), mas é só uma forma de resolver um problema grande quebrando-o em um pedaço igual, só que menor, até chegar num pedaço tão pequeno que a resposta é óbvia.

Você vai aprender
  • As duas partes de toda função recursiva: o caso base (onde ela para) e o caso recursivo (onde ela chama a si mesma com um problema menor).
  • Contagem regressiva, fatorial e soma de uma lista, passo a passo, com o "rastro" das chamadas.
  • Onde a recursão brilha de verdade: percorrer uma estrutura com níveis dentro de níveis (um cardápio com subcategorias).
  • Por que o Fibonacci recursivo é lento, e como uma tabela de "memória" resolve.
  • O que é a pilha de chamadas e o erro real stack overflow: quantas chamadas cabem no Lua 5.5.
  • Por que a função recursiva precisa ser local function nome, e o erro (global 'fatorial').

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook) com lua arquivo.lua. Antes, convém conhecer Funções e return.

A ideia: a fila do pão

A Ana chega à padaria e encontra uma fila enorme. Ela quer saber em que posição está, mas não dá para contar daqui. Então ela cutuca a pessoa da frente: "qual é a sua posição?". Essa pessoa também não sabe, e cutuca a da frente dela com a mesma pergunta. E assim por diante, até chegar à primeira pessoa da fila, que olha para o balcão e diz: "eu sou a 1ª!".

Aí as respostas voltam: a segunda pessoa pensa "a da minha frente é a 1ª, então eu sou a 2ª", e conta para quem perguntou. A terceira faz 2 + 1 = 3. … Até a resposta chegar à Ana.

Repare nas duas regras que cada pessoa segue, que são as duas partes de toda recursão:

  1. Caso base: se não tem ninguém na sua frente, responda 1. É a pergunta que se responde sem perguntar para mais ninguém. É ele que faz a recursão parar.
  2. Caso recursivo: senão, pergunte a mesma coisa para a pessoa da frente (um problema menor: a fila dela é mais curta) e some 1 à resposta.

Sem o caso base, ninguém nunca pararia de perguntar. Sem o problema ficar menor a cada passo, a pergunta nunca chegaria ao começo da fila. Nos dois casos, o resultado é o mesmo: o programa quebra com stack overflow, como você vai ver na seção 6.

1. A primeira função recursiva: contagem regressiva

local function contagem(n)
  if n == 0 then
    print("Já!")
    return
  end
  print(n .. "...")
  contagem(n - 1)
end

contagem(3)
local function contagem(n)
Uma função comum, com um parâmetro n (quantos segundos faltam). O local function é importante aqui; a seção Quando dá errado mostra por quê.
if n == 0 then … return end
O caso base: quando não falta mais nada, mostra Já! e o return sai da função sem chamar mais ninguém. É aqui que a recursão para.
print(n .. "...")
O trabalho desta chamada: mostrar o número atual.
contagem(n - 1)
O caso recursivo: a função chama a si mesma com um problema menor (um segundo a menos). Cada chamada fica esperando a próxima terminar.

2. Recursão que devolve um valor: o fatorial

O fatorial de um número (escrito 5! na matemática) é a multiplicação de todos os inteiros de 1 até ele: 5! = 5 × 4 × 3 × 2 × 1 = 120. Ele aparece em contas de combinação: de quantas formas diferentes dá para arrumar 5 pães na vitrine? 120.

A sacada para a recursão: 5! = 5 × 4!. E 4! = 4 × 3!. E assim vai, até 1! = 1, que é o caso base.

local function fatorial(n)
  if n <= 1 then
    return 1
  end
  return n * fatorial(n - 1)
end

print(fatorial(1))
print(fatorial(3))
print(fatorial(5))
print(fatorial(10))
print(fatorial(20))
if n <= 1 then return 1 end
Caso base: o fatorial de 1 (e de 0, por definição) é 1. Usar <= 1 em vez de == 1 protege a função se alguém chamar fatorial(0).
return n * fatorial(n - 1)
Caso recursivo: "o meu resultado é n vezes o fatorial do número anterior". Para fazer essa multiplicação, a chamada atual precisa esperar a resposta de fatorial(n - 1).

Seguindo o rastro das chamadas

Para enxergar a ida e a volta, a versão abaixo recebe um segundo parâmetro, nivel, que só serve para recuar o texto (2 espaços por nível, com string.rep):

local function fatorial(n, nivel)
  local recuo = string.rep("  ", nivel)
  print(recuo .. "fatorial(" .. n .. ") começou")
  if n <= 1 then
    print(recuo .. "fatorial(" .. n .. ") devolve 1")
    return 1
  end
  local resultado = n * fatorial(n - 1, nivel + 1)
  print(recuo .. "fatorial(" .. n .. ") devolve " .. resultado)
  return resultado
end

print("Resultado:", fatorial(4, 0))

3. Recursão com listas: somar os itens

Dá para pensar numa lista do mesmo jeito: "a soma da lista é o primeiro item mais a soma do resto". E a soma de uma lista vazia é 0 (caso base). Esta versão anda pela lista com um índice i:

local function soma(lista, i)
  i = i or 1
  if i > #lista then
    return 0
  end
  return lista[i] + soma(lista, i + 1)
end

print(soma({10, 20, 30}))
print(soma({}))
i = i or 1
Se quem chamou não passou o i, ele vale nil, e o or põe 1 no lugar: a soma começa do primeiro item (veja and, or e not).
if i > #lista then return 0 end
Caso base: o índice passou do último item (#lista é o tamanho). Não sobrou nada para somar.
lista[i] + soma(lista, i + 1)
Caso recursivo: o item atual mais a soma do resto da lista.
$ lua soma_lista.lua
60
0

Funciona, mas sejamos honestos: para somar uma lista, um for é mais simples e mais rápido. A recursão vale mesmo a pena no próximo caso.

4. Onde a recursão brilha: níveis dentro de níveis

O cardápio da padaria tem categorias, e algumas categorias têm subcategorias: "Doces" tem "Bolos", que tem "Cenoura" e "Fubá". Ninguém sabe de antemão quantos níveis existem. Com laços, você precisaria de um for dentro de um for dentro de um for… e quantos? Com recursão, uma função dá conta de qualquer profundidade:

local cardapio = {
  nome = "Padaria",
  itens = {
    { nome = "Pães", itens = {
      { nome = "Francês" },
      { nome = "Integral" },
    }},
    { nome = "Doces", itens = {
      { nome = "Bolos", itens = {
        { nome = "Cenoura" },
        { nome = "Fubá" },
      }},
      { nome = "Sonho" },
    }},
    { nome = "Café" },
  },
}

local function mostrar(no, nivel)
  print(string.rep("  ", nivel) .. "- " .. no.nome)
  if no.itens then
    for _, filho in ipairs(no.itens) do
      mostrar(filho, nivel + 1)
    end
  end
end

mostrar(cardapio, 0)

Mostra o nome deste nó, recuado conforme o nível.

Caso base "escondido": um nó sem itens (como "Francês") não chama mais ninguém. A recursão para sozinha nas folhas.

Pastas dentro de pastas no computador, comentários com respostas de respostas, a árvore genealógica da família, menus com submenus: tudo isso tem o mesmo formato, e a recursão é o jeito natural de percorrer.

5. Cuidado com a repetição: o Fibonacci

A sequência de Fibonacci começa com 1, 1, e cada número seguinte é a soma dos dois anteriores: 1, 1, 2, 3, 5, 8, 13… A definição já é recursiva: fib(n) = fib(n - 1) + fib(n - 2). Escrevendo do jeito mais direto, e contando quantas vezes a função é chamada:

local chamadas = 0
local function fib(n)
  chamadas = chamadas + 1
  if n <= 2 then return 1 end
  return fib(n - 1) + fib(n - 2)
end

for _, n in ipairs({10, 20, 30}) do
  chamadas = 0
  print("fib(" .. n .. ") = " .. fib(n), "chamadas: " .. chamadas)
end

$ lua fib.lua
fib(10) = 55	chamadas: 109
fib(20) = 6765	chamadas: 13529
fib(30) = 832040	chamadas: 1664079

Mais de 1,6 milhão de chamadas para calcular o 30º número! O motivo: fib(30) chama fib(29) e fib(28); mas fib(29) também chama fib(28), que é calculado de novo do zero. E cada um deles recalcula os de baixo, outra vez e outra vez. A cada número a mais, o trabalho quase dobra.

A solução: anotar o que já foi calculado

Se a função guardar cada resposta numa tabela, ela nunca calcula a mesma coisa duas vezes. Essa técnica se chama memoização (de "memória"):

local chamadas = 0
local guardados = {}
local function fib(n)
  chamadas = chamadas + 1
  if n <= 2 then return 1 end
  if guardados[n] then return guardados[n] end
  local r = fib(n - 1) + fib(n - 2)
  guardados[n] = r
  return r
end

print(fib(30), "chamadas: " .. chamadas)
chamadas = 0
print(fib(90), "chamadas: " .. chamadas)

$ lua fib_memo.lua
832040	chamadas: 57
2880067194370816120	chamadas: 121

De 1.664.079 chamadas para 57. E o fib(90), que sem a memória levaria anos, sai na hora (aproveitando o que já estava guardado até o 30). A tabela guardados fica fora da função, numa local que ela enxerga (veja Closures).

6. A pilha de chamadas e o stack overflow

Cada chamada que ainda não terminou precisa ser lembrada em algum lugar: qual função era, em que linha ela parou, quanto valiam as locais dela. O Lua guarda isso numa pilha de chamadas (em inglês, call stack), como uma pilha de pratos: cada chamada nova é um prato em cima; cada return tira o prato de cima.

A pilha tem um tamanho máximo. Uma recursão que nunca chega ao caso base empilha pratos até não caber mais nenhum, e o Lua para o programa com o erro stack overflow ("estouro da pilha"). Veja um fatorial em que a Ana esqueceu o caso base:

local function fatorial(n)
  return n * fatorial(n - 1)
end

print(fatorial(5))

Quantas chamadas cabem na pilha?

Dá para medir: o programa abaixo desce sem parar, anota até onde chegou e usa o pcall para capturar o erro em vez de quebrar:

local maior = 0
local function descer(n)
  maior = n
  descer(n + 1)
end

print(pcall(descer, 1))
print("chegou a", maior, "chamadas")

Quase 500 mil chamadas empilhadas no Lua 5.5 da Ana. O editor do guia, que roda o mesmo Lua 5.5 no navegador, chega exatamente ao mesmo número. Mas esse limite não é fixo: ele é contado em "espaço de pilha", e cada chamada ocupa mais espaço quanto mais locais ela tem. Com 10 locais a mais dentro do descer, a mesma medição parou em 83332. Uma recursão que não estoura

Existe um tipo especial de chamada que não empilha: quando a última coisa que a função faz é return outra_chamada(...), sem nenhuma conta depois. Com ela, uma função pode chamar a si mesma um milhão de vezes sem estourar nada. É a próxima aula: Chamada de Cauda.

7. Duas funções que se chamam: recursão mútua

A recursão também pode dar uma volta: a chama b, que chama a. Um exemplo clássico (de brincadeira, porque o % resolve isso numa linha): "um número é par se o anterior for ímpar".

local impar

local function par(n)
  if n == 0 then return true end
  return impar(n - 1)
end

function impar(n)
  if n == 0 then return false end
  return par(n - 1)
end

print(par(10), impar(7), par(3))

$ lua par_impar.lua
true	true	false

O detalhe de escopo: a par usa a impar, que só é escrita depois. Por isso a linha 1 declara a local impar antes (vazia), e a linha 8 (function impar, sem local) preenche essa mesma local. Sem a linha 1, a par procuraria uma global impar. A regra está em Escopo e Blocos.

Formas diferentes de fazer a mesma coisa

Quase toda recursão pode virar um laço, e vice-versa. O fatorial com for:

local function fatorial(n)
  local r = 1
  for i = 2, n do
    r = r * i
  end
  return r
end
print(fatorial(5), fatorial(20))

Missão: a função potencia(base, exp) deveria calcular base elevado a exp (2 elevado a 10 = 1024). O caso base já está pronto (qualquer número elevado a 0 é 1). Complete o caso recursivo: a potência é base vezes a potência com o expoente um a menos.

local function potencia(base, exp)
  if exp == 0 then
    return 1
  end
  return base
end

print(potencia(3, 4))

local function potencia(base, exp)
  if exp == 0 then
    return 1
  end
  return base * potencia(base, exp - 1)

"Tentativa de chamar um valor nil (global 'fatorial')". De novo a pista global: uma local só vale depois da linha que a declara, e a função inteira (linhas 1 a 4) faz parte dessa linha. Quando o Lua leu o fatorial(n - 1) da linha 3, a local fatorial ainda não existia, e ele entendeu "uma global chamada fatorial", que não existe. Repare no rastro: a primeira chamada funcionou (in local 'fatorial', vinda da linha 6); o erro foi na chamada de dentro.

Como consertar: use local function fatorial(n). Essa forma é um atalho que o Lua traduz para local fatorial; fatorial = function(n) … end: primeiro cria a local, depois põe a função nela, e assim a função enxerga o próprio nome.

Fibonacci "travado"

Não é erro, mas parece: um fib(40) sem memoização faz mais de 200 milhões de chamadas (204.668.309, pela conta do contador) e demora bastante: no editor do guia, ele passou do limite de 10 segundos e foi interrompido, com a mensagem o editor parou o programa: ele rodou mais de 10 segundos sem terminar. Se uma recursão com duas chamadas (fib(n - 1) + fib(n - 2)) está lenta, guarde os resultados numa tabela (seção 5).

Missão final: a soma que estourava

Missão: a função soma_ate(n) deveria somar 1 + 2 + … + n, mas ela estoura a pilha (stack overflow). Rode para ver o erro e acrescente o caso base que falta (a soma até 0 é 0), para o programa mostrar 5050.

local function soma_ate(n)
  return n + soma_ate(n - 1)
end

print(soma_ate(100))

local function soma_ate(n)
  if n == 0 then
    return 0
  end
  return n + soma_ate(n - 1)
end

print(soma_ate(100))

No lab, com o caso base, soma_ate(100) deu 5050 e até soma_ate(100000) funcionou (5000050000): cem mil chamadas empilhadas ainda cabem nos ~500 mil do Lua 5.5. No LuaJIT, que para perto de 22 mil, o mesmo programa estouraria.

Resumo

  • Uma função recursiva chama a si mesma com um problema menor.
  • Toda recursão precisa de um caso base (resposta direta, sem nova chamada) e de um caso recursivo que se aproxime dele a cada passo.
  • As chamadas descem até o caso base e as respostas sobem de volta; cada chamada tem as suas próprias locais.
  • A recursão brilha em estruturas com níveis dentro de níveis; para contas "em linha reta", um laço costuma ser mais simples.
  • Duas chamadas recursivas por vez (Fibonacci) podem explodir o trabalho; guardar os resultados numa tabela (memoização) resolve.
  • Sem caso base, a pilha de chamadas enche e o Lua para com stack overflow (no 5.5, perto de 500 mil chamadas simples).
  • Declare com local function nome, senão a função não enxerga o próprio nome ((global 'nome')).
