Lua Vários Retornos

Na aula return, cada função devolvia um valor. Mas às vezes a resposta tem duas partes: uma divisão tem o resultado e o resto; uma lista de notas tem a menor e a maior; uma busca tem o achado ou o motivo de não ter achado. Em muitas linguagens você precisaria embrulhar tudo numa lista. No Lua, não: o return devolve quantos valores quiser, separados por vírgula.

Você vai aprender
  • A devolver vários valores com return a, b e a recebê-los com local x, y = f().
  • O que acontece com variáveis a mais ou a menos, e o _ para ignorar um valor.
  • O costume do Lua return nil, "mensagem" para avisar que algo deu errado.
  • As funções prontas que já devolvem vários valores: string.find, string.gsub, math.modf, io.open.
  • As regras de ajuste: quando os valores todos passam e quando só o primeiro passa (só a última chamada da lista expande; os parênteses cortam para um).
  • Os erros reais que essas regras causam, como bad argument #2 to 'insert'.

A ideia: o troco com a nota fiscal

Quando a Ana paga na padaria, o caixa devolve duas coisas: o troco e a nota fiscal. Ela pode guardar as duas, guardar só o troco e jogar a nota fora, ou estender a mão esperando três coisas e ficar com uma mão vazia. Uma função com vários retornos é assim: ela entrega vários valores de uma vez, na ordem, e quem recebe decide quantos pega.

1. Devolvendo e recebendo dois valores

A divisão inteira tem duas respostas: quantas vezes o 5 cabe no 17 (3) e quanto sobra (2). Uma função pode devolver as duas:

local function dividir(a, b)
  return a // b, a % b
end

local q, r = dividir(17, 5)
print("17 dividido por 5 dá " .. q .. " e sobra " .. r)

$ lua dividir.lua
17 dividido por 5 dá 3 e sobra 2
return a // b, a % b
Dois valores, separados por vírgula: o quociente (//, divisão inteira) e o resto (%), da aula Divisão.
local q, r = dividir(17, 5)
Duas variáveis do lado esquerdo, separadas por vírgula, como na Atribuição Múltipla. O 1º valor devolvido vai para q, o 2º para r.

Variáveis a menos, a mais, e o _

A regra é a mesma dos argumentos (aula Parâmetros e Argumentos): o que sobra é descartado; o que falta vira nil.

local function dividir(a, b)
  return a // b, a % b
end

local q = dividir(17, 5)
print("só uma variável:", q)

local x, y, z = dividir(17, 5)
print("três variáveis:", x, y, z)

local _, resto = dividir(17, 5)
print("só o resto:", resto)

$ lua receber.lua
só uma variável:	3
três variáveis:	3	2	nil
só o resto:	2
local q = dividir(17, 5)
Uma variável só: ela fica com o 1º valor, e o resto (2) é jogado fora. A Ana pegou o troco e deixou a nota.
local x, y, z = …
Três variáveis para dois valores: z fica nil. A mão vazia.
local _, resto = …
Para pegar só o segundo, ponha um nome qualquer no primeiro. O costume é o _ (sublinhado), que quer dizer "não vou usar este". Para o Lua, _ é um nome de variável comum; é só um combinado entre programadores.

Um exemplo útil: a menor e a maior nota

local function menor_maior(lista)
  local menor, maior = lista[1], lista[1]
  for i = 2, #lista do
    if lista[i] < menor then menor = lista[i] end
    if lista[i] > maior then maior = lista[i] end
  end
  return menor, maior
end

local notas = {7.5, 9, 4, 8, 6.5}
local pior, melhor = menor_maior(notas)
print("Pior nota: " .. pior)
print("Melhor nota: " .. melhor)

$ lua menor_maior.lua
Pior nota: 4
Melhor nota: 9

Uma passada só pela lista, e as duas respostas saem juntas.

2. O costume do Lua: return nil, "mensagem"

Quando uma função pode falhar, o Lua tem um costume: em caso de sucesso, devolve o resultado; em caso de falha, devolve nil e uma mensagem explicando o motivo.

local precos = {pao = 0.80, leite = 5.50, bolo = 18}

local function preco(produto)
  local valor = precos[produto]
  if valor == nil then
    return nil, "não temos " .. produto
  end
  return valor
end

for _, produto in ipairs({"leite", "sonho", "pao"}) do
  local valor, erro = preco(produto)
  if valor then
    print(produto .. ": R$ " .. string.format("%.2f", valor))
  else
    print("Erro: " .. erro)
  end
end

$ lua nil_msg.lua
leite: R$ 5.50
Erro: não temos sonho
pao: R$ 0.80

Quem chama recebe duas variáveis (valor, erro) e testa a primeira: se ela tem valor, deu certo; se é nil, a segunda diz por quê. Repare que o for _, produto in ipairs(…) usa o mesmo _ para ignorar a posição (aula ipairs).

Esse é exatamente o jeito do io.open, que abre arquivos (aula io.open). As funções prontas do Lua usam muito os vários retornos:

print(string.find("Padaria do bairro", "do"))
print(string.gsub("banana", "a", "o"))
print(math.modf(3.75))
print(io.open("nao_existe.txt"))

$ lua prontas.lua
9	10
bonono	3
3	0.75
nil	nao_existe.txt: No such file or directory	2
FunçãoO que devolveAula

3. As regras de ajuste: quando todos os valores passam

Aqui está a parte que confunde até quem já programa há tempos. Uma chamada que devolve vários valores nem sempre entrega todos. O Lua "ajusta" a quantidade conforme o lugar onde a chamada aparece. Veja com uma função que devolve "a", "b":

local function dois()
  return "a", "b"
end

print(dois())
print(dois(), "fim")
print("início", dois())
print((dois()))
print(dois() .. "!")
local t1 = {dois()}
local t2 = {dois(), "z"}
print(#t1, #t2, t2[1], t2[2])
local p, q, r = dois(), "x"
print(p, q, r)
local s, u, v = "x", dois()
print(s, u, v)

$ lua ajuste.lua
a	b
a	fim
início	a	b
a
a!
2	2	a	z
a	x	nil
x	a	b

A regra numa frase

Numa lista separada por vírgulas (argumentos, valores de uma atribuição, itens de uma tabela, valores de um return), só a última chamada se abre em todos os valores. Qualquer outra chamada, ou uma chamada entre parênteses, ou uma chamada no meio de uma conta, entrega só o primeiro. E uma chamada que devolve zero valores, num desses lugares, vira um nil.

Passando os valores adiante

Como a última chamada abre todos os valores, dá para mandar o resultado de uma função direto como argumentos de outra:

local function dividir(a, b)
  return a // b, a % b
end

local function mostrar(quociente, resto)
  print("quociente " .. quociente .. ", resto " .. resto)
end

mostrar(dividir(17, 5))

$ lua repassar.lua
quociente 3, resto 2

mostrar(dividir(17, 5)) vira mostrar(3, 2). E num return, a mesma regra: return dividir(n, 5) devolve os dois valores; return (dividir(n, 5)), só um:

local function dividir(a, b)
  return a // b, a % b
end

local function dividir_por_5(n)
  return dividir(n, 5)
end

local function so_quociente(n)
  return (dividir(n, 5))
end

print(dividir_por_5(17))
print(so_quociente(17))

$ lua return_chamada.lua

E nas outras versões?

Os vários retornos e as regras de ajuste são iguais no Lua 5.1, no LuaJIT, no 5.4 e no 5.5: o mesmo ajuste.lua deu exatamente a mesma saída no lua5.1 e no luajit. Para transformar uma tabela de volta em vários valores existe o table.unpack (no Lua 5.1 ele se chama só unpack; o LuaJIT aceita os dois nomes; no 5.5 só existe table.unpack): aula table.unpack e table.pack.

Formas diferentes de devolver mais de uma coisa

-- forma 1: vários valores
local function dividir1(a, b)
  return a // b, a % b
end

-- forma 2: uma tabela com campos
local function dividir2(a, b)
  return {quociente = a // b, resto = a % b}
end

local q, r = dividir1(17, 5)
local res = dividir2(17, 5)
print(q, r, res.quociente, res.resto)

$ lua formas.lua

return {campo = …}Muitas respostas, ou quando o resultado vai ser guardado e passado adiante: os nomes dos campos dizem o que é cada coisa, e as regras de ajuste não atrapalham

Os parênteses em volta de dividir(17, 5) parecem inofensivos, mas cortaram o resultado para um valor. r ficou nil, e o .. reclamou na linha 6: attempt to concatenate a nil value (local 'r'). Como consertar: tire os parênteses de fora: local q, r = dividir(17, 5).

A chamada no meio da lista 
local function dividir(a, b)
  return a // b, a % b
end

local function mostrar(quociente, resto, unidade)
  print(quociente .. " " .. unidade .. ", sobram " .. resto)
end

mostrar(dividir(17, 5), "caixas")

$ lua erro_meio.lua
lua: erro_meio.lua:6: attempt to concatenate a nil value (local 'unidade')
stack traceback:
	erro_meio.lua:6: in local 'mostrar'
	erro_meio.lua:9: in main chunk
	[C]: in ?

A ideia era mostrar(3, 2, "caixas"). Mas dividir(17, 5) não é o último argumento, então entregou só o 3. A chamada virou mostrar(3, "caixas"): o resto recebeu "caixas" e a unidade ficou nil. O rastro aponta a linha 9 como a chamada culpada. Como consertar: guarde os valores antes (local q, r = dividir(17, 5) e mostrar(q, r, "caixas")), ou ponha a chamada no fim da lista, mudando a ordem dos parâmetros.

O valor "escondido" do string.gsub 
local nomes = {}
table.insert(nomes, string.upper("ana"))
table.insert(nomes, string.gsub("bia lima", " ", "_"))
print(nomes[1], nomes[2])

$ lua erro_insert.lua
lua: erro_insert.lua:3: bad argument #2 to 'insert' (number expected, got string)
stack traceback:
	[C]: in field 'insert'
	erro_insert.lua:3: in main chunk
	[C]: in ?

Este é um clássico. O string.gsub devolve dois valores: "bia_lima" e 1 (uma troca). Como ele é o último argumento, os dois passam, e a chamada vira table.insert(nomes, "bia_lima", 1). Com três argumentos, o table.insert entende "insira o valor 1 na posição "bia_lima"" (aula table.insert e table.remove), e a posição tem de ser um número.

bad argument #2 to 'insert'
"Argumento nº 2 do insert inválido": o problema está no segundo argumento.
(number expected, got string)
"Esperava um número, veio um texto": no lugar da posição veio "bia_lima".
[C]: in field 'insert'
O erro foi detectado dentro do table.insert, que é escrito em C; o nosso código culpado é a linha 3.

Como consertar: parênteses em volta do gsub, para cortar para um valor:

local nomes = {}
table.insert(nomes, (string.gsub("bia lima", " ", "_")))
print(nomes[1])

$ lua erro_insert_ok.lua
bia_lima

Aqui os parênteses extras são exatamente o que se quer.

Resumo

  • return a, b devolve vários valores; local x, y = f() os recebe, na ordem.
  • Variáveis a menos: o que sobra é descartado. Variáveis a mais: ficam nil. Para pular um valor, _.
  • Costume para falhas: return nil, "mensagem"; é o que o io.open faz.
  • Só a última chamada de uma lista (argumentos, atribuição, tabela, return) entrega todos os valores; as outras entregam o primeiro.
  • Parênteses em volta, (f()), cortam para um valor; numa conta ou num .., também só o primeiro entra.
  • Cuidado com funções prontas de dois valores, como o string.gsub, como último argumento.
