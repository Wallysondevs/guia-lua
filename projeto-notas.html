Projeto Notas da Turma (CSV)

A Ana é professora e guarda as notas da turma numa planilha. A planilha sabe exportar um arquivo CSV, e é esse arquivo que o programa vai ler: calcular a média de cada aluno, dizer quem passou, mostrar um relatório em ordem e gravar um CSV novo com os resultados, que a planilha abre de volta. Este projeto não conversa com o teclado: ele lê um arquivo e escreve outro.

Você vai praticar
  • Ler um arquivo linha por linha com io.lines.
  • Separar cada linha nas vírgulas com gmatch e um padrão.
  • Guardar cada aluno como uma tabela com campos numa lista.
  • Calcular médias com uma função e escolher a situação com elseif.
  • Ordenar com table.sort e uma função de comparação, e alinhar colunas com string.format.
  • Gravar um arquivo novo com write.

O que vamos construir

O arquivo que a planilha exportou, notas.csv:

nome,prova1,prova2,prova3
Ana Clara,8.5,7.0,9.0
Bruno,5.0,6.5,4.0
Carla,7.0,7.0,7.5
Diego,3.5,5.0,6.0
Elisa,10,9.5,9.0

CSV quer dizer comma-separated values, "valores separados por vírgula": cada linha é uma linha da planilha, e as vírgulas separam as colunas. A primeira linha é o cabeçalho, com os nomes das colunas. (Repare que as notas usam ponto como separador decimal: 8.5. A vírgula já está ocupada separando as colunas.) O programa pronto, no terminal da Ana:

$ lua notas.lua

Ana Clara    8.5   7.0   9.0    8.17  aprovado(a)
Carla        7.0   7.0   7.5    7.17  aprovado(a)
Bruno        5.0   6.5   4.0    5.17  recuperação
Diego        3.5   5.0   6.0    4.83  reprovado(a)
------------------------------------------------
Média da turma: 6.97
Aprovados: 3 de 5
Relatório gravado em relatorio.csv.
$ cat relatorio.csv

Ana Clara,8.17,aprovado(a)
Carla,7.17,aprovado(a)

  1. Ler o CSV (io.lines, gmatch).
  2. Média e situação (funções, elseif).
  3. O relatório (table.sort com função, colunas com %5.1f).
  4. Gravar o relatorio.csv (io.open com "w").

E, depois delas, o que dá errado num CSV de verdade.

Antes de começar

Crie a pasta do projeto e, dentro dela, o notas.csv (copie o conteúdo acima num editor de texto; ou exporte da sua planilha como CSV, com ponto nos decimais). O programa vai se chamar notas.lua e fica na mesma pasta:

$ mkdir -p projetos/notas
$ cd projetos/notas

Versão 1 · Ler o CSV

O primeiro passo é transformar o texto do arquivo em dados que o programa entende: uma lista de alunos, cada um com nome e notas. O io.lines entrega o arquivo uma linha por vez; o gmatch quebra cada linha nas vírgulas.

local alunos = {}
local cabecalho = true

for linha in io.lines("notas.csv") do
  if cabecalho then
    cabecalho = false             -- a 1ª linha só tem os nomes das colunas
  else
    -- separa a linha nas vírgulas
    local campos = {}
    for campo in linha:gmatch("[^,]+") do
      campos[#campos + 1] = campo
    end

    local aluno = { nome = campos[1], notas = {} }
    for i = 2, #campos do
      aluno.notas[#aluno.notas + 1] = tonumber(campos[i])
    end
    alunos[#alunos + 1] = aluno
  end
end

print(#alunos .. " alunos lidos.")
for _, aluno in ipairs(alunos) do
  print(aluno.nome .. ": " .. table.concat(aluno.notas, " "))
end

Versão 2 · Média e situação

Com os dados em tabelas, as contas ficam fáceis. Três funções: separar (o laço do gmatch, agora com nome), media e situacao. A regra da escola da Ana: média 7 ou mais, aprovado; de 5 a 7, recuperação; abaixo de 5, reprovado.

-- Separa uma linha do CSV nas vírgulas.
local function separar(linha)
  local campos = {}
  for campo in linha:gmatch("[^,]+") do
    campos[#campos + 1] = campo
  end
  return campos
end

local function media(notas)
  local soma = 0
  for _, nota in ipairs(notas) do
    soma = soma + nota
  end
  return soma / #notas
end

local function situacao(m)
  if m >= 7 then
    return "aprovado(a)"
  elseif m >= 5 then
    return "recuperação"
  else
    return "reprovado(a)"
  end
end

local alunos = {}
local cabecalho = true
for linha in io.lines("notas.csv") do
  if cabecalho then
    cabecalho = false
  else
    local campos = separar(linha)
    local aluno = { nome = campos[1], notas = {} }
    for i = 2, #campos do
      aluno.notas[#aluno.notas + 1] = tonumber(campos[i])
    end
    aluno.media = media(aluno.notas)
    alunos[#alunos + 1] = aluno
  end
end

for _, aluno in ipairs(alunos) do
  print(string.format("%s: média %.2f, %s", aluno.nome, aluno.media, situacao(aluno.media)))
end
local soma = 0 … soma = soma + nota
O acumulador clássico: começa em zero e cada nota é somada. No fim, soma / #notas é a média (a barra sempre dá float, veja Divisão).
if m >= 7 … elseif m >= 5 … else
A ordem importa: quem tem 8 também tem "5 ou mais", mas o elseif só é testado se o if de cima falhou (veja elseif).
aluno.media = media(aluno.notas)
Guarda a média dentro do aluno, num campo novo. Calcula uma vez e usa quantas vezes precisar (a versão 3 usa para ordenar).
string.format("%s: média %.2f, %s", …)
%.2f = um número com 2 casas decimais: 8.1666… vira 8.17 (arredondado).

Uma função, um nome: media e aluno.media

A função se chama media e o campo também. Não há confusão para o Lua: media sozinho é a variável local que guarda a função, e aluno.media é o campo "media" dentro da tabela aluno. São lugares diferentes. Só não crie uma variável local chamada media depois da função: ela esconderia a função (veja Escopo e Blocos).

Médias iguais: o table.sort não garante a ordem do empate

Se dois alunos tiverem exatamente a mesma média, o table.sort pode colocá-los em qualquer ordem entre si (ele não é "estável"). Para um relatório que precisa sair sempre igual, desempate na função: if a.media ~= b.media then return a.media > b.media end return a.nome < b.nome (empate: ordem alfabética). E a função de comparação precisa ser coerente: nunca use >=, que diz que a vem antes de b e b antes de a ao mesmo tempo, e pode até dar erro. Com 100 notas iguais:

$ lua -e 'local t = {} for i = 1, 100 do t[i] = 5 end table.sort(t, function (a, b) return a >= b end) print("ok")'
lua: (command line):1: invalid order function for sorting
stack traceback:
	[C]: in field 'sort'
	(command line):1: in main chunk
	[C]: in ?

"Função de ordem inválida para ordenar": o table.sort percebeu que as respostas da função se contradizem.

Quando dá errado

O notas.csv da página é perfeito. O de verdade, preenchido por gente, não é: uma nota que faltou, um "sete" por extenso, uma linha em branco no fim. Três problemas reais, testados com a versão 2 (que é mais curta).

Um campo vazio: a média errada, sem aviso

O Bruno faltou à prova 2, e a célula ficou vazia:

Média 4.50 é (5.0 + 4.0) / 2: o programa dividiu por 2, como se o Bruno tivesse feito só duas provas. O culpado é o padrão [^,]+, "um ou mais caracteres que não são vírgula": entre as duas vírgulas seguidas não há nenhum caractere, então ali não há pedaço nenhum. No modo interativo:

[Bruno] [5.0] [4.0]
> for campo in ("Bruno,5.0,,4.0" .. ","):gmatch("([^,]*),") do io.write("[", campo, "] ") end print()
[Bruno] [5.0] [] [4.0]
> os.exit()

O segundo padrão, ([^,]*),, quer dizer "zero ou mais caracteres que não são vírgula, seguidos de uma vírgula", e guarda (os parênteses) só a parte de antes da vírgula. Com o *, o campo vazio também conta: aparece como []. A vírgula acrescentada no fim da linha (linha .. ",") é para o último campo também terminar em vírgula. Formas diferentes de guardar cada aluno

Este projeto guardou cada aluno como { nome = "Bruno", notas = { 5.0, 6.5, 4.0 }, media = 5.17 }, numa lista. Outras escolhas possíveis:

FormaExemploQuando usar
Lista de tabelas com campos (este projeto)alunos[2].notas[1]Quando a ordem importa (ordenar, mostrar) e cada aluno tem várias informações.
Dicionário pelo nomealunos["Bruno"].mediaQuando o programa procura alunos pelo nome (como a Agenda). Para ordenar, é preciso copiar os nomes para uma lista.
Campos com o nome das colunas do cabeçalho{ nome = "Bruno", prova1 = 5.0, prova2 = 6.5 }Quando o CSV tem colunas de tipos diferentes: o programa lê o cabeçalho e usa cada nome de coluna como chave. Funciona para qualquer CSV, mas a conta da média fica menos direta.
Para separar a linhaCampo vazioQuando usar

(linha .. ","):gmatch("([^,]*),")Vira ""Com dados reais: mantém a posição de cada coluna.

  • Ler o nome do arquivo da linha de comando (lua notas.lua turma-b.csv), com arg[1].

Resumo

  • Um CSV é texto: uma linha por registro, vírgulas entre os campos, e a primeira linha com os nomes das colunas.
  • io.lines entrega as linhas; gmatch com um padrão separa os campos. [^,]+ perde os campos vazios; (linha .. ","):gmatch("([^,]*),") os mantém.
  • Cada aluno vira uma tabela com campos, numa lista; a média é calculada uma vez e guardada no próprio aluno.
  • table.sort com uma função de comparação ordena por qualquer campo; %-10s e %5.1f alinham as colunas.
  • Gravar um CSV é io.open(…, "w"), uma linha por registro com string.format, e close.
  • Arquivo feito por pessoas tem defeitos: confira cada linha, diga qual linha e por quê, e nunca deixe um nil virar uma média errada em silêncio.
