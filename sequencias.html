Lua Sequências e Buracos

Até aqui, toda lista que você fez estava "cheia": item 1, item 2, item 3, sem falhas. O Lua chama uma lista assim de sequência, e é com ela que o #, o ipairs, o table.insert e o table.concat funcionam direito. Esta aula mostra o que acontece quando aparece um nil no meio, um buraco: o # passa a poder responder números diferentes, o ipairs para antes da hora, e erros estranhos aparecem. E, claro, como evitar tudo isso.

Você vai aprender
  • O que é uma sequência e o que é um buraco.
  • O que é a borda de uma tabela, e por que o # de uma lista com buracos não tem resposta certa.
  • Que o ipairs para no primeiro buraco.
  • A remover um item sem furar a lista: table.remove.
  • A guardar "nada" numa lista: com false ou com um contador n (como o do table.pack).
  • Os erros reais que um buraco provoca.

A ideia: as cadeiras numeradas

Pense numa fileira de cadeiras numeradas no cinema: 1, 2, 3, 4. Se todas estão ocupadas, contar quantas pessoas há na fileira é fácil: vá até a primeira cadeira vazia e pare. Agora imagine que a pessoa da cadeira 2 saiu, e as outras ficaram no lugar. Quantas pessoas há "na fileira"? Se você para na primeira cadeira vazia, conta 1. Se olha até a última ocupada, conta até 4. As duas respostas fazem algum sentido, e nenhuma é a "certa".

No Lua, a lista é a fileira, e nil é a cadeira vazia. Guardar nil numa posição é o mesmo que não guardar nada lá: a cadeira fica vazia.

1. A sequência: a lista sem buracos

Uma sequência é uma tabela em que as posições 1, 2, 3… até um número n têm valor, e daí em diante não há mais nada. Nela o # responde n, sem dúvida nenhuma:

local fila = {"Ana", "Bia", "Caio", "Davi"}
print(#fila)
for i = 1, #fila do
  print(i, fila[i])
end
print(fila[5])

$ lua sequencia.lua
4
1	Ana
2	Bia
3	Caio
4	Davi
nil

As posições 1 a 4 estão ocupadas, a 5 não (fila[5] é nil). É uma sequência: #fila é 4. Todas as listas das aulas anteriores eram sequências.

2. O buraco e a borda

Agora uma lista com um nil no meio:

local t = {10, 20, 30, nil, 50}
print(t[1], t[2], t[3], t[4], t[5], t[6])
print(#t)

A posição 4 é um buraco. Para entender o que o # faz aqui, o manual do Lua usa a palavra borda (border):

Borda

Uma borda é uma posição com valor que é seguida de uma posição sem valor (ou o 0, se a posição 1 estiver vazia). Na tabela acima, a posição 3 tem valor e a 4 não: 3 é uma borda. A 5 tem valor e a 6 não: 5 também é uma borda. Uma sequência é uma tabela com uma borda só. E a regra do manual é esta: quando a tabela não é uma sequência, #t pode devolver qualquer uma das bordas.

Posição123456
Valor102030nil50nil
É borda?sim (3 tem, 4 não)sim (5 tem, 6 não)

Então o #t pode dar 3 ou 5. Qual dos dois sai depende de como o Lua guardou a tabela por dentro, e isso muda de uma versão para outra. No laboratório, o mesmo arquivo rodado no Lua 5.5 e no 5.4:

$ lua borda.lua
10	20	30	nil	50	nil
3
$ lua5.4 borda.lua
10	20	30	nil	50	nil
5

Os valores guardados são os mesmos (primeira linha), mas o 5.5 respondeu 3 e o 5.4 respondeu 5. Os dois estão certos: os dois devolveram uma borda. Mais alguns casos, cada um criado de um jeito:

local a = {10, 20, nil, 40}
print("a:", #a)
local c = {10, 20, 30, 40, 50}
c[3] = nil
print("c:", #c)
local d = {}
d[1] = 10
d[2] = 20
d[4] = 40
print("d:", #d)

$ lua buracos.lua
a:	2
c:	2
d:	2
$ lua5.4 buracos.lua
a:	4
c:	5
d:	4

De novo, respostas diferentes, e todas são bordas. Por isso esta aula não vai dizer "o # de uma lista com buraco dá tal número". No seu computador, com outra versão ou com a tabela montada de outro jeito, pode sair outra borda. A única coisa garantida é esta:

Lista com buraco: não confie no #

Com um nil no meio, o # devolve uma borda qualquer. Um programa que depende do # numa lista com buracos pode funcionar hoje e falhar amanhã, numa versão nova do Lua ou depois de uma mudança pequena no código. A solução não é adivinhar a borda: é não fazer buracos (seção 4) ou guardar o tamanho você mesmo (seção 5).

nil no fim não é buraco

Na tabela {1, 2, 3, nil}, o nil está no fim: depois do 3 não há mais nada, só uma borda (3). É uma sequência de 3 itens, e o # dá 3 em qualquer versão. Buraco é só o nil que tem algum valor depois dele.

3. O ipairs para no buraco

O ipairs percorre a lista a partir da posição 1 e para na primeira posição vazia. Ele não usa o #, então o resultado dele é sempre o mesmo, mas talvez não seja o que você queria:

local compras = {"arroz", "feijão", "café", "leite"}
compras[2] = nil
for i, item in ipairs(compras) do
  print("ipairs:", i, item)
end
for i = 1, 4 do
  print("1 a 4:", i, compras[i])
end

$ lua ipairs_buraco.lua
ipairs:	1	arroz
1 a 4:	1	arroz
1 a 4:	2	nil
1 a 4:	3	café
1 a 4:	4	leite
compras[2] = nil
A Ana apagou o feijão guardando nil no lugar dele: fez um buraco na posição 2.
ipairs(compras)
Mostrou o arroz e parou: a posição 2 está vazia. O café e o leite continuam na tabela, mas o ipairs nunca chega neles.
for i = 1, 4
Com o fim escrito à mão, o laço passa por todas as posições, e a 2 aparece como nil.

O mesmo vale ao contrário: um item guardado "longe", depois de um buraco, fica invisível para o ipairs (e, aqui, também para o #):

local fila = {"Ana", "Bia"}
fila[5] = "Caio"
print(#fila)
for i, nome in ipairs(fila) do print(i, nome) end
print(fila[5])

$ lua pular.lua
2
1	Ana
2	Bia
Caio

O Caio está lá (fila[5]), mas as posições 3 e 4 estão vazias: para o ipairs, a lista acaba na Bia. O pairs passaria por todos, mas sem ordem garantida.

4. Removendo sem furar: table.remove

Guardar nil no meio é o jeito mais comum de criar um buraco sem querer. Para tirar um item do meio de uma lista, use table.remove (aula table.insert e table.remove): ele tira o item e puxa os de trás uma posição para a frente, como as pessoas que andam uma cadeira para ocupar a vaga.

local compras = {"arroz", "feijão", "café", "leite"}
table.remove(compras, 2)
print(#compras, table.concat(compras, ", "))
compras[#compras] = nil
print(#compras, table.concat(compras, ", "))

$ lua remover.lua
3	arroz, café, leite
2	arroz, café
table.remove(compras, 2)
Tirou o feijão; o café foi para a posição 2 e o leite para a 3. A lista continua uma sequência, de 3 itens.
compras[#compras] = nil
Apagar o último com nil não faz buraco: não há nada depois dele. A lista encolhe para 2. (É o que table.remove(compras), sem posição, também faz.)

Missão: a Bia saiu da fila, e o programa apagou ela com fila[2] = nil, que faz um buraco. Rode e veja o que sai. Depois troque essa linha por table.remove(fila, 2) para o programa mostrar 3 na fila: Ana, Caio, Davi.

local fila = {"Ana", "Bia", "Caio", "Davi"}
fila[2] = nil
print(#fila .. " na fila: " .. table.concat(fila, ", "))

local fila = {"Ana", "Bia", "Caio", "Davi"}
table.remove(fila, 2)
print(#fila .. " na fila: " .. table.concat(fila, ", "))

5. E quando eu preciso guardar "nada"?

Às vezes o "nada" faz parte dos dados: o aluno que faltou, a pergunta sem resposta. Há três jeitos de guardar isso sem estragar a lista.

Jeito 1: false no lugar de nil

false é um valor de verdade (aula Booleanos): a posição fica ocupada, e a lista continua uma sequência. E no if, o false se comporta como o nil: conta como "não".

local presenca = {true, false, true, false, true}
print(#presenca)
local presentes = 0
for i = 1, #presenca do
  if presenca[i] then
    presentes = presentes + 1
  end
end
print(presentes .. " de " .. #presenca)

$ lua presenca.lua
5
3 de 5

Jeito 2: guardar o tamanho num campo n

Se o valor que falta tem de ser nil mesmo, deixe de perguntar o tamanho para o #: anote você mesmo, num campo n, a cada item que entra. O laço vai até n, e o buraco não atrapalha:

local respostas = {n = 0}
local function anotar(valor)
  respostas.n = respostas.n + 1
  respostas[respostas.n] = valor
end
anotar("sim")
anotar(nil)
anotar("não")
print(respostas.n)
for i = 1, respostas.n do
  print(i, respostas[i])
end
local p = table.pack("sim", nil, "não")
print(p.n)

$ lua contador.lua
3
1	sim
2	nil
3	não
3
{n = 0}
Uma tabela que já nasce com um campo n valendo 0 (campos com nome são a aula Tabelas como Dicionários).
respostas.n = respostas.n + 1
Cada item novo aumenta o contador, mesmo que o item seja nil.
for i = 1, respostas.n do
O fim do laço é o contador, nunca o #.

Jeito 3: table.pack, que já vem com o n

É exatamente a ideia do table.pack: a última linha do programa acima mostra que table.pack("sim", nil, "não").n é 3. O manual avisa que a tabela do table.pack pode não ser uma sequência, quando algum valor é nil; por isso ela traz o n.

Missão: o ipairs para no buraco e só mostra o leite. Troque o laço por for i = 1, t.n do (e escreva t[i] no lugar de item) para aparecerem as três posições, até 3: pão.

local t = table.pack("leite", nil, "pão")
for i, item in ipairs(t) do
  print(i .. ": " .. tostring(item))
end

local t = table.pack("leite", nil, "pão")
for i = 1, t.n do
  print(i .. ": " .. tostring(t[i]))
end

Quando dá errado

Somar uma lista que tem buraco 
local notas = {8, 7, 9, 10}
notas[3] = nil
local soma = 0
for i = 1, 4 do
  soma = soma + notas[i]
end
print(soma)

$ lua erro_soma.lua
lua: erro_soma.lua:5: attempt to perform arithmetic on a nil value (field '?')
stack traceback:
	erro_soma.lua:5: in main chunk
	[C]: in ?
lua: erro_soma.lua:5:
O erro foi na linha 5, a da soma.
attempt to perform arithmetic on a nil value
"Tentativa de fazer conta com um valor nil": na volta i = 3, notas[3] é nil, e soma + nil não existe.
(field '?')
O nil veio de um campo de tabela (notas[i]). O '?' quer dizer que a posição era uma variável (i), e o Lua não sabe dizer o nome; se fosse notas.media, ele diria (field 'media').
stack traceback:
O caminho até o erro: a linha 5 do corpo do arquivo (main chunk), chamado pelo programa lua ([C]: in ?).

Como consertar: não faça o buraco (table.remove). Se o buraco é de propósito, pule as posições vazias: if notas[i] then soma = soma + notas[i] end.

table.concat encontrou o buraco 
local compras = {"arroz", "feijão", "café"}
compras[2] = nil
print(table.concat(compras, ", ", 1, 3))

$ lua erro_concat.lua
lua: erro_concat.lua:3: invalid value (nil) at index 2 in table for 'concat'
stack traceback:
	[C]: in field 'concat'
	erro_concat.lua:3: in main chunk
	[C]: in ?

"Valor inválido (nil) na posição 2 da tabela, para o concat": o table.concat só junta textos e números, e a posição 2 está vazia. Aqui o fim (3) foi dado à mão; sem ele, o concat usaria o #, e aí o resultado dependeria de qual borda saísse: um texto mais curto, sem aviso, ou este mesmo erro. Como consertar: remova com table.remove.

Inserir longe demais 
local fila = {"Ana", "Bia"}
table.insert(fila, 5, "Caio")

$ lua erro_insert.lua
lua: erro_insert.lua:2: bad argument #2 to 'insert' (position out of bounds)
stack traceback:
	[C]: in field 'insert'
	erro_insert.lua:2: in main chunk
	[C]: in ?

"Argumento ruim nº 2 para insert (posição fora dos limites)". O table.insert protege a sequência: ele só aceita posições de 1 até #fila + 1 (aqui, até 3), porque inserir na 5 deixaria as posições 3 e 4 vazias. Como consertar: para pôr no fim, table.insert(fila, "Caio"). (Já fila[5] = "Caio" não dá erro nenhum, e cria os buracos: seção 3.)

O laço parou no meio, sem erro 
local compras = {"arroz", "feijão", "café", "leite"}
compras[2] = nil
for i, item in ipairs(compras) do
  print("ipairs:", i, item)
end

$ lua ipairs_buraco.lua
ipairs:	1	arroz

Nenhuma mensagem: o ipairs chegou à posição 2, achou nil e entendeu que a lista tinha acabado. É o erro mais difícil de achar, porque o programa termina "normalmente". Como consertar: sem buracos, ou um laço até o n que você guardou.

Missão final: a chamada da turma

Missão: a professora marcou com nil quem faltou, e a lista ficou com buracos: o # não é confiável. Troque os nil por false, para a lista virar uma sequência e o programa mostrar 5 alunos, 3 presentes.

local presenca = {true, nil, true, nil, true}
local presentes = 0
for i = 1, #presenca do
  if presenca[i] then
    presentes = presentes + 1
  end
end
print(#presenca .. " alunos, " .. presentes .. " presentes")

local presenca = {true, false, true, false, true}
local presentes = 0
for i = 1, #presenca do
  if presenca[i] then
    presentes = presentes + 1
  end
end
print(#presenca .. " alunos, " .. presentes .. " presentes")

Resumo

  • Uma sequência tem as posições 1 a n ocupadas e nada depois; nela o #, o ipairs, o insert e o concat funcionam direito.
  • Um nil no meio é um buraco. Com buracos, a tabela tem várias bordas, e o # devolve qualquer uma delas: o mesmo código deu 3 no Lua 5.5 e 5 no 5.4.
  • O ipairs para no primeiro buraco, sem erro.
  • Para tirar do meio, table.remove; nunca t[i] = nil. Apagar o último com nil não faz buraco.
  • Para guardar "nada": false, ou um campo n com o tamanho (o table.pack já traz o seu).
