Lua <const>

Alguns valores de um programa não deveriam mudar nunca depois de definidos: a taxa de entrega da padaria, o número de dias da semana, o limite de itens do carrinho. Se alguma linha, lá no meio do programa, trocar esse valor sem querer, o resultado sai errado e ninguém percebe. O Lua tem uma proteção para isso: escrever <const> (de constant, "constante") depois do nome da variável. A partir daí, qualquer tentativa de trocar o valor é erro, e o Lua avisa antes mesmo de o programa começar.

Você vai aprender
  • O que é uma constante e como se escreve: local TAXA <const> = 7.50.
  • A mensagem real attempt to assign to const variable e por que ela aparece antes de o programa rodar.
  • Por que uma tabela <const> ainda pode ganhar e perder itens.
  • A forma nova do Lua 5.5 (local <const> A, B = 1, 2) e o que acontece nas versões mais antigas.
  • Os erros mais comuns: o atributo com nome errado, o parâmetro de função e o += que não existe.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com lua arquivo.lua. Você precisa já conhecer as variáveis local (aula local).

A ideia: o preço pintado na parede

Na padaria do bairro, os preços do dia ficam num quadro de giz: o padeiro apaga e escreve de novo quando quiser. Isso é uma variável comum. Mas o horário de funcionamento está pintado na parede da entrada: para mudar, só repintando a parede inteira. Ninguém troca por engano, passando o dedo.

Uma variável com <const> é a parede pintada: você escolhe o valor uma vez, quando cria a variável, e depois o Lua não deixa nenhuma linha trocar. Se alguém tentar, o programa nem começa.

1. A primeira constante

local TAXA_ENTREGA <const> = 7.50
local pedido = 32.40
print("Pedido:", pedido)
print("Total:", pedido + TAXA_ENTREGA)
local
Uma constante é sempre uma variável local (o caso das globais fica para a aula A Declaração global).
TAXA_ENTREGA
O nome. É costume escrever constantes em MAIÚSCULAS_COM_SUBLINHADO, para quem lê saber de longe que aquele valor não muda. O Lua não exige isso; é só um combinado entre programadores.
<const>
O atributo (uma "etiqueta" entre os sinais < e >), logo depois do nome. Ele diz: esta variável é só para leitura.
= 7.50
O valor, que é dado uma vez só, aqui na criação.
$ lua taxa.lua
Pedido:	32.4
Total:	39.9

Para ler a constante, nada muda: pedido + TAXA_ENTREGA funciona como com qualquer variável. A diferença só aparece quando alguém tenta escrever nela.

2. Tentando mudar uma constante

print("começou")
local TAXA_ENTREGA <const> = 7.50
TAXA_ENTREGA = 10
print(TAXA_ENTREGA)

$ lua muda.lua
lua: muda.lua:3: attempt to assign to const variable 'TAXA_ENTREGA'
$ echo $?
1
lua: muda.lua:3:
O problema está no arquivo muda.lua, linha 3: a linha TAXA_ENTREGA = 10.
attempt to assign to const variable 'TAXA_ENTREGA'
"Tentativa de atribuir a uma variável constante 'TAXA_ENTREGA'". Atribuir é dar um valor com o =.
echo $? → 1
O programa terminou com o código de erro 1.

Repare em duas coisas:

  • O começou da linha 1 não apareceu. O Lua lê o arquivo inteiro e o traduz antes de rodar a primeira linha (essa etapa se chama compilação). A constante foi pega nessa etapa, e o programa nem começou.
  • Não há stack traceback:. Um erro de compilação não tem "rastro de chamadas", porque nenhuma função chegou a ser chamada. É o mesmo jeito dos erros de sintaxe (veja Lendo uma Mensagem de Erro).

Por isso dá até para conferir sem rodar, com o luac -p (o "verificador" que vem junto com o Lua: o -p quer dizer "só analise"):

$ luac -p muda.lua
luac: muda.lua:3: attempt to assign to const variable 'TAXA_ENTREGA'
Por que isso é bom

Um erro que aparece antes de rodar é o melhor tipo de erro: você não precisa testar todos os caminhos do programa para achá-lo. Sem o <const>, a linha TAXA_ENTREGA = 10 rodaria quietinha, e todas as entregas depois dela sairiam com a taxa errada.

E se eu precisar de um valor novo?

Então você não quer mudar a constante: você quer outra variável, calculada a partir dela. A padaria vai reajustar o pão em 10%. O preço antigo continua sendo o preço antigo; o novo ganha um nome próprio:

local PRECO_PAO <const> = 0.75
local REAJUSTE <const> = 1.10
local novo_preco = PRECO_PAO * REAJUSTE
print(string.format("Pão: R$ %.2f", PRECO_PAO))
print(string.format("Pão com reajuste: R$ %.2f", novo_preco))

$ lua reajuste.lua
Pão: R$ 0.75
Pão com reajuste: R$ 0.83

(O %.2f do string.format mostra 2 casas decimais.)

Missão: este programa tenta mudar uma constante e para com attempt to assign to const variable 'PRECO_PAO'. Rode para ver o erro. Depois conserte sem tirar o <const>: crie uma variável nova, local novo_preco = …, e mostre ela no print.

local PRECO_PAO <const> = 0.75
local REAJUSTE <const> = 1.10
PRECO_PAO = PRECO_PAO * REAJUSTE
print(string.format("Pão com reajuste: R$ %.2f", PRECO_PAO))

local PRECO_PAO <const> = 0.75
local REAJUSTE <const> = 1.10
local novo_preco = PRECO_PAO * REAJUSTE
print(string.format("Pão com reajuste: R$ %.2f", novo_preco))

3. Constante não é "congelada": o caso das tabelas

O <const> protege a variável, e não o que está dentro dela. Com números e textos, dá na mesma. Com tabelas, não: lembre que a variável guarda só uma referência para a tabela (aula Tabelas São Referências).

local CORES <const> = { "vermelho", "verde" }
CORES[3] = "azul"
print(#CORES, CORES[3])

$ lua tabela.lua
3	azul

Funcionou! CORES[3] = "azul" não muda a variável CORES: ela continua apontando para a mesma tabela. O que mudou foi o conteúdo da tabela. Agora tente trocar a tabela inteira:

local CORES <const> = { "vermelho", "verde" }
CORES = { "azul" }

$ lua tabela2.lua
lua: tabela2.lua:2: attempt to assign to const variable 'CORES'

Esse sim é proibido: seria fazer a variável apontar para outra tabela. Voltando à padaria: a parede pintada diz "Cardápio: veja o quadro ao lado". Ninguém pode repintar a parede para apontar para outro quadro, mas o que está escrito no quadro continua mudando. Para impedir que alguém mexa dentro de uma tabela, é preciso outra técnica, com metatabelas (o __newindex da aula __index e __newindex).

4. O valor pode vir de qualquer lugar

A constante não precisa ser um número escrito no código. Pode ser o resultado de uma conta, de uma função, até do que a pessoa digitou. O que não pode é mudar depois:

local INICIO <const> = os.time()
local NOME <const> = io.read()
print("Olá, " .. NOME)
print(type(INICIO))

$ echo Ana | lua hora.lua
Olá, Ana
number

E uma constante criada sem valor fica nil para sempre (o que quase nunca é útil):

local X <const>
print(X)

$ lua semvalor.lua
nil

5. Constantes dentro de funções

Uma função criada depois da constante pode usá-la (é uma closure: veja Closures):

local LIMITE <const> = 3
local function pode(n)
  return n <= LIMITE
end
print(pode(2), pode(5))

$ lua closure2.lua
true	false

Mas a função também não pode mudá-la. Este arquivo nem chama a função, e mesmo assim não roda:

local LIMITE <const> = 3
local function pode(n)
  LIMITE = n
  return n <= LIMITE
end

$ lua closure.lua
lua: closure.lua:3: attempt to assign to const variable 'LIMITE'

De novo: o erro é de compilação. O Lua olha o texto inteiro, achou a linha 3, e recusou o arquivo, sem precisar chamar pode.

Um nome igual, mais para dentro

Num bloco mais interno, você pode criar uma outra variável com o mesmo nome (veja Escopo e Blocos). Ela é uma variável nova, comum, que esconde a constante só dentro do bloco:

local PRECO <const> = 10
do
  local PRECO = 20
  PRECO = 25
  print(PRECO)
end
print(PRECO)

$ lua sombra.lua
25
10

Dentro do do … end, PRECO é a variável nova (sem <const>), e pode mudar. Fora dele, a constante continua 10. Funciona, mas confunde quem lê: evite repetir o nome de uma constante.

5.5 A variável do for também é constante

No Lua 5.5, a variável de controle do for é só para leitura, como se tivesse um <const> invisível. Tentar mudá-la dá a mesma mensagem desta aula: lua -e 'for i = 1, 3 do i = i * 2 print(i) end' → lua: (command line):1: attempt to assign to const variable 'i'. No Lua 5.4, o mesmo código roda e mostra 2, 4, 6. Detalhes na aula for Numérico.

Formas diferentes de fazer a mesma coisa

Para criar várias constantes de uma vez, você pode pôr o <const> depois de cada nome:

local LARGURA <const>, ALTURA <const> = 80, 24
local nome <const>, idade = "Ana", 30
idade = idade + 1
print(LARGURA * ALTURA, nome, idade)

$ lua posfixo.lua
1920	Ana	31

Na segunda linha, só nome é constante; idade é uma variável comum, e pôde mudar.

5.5 No Lua 5.5 há uma forma nova: o atributo antes da lista vale para todos os nomes dela:

local <const> LARGURA, ALTURA = 80, 24
print(LARGURA * ALTURA)

$ lua prefixo.lua
1920

O espaço em volta do atributo não importa: local a<const> = 1 e local b < const > = 2 também funcionaram no lab. Mas a forma mais comum (e mais fácil de ler) é a desta aula: NOME <const>, com um espaço antes.

SituaçãoQual usar
Um valor que nunca muda (taxa, limite, nome de arquivo de configuração)local NOME <const> = valor
Vários valores fixos de uma vez, só no 5.5local <const> A, B = 1, 2
Vários de uma vez, funcionando também no 5.4local A <const>, B <const> = 1, 2
Um valor que muda durante o programa (contador, total)uma variável local comum
Uma tabela cujo conteúdo não pode mudar<const> não basta: use uma metatabela com __newindex
E nas outras versões?

O <const> surgiu no Lua 5.4. No lab, o posfixo.lua rodou igual no lua5.4. Mas a forma com o atributo na frente é só do 5.5: lua5.4 prefixo.lua → lua5.4: prefixo.lua:1: <name> expected near '<' ("era esperado um nome perto de '<'"). No Lua 5.1 e no LuaJIT (o do Neovim e do LÖVE) não existe <const> nenhum: luajit posfixo.lua → luajit: posfixo.lua:1: unexpected symbol near '<'. Lá, a constante é só um combinado: o nome em MAIÚSCULAS. Veja as diferenças entre as versões.

Quando dá errado

Escreveu o nome do atributo errado 
local PI <constante> = 3.14

$ lua desconhecido.lua
lua: desconhecido.lua:1: unknown attribute 'constante'

"Atributo desconhecido 'constante'". O Lua só conhece dois atributos: const e close (este é da próxima aula, <close>). Tem de ser em inglês e em minúsculas. Como consertar: local PI <const> = 3.14.

Tentou pôr <const> num parâmetro de função 
local function f(x <const>)
  return x
end

$ lua param.lua
lua: param.lua:1: ')' expected near '<'

"Era esperado ')' perto de '<'". Os parâmetros de uma função não aceitam atributos. Como consertar: se quiser garantir que a função não mude o valor, copie para uma constante logo na primeira linha: local X <const> = x.

Usou +=, que não existe no Lua 
local ITENS <const> = 3
ITENS += 1

$ lua comp.lua
lua: comp.lua:2: syntax error near '+'

Aqui a mensagem não fala de constante: o Lua nem chegou a esse ponto. É que o Lua não tem += (quem vem de outras linguagens estranha). O jeito do Lua é ITENS = ITENS + 1, e aí sim, como ITENS é constante, apareceria o attempt to assign to const variable 'ITENS'.

Rodou num Lua antigo 
$ lua5.1 posfixo.lua
lua5.1: posfixo.lua:1: unexpected symbol near '<'

"Símbolo inesperado perto de '<'". O Lua 5.1 e o LuaJIT não conhecem atributos. Se o seu programa precisa rodar neles (um plugin do Neovim, um jogo no LÖVE), não use <const>: use o nome em MAIÚSCULAS e cuidado.

Missão final: o limite que mudou sozinho

Este programa deveria parar no 3º item do carrinho, mas no lab ele mostrou os 4 itens: uma linha lá embaixo troca o LIMITE para 10 quando passa pelo café. Num programa grande, achar uma linha dessas dá trabalho.

$ lua limite.lua
Item 1: pão
Item 2: leite
Item 3: café
Item 4: açúcar

Missão: faça o Lua achar a linha culpada para você: transforme o LIMITE numa constante e rode. A mensagem de erro vai dizer o número da linha que tenta mudá-lo. (Depois, por conta própria, apague essa linha e veja o programa parar no café.)

local LIMITE = 3
local carrinho = { "pão", "leite", "café", "açúcar" }
for i = 1, #carrinho do
  if i > LIMITE then
    print("Limite de " .. LIMITE .. " itens atingido!")
    break
  end
  print("Item " .. i .. ": " .. carrinho[i])
  if carrinho[i] == "café" then LIMITE = 10 end
end

local LIMITE <const> = 3
local carrinho = { "pão", "leite", "café", "açúcar" }

end

Resumo

  • local NOME <const> = valor cria uma variável que só pode ser lida. O valor é dado uma vez, na criação, e pode vir de qualquer expressão.
  • Qualquer NOME = … depois disso dá attempt to assign to const variable 'NOME', na compilação: o programa nem começa, e não há stack traceback.
  • O <const> protege a variável, não o conteúdo: uma tabela constante ainda pode ganhar e perder itens.
  • Costume: constantes em MAIÚSCULAS_COM_SUBLINHADO.
  • O <const> existe desde o Lua 5.4; a forma local <const> A, B é nova do 5.5; o 5.1 e o LuaJIT não têm atributos.
