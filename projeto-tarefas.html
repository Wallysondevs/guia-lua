Projeto Lista de Tarefas

A Ana vive esquecendo o que tem para fazer. Neste projeto ela ganha uma lista de tarefas no terminal: um menu para ver, adicionar, concluir e remover tarefas, que no fim guarda tudo num arquivo, para a lista continuar lá no dia seguinte. É o primeiro projeto do guia que guarda dados entre uma execução e outra.

Você vai praticar
  • Montar um menu com while e if/elseif.
  • Guardar a lista numa tabela, com table.insert e table.remove, e percorrê-la com ipairs.
  • Representar cada tarefa como uma tabela com campos ({ texto = …, feita = false }): tabelas dentro de tabelas.
  • Separar o programa em funções e validar o número digitado.
  • Gravar e ler um arquivo de texto com io.open, write e lines, separando os campos com um padrão.

O que vamos construir

A lista pronta, em duas execuções no terminal da Ana. O que vem depois de "Escolha:", "Nova tarefa:" e "Número…:" foi digitado por ela. Na segunda vez, a lista continua lá:

Quatro versões, uma novidade em cada:

  1. O menu e a lista (while, table.insert, ipairs).
  2. Concluir e remover (cada tarefa vira uma tabela; table.remove).
  3. Funções e número validado.
  4. Guardar num arquivo (io.open, write, lines, match).

Antes de começar

Este projeto usa o que você viu na Calculadora (io.read, while true, funções) e na Forca (listas e #). Crie a pasta; o arquivo vai se chamar tarefas.lua:

$ mkdir -p projetos/tarefas
$ cd projetos/tarefas

Versão 1 · O menu e a lista

A primeira versão mostra um menu, lê a opção e faz o que foi pedido, até a Ana escolher 0. As tarefas ficam numa lista de textos: tarefas[1] é a primeira, tarefas[2] a segunda, e #tarefas diz quantas são.

local tarefas = {}

print("=== Lista de Tarefas da Ana ===")

while true do
  print()
  print("1) Ver tarefas")
  print("2) Adicionar tarefa")
  print("0) Sair")
  io.write("Escolha: ")
  local opcao = io.read()

  if opcao == "1" then
    if #tarefas == 0 then
      print("Nenhuma tarefa. Que tranquilidade!")
    else
      for i, tarefa in ipairs(tarefas) do
        print(i .. ". " .. tarefa)
      end
    end
  elseif opcao == "2" then
    io.write("Nova tarefa: ")
    local texto = io.read()
    table.insert(tarefas, texto)
    print("Anotado: " .. texto)
  elseif opcao == "0" or opcao == nil then
    print("Até logo!")
    break
  else
    print("Opção inválida: " .. opcao)
  end
end

Versão 2 · Concluir e remover

Uma tarefa agora tem duas informações: o texto e se já foi feita. Um texto sozinho não guarda isso, então cada tarefa vira uma tabela com campos: { texto = "Comprar pão", feita = false }. A lista tarefas passa a ser uma lista de tabelas (veja Tabelas Aninhadas). E o menu ganha as opções 3 e 4.

local tarefas = {}

print("=== Lista de Tarefas da Ana ===")

while true do
  print()
  print("1) Ver tarefas")
  print("2) Adicionar tarefa")
  print("3) Concluir tarefa")
  print("4) Remover tarefa")
  print("0) Sair")
  io.write("Escolha: ")
  local opcao = io.read()

  if opcao == "1" then
    if #tarefas == 0 then
      print("Nenhuma tarefa. Que tranquilidade!")
    else
      for i, tarefa in ipairs(tarefas) do
        local marca = tarefa.feita and "[x]" or "[ ]"
        print(string.format("%d. %s %s", i, marca, tarefa.texto))
      end
    end
  elseif opcao == "2" then
    io.write("Nova tarefa: ")
    local texto = io.read()
    table.insert(tarefas, { texto = texto, feita = false })
    print("Anotado: " .. texto)
  elseif opcao == "3" then
    io.write("Número da tarefa concluída: ")
    local n = tonumber(io.read())
    tarefas[n].feita = true
    print("Feito: " .. tarefas[n].texto)
  elseif opcao == "4" then
    io.write("Número da tarefa a remover: ")
    local n = tonumber(io.read())
    local removida = table.remove(tarefas, n)
    print("Removida: " .. removida.texto)
  elseif opcao == "0" or opcao == nil then
    print("Até logo!")
    break
  else
    print("Opção inválida: " .. opcao)
  end
end
{ texto = texto, feita = false }
Uma tabela nova com dois campos. Do lado esquerdo do =, o nome do campo; do lado direito, o valor. texto = texto parece estranho, mas quer dizer "o campo texto recebe o valor da variável texto".
tarefa.feita and "[x]" or "[ ]"
O truque do and/or: [x] se feita, [ ] se não.
tarefas[n].feita = true
Duas etapas: tarefas[n] pega a tarefa número n (uma tabela) e .feita = true muda o campo dela. A tarefa continua no mesmo lugar da lista.
table.remove(tarefas, n)
Tira o item da posição n, puxa os de baixo para cima (a 3 vira 2…) e devolve o item tirado, que o programa usa para dizer qual foi.

Versão 3 · Funções e número validado

A versão 3 conserta os três defeitos de uma vez, com uma função ler_numero que só devolve um número se ele for um inteiro de 1 até #tarefas. E aproveita para separar cada opção do menu numa função; o laço principal fica curto. O menu também fica numa linha só, para a tela não encher.

-- Lista de Tarefas da Ana, versão 3: funções e número validado

-- Pergunta e devolve a resposta sem espaços nas pontas (ou nil no fim da entrada).
local function perguntar(texto)
  io.write(texto)
  local resposta = io.read()
  if resposta == nil then
    return nil
  end
  return resposta:match("^%s*(.-)%s*$")
end

local function mostrar(tarefas)
  if #tarefas == 0 then
    print("Nenhuma tarefa. Que tranquilidade!")
    return
  end
  for i, tarefa in ipairs(tarefas) do
    local marca = tarefa.feita and "[x]" or "[ ]"
    print(string.format("%d. %s %s", i, marca, tarefa.texto))
  end
end

-- Pede o número de uma tarefa. Devolve o número, ou nil (com aviso) se não servir.
local function ler_numero(tarefas, pergunta)
  if #tarefas == 0 then
    print("Ainda não há tarefas.")
    return nil
  end
  local n = tonumber(perguntar(pergunta) or "")
  if n == nil or math.type(n) ~= "integer" or n < 1 or n > #tarefas then
    print(string.format("Digite um número de 1 a %d.", #tarefas))
    return nil
  end
  return n
end

local function adicionar(tarefas)
  local texto = perguntar("Nova tarefa: ")
  if texto == nil or texto == "" then
    print("Tarefa vazia: nada foi anotado.")
    return
  end
  table.insert(tarefas, { texto = texto, feita = false })
  print("Anotado: " .. texto)
end

local function concluir(tarefas)
  local n = ler_numero(tarefas, "Número da tarefa concluída: ")
  if n then
    tarefas[n].feita = true
    print("Feito: " .. tarefas[n].texto)
  end
end

local function remover(tarefas)
  local n = ler_numero(tarefas, "Número da tarefa a remover: ")
  if n then
    local removida = table.remove(tarefas, n)
    print("Removida: " .. removida.texto)
  end
end

local tarefas = {}
print("=== Lista de Tarefas da Ana ===")

while true do
  print()
  print("1) Ver  2) Adicionar  3) Concluir  4) Remover  0) Sair")
  local opcao = perguntar("Escolha: ")

  if opcao == "1" then
    mostrar(tarefas)
  elseif opcao == "2" then
    adicionar(tarefas)
  elseif opcao == "3" then
    concluir(tarefas)
  elseif opcao == "4" then
    remover(tarefas)
  elseif opcao == "0" or opcao == nil then
    print("Até logo!")
    break
  else
    print("Opção inválida: " .. opcao)
  end
end
PeçaO que faz
perguntar(texto)Mostra a pergunta, lê a resposta e tira os espaços das pontas. Devolve nil se a entrada acabou. Todas as perguntas passam por ela.
mostrar(tarefas)A listagem. O return sozinho, na lista vazia, sai da função sem devolver nada: o for nem chega a rodar.
tonumber(perguntar(pergunta) or "")Se perguntar der nil (fim da entrada), o or "" troca por um texto vazio, e o tonumber("") dá nil sem erro.
n == nil or math.type(n) ~= "integer" or n < 1 or n > #tarefasRecusa, nesta ordem: o que não é número, o que não é inteiro (1.5), e o que está fora da lista. Por causa do or, o Lua para no primeiro true: se n for nil, as comparações com < nem rodam (e não dão erro).
return nil + avisoQuem chama (concluir, remover) só faz alguma coisa if n then. Assim o table.remove nunca recebe nil.
texto == nil or texto == ""Em adicionar: não anota tarefa vazia (só Enter).
adicionar(tarefas), concluir(tarefas)…A lista é passada para as funções. Como tabelas são referências, a função mexe na mesma lista do programa principal, e não numa cópia.

Versão 4 · Guardar num arquivo

Agora a lista sobrevive ao fim do programa. A ideia: no começo, carregar as tarefas de um arquivo de texto; depois de cada mudança, salvar a lista inteira de novo. O formato do arquivo é simples, uma tarefa por linha, com a marca na frente:

1;Comprar pão
0;Pagar a conta de luz; vence dia 20

1 quer dizer "feita", 0 "por fazer", e o ; separa a marca do texto. Um arquivo assim dá para ler e até consertar à mão, com qualquer editor. O programa completo (as funções novas são carregar e salvar; o resto é a versão 3):

io.open(ARQUIVO, "r")
Tenta abrir para leitura. Na primeira vez o arquivo ainda não existe: o io.open devolve nil e o carregar devolve a lista vazia, sem erro. É o comportamento certo, não um problema.
linha:match("^([01]);(.*)$")
O padrão que separa a linha: ^ começo; ([01]) um 0 ou um 1, guardado (é a primeira captura); ; o separador; (.*) todo o resto até o fim, guardado (a segunda). O match devolve as duas capturas, que vão para marca e texto. Se a linha não tiver esse formato, devolve nil.
feita = (marca == "1")
A comparação já dá true ou false: é exatamente o valor do campo.
numero_linha
Conta as linhas, só para o aviso dizer qual linha estava estragada.
assert(io.open(ARQUIVO, "w"))
Abre para escrita ("w", de write): cria o arquivo, ou apaga o que havia nele. Como o salvar grava a lista inteira toda vez, é isso mesmo que se quer. O assert para o programa com a mensagem do io.open se não der para abrir (disco cheio, pasta sem permissão).
arquivo:write(…, ";", tarefa.texto, "\n")
Escreve os pedaços em sequência; o "\n" termina a linha. O write não pula linha sozinho, ao contrário do print.
salvar(tarefas)
Chamado logo depois de adicionar, concluir e remover. Se a luz acabar no meio do uso, nada se perde.

A sessão completa está no começo da página. E o texto "Pagar a conta de luz; vence dia 20" tem um ; dentro, e mesmo assim voltou inteiro: o padrão pega só o primeiro ; (logo depois da marca) e o (.*) fica com todo o resto.

O match deu nil para a linha 3, e o programa avisou em vez de quebrar. (O aviso sai antes do título porque o carregar() roda antes do primeiro print.) Abrir com "a" em vez de "w": tudo duplicado

Sem o segundo argumento, o io.open abre para leitura ("r"), e um arquivo que não existe não dá para ler: "nenhum arquivo ou diretório com esse nome". Formas diferentes de fazer

O menu com uma tabela de funções

Como na Calculadora, a escada de elseif do menu pode virar uma tabela que liga cada opção a uma função. Como todas as funções da versão 3 recebem a mesma coisa (a lista), a troca é direta; o laço principal fica assim:

local tarefas = {}
local acoes = {
  ["1"] = mostrar,
  ["2"] = adicionar,
  ["3"] = concluir,
  ["4"] = remover,
}

print("=== Lista de Tarefas da Ana ===")
while true do
  print()
  print("1) Ver  2) Adicionar  3) Concluir  4) Remover  0) Sair")
  local opcao = perguntar("Escolha: ")
  if opcao == "0" or opcao == nil then
    print("Até logo!")
    break
  end
  local acao = acoes[opcao]
  if acao then
    acao(tarefas)
  else
    print("Opção inválida: " .. opcao)
  end
end

Resumo

  • Um menu é um while true com if/elseif sobre a opção lida como texto, e um break para sair.
  • A lista é uma tabela: table.insert põe no fim, ipairs percorre, table.remove tira e fecha o buraco.
  • Quando cada item tem várias informações, cada item vira uma tabela com campos: { texto = …, feita = false }.
  • Valide o número antes de usá-lo como posição: tarefas[9] é nil, e table.remove(lista, nil) apaga o último sem avisar.
  • Para a lista sobreviver ao fim do programa: carregue de um arquivo no começo e salve depois de cada mudança, com "w".
  • Um formato de uma linha por item (1;texto), lido com lines e match, é simples de ler, de escrever e de consertar à mão.
