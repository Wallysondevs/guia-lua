Lua Tabelas São Referências

Com números e textos, local y = x faz o que você espera: y fica com o mesmo valor, e mudar um não muda o outro. Com tabelas, não. local b = a não cria uma tabela nova: as duas variáveis passam a apontar para a mesma tabela, e o que você muda por uma aparece na outra. Esta aula explica por quê, mostra como isso afeta as funções e o ==, e ensina a fazer uma cópia de verdade.

Você vai aprender
  • O que é uma referência, e por que b = a não copia uma tabela.
  • Que uma função que recebe uma tabela pode mudar a tabela de quem chamou.
  • Que o == entre tabelas pergunta "é a mesma tabela?", e não "têm o mesmo conteúdo?".
  • A escrever uma função de cópia rasa, e por que ela não basta para tabelas aninhadas.
  • A escrever uma função de cópia profunda.
  • Os erros reais: as mudanças que "vazam", o < entre tabelas e o stack overflow da tabela que contém a si mesma.

A ideia: o endereço da casa

Uma tabela é como uma casa. A variável não guarda a casa: guarda um papel com o endereço dela. Quando você escreve local b = a, o Lua copia o papel com o endereço, e não a casa. Agora há dois papéis apontando para a mesma casa: se alguém usar o papel b para ir lá e pintar a parede, quem for pelo papel a vai encontrar a parede pintada.

Esse "papel com o endereço" é o que se chama referência. Com números, textos e booleanos é diferente: a variável guarda o próprio valor, e copiar a variável copia o valor.

O x continuou 10 e o nome continuou "Ana". Um texto nunca é modificado "por dentro": outro .. " Lima" cria um texto novo, e só a variável outro passa a guardá-lo.

Trocar a tabela × mudar a tabela

Há uma diferença importante entre mudar o que tem dentro da tabela e pôr outra tabela na variável:

local a = {"arroz"}
local b = a
b = {"pão"}
print(a[1], b[1])
local function limpar(lista)
  lista = {}
end
local compras = {"leite"}
limpar(compras)
print(#compras)

$ lua trocar.lua
arroz	pão
1
b = {"pão"}
Isso não mexe na casa: é trocar o papel. Agora b aponta para uma tabela nova, e a continua apontando para a antiga. Por isso a[1] ainda é "arroz".
lista = {}
Dentro da função, o mesmo: a variável lista passou a apontar para uma tabela vazia nova; a tabela compras não foi tocada e continua com 1 item.

Resumo: b.x = …, b[1] = … e table.insert(b, …) mudam a tabela (todo mundo vê). b = … só troca para onde b aponta (ninguém mais vê).

2. Funções recebem a mesma tabela

Quando você passa uma tabela para uma função (aula Funções), a função recebe a referência. Se ela mudar o conteúdo, a mudança fica valendo para quem chamou. Com um número, não:

local function dar_desconto(precos)
  for produto, preco in pairs(precos) do
    precos[produto] = preco * 0.9
  end
end
local function dobrar(n)
  n = n * 2
end
local precos = {leite = 5, pao = 1}
dar_desconto(precos)
print(precos.leite, precos.pao)
local quantidade = 3
dobrar(quantidade)
print(quantidade)

$ lua funcao.lua
4.5	0.9
3
local function dar_desconto(precos)
Uma função é um pedaço de código com nome, que roda quando é chamado: dar_desconto(precos). O que vai entre os parênteses na chamada chega na variável precos de dentro dela.
precos[produto] = preco * 0.9
A função mudou os preços (10% de desconto) na tabela que recebeu, que é a mesma tabela de fora. Depois da chamada, o leite custa 4.5.
dobrar(quantidade)
A função recebeu uma cópia do número 3; o n = n * 2 mudou só a cópia. Fora, quantidade continua 3.

Isso é útil (uma função que arruma uma lista no lugar, como o table.sort e o table.insert, que mudam a tabela que você passa) e perigoso (uma função que você achava que só "lia" a tabela e acabou mudando). Se a função não deve mexer na sua tabela, passe uma cópia (seção 4).

3. O == compara a referência

local a = {1, 2, 3}
local b = {1, 2, 3}
local c = a
print(a == b)
print(a == c)
print({} == {})
local function mesmas(x, y)
  if #x ~= #y then return false end
  for i = 1, #x do
    if x[i] ~= y[i] then return false end
  end
  return true
end
print(mesmas(a, b))
print(mesmas(a, {1, 2}))

$ lua iguais.lua
false
true
false
true
false
a == b
false, mesmo com o mesmo conteúdo: são duas tabelas, duas casas iguais em endereços diferentes. O == pergunta "é a mesma tabela?".
a == c
true: c recebeu a referência de a.
{} == {}
false: cada {} cria uma tabela nova.
mesmas(x, y)
Para comparar o conteúdo, escreva uma função: mesmo tamanho e item por item igual. O return false sai da função na hora, no primeiro item diferente (aula return).
A mesma regra vale para tabela como chave

Uma tabela pode ser chave de outra (aula Dicionários), mas a chave é a referência. t[{1, 2}] = true seguido de t[{1, 2}] dá nil: são duas tabelas {1, 2} diferentes. Guarde a tabela numa variável e use sempre a mesma variável como chave.

local visitados = {}
visitados[{1, 2}] = true
print(visitados[{1, 2}])
local ponto = {1, 2}
visitados[ponto] = true
print(visitados[ponto])

$ lua chave_tabela.lua
nil
true

Missão: as duas listas de compras têm os mesmos itens, mas o == responde false. Troque o a == b por uma comparação item por item (com um for, como a função mesmas acima), para o programa mostrar iguais: true.

local a = {"arroz", "feijão", "café"}
local b = {"arroz", "feijão", "café"}
local iguais = a == b
print("iguais: " .. tostring(iguais))

local a = {"arroz", "feijão", "café"}
local b = {"arroz", "feijão", "café"}
local iguais = #a == #b
for i = 1, #a do
  if a[i] ~= b[i] then
    iguais = false
  end
end
print("iguais: " .. tostring(iguais))

4. Cópia rasa: uma tabela nova com os mesmos valores

O Lua não tem uma função pronta "copiar tabela". Mas ela é curta: crie uma tabela vazia e passe por todos os pares da original com pairs, guardando cada um na nova.

local function copiar(t)
  local nova = {}
  for chave, valor in pairs(t) do
    nova[chave] = valor
  end
  return nova
end
local hoje = {"arroz", "feijão", dia = "segunda"}
local amanha = copiar(hoje)
table.insert(amanha, "café")
amanha.dia = "terça"
print(table.concat(hoje, ", "), hoje.dia)
print(table.concat(amanha, ", "), amanha.dia)
print(hoje == amanha)

$ lua rasa.lua
arroz, feijão	segunda
arroz, feijão, café	terça
false
local nova = {}
Aqui nasce a tabela nova: uma casa nova, num endereço novo.
nova[chave] = valor
Cada par da original é guardado na nova. Funciona para listas e para dicionários, porque o pairs passa por todas as chaves.
return nova
A função devolve a tabela nova (aula return).
o resultado
O café e a terça-feira ficaram só em amanha; hoje não mudou. E hoje == amanha é false: são duas tabelas.

Só para listas: dois atalhos

local notas = {7, 8, 9}
local c1 = {table.unpack(notas)}
local c2 = table.move(notas, 1, #notas, 1, {})
c1[1] = 0
c2[2] = 0
print(table.concat(notas, " "), table.concat(c1, " "), table.concat(c2, " "))

$ lua lista_copia.lua
7 8 9	0 8 9	7 0 9
{table.unpack(notas)}
Tira os itens (aula table.unpack) e põe numa tabela nova. Bom para listas pequenas e sem buracos; com listas enormes, dá too many results to unpack.
table.move(notas, 1, #notas, 1, {})
"Mover" (na verdade, copiar) os itens de 1 a #notas de notas para a posição 1 de uma tabela nova {}, e devolver essa tabela. Funciona com listas de qualquer tamanho.

Os dois só copiam a parte de lista. Para uma tabela com chaves de nome, use a função copiar.

5. Por que "rasa": as tabelas de dentro continuam as mesmas

A cópia rasa copia os valores do primeiro nível. Se um desses valores é outra tabela (aula Tabelas Aninhadas), o que é copiado é a referência para ela, e as duas cópias passam a dividir a mesma tabela de dentro:

local function copiar(t)
  local nova = {}
  for chave, valor in pairs(t) do
    nova[chave] = valor
  end
  return nova
end
local ana = {nome = "Ana", endereco = {cidade = "Teresina"}}
local bia = copiar(ana)
bia.nome = "Bia"
bia.endereco.cidade = "Picos"
print(ana.nome, ana.endereco.cidade)
print(bia.nome, bia.endereco.cidade)
print(ana.endereco == bia.endereco)

$ lua rasa_aninhada.lua
Ana	Picos
Bia	Picos
true
bia.nome = "Bia"
O nome é um texto, do primeiro nível: cada ficha tem o seu. A Ana continuou Ana.
bia.endereco.cidade = "Picos"
O endereço é uma tabela. A cópia rasa guardou em bia.endereco a mesma referência de ana.endereco. Mudar a cidade da Bia mudou a da Ana.
ana.endereco == bia.endereco
true: é uma tabela de endereço só, dividida pelas duas fichas.

6. Cópia profunda: copiar também o que está dentro

A cópia profunda copia todos os níveis: sempre que encontra um valor que é tabela, faz uma cópia dessa tabela também, e das tabelas que estiverem dentro dela, e assim por diante. O jeito mais curto de escrever isso é uma função que chama a si mesma para as tabelas de dentro (isso tem nome, recursão, e tem aula própria):

local function copiar_tudo(t)
  local nova = {}
  for chave, valor in pairs(t) do
    if type(valor) == "table" then
      nova[chave] = copiar_tudo(valor)
    else
      nova[chave] = valor
    end
  end
  return nova
end
local ana = {nome = "Ana", endereco = {cidade = "Teresina"}, notas = {7, 8}}
local bia = copiar_tudo(ana)
bia.nome = "Bia"
bia.endereco.cidade = "Picos"
bia.notas[1] = 10
print(ana.nome, ana.endereco.cidade, ana.notas[1])
print(bia.nome, bia.endereco.cidade, bia.notas[1])
print(ana.endereco == bia.endereco)

$ lua profunda.lua
Ana	Teresina	7
Bia	Picos	10
false
type(valor) == "table"
Pergunta se o valor é uma tabela (aula type).
nova[chave] = copiar_tudo(valor)
Se for, não guarda a referência: guarda uma cópia dela, feita pela própria copiar_tudo. Se dentro dessa tabela houver outra, a chamada de dentro faz o mesmo, até não sobrar nenhum nível.
else nova[chave] = valor
Número, texto, booleano: copia o valor, como na cópia rasa.
o resultado
Agora a Bia tem o próprio endereço e as próprias notas. A Ana continuou em Teresina com nota 7, e ana.endereco == bia.endereco é false.
Os limites desta copiar_tudo
  • Ela não serve para uma tabela que contém a si mesma (direta ou indiretamente): ela entra num ciclo sem fim. Veja o último cenário de Quando dá errado e o conserto.
  • Ela não copia a metatabela (aula Metatabelas); para objetos com metatabela, a cópia precisa de um setmetatable.
  • Chaves que são tabelas não são copiadas (continuam a mesma referência). Quase nunca isso importa.

Quando dá errado

A mudança "vazou" para a outra tabela (sem erro) 
local a = {"arroz", "feijão"}
local b = a
table.insert(b, "café")
print(#a, table.concat(a, ", "))

$ lua mesma.lua
3	arroz, feijão, café

O café só foi posto em b, mas apareceu em a. Não é erro do Lua: b = a não copia (seção 1). Como consertar: se as duas listas devem ser independentes, faça uma cópia: local b = copiar(a).

Comparar duas listas iguais deu false 
local a = {1, 2, 3}
local b = {1, 2, 3}
print(a == b)

$ lua iguais.lua
false

O == compara referências: são duas tabelas (seção 3). Como consertar: compare o conteúdo com uma função como a mesmas.

Maior e menor entre tabelas 
local a = {preco = 5}
local b = {preco = 3}
print(a < b)

$ lua erro_comparar.lua
lua: erro_comparar.lua:3: attempt to compare two table values
stack traceback:
	erro_comparar.lua:3: in main chunk
	[C]: in ?

"Tentativa de comparar dois valores tabela". O == funciona (compara referências), mas o < e o > não: o Lua não sabe o que é uma tabela "menor" que outra. Como consertar: compare o campo que interessa: a.preco < b.preco. (Com metatabelas dá para ensinar o Lua a comparar, com o __lt.)

A cidade da Ana mudou junto. A cópia rasa não copia as tabelas de dentro (seção 5). Como consertar: use a cópia profunda, copiar_tudo.

A tabela que contém a si mesma: stack overflow 
local function copiar_tudo(t)
  local nova = {}
  for chave, valor in pairs(t) do
    if type(valor) == "table" then
      nova[chave] = copiar_tudo(valor)
    else
      nova[chave] = valor
    end
  end
  return nova
end
local pasta = {nome = "Documentos"}
pasta.eu_mesma = pasta
local copia = copiar_tudo(pasta)

A mensagem real tem 24 linhas; aqui estão a primeira parte e a última, sem algumas das linhas repetidas do meio:

A tabela guarda uma referência para ela mesma. Isso é permitido (e às vezes útil).
stack overflow
"Estouro da pilha". A copiar_tudo achou eu_mesma, que é uma tabela, e chamou a si mesma para copiá-la; lá dentro, achou eu_mesma de novo… sem fim. Cada chamada que ainda não terminou ocupa um lugar na pilha, e a pilha acabou.

Cada linha do rastro é uma chamada da copiar_tudo que estava esperando a de dentro terminar. São tantas que o Lua pulou (skipping) 124977 delas para não encher a tela.
erro_ciclo.lua:14: in main chunk
A primeira chamada, a da linha 14, no corpo do arquivo.

Como consertar: a cópia anota, numa tabela vistas, cada tabela que já copiou (a original vira a chave; a cópia, o valor). Se encontrar de novo uma tabela já vista, devolve a cópia que já fez, em vez de começar outra:

local function copiar_tudo(t, vistas)
  vistas = vistas or {}
  if vistas[t] then return vistas[t] end
  local nova = {}
  vistas[t] = nova
  for chave, valor in pairs(t) do
    if type(valor) == "table" then
      nova[chave] = copiar_tudo(valor, vistas)
    else
      nova[chave] = valor
    end
  end
  return nova
end
local pasta = {nome = "Documentos"}
pasta.eu_mesma = pasta
local copia = copiar_tudo(pasta)
print(copia.nome, copia.eu_mesma == copia, copia == pasta)

$ lua ciclo_ok.lua
Documentos	true	false

A cópia aponta para si mesma (copia.eu_mesma == copia), como a original, e é uma tabela nova (copia == pasta é false).

Missão final: a ficha independente

Missão: a função copiar faz uma cópia rasa, e a mudança de cidade da Bia vaza para a Ana. Transforme-a numa cópia profunda: quando o valor for uma tabela (type(valor) == "table"), guarde copiar(valor) em vez do próprio valor. O programa deve mostrar Ana mora em Teresina e Bia mora em Picos.

local function copiar(t)
  local nova = {}
  for chave, valor in pairs(t) do
    nova[chave] = valor
  end
  return nova
end
local ana = {nome = "Ana", endereco = {cidade = "Teresina"}}
local bia = copiar(ana)
bia.nome = "Bia"
bia.endereco.cidade = "Picos"
print(ana.nome .. " mora em " .. ana.endereco.cidade)

    if type(valor) == "table" then
      nova[chave] = copiar(valor)

      nova[chave] = valor

Resumo

  • Uma variável de tabela guarda uma referência (o "endereço"), não a tabela. b = a faz duas variáveis apontarem para a mesma tabela.
  • Mudar o conteúdo (b.x = …, table.insert(b, …)) aparece em todas as referências; b = {} só troca para onde b aponta.
  • Funções recebem a mesma tabela e podem mudá-la; números e textos chegam como cópia.
  • == entre tabelas pergunta "é a mesma tabela?"; para comparar o conteúdo, escreva uma função. < entre tabelas é erro.
  • Cópia rasa: tabela nova com os mesmos pares (pairs), mas as tabelas de dentro continuam divididas.
  • Cópia profunda: uma função que copia também cada tabela de dentro, chamando a si mesma; para tabelas que contêm a si mesmas, anote as já copiadas.
