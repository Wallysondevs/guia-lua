Lua Classes com Metatabelas

O banco da Ana tem milhares de contas, e todas sabem fazer as mesmas coisas: depositar, sacar, mostrar o extrato. Em muitas linguagens, isso se escreve com uma classe: um molde que descreve o que todo objeto daquele tipo tem e faz. O Lua não tem uma palavra class, mas tem tudo o que é preciso para montar uma: metatabelas, o __index e os métodos com dois-pontos. Nesta aula você junta as três peças num padrão de duas linhas que todo programador Lua conhece: Conta.__index = Conta e Conta.new.

Você vai aprender
  • O que é uma classe e um objeto, com a comparação da fôrma de bolo.
  • Por que copiar os métodos para cada objeto não é uma boa ideia.
  • O padrão completo: local Conta = {}, Conta.__index = Conta, Conta.new(…) e function Conta:metodo(…).
  • O caminho que o Lua faz para achar conta_ana:depositar.
  • Metamétodos e valores padrão na classe (__tostring, __lt, limite_saque).
  • As formas Conta.new, Conta:new e Conta(…), e qual escolher.
  • Os erros reais: esquecer o __index, o setmetatable ou o return, e chamar o método na classe.

Todos os programas rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook) com lua arquivo.lua. Esta aula usa tudo das quatro anteriores: Metatabelas, __index e __newindex, __tostring e Métodos.

A ideia: a fôrma e os bolos

Na padaria, a Ana tem uma fôrma de bolo e a receita colada nela. Com ela, faz quantos bolos quiser. Cada bolo tem o seu sabor e o seu recheio (os dados), mas todos foram feitos do mesmo jeito e seguem a mesma receita (os métodos).

  • A classe é a fôrma com a receita: a tabela Conta, onde ficam os métodos depositar, sacar, extrato.
  • Cada objeto (ou instância) é um bolo: a conta da Ana, a conta da Bia. Cada um guarda só os seus dados (titular, saldo).
  • A metatabela com __index é a ligação "este bolo saiu desta fôrma": quando você pede ao objeto um método que ele não tem, o Lua vai procurar na classe.

1. O jeito sem classe: copiar os métodos

Com o que você aprendeu em Métodos, já dá para criar várias contas com os mesmos métodos: uma função que monta a tabela e põe as funções em cada uma.

local function depositar(self, valor) self.saldo = self.saldo + valor end
local function extrato(self) print(self.titular .. ": " .. self.saldo) end

local function nova_conta(titular, saldo)
  return { titular = titular, saldo = saldo, depositar = depositar, extrato = extrato }
end

local a = nova_conta("Ana", 100)
local b = nova_conta("Bia", 20)
a:depositar(50)
b:depositar(30)
a:extrato()
b:extrato()
local campos = 0
for _ in pairs(a) do campos = campos + 1 end
print("campos em cada conta:", campos)

$ lua copias.lua
Ana: 150
Bia: 50
campos em cada conta:	4

Funciona, mas cada conta carrega 4 campos: 2 de dados e 2 de métodos. Com 10 métodos, seriam 12 campos por conta, repetidos em milhares de contas. E, se a Ana criar um método novo depois, as contas que já existem não ficam sabendo dele. O jeito com classe resolve as duas coisas: os métodos ficam num lugar só.

2. A primeira classe: Conta

local Conta = {}
Conta.__index = Conta

function Conta.new(titular, saldo)
  local self = setmetatable({}, Conta)
  self.titular = titular
  self.saldo = saldo or 0
  return self
end

function Conta:depositar(valor)
  self.saldo = self.saldo + valor
end

function Conta:extrato()
  print(string.format("%s: R$ %.2f", self.titular, self.saldo))
end

local conta_ana = Conta.new("Ana", 100)
local conta_bia = Conta.new("Bia")
conta_ana:depositar(50)
conta_bia:depositar(30)
conta_ana:extrato()
conta_bia:extrato()

$ lua conta.lua
Ana: R$ 150.00
Bia: R$ 30.00
local Conta = {}
A classe é uma tabela comum. O nome começa com maiúscula por convenção: assim quem lê sabe que Conta é a fôrma, e conta_ana é um bolo.
Conta.__index = Conta
A linha mais importante. A tabela Conta vai ter dois papéis: guardar os métodos e ser a metatabela dos objetos. Com __index apontando para ela mesma, o recado é: "o que faltar no objeto, procure na Conta".
function Conta.new(titular, saldo)
O construtor: a função que fabrica objetos. O nome new ("novo") é tradição, não regra. Ela é chamada com ponto, porque não trabalha num objeto que já existe.
local self = setmetatable({}, Conta)
Cria uma tabela vazia, liga a metatabela Conta e chama o resultado de self (poderia ser obj, nova…). A partir daqui, ela já "saiu da fôrma".
self.saldo = saldo or 0
Guarda os dados no objeto. Se o saldo não veio (como na conta da Bia), começa em 0.
return self
Entrega o objeto pronto para quem chamou Conta.new.
function Conta:depositar(valor)
Os métodos ficam na classe, com dois-pontos. O self de cada chamada será o objeto que veio antes do :.

Passo a passo: como o Lua acha conta_ana:depositar

  1. conta_ana:depositar(50) é conta_ana.depositar(conta_ana, 50). Primeiro, o Lua precisa do valor de conta_ana.depositar.
  2. Ele procura depositar na própria conta_ana. Ela só tem titular e saldo: não acha.
  3. A conta_ana tem metatabela? Tem: Conta. E Conta.__index existe? Existe: é a própria Conta.
  4. Ele procura depositar em Conta, acha a função, e a chama com (conta_ana, 50). O self é a conta_ana: o depósito cai no lugar certo.

Vamos conferir que os objetos guardam só os dados:

local conta_ana = Conta.new("Ana", 100)
print(rawget(conta_ana, "depositar"))
print(conta_ana.depositar == Conta.depositar)
print(getmetatable(conta_ana) == Conta)
local nomes = {}
for chave in pairs(conta_ana) do nomes[#nomes + 1] = chave end
table.sort(nomes)
print("campos da conta:", table.concat(nomes, ", "))
local metodos = {}
for chave in pairs(Conta) do metodos[#metodos + 1] = chave end
table.sort(metodos)
print("campos da classe:", table.concat(metodos, ", "))

(O começo do arquivo, com a classe Conta, o new e o depositar, é igual ao de conta.lua.) O rawget confirma que depositar não está no objeto (veja rawget); mesmo assim, conta_ana.depositar é a função da classe. O objeto tem só saldo e titular; a classe tem o __index, o depositar e o new. 3. Metamétodos e valores padrão na classe

Como a classe é a metatabela dos objetos, os metamétodos que você aprendeu nas aulas anteriores entram nela direto: Conta.__tostring vale para todas as contas. E um campo comum na classe vira um valor padrão para todos os objetos (graças ao __index), que cada objeto pode trocar só para si:

local Conta = {}
Conta.__index = Conta
Conta.limite_saque = 500

function Conta.new(titular, saldo)
  return setmetatable({ titular = titular, saldo = saldo or 0 }, Conta)
end

function Conta:sacar(valor)
  if valor > self.limite_saque then
    return false, "acima do limite de R$ " .. self.limite_saque
  end
  if valor > self.saldo then
    return false, "saldo insuficiente"
  end
  self.saldo = self.saldo - valor
  return true
end

Conta.__tostring = function (c)
  return string.format("Conta(%s, R$ %.2f)", c.titular, c.saldo)
end

Conta.__lt = function (a, b)
  return a.saldo < b.saldo
end

local ana = Conta.new("Ana", 1000)
local bia = Conta.new("Bia", 3000)
bia.limite_saque = 2000

print(ana, bia)
print(ana:sacar(800))
print(bia:sacar(800))
print(ana, bia)
print(ana < bia)

$ lua tostring.lua
Conta(Ana, R$ 1000.00)	Conta(Bia, R$ 3000.00)
false	acima do limite de R$ 500
true
Conta(Ana, R$ 1000.00)	Conta(Bia, R$ 2200.00)
true
Conta.limite_saque = 500
Um dado da classe: todas as contas enxergam self.limite_saque como 500, pelo __index, sem guardar uma cópia.
bia.limite_saque = 2000
A Bia ganhou um limite maior. A gravação cria o campo no objeto bia; a classe continua com 500, e a Ana também. É a mesma regra das configurações padrão em __index e __newindex.
ana:sacar(800) → false, acima do limite…
Para a Ana, 800 passa do limite de 500. Para a Bia, não: o saque foi feito, e o saldo dela foi a 2200.
Conta.__tostring e Conta.__lt
Metamétodos na classe: o print mostra as contas de um jeito legível, e ana < bia compara os saldos (o que também permitiria ordenar uma lista de contas com table.sort).
Dado da classe que é tabela: cuidado

Valores simples (números, textos) na classe funcionam bem como padrão, porque gravar no objeto cria uma cópia só dele. Mas se a classe tiver uma tabela, como Conta.historico = {}, e um método fizer table.insert(self.historico, …), todos os objetos vão escrever na mesma tabela da classe (o __index devolve a mesma tabela para todos). No lab, com a conta da Ana em a e a da Bia em b, depois de a:registrar("depósito da Ana"), o #b.historico deu 1, e o item era depósito da Ana: o histórico da Bia mostrava o depósito da Ana. Tabelas de cada objeto devem ser criadas no new: self.historico = {}.

4. Outra classe: Retangulo

O padrão é sempre o mesmo, para qualquer tipo de coisa. As figuras da Ana:

local Retangulo = {}
Retangulo.__index = Retangulo

function Retangulo.new(largura, altura)
  return setmetatable({ largura = largura, altura = altura }, Retangulo)
end

function Retangulo:area()
  return self.largura * self.altura
end

Retangulo.__tostring = function (r)
  return "Retângulo " .. r.largura .. "x" .. r.altura
end

local porta = Retangulo.new(1, 2)
local mesa = Retangulo.new(3, 4)
print(porta, porta:area())
print(mesa, mesa:area())

$ lua retangulo.lua
Retângulo 1x2	2
Retângulo 3x4	12

Aqui o new cria e liga a metatabela numa linha só (return setmetatable({ … }, Retangulo)), o que é muito comum quando o construtor não precisa fazer mais nada. Na próxima aula, Herança, o quadrado vai aproveitar tudo do retângulo.

Formas diferentes de fazer a mesma coisa

Você vai encontrar três jeitos de escrever o construtor em códigos por aí:

-- forma 1 (desta aula): Conta.new, com ponto
function Conta.new(titular, saldo)
  local self = setmetatable({}, Conta)
  …
  return self
end
local a = Conta.new("Ana", 100)

-- forma 2: Conta:new, com dois-pontos (o self é a classe)
function Conta:new(titular, saldo)
  local obj = setmetatable({}, self)
  obj.titular = titular
  obj.saldo = saldo or 0
  return obj
end
local a = Conta:new("Ana", 100)

-- forma 3: chamar a classe como função, com __call na metatabela da classe
setmetatable(Conta, {
  __call = function (classe, ...)
    return classe:new(...)
  end,
})
local b = Conta("Bia", 20)

No lab, as formas 2 e 3 juntas (um programa com Conta:new e o __call) criaram as duas contas certinho: Ana 100 true e Bia 20 true, o true sendo o getmetatable(…) == Conta. O ... repassa todos os argumentos (veja Funções Variádicas), e o __call é o da aula __tostring, __call e __len.

FormaVantagemCuidado
Conta.new(…)A mais simples de entender: o new é uma função comumChame com ponto, sempre
Conta:new(…)Usa self como metatabela, o que facilita a herança (o livro Programming in Lua usa esta forma)Chame com dois-pontos, sempre; dentro do new, self é a classe, não o objeto
Conta(…)Parece com outras linguagensUma metatabela a mais (a da classe), com __call

Escolha uma e use sempre a mesma no programa inteiro. Neste guia, usamos Conta.new.

O objeto tem a metatabela Conta, mas a metatabela não tem __index: o Lua não sabe que deve procurar os métodos nela, e conta_ana.depositar dá nil. Referência rápida: o molde de uma classe

local Classe = {}
Classe.__index = Classe              -- objetos procuram os métodos aqui

function Classe.new(a, b)            -- construtor (chame com ponto)
  local self = setmetatable({}, Classe)
  self.a = a                         -- dados ficam no objeto
  self.b = b
  return self
end

function Classe:metodo(x)            -- métodos com dois-pontos
  return self.a + x
end

Classe.__tostring = function (obj)   -- metamétodos na própria classe
  return "Classe(" .. obj.a .. ")"
end

local obj = Classe.new(1, 2)         -- criar
print(obj:metodo(10))                -- usar

Resumo

  • Uma classe no Lua é uma tabela com os métodos, que também serve de metatabela para os objetos. Um objeto é uma tabela com os dados, ligada à classe.
  • O padrão: local Conta = {}, Conta.__index = Conta, um construtor Conta.new que faz setmetatable({}, Conta) e return, e métodos function Conta:metodo().
  • Quando o objeto não tem o método, o __index leva o Lua até a classe; o self é o objeto da chamada.
  • Metamétodos (__tostring, __lt…) ficam na classe e valem para todos os objetos. Campos simples da classe são padrões que cada objeto pode trocar.
  • attempt to call a nil value (method '…'): confira o __index e o setmetatable. Construtor com ponto, métodos com dois-pontos.
