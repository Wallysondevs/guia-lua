Lua Metamétodos de Operadores

Na aula Metatabelas, você ensinou o + a somar duas cestas com o __add. Todos os outros operadores do Lua também podem ser ensinados: subtrair, multiplicar, comparar com == e <, juntar com ... Nesta aula, a Ana cria um tipo novo para os preços da padaria, o Dinheiro, e ensina a ele um operador de cada vez.

Você vai aprender
  • Os erros reais que o Lua dá quando você usa um operador numa tabela sem metamétodo.
  • As contas: __add (+), __sub (-), __mul (*) e __unm (o sinal de negativo).
  • O que fazer quando um dos lados da conta é um número comum (pao * 6 e 6 * pao).
  • As comparações: __eq (== e ~=), __lt (< e >) e __le (<= e >=), e como o __lt faz o table.sort funcionar.
  • O __concat, para escrever "Preço: " .. preco.
  • A lista completa dos metamétodos de operadores.

Todos os programas rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook) com lua arquivo.lua. Você precisa já conhecer setmetatable (aula Metatabelas), operadores aritméticos, comparações e string.format.

A ideia: ensinar as contas a um tipo novo

Pense numa calculadora de padaria que só conhece números. Um dia, o dono quer que ela entenda "dinheiro": que R$ 10,50 + R$ 6,25 dê R$ 16,75, que um preço possa ser comparado com outro, que o total apareça bonito no papel. Ninguém muda a calculadora: o dono escreve um manual com uma página para cada tecla, dizendo "quando apertarem + com dinheiro, faça assim".

No Lua, cada operador tem a sua "página" no manual (a metatabela), com um nome fixo:

OperadorMetamétodoLê-se (inglês)
a + b__addadd, somar
a - b__subsubtract, subtrair
a * b__mulmultiply, multiplicar
-a__unmunary minus, menos de um operando só
a == b__eqequal, igual
a < b__ltless than, menor que
a <= b__leless or equal, menor ou igual
a .. b__concatconcatenate, juntar

A lista completa (com /, //, %, ^ e os operadores de bits) está na Referência rápida.

1. Sem manual: os erros de cada operador

Primeiro, o que o Lua faz com duas tabelas comuns. O pcall abaixo serve só para o programa continuar depois de cada erro e mostrar todas as mensagens de uma vez (ele devolve false e a mensagem):

local a = { centavos = 1050 }
local b = { centavos = 1050 }
print(pcall(function () return a - b end))
print(pcall(function () return a * 2 end))
print(pcall(function () return -a end))
print(pcall(function () return a < b end))
print(pcall(function () return a .. "!" end))
print(a == b)
print(a == a)

2. O tipo Dinheiro: __add e __sub

A Ana guarda os preços em centavos, como número inteiro: R$ 10,50 vira 1050. Assim as contas nunca dão "quebrados" estranhos de número com vírgula (veja Números). A metatabela se chama Dinheiro, com letra maiúscula, porque ela representa um tipo de valor (é uma convenção, você vai vê-la de novo em Classes).

local Dinheiro = {}

local function reais(centavos)
  return setmetatable({ centavos = centavos }, Dinheiro)
end

local function mostrar(d)
  return string.format("R$ %d,%02d", d.centavos // 100, d.centavos % 100)
end

Dinheiro.__add = function (a, b)
  return reais(a.centavos + b.centavos)
end

Dinheiro.__sub = function (a, b)
  return reais(a.centavos - b.centavos)
end

local pao = reais(1050)
local leite = reais(625)
local total = pao + leite
print("Total: " .. mostrar(total))
local troco = reais(2000) - total
print("Troco: " .. mostrar(troco))

$ lua dinheiro.lua
Total: R$ 16,75
Troco: R$ 3,25

A função que cria um valor de Dinheiro: uma tabela com o campo centavos, já ligada ao manual. reais(1050) é "dez reais e cinquenta".
local function mostrar(d)
Transforma em texto para mostrar: 1675 // 100 é 16 (os reais) e 1675 % 100 é 75 (os centavos); o %02d põe um zero na frente quando precisa (R$ 3,05). Veja Divisão: /, // e %.
Dinheiro.__add = function (a, b)
Ensina o +: soma os centavos e devolve um Dinheiro novo (criado com reais). Por devolver um Dinheiro, o resultado também sabe fazer contas: foi o que permitiu reais(2000) - total logo depois.

Ensina o - do mesmo jeito. Atenção à ordem: a é o lado esquerdo (reais(2000)) e b o direito (total). Na subtração, a ordem importa.

3. Quando um lado é número: __mul

Seis pães de R$ 1,50: a Ana quer escrever pao * 6. Aqui um lado é Dinheiro e o outro é um número comum. A primeira tentativa:

local Dinheiro = {}

local function reais(centavos)
  return setmetatable({ centavos = centavos }, Dinheiro)
end

local function mostrar(d)
  return string.format("R$ %d,%02d", d.centavos // 100, d.centavos % 100)
end

Dinheiro.__mul = function (a, b)
  return reais(a.centavos * b)
end

local pao = reais(150)
print(mostrar(pao * 6))
print(mostrar(6 * pao))

$ lua mul.lua
R$ 9,00
lua: mul.lua:12: attempt to index a number value (local 'a')
stack traceback:
	mul.lua:12: in metamethod 'mul'
	mul.lua:17: in main chunk
	[C]: in ?

pao * 6 funcionou, mas 6 * pao não. O motivo: o Lua sempre passa os dois lados na ordem em que estão escritos. Em 6 * pao, o a é o número 6, e a.centavos tenta pegar um campo de um número.

mul.lua:12: attempt to index a number value (local 'a')
"Tentativa de indexar (pegar um campo de) um valor número, a variável local a": é o a.centavos da linha 12, com a = 6.
mul.lua:12: in metamethod 'mul'
A primeira linha do rastro: o erro aconteceu dentro do metamétodo __mul (o Lua escreve sem os sublinhados).
mul.lua:17: in main chunk
E quem disparou o metamétodo foi a linha 17, a do 6 * pao. O rastro mostra as duas pontas: onde a conta foi escrita e onde a sua função quebrou.

Para ver com os próprios olhos o que o Lua passa, este programa só mostra os tipos de a e b:

local mt = {}
mt.__add = function (a, b)
  print("a =", type(a), "b =", type(b))
  return 0
end
mt.__unm = function (a, b)
  print("unm:", type(a), type(b), a == b)
  return 0
end
local t = setmetatable({}, mt)
local _ = t + 1
_ = 1 + t
_ = t + t
_ = -t

$ lua argumentos.lua
a =	table	b =	number
a =	number	b =	table
a =	table	b =	table
unm:	table	table	true

Em 1 + t, a tabela chegou em b. E o sinal de negativo (-t, com um operando só) chama o __unm com a mesma tabela duas vezes (a == b deu true): use só o primeiro parâmetro. (O _ é um nome de variável comum, usado quando o valor não interessa.)

O conserto do __mul: se o número veio na esquerda, troque os dois de lugar antes da conta. E, de brinde, o __unm:

Dinheiro.__mul = function (a, b)
  if type(a) == "number" then
    a, b = b, a
  end
  return reais(a.centavos * b)
end

Dinheiro.__unm = function (a)
  return reais(-a.centavos)
end

local pao = reais(150)
print(mostrar(pao * 6))
print(mostrar(6 * pao))
print((-pao).centavos)

$ lua mul2.lua
R$ 9,00
R$ 9,00
-150

(O começo do arquivo, com Dinheiro, reais e mostrar, é igual ao de mul.lua.) O a, b = b, a troca os valores das duas variáveis numa linha (veja Atribuição Múltipla). Na multiplicação a ordem não muda o resultado, então trocar é seguro. Na subtração e na divisão, não: lá a - b e b - a são contas diferentes.

4. Igualdade: __eq

Duas etiquetas de R$ 10,50 são o mesmo preço. Mas, como você viu na seção 1, duas tabelas diferentes nunca são == sem manual. O __eq ensina o que é "igual" para o Dinheiro:

local Dinheiro = {}

local function reais(centavos)
  return setmetatable({ centavos = centavos }, Dinheiro)
end

local a = reais(1050)
local b = reais(1050)
print("antes do __eq:", a == b, a ~= b)

Dinheiro.__eq = function (x, y)
  return x.centavos == y.centavos
end
print("depois do __eq:", a == b, a ~= b)
print(a == reais(999))
print(a == 1050)

$ lua igual.lua
antes do __eq:	false	true
depois do __eq:	true	false
false
false
antes do __eq: false true
Sem o metamétodo, a e b são tabelas diferentes, então não são iguais (e são "diferentes", ~=).
Dinheiro.__eq = function (x, y)
A regra: dois Dinheiros são iguais se têm os mesmos centavos. O resultado é sempre convertido para true ou false.
depois do __eq: true false
Agora a == b chama o __eq. E o ~= ("diferente") usa o mesmo metamétodo, só que ao contrário: não existe um __ne.
a == 1050 → false
O __eq só é chamado quando os dois lados são tabelas (e não são a mesma tabela). Uma tabela comparada com um número é sempre diferente, sem nem perguntar ao manual.

Missão: a padaria e o mercado vendem o leite pelo mesmo preço, mas o programa diz que os preços são diferentes. Escreva um Dinheiro.__eq que compare os centavos, para aparecer Mesmo preço!.

  print("Mesmo preço!")
else

5. Menor e maior: __lt e __le

Para saber qual preço é mais barato, o Lua precisa de duas páginas no manual: __lt ("menor que", para <) e __le ("menor ou igual", para <=). Não existem páginas para > e >=: o Lua vira a conta ao contrário. a > b vira b < a, e a >= b vira b <= a.

local Dinheiro = {}

local function reais(centavos)
  return setmetatable({ centavos = centavos }, Dinheiro)
end

Dinheiro.__lt = function (a, b)
  return a.centavos < b.centavos
end

local cafe = reais(800)
local bolo = reais(2500)
print(cafe < bolo)
print(cafe > bolo)
print(bolo > cafe)
print(pcall(function () return cafe <= bolo end))

Dinheiro.__le = function (a, b)
  return a.centavos <= b.centavos
end
print(cafe <= bolo, cafe >= bolo, cafe <= reais(800))

$ lua menor.lua

false
true
false	menor.lua:16: attempt to compare two table values
true	false	true
cafe < bolo → true
R$ 8,00 é menor que R$ 25,00: o __lt foi chamado com (cafe, bolo).
cafe > bolo → false
O Lua transformou em bolo < cafe e chamou o mesmo __lt, com os lados trocados.
cafe <= bolo → erro
Com só o __lt, o <= dá attempt to compare two table values. No Lua 5.5, cada um precisa da sua página: o <= não é deduzido do <.
Dinheiro.__le = …
Com o __le, as três comparações da última linha funcionaram: <= e >= (virado para <=).
O <= sem __le nas outras versões

Nas versões antigas, quando faltava o __le, o Lua tentava not (b < a) com o __lt. No lab, um programa com só o __lt deu true para x <= y no lua5.1, no luajit e também no lua5.4 do Ubuntu (que vem com essa compatibilidade ligada); no lua (5.5), deu o erro acima. Escreva sempre os dois metamétodos, e o seu programa funciona em todas. Veja as diferenças entre as versões.

O __lt e o table.sort

O table.sort ordena uma lista comparando os itens com <. Numa lista de tabelas comuns, ele não tem como comparar:

local precos = { { centavos = 2500 }, { centavos = 800 } }
table.sort(precos)

$ lua ordenar_sem.lua
lua: attempt to compare two table values
stack traceback:
	[C]: in field 'sort'
	ordenar_sem.lua:2: in main chunk
	[C]: in ?

Repare: desta vez a mensagem não tem número de linha logo depois de lua:. A comparação aconteceu dentro do table.sort, que é escrito em C ([C]: in field 'sort'), e não numa linha do seu arquivo. A linha do seu programa aparece no rastro: ordenar_sem.lua:2. Com o __lt no manual, o table.sort funciona sem você mudar nada nele; é a missão final desta aula.

6. Juntar com texto: __concat

Até aqui, para mostrar um preço, a Ana chamou mostrar(total). Seria mais natural escrever "Preço: " .. preco. Sem manual:

local preco = { centavos = 1050 }
print("Preço: " .. preco)

$ lua juntar.lua
lua: juntar.lua:2: attempt to concatenate a table value (local 'preco')
stack traceback:
	juntar.lua:2: in main chunk
	[C]: in ?

O __concat recebe os dois lados do ... Um deles é Dinheiro; o outro, em geral, é um texto, e pode estar na esquerda ou na direita. A função abaixo transforma em texto o lado (ou os lados) que for Dinheiro e junta:

local Dinheiro = {}

local function reais(centavos)
  return setmetatable({ centavos = centavos }, Dinheiro)
end

local function mostrar(d)
  return string.format("R$ %d,%02d", d.centavos // 100, d.centavos % 100)
end

Dinheiro.__concat = function (a, b)
  if getmetatable(a) == Dinheiro then a = mostrar(a) end
  if getmetatable(b) == Dinheiro then b = mostrar(b) end
  return a .. b
end

local preco = reais(1050)
print("Preço: " .. preco)
print(preco .. " por quilo")
print("De " .. reais(1200) .. " por " .. preco)

$ lua concat.lua
Preço: R$ 10,50
R$ 10,50 por quilo
De R$ 12,00 por R$ 10,50
getmetatable(a) == Dinheiro
O jeito de perguntar "este valor é um Dinheiro?": é Dinheiro se a metatabela dele for a tabela Dinheiro.
return a .. b
Aqui os dois lados já são textos, então este .. é o normal do Lua, sem manual.
"De " .. reais(1200) .. " por " .. preco
Uma corrente de .. com dois Dinheiros no meio: o __concat foi chamado o quanto precisou, e tudo virou um texto só.
E para o print(preco) sozinho?

O __concat só entra no ... Para o print(preco) e o tostring(preco) mostrarem R$ 10,50, o metamétodo é outro, o __tostring, na aula __tostring, __call e __len. Com ele, o mostrar nem é mais necessário.

Formas diferentes de fazer a mesma coisa

Os metamétodos podem ser escritos um por um, como nesta aula, ou todos juntos, dentro das chaves da metatabela. Como as funções usam reais, e reais usa a metatabela, a forma "tudo junto" precisa que a metatabela já exista (por isso o local Dinheiro vem antes, numa linha separada):

local Dinheiro
local function reais(centavos)
  return setmetatable({ centavos = centavos }, Dinheiro)
end

Dinheiro = {
  __add = function (a, b) return reais(a.centavos + b.centavos) end,
  __sub = function (a, b) return reais(a.centavos - b.centavos) end,
  __eq  = function (a, b) return a.centavos == b.centavos end,
  __lt  = function (a, b) return a.centavos < b.centavos end,
  __le  = function (a, b) return a.centavos <= b.centavos end,
}

E, claro, nada obriga a usar operadores: uma função comum como somar(a, b) faz o mesmo trabalho. Quando escolher cada um:

SituaçãoQual usar
O operador tem um sentido óbvio para o seu tipo (somar dinheiro, comparar preços, somar vetores)Metamétodo: total = pao + leite fica fácil de ler
O sentido não é óbvio ("multiplicar" duas cestas?)Uma função com nome claro: juntar_cestas(a, b)
Você precisa ordenar uma lista com table.sort__lt no tipo, ou uma função de comparação no próprio table.sort(lista, function (a, b) … end) (veja table.sort)
Comparar com <= e >=Escreva __le também (o 5.5 não o deduz do __lt)

Usou <= com só o __lt

Ordenou uma lista de tabelas sem __lt

local Dinheiro = {}

local function reais(centavos)
  return setmetatable({ centavos = centavos }, Dinheiro)
end

local function mostrar(d)
  return string.format("R$ %d,%02d", d.centavos // 100, d.centavos % 100)
end

Dinheiro.__lt = function (a, b)
  return a.centavos < b.centavos
end

local precos = { reais(2500), reais(800), reais(1050), reais(375) }
table.sort(precos)
for i, p in ipairs(precos) do
  print(i .. "º: " .. mostrar(p))
end

No lab, a solução mostrou:

$ lua vitrine.lua
1º: R$ 3,75
2º: R$ 8,00
3º: R$ 10,50
4º: R$ 25,00

Desafio extra: troque o < por > dentro do __lt. A vitrine passa a ir do mais caro para o mais barato, porque o table.sort confia no que o manual disser que é "menor".

Resumo

  • Cada operador tem um metamétodo com nome fixo: __add, __sub, __mul, __unm, __eq, __lt, __le, __concat, e outros na tabela de referência.
  • Sem o metamétodo, o Lua dá attempt to perform arithmetic on a table value, attempt to compare two table values ou attempt to concatenate a table value. O == não dá erro: compara se é a mesma tabela.
  • O metamétodo recebe os dois lados na ordem escrita; um deles pode ser um número ou um texto. Confira com type ou getmetatable.
  • Devolva um valor do mesmo tipo (return reais(…)) para o resultado continuar sabendo fazer contas; sem return, o resultado é nil.
  • > e >= usam __lt e __le com os lados trocados. No 5.5, escreva os dois. O __lt faz o table.sort funcionar.
