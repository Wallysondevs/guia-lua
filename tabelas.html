Lua Tabelas: a Estrutura de Tudo

Até aqui, cada variável guardou um valor: um número, um texto, um true. Mas a lista de compras da Ana tem vários itens, a ficha de um cliente tem nome, telefone e endereço, e o estoque da padaria tem dezenas de produtos. Para guardar muitos valores juntos, o Lua tem uma única ferramenta: a tabela (em inglês, table). Outras linguagens têm um tipo para listas, outro para dicionários, outro para objetos. O Lua tem só a tabela, e ela faz o papel de todos.

Você vai aprender
  • O que é uma tabela: um armário de gavetas com etiquetas (chaves) e conteúdo (valores).
  • Como criar uma tabela com {}, guardar e ler com t[chave] e com o atalho t.campo.
  • Por que uma gaveta que não existe devolve nil.
  • Os três papéis da tabela: lista, dicionário e objeto (ficha).
  • O construtor completo: {"a", "b", nome = "Ana", ["com espaço"] = 1}.
  • Como mudar e apagar um campo, e quais valores podem ser chave.
  • O que o print(t) mostra (table: 0x…) e por que esse número muda.
  • Os erros reais: indexar nil, chave nil, juntar tabela com texto, vírgula esquecida.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), com lua arquivo.lua. As próximas aulas aprofundam cada papel da tabela: Tabelas como Listas e Tabelas como Dicionários.

A ideia: um armário de gavetas com etiquetas

Imagine um armário com gavetas. Cada gaveta tem uma etiqueta na frente e guarda uma coisa dentro. Para pegar algo, você não precisa saber em que posição a gaveta está: basta ler a etiqueta.

Etiqueta (chave)Conteúdo (valor)
"nome""Ana"
"idade"30
1"primeira gaveta"

Uma tabela do Lua é exatamente isso: um conjunto de pares chave → valor. A chave é a etiqueta; o valor, o que está guardado. A etiqueta pode ser um texto ("nome") ou um número (1). E o armário cresce sozinho: quantas gavetas você quiser, sem precisar avisar antes.

1. Criando uma tabela: {}

Uma tabela nova e vazia se cria com um par de chaves, {}:

local t = {}
print(type(t))
print(t)

$ lua vazia.lua
table
table: 0x55c77b3bb4e0
{}
O construtor de tabela: cria uma tabela nova. Vazia, por enquanto.
type(t)
O tipo do valor (veja Descobrindo o Tipo): table. É um dos tipos do Lua, como number e string.
print(t) → table: 0x55c77b3bb4e0
O print não mostra o que tem dentro da tabela. Ele mostra a palavra table e um número em hexadecimal (o 0x avisa: base 16, com dígitos de 0 a 9 e de a a f). Esse número é o endereço: o lugar da memória onde a tabela foi guardada. É como o número do armário no depósito, não o conteúdo dele.

Rodando o mesmo programa mais duas vezes, o endereço mudou a cada vez:

$ lua vazia.lua
table
table: 0x55a9bee3f4e0
$ lua vazia.lua
table
table: 0x55cbde5784e0

Cada vez que o programa roda, o sistema dá ao Lua um pedaço diferente da memória, então o endereço que você vai ver será outro. No editor do guia ele também é diferente: mais curto (como table: 0x80e560), porque o Lua de lá roda dentro do navegador, e costuma se repetir de um Rodar para outro. Não tente decorar nem comparar esse número com o desta página: ele só serve para dizer "é uma tabela, e é esta tabela". Para ver o conteúdo, é preciso pedir gaveta por gaveta, como nas próximas seções.

2. Guardando e lendo: t[chave]

Para guardar um valor numa gaveta, escreva o nome da tabela, a chave entre colchetes, = e o valor. Para ler, a mesma coisa sem o =:

local armario = {}
armario["nome"] = "Ana"
armario["idade"] = 30
armario[1] = "primeira gaveta"
print(armario["nome"])
print(armario["idade"])
print(armario[1])
print(armario["telefone"])
armario["nome"] = "Ana"
"Na gaveta de etiqueta "nome", guarde "Ana"." Se a gaveta não existia, ela passa a existir.
armario[1] = …
A etiqueta também pode ser um número. 1 (número) e "1" (texto) são etiquetas diferentes.
armario["nome"]
Sem =, é leitura: devolve o que está na gaveta.
armario["telefone"]
Uma gaveta que ninguém criou. Não é erro: o Lua devolve nil, o "nada".
$ lua gavetas.lua
Ana
30
primeira gaveta
nil

Esse nil é importante: numa tabela, toda chave que não foi usada vale nil. Ler uma gaveta vazia nunca dá erro; o erro só aparece depois, se você tentar fazer conta ou juntar texto com esse nil (veja Quando dá errado).

O atalho do ponto: t.campo

Quando a chave é um texto que poderia ser um nome de variável (letras, números e _, sem espaço e sem começar com número), dá para trocar t["nome"] por t.nome. As duas formas são a mesma gaveta:

local ficha = {}
ficha.nome = "Ana"
ficha.idade = 30
print(ficha.nome, ficha["nome"])
print(ficha.idade + 1)

$ lua ponto.lua
Ana	Ana
31

O ponto é só uma forma mais curta de escrever. ficha.nome é ficha["nome"], com aspas e tudo. Cuidado: ficha[nome], sem aspas, é outra coisa: usa o valor da variável nome como chave.

No modo interativo

No modo interativo, digitar o nome de um campo mostra o valor; digitar a tabela inteira mostra só o endereço:

$ lua
Lua 5.5.0  Copyright (C) 1994-2025 Lua.org, PUC-Rio
> ficha = {nome = "Ana", idade = 30}
> ficha.nome
Ana
> ficha.idade + 1

> ficha
table: 0x55c2979c9e70
> ficha.telefone
nil
> type(ficha)
table
> os.exit()

(No modo interativo a ficha foi criada sem local, porque um local não sobrevive de uma linha para a outra lá; veja O Modo Interativo.)

3. Os três papéis da tabela

A mesma ferramenta, usada de três jeitos:

-- 1) lista: itens em ordem, chaves 1, 2, 3...
local compras = {"pão", "leite", "café"}
print(compras[1], compras[3], #compras)

-- 2) dicionário: cada chave é um nome
local precos = {pao = 0.75, leite = 5.49, cafe = 18.90}
print(precos.leite, precos["cafe"])

-- 3) objeto (ficha): as informações de uma coisa só
local produto = {nome = "Café", preco = 18.90, estoque = 5}
print(produto.nome .. " custa R$ " .. produto.preco)

$ lua tres_usos.lua
pão	café	3
5.49	18.9
Café custa R$ 18.9
PapelComo se escreveAs chaves são…Para quêAula
Lista (sequência){"pão", "leite", "café"}1, 2, 3… (o Lua numera sozinho, a partir do 1)Coisas em ordem: compras, notas, filaTabelas como Listas
Dicionário{pao = 0.75, leite = 5.49}Nomes escolhidos por vocêProcurar pelo nome: preço de cada produto, telefone de cada amigoTabelas como Dicionários

Repare que o dicionário e o objeto se escrevem igual. A diferença está no uso: no dicionário, todas as chaves são "do mesmo tipo" (todas são produtos); no objeto, cada chave é uma característica diferente da mesma coisa. Para o Lua, tanto faz: é tudo tabela. Duas coisas do resultado:

  • #compras deu 3: o # conta os itens de uma lista (veja O Operador de Tamanho).
  • 18.90 apareceu como 18.9: o Lua guarda o número, não o jeito que você o escreveu, e o zero do fim não muda o número. Para mostrar dinheiro com duas casas, use string.format("%.2f", preco) (veja string.format).

Missão: o programa quer mostrar a ficha do leite, mas a tabela só tem o nome, e por isso termina com um erro. Complete a ficha com preco = 5.49 e estoque = 12 para sair Leite: R$ 5.49 (12 no estoque).

local produto = {nome = "Leite"}
print(produto.nome .. ": R$ " .. produto.preco .. " (" .. produto.estoque .. " no estoque)")

4. O construtor por inteiro

Dentro das chaves do construtor { }, dá para misturar tudo:

local t = {
  "pão",
  "leite",
  nome = "Ana",
  ["meu apelido"] = "Aninha",
  [10] = "dez",
}
print(t[1], t[2], t.nome, t["meu apelido"], t[10])
local u = {1, 2, 3,}
local v = {x = 1; y = 2}
print(#u, v.x, v.y)

$ lua construtor.lua

A vírgula do fim é sua amiga

Tabelas grandes ficam melhores com um item por linha, como a t acima. Deixando uma vírgula depois do último item, para acrescentar um item novo basta escrever uma linha a mais, sem mexer na anterior. Esquecer a vírgula entre dois itens é que dá erro (veja Quando dá errado).

5. Mudando e apagando

Guardar numa gaveta que já tem algo troca o conteúdo. E guardar nil apaga a gaveta:

local ficha = {nome = "Ana", idade = 30}
print(ficha.idade)
ficha.idade = 31
print(ficha.idade)
ficha.cidade = "Recife"
print(ficha.cidade)
ficha.cidade = nil
print(ficha.cidade)

$ lua mudar.lua
30
31
Recife
nil

A tabela mudou sem ser criada de novo: é a mesma ficha, com uma gaveta trocada, uma criada e depois apagada. Não existe um comando "apagar" separado: no Lua, uma chave com valor nil e uma chave que não existe são a mesma coisa.

6. O que pode ser chave

local t = {}
t[1] = "número um"
t["1"] = "texto um"
print(t[1], t["1"])
t[2.0] = "dois"
print(t[2])
t[true] = "sim"
print(t[true])
print(#t)

$ lua chaves.lua
número um	texto um
dois
sim
2
  • 1 e "1" são chaves diferentes: um é número, o outro é texto (veja Conversão). Isso pega muita gente que lê números do teclado com io.read, que devolve texto.
  • 2.0 e 2 são a mesma chave: um float com valor inteiro vira o inteiro na hora de ser chave (veja Números).
  • Até true pode ser chave. Na verdade, qualquer valor pode, inclusive outra tabela ou uma função, com uma exceção: nil (e o número especial 0/0, o "não é um número").
  • O #t deu 2: ele conta só a parte "lista" (as chaves 1, 2…), ignorando "1" e true.

7. A variável guarda a tabela, ou só o caminho até ela?

Com números e textos, b = a faz uma cópia. Com tabelas, não: as duas variáveis passam a apontar para o mesmo armário.

local a = {nome = "Ana"}
local b = a
b.nome = "Bia"
print(a.nome)
print(a == b)
print({} == {})
local c = {nome = "Bia"}
print(b == c)

$ lua referencia.lua
Bia
true
false
false

Mudar b.nome mudou a.nome, porque a e b são o mesmo armário com dois nomes. E o == entre tabelas pergunta "é o mesmo armário?", não "têm o mesmo conteúdo?": dois {} são armários diferentes (dois endereços diferentes), e b e c também, mesmo com o mesmo nome dentro. Isso tem aula própria: Tabelas São Referências.

8. Mostrando o que tem dentro

Como o print(t) só mostra o endereço, para ver o conteúdo de uma lista percorra as posições com um for de 1 até #t:

local compras = {"pão", "leite", "café"}
print(compras)
for i = 1, #compras do
  print(i, compras[i])
end

$ lua mostrar.lua
table: 0x56284d6db6f0
1	pão
2	leite
3	café

Há outros jeitos, cada um com a sua aula: ipairs (percorrer uma lista), table.concat (juntar os itens num texto só) e pairs (percorrer todas as chaves, inclusive as de texto, numa ordem que o Lua escolhe).

Experimente: rode e veja o endereço que o seu editor mostra (vai ser diferente do desta página). Depois acrescente "manteiga" à lista e rode de novo: o for se ajusta sozinho, porque usa #compras.

local compras = {"pão", "leite", "café"}
print(compras)
for i = 1, #compras do
  print(i, compras[i])
end

Formas diferentes de fazer a mesma coisa

A mesma ficha, de três jeitos. Todos criam uma tabela igual:

-- tudo no construtor (o mais comum)
local f1 = {nome = "Ana", idade = 30}

-- vazia, campo por campo, com o ponto
local f2 = {}
f2.nome = "Ana"
f2.idade = 30

-- vazia, com colchetes
local f3 = {}
f3["nome"] = "Ana"
f3["idade"] = 30

"Tentativa de fazer conta com um valor nil."

O nil veio do campo (field) quantidade de uma tabela: a gaveta que ninguém criou.

O rastro: linha 2 do programa principal (main chunk), chamado pelo próprio lua ([C]: in ?).

Como consertar: crie o campo (quantidade = 2 no construtor) ou confira o nome. A mesma coisa acontece com letra maiúscula: produto.Nome é outra gaveta, e devolve nil (no lab, print(produto.Nome) mostrou nil e print(produto.nome) mostrou Café).

Pediu o campo de um campo que não existe 
local ficha = {nome = "Ana"}
print(ficha.endereco.rua)

$ lua indexar_nil.lua
lua: indexar_nil.lua:2: attempt to index a nil value (field 'endereco')
stack traceback:
	indexar_nil.lua:2: in main chunk
	[C]: in ?

"Tentativa de indexar um valor nil (o campo endereco)." Indexar é abrir uma gaveta ([ ] ou .). ficha.endereco é nil, e não dá para abrir a gaveta rua de um nil: ele não é uma tabela. O mesmo erro aparece com uma variável que nunca recebeu tabela: local t e depois t.nome dá attempt to index a nil value (local 't'). Como consertar: crie a tabela antes (ficha.endereco = {rua = "…"}), ou confira antes de abrir: if ficha.endereco then … end.

A chave era nil 
local t = {}
local chave
t[chave] = "algo"

$ lua chave_nil.lua
lua: chave_nil.lua:3: table index is nil
stack traceback:
	chave_nil.lua:3: in main chunk
	[C]: in ?

"O índice da tabela é nil." A variável chave foi declarada sem valor, então vale nil, e nil não pode ser etiqueta de gaveta. Ler t[nil] não dá erro (devolve nil); guardar dá. Acontece muito quando a chave vem de uma variável com o nome digitado errado. Como consertar: dê um valor à variável da chave.

Tentou juntar a tabela com um texto 
local compras = {"pão", "leite"}
print("Lista: " .. compras)

$ lua concat_tab.lua
lua: concat_tab.lua:2: attempt to concatenate a table value (local 'compras')
stack traceback:
	concat_tab.lua:2: in main chunk
	[C]: in ?

"Tentativa de concatenar (juntar) um valor do tipo tabela (a variável local compras)." O .. só junta textos e números (veja Juntando Textos). Como consertar: junte os itens antes, com table.concat(compras, ", ") (aula table.concat), ou junte um item: "Lista: " .. compras[1].

Esqueceu a vírgula entre dois itens 
local compras = {"pão" "leite"}

$ lua sem_virgula.lua
lua: sem_virgula.lua:1: '}' expected near '"leite"'

"Era esperado } perto de "leite"." Depois de "pão", o Lua esperava uma vírgula (mais um item) ou o } (fim da tabela), e achou outro texto. É um erro de sintaxe: o programa não roda e não há traceback. Como consertar: {"pão", "leite"}.

Usou o ponto com um número 
local compras = {"pão", "leite"}
print(compras.1)

$ lua ponto_numero.lua
lua: ponto_numero.lua:2: ')' expected near '.1'

O atalho do ponto só vale para chaves que são nomes. .1 o Lua lê como o número 0.1 escrito sem o zero, e não entende o que um número está fazendo ali. Como consertar: posições de lista sempre com colchetes: compras[1].

Resumo

  • A tabela é a única estrutura de dados do Lua: um conjunto de pares chave → valor, como gavetas com etiquetas. Ela faz o papel de lista, de dicionário e de objeto.
  • {} cria uma tabela. t[chave] = valor guarda; t[chave] lê. Para chaves que são nomes, t.nome é o mesmo que t["nome"].
  • Chave que não existe vale nil. Guardar nil apaga o campo. A chave não pode ser nil.
  • No construtor: valores soltos viram a lista (1, 2, 3…), nome = valor vira campo, [qualquer] = valor aceita qualquer chave.
  • print(t) mostra table: 0x…, o endereço da tabela na memória, que muda a cada execução. Para ver o conteúdo, leia campo por campo ou percorra com um laço.
  • Duas variáveis podem apontar para a mesma tabela; == compara se é a mesma, não se o conteúdo é igual.
