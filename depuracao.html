Lua Depurando um Programa

Todo programador escreve programas com defeito. Todo mesmo: o que muda com a experiência é a rapidez para achar o defeito. Um defeito num programa se chama bug ("inseto", em inglês), e o trabalho de achá-lo e tirá-lo se chama depurar (em inglês, debug). Esta aula não apresenta funções novas: ela ensina um jeito de trabalhar, com as ferramentas que você já tem no seu computador (o lua, o luac, o print, o assert e a biblioteca debug).

Você vai aprender
  • Os dois tipos de defeito: o que dá erro e o que dá resultado errado.
  • Como ler a mensagem de erro: arquivo, linha, o que aconteceu, e o rastro.
  • O print de depuração, e como usar type e %q para ver o que uma variável tem de verdade.
  • O assert para o defeito aparecer cedo, perto da causa.
  • debug.traceback para saber quem chamou, luac -p para conferir a sintaxe e lua -i para olhar o programa por dentro.
  • Diminuir o problema até ele ficar óbvio, e um roteiro para seguir sempre.

Os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), com lua arquivo.lua.

A ideia: o detetive e as pistas

Quando o bolo da Ana sai solado, ela não joga a receita fora nem começa outra do zero. Ela vira detetive: "o forno estava quente? Pus o fermento? Quanto de farinha?". Ela procura pistas, levanta uma suspeita, faz um teste (outro bolo, mudando só uma coisa) e vê se a suspeita se confirma.

Depurar é igual. As pistas são a mensagem de erro e o que o programa mostra. A suspeita é "acho que a variável total está errada". O teste é um print no lugar certo, ou um programa menor. E a regra de ouro do detetive vale aqui: mude uma coisa de cada vez e rode de novo.

1. Primeira pista: ler a mensagem de erro

A Ana escreveu um programa que calcula a média da turma:

local notas = { 7, 8.5, 10, 6 }

local function media(lista)
  local total = 0
  for i = 1, #lista do
    total = total + lista[i]
  end
  return totl / #lista
end

print("Média da turma: " .. media(notas))

$ lua media1.lua
lua: media1.lua:8: attempt to perform arithmetic on a nil value (global 'totl')
stack traceback:
	media1.lua:8: in local 'media'
	media1.lua:11: in main chunk
	[C]: in ?

Muita gente iniciante olha a mensagem em inglês, se assusta e vai direto para o código. Não faça isso: a mensagem é a melhor pista que você vai ter. Leia pedaço por pedaço:

lua:
Quem está falando: o programa lua.
media1.lua:8:
Onde: no arquivo media1.lua, linha 8. Abra o arquivo nessa linha antes de qualquer coisa.
attempt to perform arithmetic on a nil value
O quê: "tentativa de fazer conta com um valor nil". Alguma coisa da linha 8 que entrou numa conta não tinha valor.
(global 'totl')
Quem: a variável global totl. Global? A Ana nunca criou uma global com esse nome... Exato: ela digitou totl em vez de total. Para o Lua, um nome que não é local é uma global, e uma global que ninguém criou vale nil (veja local × Global).
stack traceback:
O caminho: a linha 8 está dentro da função media, que foi chamada na linha 11 do programa principal. Útil quando a mesma função é chamada de vários lugares.

Quatro informações em duas linhas: onde, o quê, quem e por qual caminho. O conserto é trocar totl por total. A aula Lendo uma Mensagem de Erro explica cada parte com mais calma, e a tabela de mensagens comuns traduz as mais frequentes.

A linha da mensagem nem sempre é a do defeito

A mensagem diz onde o programa percebeu o problema, que às vezes é longe de onde ele nasceu. Se a linha indicada parece certa, pergunte: "de onde veio esse valor?" e suba pelo código (ou pelo rastro).

2. O resultado errado: o print de depuração

A Ana consertou o totl, mas fez outra mudança sem perceber, e agora o programa roda sem erro... com a resposta errada:

local notas = { 7, 8.5, 10, 6 }

local function media(lista)
  local total = 0
  for i = 1, #lista - 1 do
    total = total + lista[i]
  end
  return total / #lista
end

print("Média da turma: " .. media(notas))

$ lua media2.lua
Média da turma: 6.375

As notas são 7, 8,5, 10 e 6. A média não pode ser 6,375: é menor que quase todas as notas! Sem mensagem de erro, a pista agora é você que produz: um print em cada ponto onde quer ver os valores. Escreva uma marca (como [depurar]) para lembrar de tirar depois:

local notas = { 7, 8.5, 10, 6 }

local function media(lista)
  local total = 0
  for i = 1, #lista - 1 do
    total = total + lista[i]
    print("[depurar] i =", i, "nota =", lista[i], "total =", total)
  end
  print("[depurar] dividindo", total, "por", #lista)
  return total / #lista
end

print("Média da turma: " .. media(notas))

$ lua media3.lua
[depurar] i =	1	nota =	7	total =	7
[depurar] i =	2	nota =	8.5	total =	15.5
[depurar] i =	3	nota =	10	total =	25.5
[depurar] dividindo	25.5	por	4
Média da turma: 6.375

Pronto, o mistério se resolve sozinho: o laço só deu 3 voltas, e a nota 6 (a quarta) nunca entrou no total. Mas a divisão foi por 4. O culpado é o #lista - 1 do for. Sem o print, você ficaria lendo o código e "vendo" o que queria ver; com o print, o programa conta o que fez.

Missão: rode o programa com os print de depuração, ache o defeito pelo que eles mostram e conserte. Depois de consertar, apague as linhas [depurar]. A média certa das notas 7, 8,5, 10 e 6 é 7,875.

local notas = { 7, 8.5, 10, 6 }

local function media(lista)
  local total = 0
  for i = 1, #lista - 1 do
    total = total + lista[i]
    print("[depurar] i =", i, "nota =", lista[i], "total =", total)
  end
  print("[depurar] dividindo", total, "por", #lista)
  return total / #lista
end

print("Média da turma: " .. media(notas))

local notas = { 7, 8.5, 10, 6 }

local function media(lista)
  local total = 0
  for i = 1, #lista do
    total = total + lista[i]
  end
  return total / #lista
end

print("Média da turma: " .. media(notas))

O que pôr no print

  • O nome junto com o valor ("total =", total): com cinco números soltos na tela, você não sabe qual é qual.
  • Dentro dos laços, para ver cada volta, e logo antes da linha suspeita.
  • Na entrada de uma função, os parâmetros que ela recebeu: metade dos defeitos é "a função recebeu outra coisa".

3. O que a variável tem de verdade: type e %q

Às vezes o print mostra um valor que parece certo. A Ana lê as notas de um arquivo, no formato nome;nota:

local linha = "Bia;8,5"
local nome, nota = linha:match("([^;]+);(.*)")
if tonumber(nota) >= 7 then
  print(nome .. " passou")
end

$ lua texto.lua
lua: texto.lua:3: attempt to compare number with nil
stack traceback:
	texto.lua:3: in main chunk
	[C]: in ?

"Tentativa de comparar número com nil". O único número da linha 3 é o 7, então o nil é o tonumber(nota) (o Lua cita os dois tipos na ordem em que comparou por dentro: ele faz o a >= 7 como 7 <= a, por isso o número vem primeiro). Por que o tonumber devolveu nil? Um print com type e com o formato %q (que mostra o texto entre aspas, exatamente como ele é; veja string.format):

local linha = "Bia;8,5"
local nome, nota = linha:match("([^;]+);(.*)")
print("[depurar] nota =", nota, type(nota), tonumber(nota))
print(string.format("[depurar] %q", nota))

$ lua texto2.lua
[depurar] nota =	8,5	string	nil
[depurar] "8,5"

A nota é o texto "8,5", com vírgula. O Lua só entende número com ponto (8.5), então o tonumber desiste e devolve nil (veja Conversão). O %q também revela espaços escondidos e quebras de linha no fim do texto, que um print normal esconde.

Três perguntas para uma variável suspeita

1) Qual o tipo? print(type(x)) · 2) Qual o valor exato? print(string.format("%q", x)) para textos · 3) Ela existe? Se o type diz nil, procure onde ela deveria ter recebido valor (nome digitado errado? função sem return?).

4. Fazer o defeito aparecer cedo: assert

Um defeito é mais fácil de achar quando o programa para perto da causa. Olhe esta média de uma lista vazia:

local function media(lista)
  local total = 0
  for _, n in ipairs(lista) do total = total + n end
  return total / #lista
end

print(media({ 7, 9 }))
print(media({}))

$ lua semassert.lua
8.0
-nan

Nenhum erro: a lista vazia deu 0 / 0, que é nan ("não é um número"; o sinal de menos na frente é coisa do sistema). Esse -nan pode viajar pelo programa inteiro e só aparecer muito depois, num boletim, sem pista nenhuma de onde veio. Com assert, a função confere o que recebeu e para na hora, com uma mensagem sua:

local function media(lista)
  assert(type(lista) == "table", "media: esperava uma lista de notas")
  assert(#lista > 0, "media: a lista de notas está vazia")
  local total = 0
  for _, n in ipairs(lista) do total = total + n end
  return total / #lista
end

print(media({ 7, 9 }))
print(media({}))

$ lua comassert.lua
8.0
lua: comassert.lua:3: media: a lista de notas está vazia
stack traceback:
	[C]: in global 'assert'
	comassert.lua:3: in local 'media'
	comassert.lua:10: in main chunk
	[C]: in ?

Agora a mensagem diz, em português, o que estava errado, e o rastro diz quem mandou a lista vazia (a linha 10). Diferente do print de depuração, os assert podem ficar no programa: eles são a "trava de segurança" de cada função.

5. Quem chamou com o valor errado? debug.traceback

A função baixar do estoque é chamada de vários lugares. Alguém está mandando uma quantidade negativa. Quem? Um debug.traceback (aula A Biblioteca debug) no ponto suspeito mostra o caminho inteiro, sem parar o programa:

local estoque = { pao = 30 }

local function baixar(produto, quantidade)
  if quantidade < 0 then
    print(debug.traceback("quantidade negativa: " .. quantidade))
  end
  estoque[produto] = estoque[produto] - quantidade
end

local function devolucao(produto, quantidade)
  baixar(produto, -quantidade)
end

baixar("pao", 5)
devolucao("pao", 2)
print("Pão:", estoque.pao)

$ lua quem_chama.lua
quantidade negativa: -2
stack traceback:
	quem_chama.lua:5: in upvalue 'baixar'
	quem_chama.lua:11: in local 'devolucao'
	quem_chama.lua:15: in main chunk
	[C]: in ?
Pão:	27

O rastro aponta a linha 11, dentro de devolucao: ela chama baixar com o sinal trocado. (Neste caso, de propósito: devolver 2 pães é "baixar −2". Mas agora a Ana sabe de onde vem o número, e pode decidir se está certo.)

6. Conferir a sintaxe sem rodar: luac -p

O luac (o compilador do Lua, que vem junto com ele) tem a opção -p ("parse only", só analisar): ele lê o arquivo, procura erros de sintaxe e não roda nada. É útil num programa que apaga arquivos ou que demora para chegar à parte nova:

local notas = { 7, 8.5, 10, 6 }
for i = 1, #notas do
  if notas[i] >= 7 then
    print(i, "aprovada")
  else
    print(i, "reprovada")
end

$ luac -p sintaxe.lua
luac: sintaxe.lua:8: 'end' expected (to close 'for' at line 2) near <eof>
$ luac -p media2.lua
$ echo $?
0

O arquivo tem 7 linhas, e o erro diz linha 8, perto de <eof> (end of file, "fim do arquivo"): o Lua chegou ao fim procurando um end. O end da linha 7 fechou o if, e o for da linha 2 ficou aberto. Com erro de sintaxe, a linha da mensagem quase sempre é depois do defeito: o Lua só percebe que faltou alguma coisa quando já passou do lugar. Quando o arquivo está certo, o luac -p não diz nada (e o código de saída é 0). A indentação certinha (aula Estilo de Código) faz esse tipo de erro saltar aos olhos.

7. Olhar por dentro depois de rodar: lua -i

lua -i arquivo.lua roda o arquivo e, em vez de sair, abre o modo interativo. Dá para perguntar o valor das variáveis globais do jeito que o programa as deixou:

alunos = { "Ana", "Bia", "Caio" }
local notas = { 8, 6, 9 }
total = 0
for i = 1, #notas do total = total + notas[i] end

$ lua -i turma.lua
Lua 5.5.0  Copyright (C) 1994-2025 Lua.org, PUC-Rio
> alunos[2]
Bia
> total
23
> notas
nil
> #alunos
3
> os.exit()

As globais alunos e total estão lá. A notas, que é local, não: ela só existia dentro do arquivo. Por isso essa técnica serve para experimentos rápidos; num programa com local em tudo (como deve ser), o print e o assert continuam sendo as ferramentas principais.

8. Diminuir o problema

Quando o programa é grande e você não faz ideia de onde está o defeito, corte:

  1. Copie o programa para um arquivo de teste (nunca corte o original).
  2. Apague ou comente metade (veja Comentários: --[[ … ]] desliga um trecho inteiro).
  3. Rode. O defeito continua? Ele está na metade que sobrou. Sumiu? Está na metade que você tirou.
  4. Repita com a metade culpada até sobrarem poucas linhas.
  5. Troque as entradas complicadas por valores fixos e pequenos (local notas = { 7, 9 } em vez de ler um arquivo de 500 linhas).

Um programa de 5 linhas que mostra o defeito quase sempre deixa a causa óbvia. E, se não deixar, é exatamente o que você deve mostrar a alguém quando for pedir ajuda.

Explicar em voz alta

Uma técnica antiga e que funciona: explique o programa, linha por linha, em voz alta, para alguém (ou para um patinho de borracha na mesa, o "método do patinho"). No meio da explicação, você mesmo percebe "...e aqui ele soma até #lista - 1... opa". Explicar obriga a ler o que está escrito, e não o que você acha que escreveu.

Formas diferentes de fazer a mesma coisa

O print de depuração tem um problema: ele se mistura com a saída de verdade, e é fácil esquecer um no programa. Uma forma mais organizada é uma função log com um interruptor, que escreve no canal de erros (io.stderr) em vez da saída normal:

local DEPURAR = true

local function log(...)
  if DEPURAR then
    io.stderr:write("[depurar] ", table.concat({ ... }, " "), "\n")
  end
end

local estoque = { pao = 30, leite = 12 }
local function vender(produto, quantidade)
  log("vender", produto, quantidade)
  estoque[produto] = estoque[produto] - quantidade
  log("sobrou", estoque[produto])
end

vender("pao", 6)
vender("leite", 2)
print("Pão:", estoque.pao, "Leite:", estoque.leite)

$ lua log.lua
[depurar] vender pao 6
[depurar] sobrou 24
[depurar] vender leite 2
[depurar] sobrou 10
Pão:	24	Leite:	10
$ lua log.lua 2>/dev/null
Pão:	24	Leite:	10

No terminal aparece tudo. Com 2>/dev/null (o terminal joga fora o canal de erros), sobra só a saída de verdade. E para desligar todos os log de uma vez, basta local DEPURAR = false.

Quando dá errado (os defeitos mais comuns)

Função sem return 
local function media(lista)
  local total = 0
  for _, n in ipairs(lista) do total = total + n end
  local resultado = total / #lista
end

local m = media({ 7, 9 })
print("Média: " .. m)

$ lua semreturn.lua
lua: semreturn.lua:8: attempt to concatenate a nil value (local 'm')
stack traceback:
	semreturn.lua:8: in main chunk
	[C]: in ?

"Tentativa de juntar (..) um valor nil (a local m)". O erro aparece na linha 8, mas o defeito está na função: ela calcula o resultado e não devolve. Função sem return devolve nada, e a variável que recebe fica nil (veja return). Como consertar: return total / #lista. É o exemplo perfeito da dica da seção 1: a linha da mensagem é onde o problema foi percebido.

Número com vírgula vindo de um texto

O caso da seção 3: tonumber("8,5") dá nil, e o erro aparece só na conta ou na comparação seguinte (attempt to compare number with nil, attempt to perform arithmetic on a nil value). Como consertar: troque a vírgula por ponto antes de converter, com parênteses em volta do gsub: tonumber((nota:gsub(",", "."))). Sem os parênteses extras, o gsub manda dois valores para o tonumber (o texto e o número de trocas), e o segundo vira a "base" do número:

$ lua compras_gsub.lua
lua: compras_gsub.lua:1: bad argument #2 to 'tonumber' (base out of range)
stack traceback:
	[C]: in global 'tonumber'
	compras_gsub.lua:1: in main chunk
	[C]: in ?

(O compras_gsub.lua tem uma linha só: print(tonumber(("4,50"):gsub(",", "."))).)

Consertar sem entender

Não é uma mensagem do Lua, mas é o erro mais caro: mudar coisas ao acaso até "funcionar". O programa até pode passar a mostrar o número certo para aquelas notas, e falhar com outras. Antes de mudar uma linha, você deve conseguir dizer por que ela está errada (como "o laço para uma volta antes"). Se não consegue, volte para os print.

Esqueceu os print de depuração no programa

O programa funciona, mas continua mostrando [depurar] i = 1 … para quem usa. Por isso a marca [depurar]: procure por ela antes de dar o programa por pronto (ou use a função log com interruptor).

Roteiro de depuração

  1. Reproduza: rode de novo e confirme que o defeito acontece sempre, com as mesmas entradas.
  2. Leia a mensagem inteira (se houver): arquivo, linha, o quê, quem, o rastro.
  3. Vá até a linha e pergunte de onde vem cada valor que ela usa.
  4. Levante uma suspeita e teste com um print (com o nome, o type, o %q).
  5. Diminua o programa se a suspeita não aparecer.
  6. Conserte uma coisa só, sabendo por que ela estava errada, e rode de novo.
  7. Limpe os print de depuração, e pense se um assert teria pegado o defeito antes. Se sim, deixe o assert.

Missão final: dois defeitos na lista de compras

(Dicas: o primeiro tem a ver com a vírgula dos preços, e a seção "Quando dá errado" mostra o jeito certo; o segundo, a mensagem conta direitinho.) O total certo é R$ 23.40.

local compras = { "pão;4,50", "leite;6,90", "café;12,00" }
local total = 0
for _, linha in ipairs(compras) do
  local item, preco = linha:match("([^;]+);(.*)")

Resumo

  • Depurar é trabalho de detetive: pistas, suspeita, teste, uma mudança de cada vez.
  • A mensagem de erro diz onde (arquivo e linha), o quê, quem (a variável) e o caminho (o rastro). Leia inteira antes de mexer no código.
  • Sem mensagem, faça o programa contar o que faz: print com o nome, type e %q.
  • assert faz o defeito aparecer cedo, perto da causa, e pode ficar no programa.
  • debug.traceback mostra quem chamou; luac -p confere a sintaxe; lua -i mostra as globais depois de rodar.
  • Sem pista nenhuma? Copie o programa e corte pela metade até o defeito ficar óbvio.
