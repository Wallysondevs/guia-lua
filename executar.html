Lua Rodando um Programa (.lua)

Um programa Lua é um arquivo de texto, com o nome terminado em .lua, que o interpretador lua lê e executa. Nesta aula você vai fazer o ciclo completo pela primeira vez: criar uma pasta para os seus programas, escrever um arquivo com o editor nano, rodá-lo com lua ola.lua e entender o que o terminal responde, inclusive quando ele não acha o arquivo. Você também vai descobrir um detalhe importante do Lua: ele confere o arquivo inteiro antes de rodar a primeira linha. No fim, vai transformar o arquivo num comando que roda sozinho, com a linha #!/usr/bin/env lua.

Você vai aprender
  • A criar uma pasta para os seus programas e um arquivo .lua com o nano.
  • A rodar o programa com lua arquivo.lua, e o que cada parte do comando quer dizer.
  • O que é a pasta atual e como chegar a um arquivo que está em outra pasta (caminhos).
  • Que o Lua primeiro confere a escrita do arquivo todo e depois executa de cima para baixo, parando no primeiro erro.
  • O que é o código de saída (echo $?).
  • A rodar o arquivo como um comando, com #!/usr/bin/env lua e chmod +x.
  • Outras formas de rodar: lua -e, lua -, lua -i e o editor do guia.

Tudo nesta aula foi rodado de verdade com o Lua 5.5 no computador da Ana (Ubuntu 26.04). Se você ainda não tem o Lua, veja Instalar o Lua, ou faça só as caixas Experimente, que rodam no navegador.

A ideia: a receita e o cozinheiro

Pense numa receita escrita num caderno. Ela fica guardada na gaveta, e você pode ler, corrigir e copiar quantas vezes quiser; mas a receita não cozinha sozinha. Quando chega a hora, alguém abre o caderno na página certa e segue os passos, um por um, de cima para baixo.

No Lua é igual:

Na cozinhaNo computador
A receita escritaO arquivo ola.lua, com o seu programa
O caderno guardado na gavetaA pasta onde o arquivo está, por exemplo /home/ana/programas
O cozinheiroO interpretador lua
"Cozinheiro, faça a receita da página tal"O comando lua ola.lua, digitado no terminal

E este cozinheiro tem uma mania: antes de acender o fogão, ele lê a receita inteira, do começo ao fim, para ver se ela está bem escrita. Se achar uma frase sem pé nem cabeça, devolve o caderno sem cozinhar nada. Você vai ver isso acontecer na seção 5.

1. Uma pasta para os seus programas

Antes de escrever, crie uma pasta só para os programas do curso. Assim eles não se misturam com as fotos e os documentos. Abra o terminal (Ctrl+Alt+T):

$ mkdir programas                                  « cria a pasta "programas"
$ cd programas                                     « entra nela
$ pwd                                              « "onde estou?"
/home/ana/programas
$ ls                                               « o que tem aqui? (nada, ainda)
mkdir programas
make directory, "crie uma pasta" chamada programas. Ela é criada dentro da pasta onde você está; o terminal sempre começa na sua pasta pessoal, /home/ana.
cd programas
change directory, "mude de pasta": entre na pasta programas. Repare que o prompt mudou de ~ para ~/programas (o ~ é o apelido da sua pasta pessoal).
pwd
print working directory, "mostre a pasta atual".
ls
list, "liste o que tem aqui". A pasta é nova, então não aparece nada.

A pasta atual é como o caderno que está aberto em cima da mesa: quando você fala só o nome de um arquivo, o terminal (e o Lua) procuram nessa pasta. Lembre-se disso; é a causa do erro mais comum desta aula.

2. Escrevendo o arquivo com o nano

O nano é um editor de texto que roda dentro do próprio terminal. Ele já vem no Ubuntu. Para criar (ou abrir) o arquivo ola.lua:

$ nano ola.lua

O terminal vira o editor. Digite as duas linhas do programa, exatamente assim (com os parênteses e as aspas):

print("Olá, mundo!")
print("Meu primeiro programa em Lua.")

A tela do nano fica assim (a tela inteira tem mais linhas em branco no meio):

As duas linhas de baixo são a "cola" dos atalhos. O ^ quer dizer Ctrl: ^O é Ctrl+O. Você só precisa de dois:

  1. Gravar: aperte Ctrl+O. Embaixo aparece o nome do arquivo; aperte Enter para confirmar. O nano responde com quantas linhas gravou.
  2. Sair: aperte Ctrl+X. Você volta para o terminal. (Se você tentar sair sem gravar, o nano pergunta se quer salvar as mudanças: responda S para sim ou N para não.)

De volta ao terminal, confira que o arquivo existe e o que tem dentro dele. O cat mostra o conteúdo de um arquivo:

$ ls
ola.lua
$ cat ola.lua
print("Olá, mundo!")
print("Meu primeiro programa em Lua.")
Por que .lua?

A extensão .lua é a etiqueta que diz "isto é um programa Lua". Os editores usam a etiqueta para colorir o código, as outras pessoas sabem o que é o arquivo só de olhar o nome, e o require procura os módulos que você vai criar mais tarde pelo nome com .lua. Para rodar com lua arquivo, a extensão nem é obrigatória (o Lua lê qualquer arquivo de texto), mas use sempre: é o costume, e evita confusão.

3. Rodando: lua ola.lua

Agora, o momento esperado. Ainda dentro da pasta programas:

$ lua ola.lua
Olá, mundo!
Meu primeiro programa em Lua.
lua
O interpretador: o "cozinheiro".
ola.lua
O arquivo que ele deve ler e executar: a "receita". Como foi escrito só o nome, ele é procurado na pasta atual.

O Lua leu o arquivo, executou a primeira linha e mostrou Olá, mundo!; executou a segunda e mostrou Meu primeiro programa em Lua.; chegou ao fim do arquivo e terminou, devolvendo o prompt ($) para você. As aspas e os parênteses não aparecem: eles são a "embalagem" do texto, só para o Lua saber onde a frase começa e termina (aula print()).

O arquivo continua lá, guardado. Rode quantas vezes quiser; mude o texto no nano e rode de novo para ver a diferença. Esse é o ciclo de todo programador: editar → gravar → rodar → olhar o resultado.

No editor do guia é a mesma coisa

As caixas Experimente fazem esse ciclo para você: o código da caixa vira um arquivo chamado main.lua, e o botão Rodar faz o equivalente a lua main.lua, com o Lua 5.5 de verdade, no navegador. A aula O Editor do Guia mostra tudo o que ele faz.

Missão: acrescente uma terceira linha ao programa, com um print que mostre Meu nome é e o seu nome (por exemplo, Meu nome é Ana.). Rode e confira as três linhas.

print("Olá, mundo!")
print("Meu primeiro programa em Lua.")

print("Olá, mundo!")
print("Meu primeiro programa em Lua.")
print("Meu nome é Ana.")

4. A pasta atual e os caminhos

Agora a Ana voltou para a pasta pessoal (o cd sozinho leva para lá) e tentou rodar o mesmo programa:

$ cd
$ pwd

$ lua ola.lua
lua: cannot open ola.lua: No such file or directory
lua:
Quem está reclamando: o próprio lua, antes mesmo de começar o programa.
cannot open ola.lua
"Não consigo abrir ola.lua". O nome que aparece é exatamente o que você digitou; ele foi procurado na pasta atual, /home/ana.
No such file or directory
"Arquivo ou pasta inexistente". É a explicação que o próprio Linux dá.

O arquivo não sumiu: ele está em /home/ana/programas/ola.lua, mas o Lua procurou um ola.lua em /home/ana. Há dois jeitos de resolver. O primeiro é entrar na pasta do arquivo (cd programas) e rodar como antes. O segundo é dizer o caminho até o arquivo:

$ lua programas/ola.lua                           « caminho a partir da pasta atual
Olá, mundo!
Meu primeiro programa em Lua.
$ lua ~/programas/ola.lua                         « caminho a partir da pasta pessoal
Olá, mundo!
Meu primeiro programa em Lua.

Digite lua ~/pro e aperte Tab: o terminal completa o nome da pasta (~/programas/). Aperte Tab de novo depois de o e ele completa ola.lua. Se o Tab não completar, é sinal de que o arquivo não está onde você pensa. Usar o Tab evita a maioria dos erros de digitação em nomes de arquivo.

5. Primeiro ele confere, depois executa de cima para baixo

O lua trabalha em duas etapas. Primeiro ele lê o arquivo inteiro e confere se a escrita está certa (a sintaxe, a "gramática" da linguagem), traduzindo tudo para bytecode (a tradução que você conheceu na Introdução). Só se estiver tudo certo ele começa a executar, uma linha de cada vez, de cima para baixo. Dois erros da Ana mostram a diferença.

Um erro durante a execução

A Ana escreveu a lista de compras e esqueceu as aspas no feijão. (O .., dois pontos seguidos, junta dois textos num só: aula Juntando Textos.)

print("Lista de compras da Ana")
print("1. arroz")
print("2. " .. feijao)
print("3. café")

$ lua compras.lua
Lista de compras da Ana                            « linha 1: rodou
1. arroz                                           « linha 2: rodou
lua: compras.lua:3: attempt to concatenate a nil value (global 'feijao')
stack traceback:
	compras.lua:3: in main chunk
	[C]: in ?

A escrita do arquivo estava certa (para o Lua, feijao sem aspas é um nome válido), então ele começou a executar. As duas primeiras linhas rodaram, e as frases apareceram. Na terceira, o Lua encontrou um problema e parou ali: a quarta linha (o café) nunca chegou a ser executada. A mensagem, pedaço por pedaço:

lua: compras.lua:3:
No arquivo compras.lua, linha 3.
attempt to concatenate a nil value
"Tentativa de concatenar (juntar) um valor nil". O .. tentou juntar o texto "2. " com uma coisa que vale nil, o "nada" do Lua.
(global 'feijao')
A coisa que vale nil: o nome feijao. Sem aspas, o Lua acha que feijao é o nome de uma variável, e nenhuma variável com esse nome foi criada; um nome que ninguém criou vale nil. Com aspas ("feijão"), seria um texto.
stack traceback: … compras.lua:3: in main chunk
O "rastro" do erro: aconteceu na linha 3, no corpo principal do arquivo (o main chunk, e não dentro de uma função, que você vai aprender depois). O [C]: in ? do fim é o próprio interpretador.

Missão: rode e veja o programa parar na linha 3. Conserte a linha (o feijão é um texto: precisa de aspas) e rode de novo, até aparecerem os três itens.

print("Lista de compras da Ana")
print("1. arroz")
print("2. " .. feijao)
print("3. café")

print("Lista de compras da Ana")
print("1. arroz")
print("2. " .. "feijão")
print("3. café")

Um erro de escrita: nada roda

Agora a Ana esqueceu de fechar um parêntese na linha 3:

print("Lista de compras da Ana")

print("2. feijão"
print("3. café")

$ lua compras2.lua
lua: compras2.lua:4: ')' expected (to close '(' at line 3) near 'print'

Repare: nenhuma linha apareceu, nem a primeira, que estava perfeita. Desta vez o erro é de sintaxe, e o Lua o encontrou na etapa de conferir, antes de executar qualquer coisa. Também não tem stack traceback: o programa nem começou. A mensagem:

compras2.lua:4:
Onde o Lua percebeu o problema: na linha 4. Mas o erro de verdade está na linha 3; continue lendo.
')' expected
"Era esperado um )".
(to close '(' at line 3)
"Para fechar o ( da linha 3". Esta é a pista boa: o parêntese que ficou aberto está na linha 3.
near 'print'
"Perto de print": o Lua ainda esperava o ) quando deu de cara com o print da linha 4.

Dica de leitura: numa mensagem de erro do Lua, olhe primeiro o arquivo e a linha (compras.lua:3:) e depois a explicação. A aula Lendo uma Mensagem de Erro ensina a ler mensagens maiores.

O código de saída

Todo programa, quando termina, devolve ao terminal um número, o código de saída: 0 quer dizer "terminei bem"; qualquer outro número quer dizer "deu problema". O terminal guarda esse número em $?, e o echo mostra:

$ lua ola.lua
Olá, mundo!
Meu primeiro programa em Lua.
$ echo $?
0                                                  « terminou bem
$ lua compras.lua
Lista de compras da Ana
1. arroz
lua: compras.lua:3: attempt to concatenate a nil value (global 'feijao')
stack traceback:
	compras.lua:3: in main chunk
	[C]: in ?
$ echo $?
1                                                  « terminou com erro

O erro de sintaxe e o "cannot open" também dão 1. Você não precisa disso no dia a dia (a mensagem de erro já é bem clara), mas outros programas usam o código de saída para saber se o seu deu certo. O editor do guia também mostra esse número embaixo da saída de cada execução.

6. Rodando o arquivo como um comando

Os programas do sistema, como o ls, são rodados só pelo nome, sem lua na frente. Dá para fazer o mesmo com os seus. A Ana tentou:

$ ./ola.lua
bash: ./ola.lua: Permissão negada

O ./ quer dizer "o arquivo desta pasta" (o ponto é a pasta atual). O terminal achou o arquivo, mas recusou: no Linux, um arquivo só pode ser executado se tiver a permissão de execução, e um arquivo novo não tem. O chmod +x ("mude as permissões: acrescente execução") dá essa permissão:

$ chmod +x ola.lua
$ ls -l ola.lua
-rwxrwxr-x 1 ana ana 61 Oct 18 16:45 ola.lua          « os x quer dizer "pode executar"
$ ./ola.lua
./ola.lua: linha 1: erro de sintaxe próximo ao token inesperado `"Olá, mundo!"'
./ola.lua: linha 1: `print("Olá, mundo!")'

Agora ele rodou, mas deu um erro estranho, em português. Repare que a mensagem não começa com lua:: quem reclamou foi o bash, o programa do terminal. Sem saber quem deveria ler o arquivo, o terminal tentou executá-lo como se fosse uma lista de comandos do próprio terminal, e print("Olá, mundo!") não faz sentido para ele. Falta dizer, dentro do arquivo, quem é o cozinheiro.

A linha #!/usr/bin/env lua

Ela vai na primeira linha do arquivo, sozinha:

#!/usr/bin/env lua
print("Olá, mundo!")
print("Meu primeiro programa em Lua.")
#!
Chamado de shebang (lê-se "xibéngue"). Quando um arquivo executável começa com esses dois caracteres, o Linux lê o resto da linha para saber qual programa deve abrir o arquivo.
/usr/bin/env
Um programa do sistema que procura outro programa pelo nome, nas pastas de comandos. Usar o env em vez de escrever /usr/bin/lua direto faz o arquivo funcionar mesmo num computador em que o Lua está em outra pasta (no macOS com Homebrew, ou com o Lua compilado em /usr/local).
lua
O programa que o env deve procurar e chamar.

Com a linha no lugar (a permissão continua lá, porque o arquivo é o mesmo):

$ cat ola.lua
#!/usr/bin/env lua
print("Olá, mundo!")
print("Meu primeiro programa em Lua.")
$ ./ola.lua
Olá, mundo!
Meu primeiro programa em Lua.
$ lua ola.lua                                      « o jeito de sempre continua valendo
Olá, mundo!
Meu primeiro programa em Lua.

E por que o #! não atrapalha quando você roda com lua ola.lua? No Lua, o # não é comentário (o comentário do Lua é --, aula Comentários). É uma exceção feita de propósito: quando a primeira linha do arquivo começa com #, o lua pula essa linha. Em qualquer outra linha, o # no começo é erro:

print("Olá, mundo!")
#!/usr/bin/env lua

$ lua shebang2.lua
lua: shebang2.lua:2: unexpected symbol near '#'

"Símbolo inesperado perto de #", na linha 2. É um erro de sintaxe (repare: nem o Olá, mundo! da linha 1 apareceu). O # no meio do código tem outro trabalho, o de medir o tamanho das coisas (aula O Operador de Tamanho).

Por que o ./?

Sem o ./, o terminal procura o comando só nas pastas de comandos do sistema (como /usr/bin), e não na pasta atual:

$ ola.lua
ola.lua: comando não encontrado

É uma proteção: assim, um arquivo qualquer numa pasta não consegue se passar por um comando do sistema. Para os seus programas, use ./ola.lua (ou lua ola.lua).

7. Outras formas de rodar

lua -e: uma linha, sem arquivo

Para testar uma linha só, sem criar arquivo, use -e (de execute, "execute") e o código entre aspas simples. Dá para usar mais de um -e, e eles rodam em ordem:

$ lua -e 'print("Olá, Ana!")'
Olá, Ana!
$ lua -e 'print(2 + 3)' -e 'print("fim")'
5
fim

As aspas simples por fora protegem o código do terminal (as aspas duplas de dentro são do Lua). Quando dá erro num -e, a mensagem chama o código de (command line), "linha de comando", no lugar do nome do arquivo.

lua -: o programa vem pelo "cano"

Com um - sozinho no lugar do nome do arquivo, o lua lê o programa da entrada: do que outro comando manda para ele pelo | (o "cano", em inglês pipe):

$ echo 'print("veio pelo cano")' | lua -
veio pelo cano

Você quase não vai usar isso, mas vai ver em tutoriais.

lua -i: roda o arquivo e fica no Lua

O -i (de interactive, "interativo") roda o arquivo e, em vez de terminar, abre o modo interativo (>), para você continuar experimentando:

$ lua -i ola.lua
Lua 5.5.0  Copyright (C) 1994-2025 Lua.org, PUC-Rio
Olá, mundo!
Meu primeiro programa em Lua.
> print("Ainda estou no Lua")
Ainda estou no Lua
> os.exit()

(O os.exit() fecha o Lua e volta ao terminal. A aula O Modo Interativo mostra tudo o que dá para fazer lá dentro.)

Criar o arquivo sem abrir o editor

Para um programa de uma linha, dá até para criar o arquivo direto do terminal, com o echo e o > ("mande para o arquivo"):

$ echo 'print("Feito com echo!")' > rapido.lua
$ lua rapido.lua
Feito com echo!

Cuidado: o > apaga o que havia no arquivo antes. Para programas de verdade, use um editor.

./arquivo.lua (com #! e chmod +x)Programas que você vai usar como ferramenta, todo dia, como um comando do sistema

Quando dá errado

Nome do arquivo digitado errado 
$ lua ol.lua
lua: cannot open ol.lua: No such file or directory
$ lua Ola.lua
lua: cannot open Ola.lua: No such file or directory
$ lua ola

O que aconteceu: o mesmo "não consigo abrir" da seção 4, mas agora a pasta está certa e o nome, errado: ol.lua sem o a; Ola.lua com maiúscula (no Linux, Ola.lua e ola.lua são arquivos diferentes); ola sem o .lua (o lua não acrescenta a extensão sozinho). Leia o nome na mensagem: ele mostra exatamente o que o Lua procurou.

Como resolver: confira com ls o nome exato do arquivo e use o Tab para completar.

Arquivo com espaço no nome

A Ana salvou um programa como meu programa.lua, com espaço:

$ lua meu programa.lua
lua: cannot open meu: No such file or directory
$ lua "meu programa.lua"                           « com aspas, funciona
Olá, mundo!
Meu primeiro programa em Lua.

O que aconteceu: no terminal, o espaço separa as partes do comando. O lua entendeu que o arquivo era meu (e que programa.lua era outra coisa, passada para o programa). Repare no nome da mensagem: meu.

Como resolver: ponha o nome entre aspas ou, melhor, não use espaços em nomes de programas. Use o sublinhado: meu_programa.lua.

$ mv "meu programa.lua" meu_programa.lua          « mv renomeia o arquivo
$ lua meu_programa.lua
Olá, mundo!
Meu primeiro programa em Lua.
Permissão negada ao rodar com ./ 
$ ./ola.lua
bash: ./ola.lua: Permissão negada

O que aconteceu: o arquivo não tem permissão de execução. Como resolver: chmod +x ola.lua, uma vez só; ou rode com lua ola.lua, que não precisa dessa permissão.

Erro do bash em português: erro de sintaxe próximo ao token inesperado 
$ ./ola.lua
./ola.lua: linha 1: erro de sintaxe próximo ao token inesperado `"Olá, mundo!"'
./ola.lua: linha 1: `print("Olá, mundo!")'

O que aconteceu: o arquivo foi executado com ./, mas não tem a linha #!/usr/bin/env lua no começo (ou ela não está na primeira linha, ou está com um espaço antes do #!). O terminal tentou ler o Lua como se fossem comandos do terminal. A pista: a mensagem é em português e não começa com lua:, então não veio do Lua.

Como resolver: coloque #!/usr/bin/env lua como primeira linha, sem nada antes, ou rode com lua ola.lua.

Digitei lua ola.lua dentro do > 
$ lua
Lua 5.5.0  Copyright (C) 1994-2025 Lua.org, PUC-Rio
> lua ola.lua
stdin:1: syntax error near 'ola'
> os.exit()

O que aconteceu: o lua ola.lua é um comando do terminal (o $). Dentro do modo interativo (o >), quem lê é o Lua, e para ele lua ola.lua são dois nomes soltos, um do lado do outro, sem sentido: "erro de sintaxe perto de ola". O stdin:1: é o "arquivo" do modo interativo (o que você digita), linha 1.

Como resolver: saia com os.exit() (ou Ctrl+D) e digite o comando no $. (Para rodar um arquivo sem sair do Lua existe o dofile("ola.lua"), assunto da aula load, loadfile e dofile.)

Exercícios

1. Rodar o programa

Complete o comando que roda o programa notas.lua da pasta atual:

$ notas.lua

2. O shebang

Complete a primeira linha que permite rodar um arquivo Lua com ./:

#!/usr/bin/env

3. A permissão

Complete o comando que dá permissão de execução ao arquivo:

$ chmod ola.lua

4. A Ana está em /home/ana e o arquivo está em /home/ana/programas/ola.lua. Ela digitou lua ola.lua e recebeu cannot open ola.lua: No such file or directory. O que ela pode fazer?

5. Um programa de 10 linhas tem um ) faltando na linha 7. O que aparece quando a Ana roda?

6. O que o echo $? mostra logo depois de um programa que terminou com attempt to call a nil value?

7. Por que a linha #!/usr/bin/env lua não dá erro quando você roda lua ola.lua?

Resumo

  • Um programa Lua é um arquivo de texto .lua. Escreva com um editor (o nano: Ctrl+O grava, Ctrl+X sai) e rode com lua arquivo.lua.
  • O nome sozinho é procurado na pasta atual. Fora dela, use o caminho (lua ~/programas/ola.lua) ou entre na pasta com cd. Se o arquivo não for achado: lua: cannot open …: No such file or directory.
  • O Lua confere a escrita do arquivo inteiro antes de rodar: com um erro de sintaxe, nenhuma linha roda e não há stack traceback.
  • Depois, ele executa de cima para baixo e para no primeiro erro de execução; as linhas de antes já rodaram.
  • As mensagens dizem o arquivo e a linha (lua: compras.lua:3:) e o problema. O código de saída (echo $?) é 0 quando dá certo e 1 com erro.
  • Com #!/usr/bin/env lua na primeira linha e chmod +x, o arquivo roda como um comando: ./ola.lua. O lua pula só essa primeira linha com #.
  • lua -e '…' roda uma linha sem arquivo; lua - lê o programa da entrada; lua -i arquivo.lua roda e abre o modo interativo.
