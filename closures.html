Lua Closures

Na aula Funções São Valores, uma função criou e devolveu outra função. Agora vem o detalhe que torna isso poderoso: a função criada lembra das variáveis locais de quem a criou, e continua podendo usá-las e mudá-las, mesmo depois que a função de fora já terminou. Uma função assim, junto com as variáveis que ela lembra, se chama closure (em português, às vezes, "fechamento"). Com ela dá para fazer um contador que guarda a conta sozinho, sem nenhuma variável global.

Você vai aprender
  • Que uma função enxerga as variáveis locais de fora dela.
  • A fazer um contador com novo_contador(), e por que cada contador tem a sua própria conta.
  • A fazer "fábricas de funções", como criar_multiplicador(2).
  • A fazer duas funções que dividem a mesma variável escondida (o cofrinho).
  • O que acontece com closures dentro de um for e de um while.
  • Os erros reais: o local no lugar errado (o contador que sempre dá 1), a variável global que mistura os contadores e attempt to perform arithmetic on a function value.

A ideia: a máquina de senhas

Na entrada da padaria há uma maquininha de senhas. Cada vez que alguém aperta o botão, sai a próxima: 1, 2, 3… Quem aperta não sabe qual foi a última senha, nem precisa: a máquina guarda o número lá dentro, e ninguém de fora consegue mexer nele. E se a padaria comprar uma segunda máquina para o caixa, ela começa do 1 e conta sozinha, sem se misturar com a primeira.

Uma closure é essa máquina: uma função (o botão) com uma variável guardada só para ela (o número lá dentro).

1. Uma função enxerga as variáveis de fora

Primeiro, uma coisa que você já usou sem perceber: dentro de uma função dá para usar uma variável local criada antes dela, fora dela:

local loja = "Padaria Pão Quente"

local function assinatura()
  print("-- " .. loja)
end

assinatura()
loja = "Padaria Pão Quentinho"
assinatura()

$ lua enxerga.lua
-- Padaria Pão Quente
-- Padaria Pão Quentinho

A função assinatura não tem parâmetro, mas usa a variável loja, que é de fora. E repare na segunda chamada: ela mostrou o nome novo. A função não guardou uma cópia do texto; ela guardou o acesso à variável loja, e lê o valor que estiver lá na hora da chamada.

Uma variável local de fora que uma função usa tem um nome técnico no Lua: upvalue ("valor de cima", porque ela vem do bloco de cima). O nome aparece nas mensagens de erro, como (upvalue 'n') (veja em Quando dá errado), e em funções da biblioteca debug (aula A Biblioteca debug).

2. O contador: a função que lembra

Agora junte isso com uma função que devolve outra função:

local function novo_contador()
  local n = 0
  return function()
    n = n + 1
    return n
  end
end

local contar = novo_contador()
print(contar())
print(contar())
print(contar())

$ lua contador.lua
1
2
3
local function novo_contador()
A "fábrica": cada vez que é chamada, monta uma máquina de senhas nova.
local n = 0
Uma variável local da fábrica: o número lá dentro da máquina.
return function() … end
A fábrica devolve uma função anônima (o botão). Essa função usa o n de fora: é uma closure.
n = n + 1
A closure não só lê o n, ela muda o n. E a mudança fica guardada para a próxima chamada.
local contar = novo_contador()
Chama a fábrica uma vez e guarda a máquina (a closure) em contar.

A parte surpreendente: quando novo_contador() terminou (no return), a variável n deveria ter acabado, como acaba toda variável local no fim da sua função. Mas ela continua viva, porque a closure ainda precisa dela. O Lua só joga fora o n quando ninguém mais pode usá-lo (aula Coleta de Lixo).

  1. novo_contador() cria n = 0, cria a função anônima, devolve a função e termina. O n fica guardado junto com a função.
  2. contar(): n vira 1; devolve 1.
  3. contar() de novo: o n ainda é 1 (ele foi lembrado); vira 2; devolve 2.
  4. E assim por diante.

Cada máquina tem a sua conta

Cada chamada de novo_contador() executa de novo o local n = 0, criando um n novo. Então cada contador tem o seu:

local function novo_contador()
  local n = 0
  return function()
    n = n + 1
    return n
  end
end

local paes = novo_contador()
local bolos = novo_contador()
paes()
paes()
paes()
bolos()
print("pães vendidos:", paes())
print("bolos vendidos:", bolos())

$ lua dois_contadores.lua
pães vendidos:	4
bolos vendidos:	2

O contador de pães foi chamado quatro vezes; o de bolos, duas. Um não atrapalha o outro. E nenhum pedaço do programa consegue mexer no n de fora das closures: ele está escondido, como o número dentro da máquina.

3. Fábricas de funções

A variável lembrada pode ser um parâmetro da fábrica. Assim, a fábrica monta funções diferentes conforme o que recebe:

local function criar_multiplicador(fator)
  return function(n)
    return n * fator
  end
end

local dobro = criar_multiplicador(2)
local triplo = criar_multiplicador(3)
print(dobro(5), triplo(5), dobro(triplo(1)))

$ lua multiplicador.lua
10	15	6

dobro lembra de fator = 2; triplo lembra de fator = 3. As duas foram feitas pelo mesmo código, mas cada uma guardou o seu fator.

Uma fábrica útil: a ordem do table.sort

Na aula anterior, cada ordem do table.sort precisava de uma função de comparação escrita à mão. Com uma fábrica, uma função monta a comparação para qualquer campo:

local function ordenar_por(campo)
  return function(a, b)
    return a[campo] < b[campo]
  end
end

local produtos = {
  {nome = "sonho", preco = 4.5},
  {nome = "café", preco = 4},
  {nome = "bolo", preco = 18},
}

table.sort(produtos, ordenar_por("preco"))
print(produtos[1].nome, produtos[2].nome, produtos[3].nome)
table.sort(produtos, ordenar_por("nome"))
print(produtos[1].nome, produtos[2].nome, produtos[3].nome)

$ lua ordenar_por.lua
café	sonho	bolo
bolo	café	sonho

Aqui, sim, vão os parênteses: ordenar_por("preco") é chamada, e o que vai para o table.sort é a função que ela devolveu, que lembra de campo = "preco".

4. Duas funções dividindo a mesma variável: o cofrinho

Se a fábrica cria duas funções que usam a mesma variável, as duas enxergam a mesma variável. Uma muda, a outra vê a mudança:

local function criar_cofrinho()
  local saldo = 0
  local function depositar(valor)
    saldo = saldo + valor
  end
  local function ver_saldo()
    return saldo
  end
  return depositar, ver_saldo
end

local depositar, ver_saldo = criar_cofrinho()
depositar(10)
depositar(5.5)
print("No cofrinho: " .. ver_saldo())
print(saldo)

$ lua conta.lua
No cofrinho: 15.5
nil
local saldo = 0
A variável escondida, compartilhada pelas duas funções de dentro.
return depositar, ver_saldo
A fábrica devolve as duas funções (aula Vários Retornos).
print(saldo)
nil: fora do cofrinho, não existe variável saldo. O único jeito de mexer no dinheiro é pelas funções que o cofrinho oferece: só dá para depositar e olhar, nunca para tirar escondido.

Esse jeito de esconder dados atrás de funções é a base da aula Privacidade com Closures.

5. Closures dentro de laços

E se as closures forem criadas num laço? No for, cada volta tem a sua variável de controle, e cada closure lembra a da sua volta:

local avisos = {}
for i = 1, 3 do
  avisos[i] = function()
    print("Mesa " .. i .. ": pedido pronto")
  end
end

avisos[1]()
avisos[2]()
avisos[3]()

$ lua laco_for.lua
Mesa 1: pedido pronto
Mesa 2: pedido pronto
Mesa 3: pedido pronto

Com o while e uma variável criada fora do laço, a história é outra: existe uma variável i só, e as três closures lembram dela, a mesma:

local avisos = {}
local i = 1
while i <= 3 do
  avisos[i] = function()
    print("Mesa " .. i .. ": pedido pronto")
  end
  i = i + 1
end

avisos[1]()
avisos[2]()
avisos[3]()

$ lua laco_while.lua
Mesa 4: pedido pronto
Mesa 4: pedido pronto
Mesa 4: pedido pronto

Quando as closures foram chamadas, o laço já tinha terminado, e o único i valia 4. Elas mostram o valor atual da variável, não o valor da hora em que foram criadas (como a assinatura da seção 1). O conserto: criar uma variável local dentro do laço, que é nova a cada volta:

local avisos = {}
local i = 1
while i <= 3 do
  local mesa = i
  avisos[i] = function()
    print("Mesa " .. mesa .. ": pedido pronto")
  end
  i = i + 1
end

avisos[1]()
avisos[2]()
avisos[3]()

$ lua laco_while_ok.lua
Mesa 1: pedido pronto
Mesa 2: pedido pronto
Mesa 3: pedido pronto
E nas outras versões?

Closures funcionam do mesmo jeito no Lua 5.1, no LuaJIT, no 5.4 e no 5.5: o laco_for.lua deu a mesma saída no lua5.1, e o contador.lua, no luajit. Uma diferença do 5.5: a variável do for não pode ser alterada dentro do laço (aula for Numérico), então nem uma closure consegue mudar o i do for: local f = function() i = i + 1 end dentro do laço dá attempt to assign to const variable 'i'. 5.5 Quem vem do JavaScript antigo (com var) conhece o problema do while acima acontecendo também no for; no Lua, o for não tem esse problema.

Formas diferentes de guardar um estado

O contador precisa lembrar de um número entre uma chamada e outra. Há três jeitos de fazer isso:

FormaExemploVantagemProblema
Variável globaln = 0 e function contar() n = n + 1 endSimplesUm contador só; qualquer parte do programa pode mudar o n sem querer
Uma tabelalocal c = {n = 0} e c.n = c.n + 1Vários contadores, cada um numa tabelaO n fica à mostra: qualquer um faz c.n = 100
Closurelocal contar = novo_contador()Vários contadores, e o n fica escondidoPara olhar o valor sem somar, é preciso criar outra função (como o ver_saldo)

Para um contador, uma fábrica de funções ou uma comparação do table.sort, a closure é o jeito do Lua. Quando o "objeto" tem muitos dados e muitas ações, a aula Classes com Metatabelas mostra o caminho das tabelas.

Quando dá errado

O local dentro da função de dentro: sempre 1 
local function novo_contador()
  return function()
    local n = 0
    n = n + 1
    return n
  end
end

local contar = novo_contador()
print(contar(), contar(), contar())

$ lua erro_local_dentro.lua
1	1	1

Sem erro, mas o contador não conta. O local n = 0 está dentro da closure: a cada chamada, ela cria um n novo, valendo 0, soma 1 e devolve 1. Não sobra nada para lembrar. Como consertar: o local n = 0 vai na fábrica, antes do return function.

Esquecer o valor inicial: (upvalue 'n') 
local function novo_contador()
  local n
  return function()
    n = n + 1
    return n
  end
end

local contar = novo_contador()
print(contar())

$ lua upv.lua
lua: upv.lua:4: attempt to perform arithmetic on a nil value (upvalue 'n')
stack traceback:
	upv.lua:4: in local 'contar'
	upv.lua:10: in main chunk
	[C]: in ?

local n sem = 0 cria a variável valendo nil, e nil + 1 não existe. A novidade está no fim da primeira linha: (upvalue 'n'). Até agora o Lua dizia local ou global; aqui ele avisa que o n é uma variável de fora da função que deu o erro, lembrada pela closure. E o rastro diz in local 'contar': a closure não tem nome próprio, então o Lua usa o nome da variável por onde ela foi chamada. Como consertar: local n = 0.

Chamar a fábrica toda vez 
local function novo_contador()
  local n = 0
  return function()
    n = n + 1
    return n
  end
end

print(novo_contador()())
print(novo_contador()())
print(novo_contador()())

$ lua erro_fabrica_cada_vez.lua
1
1
1

A fábrica está certa, mas cada linha monta uma máquina nova, aperta o botão uma vez e joga a máquina fora. Como consertar: chame a fábrica uma vez, guarde a closure (local contar = novo_contador()) e chame só a closure depois.

Esquecer o local na fábrica: os contadores se misturam 
local function novo_contador()
  n = 0
  return function()
    n = n + 1
    return n
  end
end

local paes = novo_contador()
paes()
paes()

print("bolos:", bolos())

$ lua erro_global.lua

bolos:	2

Sem o local, o n é uma variável global, uma só para o programa inteiro (aula local × Global). Os pães já iam em 2, mas criar o contador de bolos fez n = 0 de novo, zerando os pães; depois, pães e bolos somaram no mesmo n. O resultado parece aleatório e não dá erro nenhum. Como consertar: local n = 0.

Esquecer de chamar a fábrica 
local function novo_contador()
  local n = 0
  return function()
    n = n + 1
    return n
  end
end

local contar = novo_contador
print(contar())
print(contar() + 1)

$ lua erro_sem_chamar.lua

Sem parênteses, contar recebeu a fábrica, não o contador. Então contar() monta um contador e devolve a closure: o print mostrou function: 0x… (o endereço muda a cada execução). E contar() + 1 tentou somar 1 a uma função: attempt to perform arithmetic on a function value, "tentativa de fazer conta com um valor do tipo função". Como consertar: local contar = novo_contador(), com parênteses.

A closure mostra o valor de agora, não o de antes

Sem erro: as três mesas do while mostraram Mesa 4 (seção 5). A closure lembra a variável, e mostra o valor que ela tem na hora da chamada. Como consertar: uma variável local nova dentro do laço (local mesa = i).

Resumo

  • Uma função enxerga as variáveis locais de fora dela (os upvalues) e lê o valor que elas têm na hora da chamada.
  • Uma closure é uma função que lembra dessas variáveis mesmo depois que a função que as criou terminou.
  • O contador: a fábrica cria local n = 0 e devolve uma função que faz n = n + 1. Cada chamada da fábrica cria um n novo, então cada contador é independente.
  • A variável lembrada pode ser um parâmetro: criar_multiplicador(2), ordenar_por("preco").
  • Duas closures da mesma fábrica dividem a mesma variável, que fica escondida do resto do programa (o cofrinho).
  • No for, cada volta tem a sua variável; no while, crie uma local dentro do laço.
  • Erros comuns: o local dentro da closure (sempre 1), o local esquecido na fábrica (contadores misturados) e a fábrica sem parênteses (attempt to perform arithmetic on a function value).
