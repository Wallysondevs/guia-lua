Lua Herança

A Ana já tem a classe Conta (aula Classes). Agora o banco quer uma Poupança: ela faz tudo o que uma conta faz (depositar, sacar, extrato) e mais uma coisa, render juros. Copiar a classe Conta inteira e acrescentar o método novo funcionaria, mas aí qualquer conserto na Conta teria de ser feito duas vezes. A herança resolve isso: a classe Poupanca (a "filha") aproveita tudo da Conta (a "mãe") e só escreve o que é diferente.

Você vai aprender
  • A ideia de herança, com uma comparação do dia a dia.
  • A linha que liga a filha à mãe: setmetatable(Poupanca, { __index = Conta }).
  • O construtor da filha, que aproveita o da mãe.
  • O caminho que o Lua faz para achar um método herdado (a corrente objeto → filha → mãe).
  • Sobrescrever um método e chamar a versão da mãe com Conta.sacar(self, valor).
  • As figuras: Quadrado herdando de Retangulo.
  • Por que os metamétodos (__tostring) não passam sozinhos para a filha.
  • Os erros reais: Conta:sacar em vez de Conta.sacar, o self:sacar que chama a si mesmo, e a corrente esquecida.

Todos os programas rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook) com lua arquivo.lua. Faça antes a aula Classes com Metatabelas. Usamos também require (aula Criando seu Módulo) e a corrente de procura do __index.

A ideia: a receita da família

A avó da Ana tem uma receita de bolo simples. A mãe dela fez a versão de chocolate: ela não reescreveu a receita inteira, só anotou "igual à da vovó, mas troque metade da farinha por chocolate". Quando alguém pergunta "quanto de açúcar?", a resposta está na receita da avó. Quando pergunta "e o chocolate?", está na anotação da mãe.

  • A receita da avó é a classe mãe (Conta).
  • A anotação "igual à da vovó, mas…" é a classe filha (Poupanca): só o que é novo ou diferente.
  • "Se não estiver na anotação, olhe a receita da avó" é o __index ligando a filha à mãe.

Em programação se diz que a Poupança "é uma" Conta: tudo o que vale para uma conta vale para ela. Esse "é um" é o teste para saber se a herança faz sentido.

A classe mãe: conta.lua

Para não repetir a classe Conta em todos os exemplos, ela fica num arquivo próprio, conta.lua, que devolve a classe no fim (um módulo). É a mesma classe da aula anterior, com um sacar que recusa quando falta saldo:

local Conta = {}
Conta.__index = Conta

function Conta.new(titular, saldo)
  local self = setmetatable({}, Conta)
  self.titular = titular
  self.saldo = saldo or 0
  return self
end

function Conta:depositar(valor)
  self.saldo = self.saldo + valor
end

function Conta:sacar(valor)
  if valor > self.saldo then
    return false, "saldo insuficiente"
  end
  self.saldo = self.saldo - valor
  return true
end

function Conta:extrato()
  print(string.format("%s: R$ %.2f", self.titular, self.saldo))
end

return Conta

Os programas desta aula começam com local Conta = require("conta"), e o require acha o conta.lua na mesma pasta.

1. A filha: Poupanca

local Conta = require("conta")

local Poupanca = setmetatable({}, { __index = Conta })
Poupanca.__index = Poupanca

function Poupanca.new(titular, saldo, taxa)
  local self = Conta.new(titular, saldo)
  setmetatable(self, Poupanca)
  self.taxa = taxa
  return self
end

function Poupanca:render()
  self.saldo = self.saldo * (1 + self.taxa)
end

local p = Poupanca.new("Ana", 1000, 0.01)
p:depositar(200)
p:render()
p:extrato()
print(p:sacar(5000))
print(getmetatable(p) == Poupanca, getmetatable(Poupanca).__index == Conta)
print(rawget(Poupanca, "depositar"), Poupanca.depositar == Conta.depositar)

local c = Conta.new("Bia", 50)
print(c.render)

A linha da herança. A classe Poupanca é uma tabela que ganha uma metatabela com __index = Conta: "o que faltar na Poupanca, procure na Conta".
Poupanca.__index = Poupanca
A mesma linha de toda classe: os objetos de Poupanca vão procurar os métodos na Poupanca.
local self = Conta.new(titular, saldo)
O construtor da filha aproveita o da mãe: quem guarda o titular e o saldo é o Conta.new. Assim, se um dia a Conta ganhar um campo novo no construtor, a poupança ganha junto.
setmetatable(self, Poupanca)
O Conta.new devolveu um objeto ligado à Conta. Aqui trocamos a metatabela dele para Poupanca: agora ele é uma poupança (e, pela corrente, também enxerga tudo da conta).
self.taxa = taxa
O dado que só a poupança tem: a taxa de rendimento (0.01 = 1%).
function Poupanca:render()
O método que só a poupança tem. 1200 com 1% dá 1212.

As três últimas linhas da saída confirmam o que aconteceu por dentro: a metatabela de p é Poupanca, a metatabela da Poupanca aponta para a Conta; a Poupanca não tem um depositar só dela (rawget deu nil), mas acha o da Conta. E uma conta comum não tem render (nil): a herança vai da mãe para a filha, nunca ao contrário.

Passo a passo: p:depositar(200)

  1. O Lua procura depositar no objeto p. Ele só tem titular, saldo e taxa: não acha.
  2. A metatabela de p é Poupanca, e Poupanca.__index é a própria Poupanca. O Lua procura depositar na Poupanca: ela só tem __index, new e render. Não acha.
  3. A Poupanca também tem metatabela, com __index = Conta. O Lua procura depositar na Conta, e acha.
  4. Ele chama Conta.depositar(p, 200). O self é o p, então o depósito cai na poupança da Ana.

É a corrente de procura da aula __index e __newindex (cafeteira → modelo → fábrica), agora com classes: objeto → filha → mãe.

2. As figuras: Quadrado é um Retangulo

O mesmo padrão serve para qualquer família de classes. Todo quadrado é um retângulo com largura e altura iguais. A classe Quadrado só precisa de um construtor mais simples (um lado só) e de uma descrição própria; a área vem do Retangulo:

local Retangulo = {}
Retangulo.__index = Retangulo

function Retangulo.new(largura, altura)
  return setmetatable({ largura = largura, altura = altura }, Retangulo)
end

function Retangulo:area()
  return self.largura * self.altura
end

function Retangulo:descricao()
  return "retângulo " .. self.largura .. "x" .. self.altura
end

local Quadrado = setmetatable({}, { __index = Retangulo })
Quadrado.__index = Quadrado

function Quadrado.new(lado)
  return setmetatable(Retangulo.new(lado, lado), Quadrado)
end

function Quadrado:descricao()
  return "quadrado de lado " .. self.largura
end

local figuras = { Retangulo.new(3, 4), Quadrado.new(5), Retangulo.new(1, 2) }
for _, f in ipairs(figuras) do
  print(f:descricao() .. ": área " .. f:area())
end

$ lua figuras.lua
retângulo 3x4: área 12
quadrado de lado 5: área 25
retângulo 1x2: área 2

Repare no laço: ele chama f:descricao() e f:area() sem saber se f é retângulo ou quadrado. Cada objeto responde do seu jeito: o quadrado usa a sua descricao (o Lua a acha na Quadrado e para de procurar) e a area herdada. Isso tem um nome comprido, polimorfismo ("muitas formas"): o mesmo pedido, respostas diferentes conforme o objeto.

Missão: a classe Quadrado não está ligada ao Retangulo, e q:area() dá attempt to call a nil value (method 'area'). Troque local Quadrado = {} pela linha da herança, para o quadrado aproveitar a area do retângulo.

3. Sobrescrever um método e chamar o da mãe

Às vezes a filha precisa fazer uma coisa do jeito dela. A poupança da Ana só permite 2 saques por mês. Ela escreve o seu próprio Poupanca:sacar: como o Lua acha esse método na Poupanca antes de chegar na Conta, a versão da filha "cobre" a da mãe. Isso se chama sobrescrever (em inglês, override).

Mas a regra do saldo (não sacar mais do que tem) continua igual. Em vez de reescrevê-la, o sacar da filha chama o da mãe:

local Conta = require("conta")

local Poupanca = setmetatable({}, { __index = Conta })
Poupanca.__index = Poupanca

function Poupanca.new(titular, saldo, taxa)
  local self = setmetatable(Conta.new(titular, saldo), Poupanca)
  self.taxa = taxa
  self.saques_no_mes = 0
  return self
end

function Poupanca:sacar(valor)
  if self.saques_no_mes >= 2 then
    return false, "a poupança só permite 2 saques por mês"
  end
  local ok, motivo = Conta.sacar(self, valor)
  if ok then
    self.saques_no_mes = self.saques_no_mes + 1
  end
  return ok, motivo
end

local p = Poupanca.new("Ana", 1000, 0.01)
print(p:sacar(100))
print(p:sacar(5000))
print(p:sacar(100))
print(p:sacar(100))
p:extrato()

local c = Conta.new("Bia", 1000)
print(c:sacar(100), c:sacar(100), c:sacar(100))

A chamada à mãe. Com ponto e passando o self à mão: "rode o sacar da Conta, mas nesta poupança". É o caso da tabela de Métodos: chamar o método de uma tabela passando outra como self.

O primeiro saque deu certo. O nil é o motivo: a mãe devolveu só true, e a filha devolve ok, motivo.

Quem recusou foi a regra da mãe, chamada pela filha. Esse saque não contou.

No terceiro pedido (o segundo que deu certo foi o anterior), quem recusou foi a regra da filha, antes mesmo de chamar a mãe.
Ponto, não dois-pontos, para chamar a mãe

Conta:sacar(valor) seria Conta.sacar(Conta, valor): o self seria a classe Conta, que não tem saldo. E self:sacar(valor) chamaria a própria versão da filha de novo, para sempre. Os dois erros estão em Quando dá errado.

4. Os metamétodos não são herdados sozinhos

Uma surpresa: a Conta ganha um __tostring, e a poupança continua aparecendo como table: 0x…:

local Conta = require("conta")
Conta.__tostring = function (c)
  return string.format("Conta de %s (R$ %.2f)", c.titular, c.saldo)
end

local Poupanca = setmetatable({}, { __index = Conta })
Poupanca.__index = Poupanca

function Poupanca.new(titular, saldo)
  return setmetatable(Conta.new(titular, saldo), Poupanca)
end

local c = Conta.new("Bia", 50)
local p = Poupanca.new("Ana", 1000)
print(c)
print((tostring(p):gsub("0x%x+", "0x...")))
print(Poupanca.__tostring == Conta.__tostring)

Poupanca.__tostring = Conta.__tostring
print(p)

true
Conta de Ana (R$ 1000.00)
print(c) → Conta de Bia…
A conta comum usa o __tostring da Conta, a metatabela dela.
tostring(p) → table: 0x...
A metatabela da poupança é a Poupanca, e a Poupanca não tem um __tostring dela. (O gsub só esconde o endereço, que muda a cada vez.)
Poupanca.__tostring == Conta.__tostring → true
O curioso: lendo Poupanca.__tostring, o __index da corrente acha o da Conta. Mas quando o Lua procura um metamétodo, ele olha a metatabela crua (como um rawget), sem seguir a corrente.
Poupanca.__tostring = Conta.__tostring
O conserto: copiar o metamétodo para a filha. Depois disso, print(p) funcionou.

Vale para todos os metamétodos (__tostring, __eq, __lt, __add, __len…): a filha precisa ter os seus. O __index da filha é o único que você já escreve sempre (Poupanca.__index = Poupanca).

5. "Este objeto é uma Conta?"

Na aula anterior, getmetatable(obj) == Conta dizia se o objeto era uma conta. Com herança, isso não basta: para uma poupança, a metatabela é Poupanca, não Conta. Uma função que sobe a corrente resolve:

local Conta = require("conta")
local Poupanca = setmetatable({}, { __index = Conta })
Poupanca.__index = Poupanca
function Poupanca.new(t, s) return setmetatable(Conta.new(t, s), Poupanca) end

local function eh_um(objeto, classe)
  local mt = getmetatable(objeto)
  while mt do
    if mt == classe then return true end
    local mae = getmetatable(mt)
    mt = mae and mae.__index
  end
  return false
end

local p = Poupanca.new("Ana", 10)
local c = Conta.new("Bia", 10)
print(eh_um(p, Poupanca), eh_um(p, Conta))
print(eh_um(c, Poupanca), eh_um(c, Conta))
print(getmetatable(p) == Conta)

$ lua eh_um.lua
true	true
false	true
false

A poupança "é uma" Poupança e "é uma" Conta; a conta comum é só Conta. A função começa na classe do objeto e vai subindo (mae.__index, a mãe de cada classe) até achar a classe procurada ou acabar a corrente (mt vira nil). O mae and mae.__index evita erro quando a classe não tem mãe (veja O Truque do and/or).

Formas diferentes de fazer a mesma coisa

O livro Programming in Lua, do criador da linguagem, usa outro estilo: a classe é criada com Conta:new(), e a filha é "um objeto especial" da mãe. Funciona porque o new usa self (que é a classe que chamou) como metatabela:

local Conta = { saldo = 0 }

function Conta:new(o)
  o = o or {}
  self.__index = self
  setmetatable(o, self)
  return o
end

function Conta:depositar(v) self.saldo = self.saldo + v end

local Poupanca = Conta:new()
function Poupanca:render() self.saldo = self.saldo * 1.01 end

local p = Poupanca:new({ titular = "Ana", saldo = 1000 })
p:depositar(200)
p:render()
print(p.titular, p.saldo)

$ lua pil.lua
Ana	1212.0

Aqui Poupanca = Conta:new() cria a filha, e Poupanca:new(…) roda o mesmo new da Conta, mas com self = Poupanca: o objeto fica ligado à filha. É mais curto, mas menos explícito; o Conta.new com setmetatable(Filha, { __index = Mae }) mostra a ligação com todas as letras.

SituaçãoQual usar
A filha "é uma" mãe, com algo a mais ou diferente (Poupança é Conta, Quadrado é Retângulo)Herança: setmetatable(Filha, { __index = Mae })
Só quer reaproveitar uma função, sem a relação "é um"Chame a função direto, ou copie-a para a outra classe: herança não é obrigatória
Muitos níveis (Avó → Mãe → Filha → Neta)Funciona, mas fica difícil de seguir; prefira poucos níveis
Código de outras pessoas com Classe:new(o)É o estilo do Programming in Lua (acima): leia o self do new como "a classe que chamou"

Referência rápida: o molde da herança

local Filha = setmetatable({}, { __index = Mae })   -- liga a filha à mãe
Filha.__index = Filha                               -- objetos procuram na filha

function Filha.new(a, b, extra)
  local self = Mae.new(a, b)                        -- a mãe monta a base
  setmetatable(self, Filha)                         -- agora é uma Filha
  self.extra = extra                                -- o que só a filha tem
  return self
end

function Filha:metodo_novo() … end                  -- só a filha tem

function Filha:metodo_da_mae(x)                     -- sobrescreve
  -- … o que muda …
  return Mae.metodo_da_mae(self, x)                 -- chama a versão da mãe
end

Missão: a conta corrente cobra uma tarifa de R$ 2 por saque. local Conta = {}
Conta.__index = Conta

function Conta.new(titular, saldo)
  local self = setmetatable({}, Conta)
  self.titular = titular
  self.saldo = saldo or 0
  return self
end

function Conta:depositar(valor)
  self.saldo = self.saldo + valor
end

function Conta:sacar(valor)
  if valor > self.saldo then
    return false, "saldo insuficiente"
  end
  self.saldo = self.saldo - valor
  return true
end

function Conta:extrato()
  print(string.format("%s: R$ %.2f", self.titular, self.saldo))
end

return Conta

local Conta = require("conta")

local Corrente = setmetatable({}, { __index = Conta })
Corrente.__index = Corrente

function Corrente.new(titular, saldo)
  local self = setmetatable(Conta.new(titular, saldo), Corrente)
  self.tarifa = 2
  return self
end

function Corrente:sacar(valor)
  return Conta.sacar(self, valor + self.tarifa)
end

local c = Corrente.new("Bia", 100)
print(c:sacar(20))
print(c:sacar(77))
c:extrato()

No lab, a solução mostrou true, depois false saldo insuficiente (77 + 2 de tarifa = 79, mais do que os 78 que sobraram: a regra da mãe recusou) e, por fim, Bia: R$ 78.00.

Resumo

  • Herança: a classe filha aproveita tudo da mãe e só escreve o que é novo ou diferente. Use quando a filha "é uma" mãe.
  • A ligação: local Filha = setmetatable({}, { __index = Mae }) e Filha.__index = Filha. A procura segue a corrente objeto → filha → mãe.
  • O construtor da filha chama o da mãe (Mae.new(…)) e troca a metatabela: setmetatable(self, Filha).
  • Sobrescrever: escreva o método na filha. Para usar a versão da mãe, Mae.metodo(self, …), com ponto e self. Nunca Mae:metodo nem self:metodo dentro dele mesmo.
  • Os metamétodos (__tostring, __eq…) não seguem a corrente: copie-os para a filha.
  • Próximo passo: dados que ninguém de fora consegue mexer, em Privacidade com Closures.
