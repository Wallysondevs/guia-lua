Lua Tabelas Aninhadas

Um valor guardado numa tabela pode ser qualquer coisa, inclusive outra tabela. Quando uma tabela tem tabelas dentro, dizemos que elas estão aninhadas (uma dentro da outra, como os ovos num ninho). É assim que se guarda no Lua quase tudo que tem mais de um nível: as notas de cada aluno em cada bimestre, a ficha de uma pessoa com o endereço dentro, a turma inteira, o tabuleiro de um jogo.

Você vai aprender
  • A fazer uma lista de listas (uma "matriz", com linhas e colunas) e a ler notas[2][3].
  • A pôr um dicionário dentro de outro e ler ficha.endereco.cidade.
  • A fazer uma lista de fichas (a turma) e a ordená-la por um campo.
  • A fazer um dicionário de listas (cada pessoa com vários telefones).
  • A criar os níveis por partes, a ler com segurança quando um nível pode faltar e a percorrer tudo com laços aninhados.
  • Os erros reais: attempt to index a nil value e a "mesma linha repetida".

A ideia: o fichário

A secretaria da escola tem um fichário. O fichário é uma caixa (uma tabela) cheia de fichas. Cada ficha é outra tabela: nome, idade, endereço. E o endereço também tem partes: rua, cidade, estado. Para achar a cidade da Ana, você abre o fichário, pega a ficha da Ana, olha o endereço e lê a cidade: um nível de cada vez.

1. Lista de listas: a matriz

A professora guarda as notas da turma assim: uma lista com uma linha por aluno, e cada linha é uma lista com as notas dos 4 bimestres.

local notas = {
  {7, 8, 6, 9},
  {9, 7, 8, 10},
  {5, 6, 7, 8},
}
print(#notas)
print(#notas[1])
print(notas[2])
print(notas[2][3])
local linha = notas[2]
print(linha[3])
notas[3][1] = 6
print(notas[3][1])

A tabela de fora tem 3 itens, e cada item é uma tabela com 4 números. Escrever uma linha por item, com 2 espaços na frente, deixa a "grade" visível no código.
#notas
Quantos itens a tabela de fora tem: 3 linhas (3 alunos).
#notas[1]
Quantos itens a primeira linha tem: 4 notas.
notas[2]
A segunda linha inteira: uma tabela (o print só mostra o endereço).
notas[2][3]
Leia da esquerda para a direita: notas[2] é a linha da Bia; o [3] pega o 3º item dessa linha. Resultado: 8.
local linha = notas[2]
É o mesmo, em dois passos: guardar a linha numa variável e depois pegar linha[3].
notas[3][1] = 6
Para mudar, a mesma escrita, do lado esquerdo do =.

Missão: a Bia é a linha 2. Troque o 0 pela nota dela no 3º bimestre, usando notas[2][3], para o programa mostrar Nota: 8.

local notas = {
  {7, 8, 6, 9},
  {9, 7, 8, 10},
  {5, 6, 7, 8},
}
print("Nota: " .. 0)

local notas = {
  {7, 8, 6, 9},
  {9, 7, 8, 10},
  {5, 6, 7, 8},
}
print("Nota: " .. notas[2][3])

Percorrendo: um laço dentro do outro

Para passar por todas as notas, use um laço aninhado: o de fora passa pelas linhas; o de dentro, pelas notas da linha atual.

local nomes = {"Ana", "Bia", "Caio"}
local notas = {
  {7, 8, 6, 9},
  {9, 7, 8, 10},
  {5, 6, 7, 8},
}
for i, linha in ipairs(notas) do
  local soma = 0
  for j, nota in ipairs(linha) do
    soma = soma + nota
  end
  print(nomes[i], soma / #linha)
end

$ lua matriz_laco.lua
Ana	7.5
Bia	8.5
Caio	6.5
for i, linha in ipairs(notas)
A cada volta, linha é uma das listas de dentro, e i é a posição dela (1, 2, 3).
local soma = 0
Fica dentro do laço de fora: a soma recomeça do zero para cada aluno.
for j, nota in ipairs(linha)
O laço de dentro passa pelas 4 notas da linha atual.
nomes[i]
Os nomes estão numa lista separada, na mesma ordem das linhas. (Na seção 3, eles vão para dentro da própria ficha.)

2. Dicionário dentro de dicionário: a ficha

local ficha = {
  nome = "Ana",

print(ficha.nome)
print(ficha.endereco.cidade)
print(ficha["endereco"]["uf"])
print(ficha.telefones[2])
print(#ficha.telefones)
ficha.endereco.cidade = "Picos"
print(ficha.endereco.cidade)

$ lua ficha.lua

Teresina
PI
3222-0001
2
Picos
endereco = { … }
O valor da chave endereco é outro dicionário, com rua, cidade e uf. A indentação mostra o nível: 2 espaços para os campos da ficha, 4 para os do endereço.
telefones = {…}
Uma chave da ficha pode guardar também uma lista.
ficha.endereco.cidade
Um ponto por nível: a ficha, o endereço dela, a cidade do endereço.
ficha["endereco"]["uf"]
A mesma coisa com colchetes (aula Dicionários): t.x é o mesmo que t["x"], em qualquer nível.
ficha.telefones[2]
Mistura: o ponto para a chave de texto, os colchetes para a posição na lista.
#ficha.telefones
O # vale para o último nível: o tamanho da lista de telefones, 2.

3. Lista de fichas: a turma

O formato mais comum de todos: uma lista em que cada item é um dicionário com os mesmos campos. É como uma planilha: cada ficha é uma linha, cada campo é uma coluna.

local turma = {
  {nome = "Ana", nota = 7.5},
  {nome = "Bia", nota = 9},
  {nome = "Caio", nota = 6},
}
print(#turma)
print(turma[2].nome)
for i, aluno in ipairs(turma) do
  print(i, aluno.nome, aluno.nota)
end
table.insert(turma, {nome = "Davi", nota = 8})
table.sort(turma, function(a, b) return a.nota > b.nota end)
for i, aluno in ipairs(turma) do
  print(i .. "º", aluno.nome, aluno.nota)
end

$ lua turma.lua
3
Bia
1	Ana	7.5
2	Bia	9
3	Caio	6
1º	Bia	9
2º	Davi	8
3º	Ana	7.5
4º	Caio	6
turma[2].nome
turma[2] é a ficha da Bia; .nome é o nome dela.
for i, aluno in ipairs(turma)
A cada volta, aluno é uma ficha inteira; os campos saem com aluno.nome e aluno.nota. Como a turma é uma lista, o ipairs passa em ordem.
table.insert(turma, {nome = "Davi", nota = 8})
Uma ficha nova, criada ali mesmo, vai para o fim da lista.
table.sort(turma, function(a, b) return a.nota > b.nota end)
As fichas não sabem se comparar sozinhas: a função diz que a vem antes de b se a nota de a for maior (aula table.sort). A turma ficou em ordem de nota, da maior para a menor.

4. Dicionário de listas: a agenda

O contrário da turma: um dicionário em que cada valor é uma lista. Na agenda da Ana, cada pessoa pode ter vários telefones:

local agenda = {
  Ana = {"99999-0001"},
  Bia = {"99999-0002", "3222-0002"},
}
table.insert(agenda.Ana, "3222-0001")
agenda.Caio = {}
table.insert(agenda.Caio, "98888-0003")
print(#agenda.Ana, #agenda.Bia, #agenda.Caio)
print(table.concat(agenda.Bia, " / "))

$ lua agenda.lua
2	2	1
99999-0002 / 3222-0002
table.insert(agenda.Ana, "3222-0001")
agenda.Ana é uma lista comum: tudo que você faz com uma lista funciona nela.
agenda.Caio = {}
Para uma pessoa nova, primeiro crie a lista vazia; só depois dá para inserir nela (veja a seção 5).
table.concat(agenda.Bia, " / ")
Junta os telefones da Bia num texto (aula table.concat).

Para mostrar a agenda inteira, use pairs no dicionário de fora; e, para ela sair em ordem alfabética, ordene os nomes antes (aula pairs).

5. Criando por partes, e lendo com segurança

Você não precisa escrever tudo de uma vez. Mas cada nível tem de existir antes de você guardar coisas dentro dele:

local ficha = {nome = "Bia"}
ficha.endereco = {}
ficha.endereco.cidade = "Parnaíba"
print(ficha.endereco.cidade)
local outra = {nome = "Caio"}
print(outra.endereco)
print(outra.endereco and outra.endereco.cidade)
print((outra.endereco or {}).cidade)

$ lua partes.lua
Parnaíba
nil
nil
nil
ficha.endereco = {}
Primeiro cria a tabela do endereço, vazia.
ficha.endereco.cidade = "Parnaíba"
Depois guarda a cidade dentro dela. Sem a linha de cima, esta linha dá erro (veja Quando dá errado).
outra.endereco
O Caio não tem endereço: nil, sem erro (um nível só).
outra.endereco and outra.endereco.cidade
Leitura segura: se outra.endereco for nil, o and para ali e devolve nil, sem tentar ler .cidade de um nil (aula and, or e not).
(outra.endereco or {}).cidade
Outro jeito: se o endereço faltar, usa uma tabela vazia no lugar; a cidade de uma tabela vazia é nil.

Montando uma matriz com laços

Para um tabuleiro de jogo da velha (3 linhas, 3 colunas), em vez de escrever as 9 casas à mão, use dois laços. Repare na linha tabuleiro[i] = {}: ela cria uma tabela nova para cada linha.

local tabuleiro = {}
for i = 1, 3 do
  tabuleiro[i] = {}
  for j = 1, 3 do
    tabuleiro[i][j] = "."
  end
end
tabuleiro[1][1] = "X"
tabuleiro[2][2] = "O"
for _, l in ipairs(tabuleiro) do
  print(table.concat(l, " "))
end

$ lua tabuleiro.lua
X . .
. O .
. . .

O X foi para a casa (1, 1) e o O para a (2, 2), e cada um apareceu só onde devia. O último cenário de Quando dá errado mostra o que acontece quando as três linhas são a mesma tabela.

Missão: o Caio é contato novo. Antes do print, crie a lista dele (agenda.Caio = {}) e insira o telefone "98888-0003" com table.insert, para o programa mostrar Caio tem 1 telefone(s).

local agenda = {
  Ana = {"99999-0001"},
  Bia = {"99999-0002", "3222-0002"},
}

print("Caio tem " .. #(agenda.Caio or {}) .. " telefone(s)")

local agenda = {
  Ana = {"99999-0001"},
  Bia = {"99999-0002", "3222-0002"},
}
agenda.Caio = {}
table.insert(agenda.Caio, "98888-0003")
print("Caio tem " .. #(agenda.Caio or {}) .. " telefone(s)")

Três ou quatro níveis já ficam difíceis de ler (escola.turmas[2].alunos[5].notas[3]). Quando ficar assim, guarde um nível numa variável com nome (local aluno = escola.turmas[2].alunos[5]) e continue a partir dela.

Quando dá errado

Ler dentro de um nível que não existe 
local ficha = {nome = "Caio"}
print(ficha.endereco.cidade)

$ lua erro_endereco.lua
lua: erro_endereco.lua:2: attempt to index a nil value (field 'endereco')
stack traceback:
	erro_endereco.lua:2: in main chunk
	[C]: in ?
lua: erro_endereco.lua:2:
Linha 2.
attempt to index a nil value
"Tentativa de indexar um valor nil". Indexar é usar o ponto ou os colchetes num valor (x.cidade, x[1]). O Lua tentou fazer .cidade em algo que era nil.
(field 'endereco')
E diz quem era nil: o campo endereco. A ficha do Caio não tem endereço; ficha.endereco deu nil, e não existe "cidade de nada".

Repare: um nível que falta dá nil sem erro (ficha.endereco); o erro vem quando você tenta entrar nele. Como consertar: se o nível pode faltar, leia com segurança: ficha.endereco and ficha.endereco.cidade (seção 5).

Guardar dentro de um nível que não existe 
local ficha = {nome = "Caio"}
ficha.endereco.cidade = "Picos"

$ lua erro_criar.lua
lua: erro_criar.lua:2: attempt to index a nil value (field 'endereco')
stack traceback:
	erro_criar.lua:2: in main chunk
	[C]: in ?

A mesma mensagem: o Lua não cria o endereco sozinho. Como consertar: crie o nível antes: ficha.endereco = {}, ou ficha.endereco = ficha.endereco or {} (cria só se ainda não existir).

Linha que não existe na matriz 
local notas = {
  {7, 8, 6, 9},
  {9, 7, 8, 10},
}
print(notas[3][1])

$ lua erro_linha.lua
lua: erro_linha.lua:5: attempt to index a nil value (field 'integer index')
stack traceback:
	erro_linha.lua:5: in main chunk
	[C]: in ?

Só há 2 linhas: notas[3] é nil, e o [1] tentou entrar nele. Aqui o Lua não tem um nome para mostrar e escreve field 'integer index' ("campo de índice inteiro"): o nil veio de uma posição numérica escrita direto no código. Se a posição estiver numa variável (notas[i][1]), a mensagem diz (field '?'). Como consertar: confira os limites: i de 1 até #notas, j de 1 até #notas[i].

Um nível a mais 
local turma = {
  {nome = "Ana", nota = 7.5},
}
print(turma[1].nota.valor)

$ lua erro_numero.lua
lua: erro_numero.lua:4: attempt to index a number value (field 'nota')
stack traceback:
	erro_numero.lua:4: in main chunk
	[C]: in ?

"Tentativa de indexar um valor número": turma[1].nota já é o número 7.5, e número não tem campos. Você foi um nível além do que existe. Como consertar: pare no nível certo: turma[1].nota.

Juntar uma tabela com texto 
local ficha = {nome = "Ana", endereco = {cidade = "Teresina"}}
print("Cidade: " .. ficha.endereco)

$ lua erro_print.lua
lua: erro_print.lua:2: attempt to concatenate a table value (field 'endereco')
stack traceback:
	erro_print.lua:2: in main chunk
	[C]: in ?

O contrário do anterior: parou um nível antes. ficha.endereco é uma tabela, e o .. só junta textos e números. Como consertar: desça até o valor: ficha.endereco.cidade.

As linhas do tabuleiro mudam todas juntas (sem erro) 
local linha = {".", ".", "."}
local tabuleiro = {linha, linha, linha}
tabuleiro[1][1] = "X"
for _, l in ipairs(tabuleiro) do
  print(table.concat(l, " "))
end

$ lua erro_mesma_linha.lua
X . .
X . .
X . .

A Ana marcou o X só na linha 1, e ele apareceu nas três. Não há três linhas: há uma tabela linha, guardada três vezes. Pôr uma tabela dentro de outra não faz uma cópia; guarda a mesma tabela (aula Tabelas São Referências). Como consertar: crie uma tabela nova para cada linha, com tabuleiro[i] = {} dentro do laço (seção 5).

Missão final: o boletim

Missão: cada aluno da turma tem um nome e uma lista de notas. Para cada aluno, some as notas com um laço dentro do laço e mostre a média com uma casa, assim: Ana: 7.5 e Bia: 8.5. Use string.format("%s: %.1f", aluno.nome, media).

local turma = {
  {nome = "Ana", notas = {7, 8, 6, 9}},
  {nome = "Bia", notas = {9, 7, 8, 10}},
}
for _, aluno in ipairs(turma) do
  print(aluno.nome)
end

local turma = {
  {nome = "Ana", notas = {7, 8, 6, 9}},
  {nome = "Bia", notas = {9, 7, 8, 10}},
}
for _, aluno in ipairs(turma) do
  local soma = 0
  for _, nota in ipairs(aluno.notas) do
    soma = soma + nota
  end
  local media = soma / #aluno.notas
  print(string.format("%s: %.1f", aluno.nome, media))
end

Resumo

  • Uma tabela pode guardar outras tabelas: é assim que se guardam dados com vários níveis.
  • Lê-se um nível de cada vez, da esquerda para a direita: notas[2][3], ficha.endereco.cidade, turma[2].nome, agenda.Bia[1].
  • Os quatro formatos: lista de listas, dicionário com dicionário, lista de dicionários, dicionário de listas.
  • Para percorrer, um laço por nível (laços aninhados).
  • Cada nível tem de existir antes de você entrar nele; senão, attempt to index a nil value (field '…'). Leia com segurança com t.a and t.a.b; crie com t.a = t.a or {}.
  • Pôr a mesma tabela em dois lugares não copia: as linhas de uma matriz precisam ser tabelas novas, uma para cada.
