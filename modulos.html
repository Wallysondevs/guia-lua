Lua Módulos e require

Até agora, cada programa seu morou num arquivo só. Quando o programa cresce, isso vira uma bagunça: centenas de linhas, funções de assuntos diferentes misturadas, e a mesma função copiada e colada em vários programas. A saída é separar o código em módulos: arquivos com um pedaço do trabalho, que outros programas podem pedir emprestado. Quem faz o pedido é a função require, que em inglês quer dizer "exigir, precisar de".

Você vai aprender
  • O que é um módulo no Lua: um arquivo .lua que devolve uma tabela cheia de funções.
  • Como usar um módulo com local contas = require("contas"), e o que cada parte dessa linha faz.
  • Por que o require roda o arquivo uma vez só, mesmo que você peça duas vezes (a tabela package.loaded).
  • Que string, math, table e companhia também são módulos, que já vêm carregados.
  • Os erros reais: module 'x' not found (com a lista de lugares onde o Lua procurou), o módulo que esqueceu o return, o erro de sintaxe dentro do módulo e o require sem local.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), numa pasta chamada loja, com lua arquivo.lua (veja Rodando um Programa). Nas caixas "Experimente", o módulo aparece numa aba ao lado do main.lua.

A ideia: a caixa de ferramentas emprestada

A Ana tem uma lojinha e escreveu, com muito cuidado, as contas que ela faz todo dia: somar a compra, dar desconto, calcular o troco. Agora ela quer usar essas mesmas contas em três programas: o do caixa, o do estoque e o do relatório do mês. Copiar e colar as funções nos três tem dois problemas:

  • se ela achar um erro no desconto, vai ter de consertar três vezes (e um dia vai esquecer uma);
  • cada programa fica comprido, cheio de coisa que não é assunto dele.

O jeito melhor é guardar as contas numa caixa de ferramentas com etiqueta, num lugar só, e cada programa pedir a caixa emprestada quando precisar. No Lua:

Na vida realNo Lua
A caixa de ferramentasUma tabela com funções dentro (veja Tabelas)
O armário onde a caixa fica guardadaUm arquivo, por exemplo contas.lua
A etiqueta da caixaO nome do arquivo sem o .lua: "contas"
"Me empresta a caixa de contas?"require("contas")
Usar uma ferramenta da caixacontas.somar(12, 30)

Um módulo, então, é só isso: um arquivo que, no fim, devolve uma tabela (com return). Não existe palavra especial nem comando novo para criar um. Nesta aula você vai usar um módulo; na próxima, Criando seu Módulo, vai aprender a escrever os seus com todos os detalhes.

1. O módulo e o programa que usa

A Ana criou dois arquivos na pasta loja. O primeiro é o módulo, com as contas:

print("carregando o módulo contas...")
local contas = {}

function contas.somar(a, b)
  return a + b
end

function contas.desconto(preco, porcento)
  return preco - preco * porcento / 100
end

return contas
print("carregando o módulo contas...")
Uma linha só para a gente ver quando o arquivo roda. Módulos de verdade quase nunca imprimem nada ao carregar; aqui ela vai ajudar a entender o require.
local contas = {}
A caixa de ferramentas: uma tabela vazia, guardada numa variável local.
function contas.somar(a, b)
Põe uma função dentro da tabela, no campo somar. É o mesmo que contas.somar = function (a, b) … end (veja Funções São Valores).
function contas.desconto(preco, porcento)
Mais uma ferramenta: o preço menos a porcentagem de desconto.
return contas
A linha mais importante: o arquivo devolve a tabela. É isso que o require vai entregar a quem pediu.

O segundo arquivo é o programa principal, que usa o módulo:

local contas = require("contas")
print(contas.somar(12, 30))
print(contas.desconto(80, 10))
require("contas")
"Preciso do módulo contas." O Lua procura um arquivo contas.lua, roda o arquivo inteiro e devolve o que ele deu no return: a tabela com as funções. Repare: você escreve o nome sem o .lua.
local contas =
Guarda a tabela recebida numa variável local. O nome da variável é você que escolhe; usar o mesmo nome do módulo é o costume, porque fica claro de onde ele veio.
contas.somar(12, 30)
Chama a ferramenta somar que mora dentro da tabela: nome da tabela, ponto, nome da função.
$ lua main.lua
carregando o módulo contas...
42
72.0

Primeiro apareceu o carregando o módulo contas...: foi o require rodando o contas.lua. Depois, os resultados das duas contas. O desconto deu 72.0, com .0, porque a divisão / sempre dá um número com vírgula, um float (veja Divisão: /, // e %).

Passo a passo: o que o Lua fez

  1. Começou a rodar o main.lua, linha 1: encontrou require("contas").
  2. Procurou um arquivo chamado contas.lua numa lista de lugares (você vai ver a lista daqui a pouco) e o achou na pasta atual: ./contas.lua.
  3. Rodou o contas.lua do começo ao fim: imprimiu a mensagem, criou a tabela, pôs as duas funções nela e chegou ao return contas.
  4. Guardou essa tabela num lugar especial, a tabela package.loaded (seção 3).
  5. Entregou a tabela ao main.lua, que a guardou na variável contas e seguiu para a linha 2.

Missão: o módulo está na aba contas.lua. No main.lua, troque o comentário por um print que mostre o preço de um produto de R$ 50 com 20% de desconto, usando a ferramenta contas.desconto. Dê uma olhada na aba do módulo antes.

print(contas.somar(12, 30))
-- mostre aqui o preço de 50 reais com 20% de desconto

  return a + b
end

end

print(contas.desconto(50, 20))

2. O require devolve a tabela, e não cria nada sozinho

Uma confusão comum: achar que o require "instala" o nome contas no programa. Ele não faz isso. Ele devolve a tabela, e é você que a guarda numa variável. Veja o que acontece com um require solto, sem guardar o resultado:

require("contas")
print(contas.somar(2, 3))

$ lua global.lua
carregando o módulo contas...
lua: global.lua:2: attempt to index a nil value (global 'contas')
stack traceback:
	global.lua:2: in main chunk
	[C]: in ?

O módulo foi carregado (a mensagem apareceu), mas a tabela que ele devolveu foi jogada fora. Na linha 2, o nome contas não existe: o Lua o procura como variável global (global 'contas'), acha nil, e "tentar indexar um valor nil" quer dizer "tentar pegar .somar de uma coisa que não existe". O conserto é a linha que você já conhece: local contas = require("contas").

Por que o módulo usa local contas lá dentro?

Dentro do contas.lua, a tabela também é local. Por isso o nome contas do módulo não vaza para o programa que o carregou: o único jeito de chegar às funções é pelo que o require devolve. Isso é bom: dois módulos diferentes podem ter, cada um, a sua variável contas sem um atrapalhar o outro. (Em programas muito antigos, do Lua 5.1, você pode encontrar a função module(...), que criava variáveis globais. Ela não existe mais: no 5.5, type(module) dá nil. Veja as diferenças entre versões.)

O segundo valor: onde o arquivo estava

Desde o Lua 5.4, o require devolve dois valores: a tabela do módulo e o caminho do arquivo que ele achou (veja Vários Retornos):

local contas, onde = require("contas")
print(type(contas), onde)

$ lua volta.lua
carregando o módulo contas...
table	./contas.lua
$ lua5.1 volta.lua                « o mesmo arquivo no Lua 5.1
carregando o módulo contas...
table	nil

./contas.lua quer dizer "o arquivo contas.lua da pasta atual" (o . é a pasta onde você está). No 5.1 (e no LuaJIT, que segue o 5.1) esse segundo valor não existe, por isso deu nil. Quase ninguém usa esse segundo valor; ele serve para descobrir qual arquivo foi carregado quando você está em dúvida.

3. O require carrega uma vez só: package.loaded

E se o programa pedir o mesmo módulo duas vezes? Isso acontece muito: o programa principal pede contas, e o módulo de estoque, que o programa também usa, pede contas de novo. Veja:

local c1 = require("contas")
local c2 = require("contas")
print(c1 == c2)
print(package.loaded["contas"] == c1)

$ lua duas.lua
carregando o módulo contas...
true
true

Três coisas para reparar:

  • A mensagem carregando o módulo contas... apareceu uma vez só. O arquivo não rodou de novo no segundo require.
  • c1 == c2 deu true: as duas variáveis apontam para a mesma tabela, não para duas cópias (veja Tabelas São Referências).
  • Essa tabela está guardada em package.loaded["contas"].

O package.loaded é o caderninho de empréstimos do require: uma tabela comum, onde a chave é o nome do módulo e o valor é o que ele devolveu. Antes de procurar qualquer arquivo, o require olha o caderninho:

  1. Tem package.loaded["contas"]? Sim → devolve na hora, sem rodar nada.
  2. Não → procura o arquivo, roda, anota o resultado no caderninho e devolve.

Isso deixa o programa mais rápido (o arquivo é lido uma vez) e garante que todo mundo usa o mesmo módulo. A aula Criando seu Módulo mostra uma consequência curiosa disso: um módulo que guarda um contador é compartilhado por todos que o pedem.

E se eu mudar o arquivo do módulo com o programa rodando?

O require não vai perceber, porque ele só olha o caderninho. Para forçar uma nova leitura (raro, mas útil no modo interativo enquanto você testa), apague a anotação antes: package.loaded["contas"] = nil, e chame require("contas") de novo.

As bibliotecas que já vêm prontas também são módulos

O string, o math, o table que você já usou são módulos que o próprio lua carrega antes de o seu programa começar. Eles estão no caderninho desde o início:

$ lua -e 'print(require("string") == string, package.loaded.math == math)'
true	true
$ lua -e 'for _, nome in ipairs({"_G", "coroutine", "debug", "io", "math", "os", "package", "string", "table", "utf8"}) do print(nome, package.loaded[nome] ~= nil) end'
_G	true
coroutine	true
debug	true
io	true
math	true
os	true
package	true
string	true
table	true
utf8	true

(O lua -e '…' roda um pedacinho de código direto da linha de comando, sem arquivo.) Por isso require("math") funciona e devolve a mesma tabela math de sempre, sem procurar arquivo nenhum. Você não precisa pedir: elas já estão lá, nas variáveis globais string, math etc.

No editor do guia

A caixa "Experimente" imita a pasta da Ana: as abas viram arquivos na mesma pasta do main.lua, e o require procura nos mesmos lugares, na mesma ordem (conferido: a lista do erro sai idêntica). A diferença é que lá não há nenhuma biblioteca instalada nas pastas do sistema: só o que está nas abas.

5. Três jeitos de escrever o require

local somar = require("contas").somar
print(somar(2, 3))
require "contas"
print(contas)

$ lua curto.lua
carregando o módulo contas...
5
nil
  • require("contas").somar pega a tabela e, na mesma hora, só a função somar dela. Prático quando você só precisa de uma ferramenta.
  • require "contas", sem parênteses: no Lua, uma função chamada com um único texto pode dispensar os parênteses (o mesmo vale para print "oi"). É muito comum ver o require escrito assim.
  • O último print(contas) deu nil, como na seção 2: ninguém guardou a tabela no nome contas. Reparou que a mensagem de carregamento apareceu uma vez só? O segundo require veio do caderninho.
FormaQuando usar
local contas = require("contas")O jeito de sempre: no começo do arquivo, um require por módulo. Use esta.
local contas = require "contas"O mesmo, sem parênteses. Questão de gosto; escolha uma forma e use sempre a mesma.
local somar = require("contas").somarQuando você só precisa de uma função do módulo e quer chamá-la sem o contas. na frente.
require("contas") sozinhoSó para módulos que fazem algo ao carregar e não devolvem nada útil (raro). Para usar as funções, não serve.
Boa prática: os require no topo

Ponha todos os require nas primeiras linhas do arquivo, cada um numa variável local. Quem abrir o arquivo vê logo de quais módulos ele depende, e um nome errado dá erro logo no começo, e não no meio do programa.

O módulo esqueceu o return 
local contas = {}
function contas.somar(a, b) return a + b end

$ lua -e 'local c = require("semret") print(c) print(c.somar(1, 2))'
true
lua: (command line):1: attempt to index a boolean value (local 'c')
stack traceback:
	(command line):1: in main chunk
	[C]: in ?

O arquivo foi achado e rodou sem erro, mas não devolveu nada. Nesse caso o require devolve true (quer dizer só "carreguei"). O primeiro print mostrou esse true; o segundo tentou pegar .somar de um booleano: "tentar indexar um valor booleano (a local c)". Como consertar: a última linha do módulo tem de ser return contas. Quando você vir attempt to index a boolean value logo depois de um require, desconfie disso.

Erro de sintaxe dentro do módulo 
local contas = {}
function contas.somar(a, b)
  return a + b
return contas

$ lua -e 'local c = require("quebrado")'
lua: error loading module 'quebrado' from file './quebrado.lua':

Chamou uma função que o módulo não tem 
local contas = require("contas")
print(contas.subtrair(10, 3))

$ lua erro1.lua
carregando o módulo contas...
lua: erro1.lua:2: attempt to call a nil value (field 'subtrair')
stack traceback:
	erro1.lua:2: in main chunk
	[C]: in ?

"Tentar chamar um valor nil (o campo subtrair)". A tabela contas existe, mas não tem nada no campo subtrair. Ou o nome está errado (somar? Somar?), ou a função não existe no módulo. Como descobrir o que tem lá dentro: liste as chaves da tabela, em ordem (veja pairs e table.sort):

local c = require("contas")
local nomes = {}
for k in pairs(c) do nomes[#nomes + 1] = k end
table.sort(nomes)
print(table.concat(nomes, ", "))

$ lua nomes.lua
carregando o módulo contas...
desconto, somar
O erro acontece dentro do módulo 
local contas = require("contas")
print(contas.somar(10, "três"))

$ lua erro2.lua
carregando o módulo contas...
lua: ./contas.lua:5: attempt to add a 'number' with a 'string'
stack traceback:
	[C]: in metamethod 'add'
	./contas.lua:5: in field 'somar'

A primeira linha aponta para ./contas.lua:5, o return a + b do módulo: "tentar somar um número com um texto". Mas o culpado não é o módulo! Leia o rastro de cima para baixo: o erro foi na linha 5 do contas.lua, dentro da função somar (in field 'somar'), que foi chamada pela linha 2 do erro2.lua. Foi lá que alguém passou "três" por extenso. Como consertar: quando o erro aponta para um módulo que já funcionava, desça no rastro até achar o seu arquivo.

Missão final: o caixa da padaria

Missão: o programa do caixa soma os itens com o módulo contas, mas não roda: leia a mensagem de erro e conserte o nome do módulo (olhe o nome da aba). Depois, aplique 10% de desconto no total com contas.desconto, para aparecer Total com desconto: R$ 27.00.

local contas = require("Contas")

local precos = {12.5, 8, 9.5}
local total = 0
for _, p in ipairs(precos) do
  total = contas.somar(total, p)
end
print(string.format("Total: R$ %.2f", total))
-- mostre aqui o total com 10% de desconto

local contas = {}

function contas.somar(a, b)
  return a + b
end

function contas.desconto(preco, porcento)
  return preco - preco * porcento / 100
end

return contas

local contas = require("contas")

local precos = {12.5, 8, 9.5}
local total = 0
for _, p in ipairs(precos) do
  total = contas.somar(total, p)
end
print(string.format("Total: R$ %.2f", total))
print(string.format("Total com desconto: R$ %.2f", contas.desconto(total, 10)))

A soma dá R$ 30,00, e 10% de 30 são 3: sobra R$ 27,00. O %.2f do string.format mostra o número com duas casas, o jeito de escrever dinheiro.

Resumo

  • Um módulo é um arquivo .lua que, no fim, devolve uma tabela (return contas) com as suas funções.
  • local contas = require("contas") procura o arquivo contas.lua, roda, e guarda a tabela devolvida. O nome vai sem .lua, e um ponto no nome quer dizer pasta.
  • O require não cria variáveis sozinho: guarde o resultado numa local.
  • Cada módulo roda uma vez só: o resultado fica em package.loaded, e todo require seguinte devolve a mesma tabela.
  • string, math, table e as outras bibliotecas padrão são módulos que já vêm carregados.
  • No erro module 'x' not found, procure a linha no file './x.lua': confira o nome e a pasta de onde você rodou o lua.
