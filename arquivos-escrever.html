Lua Escrevendo Arquivos

Ler arquivos que alguém já escreveu é metade da história. A outra metade é o seu programa guardar o que fez: a lista de compras que a Ana montou, o relatório do estoque da lojinha, as vendas do dia, as notas da turma num formato que a planilha abre. Para isso existe o f:write ("escrever"), o irmão do f:read que você viu em Lendo Arquivos.

Você vai aprender
  • Como abrir um arquivo para escrita e gravar linhas com f:write, e por que o \n é com você.
  • Como escrever vários valores (textos e números) numa chamada só, e encadear chamadas: f:write(…):write(…).
  • Como gravar uma lista inteira com um laço, uma tabela alinhada com string.format e um arquivo CSV.
  • A diferença, na prática, entre o modo "w" (recomeça) e o "a" (acrescenta).
  • Quando o texto chega de verdade ao disco: f:flush() e f:close().
  • Os erros reais: escrever true ou nil, escrever num arquivo fechado, e o print que não vai para o arquivo.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), em /home/ana. Depois de cada um, o comando cat do terminal mostra o que ficou gravado no arquivo.

A ideia: escrever no caderno é diferente de falar

Quando a Ana dita a lista de compras em voz alta, cada item sai numa "linha" sozinho, porque ela respira entre um e outro. No caderno, não: se ela escrever arroz, feijão e ovos sem pular de linha, fica tudo grudado: arrozfeijãoovos. Quem pula a linha é a mão dela.

No Lua é igual. O print é a fala: cada print termina a linha sozinho. O f:write é a mão no caderno: escreve exatamente o que você mandou, nem um caractere a mais. Para pular de linha, você manda o \n (a quebra de linha; veja Caracteres de Escape). É a mesma regra do io.write, que escreve na tela.

1. O primeiro arquivo gravado

local f = assert(io.open("lista.txt", "w"))
f:write("arroz\n")
f:write("feijão\n")
f:write("ovos\n")
f:close()
print("Lista gravada.")
io.open("lista.txt", "w")
Abre para escrever ("w", de write). Se a lista.txt não existe, é criada; se existe, é esvaziada antes (veja os modos em Abrindo Arquivos).
assert(…)
Se não der para abrir (pasta que não existe, sem permissão), o programa para com a mensagem do motivo, em vez de seguir sem arquivo.
f:write("arroz\n")
Escreve o texto no arquivo. O \n no fim é a quebra de linha: sem ele, o próximo item continuaria na mesma linha.
f:close()
Fecha o arquivo e garante que tudo o que foi escrito chegou ao disco (a seção 6 explica por que isso importa).
print("Lista gravada.")
Este vai para a tela, não para o arquivo. É só um aviso para quem rodou o programa.
$ lua primeiro.lua
Lista gravada.
$ cat lista.txt
arroz
feijão
ovos

Na tela, só o aviso. O conteúdo foi para o arquivo, e o cat mostra que ele ficou do jeito que o programa mandou: três linhas.

Sem o \n

Os mesmos três write, sem a quebra de linha:

local f = assert(io.open("lista.txt", "w"))
f:write("arroz")
f:write("feijão")
f:write("ovos")
f:close()

$ lua sem_enter.lua
$ cat lista.txt
arrozfeijãoovos                  « sem Enter no fim, o prompt do terminal aparece grudado aqui

Tudo grudado, como no caderno. E como nem a última linha termina com \n, no terminal o prompt seguinte aparece colado no ovos. Arquivo de texto bem-feito termina cada linha (inclusive a última) com \n.

2. Vários valores de uma vez, e números

O f:write aceita quantos valores você quiser, separados por vírgula. Ele escreve um logo depois do outro, sem espaço entre eles (o print poria um TAB). Números também valem; o Lua os transforma em texto:

local f = assert(io.open("pedido.txt", "w"))
local item, quantidade, preco = "pão francês", 10, 0.75
f:write("Item: ", item, "\n")
f:write("Quantidade: ", quantidade, "\n")
f:write("Preço: ", preco, "\n")
f:write("Total: ", quantidade * preco, "\n")
f:close()

$ lua varios.lua
$ cat pedido.txt
Item: pão francês
Quantidade: 10
Preço: 0.75
Total: 7.5

Cada f:write juntou três pedaços: o rótulo, o valor e o \n. O quantidade * preco foi calculado antes de ser escrito (7.5). Repare que o total saiu como 7.5, não como 7.50: o Lua escreve o número do jeito mais curto. Para dinheiro com duas casas, use o string.format da seção 4.

Só textos e números

O f:write só aceita textos e números. Um true, um nil ou uma tabela param o programa (a seção Quando dá errado mostra a mensagem). Para escrever outros valores, transforme em texto antes com tostring(valor) (veja Conversão).

Encadeando: f:write(…):write(…)

Quando dá certo, o f:write devolve o próprio arquivo. Por isso dá para emendar um :write no outro:

local f = assert(io.open("recado.txt", "w"))
print(f:write("Oi, "))
f:write("Bia! "):write("Não esquece "):write("o bolo.\n")
f:close()

$ lua encadeado.lua
file (0x561520c40300)
$ cat recado.txt
Oi, Bia! Não esquece o bolo.

O print(f:write("Oi, ")) mostrou o que o write devolve: um file (0x…), o mesmo arquivo f (o número é um endereço de memória e muda a cada execução). Na linha seguinte, o primeiro :write devolve o f, o segundo :write é chamado nele, e assim por diante. O resultado é o mesmo de três linhas de f:write, ou de um só f:write("Bia! ", "Não esquece ", "o bolo.\n"). Use o que ficar mais fácil de ler.

Quando dá errado (o disco encheu, o arquivo foi aberto só para leitura), o f:write não para o programa: devolve nil, a mensagem, o código do erro e, no Lua 5.5, quantos bytes chegaram a ser escritos. Para não deixar passar, dá para embrulhar num assert: assert(f:write("texto\n")).

3. Gravando uma lista inteira

A lista de compras da Ana está numa tabela (veja Tabelas como Listas). Um for com ipairs passa por cada item e escreve uma linha:

local compras = {"arroz", "feijão", "ovos", "café"}
local f = assert(io.open("lista.txt", "w"))
for i, item in ipairs(compras) do
  f:write(i, ". ", item, "\n")
end
f:close()
print("Gravei " .. #compras .. " itens.")

$ lua lista_tabela.lua
Gravei 4 itens.
$ cat lista.txt
1. arroz
2. feijão
3. ovos
4. café

O arquivo é aberto uma vez, antes do laço, e fechado uma vez, depois dele. Dentro do laço, só o write. Abrir com "w" dentro do laço seria um erro: a cada volta o arquivo seria apagado, e só o último item sobraria.

4. Uma tabela alinhada com string.format

A Ana quer um relatório do estoque da lojinha, com colunas alinhadas, para imprimir e colar na parede. O string.format monta cada linha com largura fixa, e o f:write grava:

local produtos = {
  {nome = "arroz", qtd = 12, preco = 6.5},
  {nome = "feijão", qtd = 8, preco = 8.9},
  {nome = "café", qtd = 5, preco = 18.75},
}
local f = assert(io.open("estoque.txt", "w"))
f:write(string.format("%-8s %5s %9s\n", "Produto", "Qtd", "Preço"))
for _, p in ipairs(produtos) do
  f:write(string.format("%-8s %5d %9.2f\n", p.nome, p.qtd, p.preco))
end
f:close()
%-8s
Um texto, ocupando 8 posições, encostado à esquerda (o -).
%5d
Um número inteiro, ocupando 5 posições, encostado à direita.
%9.2f
Um número com 2 casas decimais, ocupando 9 posições: o jeito de escrever dinheiro (6.50, e não 6.5).
\n
A quebra de linha vai dentro do formato, no fim.
$ lua estoque.lua
$ cat estoque.txt
Produto    Qtd    Preço
arroz       12      6.50
feijão      8      8.90
café        5     18.75

Quase perfeito, mas olhe bem: as linhas do feijão e do café ficaram uma posição para a esquerda, e o título Preço também. O culpado é o acento. O string.format conta bytes, não letras: "feijão" tem 6 letras e 7 bytes (o "ã" ocupa 2), então ele achou que já tinha 7 dos 8 lugares preenchidos e pôs um espaço só. Com "arroz", sem acento, deu certo. É a mesma história do # que conta bytes; o que fazer com isso está em Acentos e a Biblioteca utf8. Para um relatório sem acento nos nomes (ou para um arquivo que outro programa vai ler), o string.format resolve sozinho.

5. Um arquivo CSV para a planilha

CSV (de comma-separated values, "valores separados por vírgula") é um arquivo de texto em que cada linha é uma linha da planilha e as colunas se separam por um caractere combinado. No Brasil, como a vírgula é usada nos números decimais, as planilhas costumam usar o ponto e vírgula:

local turma = {
  {"Ana", 9.5},
  {"Bia", 7},
  {"Caio", 8.25},
}
local f = assert(io.open("notas.csv", "w"))
f:write("nome;nota\n")
for _, aluno in ipairs(turma) do
  f:write(aluno[1], ";", aluno[2], "\n")
end
f:close()

$ lua csv.lua
$ cat notas.csv
nome;nota
Ana;9.5
Bia;7
Caio;8.25

A primeira linha é o cabeçalho (os nomes das colunas). Esse arquivo abre no LibreOffice Calc ou no Excel como uma planilha de duas colunas. (O separador decimal que a planilha espera depende da configuração dela: com o idioma em português, ela pode querer 9,5 em vez de 9.5. Ler um CSV de volta é parte do Projeto: Notas da Turma.)

6. "w" recomeça, "a" acrescenta

A Ana vende bolos e quer anotar cada venda num arquivo, sem perder as anteriores. É o modo "a" (append, "acrescentar"): o que você escreve vai para o fim do arquivo, e o que já estava lá fica.

local f = assert(io.open("vendas.txt", "a"))
f:write("bolo de cenoura;25\n")
f:close()

Ela rodou o programa três vezes, uma para cada bolo vendido:

$ lua vendas.lua
$ lua vendas.lua
$ lua vendas.lua
$ cat vendas.txt
bolo de cenoura;25
bolo de cenoura;25
bolo de cenoura;25

Três execuções, três linhas. Na primeira vez, o arquivo não existia, e o "a" o criou. Com "w" no lugar do "a", o arquivo terminaria com uma linha só, por mais vezes que o programa rodasse: cada execução apagaria a anterior.

7. Quando o texto chega ao disco: f:flush()

Escrever no disco é lento comparado com o resto do programa. Por isso o f:write não vai ao disco a cada chamada: ele junta o texto num pedaço da memória (um buffer, "reservatório") e só leva tudo de uma vez quando o buffer enche, quando você fecha o arquivo, ou quando você pede com f:flush() ("descarregar"). Este programa mostra isso acontecendo. Ele escreve com f e, sem fechar, lê o mesmo arquivo por outra variável, g:

local f = assert(io.open("teste.txt", "w"))
f:write("linha importante\n")

local g = assert(io.open("teste.txt", "r"))
print("antes do flush: [" .. g:read("a") .. "]")

f:flush()
g:seek("set")
print("depois do flush: [" .. g:read("a") .. "]")

g:close()
f:close()

$ lua flush.lua
antes do flush: []
depois do flush: [linha importante
]

Antes do flush, o arquivo no disco ainda estava vazio: a linha importante esperava no buffer. Depois do f:flush(), ela estava lá. (O g:seek("set") põe o marcador de leitura de volta no começo; veja Lendo Arquivos.)

Na prática:

  • O f:close() faz o flush sozinho. Fechando o arquivo, você não precisa se preocupar.
  • Quando o programa termina normalmente (ou com um erro comum), o Lua também fecha e descarrega os arquivos abertos.
  • O f:flush() é para programas que ficam muito tempo rodando com o arquivo aberto (um registro que recebe uma linha a cada minuto): sem ele, se o computador desligar de repente, o que estava no buffer se perde.

Formas diferentes de escrever as mesmas linhas

As quatro formas abaixo gravam a mesma coisa no arquivo (Ana;9.5 e a quebra de linha):

local nome, nota = "Ana", 9.5
local f = assert(io.open("formas.txt", "w"))

f:write(nome, ";", nota, "\n")                      -- 1) vários valores
f:write(nome .. ";" .. nota .. "\n")                 -- 2) juntando com ..
f:write(nome):write(";"):write(nota):write("\n")     -- 3) encadeado
f:write(string.format("%s;%.1f\n", nome, nota))      -- 4) string.format

f:close()

$ lua formas.lua
$ cat formas.txt
Ana;9.5
Ana;9.5
Ana;9.5
Ana;9.5
FormaQuando usar
f:write(a, b, c)O jeito mais comum: rápido e claro
f:write(a .. b .. c)Funciona, mas cria um texto novo só para escrever; e o .. com nil dá erro antes de chegar ao arquivo
f:write(a):write(b)Quando os pedaços vêm de lugares diferentes do código, ou para escrever "em cascata"
f:write(string.format(…))Quando o número precisa de formato fixo (dinheiro com 2 casas, colunas alinhadas)
io.output(nome) + io.write(…)Para mandar o io.write de um programa inteiro para um arquivo (veja a nota abaixo)
io.output: trocar o destino do io.write

O io.write escreve na "saída atual", que normalmente é a tela. O io.output("saida.txt") troca a saída atual para um arquivo; o io.output(io.stdout) volta para a tela (io.stdout é a tela, a "saída padrão"):

io.output("saida.txt")
io.write("escrito com io.write\n")
io.close()
io.output(io.stdout)
io.write("de volta na tela\n")

$ lua io_output.lua
de volta na tela
$ cat saida.txt
escrito com io.write

O io.close() sem argumento fecha a saída atual (o saida.txt). É prático em programas pequenos, mas o f:write com um arquivo seu é mais claro: quem lê o código vê para onde cada linha vai. E o print não muda: ele sempre escreve na tela.

Quando dá errado

Escreveu um true 
local f = assert(io.open("config.txt", "w"))
local som_ligado = true
f:write("som=", som_ligado, "\n")
f:close()

$ lua booleano.lua
lua: booleano.lua:3: bad argument #2 to 'write' (string expected, got boolean)
stack traceback:
	[C]: in method 'write'
	booleano.lua:3: in main chunk
	[C]: in ?

"Argumento ruim nº 2 para o write (esperava uma string, veio um booleano)". O argumento nº 2 é o som_ligado (o nº 1 é o "som="). O f:write não converte true e false em texto. Como consertar: f:write("som=", tostring(som_ligado), "\n"), que grava som=true.

Escreveu um campo que não existe (nil) 
local f = assert(io.open("contato.txt", "w"))
local contato = {nome = "Bia"}
f:write("Nome: ", contato.nome, "\n")
f:write("Telefone: ", contato.telefone, "\n")
f:close()

$ lua nil_write.lua
lua: nil_write.lua:4: bad argument #2 to 'write' (string expected, got nil)
stack traceback:
	[C]: in method 'write'
	nil_write.lua:4: in main chunk
	[C]: in ?
$ cat contato.txt
Nome: Bia
Telefone:                        « e o arquivo terminou aqui, sem o Enter

O contato não tem telefone, então contato.telefone é nil. Repare no arquivo: o write escreve os valores na ordem e só reclamou ao chegar no segundo; o Telefone: já tinha sido gravado. O arquivo ficou pela metade. Como consertar: dê um valor para quando faltar: contato.telefone or "(sem telefone)" (veja O Truque do and/or).

Escreveu depois de fechar 
local f = assert(io.open("lista.txt", "w"))
f:write("arroz\n")
f:close()
f:write("feijão\n")

$ lua fechado.lua
lua: fechado.lua:4: attempt to use a closed file
stack traceback:
	[C]: in method 'write'
	fechado.lua:4: in main chunk
	[C]: in ?

"Tentativa de usar um arquivo fechado". O close veio cedo demais. Como consertar: o f:close() é sempre a última coisa feita com o arquivo; num laço, ele vai depois do end.

Usou print e o arquivo ficou vazio 
local f = assert(io.open("lista.txt", "w"))
print("arroz")
f:close()

$ lua print_errado.lua
arroz
$ ls -l lista.txt
-rw-rw-r-- 1 ana ana 0 Oct 18 16:43 lista.txt

Nenhuma mensagem de erro, mas o arroz apareceu na tela, e o arquivo tem 0 bytes (e a lista antiga sumiu, por causa do "w"). O print não sabe nada do f: ele sempre escreve na tela. Como consertar: f:write("arroz\n").

Resumo

  • Abra com "w" para escrever do zero ou com "a" para acrescentar no fim; feche com f:close() quando terminar.
  • f:write escreve exatamente o que recebe: sem espaço entre os valores e sem pular linha. O "\n" é com você.
  • Aceita textos e números, vários de uma vez (f:write(nome, ";", nota, "\n")). true, false e nil dão erro: use tostring ou um valor padrão.
  • Ele devolve o próprio arquivo, por isso dá para encadear: f:write("a"):write("b").
  • Para gravar uma lista, abra uma vez antes do laço, escreva dentro e feche depois. Para formatos fixos, string.format (que conta bytes, não letras).
  • O texto fica num buffer até o close (ou o f:flush()). O print sempre vai para a tela, nunca para o arquivo.
