Lua global 5.5

Desde o começo do guia, você viu que no Lua uma variável sem local vira global sozinha, e que isso é perigoso: um erro de digitação (totl no lugar de total) cria uma variável nova em silêncio, e o programa dá a resposta errada sem reclamar. O Lua 5.5 trouxe uma ferramenta nova contra isso: a declaração global. Com ela você diz ao Lua quais globais existem, e a partir daí qualquer outro nome solto vira erro, antes mesmo de o programa rodar.

Você vai aprender
  • Como o Lua sempre tratou os nomes soltos (o "global por padrão") e o que muda com global.
  • As formas da declaração: global nome, global nome = valor, global function, global * e global<const> *.
  • Por que, depois de um global, até o print precisa ser declarado, e como fazer isso.
  • Como o global pega erros de digitação, e até onde vale uma declaração (o bloco).
  • As mensagens reais: variable 'x' not declared, global 'x' already defined e a do Lua 5.4.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com lua arquivo.lua. As comparações com versões antigas rodaram no lua5.4 e no luajit da mesma máquina. Antes desta aula, veja local e <const>.

A ideia: a lista de convidados

Imagine a festa de aniversário da Ana. Existem dois jeitos de cuidar da porta:

  • Festa aberta: entra quem chegar. É prático, mas se alguém chega com o nome errado no crachá, ninguém percebe.
  • Festa com lista: o porteiro tem uma lista de convidados. Chegou alguém que não está na lista? Ele barra na porta, e avisa o nome.

Um programa Lua sem nenhuma declaração global é a festa aberta: todo nome que não é local entra como global. Quando você escreve um global, o Lua vira o porteiro com lista: dali para a frente, só passam os nomes declarados (locais ou globais). O resto é barrado, com o nome na mensagem.

1. Como sempre foi: global por padrão

O manual do Lua 5.5 explica assim: todo arquivo começa com uma declaração invisível, global *, que quer dizer "todos os nomes soltos são globais". É por isso que este programa, com um erro de digitação, roda sem reclamar:

total = 0
local precos = { 4.50, 12.90, 3.25 }
for i = 1, #precos do
  totl = total + precos[i]
end
print(string.format("Total: R$ %.2f", total))

$ lua soma.lua
Total: R$ 0.00

O certo era R$ 20.65. A linha 4 escreveu em totl, uma global nova criada sem querer, e o total ficou em zero. Num programa de 500 linhas, achar esse erro leva tempo.

2. A primeira declaração

Agora o mesmo tipo de programa, com uma declaração no topo:

global total = 10
print(total)

$ lua g1.lua
lua: g1.lua:2: variable 'print' not declared

Surpresa: o erro é no print! "Variável 'print' não declarada". Linha por linha:

global total = 10
Declara a global total e dá a ela o valor 10. Mas, ao mesmo tempo, essa linha desliga a declaração invisível global *. A partir dela, o Lua só aceita nomes declarados.
print(total)
total está declarado. print, não. E o print também é uma global (é uma função guardada na tabela das globais; veja _G e _ENV).
lua: g1.lua:2: variable 'print' not declared
O erro aponta a linha 2 e o nome barrado. Não há stack traceback: como o erro do <const>, este é descoberto na compilação, quando o Lua lê o arquivo antes de rodar. Nada do programa chegou a rodar.

Para consertar, declare também o print. Uma declaração aceita vários nomes, separados por vírgula, e pode ser escrita em várias linhas:

global print
global total = 10
print(total)

$ lua g2.lua
10

Missão: rode e veja o erro variable 'print' not declared. Conserte sem apagar a declaração do total: declare as globais que faltam. (Dica: são duas, e uma delas não é o print. Rode de novo e leia a mensagem.)

global total = 10
print(string.format("Total: %d", total))

global print, string
global total = 10
print(string.format("Total: %d", total))

A segunda que faltava é a string: a biblioteca string também é uma global (uma tabela com as funções de texto). Depois de um global, tudo o que vem das globais precisa estar declarado: print, string, math, io, table, ipairs, tostring…

3. O porteiro pegando o erro de digitação

Agora volte ao programa da seção 1, com as declarações no topo:

global print, string
global total = 0
local precos = { 4.50, 12.90, 3.25 }
for i = 1, #precos do
  totl = total + precos[i]
end
print(string.format("Total: R$ %.2f", total))

$ lua g3.lua
lua: g3.lua:5: variable 'totl' not declared

Pronto: em vez de uma resposta errada, o Lua mostra a linha e o nome do erro de digitação. E como é um erro de compilação, ele aparece mesmo que essa linha fique dentro de um if que quase nunca roda. Dá até para conferir sem rodar, com o luac -p:

$ luac -p g3.lua
luac: g3.lua:5: variable 'totl' not declared

Repare que precos e i não precisaram de nada: eles são locais, e variáveis locais (inclusive as do for e os parâmetros de função) já são "declaradas" por natureza. A lista do porteiro só vale para os nomes que não são locais. O mesmo vale dentro de funções:

global print
local function soma(a, b)
  local r = a + b
  return resultado
end
print(soma(1, 2))

$ lua g16.lua
lua: g16.lua:4: variable 'resultado' not declared

Sem o global print da linha 1, esse programa rodaria e mostraria nil (a global resultado não existe). Com ele, o Lua achou que o certo era return r.

4. As formas da declaração

global nome: só declarar

Diz que o nome é uma global, sem mudar o valor dela. Se ela não existia, continua nil até alguém dar um valor:

global print
global total
print(total)
total = 3
print(total)

$ lua g20.lua
nil
3

(Diferente do local x, que sempre começa em nil: o global x deixa a global com o valor que ela já tinha.)

global nome = valor: declarar e criar

Declara e dá o valor inicial. Mas atenção: o manual diz que essa forma dá erro se a global já existir (já tiver um valor diferente de nil). É uma proteção: você está dizendo "esta global é nova", e o Lua confere:

contador = 5
global print
global contador = 1
print(contador)

$ lua g8.lua
lua: g8.lua:3: global 'contador' already defined
stack traceback:
	g8.lua:3: in main chunk
	[C]: in ?

"Global 'contador' já definida". Este erro tem stack traceback: ele é de execução. Na compilação, o Lua não tem como saber se a global já existe; só descobre ao rodar a linha 3. Se você só quer mudar o valor de uma global que já existe, declare com global contador e depois atribua com contador = 1.

global function: declarar uma função global

global print
global function dobro(x)
  return 2 * x
end
print(dobro(21))

$ lua g10.lua
42

É o par do local function. Ela também conta como "global nova": se já existisse uma global dobro, daria global 'dobro' already defined (no lab, com um function dobro(x) … end antes, deu exatamente isso, na linha do global function).

global <const>: globais que não mudam

O atributo <const> da aula <const> também funciona com globais, depois do nome ou antes da lista:

global print, tostring
global <const> PI_APROX, NOME_LOJA = 3.14, "Padaria"
print(PI_APROX, NOME_LOJA)

$ lua g18.lua
3.14	Padaria

E tentar mudar dá o erro de sempre, na compilação: com global VERSAO <const> = "1.0" e depois VERSAO = "2.0", o lab mostrou lua: g15.lua:2: attempt to assign to const variable 'VERSAO'. (O <close>, ao contrário, não vale para globais: veja a aula <close>.)

global * e global<const> *: todos os outros

O asterisco quer dizer "todos os nomes que eu ainda não declarei". global * devolve o comportamento antigo (tudo é global). Mais útil é global<const> *: todos os outros nomes são globais só para leitura. Você pode usar print, math e companhia à vontade, mas só pode escrever nas globais que declarou. É o exemplo do próprio manual:

global X
global<const> *
print(math.pi)
X = 1
Y = 1

$ lua g6.lua
lua: g6.lua:5: attempt to assign to const variable 'Y'

Linha 3: print e math são lidos, e pode. Linha 4: X foi declarado sem <const>, e pode receber valor. Linha 5: Y caiu no *, que é só leitura: erro (de compilação, por isso nem o math.pi chegou a aparecer). É uma ótima primeira linha para um programa novo: não precisa listar print, string, io… e nenhuma linha consegue criar uma global por engano, nem estragar uma de verdade (com global<const> *, print = nil dá attempt to assign to const variable 'print').

EscritaO que declara
global a, ba e b são globais (o valor não muda)
global a = 1declara e cria; erro se a já tiver valor
global function f() … enddeclara e cria a função global f
global a <const> = 1 / global <const> a, b = 1, 2globais só para leitura
global *todo nome não declarado é global (o padrão de sempre)
global<const> *todo nome não declarado é global só para leitura

5. Até onde vale uma declaração: o bloco

Uma declaração global vale do ponto onde foi escrita até o fim do bloco onde está (como um local; veja Escopo e Blocos). Fora do bloco, o Lua volta ao que valia antes. O manual traz este exemplo:

X = 1
do
  global Y
  Y = 1
  X = 1
end
X = 2

$ lua g4.lua
lua: g4.lua:5: variable 'X' not declared

Na linha 1, ainda vale o global * invisível: X = 1 pode. Dentro do do … end, o global Y ligou o porteiro: Y pode, X não (linha 5). Tirando a linha 5, o programa roda, e a linha 7 (X = 2), já fora do bloco, volta a poder:

X = 1
do
  global Y
  Y = 1
end
X = 2
print(X, Y)

$ lua g5.lua
2	1

O contrário também acontece: uma declaração feita dentro de um bloco não vale fora dele:

global print
if true then
  global x = 1
end
print(x)

$ lua g25.lua
lua: g25.lua:5: variable 'x' not declared

A global x até foi criada (o = 1 rodaria), mas o nome só foi declarado dentro do if. Por isso, ponha as declarações global no topo do arquivo. Com global print, x na linha 1 e só x = 1 dentro do if, o lab mostrou 1.

No modo interativo

No > do Lua, cada linha que você digita é compilada separada (como um arquivo pequeno). Uma declaração vale só para a própria linha:

$ lua
Lua 5.5.0  Copyright (C) 1994-2025 Lua.org, PUC-Rio
> global x = 1
> x
1
> print(x)
1
> global print; global y = 2; print(y)
2

Na linha do print(x), o porteiro já tinha ido embora (ela é outro pedaço), e o print funcionou sem declarar.

6. Um exemplo completo

Um programa curto da padaria, com tudo declarado no topo: as bibliotecas que ele usa, uma constante e um contador global:

global print, tostring, string
global <const> TAXA = 0.1
global pedidos = 0
local function registrar(valor)
  pedidos = pedidos + 1
  return valor * (1 + TAXA)
end
print(string.format("%.2f", registrar(20)))
print(pedidos)

$ lua g27.lua
22.00
1

Quem lê as três primeiras linhas já sabe tudo o que o programa usa "de fora" e tudo o que ele cria de global. Esse é o outro ganho do global, além de pegar erros: o código se documenta.

global não substitui o local

A regra do guia continua a mesma: local sempre que der. Uma global é vista pelo programa inteiro (e pelos módulos que ele carrega), e qualquer parte pode mudá-la. O global serve para deixar explícitas as poucas globais de que você realmente precisa, e para pegar os nomes errados.

Formas diferentes de fazer a mesma coisa

Três jeitos de começar um programa no Lua 5.5:

-- 1) sem nada: tudo o que não é local é global, para ler e escrever
-- 2) global<const> *: lê qualquer global, escreve só nas declaradas
global contador
global<const> *
-- 3) lista fechada: só passam os nomes da lista
-- global print, string, contador
SituaçãoQual usar
Programa que precisa rodar também no Lua 5.4, 5.1 ou LuaJITNenhuma declaração (e local sempre)
Programa novo, só para o 5.5, e você quer pegar erros de digitação sem listar tudoglobal<const> * no topo, com as suas globais declaradas antes
Um módulo ou programa em que você quer saber exatamente o que vem de foraglobal print, string, … (a lista fechada)

O manual avisa: a declaração global é só sintática (fora o = valor, ela não faz nada ao rodar). Ela não protege as globais de verdade: outro arquivo, ou um acesso pela tabela das globais, ainda pode mudá-las. Com global print, _G e global VERSAO <const> = "1.0", a linha _G.VERSAO = "2.0" funcionou no lab, e o segundo print(VERSAO) mostrou 2.0. A tabela _G é assunto da próxima aula: _G e _ENV.

Quando dá errado

Esqueceu de declarar uma biblioteca 
global print
local nome = io.read()
print("Olá, " .. nome)

Resultado: variable 'io' not declared na linha 2. Toda biblioteca padrão (io, os, string, table, math, utf8, coroutine) e toda função solta (print, type, tostring, tonumber, pairs, ipairs, pcall, error, setmetatable…) é global. Como consertar: global print, io. Com isso, echo Ana | lua g21.lua mostrou Olá, Ana. Se a lista ficar comprida, use global<const> *.

Criou com = uma global que já existia 
$ lua g8.lua
lua: g8.lua:3: global 'contador' already defined
stack traceback:
	g8.lua:3: in main chunk
	[C]: in ?

Veja a seção 4. global x = valor é para globais novas. Para mudar uma que já existe: global x e, em outra linha, x = valor.

Declarou o _ENV como global 
global print, _ENV
global VERSAO <const> = "1.0"
print(VERSAO)

$ lua g14.lua
lua: g14.lua:2: _ENV is global when accessing variable 'VERSAO'

"_ENV é global ao acessar a variável 'VERSAO'". O _ENV é especial: ele é a tabela onde moram as globais (aula _G e _ENV), e por isso ele mesmo não pode ser uma global. Nunca ponha _ENV numa declaração global; se precisar da tabela das globais, declare o _G.

Rodou o programa num Lua antigo 
$ lua5.4 g2.lua
lua5.4: g2.lua:1: syntax error near 'print'
$ luajit g2.lua
luajit: g2.lua:1: '=' expected near 'print'

No Lua 5.4 e no LuaJIT, global é um nome comum, como total. Eles leem global print como "a variável global seguida da variável print", o que não faz sentido: "erro de sintaxe perto de 'print'" (5.4), "era esperado '=' perto de 'print'" (LuaJIT). Programas com global só rodam no Lua 5.5 ou mais novo. Veja as diferenças entre as versões.

Um programa antigo usa global como nome

O manual do 5.5 diz que global é uma palavra reservada (como if e end), com uma opção de compilação, LUA_COMPAT_GLOBAL, que a deixa ser um nome comum. No Lua 5.5.0 essa opção vem ligada: está no luaconf.h da distribuição oficial, e no do Ubuntu também. Por isso, no lab, programas antigos com uma variável chamada global continuaram rodando:

$ cat g17.lua
local global = 1
print(global)
$ lua g17.lua
1
$ cat g22.lua
global = 5
print(global)
$ lua g22.lua
5

No editor do guia é igual: ele foi compilado com o mesmo luaconf.h do Ubuntu, e o local global = 1 também roda lá. Funciona porque, com essa opção, o Lua só entende global como declaração quando ele vem seguido de um nome, de <, de * ou de function (é o que está no código-fonte do Lua 5.5.0, no arquivo lparser.c); seguido de = ou de (, é um nome comum. Mesmo assim, não use global como nome em código novo: o manual avisa que as opções de compatibilidade vão ser removidas no futuro, e, segundo o manual, num Lua compilado sem ela global é palavra reservada (não deu para conferir no lab: os dois Lua 5.5 do guia têm a opção ligada). Veja também Nomes de Variáveis.

Resumo

  • 5.5 Todo arquivo começa com um global * invisível: nome solto é global. Qualquer outra declaração global desliga isso até o fim do bloco.
  • Dentro do alcance de um global, todo nome tem de ser local ou declarado, inclusive print, string, io… Senão: variable 'x' not declared, na compilação.
  • global x só declara; global x = v e global function x também criam, e dão global 'x' already defined se ela já existir.
  • global<const> * deixa ler qualquer global e escrever só nas declaradas: uma ótima primeira linha para programas novos.
  • A declaração vale até o fim do bloco: ponha-a no topo do arquivo. É só uma regra do compilador; ela não tranca as globais de verdade.
  • O 5.4, o 5.1 e o LuaJIT não conhecem global. E continue usando local sempre que puder.
