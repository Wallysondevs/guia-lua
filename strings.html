Lua strings (textos)

Nomes, recados, endereços, a lista de compras, as mensagens que o programa mostra: quase tudo o que uma pessoa lê é texto. Em programação, um texto se chama string (em inglês, "cordão" ou "fio": uma fileira de caracteres, um atrás do outro, como contas num colar). Você já usou strings desde o primeiro print("Olá, mundo!"). Esta aula é sobre elas.

Você vai aprender
  • Como escrever uma string: aspas duplas ou simples, e quando usar cada uma.
  • O texto vazio ("") e a diferença entre ele e o nil.
  • A diferença entre o texto "10" e o número 10.
  • Que uma string nunca muda: as funções de texto devolvem um texto novo.
  • Como comparar textos: maiúsculas contam, e a "ordem alfabética" do Lua tem surpresas.
  • Os erros reais: aspas sem fechar, aspas dentro de aspas, as aspas curvas do editor de texto, e outros.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com lua arquivo.lua (veja Rodando um Programa). Você pode rodar cada um no editor do guia.

A ideia: o que está entre aspas é "ao pé da letra"

Quando a Ana deixa um bilhete para o filho dizendo escreva "pão" na lista, as aspas avisam: não é para ir buscar pão, é para escrever a palavra pão. No Lua é igual:

  • nome, sem aspas, é uma variável: o Lua vai buscar o valor guardado nela.
  • "nome", com aspas, é um texto: as quatro letras n, o, m, e, ao pé da letra.

As aspas marcam onde o texto começa e onde ele termina. Elas não fazem parte do texto: print("Ana") mostra Ana, sem aspas.

1. Aspas duplas ou simples

No Lua, tanto faz escrever um texto entre aspas duplas (") ou simples (', o apóstrofo). O resultado é exatamente o mesmo:

print("Ana")
print('Ana')
print("Copo d'água")
print('Ela disse "bom dia"')
print("Ana" == 'Ana')
print(type("Ana"), type('Ana'))

$ lua aspas.lua
Ana
Ana
Copo d'água
Ela disse "bom dia"
true
string	string
"Ana" e 'Ana'
As duas formas criam o mesmo texto. A única regra é fechar com a mesma aspa que abriu.
"Copo d'água"
Para um texto que tem apóstrofo dentro, use aspas duplas por fora: o ' do meio vira só mais uma letra.
'Ela disse "bom dia"'
E para um texto com aspas duplas dentro, use simples por fora.
"Ana" == 'Ana'
A comparação dá true: para o Lua, os dois são o mesmo texto (veja Comparações).
type(…)
O tipo de um texto é string, qualquer que seja a aspa (veja type).

E se o texto tiver os dois tipos de aspas, ou uma quebra de linha? Aí entram os caracteres de escape (\", \n), na aula Caracteres de Escape, e os textos longos ([[ … ]]), em Textos Longos.

Escolha uma e seja coerente

Neste guia, usamos aspas duplas como padrão, e as simples só quando o texto tem aspas duplas dentro. Muitos projetos de Lua fazem assim; outros preferem as simples. O importante é não ficar misturando sem motivo (veja Estilo de Código).

print("Ela disse "bom dia"")

print('Ela disse "bom dia"')

2. O texto vazio

Duas aspas sem nada no meio, "", formam o texto vazio: uma string de tamanho zero. Ele é diferente de nil (veja O Valor nil): o texto vazio é uma folha em branco, e o nil é não ter folha nenhuma.

local vazio = ""
local nada = nil
print(type(vazio), #vazio)
print(type(nada))
print(vazio == nil)
print("[" .. vazio .. "]")
print("[" .. " " .. "]")

$ lua vazio.lua
string	0
nil
false
[]
[ ]
  • O texto vazio é do tipo string e tem tamanho 0 (o # mede o tamanho; veja O Operador de Tamanho).
  • vazio == nil dá false: são coisas diferentes.
  • Os colchetes em volta mostram a diferença entre "" (nada entre eles) e " " (um espaço). Na tela, um espaço é invisível; os colchetes são um truque para enxergá-lo.

Uma diferença prática: o texto vazio pode ser concatenado com ..; o nil não (dá attempt to concatenate a nil value; veja Juntando Textos).

3. "10" não é 10

Um número escrito entre aspas é um texto que, por acaso, só tem algarismos. Um texto e um número são coisas diferentes, mesmo quando parecem iguais:

local texto = "10"
local numero = 10
print(type(texto), type(numero))
print(texto == numero)
print(texto + 1, numero + 1)
print(texto .. 1, numero .. 1)
print(tonumber(texto) == numero, tostring(numero) == texto)

$ lua numero_texto.lua
string	number
false
11	11
101	101
true	true
texto == numero → false
O == compara também o tipo: um texto nunca é igual a um número.
texto + 1 → 11
Nas contas, o Lua é camarada: ele converte o texto "10" em número sozinho. Isso se chama coerção.
numero .. 1 → 101
No .., é o contrário: o número vira texto, e os dois são colados.
tonumber / tostring
As funções para converter de propósito: tonumber("10") dá o número 10, e tostring(10) dá o texto "10". Aula própria: Conversão.

Esse assunto importa porque tudo o que vem do teclado (io.read(); veja io.read()) e de arquivos chega como texto. Converta com tonumber antes de comparar com números.

4. Uma string nunca muda

Depois de criado, um texto não muda nunca. Os programadores dizem que as strings do Lua são imutáveis. Parece estranho, porque existem funções como upper ("maiúsculas"); mas olhe o que elas fazem de verdade:

local nome = "ana"
local maiusculo = nome:upper()
print(nome)
print(maiusculo)
nome = nome:upper()
print(nome)

$ lua imutavel.lua
ana
ANA
ANA
nome:upper()
Chama a função upper no texto de nome. Ela não mexe em "ana": ela fabrica um texto novo, "ANA", e o devolve. (O : é um jeito curto de escrever string.upper(nome); as funções de texto têm aula própria: Funções de Texto.)
print(nome) → ana
A prova: depois do upper, nome continua em minúsculas.
nome = nome:upper()
Para a variável passar a ter o texto em maiúsculas, guarde o texto novo nela. O texto antigo, "ana", não foi alterado: a variável é que passou a apontar para outro texto.

Pense na variável como uma etiqueta presa num texto (veja Variáveis). nome = nome:upper() não reescreve o texto: ela descola a etiqueta do "ana" e cola no "ANA".

Missão: o programa chama nome:upper(), mas continua mostrando o nome em minúsculas, porque jogou o resultado fora. Guarde o resultado de volta em nome para ele mostrar ANA LIMA.

local nome = "ana lima"
nome:upper()
print(nome)

local nome = "ana lima"
nome = nome:upper()
print(nome)

Não dá para trocar uma letra

Por ser imutável, uma string não deixa você trocar uma letra no meio. Nem dá para pegar uma letra com colchetes, como numa lista:

local nome = "Ana"
print(nome[1])
print(nome:sub(1, 1))

$ lua indice.lua
nil
A

nome[1] deu nil, sem erro: os colchetes não pegam letras de um texto. Para isso existe o sub ("substring", pedaço do texto): nome:sub(1, 1) é o pedaço que vai da 1ª à 1ª letra (veja Pedaços de Texto). E para "trocar" a primeira letra, monte um texto novo com os pedaços:

local nome = "Ana"
nome = "E" .. nome:sub(2)
print(nome)

$ lua troca2.lua
Ena

nome:sub(2) é o texto da 2ª letra até o fim ("na"), e o .. cola o "E" na frente.

5. Comparando textos

print("Ana" == "Ana")
print("ana" == "Ana")
print("Ana" == "Ana ")
print("abacate" < "banana")
print("Bia" < "ana")
print("10" < "9")
print(10 < 9)
print(("ana"):upper() == ("ANA"):upper())

$ lua comparar.lua
true
false
false
true
true
true
false
true
"ana" == "Ana" → false
Maiúsculas e minúsculas são letras diferentes para o computador.
"Ana" == "Ana " → false
Um espaço a mais no fim também faz diferença. Isso acontece muito com o que a pessoa digita.
"abacate" < "banana" → true
Com < e >, os textos são comparados letra por letra, como na ordem do dicionário: "a" vem antes de "b".
"Bia" < "ana" → true
Surpresa: para o computador, todas as maiúsculas vêm antes de todas as minúsculas. Ele compara os códigos das letras (o "B" é 66, o "a" é 97), não a ordem do dicionário. Letras com acento ficam ainda mais longe.
"10" < "9" → true
Outra surpresa: como textos, "10" vem antes de "9", porque a comparação começa pelo primeiro caractere, e "1" vem antes de "9". Como números, 10 < 9 é false, como esperado.
("ana"):upper() == ("ANA"):upper()
Para comparar sem ligar para maiúsculas, transforme os dois lados em maiúsculas (ou os dois em minúsculas, com lower) antes. Os parênteses em volta de "ana" são obrigatórios para chamar uma função com : num texto escrito direto.
Números guardados como texto se comparam errado

Se as notas da turma vierem de um arquivo como textos ("10", "9", "7"), compará-las com < dá a ordem errada. Converta com tonumber antes de comparar ou ordenar.

Quando dá errado

Esqueceu de fechar as aspas 
print("Olá, Ana)

$ lua aberta.lua
lua: aberta.lua:1: unfinished string near '"Olá, Ana)'

Linha por linha:

lua: aberta.lua:1:
O problema está na linha 1 do arquivo.
unfinished string
"String não terminada": o Lua abriu um texto com " e chegou ao fim da linha sem encontrar outra ".
near '"Olá, Ana)'
"Perto de…": o Lua mostra o texto que ficou aberto. Repare que o ) foi engolido: para o Lua, ele faz parte do texto.

É um erro de sintaxe: o programa nem começa (por isso não há stack traceback). Como consertar: print("Olá, Ana").

Abriu com uma aspa e fechou com outra 
print("Olá, Ana')

$ lua misturada.lua
lua: misturada.lua:1: unfinished string near '"Olá, Ana')'

A mesma mensagem: para um texto aberto com ", o ' é só mais uma letra, e o texto continua aberto. Como consertar: feche com a mesma aspa que abriu.

Quebrou a linha no meio do texto 
local recado = "Comprar pão
e leite"
print(recado)

$ lua multi.lua
lua: multi.lua:1: unfinished string near '"Comprar pão'

Um texto entre aspas não pode atravessar a linha. Como consertar: use "Comprar pão\ne leite" (o \n é a quebra de linha; veja Caracteres de Escape) ou um texto longo, [[Comprar pão / e leite]] (veja Textos Longos).

Aspas iguais dentro do texto 
print("Ela disse "bom dia"")

$ lua dentro.lua
lua: dentro.lua:1: ')' expected near 'bom'

"Era esperado um ) perto de bom". A segunda " fechou o texto "Ela disse ", e o Lua achou que bom fosse um nome solto depois dele, onde deveria vir o ). A mensagem não fala em aspas, mas a causa é essa. Como consertar: 'Ela disse "bom dia"' ou "Ela disse \"bom dia\"".

Aspas curvas, copiadas de um editor de texto

Programas como o Word, o LibreOffice e alguns sites trocam as aspas retas (") por aspas "bonitas", curvas (“ e ”). Quem copia um código de lá e cola no arquivo .lua leva junto as aspas curvas:

print(“Olá”)

$ lua curvas.lua
lua: curvas.lua:1: unexpected symbol near '<\226>'

"Símbolo inesperado perto de <\226>". O Lua só reconhece as aspas retas. A aspa curva, em UTF-8, ocupa 3 bytes, e o primeiro deles vale 226; como o Lua não sabe que caractere é aquele, ele mostra o número do byte entre <\ e >. Como consertar: apague as aspas e digite-as de novo no editor de código (não no editor de texto).

Tentou trocar uma letra com colchetes 
local nome = "Ana"
nome[1] = "E"

$ lua troca.lua
lua: troca.lua:2: attempt to index a string value (local 'nome')
stack traceback:
	troca.lua:2: in main chunk
	[C]: in ?

"Tentativa de indexar (usar colchetes em) um valor do tipo string". Os colchetes com = servem para guardar algo numa tabela, e uma string não é tabela; além disso, ela é imutável. Como consertar: monte um texto novo: nome = "E" .. nome:sub(2) (seção 4).

Comparou um texto com um número 
local idade = "30"
print(idade > 18)

$ lua comp_num.lua
lua: comp_num.lua:2: attempt to compare number with string
stack traceback:
	comp_num.lua:2: in main chunk
	[C]: in ?

"Tentativa de comparar um número com uma string". Com ==, um texto e um número só dão false; com < e >, o programa para. (A mensagem diz "number with string", na ordem contrária à do código, porque o Lua transforma a > b em b < a por dentro.) Como consertar: tonumber(idade) > 18.

Resumo

  • Uma string é um texto entre aspas. Aspas duplas e simples são equivalentes; feche com a mesma que abriu, e use uma para conter a outra.
  • "" é o texto vazio (tamanho 0), diferente de nil.
  • "10" é texto, 10 é número: "10" == 10 é false. Nas contas o Lua converte sozinho; para comparar, use tonumber.
  • Strings são imutáveis: upper, sub e companhia devolvem um texto novo. Para a variável mudar, guarde o resultado: nome = nome:upper().
  • Na comparação, maiúsculas contam, espaços contam, e a ordem é a dos códigos das letras ("Bia" < "ana", "10" < "9").
  • Erros comuns: unfinished string (aspas sem fechar ou quebra de linha), aspas iguais dentro do texto, aspas curvas copiadas (<\226>).
