Lua Funções (function)

Você já usou várias funções sem perceber: print(), io.write(), io.read(), type(), string.rep(). Cada uma é um pedaço de código que alguém escreveu, deu um nome e deixou pronto para usar. Nesta aula você vai fazer o mesmo: criar os seus próprios comandos. Você junta algumas linhas, dá um nome a elas, e depois basta escrever esse nome para que todas rodem de novo, quantas vezes quiser.

Você vai aprender
  • O que é uma função, com a comparação da receita de bolo.
  • A criar uma função com local function … end, e o que é cada parte.
  • A diferença entre definir e chamar uma função (definir não roda nada).
  • Em que ordem o Lua executa um programa que tem funções.
  • Uma função chamando outra, e por que a ordem das definições importa.
  • As três formas de escrever uma função: local function, function (global) e local f = function, e qual usar.
  • Os erros reais: chamar antes de definir (attempt to call a nil value), errar o nome, esquecer os parênteses ou o end.

A ideia: uma receita com nome

A Ana anotou no caderno a receita do bolo de milho da avó. Escrever a receita não faz bolo nenhum: é só uma lista de passos guardada com um título, "Bolo de milho". O bolo só aparece quando alguém pega o caderno e segue a receita. E a mesma receita serve para fazer um bolo hoje, outro no sábado, outro no aniversário: ninguém reescreve os passos a cada vez.

Uma função é isso: um grupo de linhas de código guardado com um nome. São dois momentos diferentes:

Na cozinhaNo LuaO que acontece
Escrever a receita no cadernoDefinir a função, com function … endO Lua guarda os passos com um nome. Nada é executado ainda
Fazer o bolo seguindo a receitaChamar a função: nome()O Lua executa os passos guardados, um por um

"Função", em programação, não tem a ver com a função da matemática da escola (aquela do f(x)), pelo menos por enquanto: pense nela como uma receita com nome.

1. Definindo a primeira função

Toda manhã, o programa da Ana mostra duas mensagens. Vamos guardá-las numa função chamada bom_dia:

local function bom_dia()
  print("Bom dia, Ana!")
  print("O café está pronto.")
end
local
"Local": o nome bom_dia só vale neste arquivo, como uma variável local (aula local × Global). É o jeito recomendado; a seção 6 mostra as outras formas.
function
"Função", em inglês. Avisa ao Lua: "vou criar uma função".
bom_dia
O nome da função, escolhido por você. Segue as mesmas regras dos nomes de variáveis (aula Nomes de Variáveis): letras minúsculas, palavras separadas por _, sem espaços e sem acentos.
()
Os parênteses são obrigatórios, mesmo vazios. Mais adiante, eles vão guardar as informações que a função recebe (aula Parâmetros e Argumentos).
as linhas do meio
O corpo da função: os passos da receita. Tudo o que estiver entre a linha do function e o end pertence à função.
end
"Fim": fecha a função, como fecha o if e o for (aula Sintaxe e Blocos). Quem diz onde a função termina é o end, não o recuo.

Os 2 espaços antes dos print são só para os olhos: o Lua não exige recuo nenhum. Mas eles mostram, de longe, o que está dentro da função, e todo programador Lua escreve assim.

Agora rode o programa:

$ lua so_definir.lua
$                                                  « nenhuma linha de saída

Não apareceu nada. E está certo: o programa só definiu a função. É a receita escrita no caderno. O Lua leu as linhas, guardou-as com o nome bom_dia, chegou ao fim do arquivo e terminou. Ninguém pediu o bolo.

2. Chamando a função

Para executar os passos guardados, você chama a função: escreve o nome dela seguido de parênteses, fora do bloco function … end.

local function bom_dia()
  print("Bom dia, Ana!")
  print("O café está pronto.")
end

bom_dia()

$ lua bom_dia.lua
Bom dia, Ana!
O café está pronto.
bom_dia
O nome da função que você quer executar.
()
Os parênteses são o "faça agora!". É o mesmo jeito de chamar o print(): nome e parênteses. Sem eles, o Lua nem aceita a linha (você vai ver em Quando dá errado).
Uma linha em branco

A linha em branco entre o end e a chamada não é obrigatória. É costume: ela deixa claro onde a função termina e onde o resto do programa começa.

Uma receita, vários bolos

A vantagem aparece quando você chama a função mais de uma vez. Cada chamada executa o corpo inteiro de novo:

local function bom_dia()
  print("Bom dia, Ana!")
  print("O café está pronto.")
end

3. Em que ordem o programa roda

Quem está começando costuma achar que o Lua executa tudo de cima para baixo, inclusive o que está dentro da função. Os números nas mensagens abaixo mostram a ordem de verdade:

print("1. Começou o programa")

local function bom_dia()
  print("3. Dentro da função")
end

print("2. A função foi definida, mas ainda não rodou")
bom_dia()
print("4. A função terminou, o programa continua")

$ lua ordem.lua
1. Começou o programa
2. A função foi definida, mas ainda não rodou
3. Dentro da função
4. A função terminou, o programa continua
  1. O Lua executa a linha 1 e mostra a mensagem 1.
  2. Encontra o local function: guarda o corpo da função com o nome bom_dia e pula para depois do end, sem executar o print de dentro.
  3. Mostra a mensagem 2.
  4. Encontra a chamada bom_dia(): entra na função e executa o corpo dela (mensagem 3).
  5. Quando chega ao end, volta para a linha logo depois da chamada e mostra a mensagem 4.

É como a Ana cozinhando: ela está arrumando a cozinha, para, abre o caderno, faz o bolo seguindo a receita e, quando acaba, volta a arrumar a cozinha de onde parou.

4. Para que serve: escrever uma vez, mudar num lugar só

A padaria do bairro imprime um cabeçalho em cada nota. Sem função, as quatro linhas do cabeçalho apareceriam repetidas no programa a cada nota. Com uma função:

local function cabecalho()
  print(string.rep("=", 30))
  print("   PADARIA PÃO QUENTE")
  print("   Rua das Flores, 120")
  print(string.rep("=", 30))
end

cabecalho()
print("Pão francês  x10   R$ 8,00")
print("Leite        x1    R$ 5,50")
print()
cabecalho()
print("Bolo de milho x1   R$ 18,00")

5. Uma função chamando outra

Dentro do corpo de uma função você pode escrever qualquer coisa que escreveria fora dela, inclusive a chamada de outra função:

local function linha()
  print(string.rep("-", 20))
end

local function aviso()
  linha()
  print("Loja fechada às 18h")
  linha()
end

aviso()

$ lua aviso.lua
--------------------
Loja fechada às 18h
--------------------

O programa chama aviso(); o aviso chama linha(), que mostra os tracinhos e volta; o aviso mostra a mensagem; chama linha() de novo; e termina. Cada chamada volta exatamente para o ponto de onde saiu.

Com local function, a ajudante vem primeiro

Repare que linha foi definida antes de aviso. Um nome local só existe da linha em que foi criado para baixo. Se aviso viesse primeiro, o linha() dentro dela não enxergaria a função de baixo, e o programa daria erro (veja o terceiro caso de Quando dá errado). Regra prática: as funções pequenas, que as outras usam, ficam no alto do arquivo.

6. Três formas de escrever uma função

No Lua, a mesma função pode ser escrita de três jeitos. Os três funcionam:

local function forma1()
  print("forma 1: local function")
end

function forma2()
  print("forma 2: function (global)")
end

local forma3 = function()
  print("forma 3: local ... = function")
end

forma1()
forma2()
forma3()
print(type(forma1), type(forma2), type(forma3))

$ lua tres_formas.lua
forma 1: local function
forma 2: function (global)
forma 3: local ... = function
function	function	function

O type (aula Descobrindo o Tipo) responde function para as três: no Lua, uma função é um valor, como um número ou um texto, e fica guardada numa variável. A diferença entre as formas é que tipo de variável guarda a função:

local function forma1() … end
A função fica numa variável local, que só existe deste ponto do arquivo para baixo. É a forma recomendada.
function forma2() … end
Sem o local, a função vai para uma variável global, visível no programa inteiro, até em outros arquivos (módulos). É o mesmo problema da variável global (aula local × Global): qualquer parte do programa pode, sem querer, trocar o que está nesse nome.
local forma3 = function() … end
Escreve a função sem nome (function() … end) e guarda numa variável local, como se guarda um número: local x = 10. Esse jeito fica claro na aula Funções São Valores.

As formas 1 e 3 quase sempre se comportam igual. A diferença aparece quando a função chama a si mesma (aula Recursão): o local function já conhece o próprio nome por dentro; o local f = function, não (lá dentro, o nome ainda é uma global vazia, e o Lua responde attempt to call a nil value (global 'f')).

FormaQuando usar
local function nome() … endSempre que puder. É o padrão deste guia
local nome = function() … endQuando a ideia é "guardar uma função numa variável", como nas aulas Funções São Valores e Closures
function nome() … end (global)Só quando a função precisa mesmo ser vista de qualquer lugar. No modo interativo (>) é a que funciona, porque o local não sobrevive de uma linha para a outra lá
Lua 5.1, LuaJIT, 5.4 e Lua 5.5

As três formas são iguais em todas as versões: o mesmo tres_formas.lua roda igual no lua5.1, no luajit e no lua5.4. O que muda é a mensagem de erro do Lua antigo (veja abaixo). O Lua 5.5 acrescentou uma quarta forma, global function nome() … end, que faz parte da declaração global e tem regras próprias: ela fica para a aula A Declaração global. 5.5

A função vazia

Às vezes você já sabe o nome da função, mas ainda não escreveu o corpo. No Lua, uma função vazia é permitida: basta o function e o end, com um comentário no meio para lembrar:

local function relatorio()
  -- ainda vou escrever
end

relatorio()
print("Fim")

$ lua rascunho.lua
Fim

A chamada relatorio() funcionou e não mostrou nada, porque o corpo está vazio. Depois a Ana troca o comentário pelas linhas de verdade.

Tudo numa linha

Para o Lua, o que importa são as palavras function e end, não as quebras de linha. Uma função bem curta pode caber numa linha só:

local function bom_dia() print("Bom dia, Ana!") end
bom_dia()

$ lua uma_linha.lua
Bom dia, Ana!

Use isso só para funções de uma linha. Com mais passos, um por linha é bem mais fácil de ler.

Quem reclama é o programa lua; o erro foi no arquivo antes.lua, na linha 1.
attempt to call a nil value
"Tentativa de chamar um valor nil". Chamar é usar os parênteses, bom_dia(). Mas, na linha 1, o nome bom_dia ainda está vazio: guarda nil, o "nada" do Lua (aula O Valor nil). E não dá para "executar o nada".

O erro aconteceu na linha 1, no "pedaço principal" (main chunk): o programa em si, fora de qualquer função.

Quem começou tudo: o próprio programa lua, escrito em linguagem C. Essa linha aparece no fim de todo erro; pode ignorar.

Lembre da ordem do programa: a função só passa a existir quando o Lua passa pela definição. É como pedir o bolo de milho antes de a receita ter sido escrita no caderno. Sem o local (function bom_dia()), a mensagem é exatamente a mesma. Como consertar: coloque as funções no começo do arquivo e as chamadas depois delas.

No Lua 5.1 e no LuaJIT a mesma frase vem em outra ordem: attempt to call global 'bom_dia' (a nil value). Se você achar essa forma num fórum, é o mesmo erro.

Resumo

  • Uma função é um grupo de linhas guardado com um nome: uma receita.
  • Definir (local function nome() … end) só guarda a receita; não executa nada.
  • Chamar (nome()) executa o corpo e, no fim, volta para a linha seguinte. Dá para chamar quantas vezes quiser.
  • A definição tem de vir antes da chamada, e a função ajudante antes da que a usa; senão, attempt to call a nil value (global '…').
  • Três formas: local function (use esta), function sem local (global, evite) e local f = function (a função guardada numa variável).
  • Sem parênteses na chamada → syntax error. Sem end → 'end' expected … near <eof>. Função vazia é permitida.
  • Funções evitam repetição e deixam corrigir num lugar só. Na próxima aula, elas passam a receber informações: Parâmetros e Argumentos.
