Lua Iteradores Próprios

Você já usou o for com ipairs e pairs para percorrer tabelas. Esse for se chama for genérico, e ele não tem nada de mágico: ele só chama, de novo e de novo, uma função que entrega o próximo item. Essa função se chama iterador (de "iterar", repetir passo a passo). ipairs e pairs são iteradores que já vêm com o Lua. Nesta aula você vai escrever os seus: um que conta para trás, um que só entrega os produtos caros, um que pula de dois em dois.

Você vai aprender
  • O que é um iterador e como o for genérico conversa com ele.
  • O jeito mais comum de escrever um: uma função que devolve uma função (uma closure), que lembra onde parou.
  • Iteradores com filtro: entregar só os itens que interessam.
  • Os três (e quatro) valores do for genérico, e como fazer um iterador "sem estado", igual ao ipairs.
  • Os erros reais: esquecer os parênteses, passar uma tabela no lugar do iterador, mudar a variável do laço.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), na pasta pessoal dela, com lua arquivo.lua. Você vai precisar de Closures e de ipairs.

A ideia: a senha da fila do açougue

No açougue do mercado tem aquela maquininha de senhas. Cada vez que alguém aperta o botão, sai o próximo número: 1, depois 2, depois 3. A maquininha não imprime todas as senhas de uma vez; ela só sabe duas coisas:

  • onde parou (qual foi a última senha), e
  • como dar a próxima (somar 1).

Quando o rolo de papel acaba, ela não imprime mais nada, e a fila acabou. Um iterador é essa maquininha. O for genérico é a pessoa que aperta o botão: aperta, recebe um número, atende; aperta de novo… até a maquininha não entregar nada (nil).

1. O primeiro iterador: uma contagem

local function contagem(n)
  local i = 0
  return function ()
    i = i + 1
    if i <= n then
      return i
    end
  end
end
for numero in contagem(3) do
  print("volta", numero)
end

$ lua contagem.lua
volta	1
volta	2
volta	3
local function contagem(n)
A fábrica do iterador. Ela não conta nada sozinha: ela monta e devolve a maquininha.
local i = 0
O "onde parou". É uma variável local da fábrica, mas a função de dentro continua enxergando-a depois que contagem termina: é uma closure (aula Closures).
return function () … end
A maquininha: uma função sem parâmetros. Cada chamada soma 1 ao i e devolve o número.
if i <= n then return i end
Enquanto não passou de n, entrega o número. Depois disso, a função chega ao end sem return, e devolve nada, que o for lê como nil: é o "rolo acabou".
for numero in contagem(3) do
O for chama contagem(3) uma vez, guarda a maquininha, e passa a chamá-la a cada volta. O que ela devolve vai para numero. Quando ela devolve nil, o laço acaba.

Apertando o botão à mão

Para ver que não há mágica, chame a maquininha você mesmo, sem for:

local function contagem(n)
  local i = 0
  return function ()
    i = i + 1
    if i <= n then
      return i
    end
  end
end
local proximo = contagem(2)
print("chamada 1:", proximo())
print("chamada 2:", proximo())
print("chamada 3:", proximo())
print("chamada 4:", proximo())

$ lua mao.lua
chamada 1:	1
chamada 2:	2
chamada 3:
chamada 4:

As duas primeiras chamadas entregaram 1 e 2. A terceira e a quarta não devolveram nada: depois do texto, o print não tinha mais o que mostrar. O for faz exatamente isso, e para na primeira resposta vazia.

Missão: este iterador conta para a frente e o programa mostra 1..., 2..., 3.... Mude o iterador (sem mexer no for) para ele contar para trás: 3..., 2..., 1... e depois Já!. Dica: comece o atual em n + 1 e diminua.

local function regressiva(n)
  local atual = 0
  return function ()
    atual = atual + 1
    if atual <= n then
      return atual
    end
  end
end
for s in regressiva(3) do
  print(s .. "...")
end
print("Já!")

local function regressiva(n)
  local atual = n + 1
  return function ()
    atual = atual - 1
    if atual >= 1 then
      return atual
    end
  end
end
for s in regressiva(3) do
  print(s .. "...")
end
print("Já!")

2. Um iterador com filtro

A vantagem de escrever o seu iterador é esconder dentro dele o trabalho chato. A Ana quer percorrer o estoque da lojinha, mas só os produtos de R$ 10 ou mais. Em vez de pôr um if dentro de todo for, ela faz um iterador que já entrega só os caros:

local function caros(produtos, limite)
  local i = 0
  return function ()
    repeat
      i = i + 1
      local p = produtos[i]
      if p and p.preco >= limite then
        return p.nome, p.preco
      end
    until p == nil
  end
end
local estoque = {
  { nome = "pão", preco = 0.75 },
  { nome = "queijo", preco = 32.90 },
  { nome = "café", preco = 18.50 },
  { nome = "bala", preco = 0.10 },
}
for nome, preco in caros(estoque, 10) do
  print(string.format("%s: R$ %.2f", nome, preco))
end

$ lua caros.lua
queijo: R$ 32.90
café: R$ 18.50

O que mudou em relação à contagem:

  • Dois valores por volta. A maquininha devolve p.nome, p.preco, e o for distribui: for nome, preco in …. O laço acaba quando o primeiro valor é nil.
  • Um laço dentro do iterador. A cada chamada, o repeat … until (aula repeat) avança o i até achar um produto caro, e o return sai na hora. Se chegar ao fim da lista (p == nil), sai do repeat sem return: o iterador devolve nada, e o for termina.

O for lá embaixo ficou limpo: quem lê entende na hora que ele percorre "os produtos caros do estoque".

Iteradores que já vêm com o Lua

Além de ipairs e pairs, há outros. O string.gmatch (aula gmatch) é um iterador que entrega cada pedaço de um texto que casa com um padrão. E um iterador seu pode simplesmente devolver um deles:

local frase = "pão leite café"
for palavra in string.gmatch(frase, "%S+") do
  print(palavra)
end
local function palavras(texto)
  return string.gmatch(texto, "%S+")
end
for p in palavras("um dois") do print(p) end

$ lua palavras.lua
pão
leite
café
um
dois

(%S+ quer dizer "um ou mais caracteres que não são espaço": uma palavra. Veja Padrões.) O io.lines (aula io.lines) também é um iterador: entrega uma linha do arquivo por volta.

3. O for genérico por dentro

Até aqui, o iterador era uma closure que guardava tudo dentro dela. Mas o for genérico sabe guardar algumas coisas para o iterador. O manual do Lua explica que a expressão depois do in pode dar até quatro valores:

ValorNome no manualPara que serve
1ºfunção iteradoraa maquininha, chamada a cada volta
2ºestadouma coisa que não muda, entregue à função em toda volta (por exemplo, a tabela)
3ºvalor inicial de controleo "onde parou" da primeira chamada
4ºvalor de fechamentoum valor com __close, fechado quando o laço acaba (aula <close>)

A cada volta, o for chama função(estado, controle). O primeiro valor que ela devolver vira o novo controle (e vai para a primeira variável do laço). Quando ele for nil, acabou. Veja o ipairs fazendo exatamente isso:

local f, estado, inicio = ipairs({ "x", "y" })
print(type(f), type(estado), inicio)
print(f(estado, inicio))
print(f(estado, 1))
print(f(estado, 2))

$ lua comoipairs.lua
function	table	0
1	x
2	y
nil

O ipairs devolveu três coisas: uma função, a própria tabela (o estado) e o número 0 (o controle inicial). Chamando a função com (tabela, 0) ela entrega 1, "x"; com (tabela, 1), 2, "y"; com (tabela, 2), nil. O ipairs não guarda nada dentro de si: quem lembra "onde parou" é o for. Por isso ele é chamado de iterador sem estado.

Um iterador sem estado: de dois em dois

local function proximo_par(lista, i)
  i = i + 2
  local v = lista[i]
  if v ~= nil then
    return i, v
  end
end
local function pares(lista)
  return proximo_par, lista, 0
end
local letras = { "a", "b", "c", "d", "e", "f" }
for i, v in pares(letras) do
  print(i, v)
end

$ lua semestado.lua
2	b
4	d
6	f

A função proximo_par recebe a lista (o estado) e o último índice (o controle), e devolve o próximo índice par com o valor dele. A pares só entrega as três peças ao for: proximo_par, lista, 0. Nenhuma closure, nenhuma variável escondida.

Para ver o que o for faz com essas peças, aqui está o mesmo laço escrito com while, à mão:

local function proximo_par(lista, i)
  i = i + 2
  local v = lista[i]
  if v ~= nil then
    return i, v
  end
end
local letras = { "a", "b", "c", "d", "e", "f" }
local f, s, c = proximo_par, letras, 0
while true do
  local i, v = f(s, c)
  if i == nil then break end
  c = i
  print(i, v)
end

$ lua pordentro.lua
2	b
4	d
6	f

A mesma saída. Tudo o que o for genérico faz é este while: chamar f(s, c), parar no nil, guardar o novo controle.

Dá até para passar as três peças direto no for, sem fábrica. É assim que o pairs funciona por dentro, com a função next:

local t = { "x", "y" }
for i, v in next, t do
  print(i, v)
end

$ lua nofor.lua
1	x
2	y

O quarto valor: fechar quando o laço acaba

Se o iterador usa algo que precisa ser fechado (um arquivo, por exemplo), ele pode entregar esse algo como quarto valor. O for o fecha quando o laço termina, até com break:

local function contagem(n)
  local i = 0
  local alarme = setmetatable({}, { __close = function () print("(iterador encerrado)") end })
  return function ()
    i = i + 1
    if i <= n then return i end
  end, nil, nil, alarme
end
for numero in contagem(5) do
  print(numero)
  if numero == 2 then break end
end
print("depois do for")

$ lua fechamento.lua
1
2
(iterador encerrado)
depois do for

O io.lines faz isso com o arquivo que abriu: no lab, print(select("#", io.lines("lista.txt"))) mostrou 4 (são quatro valores), e um for linha in io.lines(…) interrompido com break fecha o arquivo do mesmo jeito.

Formas diferentes de fazer a mesma coisa

Percorrer os itens 2, 4 e 6 de uma lista, de três jeitos:

local letras = { "a", "b", "c", "d", "e", "f" }

-- 1) for numérico com passo 2: sem iterador nenhum
for i = 2, #letras, 2 do print(i, letras[i]) end

-- 2) closure: o iterador lembra onde parou
local function pares_closure(lista)
  local i = 0
  return function ()
    i = i + 2
    if lista[i] ~= nil then return i, lista[i] end
  end
end
for i, v in pares_closure(letras) do print(i, v) end

-- 3) sem estado: o for lembra onde parou
local function proximo_par(lista, i)
  i = i + 2
  if lista[i] ~= nil then return i, lista[i] end
end
for i, v in proximo_par, letras, 0 do print(i, v) end
SituaçãoQual usar
Contar números com um passo fixoO for numérico (aula for Numérico): mais simples e mais rápido
Percorrer uma lista ou tabela inteiraipairs ou pairs

O "onde parou" cabe num único valor e você quer evitar criar uma closure a cada laçoUm iterador sem estado (como o ipairs)

Quando dá errado

Pôs a tabela direto no for 
local compras = { "pão", "leite" }
for item in compras do
  print(item)
end

$ lua errotabela.lua
lua: errotabela.lua:2: attempt to call a table value (for iterator 'for iterator')
stack traceback:
	errotabela.lua:2: in main chunk
	[C]: in ?

"Tentativa de chamar um valor tabela (o iterador do for)". O for genérico quer uma função para chamar a cada volta, e recebeu a tabela. Quem vem do Python estranha: lá, for item in compras funciona. Como consertar: for _, item in ipairs(compras) do.

A fábrica não devolveu a maquininha 
local function contagem(n)
end
for numero in contagem(3) do
  print(numero)
end

$ lua erronil.lua
lua: erronil.lua:3: attempt to call a nil value (for iterator 'for iterator')
stack traceback:
	erronil.lua:3: in main chunk
	[C]: in ?

Agora o for recebeu nil no lugar da função. Acontece quando a fábrica esquece o return function () … end (ou o return ficou dentro de um if que não rodou). Como consertar: confira se a fábrica sempre termina com return function ….

Esqueceu os parênteses: o laço não para 
local function contagem(n)
  local i = 0
  return function ()
    i = i + 1
    if i <= n then return i end
  end
end
for numero in contagem do
  print(numero)
end

$ lua chamou.lua | head -3
function: 0x56512f3c2530
function: 0x56512f3c25e0
function: 0x56512f3c26c0

Sem os parênteses, o for usou a fábrica como se ela fosse a maquininha. A cada volta, ele chama contagem(nil, …), que devolve uma função nova (nunca nil), e o laço nunca acaba: o lab mostrou funções diferentes sem parar (os endereços mudam a cada execução). Aqui o | head -3 mostrou só as 3 primeiras linhas e encerrou o programa; sem ele, seria preciso apertar Ctrl+C (no editor do guia, o programa é parado sozinho em menos de um segundo, com (o programa escreveu demais: …)). Como consertar: for numero in contagem(3) do.

5.5 Tentou mudar a variável do laço 
local function contagem(n)
  local i = 0
  return function ()
    i = i + 1
    if i <= n then return i end
  end
end
for numero in contagem(3) do
  numero = numero * 10
  print(numero)
end

$ lua constfor.lua
lua: constfor.lua:9: attempt to assign to const variable 'numero'
$ lua5.4 constfor.lua
10
20
30

No Lua 5.5, a variável do for (numérico e genérico) é constante: ela é o "onde parou" que o for entrega ao iterador, e mudá-la bagunçaria o percurso. O erro sai antes de rodar (como na aula <const>). No Lua 5.4 o mesmo arquivo roda. Como consertar: use outra variável: local dez_vezes = numero * 10.

O iterador nunca devolve nil 
local function sempre()
  return function () return 1 end
end
local voltas = 0
for x in sempre() do
  voltas = voltas + 1
  if voltas == 5 then print("parei na volta", voltas) break end
end

$ lua infinito.lua
parei na volta	5

Um iterador que nunca entrega nil faz um laço infinito. Aqui o break salvou; sem ele, só Ctrl+C (ou o botão Parar do editor). Às vezes é de propósito (um iterador "sem fim", como um gerador de números), e então quem usa precisa do break. Quando não é de propósito, procure o caminho do iterador que deveria terminar sem return.

Missão final: o que está acabando no estoque

Missão: escreva o corpo da maquininha de acabando: a cada chamada, ela avança o i até achar um item com quantidade menor que 5 e devolve o nome e a quantidade dele; se a lista acabar, devolve nil. O programa deve mostrar leite (2) e ovos (4), nessa ordem e só eles. (Dica: um while true do … end com dois return dentro.)

local estoque = {
  { nome = "pão", quantidade = 10 },
  { nome = "leite", quantidade = 2 },
  { nome = "café", quantidade = 7 },
  { nome = "ovos", quantidade = 4 },
}
local function acabando(lista)
  local i = 0
  return function ()
    -- avance o i até achar um item com quantidade menor que 5
    -- e devolva o nome e a quantidade dele
  end
end
for nome, qtd in acabando(estoque) do
  print(nome .. " (" .. qtd .. ")")
end

local estoque = {
  { nome = "pão", quantidade = 10 },
  { nome = "leite", quantidade = 2 },
  { nome = "café", quantidade = 7 },
  { nome = "ovos", quantidade = 4 },
}
local function acabando(lista)
  local i = 0
  return function ()
    while true do
      i = i + 1
      local item = lista[i]
      if item == nil then return nil end
      if item.quantidade < 5 then
        return item.nome, item.quantidade
      end
    end
  end
end
for nome, qtd in acabando(estoque) do
  print(nome .. " (" .. qtd .. ")")
end

Resumo

  • Um iterador é uma função que, a cada chamada, entrega o próximo item, e devolve nil quando acaba. O for genérico chama o iterador até receber nil.
  • O jeito mais comum: uma fábrica que guarda o "onde parou" numa variável local e devolve uma closure.
  • O iterador pode devolver vários valores por volta (for nome, preco in …) e pode filtrar, pulando o que não interessa.
  • Por dentro, o for recebe até quatro valores: função, estado, controle inicial e valor de fechamento; e chama função(estado, controle) a cada volta. É assim que ipairs e pairs funcionam.
  • Erros comuns: tabela direto no for, fábrica sem return, esquecer os () (laço sem fim) e, no 5.5, mudar a variável do laço.
