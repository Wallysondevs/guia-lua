Lua arg

Até aqui, para o programa saber um nome ou um número, ou ele já vinha escrito no código, ou o programa perguntava com io.read() e esperava alguém digitar. Existe um terceiro jeito, o preferido dos programas de terminal: passar a informação junto com o comando, na mesma linha: lua saudacao.lua Ana. Essas palavras extras se chamam argumentos da linha de comando, e o Lua as entrega ao programa numa tabela chamada arg.

Você vai aprender
  • Como os argumentos chegam: arg[1], arg[2]…, e quantos são, com #arg.
  • O que são o arg[0] (o nome do programa) e o arg[-1] (o lua).
  • Por que um nome com espaço precisa de aspas.
  • Que todo argumento é texto, e como transformar em número com tonumber.
  • O outro jeito de pegar os argumentos: os três pontinhos (...) no arquivo principal.
  • Como escrever a mensagem de "uso" quando faltam argumentos, aceitar opções como -m, e rodar o programa com ./programa.lua.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), em /home/ana. No editor do guia, as caixas desta aula têm um campo Argumentos, já preenchido, que você pode mudar; a caixa mostra a linha de comando (como lua main.lua Ana) quando roda.

A ideia: o pedido no balcão

Na padaria, o atendente pode trabalhar de dois jeitos. No primeiro, o cliente chega e o atendente pergunta: "O que vai ser?", "Quantos?". No segundo, o cliente já chega falando tudo de uma vez: "Seis pães e um litro de leite". O atendente não pergunta nada; só anota e entrega.

O io.read() é o primeiro jeito: o programa pergunta. Os argumentos são o segundo: quem roda o programa já diz tudo na linha do comando. Isso tem uma grande vantagem: o programa pode ser chamado por outros programas e por scripts, que não sabem responder perguntas, e o comando inteiro pode ser repetido com a seta para cima do terminal.

1. A tabela arg

print("programa:", arg[0])
print("quantos:", #arg)
for i = -1, #arg do
  print(i, arg[i])
end

$ lua args.lua Ana "Bia Lima" 42
programa:	args.lua
quantos:	3
-1	lua
0	args.lua
1	Ana
2	Bia Lima
3	42

O terminal separou a linha lua args.lua Ana "Bia Lima" 42 em pedaços, nos espaços, e o Lua montou a tabela arg com eles:

Os argumentos de verdade começam no 1, como toda lista do Lua (veja Tabelas como Listas). As posições 0 e −1 são um extra, para o programa saber como foi chamado. Sem nenhum argumento, a lista fica vazia:

$ lua args.lua

quantos:	0
-1	lua

2. Usando um argumento

local nome = arg[1]
print("Olá, " .. nome .. "!")

$ lua ola.lua Ana
Olá, Ana!
$ lua ola.lua Bia Lima
Olá, Bia!
$ lua ola.lua "Bia Lima"
Olá, Bia Lima!

Sem aspas, Bia Lima virou dois argumentos (arg[1] = Bia, arg[2] = Lima), e o programa só usa o primeiro. Com aspas, é um argumento só. Quem separa nos espaços e entende as aspas é o terminal, antes de o Lua começar: o programa recebe os pedaços já separados, sem as aspas.

local nome = "mundo"

3. Todo argumento é texto

O 42 da linha de comando chega ao programa como o texto "42", não como o número 42. O terminal só conhece texto:

print(arg[1], type(arg[1]))
print(arg[1] + 1)
print(tonumber(arg[1]), math.type(tonumber(arg[1])))
print(arg[1] == 10, tonumber(arg[1]) == 10)

$ lua tipos.lua 10
10	string
11
10	integer
false	true
type(arg[1]) → string
O 10 é um texto.
arg[1] + 1 → 11
Numa conta, o Lua converte o texto em número sozinho (veja Conversão). Por isso a soma funcionou.
tonumber(arg[1]) → 10, integer
O tonumber converte de propósito, e devolve nil se o texto não for um número. É o jeito certo.
arg[1] == 10 → false
Na comparação, o Lua não converte: o texto "10" e o número 10 são diferentes. Só o tonumber(arg[1]) == 10 dá true.

A conversão automática das contas parece prática, mas engana: ela some nas comparações (e com < e > dá erro, como você vai ver em Quando dá errado), e não avisa quando o argumento não é número. Por isso, converta sempre com tonumber, logo no começo, e confira se deu nil.

Somando todos os argumentos

Como arg é uma lista, dá para percorrê-la com ipairs (que começa no 1 e ignora o 0 e o −1):

local soma = 0
for i, texto in ipairs(arg) do
  local n = tonumber(texto)
  if n then
    soma = soma + n
  else
    print("Ignorei o argumento " .. i .. ": " .. texto)
  end
end
print("Soma: " .. soma)

$ lua soma.lua 10 20 12.5
Soma: 42.5
$ lua soma.lua 10 vinte 30
Ignorei o argumento 2: vinte
Soma: 40
$ lua soma.lua
Soma: 0

Missão: a caixa roda lua main.lua 10 20 12.5, mas o programa só soma o primeiro argumento (Soma: 10). Faça um laço por todos (com ipairs(arg) ou for i = 1, #arg), até aparecer Soma: 42.5.

local soma = 0
soma = soma + tonumber(arg[1])
print("Soma: " .. soma)

local soma = 0
for _, texto in ipairs(arg) do
  soma = soma + tonumber(texto)
end
print("Soma: " .. soma)

4. O outro jeito: os três pontinhos (...)

O arquivo principal de um programa Lua funciona como uma função, e os argumentos da linha de comando também chegam nele como os argumentos dessa função: os ... (veja Funções Variádicas). Isso permite pegar vários de uma vez, com nome:

local item, quantidade = ...
print("item:", item)
print("quantidade:", quantidade)
print("total de argumentos:", select("#", ...))
local todos = {...}
print("o último:", todos[#todos])

$ lua pontos.lua pão 6 extra
item:	pão
quantidade:	6
total de argumentos:	3
o último:	extra
local item, quantidade = ...
Os dois primeiros argumentos, cada um na sua variável, numa linha só (veja Atribuição Múltipla). O terceiro, extra, ficou de fora dessas variáveis.
select("#", ...)
Quantos argumentos vieram (veja select).
{...}
Uma tabela nova com todos eles: o mesmo que arg[1], arg[2]…, sem o 0 e o −1.

O ... só existe no nível de fora do arquivo. Dentro de uma função sua, o ... seria o dos argumentos daquela função, e a função precisa ter ... nos parênteses para usar:

local function mostrar()
  print(...)
end
mostrar()

$ lua funcao_pontos.lua a b
lua: funcao_pontos.lua:2: cannot use '...' outside a vararg function near '...'

"Não dá para usar ... fora de uma função variádica". É um erro de sintaxe: o programa nem começou (não há stack traceback). Dentro de funções, use a tabela arg, que vale no arquivo inteiro, ou passe os valores como parâmetros.

5. Faltou argumento: a mensagem de uso

Quem esquece o argumento não deve ver um stack traceback. O costume dos programas de terminal é responder com uma mensagem de uso: como o programa deve ser chamado, com um exemplo. E sair com código 1 (veja os.exit):

if #arg < 2 then
  io.stderr:write("Uso: lua uso.lua ITEM QUANTIDADE\n")
  io.stderr:write("Exemplo: lua uso.lua pão 6\n")
  os.exit(1)
end
local item = arg[1]
local quantidade = tonumber(arg[2])
if not quantidade then
  io.stderr:write("A quantidade precisa ser um número: " .. arg[2] .. "\n")
  os.exit(1)
end
print(string.format("Anotado: %d x %s", quantidade, item))

$ lua uso.lua
Uso: lua uso.lua ITEM QUANTIDADE
Exemplo: lua uso.lua pão 6
$ echo $?
1
$ lua uso.lua pão seis
A quantidade precisa ser um número: seis
$ lua uso.lua pão 6
Anotado: 6 x pão

Os nomes em MAIÚSCULAS na linha de uso (ITEM, QUANTIDADE) são um costume: "troque isto pelo seu valor". As mensagens vão para o io.stderr, o canal de erros. Duas conferências: primeiro se vieram os argumentos (#arg < 2), depois se prestam (o tonumber deu nil?).

Use o arg[0] na mensagem

Se alguém renomear o programa, a mensagem Uso: lua uso.lua … fica errada. Com "Uso: lua " .. arg[0] .. " ITEM QUANTIDADE\n", ela sempre mostra o nome com que o programa foi chamado.

6. Opções: -m e --maiusculas

Muitos comandos aceitam opções, argumentos que começam com - e mudam o comportamento (como o -l do ls -l). O costume é ter uma forma curta (-m) e uma longa (--maiusculas). Separar opções de dados é só um laço com if:

local maiusculas = false
local nomes = {}
for _, a in ipairs(arg) do
  if a == "-m" or a == "--maiusculas" then
    maiusculas = true
  else
    nomes[#nomes + 1] = a
  end
end
for _, nome in ipairs(nomes) do
  print(maiusculas and nome:upper() or nome)
end

$ lua opcoes.lua ana bia
ana
bia
$ lua opcoes.lua -m ana bia
ANA
BIA
$ lua opcoes.lua ana --maiusculas bia
ANA
BIA

A opção pode vir em qualquer posição. O nome:upper() põe em maiúsculas (veja Funções de Texto). Para programas com muitas opções existem bibliotecas prontas (como a argparse, instalável pelo LuaRocks), mas a ideia por trás é esta.

Formas diferentes de chamar o programa

Com lua -e antes: as posições negativas

Tudo o que vem antes do nome do programa vai para as posições negativas. O -e do lua roda um pedaço de código antes do programa:

for i = -3, #arg do
  print(i, arg[i])
end

$ lua -e 'x = 1' negativos.lua oi
-3	lua
-2	-e
-1	x = 1
0	negativos.lua
1	oi

O programa é sempre o arg[0], os argumentos dele começam no 1, e o que é do lua fica do 0 para trás. O #arg e o ipairs(arg) continuam olhando só os argumentos do programa.

Como um comando: #! e ./

No Linux (e no macOS), um programa Lua pode virar um comando, rodado sem escrever lua. A primeira linha começa com #! (chamado shebang) e diz ao sistema quem vai rodar o arquivo; o chmod +x dá permissão de execução:

#!/usr/bin/env lua
print("Sou o " .. arg[0] .. " e recebi " .. #arg .. " argumento(s).")

$ chmod +x executavel.lua
$ ./executavel.lua um dois
Sou o ./executavel.lua e recebi 2 argumento(s).
$ lua executavel.lua um
Sou o executavel.lua e recebi 1 argumento(s).

O /usr/bin/env lua quer dizer "procure o lua no PATH e use-o". O Lua ignora a primeira linha quando ela começa com #, então o mesmo arquivo roda dos dois jeitos. E repare no arg[0]: ele é do jeito que foi escrito no comando (./executavel.lua ou executavel.lua), não o caminho completo. Com lua Documentos/../args.lua, o arg[0] seria Documentos/../args.lua.

lua -e 'código' programa.lua a bAjustar algo antes de o programa rodar (raro)

Quando dá errado

Rodou sem o argumento 
$ lua ola.lua
lua: ola.lua:2: attempt to concatenate a nil value (local 'nome')
stack traceback:
	ola.lua:2: in main chunk
	[C]: in ?

Sem argumento, arg[1] é nil, o nome ficou nil, e o .. não junta com nil. Numa conta, o mesmo esquecimento dá attempt to perform arithmetic on a nil value:

local preco = arg[1]
print("Com desconto: " .. preco * 0.9)

$ lua nil_conta.lua 50
Com desconto: 45.0
$ lua nil_conta.lua
lua: nil_conta.lua:2: attempt to perform arithmetic on a nil value (local 'preco')
stack traceback:
	nil_conta.lua:2: in main chunk
	[C]: in ?

Como consertar: confira o #arg no começo e mostre a mensagem de uso (seção 5), ou dê um padrão: local nome = arg[1] or "visitante".

Comparou o argumento com um número 
if arg[1] > 5 then
  print("maior que 5")
end

$ lua compara.lua 10
lua: compara.lua:1: attempt to compare number with string
stack traceback:
	compara.lua:1: in main chunk
	[C]: in ?

"Tentativa de comparar número com string". O arg[1] é o texto "10", e o > não compara texto com número (a conta converte, a comparação não). A ordem da mensagem ("number with string") é porque, por dentro, o Lua transforma a > b em b < a. Como consertar: tonumber(arg[1]) > 5, de preferência numa variável convertida logo no começo.

Contou errado por causa do espaço

Sem aspas, lua ola.lua Bia Lima mostrou Olá, Bia!. Não há mensagem de erro; o Lima virou o arg[2], que o programa não usa. Como consertar: textos com espaço vão entre aspas no terminal: lua ola.lua "Bia Lima". No editor do guia, o campo Argumentos das caixas segue a mesma regra.

Resumo

  • lua programa.lua a b c: o Lua entrega a, b e c em arg[1], arg[2], arg[3]; #arg é quantos são.
  • arg[0] é o nome do programa (como foi escrito) e arg[-1] é o lua; o que vem antes do programa fica nas posições negativas.
  • Quem separa os argumentos é o terminal, nos espaços; aspas juntam: "Bia Lima".
  • Argumentos são sempre texto: converta com tonumber e confira o nil. A comparação não converte sozinha.
  • No arquivo principal, local a, b = ... dá nome aos primeiros; dentro de funções, use arg.
  • Faltou argumento? Mostre a mensagem de uso no io.stderr e saia com os.exit(1).
