Projeto Agenda de Contatos

A Ana quer os telefones dos amigos num lugar só, no terminal: listar em ordem alfabética, adicionar, buscar por um pedaço do nome e remover, com tudo guardado num arquivo. O projeto mostra o jeito mais "Lua" de guardar dados: escrever o arquivo como um programa Lua, que devolve a tabela, e lê-lo de volta com o próprio Lua.

Você vai praticar
  • Guardar os contatos num dicionário: uma tabela em que a chave é o nome.
  • Listar em ordem com table.sort, e entender por que a ordem do pairs não serve.
  • Montar um menu com funções, como na Lista de Tarefas.
  • Gravar textos com segurança com %q de string.format.
  • Ler o arquivo com dofile e loadfile, e se proteger com pcall e um ambiente vazio.

O arquivo contatos.lua é um pedacinho de programa Lua: return e uma tabela. Quatro versões até lá:

  1. Os contatos na memória (dicionário, table.sort).
  2. O menu (funções, procurar pelo nome).
  3. Salvar e carregar (%q, dofile).
  4. Buscar, remover e tratar os erros (find, loadfile num ambiente vazio, pcall).

Versão 1 · Os contatos na memória

Na Lista de Tarefas, as tarefas ficavam numa lista: tarefas[1], tarefas[2]… Para uma agenda, o natural é procurar pelo nome, e não por um número. Então a chave da tabela é o próprio nome: agenda["Bia Souza"]. É uma tabela usada como dicionário, como uma agenda de papel, em que a gente vai direto na letra B.

local agenda = {
  ["Bia Souza"] = { telefone = "11 98888-1234", email = "bia@exemplo.com" },
  ["Carlos Lima"] = { telefone = "21 97777-5678", email = "carlos@exemplo.com" },
  ["Ana Paula"] = { telefone = "31 96666-0000", email = "anapaula@exemplo.com" },
}

-- Um contato, pelo nome:
local bia = agenda["Bia Souza"]
print("Telefone da Bia: " .. bia.telefone)

-- Um contato novo:
agenda["Davi Rocha"] = { telefone = "41 95555-4321", email = "davi@exemplo.com" }

-- Todos, em ordem alfabética:
local nomes = {}
for nome in pairs(agenda) do
  nomes[#nomes + 1] = nome
end
table.sort(nomes)

print()
for _, nome in ipairs(nomes) do
  local contato = agenda[nome]
  print(string.format("%-12s %-14s %s", nome, contato.telefone, contato.email))
end

["Bia Souza"] = { telefone = …, email = … }Uma entrada do dicionário: a chave é o texto "Bia Souza" (entre colchetes, porque tem espaço e não pode ser escrita como Bia Souza = …), e o valor é outra tabela, com os dados dela.
agenda["Bia Souza"]Vai direto ao contato, sem percorrer nada. Se o nome não existir, dá nil.
agenda["Davi Rocha"] = { … }Acrescentar é só dar valor a uma chave nova. (E se a chave já existir, o contato antigo é trocado.)
for nome in pairs(agenda) doPercorre todas as chaves (veja pairs). Aqui, só para copiar os nomes para uma lista.
table.sort(nomes)Põe a lista de nomes em ordem alfabética (veja table.sort).
string.format("%-12s %-14s %s", …)%-12s = um texto ocupando 12 posições, alinhado à esquerda (sobra espaço à direita). Assim as colunas ficam alinhadas.

Listar direto pelo pairs: a ordem muda a cada execução

Por que copiar os nomes e ordenar, em vez de mostrar direto no pairs? Este teste (ordem.lua) faz isso, com os quatro contatos:

local agenda = {
  ["Bia Souza"] = { telefone = "11 98888-1234" },
  ["Carlos Lima"] = { telefone = "21 97777-5678" },
  ["Ana Paula"] = { telefone = "31 96666-0000" },
  ["Davi Rocha"] = { telefone = "41 95555-4321" },
}
for nome, contato in pairs(agenda) do
  print(nome, contato.telefone)
end

$ lua ordem.lua
Davi Rocha      41 95555-4321
Carlos Lima     21 97777-5678
Ana Paula       31 96666-0000
Bia Souza       11 98888-1234
$ lua ordem.lua
Ana Paula       31 96666-0000
Carlos Lima     21 97777-5678
Davi Rocha      41 95555-4321
Bia Souza       11 98888-1234

O mesmo programa, rodado duas vezes seguidas, mostrou os contatos em ordens diferentes. Não é defeito: o pairs passa pelas chaves na ordem em que elas estão guardadas por dentro da tabela, e, para chaves de texto, essa arrumação depende de detalhes que mudam a cada vez que o Lua começa. A ordem do pairs não é alfabética, nem a de inserção, nem a mesma de ontem. Sempre que a ordem importar, copie as chaves para uma lista e use table.sort.

Um nome que não existe: attempt to index a nil value (field 'Zeca Lima') 
$ lua -e 'local agenda = {} print(agenda["Zeca Lima"].telefone)'
lua: (command line):1: attempt to index a nil value (field 'Zeca Lima')
stack traceback:
        (command line):1: in main chunk
        [C]: in ?

agenda["Zeca Lima"] é nil, e o .telefone tenta olhar dentro de nil. Como a chave estava escrita no código, o Lua até diz o nome do campo que deu nil. A versão 2 confere antes: if contato then.

Nomes com acento desalinham as colunas 
$ lua -e 'print(string.format("[%-12s]", "Davi Rocha")) print(string.format("[%-12s]", "João Simões"))'
[Davi Rocha  ]
[João Simões]

O %-12s conta bytes, e "João Simões" tem 11 letras mas 13 bytes (o ã e o õ ocupam 2 cada; veja Acentos e a Biblioteca utf8). Já passou de 12, então não sobra espaço nenhum. Nesta agenda, isso só estraga o alinhamento; os dados ficam certos. O mesmo acontece com nomes compridos, como Carlos "Cacá" Lima, lá em cima.

Versão 2 · O menu

A agenda agora conversa com a Ana: um menu para listar, adicionar e procurar. Cada opção é uma função, como na Lista de Tarefas, e a parte de ordenar os nomes virou a função nomes_em_ordem, porque mais de uma opção precisa dela.

-- Agenda de Contatos da Ana, versão 2: o menu

local function perguntar(texto)
  io.write(texto)
  local resposta = io.read()
  if resposta == nil then
    return nil
  end
  return resposta:match("^%s*(.-)%s*$")
end

-- Os nomes da agenda em ordem alfabética.
local function nomes_em_ordem(agenda)
  local nomes = {}
  for nome in pairs(agenda) do
    nomes[#nomes + 1] = nome
  end
  table.sort(nomes)
  return nomes
end

local function mostrar(nome, contato)
  print(string.format("%-12s %-14s %s", nome, contato.telefone, contato.email))
end

local function listar(agenda)
  local nomes = nomes_em_ordem(agenda)
  if #nomes == 0 then
    print("A agenda está vazia.")
    return
  end
  for _, nome in ipairs(nomes) do
    mostrar(nome, agenda[nome])
  end
  print(#nomes .. " contato(s).")
end

local function adicionar(agenda)
  local nome = perguntar("Nome: ")
  if nome == nil or nome == "" then
    print("Sem nome, sem contato.")
    return
  end
  local telefone = perguntar("Telefone: ") or ""
  local email = perguntar("E-mail: ") or ""
  agenda[nome] = { telefone = telefone, email = email }
  print("Guardado: " .. nome)
end

local function procurar(agenda)
  local nome = perguntar("Nome exato: ")
  local contato = agenda[nome or ""]
  if contato then
    mostrar(nome, contato)
  else
    print("Não achei ninguém com esse nome.")
  end
end

local agenda = {}
print("=== Agenda da Ana ===")

while true do
  print()
  print("1) Listar  2) Adicionar  3) Procurar  0) Sair")
  local opcao = perguntar("Escolha: ")
  if opcao == "1" then
    listar(agenda)
  elseif opcao == "2" then
    adicionar(agenda)
  elseif opcao == "3" then
    procurar(agenda)
  elseif opcao == "0" or opcao == nil then
    print("Até logo!")
    break
  else
    print("Opção inválida: " .. opcao)
  end
end
nomes_em_ordem(agenda)
As linhas do pairs e do table.sort da versão 1, numa função que devolve a lista ordenada.
agenda[nome] = { telefone = telefone, email = email }
Guarda o contato com o nome como chave. Se a Ana adicionar a "Bia Souza" de novo, o telefone antigo é trocado pelo novo (às vezes é o que ela quer: atualizar).
perguntar("Telefone: ") or ""
Se a entrada acabar no meio, guarda um texto vazio em vez de nil, para o mostrar não quebrar depois.
agenda[nome or ""]
Em procurar: com nil como chave, o agenda[nil] só daria nil, mas o or "" deixa claro que o caso foi pensado.
if contato then … else print("Não achei…")

Versão 3 · Salvar e carregar

Para a agenda sobreviver ao fim do programa, ela vai para um arquivo. Muitas linguagens usam o formato JSON para isso, mas o Lua não traz JSON pronto (e, no Ubuntu 26.04, a biblioteca lua-dkjson do apt só funciona com o Lua 5.1, 5.3 e 5.4, não com o 5.5; veja LuaRocks). E o Lua tem um jeito próprio, sem biblioteca nenhuma: escrever o arquivo como código Lua.

return {
  ["Bia Souza"] = { telefone = "11 98888-1234", email = "bia@exemplo.com" },
  ["Carlos Lima"] = { telefone = "21 97777-5678", email = "carlos@exemplo.com" },
}

Isso é um programa Lua de verdade: uma tabela e um return que a devolve. Para ler, basta rodar esse "programa" com dofile ("faça o arquivo"), que devolve o que o arquivo devolveu. O Lua nasceu justamente para isso: descrever dados em arquivos de configuração. Duas funções novas, e o resto é a versão 2:

-- Agenda de Contatos da Ana, versão 3: salvar e carregar

local ARQUIVO = "contatos.lua"

local function perguntar(texto)
  io.write(texto)
  local resposta = io.read()
  if resposta == nil then
    return nil
  end
  return resposta:match("^%s*(.-)%s*$")
end

-- Os nomes da agenda em ordem alfabética.
local function nomes_em_ordem(agenda)
  local nomes = {}
  for nome in pairs(agenda) do
    nomes[#nomes + 1] = nome
  end
  table.sort(nomes)
  return nomes
end

local function mostrar(nome, contato)
  print(string.format("%-12s %-14s %s", nome, contato.telefone, contato.email))
end

local function listar(agenda)
  local nomes = nomes_em_ordem(agenda)
  if #nomes == 0 then
    print("A agenda está vazia.")
    return
  end
  for _, nome in ipairs(nomes) do
    mostrar(nome, agenda[nome])
  end
  print(#nomes .. " contato(s).")
end

-- Grava a agenda como um programa Lua: "return { ... }".
local function salvar(agenda)
  local arquivo = assert(io.open(ARQUIVO, "w"))
  arquivo:write("return {\n")
  for _, nome in ipairs(nomes_em_ordem(agenda)) do
    local c = agenda[nome]
    arquivo:write(string.format("  [%q] = { telefone = %q, email = %q },\n",
      nome, c.telefone, c.email))
  end
  arquivo:write("}\n")
  arquivo:close()
end

-- Lê a agenda gravada (ou começa vazia, se ainda não há arquivo).
local function carregar()
  local arquivo = io.open(ARQUIVO, "r")
  if not arquivo then
    return {}
  end
  arquivo:close()
  return dofile(ARQUIVO)
end

local function adicionar(agenda)
  local nome = perguntar("Nome: ")
  if nome == nil or nome == "" then
    print("Sem nome, sem contato.")
    return
  end
  local telefone = perguntar("Telefone: ") or ""
  local email = perguntar("E-mail: ") or ""
  agenda[nome] = { telefone = telefone, email = email }
  print("Guardado: " .. nome)
end

local function procurar(agenda)
  local nome = perguntar("Nome exato: ")
  local contato = agenda[nome or ""]
  if contato then
    mostrar(nome, contato)
  else
    print("Não achei ninguém com esse nome.")
  end
end

local agenda = carregar()
print("=== Agenda da Ana ===")

while true do
  print()
  print("1) Listar  2) Adicionar  3) Procurar  0) Sair")
  local opcao = perguntar("Escolha: ")

  elseif opcao == "2" then

    salvar(agenda)

  elseif opcao == "0" or opcao == nil then
    print("Até logo!")
    break
  else
    print("Opção inválida: " .. opcao)
  end
end
arquivo:write("return {\n")
A primeira linha do arquivo. Depois vem uma linha por contato e, no fim, o } que fecha a tabela.
string.format(" [%q] = { telefone = %q, email = %q },\n", …)
O %q ("quoted", entre aspas) escreve o texto como ele seria escrito num programa Lua: entre aspas, e com uma barra antes das aspas e de outros caracteres especiais que estiverem dentro. É o que garante que o arquivo volte a ser lido certo (veja o cenário).

Grava em ordem alfabética: assim o arquivo é fácil de ler, e não muda de ordem cada vez que é salvo (o que aconteceria com o pairs).

  local pedaco, erro = loadfile(ARQUIVO, "t", {})

  end

PeçaO que faz
loadfile(ARQUIVO, "t", {})Lê o arquivo e o transforma numa função, sem rodar (veja load, loadfile e dofile). O "t" aceita só texto (nada de código pré-compilado). O {} é o ambiente: a tabela onde o código do arquivo procura os nomes globais. Vazia, quer dizer que lá dentro não existem print, os, io, nada (veja _G e _ENV). Uma tabela com return não precisa de nada disso.
if not pedaco then return nil, erro endErro de sintaxe no arquivo (um } faltando): o loadfile devolve nil e a mensagem, sem parar o programa.
pcall(pedaco)Roda a função "protegida" (veja pcall): se ela der erro, o pcall devolve false e a mensagem, em vez de parar tudo. Se der certo, true e o que ela devolveu (a tabela).

-- Agenda de Contatos da Ana, versão 4: buscar, remover e tratar os erros

local ARQUIVO = "contatos.lua"

local function perguntar(texto)
  io.write(texto)
  local resposta = io.read()
  if resposta == nil then
    return nil
  end
  return resposta:match("^%s*(.-)%s*$")
end

-- Os nomes da agenda em ordem alfabética.
local function nomes_em_ordem(agenda)
  local nomes = {}
  for nome in pairs(agenda) do
    nomes[#nomes + 1] = nome
  end
  table.sort(nomes)
  return nomes
end

local function mostrar(nome, contato)
  print(string.format("%-12s %-14s %s", nome, contato.telefone, contato.email))
end

local function listar(agenda)
  local nomes = nomes_em_ordem(agenda)
  if #nomes == 0 then
    print("A agenda está vazia.")
    return
  end
  for _, nome in ipairs(nomes) do
    mostrar(nome, agenda[nome])
  end
  print(#nomes .. " contato(s).")
end

-- Grava a agenda como um programa Lua: "return { ... }".
local function salvar(agenda)
  local arquivo = assert(io.open(ARQUIVO, "w"))
  arquivo:write("return {\n")
  for _, nome in ipairs(nomes_em_ordem(agenda)) do
    local c = agenda[nome]
    arquivo:write(string.format("  [%q] = { telefone = %q, email = %q },\n",
      nome, c.telefone, c.email))
  end
  arquivo:write("}\n")
  arquivo:close()
end

-- Lê a agenda gravada. Devolve a tabela, ou nil e o motivo.
local function carregar()
  local arquivo = io.open(ARQUIVO, "r")
  if not arquivo then
    return {}                   -- primeira vez: ainda não há arquivo
  end
  arquivo:close()
  -- "t": só texto; {}: o arquivo roda sem acesso a nada (nem os, nem io)
  local pedaco, erro = loadfile(ARQUIVO, "t", {})
  if not pedaco then
    return nil, erro            -- erro de sintaxe no arquivo
  end
  local ok, agenda = pcall(pedaco)
  if not ok then
    return nil, agenda          -- erro ao rodar o arquivo
  end
  if type(agenda) ~= "table" then
    return nil, ARQUIVO .. " não devolveu uma tabela"
  end
  return agenda
end

local function adicionar(agenda)
  local nome = perguntar("Nome: ")
  if nome == nil or nome == "" then
    print("Sem nome, sem contato.")
    return
  end
  local telefone = perguntar("Telefone: ") or ""
  local email = perguntar("E-mail: ") or ""
  agenda[nome] = { telefone = telefone, email = email }
  print("Guardado: " .. nome)
end

-- Mostra todos os contatos cujo nome contém o texto (sem ligar para maiúsculas).
local function buscar(agenda)
  local parte = (perguntar("Buscar por: ") or ""):lower()
  local achados = 0
  for _, nome in ipairs(nomes_em_ordem(agenda)) do
    if nome == parte then
      mostrar(nome, agenda[nome])

end

    print("Não achei ninguém com esse nome.")
    return false
  end
  agenda[nome] = nil
  print("Removido: " .. nome)
  return true
end

Resumo

  • Uma tabela com o nome como chave é um dicionário: achar, trocar e remover (= nil) é direto, sem percorrer.
  • A ordem do pairs não vale nada: para listar em ordem, copie as chaves para uma lista e use table.sort.
  • O jeito Lua de gravar dados é escrever um arquivo Lua (return { … }), com %q em todo texto, e ler com dofile.
  • O arquivo de dados é código: prefira loadfile(nome, "t", {}) (sem acesso a nada) e rode com pcall.
  • Se não deu para ler o arquivo, pare sem regravar: senão os dados se perdem.
