Lua os.execute e io.popen

A biblioteca padrão do Lua é pequena de propósito: ela não sabe criar pastas, listar o que tem dentro delas, descobrir o nome do computador, compactar arquivos. Mas o sistema sabe, e tem um comando para cada coisa: mkdir, ls, hostname, zip. Com os.execute ("executar"), o seu programa roda qualquer um desses comandos, como se você o digitasse no terminal. Com io.popen ("abrir um processo"), ele ainda lê o que o comando respondeu.

Você vai aprender
  • Como rodar um comando com os.execute, e o que os três valores que ele devolve querem dizer.
  • Como criar uma pasta (o que o Lua puro não faz) com os.execute("mkdir …").
  • Por que o os.execute não devolve o que o comando escreveu, e como o io.popen resolve isso.
  • Como ler a resposta inteira (p:read("a")) ou linha por linha (p:lines()), e mandar texto para um comando (modo "w").
  • O perigo dos nomes de arquivo com espaço (e coisa pior), e como pôr aspas direito.
  • O que acontece no editor do guia, que roda no navegador e não tem outros programas.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook, um Ubuntu), em /home/ana. Os comandos usados (ls, mkdir, date, sort, cat) são os do Linux; no macOS são quase todos iguais, e no Windows são outros.

A ideia: o recado para o vizinho

A Ana sabe fazer bolo, mas não sabe consertar a bicicleta. Para isso ela tem o vizinho. Ela pode trabalhar com ele de dois jeitos:

  • "Conserta a bicicleta, por favor." Ela pede, espera ele terminar e só quer saber uma coisa: deu certo ou não. Esse é o os.execute.
  • "Me diz que horas são lá no teu relógio?" Agora ela quer a resposta dele, para anotar e usar. Esse é o io.popen.

Nos dois casos, quem faz o trabalho é outro programa, e o seu programa Lua espera ele terminar.

1. os.execute: rodar um comando

A Ana tem um compras.txt dentro da pasta Documentos. O comando ls Documentos lista o que tem lá:

print(os.execute("ls Documentos"))
print("--- o Lua continua depois do comando")

$ lua executar.lua
compras.txt
true	exit	0
--- o Lua continua depois do comando
os.execute("ls Documentos")
Entrega o texto ls Documentos ao shell (o programa que interpreta os comandos do terminal, o sh) e espera ele terminar.
compras.txt
Quem escreveu isso foi o ls, não o Lua. O que o comando escreve vai direto para a tela.
true exit 0
Os três valores que o os.execute devolveu, mostrados pelo print: deu certo (true), o comando terminou normalmente ("exit", "saiu") e o código de saída foi 0 (veja os.exit: 0 = deu certo).

print(os.execute("true"))

Repare na mensagem sh: 1: programa_que_nao_existe: not found: ela vem do sh, e por isso é diferente das mensagens do Lua (e sai em inglês mesmo no Ubuntu da Ana, que está em português).

2. Fazendo o que o Lua não faz: criar uma pasta

Na aula Apagando e Renomeando, você viu que o Lua puro não cria pastas. O comando mkdir cria; o -p faz ele criar as pastas do caminho que faltarem, e não reclamar se a pasta já existir:

local ok, tipo, codigo = os.execute("mkdir -p Documentos/receitas")
if ok then
  print("Pasta pronta.")
else
  print("Não consegui criar a pasta: " .. tipo .. " " .. codigo)
end
local f = assert(io.open("Documentos/receitas/bolo.txt", "w"))
f:write("3 ovos\n")
f:close()
os.execute("ls -R Documentos")

$ lua pasta.lua
Pasta pronta.
Documentos:
compras.txt
receitas

Documentos/receitas:
bolo.txt

Os três valores foram guardados em variáveis (ok, tipo, codigo), e o programa só segue achando que a pasta existe se o ok for true. Depois, um io.open normal criou o arquivo lá dentro, e o ls -R (o -R é "recursivo": entra nas subpastas) mostrou o resultado.

3. io.popen: ler o que o comando respondeu

O os.execute devolve se deu certo, mas não o que o comando escreveu. Tentando pegar o ano com o comando date +%Y:

local resultado = os.execute("date +%Y")
print("O ano é: " .. tostring(resultado))

$ lua saida_errada.lua
2026
O ano é: true

O 2026 foi para a tela, escrito pelo date, e a variável ficou com true. Para capturar o que o comando escreve, use o io.popen. Ele roda o comando e devolve algo que funciona como um arquivo aberto: você lê dele com :read, do mesmo jeito que em Lendo Arquivos:

local p = io.popen("date +%Y")
local ano = p:read("l")
print(p:close())
print("O ano é: " .. ano, type(ano))

$ lua popen.lua
true	exit	0
O ano é: 2026	string
io.popen("date +%Y")
Roda o comando e liga a saída dele ao seu programa, como um cano (é daí o nome: pipe open, "abrir um cano"). O que o date escreveria na tela vai para o p.
p:read("l")
Lê uma linha do que o comando escreveu: 2026. Os formatos são os mesmos do f:read ("a", "l", "n"…).
p:close()
Fecha o cano e espera o comando terminar. Devolve os mesmos três valores do os.execute: true exit 0.
type(ano) → string
O que vem do comando é sempre texto. Para fazer conta com o ano, tonumber(ano).

A resposta inteira, e o Enter do fim

Com "a", você pega tudo. Mas cuidado: quase todo comando termina a resposta com uma quebra de linha:

local p = assert(io.popen("hostname"))
local nome = p:read("a")
p:close()
print("[" .. nome .. "]")
print("[" .. nome:gsub("%s+$", "") .. "]")

$ lua nome.lua
[notebook
]
[notebook]

O hostname (o nome do computador) respondeu notebook e um \n; os colchetes mostram o ] indo para a linha de baixo. O nome:gsub("%s+$", "") tira os espaços e quebras de linha do fim (veja gsub). Com p:read("l") esse problema não existe, porque o "l" já tira o \n.

Linha por linha: p:lines()

local p = assert(io.popen("ls Documentos"))
local quantos = 0
for linha in p:lines() do
  quantos = quantos + 1
  print(quantos .. ": " .. linha)
end
p:close()
print("Itens em Documentos: " .. quantos)

$ lua listar.lua
1: compras.txt
2: receitas
Itens em Documentos: 2

É o mesmo for … in do io.lines. Assim o seu programa consegue a lista de arquivos de uma pasta, outra coisa que o Lua puro não faz. Como no f:lines(), o p:lines() não fecha: o p:close() depois do laço é seu.

O caminho contrário: escrever para o comando ("w")

Com o modo "w", o seu programa escreve e o comando lê, como se alguém digitasse para ele. O comando sort põe linhas em ordem:

local p = assert(io.popen("sort", "w"))
p:write("Caio\n", "Ana\n", "Bia\n")
print(p:close())

$ lua popen_w.lua
Ana
Bia
Caio
true	exit	0

O sort recebeu os três nomes e, quando o close avisou que não vinha mais nada, escreveu na tela já em ordem. (Para ordenar em Lua mesmo, o certo é o table.sort; o exemplo é só para mostrar o modo "w".) O io.popen faz um sentido por vez: ou você lê ("r", o padrão), ou escreve ("w").

O editor "Experimente" roda o Lua de verdade, mas dentro do navegador, e lá não existe ls, date, nem shell de verdade. O editor responde como um Linux em que esses comandos não estão instalados. Rode esta caixa e compare com as saídas acima:

Experimente: veja o que o editor responde. Depois troque "exit 3" por "exit 7": esse tipo de comando (e o "true" e o "false") o editor sabe responder.

print(os.execute())
print(os.execute("ls"))
print(os.execute("exit 3"))

No editor, o ls e o date dão sh: 1: ls: not found e nil exit 127, e o io.popen lê um texto vazio. Só o os.execute(), o "true", o "false" e o "exit N" funcionam como no lab. Por isso, para ver os comandos funcionando de verdade, rode os exemplos desta aula no seu terminal. E as missões abaixo treinam o que dá para treinar sem outros programas: montar o comando e entender a resposta.

5. O perigo: nomes com espaço (e pior)

O texto que você passa ao os.execute é lido pelo shell, que separa as palavras nos espaços, exatamente como o terminal faz com os argumentos. A Ana tem um arquivo chamado lista de compras.txt:

local nome = "lista de compras.txt"
print(os.execute("cat " .. nome))

$ printf 'arroz\nfeijão\n' > 'lista de compras.txt'
$ lua espaco.lua
cat: lista: No such file or directory
cat: de: No such file or directory
cat: compras.txt: No such file or directory
nil	exit	3

O comando que chegou ao shell foi cat lista de compras.txt, e o cat (que mostra arquivos) entendeu três arquivos: lista, de e compras.txt. Nenhum existe, e ele terminou com um código diferente de 0 (aqui, 3). Agora imagine o mesmo engano com rm (apagar) no lugar do cat: se existisse um compras.txt na pasta, ele seria apagado, e não o arquivo que você queria.

E é pior que espaço. Um nome de arquivo pode ter ;, que no shell separa comandos: um arquivo chamado x; rm -rf Documentos faria o seu os.execute("cat " .. nome) rodar dois comandos, e o segundo apaga a pasta inteira. Por isso a regra é: nunca junte num comando um texto que veio de fora (do usuário, de um arquivo, da internet) sem pôr aspas.

Pondo aspas direito

No shell, tudo o que fica entre aspas simples ('…') é um texto só, sem nada especial dentro. O único caractere que precisa de cuidado é a própria aspa simples. Esta função resolve:

local function aspas(texto)
  return "'" .. texto:gsub("'", "'\\''") .. "'"
end
local nome = "lista de compras.txt"
local comando = "cat " .. aspas(nome)
print(comando)
print(os.execute(comando))
print(aspas("d'água.txt"))

$ lua aspas.lua
cat 'lista de compras.txt'
arroz
feijão
true	exit	0
'd'\''água.txt'
"'" .. texto .. "'"
Embrulha o texto em aspas simples.
texto:gsub("'", "'\\''")
Troca cada ' de dentro do texto por '\'': fecha as aspas, põe uma aspa "escapada" (\') e abre de novo. É a receita clássica do shell. O \\ no código Lua vira um \ só no texto (veja Caracteres de Escape).
print(comando)
Mostrar o comando antes de rodar é um ótimo hábito: você vê exatamente o que o shell vai receber.

O 'd'\''água.txt' parece estranho, mas o shell o lê como o nome d'água.txt, inteiro. (A função usa a gramática do shell do Linux e do macOS; o Windows tem outras regras.)

Missão: o programa só mostra o comando que rodaria (sem rodar: é mais seguro para treinar). Ele monta rm foto da praia.jpg, que apagaria três arquivos errados. Use a função aspas no nome para o comando ficar rm 'foto da praia.jpg'.

local function aspas(texto)
  return "'" .. texto:gsub("'", "'\\''") .. "'"
end
local nome = "foto da praia.jpg"
local comando = "rm " .. nome
print(comando)

local function aspas(texto)
  return "'" .. texto:gsub("'", "'\\''") .. "'"
end
local nome = "foto da praia.jpg"
local comando = "rm " .. aspas(nome)
print(comando)

Comando externo é o último recurso: ele depende do sistema (o ls do Linux é o dir do Windows), é mais lento (um programa novo começa a cada chamada) e traz o perigo das aspas. Quando o Lua sabe fazer sozinho, deixe com o Lua.

Quando dá errado

O comando não existe 
local p = io.popen("programa_que_nao_existe")
print("[" .. p:read("a") .. "]")
print(p:close())

$ lua nao_existe.lua
sh: 1: programa_que_nao_existe: not found
[]
nil	exit	127

O io.popen não devolveu nil: quem foi aberto foi o shell, e ele existe. O shell é que não achou o comando, avisou com sh: 1: …: not found (direto na tela, pelo canal de erros) e terminou com 127. Para o seu programa, a resposta foi um texto vazio ([]). O único jeito de saber que falhou é olhar o que o p:close() devolve. Como consertar: confira o nome do comando (e se ele está instalado: no terminal, digite o nome sozinho e veja se o Ubuntu sugere um pacote), e sempre teste o primeiro valor do p:close().

Leu depois de fechar 
local p = io.popen("date +%Y")
p:close()
print(p:read("l"))

$ lua fechado.lua
lua: fechado.lua:3: attempt to use a closed file
stack traceback:

	fechado.lua:3: in main chunk
	[C]: in ?

A mesma mensagem dos arquivos: "tentativa de usar um arquivo fechado". Para o Lua, o p é um arquivo. Como consertar: leia tudo antes do p:close().

Ponto no lugar do dois-pontos 
local p = io.popen("date +%Y")
print(p.read("l"))

$ lua ponto.lua

	ponto.lua:2: in main chunk
	[C]: in ?

Igual ao f.read de Lendo Arquivos: com o ponto, o p não é entregue ao read. Como consertar: p:read("l").

Esperou a saída do os.execute

Você viu na seção 3: local resultado = os.execute("date +%Y") deixa o 2026 na tela e o true na variável. Não é erro do Lua; é o trabalho de cada função. Como consertar: para guardar a resposta, io.popen.

Missão final: entendendo a resposta

Missão: a função explicar recebe os três valores que o os.execute (ou o p:close()) devolve e escreve uma frase. Os testes no fim usam valores de exemplo (sem rodar comando nenhum). Hoje ela diz Deu certo. para tudo. Complete: se ok for verdadeiro, Deu certo.; senão, se o código for 127, O comando não existe (código 127).; senão, Falhou com o código N.

local function explicar(ok, tipo, codigo)
  print("Deu certo.")
end

explicar(true, "exit", 0)
explicar(nil, "exit", 127)
explicar(nil, "exit", 2)

local function explicar(ok, tipo, codigo)
  if ok then
    print("Deu certo.")
  elseif codigo == 127 then
    print("O comando não existe (código 127).")
  else
    print("Falhou com o código " .. codigo .. ".")
  end
end

explicar(true, "exit", 0)
explicar(nil, "exit", 127)
explicar(nil, "exit", 2)

No seu terminal, troque os testes por chamadas de verdade: explicar(os.execute("ls Documentos")) e explicar(os.execute("lss")). Os três valores do os.execute entram direto nos três parâmetros da função.

Resumo

  • os.execute(cmd) roda um comando do sistema, e a saída dele vai para a tela. Devolve true (ou nil), "exit" (ou "signal") e o código; comando que não existe dá sh: 1: …: not found e 127.
  • Para guardar a resposta, io.popen(cmd): leia com p:read("a"), p:read("l") ou p:lines(), e feche com p:close(), que devolve os mesmos três valores. Com "w", você escreve para o comando.
  • A resposta é texto e costuma vir com um \n no fim.
  • O shell separa nos espaços e entende ;: nomes vindos de fora vão sempre entre aspas simples, com a função aspas.
  • No editor do guia não há outros programas: comandos respondem not found e 127. Rode-os no seu terminal.
  • Quando o Lua faz sozinho (arquivos, datas, ambiente), não chame comando nenhum.
