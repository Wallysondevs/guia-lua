Lua Metamétodos

Esta é a página de consulta rápida dos metamétodos: os campos especiais, com nome começando por dois sublinhados (__add, __index…), que você põe numa metatabela para ensinar o Lua a fazer contas, comparar, mostrar ou procurar campos nas suas tabelas. Por exemplo, com __add a expressão a + b funciona mesmo quando a e b são tabelas. Estão aqui todos os que o Lua 5.5 reconhece, agrupados pelo que controlam. A explicação passo a passo começa na aula Metatabelas (setmetatable).

Como ler as tabelas
  • Quase todos os exemplos usam o tipo Vetor do programa abaixo: uma tabela {x = …, y = …} com a metatabela Vetor. Nos exemplos, a = novo(1, 2) e b = novo(3, 4).
  • Resultado é o que o Lua 5.5.0 respondeu no computador da Ana, no modo interativo. Vários valores aparecem separados por vírgula.
  • Recebe diz com que argumentos o Lua chama o seu metamétodo.
local Vetor = {}
Vetor.__index = Vetor

local function novo(x, y)
  return setmetatable({x = x, y = y}, Vetor)
end

Vetor.__add = function(a, b) return novo(a.x + b.x, a.y + b.y) end
Vetor.__eq = function(a, b) return a.x == b.x and a.y == b.y end
Vetor.__tostring = function(v) return "(" .. v.x .. ", " .. v.y .. ")" end

local a = novo(1, 2)
local b = novo(3, 4)
print(a + b)
print(a == novo(1, 2), a == b)
print(a * 2)

$ lua vetor.lua
(4, 6)
true	false
lua: vetor.lua:16: attempt to perform arithmetic on a table value (local 'a')
stack traceback:
	vetor.lua:16: in main chunk
	[C]: in ?

O a + b funcionou por causa do __add; o print mostrou (4, 6) por causa do __tostring; e o == comparou os números por causa do __eq. Já o a * 2 deu erro na linha 16: a metatabela não tem __mul, e o Lua não sabe multiplicar uma tabela (attempt to perform arithmetic on a table value = "tentativa de fazer conta com um valor tabela").

Pule direto para o grupo que você procura:

  • Contas: __add, __sub, __mul, __div, __mod, __pow, __unm, __idiv
  • Bits: __band, __bor, __bxor, __bnot, __shl, __shr
  • Juntar e tamanho: __concat, __len
  • Comparar: __eq, __lt, __le
  • Acesso a campos e chamada: __index, __newindex, __call
  • Usados pelas funções da biblioteca: __tostring, __name, __pairs, __metatable
  • Memória e fechamento: __close, __gc, __mode
  • Todos de A a Z

Contas

O Lua procura o metamétodo primeiro no operando da esquerda; se ele não tiver, no da direita. Por isso 3 * a também chama o __mul de a, com o 3 como primeiro argumento. Para os exemplos, a Ana acrescentou ao Vetor um metamétodo para cada operador (o de __mul troca a ordem quando o número vem primeiro: if type(a) == "number" then a, b = b, a end).

Sem o metamétodo, a conta é erro. Se a metatabela tem o campo __name, a mensagem usa esse nome no lugar de table:

CódigoResultado
y = setmetatable({}, {}); print(y + 1)stdin:1: attempt to perform arithmetic on a table value (global 'y')
x = setmetatable({}, {__name = "Produto"}); print(x + 1)stdin:1: attempt to perform arithmetic on a Produto value (global 'x')
Os textos já têm metamétodos de conta

É por isso que "10" + 1 dá 11: a metatabela dos textos tem __add, __sub, __mul, __div, __idiv, __mod, __pow e __unm (conferido no lab, percorrendo getmetatable("")), que tentam converter o texto em número. Quando não dá, o erro vem desse metamétodo: "abc" + 1 deu stdin:1: attempt to add a 'string' with a 'number'. Veja Conversão.

Comparar

O resultado destes três é sempre convertido em true ou false. No exemplo, o Vetor compara pelo tamanho (x² + y²).

No Lua 5.1, <= usava o __lt

No lab, a mesma tabela com só o __lt deu true para a <= b no lua5.1 (ele calculava not (b < a)) e o erro acima no lua (5.5). O manual do 5.4 já tinha tirado isso (o lua5.4 do Ubuntu ainda deduz, porque foi compilado com a compatibilidade com o 5.3), e no 5.5 acabou de vez: se você usa <= ou >=, defina o __le. O table.sort só precisa do __lt.

__ipairs não existe mais

Tutoriais antigos citam um __ipairs. Ele foi tirado do Lua: no 5.5, o ipairs(t) simplesmente lê t[1], t[2]… e, se a chave faltar, respeita o __index (no lab, uma tabela vazia com um __index que devolve i * 10 até o 3 deu 1 10, 2 20, 3 30 no ipairs). O manual do 5.5 não lista __ipairs entre os metamétodos.

Experimente

Missão: a Ana guarda dinheiro em centavos, numa tabela {centavos = …}. Do jeito que está, o + dá erro. Crie dois metamétodos na metatabela Dinheiro: __add, que devolve reais(a.centavos + b.centavos), e __tostring, que devolve string.format("R$ %.2f", d.centavos / 100). O resultado certo é Total: R$ 16.40.

local Dinheiro = {}

local function reais(centavos)
  return setmetatable({centavos = centavos}, Dinheiro)
end

-- crie aqui Dinheiro.__add e Dinheiro.__tostring

local total = reais(350) + reais(1290)
print("Total: " .. tostring(total))

local Dinheiro = {}

local function reais(centavos)
  return setmetatable({centavos = centavos}, Dinheiro)
end

Dinheiro.__add = function(a, b)
  return reais(a.centavos + b.centavos)
end

Dinheiro.__tostring = function(d)
  return string.format("R$ %.2f", d.centavos / 100)
end

local total = reais(350) + reais(1290)
print("Total: " .. tostring(total))

Livre: uma tabela de preços com valor padrão (__index) e um aviso ao cadastrar produto novo (__newindex). Troque as funções e veja o que muda.

local precos = setmetatable({pao = 0.5}, {
  __index = function(t, k)
    return 0
  end,
  __newindex = function(t, k, v)
    print("produto novo: " .. k)
    rawset(t, k, v)
  end,
})

print(precos.pao, precos.queijo)
precos.leite = 4.9
precos.leite = 5.2
print(precos.leite, rawget(precos, "queijo"))

Resumo

  • Um metamétodo é um campo __nome da metatabela; ligue com setmetatable(t, mt).
  • Contas: __add, __sub, __mul, __div, __idiv, __mod, __pow, __unm; bits: __band, __bor, __bxor, __bnot, __shl, __shr; e __concat, __len.
  • Comparar: __eq, __lt e __le (no 5.5 o <= não usa mais o __lt).
  • __index (ler chave que falta: função ou tabela, a base das classes), __newindex (gravar chave nova), __call (chamar a tabela).
  • Campos da biblioteca: __tostring, __name, __pairs, __metatable; memória: __close, __gc, __mode.
