Lua pcall: Capturando Erros

Até aqui, todo erro parava o programa inteiro. Às vezes é isso mesmo que você quer; mas imagine o caixa da padaria fechando sozinho porque um cliente digitou o preço errado. O pcall (de protected call, "chamada protegida") roda uma função e, se ela der erro, em vez de parar o programa, devolve false e a mensagem. Você decide o que fazer: avisar, tentar de novo, pular aquele item. Em outras linguagens, isso se chama try/catch; no Lua, é uma função comum.

Você vai aprender
  • Como chamar uma função com pcall(funcao, arg1, arg2…) e ler o que ela devolve: true e os resultados, ou false e a mensagem.
  • O jeito de sempre: local ok, resultado = pcall(…) e um if.
  • Como proteger um trecho de código com uma função anônima.
  • Como capturar um erro lançado como tabela e ler os campos.
  • Um programa que pede a idade de novo até a resposta ser válida.
  • O engano clássico pcall(f(x)), e o que o pcall não mostra (o rastro).

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook) com lua arquivo.lua. Antes, convém conhecer error.

A ideia: a rede do trapezista

No circo, o trapezista faz o número lá em cima, e embaixo há uma rede de proteção. Se ele cair, a rede segura, o público respira aliviado, e o espetáculo continua com o próximo número. Sem a rede, uma queda encerraria a noite.

O pcall é a rede. Você entrega a ele a função "arriscada"; ele a executa. Se tudo der certo, ele devolve true e o que a função devolveu. Se ela "cair" (der erro), a rede segura: o programa não para, e o pcall devolve false e a mensagem do erro, para você saber o que aconteceu.

1. O primeiro pcall

local function dividir(a, b)
  if b == 0 then
    error("divisão por zero")
  end
  return a / b
end

print(pcall(dividir, 10, 2))
print(pcall(dividir, 7, 0))
print("O programa continua!")

$ lua p1.lua
true	5.0
false	p1.lua:3: divisão por zero
O programa continua!
$ echo $?
0
pcall(dividir, 10, 2)
O primeiro argumento é a função, sem parênteses: dividir, e não dividir(…). Os outros (10, 2) são os argumentos que o pcall vai passar para ela. É como dizer: "pcall, chame o dividir com 10 e 2, e me segure se cair".
true 5.0
Deu certo: o primeiro valor é true, e depois vem o que a função devolveu.
false p1.lua:3: divisão por zero
Deu erro: o primeiro valor é false, e o segundo é a mensagem, exatamente como apareceria no terminal, com arquivo:linha: e sem o lua: na frente.
O programa continua!
O erro foi capturado; o programa seguiu até o fim e terminou com código de saída 0, como se nada tivesse acontecido.

Repare que não há stack traceback: quem mostra o rastro é o programa lua, quando um erro chega até ele sem ser capturado. Aqui o erro foi segurado antes. (Para ter o rastro mesmo capturando o erro, existe o xpcall.)

2. O jeito de sempre: ok, resultado e um if

Na prática, ninguém imprime o pcall direto. Guarde os dois valores em locais e teste o primeiro:

local saldo = 100

local function sacar(valor)
  if valor > saldo then
    error("saldo insuficiente: tem " .. saldo .. ", pediu " .. valor, 0)
  end
  saldo = saldo - valor
  return saldo
end

for _, valor in ipairs({30, 50, 40, 10}) do
  local ok, resultado = pcall(sacar, valor)
  if ok then
    print("Saque de " .. valor .. " ok. Saldo: " .. resultado)
  else
    print("Saque de " .. valor .. " recusado: " .. resultado)
  end
end

$ lua p2.lua
Saque de 30 ok. Saldo: 70
Saque de 50 ok. Saldo: 20
Saque de 40 recusado: saldo insuficiente: tem 20, pediu 40
Saque de 10 ok. Saldo: 10
error(…, 0)
O nível 0 tira o arquivo:linha: da mensagem (veja error). Como ela vai ser mostrada para a cliente, fica mais limpa assim.
local ok, resultado = pcall(sacar, valor)
Dois valores, duas variáveis (veja Vários Retornos). O nome ok é o costume da comunidade.
if ok then
Deu certo: o resultado é o que a função devolveu (o saldo novo).
else
Deu erro: o resultado é a mensagem. O mesmo nome guarda coisas diferentes conforme o caso; por isso o if vem sempre antes de usar.

O saque de 40 foi recusado, e o de 10, depois dele, funcionou: um erro no meio da lista não estragou os outros. Sem o pcall, o programa teria parado no terceiro saque.

3. Protegendo um trecho: a função anônima

E se o código arriscado não for uma função pronta, mas algumas linhas soltas? Embrulhe-as numa função anônima (sem nome), escrita ali mesmo, dentro do pcall:

local ok, msg = pcall(function ()
  print("antes do erro")
  error("parou aqui")
  print("depois do erro")
end)
print(ok, msg)

$ lua p11.lua
antes do erro
false	p11.lua:3: parou aqui

O function () … end cria a função na hora, e o pcall a executa. O que estava antes do erro rodou (antes do erro); o que estava depois, dentro da função, não (depois do erro nunca apareceu). O erro "pula" direto para fora da função, até o pcall que o segura.

O pcall segura qualquer erro, não só os lançados com error. Os erros do próprio Lua chegam com a mesma mensagem que você veria no terminal:

local ok, msg = pcall(function ()
  local t = nil
  return t.nome
end)
print(ok)
print(msg)
print(pcall(function () return 1 + {} end))
print(pcall(string.rep, "ab", 3))
print(pcall(string.rep))
print(pcall(nil))
print(pcall(math.max, 3, 9, 4))

$ lua p3.lua
false
p3.lua:3: attempt to index a nil value (local 't')
false	p3.lua:7: attempt to perform arithmetic on a table value
true	ababab
false	bad argument #1 to 'string.rep' (string expected, got no value)
false	attempt to call a nil value
true	9

Algumas coisas para notar:

  • pcall(string.rep, "ab", 3): o pcall funciona com as funções prontas do Lua também. Deu certo, devolveu true e ababab.
  • pcall(string.rep), sem argumentos: a mensagem não tem arquivo:linha:, porque quem chamou o string.rep foi o próprio pcall, e não uma linha sua. (E o nome aparece como 'string.rep'; numa chamada normal sairia só 'rep'.)
  • pcall(nil): se o que você passa não é uma função, o pcall também não quebra: devolve false e attempt to call a nil value.

4. Erros em forma de tabela

Na aula error, você viu que dá para lançar uma tabela, e que o lua só sabia dizer (error object is a table value). Com o pcall, a tabela chega inteira nas suas mãos, e você lê os campos:

local function buscar(codigo)
  if codigo ~= 1 then
    error({ codigo = 404, mensagem = "produto não encontrado" })
  end
  return "pão francês"
end

for _, c in ipairs({1, 7}) do
  local ok, r = pcall(buscar, c)
  if ok then
    print("Achei: " .. r)
  else
    print("Erro " .. r.codigo .. ": " .. r.mensagem)
  end
end

$ lua p4.lua
Achei: pão francês
Erro 404: produto não encontrado

Com uma tabela, o programa pode decidir pelo código (um número, fácil de comparar com ==) em vez de procurar palavras dentro de uma mensagem. Num programa maior, cada tipo de problema ganha o seu código: 404 para "não encontrado", 403 para "proibido"… (os mesmos números que os sites usam).

Outros valores lançados com error também chegam como são, conferidos no lab:

local ok, msg = pcall(error, "falhou")
print(ok, msg)
print(pcall(error, "falhou", 0))
print(pcall(error))
print(pcall(error, 42))
local ok2, msg2 = pcall(error, 42)
print(type(msg2), msg2 + 1)

$ lua p6.lua
false	falhou
false	falhou
false	<no error object>
false	42
number	43
  • pcall(error, "falhou"): sem arquivo:linha:, pelo mesmo motivo do string.rep: quem chamou o error foi o pcall, não uma linha sua.
  • pcall(error, 42): o erro é o número 42 (o type diz number, e dá para somar).
  • pcall(error), sem mensagem: 5.5 o Lua 5.5 entrega o texto <no error object> ("sem objeto de erro"). No Lua 5.4 do lab, o mesmo programa devolveu nil. Nunca lance um erro sem mensagem; mas, se receber um <no error object>, já sabe de onde veio.

5. Pedir de novo até a resposta ser válida

Um uso muito comum: ler algo do teclado, validar com uma função que lança erro, e, se der erro, avisar e perguntar de novo. O pcall fica dentro de um while:

local function ler_idade(texto)
  local n = tonumber(texto)
  if not n then
    error("isso não é um número: " .. texto, 0)
  end
  if n < 0 or n > 130 then
    error("idade fora da faixa: " .. n, 0)
  end
  return n
end

while true do
  io.write("Sua idade: ")
  local linha = io.read()
  if not linha then break end
  local ok, resultado = pcall(ler_idade, linha)
  if ok then
    print("Idade registrada: " .. resultado)
    break
  end
  print("Ops: " .. resultado .. ". Tente de novo.")
end

No terminal, a Ana digitou Ana, depois 200, depois 32:

$ lua p7.lua
Sua idade: Ana
Ops: isso não é um número: Ana. Tente de novo.
Sua idade: 200
Ops: idade fora da faixa: 200. Tente de novo.
Sua idade: 32
Idade registrada: 32
ler_idade
Só valida: ou devolve o número, ou lança um erro com nível 0 (mensagem limpa, para o usuário).
if not linha then break end
Se a entrada acabar (Ctrl+D no terminal), o io.read() devolve nil, e o laço termina em vez de perguntar para sempre.
pcall(ler_idade, linha)
A rede: um erro na validação vira um false e uma mensagem, não o fim do programa.
break
Deu certo: sai do laço (veja break).

6. O pcall também segura o stack overflow

Até o estouro da pilha (veja Recursão) é um erro como outro qualquer:

local function f(n) return f(n + 1) + 1 end
print(pcall(f, 1))
print("sobrevivi")

$ lua p8.lua
false	p8.lua:1: stack overflow
sobrevivi

Não faça disso um hábito (o certo é consertar a recursão), mas é bom saber: um pcall em volta da parte principal do programa garante que nenhum erro o derrube sem uma mensagem sua.

Formas diferentes de fazer a mesma coisa

O mesmo saque protegido, de três jeitos:

FormaCódigoQuando usar
Passando a função e os argumentospcall(sacar, valor)O mais comum: uma chamada só, de uma função que já existe
Função anônimapcall(function () return sacar(valor) end)Para proteger várias linhas, ou uma chamada de método (pcall(function () return conta:sacar(10) end))
Sem erro nenhum: nil, "mensagem"local novo, msg = sacar_seguro(valor)Quando a função é sua e o problema é esperado: ela devolve nil e a mensagem em vez de lançar erro (veja error)
Com o rastroxpcall(sacar, debug.traceback, valor)Quando você precisa saber por onde o erro passou (xpcall)

Para um método, também funciona pcall(conta.sacar, conta, 10): lembre que conta:sacar(10) é só um atalho para conta.sacar(conta, 10) (veja Métodos).

Quando dá errado

Escreveu pcall(f(x)): a rede ficou embaixo do trapezista errado 
local function dividir(a, b)
  if b == 0 then
    error("divisão por zero")
  end
  return a / b
end

local ok, msg = pcall(dividir(7, 0))
print("nunca chega aqui", ok, msg)

$ lua p5.lua
lua: p5.lua:3: divisão por zero
stack traceback:
	[C]: in global 'error'
	p5.lua:3: in local 'dividir'
	p5.lua:8: in main chunk
	[C]: in ?
$ echo $?
1

O erro não foi capturado, e repare: no rastro nem aparece o pcall. Com os parênteses, dividir(7, 0) roda primeiro, fora de qualquer proteção, para que o resultado dele seja entregue ao pcall. O erro acontece antes de o pcall começar. Como consertar: passe a função e os argumentos separados, pcall(dividir, 7, 0), ou embrulhe numa anônima, pcall(function () return dividir(7, 0) end).

Usou o resultado sem testar o ok

Se você escreve local ok, total = pcall(somar, lista) e depois print("Total: " .. total * 2) sem testar, quando der erro o total é a mensagem (um texto), e a conta quebra com outro erro, bem mais confuso, longe do problema original. No lab, com pcall(somar, {1, "x"}) seguido de print("Total: " .. total * 2), saiu attempt to mul a 'string' with a 'number' ("tentativa de multiplicar um texto por um número"): o texto era a mensagem do primeiro erro. Teste sempre o ok antes.

A mensagem capturada não diz por onde o erro passou

O pcall devolve só a mensagem: a linha onde o erro aconteceu, sem o stack traceback. Quando a função protegida chama outras, e o erro estoura lá no fundo, você sabe a linha, mas não o caminho. Para isso existe o xpcall com o debug.traceback.

O pcall escondeu um erro de digitação

O pcall captura todos os erros, inclusive os seus enganos de programação (um pirnt, um totl). Se você captura e não mostra a mensagem (if not ok then return end), o defeito some em silêncio, e o programa simplesmente "não faz nada". Ao capturar, mostre (ou guarde) a mensagem, pelo menos enquanto estiver testando.

Resumo

  • pcall(f, args…) roda f em modo protegido: devolve true e os resultados, ou false e a mensagem do erro. O programa continua.
  • Passe a função sem parênteses; pcall(f(x)) roda f(x) antes, sem proteção.
  • Use local ok, r = pcall(…) e teste o ok antes de usar o r.
  • Para proteger várias linhas, use uma função anônima: pcall(function () … end).
  • O pcall segura qualquer erro: os seus (error), os do Lua, até stack overflow. Um erro em tabela chega inteiro.
  • A mensagem capturada não traz o rastro; para isso, xpcall e debug.traceback.
