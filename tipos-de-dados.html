Lua Os Tipos de Dados

Na aula do print apareceu a regra "com aspas é texto, sem aspas é valor", e na do io.read o "30" digitado que não era o número 30. Por trás das duas está a mesma ideia: todo valor do Lua é de um tipo, e o tipo decide o que dá para fazer com ele. Número se soma, texto se junta, true e false decidem caminhos. O Lua tem só oito tipos; esta aula apresenta todos, e cada um ganha depois a sua aula própria.

Você vai aprender
  • O que é um tipo de dado, e os oito tipos do Lua: nil, boolean, number, string, table, function, userdata e thread.
  • Que no Lua quem tem tipo é o valor, não a variável.
  • Que o tipo number tem dois jeitos: inteiro (10) e float (10.0).
  • Por que "10" e 10 não são a mesma coisa: "10" + 1, "10" .. 1, 10 == "10".
  • Que só nil e false contam como "falso" (o 0 e o "" contam como verdadeiro).
  • As mensagens de erro que aparecem quando o tipo está errado, e como ler o tipo que elas citam.

Todos os programas desta aula foram rodados com o Lua 5.5 na máquina fictícia da Ana (usuária ana, computador notebook). As caixas "Experimente" rodam o mesmo Lua de verdade, no seu navegador.

A ideia: o que vai em cada pote

Na cozinha da padaria, cada coisa tem o seu jeito de ser usada: a farinha se pesa, o leite se mede em litros, os ovos se contam, a receita se lê. Ninguém tenta "pesar" uma receita ou "ler" um ovo. O tipo de cada coisa diz quais operações fazem sentido.

No Lua é igual. O 5 é um número: dá para somar, multiplicar, comparar. O "Ana" é um texto: dá para juntar com outro texto, contar as letras, pôr em maiúsculas. Tente somar "Ana" + 1, e o Lua para o programa: essa operação não existe para esse tipo.

1. Os oito tipos

A função type (em inglês, "tipo") diz o tipo de qualquer valor, como um texto. Ela tem aula própria, a próxima (Descobrindo o Tipo); aqui, ela só vai mostrar os oito:

print(type(nil))
print(type(true))
print(type(42))
print(type(3.5))
print(type("Ana"))
print(type({}))
print(type(print))
print(type(io.stdout))
print(type(coroutine.create(print)))

O 1e3 é a notação científica, "1 vezes 10 elevado a 3": mil. Ele saiu 1000.0, com .0, e isso tem a ver com a seção 3. E as três formas de escrever texto (aspas duplas, simples e colchetes duplos) dão o mesmo tipo, string.

Já tabelas e funções não têm um jeito "bonito" de aparecer: o print mostra o tipo e um endereço de memória, que muda a cada vez que o programa roda. Na máquina da Ana, duas rodadas seguidas do mesmo programa deram:

2. O valor tem tipo; a variável, não

Em algumas linguagens, você declara "esta variável é de números" e ela nunca mais aceita outra coisa. No Lua, não: a variável é só uma etiqueta, e quem tem tipo é o valor que está nela naquele momento:

local caixa = 10
print(type(caixa))
caixa = "dez"
print(type(caixa))
caixa = nil
print(type(caixa))

$ lua mudar.lua
number
string
nil

A mesma caixa foi number, string e nil. Por isso se diz que o Lua tem tipagem dinâmica: o tipo é conferido na hora em que o programa roda, e não antes. A vantagem é a liberdade; o preço é que um erro de tipo só aparece quando a linha errada roda (às vezes, só no dia em que a pessoa digita a coisa "errada").

Missão: mude só os valores da primeira linha (as aspas!) para que o programa mostre number, string e boolean, nessa ordem.

local a, b, c = "5", 5, "true"
print(type(a), type(b), type(c))

local a, b, c = 5, "5", true
print(type(a), type(b), type(c))

3. Um tipo, dois jeitos de número: inteiro e float

Para o type, todo número é number. Por dentro, porém, o Lua 5.5 guarda os números de dois jeitos: inteiro (integer, sem casa decimal) e float (com casa decimal; o nome vem de "ponto flutuante"). A função math.type mostra qual:

print(10, 10.0, 10 == 10.0)
print(math.type(10), math.type(10.0), math.type("10"))
print(7 / 2, 7 // 2, 2^3)

$ lua numeros.lua
10	10.0	true
integer	float	nil
3.5	3	8.0
10 e 10.0
O mesmo número, guardado de dois jeitos. O print mostra a diferença (o .0), mas para comparar eles são iguais: 10 == 10.0 dá true.
integer float nil
math.type diz integer ou float; para algo que não é número, como o texto "10", devolve nil.
7 / 2 → 3.5, 7 // 2 → 3, 2^3 → 8.0
A divisão / e a potência ^ sempre dão float; a divisão inteira // dá inteiro. Detalhes em Divisão e Números.
No Lua 5.1 e no LuaJIT, não há essa divisão

Até o Lua 5.2 (e no LuaJIT, que segue o 5.1), todo número era float, não existia math.type e o 10 / 2 aparecia como 5. Nem o // existia: o mesmo numeros.lua, no lua5.1 da Ana, nem rodou: lua5.1: numeros.lua:3: unexpected symbol near '/'. Mais em Lua 5.1, LuaJIT, 5.4 e 5.5.

4. Texto que parece número não é número

O "10" (entre aspas) é uma string com dois caracteres; o 10 é um number. Às vezes o Lua converte um no outro sozinho (a coerção), às vezes não, e é isso que confunde:

print("10" + 1)
print("10" .. 1)
print(10 .. "")
print(10 == "10")
print("3" * "4")

$ lua texto-numero.lua
11
101
10
false
12
"10" + 1 → 11
O + é só para números, então o Lua tenta converter o texto "10" em número, e consegue.
"10" .. 1 → 101
O .. é só para textos, então o Lua converte o 1 em texto e junta: "101".
10 .. "" → 10
Juntar um número com um texto vazio é um truque para transformar número em texto (o jeito claro é tostring(10)).
10 == "10" → false
Para comparar igualdade, o Lua não converte: um número e um texto nunca são iguais, mesmo "parecendo" iguais.
"3" * "4" → 12
Contas convertem os dois lados.

E para comparar maior e menor, também não há conversão: aí o erro aparece.

local idade = "30"
print(idade > 18)

$ lua comparar.lua
lua: comparar.lua:2: attempt to compare number with string
stack traceback:
	comparar.lua:2: in main chunk
	[C]: in ?

"Tentativa de comparar número com string". (A mensagem diz "number with string", na ordem contrária à do código, porque o Lua transforma idade > 18 em 18 < idade antes de comparar.) É exatamente o que acontece com uma resposta do io.read(). Como consertar: converta o texto com tonumber antes (aula Conversão): com local idade = tonumber("30"), o mesmo print mostra true.

A regra prática

Não conte com a coerção. Se um valor é número, guarde-o como número (tonumber logo que ele chega); se é texto para mostrar, monte o texto com .. ou string.format. Cada valor com o seu tipo certo, desde o começo.

Missão: a resposta do io.read() é texto, e a comparação quebra. Converta a resposta com tonumber(...) para que o programa mostre Maior de idade? e true. A entrada já vem pronta: 30.

io.write("Idade: ")
local idade = io.read()
print("Maior de idade?", idade >= 18)

io.write("Idade: ")
local idade = tonumber(io.read())
print("Maior de idade?", idade >= 18)

5. Verdadeiro e falso: só nil e false são falsos

Quando o Lua precisa decidir "sim ou não" (num if, num not), ele aceita qualquer valor. A regra é curta: nil e false contam como falso; todo o resto conta como verdadeiro. O not ("não") mostra isso, porque inverte:

print(not nil, not false)
print(not 0, not "", not "false")

$ lua verdade.lua
true	true
false	false	false

O not nil deu true: nil conta como falso. Já not 0 deu false: o zero conta como verdadeiro, assim como o texto vazio "" e até o texto "false". Quem vem de outras linguagens (onde o 0 e o texto vazio são falsos) tropeça nisso. A história completa está em Booleanos e em and, or e not.

6. Um gostinho de table

Os sete outros tipos guardam um valor só; a table guarda vários. É com ela que o Lua faz listas, cadastros, fichas, e até as próprias bibliotecas (io, string e math são tabelas):

local compras = {"pão", "leite", "café"}
print(compras[1], #compras)
print(type(compras))

$ lua tabela.lua
pão	3
table

O compras[1] pega o 1º item, e o # conta quantos são. É só um aperitivo: o Nível 2 começa com Tabelas: a Estrutura de Tudo.

Formas de descobrir e escolher o tipo

Quero...Use
Saber o tipo de um valortype(x) → "number", "string"... (aula type)

Quando dá errado: o tipo na mensagem

Quase todo erro de tipo tem o mesmo formato: attempt to ("tentativa de") + a operação + a ... value (o tipo do valor que atrapalhou) + entre parênteses, de onde veio o valor. Aprender a ler o tipo na mensagem resolve metade dos problemas.

Conta com uma tabela 
local compras = {"pão", "leite"}
print(compras + 1)

$ lua erro-tabela.lua
lua: erro-tabela.lua:2: attempt to perform arithmetic on a table value (local 'compras')
stack traceback:
	erro-tabela.lua:2: in main chunk
	[C]: in ?

"Tentativa de fazer conta com um valor table (a local compras)". Uma lista não se soma. Talvez você quisesse a quantidade de itens: #compras + 1.

Juntar texto com booleano ou tabela 
local pago = true
print("Pago: " .. pago)

$ lua erro-concat.lua
lua: erro-concat.lua:2: attempt to concatenate a boolean value (local 'pago')
stack traceback:
	erro-concat.lua:2: in main chunk
	[C]: in ?

O .. converte números sozinho, mas não booleanos. Com uma tabela, a mensagem diz a table value:

$ lua erro-concat2.lua
lua: erro-concat2.lua:2: attempt to concatenate a table value (local 'compras')
stack traceback:
	erro-concat2.lua:2: in main chunk
	[C]: in ?

Como consertar: "Pago: " .. tostring(pago). Para a tabela, junte os itens com table.concat.

Chamar um número como se fosse função 
local preco = 5
preco()

$ lua erro-chamar.lua
lua: erro-chamar.lua:2: attempt to call a number value (local 'preco')
stack traceback:
	erro-chamar.lua:2: in main chunk
	[C]: in ?

Os parênteses () são para chamar funções; preco é um number. É a mesma mensagem do Print errado (attempt to call a nil value), agora com outro tipo.

Usar o ponto num número 
local preco = 5
print(preco.valor)

$ lua erro-indexar.lua
lua: erro-indexar.lua:2: attempt to index a number value (local 'preco')
stack traceback:
	erro-indexar.lua:2: in main chunk
	[C]: in ?

Indexar é pegar um campo de dentro de alguma coisa, com . ou [ ]; só tabelas (e strings, para as funções delas) têm campos. Você vai ver muito o irmão deste erro, attempt to index a nil value, quando uma tabela que você esperava não existe.

Resumo

  • Todo valor tem um tipo, e o tipo decide o que dá para fazer com ele. O Lua tem oito: nil, boolean, number, string, table, function, userdata, thread.
  • Quem tem tipo é o valor; a mesma variável pode guardar valores de tipos diferentes (tipagem dinâmica).
  • number tem dois jeitos: inteiro (10) e float (10.0); math.type diz qual. 10 == 10.0 é true.
  • "10" é texto. Contas e .. convertem sozinhos; == não converte (10 == "10" é false), e </> entre texto e número dá erro. Converta com tonumber/tostring.
  • Só nil e false são falsos; 0 e "" são verdadeiros.
  • Nas mensagens attempt to ... a TIPO value (...), o tipo citado é a pista do que estava errado.
