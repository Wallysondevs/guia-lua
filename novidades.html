Novidades do Lua 5.5

O Lua 5.5 foi lançado em 22 de dezembro de 2025, cinco anos depois do 5.4. Ao longo do guia, tudo o que é novo nele ganhou a etiqueta 5.5. Esta página junta essas novidades num lugar só, na ordem da lista oficial de mudanças (readme.html#changes) e da lista de incompatibilidades do manual (manual §8). Cada uma tem um exemplo rodado no 5.5 e, quando ajuda, no 5.4, e o link para a aula que trata dela.

Você vai aprender
  • As novidades da linguagem: global, varargs com nome, a variável do for somente leitura.
  • As novidades das bibliotecas: floats mostrados com todos os dígitos, table.create, utf8.offset, a coleta de lixo.
  • O que mudou por dentro: listas menores, a readline do modo interativo, o aviso do local no >.
  • As incompatibilidades: o que um programa do 5.4 pode estranhar no 5.5.

Os exemplos rodaram na máquina da Ana (usuária ana, computador notebook), com o lua (5.5.0) e o lua5.4 (5.4.8) do Ubuntu. A versão mais recente do 5.5 em outubro de 2026 é a 5.5.1 (de 3 de agosto de 2026, segundo lua.org/versions.html); as versões "5.5.x" só corrigem defeitos, então tudo aqui vale para elas também.

A ideia: a lista de mudanças da casa nova

Quando a família da Ana se muda para um apartamento novo, a maior parte da vida continua igual: os mesmos móveis, as mesmas receitas. Mas tem coisas novas (uma varanda), coisas que mudaram de lugar (o interruptor da sala) e uma ou outra que deixou de existir (a vaga de garagem). Uma lista de mudanças evita os sustos. Esta página é essa lista para quem vem do Lua 5.4 (ou de qualquer versão anterior; para o 5.1 e o LuaJIT, veja versoes.html).

1. A declaração global

A maior novidade. No Lua, todo nome que não é local é global, e um nome digitado errado vira uma global nova, sem aviso nenhum (veja local × Global). No 5.5, a declaração global deixa você dizer quais globais o arquivo usa. Depois dela, qualquer outro nome livre é erro antes de rodar:

global x = 10
print(x)

global print, x
x = 10
print(x)

$ lua glob.lua
lua: glob.lua:2: variable 'print' not declared
$ lua glob2.lua
10
$ lua5.4 glob2.lua
lua5.4: glob2.lua:1: syntax error near 'print'

No glob.lua, só o x foi declarado; o print, não, e o 5.5 recusa o programa ("variável print não declarada"). Repare que não há stack traceback: o erro é pego na compilação, antes da primeira linha rodar. No 5.4, a linha global … é erro de sintaxe.

Outras formas, todas colhidas no lab:

global print, string
global function saudar(nome)
  print(string.format("Olá, %s!", nome))
end
saudar("Ana")

global *
contador = 1
print(contador)

global<const> *
print("ok")
x = 1

$ lua gfunc.lua
Olá, Ana!
$ lua gestrela.lua
1
$ lua glob5.lua
lua: glob5.lua:3: attempt to assign to const variable 'x'
global function saudar
Declara e cria uma função global de uma vez (como o local function, só que global).
global *
"Todo nome livre daqui para baixo é global": volta ao comportamento antigo, mas por escrito.
global<const> *
"Todo nome livre é uma global que eu só leio": dá para usar o print, mas tentar criar a global x vira erro (attempt to assign to const variable 'x'), também antes de rodar (o ok nem apareceu).
global como nome de variável

O manual do 5.5 lista global como palavra reservada (§8.1). Mas o luaconf.h oficial do 5.5.0 vem com a opção LUA_COMPAT_GLOBAL ligada, e é assim que o Lua do Ubuntu e o do editor foram compilados: local global = 1 continua funcionando, e global só vira declaração quando vem seguido de um nome, de *, de < ou de function. A explicação completa está em A Declaração global.

Missão: o programa declarou que só usa a global print, e por isso o 5.5 recusa a variável total, que foi criada sem local. Conserte sem apagar a linha do global.

global print
total = 0
for _, preco in ipairs({ 10, 20 }) do
  total = total + preco
end
print("Total: " .. total)

global print, ipairs
local total = 0
for _, preco in ipairs({ 10, 20 }) do
  total = total + preco
end
print("Total: " .. total)

Repare que, consertado o total, o Lua ainda reclama do ipairs, que também é uma global: ele precisa entrar na lista (global print, ipairs). É exatamente o tipo de conferência que a declaração faz por você.

2. Varargs com nome: ...t

Uma função variádica (que aceita "quantos argumentos vierem"; veja Funções Variádicas) agora pode dar um nome à tabela dos argumentos extras, escrito depois dos três pontos. Nessa tabela, os argumentos ficam em t[1], t[2]… e a quantidade fica em t.n:

local function soma(...t)
  local total = 0
  for i = 1, t.n do total = total + t[i] end
  return total, t.n, select("#", ...)
end
print(soma(10, 20, 30))
print(soma())

$ lua vnome.lua
60	3	3
0	0	0
$ lua5.4 vararg.lua
lua5.4: vararg.lua:1: ')' expected near 't'

O ... de sempre continua funcionando junto (o select("#", ...) deu o mesmo 3). Antes, para ter essa tabela, era preciso escrever local t = table.pack(...) (aula table.pack). O nome é uma variável somente leitura: t = {} dentro da função dá attempt to assign to const variable 't' (colhido no lab). No 5.4 (o vararg.lua começa com a mesma linha, local function soma(...t)), a sintaxe nem existe.

Missão: complete a função media usando um vararg com nome: troque (...) por (...notas) e calcule a média com notas[i] e notas.n. Para as notas 7, 8 e 9, deve sair Média: 8.0.

local function media(...)
  return 0
end

print("Média: " .. media(7, 8, 9))

local function media(...notas)
  local soma = 0
  for i = 1, notas.n do
    soma = soma + notas[i]
  end
  return soma / notas.n
end

print("Média: " .. media(7, 8, 9))

3. A variável do for é somente leitura

for i = 1, 3 do
  i = i * 2
  print(i)
end

$ lua forvar.lua
lua: forvar.lua:2: attempt to assign to const variable 'i'
$ lua5.4 forvar.lua
2
4
6

Esta é uma das incompatibilidades: um programa que mudava a variável do for rodava no 5.4 e não roda mais. O manual recomenda declarar uma local com o mesmo nome dentro do laço (local i = i * 2). Vale para o for numérico e, no for … in, para a primeira variável (a de controle): no lab, for i, nome in ipairs(lista) deixou mudar o nome, mas i = 5 deu attempt to assign to const variable 'i'. Aula: for Numérico; a missão final de versoes.html treina o conserto.

4. Floats mostrados com todos os dígitos

$ lua -e 'print(0.1 + 0.2 == 0.3, 100 / 3, 1e15 / 7, 2^63, -0.0, 1e300 * 1e10)'
false	33.333333333333336	142857142857142.84	9.2233720368547758e+18	-0.0	inf
$ lua5.4 -e 'print(0.1 + 0.2 == 0.3, 100 / 3, 1e15 / 7, 2^63, -0.0, 1e300 * 1e10)'
false	33.333333333333	1.4285714285714e+14	9.2233720368547758e+18	-0.0	inf

A lista oficial diz: "floats são mostrados em decimal com dígitos suficientes para serem lidos de volta corretamente". O 5.4 arredondava para 14 dígitos na hora de mostrar (por isso 100 / 3 aparecia como 33.333333333333). O valor não mudou, só o jeito de escrever: agora, o que o print mostra, se você digitar de volta, dá exatamente o mesmo número. O famoso 0.1 + 0.2 aparece como 0.30000000000000004, e a primeira coluna (false) mostra que ele nunca foi igual a 0.3, nem no 5.4. Para mostrar números para pessoas, continue usando string.format("%.2f", x). Aula: Números.

5. table.create

local t = table.create(1000)
print(#t, type(t))
local u = table.create(0, 10)
u.nome = "Ana"
print(u.nome)

$ lua tcreate.lua
0	table
Ana
$ lua5.4 tcreate.lua
lua5.4: tcreate.lua:1: attempt to call a nil value (field 'create')
stack traceback:
	tcreate.lua:1: in main chunk
	[C]: in ?

table.create(n) cria uma tabela vazia (o #t dá 0), mas já com espaço reservado para n itens de lista; table.create(0, m) reserva espaço para m campos com nome. É só uma otimização: para uma tabela que vai receber milhares de itens, o Lua não precisa ir aumentando o espaço aos poucos. Para o dia a dia, {} continua sendo o jeito normal. No 5.4, a função não existe.

6. utf8.offset devolve início e fim

local s = "Olá, coração"
print(utf8.offset(s, 3))
print(s:sub(utf8.offset(s, 3)))
print(s:sub((utf8.offset(s, 3))))

$ lua uoff.lua
3	4
á
á, coração
$ lua5.4 uoff.lua
3
á, coração
á, coração

O á é o 3º caractere e ocupa os bytes 3 e 4 (veja Acentos e a Biblioteca utf8). No 5.5, utf8.offset devolve as duas posições; no 5.4, só a primeira. Isso muda, sem erro, o resultado de s:sub(utf8.offset(s, 3)): o segundo valor vira o fim do sub, e sai uma letra só. Com parênteses extras em volta ((utf8.offset(s, 3))), fica só o primeiro valor, e as duas versões concordam.

Missão: a Ana queria o texto a partir do 3º caractere (á, coração), mas no 5.5 está saindo só á. Conserte com os parênteses extras, sem trocar o utf8.offset.

local s = "Olá, coração"
print(s:sub(utf8.offset(s, 3)))

local s = "Olá, coração"
print(s:sub((utf8.offset(s, 3))))

7. A coleta de lixo

Três mudanças, todas explicadas com exemplos em Coleta de Lixo (collectgarbage):

  • Os ajustes agora ficam na opção "param": collectgarbage("param", "pause", 300). No 5.4 eles iam junto com o modo (collectgarbage("incremental", 200, 100)); no 5.5 esses números extras são ignorados. É uma incompatibilidade (manual §8.2). No 5.4, "param" dá invalid option 'param'.
  • As coletas maiores do modo generacional são feitas aos poucos ("incrementalmente"), sem uma pausa grande de uma vez.
  • Listas grandes gastam cerca de 60% menos memória (a parte de lista das tabelas). No lab, uma tabela com os inteiros de 1 a 100 000 deu Lua 5.5: 1172.0 KB contra Lua 5.4: 2069.5 KB no programa inteiro. Os números do seu computador vão ser outros.

8. O programa lua: readline e o aviso do local

O aviso do local no modo interativo

$ lua5.4
Lua 5.4.8  Copyright (C) 1994-2025 Lua.org, PUC-Rio
> local y = 5
> print(y)
nil
> os.exit()
$ lua
Lua 5.5.0  Copyright (C) 1994-2025 Lua.org, PUC-Rio
> local y = 5
warning: locals do not survive across lines in interactive mode
> os.exit()

No modo interativo, cada linha é um pedacinho de programa separado, então um local some no fim da linha. O 5.4 ficava quieto e o print(y) mostrava nil, para espanto de quem estava aprendendo. O 5.5 avisa: "variáveis locais não sobrevivem de uma linha para outra no modo interativo". Aula: O Modo Interativo.

O atalho = expressão acabou

$ lua5.4
Lua 5.4.8  Copyright (C) 1994-2025 Lua.org, PUC-Rio
> = 1 + 1
2
> os.exit()
$ lua
Lua 5.5.0  Copyright (C) 1994-2025 Lua.org, PUC-Rio
> = 1 + 1
stdin:1: unexpected symbol near '='
> os.exit()

No 5.1 e no 5.4, começar uma linha do > com = era um atalho antigo para "mostre o valor" (no lab, o lua5.1 também respondeu 2). O 5.5 não aceita mais: digite só a expressão (1 + 1), que ele mostra o resultado do mesmo jeito. Tutoriais antigos usam muito esse =.

A readline carregada sozinha

A readline é a biblioteca que dá ao > as setas (voltar no texto) e o histórico (seta para cima). No 5.5, o lua tenta carregar a readline na hora, se ela existir, em vez de depender dela. Efeito prático no Ubuntu: quem instalou só o pacote lua5.5 fica sem setas, porque o arquivo que ele procura (libreadline.so) vem num pacote de desenvolvimento. Num Ubuntu 26.04 só com o lua5.5, a seta para cima aparece como ^[[A, e o lua -W (que liga os avisos) conta o motivo: Lua warning: library 'libreadline.so' not found. O conserto (sudo apt install liblua5.5-dev ou libreadline-dev) está em Instalar o Lua.

9. As outras incompatibilidades (manual §8)

Erro sem objeto vira texto

print(pcall(error))
print(pcall(error, nil))

$ lua nilerr.lua
false	<no error object>
false	<no error object>
$ lua5.4 nilerr.lua
false	nil
false	nil

O manual: "num erro, um nil como objeto de erro é trocado por uma mensagem de texto". Antes, quem fazia local ok, erro = pcall(…) podia receber erro == nil mesmo com falha; agora recebe o texto <no error object> ("sem objeto de erro"). Um error() que ninguém captura continua mostrando lua: (error object is a nil value) nas duas versões. Aulas: error e pcall.

Cadeia de __call com no máximo 15

local function encadear(n)
  local obj = function () return "chegou" end
  for i = 1, n do
    obj = setmetatable({}, { __call = obj })
  end
  return obj
end
print(pcall(encadear(14)))
print(pcall(encadear(20)))

$ lua chamada.lua
true	chegou
false	'__call' chain too long
$ lua5.4 chamada.lua
true	chegou
true	chegou

Uma tabela com __call (aula __tostring, __call e __len) pode ser chamada como função; e o __call pode ser outra tabela com __call, e assim por diante. No 5.5, essa corrente tem no máximo 15 elos. Ninguém escreve 20 elos de propósito; é só uma trava contra exageros.

Uma corrotina pode fechar a si mesma

local co = coroutine.create(function ()
  print("dentro da corrotina")
  print(coroutine.close(coroutine.running()))
  print("esta linha não aparece")
end)
print(coroutine.resume(co))
print(coroutine.status(co))

$ lua coclose.lua
dentro da corrotina
true
dead
$ lua5.4 coclose.lua
dentro da corrotina
false	coclose.lua:3: cannot close a running coroutine
dead

No 5.5, coroutine.close chamado de dentro da própria corrotina a encerra na hora: nada depois dele roda (nem o print em volta), e o resume devolve true. No 5.4.8, a mesma linha dava o erro "não é possível fechar uma corrotina que está rodando". Aula: Corrotinas.

O rastro dos erros

Não está na lista oficial, mas você vai notar: o stack traceback do 5.5 escreve [C]: in global 'error' onde o 5.4 escrevia [C]: in function 'error' (comparação completa em versoes.html, seção 11). A mensagem principal é a mesma.

Quando dá errado

Código do 5.5 no 5.4

Todos os recursos novos de sintaxe fazem o 5.4 recusar o arquivo inteiro: lua5.4: glob2.lua:1: syntax error near 'print' (o global), lua5.4: vararg.lua:1: ')' expected near 't' (o ...t). Os de biblioteca dão erro só quando a linha roda: attempt to call a nil value (field 'create'). Se o código precisa rodar nas duas versões, não use os de sintaxe.

Código do 5.4 no 5.5: o for 
$ lua forvar.lua
lua: forvar.lua:2: attempt to assign to const variable 'i'

"Tentativa de atribuir a uma variável constante i". Não tem stack traceback porque o 5.5 pega na compilação: o programa não roda nem a linha 1. Como consertar: local i = i * 2 dentro do laço.

Código do 5.4 no 5.5: a mudança que não dá erro

O s:sub(utf8.offset(s, 3)) da seção 6 e o pcall que devolvia nil da seção 9 não dão mensagem nenhuma: o programa roda e o resultado muda. São as mais perigosas. Se um programa antigo começou a dar resultados estranhos no 5.5, procure por utf8.offset e por if erro == nil.

Missão final: a lista de compras no 5.5

Missão: use duas novidades de uma vez. A função total deve receber os preços como vararg com nome (...precos) e somar com precos[i] e precos.n. E o arquivo já começa com global print, string: tudo o mais tem de ser local. Deve sair Total: R$ 23.40 (3 itens).

global print, string

local function total(...)
  -- some aqui os preços
  return 0, 0
end

local soma, quantos = total(4.5, 6.9, 12)
print(string.format("Total: R$ %.2f (%d itens)", soma, quantos))

global print, string

local function total(...precos)
  local soma = 0
  for i = 1, precos.n do
    soma = soma + precos[i]
  end
  return soma, precos.n
end

local soma, quantos = total(4.5, 6.9, 12)
print(string.format("Total: R$ %.2f (%d itens)", soma, quantos))

Se aparecer variable 'algo' not declared, é a declaração global fazendo o trabalho dela: ou o nome devia ser local, ou ele precisa entrar na lista do global.

Resumo

  • Linguagem: global (declara as globais; o resto vira erro antes de rodar), varargs com nome (...t, com t.n), variável do for somente leitura.
  • Bibliotecas: floats com todos os dígitos (0.30000000000000004), table.create, utf8.offset com dois valores, collectgarbage("param"), coroutine.close da própria corrotina.
  • Por dentro: listas grandes ~60% menores, coletas maiores aos poucos, readline carregada sozinha, aviso do local no >.
  • Incompatibilidades com o 5.4: o for, os ajustes do coletor, o erro sem objeto (<no error object>), a cadeia de __call; e, sem erro, o utf8.offset.
  • O global ainda funciona como nome de variável no 5.5.0 padrão (LUA_COMPAT_GLOBAL), mas não conte com isso no futuro.
