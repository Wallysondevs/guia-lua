Lua assert

O assert ("afirmar", "garantir") é a forma mais curta de dizer ao Lua: "isto tem de ser verdade; se não for, pare aqui". Ele recebe um valor; se o valor for false ou nil, lança um erro; se for qualquer outra coisa, deixa o programa seguir e ainda devolve o valor. Esse jeitinho de devolver faz dele o parceiro ideal das funções que avisam problemas com nil, "mensagem", como o io.open: com uma palavra, a mensagem real do sistema vira um erro claro.

Você vai aprender
  • Como usar assert(condição) e assert(condição, "mensagem"), e as mensagens reais que aparecem (assertion failed!).
  • O uso mais famoso: local f = assert(io.open(nome)), que mostra o motivo verdadeiro (No such file or directory, Permission denied).
  • Por que o assert devolve os seus argumentos, e como aproveitar isso (assert(tonumber(texto))).
  • Testes simples com assert: conferir se uma função dá o resultado esperado.
  • As pegadinhas: a mensagem calculada mesmo quando não precisa, o 0 que conta como verdadeiro, e quando é melhor usar error.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook) com lua arquivo.lua. Antes, convém conhecer error.

A ideia: o fiscal da porta

Na porta do show, o fiscal confere uma coisa só: "tem ingresso?". Se tem, a pessoa entra, com o ingresso na mão, e ele nem fala nada. Se não tem, ele barra na hora e diz o motivo: "sem ingresso não entra".

O assert é esse fiscal. Ele olha o valor que você entregou: se é "verdadeiro" (qualquer coisa que não seja false nem nil), deixa passar e devolve o próprio valor. Se não, barra o programa com uma mensagem. Ele não faz contas, não decide nada complicado: só confere e barra.

1. O primeiro assert

local preco = 10
assert(preco > 0)
print("preço ok")
local estoque = -3
assert(estoque >= 0)
print("estoque ok")

$ lua a2.lua
preço ok
lua: a2.lua:5: assertion failed!
stack traceback:
	[C]: in global 'assert'
	a2.lua:5: in main chunk
	[C]: in ?
$ echo $?
1
assert(preco > 0)
10 > 0 é true: o fiscal deixa passar, e o programa segue para o print("preço ok").
assert(estoque >= 0)
-3 >= 0 é false: o fiscal barra. O programa para ali; o estoque ok nunca aparece.
lua: a2.lua:5: assertion failed!
"A afirmação falhou!". É a mensagem padrão, quando você não escreve nenhuma. A posição (a2.lua:5:) é a linha do assert.
[C]: in global 'assert'
O rastro começa no próprio assert (escrito em C), como o error (veja Lendo uma Mensagem de Erro).

Com a sua mensagem

O assertion failed! diz onde, mas não o quê. O segundo argumento é a mensagem que aparece no lugar:

local estoque = -3
assert(estoque >= 0, "o estoque não pode ser negativo")

$ lua a3.lua
lua: a3.lua:2: o estoque não pode ser negativo
stack traceback:
	[C]: in global 'assert'
	a3.lua:2: in main chunk
	[C]: in ?

Na prática, assert(condição, "mensagem") é um atalho para:

if not (estoque >= 0) then
  error("o estoque não pode ser negativo")
end

Três linhas viram uma. (A diferença: com error você escolhe o nível da mensagem; com assert, a posição é sempre a linha do próprio assert.)

2. O uso mais famoso: assert(io.open(…))

A função io.open abre um arquivo (veja Abrindo Arquivos). Quando não consegue, ela não lança erro: devolve nil, uma mensagem e um código do sistema:

local nome = "pasta_que_nao_existe/notas.txt"
local f, msg, codigo = io.open(nome)
print(f, msg, codigo)
local g = assert(io.open(nome, "r"))

$ lua a13.lua
nil	pasta_que_nao_existe/notas.txt: No such file or directory	2
lua: a13.lua:4: pasta_que_nao_existe/notas.txt: No such file or directory
stack traceback:
	[C]: in global 'assert'
	a13.lua:4: in main chunk
	[C]: in ?

Repare na mágica da linha 4: o io.open devolveu três valores (nil, a mensagem e o 2), e todos foram para o assert. Para ele, o primeiro é o valor a conferir (nil: barra!) e o segundo é a mensagem. Resultado: o erro mostra o motivo real, escrito pelo sistema: No such file or directory, "arquivo ou pasta inexistente".

Sem o assert, o erro aparece longe e confuso

local f = io.open("compras.txt")
print(f:read("a"))
f:close()

$ lua a1b.lua
lua: a1b.lua:2: attempt to index a nil value (local 'f')
stack traceback:
	a1b.lua:2: in main chunk
	[C]: in ?

A mensagem diz que o f é nil na linha 2, mas não diz por quê. O motivo (o arquivo não existe) se perdeu na linha 1. Com o assert:

local f = assert(io.open("compras.txt"))
print(f:read("a"))
f:close()

$ lua a1.lua
lua: a1.lua:1: compras.txt: No such file or directory
stack traceback:
	[C]: in global 'assert'
	a1.lua:1: in main chunk
	[C]: in ?

Agora o erro aparece na linha certa (a 1, onde está o problema) e com o motivo certo. E quando o arquivo existe, o assert devolve o próprio arquivo, que vai para o f, como se ele nem estivesse ali.

O motivo muda conforme o problema. Tentando criar um arquivo numa pasta em que a Ana não pode escrever (no lab, uma pasta trancada com chmod 555):

$ lua a14.lua
lua: a14.lua:1: trancada/notas.txt: Permission denied
stack traceback:
	[C]: in global 'assert'
	a14.lua:1: in main chunk
	[C]: in ?

Permission denied: "permissão negada". (O a14.lua é uma linha só: local f = assert(io.open("trancada/notas.txt", "w")).) As mensagens vêm do sistema, em inglês, e por isso são tão úteis: dizem exatamente o que houve.

3. O assert devolve tudo o que recebeu

Quando o primeiro valor passa na conferência, o assert devolve todos os seus argumentos, do jeito que vieram:

print(assert(10))
print(assert("Ana", "não usada"))
print(assert(1, 2, 3))
local n = assert(tonumber("42"))
print(n + 1)
print(assert(0), assert(""), assert({}) ~= nil)

$ lua a4.lua
10
Ana	não usada
1	2	3
43
0		true
  • assert(10) devolveu 10. Por isso local n = assert(tonumber("42")) funciona: o n recebe o 42.
  • assert("Ana", "não usada") devolveu os dois: quando passa, a mensagem também volta (e normalmente é ignorada).
  • A última linha: 0, o texto vazio "" (por isso o "buraco" entre os dois TABs) e uma tabela passaram. No Lua, só false e nil são "falsos"; o zero e o texto vazio são verdadeiros (veja Booleanos). Quem vem de outras linguagens se surpreende.

assert(tonumber(…))

O tonumber devolve nil quando o texto não é um número. Com o assert, isso vira um erro:

local texto = "abc"
local n = assert(tonumber(texto), "não é um número: " .. texto)

$ lua a6.lua
lua: a6.lua:2: não é um número: abc
stack traceback:
	[C]: in global 'assert'
	a6.lua:2: in main chunk
	[C]: in ?

Aqui a mensagem é importante: diferente do io.open, o tonumber devolve só o nil, sem explicação. Sem o segundo argumento, sairia apenas lua: a5.lua:2: assertion failed! (conferido no lab, com o mesmo código sem a mensagem).

Experimente: rode e confira cada linha. Depois acrescente print(assert(false, "parou")) no fim: a partir de qual linha o programa para? E troque o 0 por nil na última linha original: o que muda?

print(assert("Ana", "não usada"))

print(n + 1)
print(assert(0), assert(""), assert({}) ~= nil)

4. Conferindo argumentos e testando funções

Dentro de uma função, o assert confere se os argumentos fazem sentido, numa linha cada:

local function cadastrar(nome, idade)
  assert(type(nome) == "string", "o nome precisa ser texto")
  assert(type(idade) == "number", "a idade precisa ser número")
  print("Cadastrado: " .. nome .. ", " .. idade)
end
cadastrar("Ana", 30)
cadastrar("Bia", "trinta")

$ lua a12.lua
Cadastrado: Ana, 30
lua: a12.lua:3: a idade precisa ser número
stack traceback:
	[C]: in global 'assert'
	a12.lua:3: in local 'cadastrar'
	a12.lua:7: in main chunk
	[C]: in ?

A mensagem aponta a linha 3 (o assert); quem passou o "trinta" é a linha 7, que aparece no rastro. Se você quer que a mensagem já aponte a linha 7, use error(msg, 2) no lugar do assert (veja error).

Testes de verdade com assert

O assert também é a ferramenta mais simples de teste: você escreve o que uma função deveria dar, e o assert confere. Se tudo passar, nada acontece; se algo falhar, o programa para na linha do teste que falhou:

local function dobro(x) return x * 2 end
assert(dobro(2) == 4)
assert(dobro(0) == 0)
assert(dobro(-3) == -6)
assert(dobro(2.5) == 5.0)
print("Todos os testes passaram!")
assert(dobro(3) == 7, "dobro(3) deveria dar 7")

$ lua a8.lua
Todos os testes passaram!
lua: a8.lua:7: dobro(3) deveria dar 7
stack traceback:
	[C]: in global 'assert'
	a8.lua:7: in main chunk
	[C]: in ?

Os quatro primeiros testes passaram em silêncio. O último é um teste errado de propósito (o dobro de 3 é 6, não 7), para você ver como fica uma falha. Testes assim, guardados num arquivo e rodados a cada mudança, avisam na hora quando você estraga algo que funcionava. A aula Testes vai além.

Formas diferentes de fazer a mesma coisa

Abrir um arquivo e reagir se não der, de três jeitos:

-- 1. assert: parar com o motivo real
local f = assert(io.open("compras.txt"))

-- 2. if: tratar sem parar
local g, msg = io.open("compras.txt")
if not g then
  print("Não consegui abrir: " .. msg)
end

-- 3. error: parar com a sua mensagem e o nível que você escolher
local h, motivo = io.open("compras.txt")
if not h then
  error("a lista de compras sumiu (" .. motivo .. ")", 2)
end
SituaçãoQual usar
Sem aquele arquivo (ou valor), o programa não tem como continuarassert(io.open(…)): uma palavra, motivo real
O problema é esperado e o programa pode seguir (perguntar outro nome, usar um padrão)local f, msg = io.open(…) e um if
Validar argumentos e culpar quem chamouerror(msg, 2)
Conferir resultados de funções (testes)assert(f(x) == esperado, "mensagem")
Parar sem fechar o programaassert dentro de um pcall: pcall(assert, false, "x") devolve false, "x"

Quando dá errado

A mensagem do assert deu erro antes dele 
local cliente
assert(cliente, "cliente não encontrado: " .. cliente)

$ lua a7.lua
lua: a7.lua:2: attempt to concatenate a nil value (local 'cliente')
stack traceback:
	a7.lua:2: in main chunk
	[C]: in ?

A mensagem que você escreveu nunca apareceu. O Lua calcula todos os argumentos de uma função antes de chamá-la; para montar o segundo argumento, ele tentou juntar o texto com o cliente, que é nil, e quebrou ali mesmo. Repare: não há [C]: in global 'assert' no rastro, porque o assert nem foi chamado. O pior: justamente quando o valor é nil (o caso que o assert devia pegar), a mensagem é que dá erro. Como consertar: não junte o próprio valor conferido na mensagem, ou converta com tostring(cliente), que transforma nil no texto "nil".

O assert deixou passar um 0 (ou um texto vazio)

assert(quantidade) com quantidade = 0 passa: o zero é verdadeiro no Lua (seção 3). Se o que você quer conferir é "maior que zero", escreva a comparação: assert(quantidade > 0, "quantidade precisa ser positiva"). O mesmo vale para o texto vazio: assert(nome ~= "", "nome vazio").

Só apareceu assertion failed!

Sem o segundo argumento, a mensagem é genérica. Você sabe a linha, mas quem lê o erro (talvez você mesmo, daqui a um mês) não sabe o que era esperado. Escreva sempre uma mensagem, a não ser no assert(io.open(…)), em que o próprio io.open fornece a mensagem.

Chamou assert() vazio 
$ lua a11.lua
lua: a11.lua:1: bad argument #1 to 'assert' (value expected)
stack traceback:
	[C]: in global 'assert'
	a11.lua:1: in main chunk
	[C]: in ?

"Argumento ruim nº 1 para o assert (era esperado um valor)". O a11.lua é print(assert()). Acontece quando uma função que você passou para o assert não devolve nada (nem nil): o assert fica sem argumento nenhum. Confira se a função tem um return.

Missão final: os testes da média

Missão: a professora escreveu três testes com assert para a função media. Rode: um dos testes falha, e a mensagem diz qual. A função tem um defeito (ela sempre divide por 2). Conserte a função (não os testes!) para os três passarem.

local function media(lista)
  local soma = 0
  for _, n in ipairs(lista) do
    soma = soma + n
  end
  return soma / 2
end

assert(media({8, 6}) == 7, "a média de 8 e 6 deveria ser 7")
assert(media({9, 9, 9}) == 9, "a média de três 9 deveria ser 9")
assert(media({10}) == 10, "a média de um 10 deveria ser 10")
print("Todos os testes passaram!")

Resumo

  • assert(v, msg) para o programa se v for false ou nil, com msg (ou assertion failed!); senão, devolve todos os argumentos.
  • local f = assert(io.open(nome)) é o jeito clássico de abrir um arquivo: se falhar, o erro mostra o motivo real do sistema, na linha certa.
  • Com funções que devolvem só nil (como tonumber), escreva a mensagem.
  • A mensagem é calculada antes da conferência: não junte nela um valor que pode ser nil (use tostring).
  • Só false e nil barram; 0 e "" passam.
  • O assert é a ferramenta mais simples de teste. Para escolher o nível da mensagem, use error; para não parar o programa, pcall.
