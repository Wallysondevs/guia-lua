Lua Tabelas como Dicionários

Numa lista, você acha um item pela posição: o primeiro, o segundo, o quinto. Mas no balcão da padaria ninguém pergunta "quanto custa o produto número 2?"; pergunta "quanto custa o leite?". A mesma tabela do Lua que vira lista também serve para isso: em vez de 1, 2, 3, você usa um nome para guardar cada valor. Uma tabela usada assim se chama dicionário (outras linguagens dizem também "mapa" ou "tabela associativa"). O nome é a chave; o que fica guardado nele é o valor.

Você vai aprender
  • A criar um dicionário: {pao = 0.50, leite = 4.75} e {["café"] = 18.90}.
  • As três escritas para ler: t.nome, t["nome"] e t[nome] (com uma variável), e quando cada uma serve.
  • Que pedir uma chave que não existe dá nil, sem erro, e como usar um valor padrão com or.
  • A acrescentar, mudar e apagar um par.
  • Que t[1] e t["1"] são chaves diferentes.
  • Por que o # de um dicionário dá 0.
  • Os erros reais de acento, palavra reservada, chave nil e maiúscula.

A ideia: a tabela de preços da padaria

Pendurada na parede da padaria há uma tabela: à esquerda o nome do produto, à direita o preço. Ninguém lê a tabela inteira: o cliente procura o nome e olha o preço ao lado.

Chave (o nome)Valor (o que está guardado)
pao0.50
leite4.75
cafe18.90

Cada linha é um par chave-valor. No Lua, essa tabela inteira cabe numa variável. E não é um tipo novo: é a mesma tabela de sempre. A lista é uma tabela cujas chaves são 1, 2, 3…; o dicionário é uma tabela cujas chaves são nomes.

1. Criando um dicionário

local precos = {pao = 0.50, leite = 4.75, cafe = 18.90}
print(precos)
print(precos.leite)
print(precos["leite"])
print(type(precos))
print(#precos)
{ … }
As chaves { } criam a tabela, como numa lista.
pao = 0.50
Um par: a chave pao, o sinal =, e o valor 0.50. Leia como "pao vale 0.50". A chave aqui é o texto "pao", escrito sem aspas.
,
A vírgula separa um par do outro.
precos.leite
Lê o valor guardado na chave "leite": o nome da tabela, um ponto, o nome da chave.
precos["leite"]
O mesmo, com colchetes e aspas. As duas escritas são a mesma coisa (seção 2).
#precos
O # conta só os itens de lista (posições 1, 2, 3…). Este dicionário não tem nenhum: dá 0.
$ lua precos.lua
table: 0x5577a57af780
4.75
4.75
table
0

O print(precos) não mostra o conteúdo: mostra table: e um endereço de memória, que muda a cada execução. Para ver todos os pares, é preciso percorrer a tabela, com o pairs (próxima aula, Percorrendo Chaves). E o # dar 0 não quer dizer que a tabela esteja vazia: quer dizer que ela não tem parte de lista. Para contar os pares, também é com o pairs.

Chaves com acento ou espaço: ["…"] =

A escrita pao = 0.50 só serve quando a chave poderia ser o nome de uma variável: letras sem acento, números e _, sem começar com número (aula Nomes de Variáveis). Para qualquer outro texto, escreva a chave entre colchetes e aspas:

local precos = {
  pao = 0.50,
  ["café"] = 18.90,
  ["pão de queijo"] = 3.00,
}
print(precos.pao)
print(precos["café"])
print(precos["pão de queijo"])
print(string.format("Café: R$ %.2f", precos["café"]))

$ lua chaves_texto.lua
0.5
18.9
3.0
Café: R$ 18.90
["café"] = 18.90
A chave é o texto "café", com acento. Entre colchetes vai qualquer valor como chave; aqui, um texto.
["pão de queijo"] = 3.00
Chave com espaços: também só com colchetes.
a vírgula depois do último par
É permitida, e facilita acrescentar outro par depois. Com muitos pares, o costume é um por linha, com 2 espaços na frente.
0.5, 18.9, 3.0
O print não mostra os zeros do fim que não mudam o número. Para mostrar dinheiro com duas casas, use string.format("%.2f", …) (aula string.format).

local precos = {pao = 0.50, leite = 4.75, ["café"] = 18.90}

2. Três escritas: t.nome, t["nome"] e t[nome]

Esta é a parte que mais confunde quem começa. Leia com calma:

local ficha = {nome = "Ana", cidade = "Teresina"}
local nome = "cidade"
print(ficha.nome)
print(ficha["nome"])
print(ficha[nome])
local campo = "nome"
print(ficha[campo])

$ lua tres_jeitos.lua
Ana
Ana
Teresina
Ana
ficha.nome
A chave é o texto "nome". O ponto é só um atalho: ficha.nome é exatamente o mesmo que ficha["nome"]. Resultado: Ana.
ficha["nome"]
A chave é o texto "nome", escrito com aspas. Resultado: Ana.
ficha[nome]
Sem aspas, dentro dos colchetes: nome é uma variável, e a chave é o que está guardado nela. A variável nome vale "cidade", então é ficha["cidade"]: Teresina.
ficha[campo]
A variável campo vale "nome": é ficha["nome"], Ana.
EscritaQual é a chaveQuando usar
t.nomeO texto "nome"Quase sempre: a chave é fixa e é um nome simples
t["nome"]O texto "nome"Quando a chave tem acento, espaço, hífen, ou é uma palavra reservada (t["café"], t["end"])
t[nome]O que estiver na variável nomeQuando a chave só é conhecida na hora: veio do teclado, de um arquivo, de um laço

Regra para não errar: depois do ponto, a chave é sempre um texto fixo; para usar uma variável como chave, só com colchetes. ficha.campo procuraria a chave "campo", e não o que está na variável campo.

3. A chave que não existe: nil

A padaria não vende bolo. O que acontece se o programa pedir o preço do bolo?

local precos = {pao = 0.50, leite = 4.75}
print(precos.bolo)
print(precos.bolo or 0)
if precos.bolo == nil then
  print("Não temos bolo.")
end
if precos.leite ~= nil then
  print("Temos leite.")
end

$ lua nao_existe.lua
nil
0
Não temos bolo.
Temos leite.
precos.bolo
Chave que não existe: o Lua não dá erro, devolve nil ("nada", aula O Valor nil). Para o Lua, "não existe" e "vale nil" são a mesma coisa.
precos.bolo or 0
O truque do or (aula and, or e not): se o da esquerda é nil, vale o da direita. É o jeito de ter um valor padrão.
precos.bolo == nil
Pergunta se a chave está faltando.
precos.leite ~= nil
Pergunta se a chave existe (~= é "diferente de").
O nil não para o programa, mas o erro aparece depois

Como pedir uma chave que não existe não dá erro, o nil segue caminho e o programa só quebra lá na frente, quando alguém tenta fazer conta ou juntar texto com ele (veja Quando dá errado). Se o valor pode faltar, trate na hora: or 0, ou um if … == nil.

Cuidado com o or quando o valor pode ser false

Se a tabela guarda true/false (config.som = false), config.som or true dá true mesmo com o som desligado, porque o or trata false igual a nil. Nesse caso, pergunte com config.som == nil.

4. Acrescentar, mudar e apagar

Um dicionário muda o tempo todo: chegou produto novo, o preço subiu, um item saiu do cardápio. As três coisas são feitas com o mesmo =:

local estoque = {pao = 40, leite = 12}
estoque.bolo = 5
estoque.leite = estoque.leite - 2
estoque["pao"] = nil
print(estoque.pao, estoque.leite, estoque.bolo)

$ lua mudar.lua
nil	10	5
estoque.bolo = 5
A chave bolo não existia: o par é criado.
estoque.leite = estoque.leite - 2
A chave já existia: o valor é trocado. Lê o valor antigo (12), tira 2, guarda 10.
estoque["pao"] = nil
Guardar nil apaga o par. Num dicionário isso é normal e seguro; os buracos só são problema em listas, onde a ordem 1, 2, 3 importa.

Cada chave aparece uma vez só na tabela. Se você escrever a mesma chave duas vezes, a segunda troca o valor da primeira.

Missão: chegaram 5 bolos e foram vendidos 2 leites. Antes dos print, acrescente a chave bolo com 5 e tire 2 do leite, para o programa mostrar leite: 10 e bolo: 5.

local estoque = {pao = 40, leite = 12}

print("pão: " .. estoque.pao)
print("leite: " .. estoque.leite)
print("bolo: " .. tostring(estoque.bolo))

local estoque = {pao = 40, leite = 12}
estoque.bolo = 5
estoque.leite = estoque.leite - 2
print("pão: " .. estoque.pao)
print("leite: " .. estoque.leite)
print("bolo: " .. tostring(estoque.bolo))

5. Chave número × chave texto: t[1] não é t["1"]

Para a tabela, o número 1 e o texto "1" são chaves diferentes, como duas gavetas com etiquetas diferentes:

local t = {}
t[1] = "número um"
t["1"] = "texto um"
print(t[1])
print(t["1"])
print(t[1.0])
print(t[1] == t["1"])
local digitado = "1"
print(t[digitado])
print(t[tonumber(digitado)])

$ lua numero_texto.lua
número um
texto um
número um
false
texto um
número um
t[1] e t["1"]
Duas chaves, dois valores: "número um" e "texto um".
t[1.0]
O número 1.0 é igual ao inteiro 1, então a chave é a mesma: "número um". Com números, vale o valor, não a escrita.
t[digitado]
O que vem do teclado (io.read) ou de um arquivo é sempre texto. Com a chave "1", achou o "texto um".
t[tonumber(digitado)]
Para usar como posição de lista, converta primeiro (aula tonumber e tostring).
O erro clássico do menu

A Ana faz um menu numa lista (opcoes = {"Ver", "Somar", "Sair"}) e lê a escolha com io.read(). O opcoes[escolha] dá nil, mesmo ela digitando 2: a escolha é o texto "2", e a lista tem a chave número 2. O conserto é opcoes[tonumber(escolha)], ou ler já como número, com io.read("n").

6. Lista e dicionário na mesma tabela

Como é tudo tabela, dá para misturar: uma parte de lista (1, 2, 3…) e uma parte de dicionário (nomes). E a chave pode ser quase qualquer valor, não só texto e número inteiro:

local turma = {"Ana", "Bia", "Caio", nome = "3º A", sala = 12}
print(#turma)
print(turma[1], turma[3])
print(turma.nome, turma.sala)
local estranho = {[true] = "sim", [false] = "não", [3.5] = "três e meio"}
print(estranho[true], estranho[false], estranho[3.5])

$ lua mistura.lua
3
Ana	Caio
3º A	12
sim	não	três e meio
{"Ana", "Bia", "Caio", nome = "3º A", sala = 12}
Os valores sem chave vão para as posições 1, 2, 3; os outros têm nome.
#turma
Conta só a parte de lista: 3. Os pares nome e sala não entram na conta.
[true] = "sim", [3.5] = …
true, false, números com vírgula, até outra tabela: tudo pode ser chave. Só dois valores não podem: nil e o "não é um número" (0/0), como mostra Quando dá errado.

Quando dá errado

Chave com acento depois do ponto 
local precos = {["café"] = 18.90}
print(precos.café)

$ lua erro_acento.lua
lua: erro_acento.lua:2: ')' expected near '<\195>'
lua: erro_acento.lua:2:
Linha 2. Não há stack traceback: é um erro de sintaxe, o programa nem começou a rodar.
')' expected
"Era esperado um )". O Lua leu precos.caf e, no "é", achou um símbolo que não pode estar num nome; para ele, o print( … ) deveria fechar ali.
near '<\195>'
"Perto do byte 195": é o primeiro pedaço do "é" (cada letra acentuada ocupa 2 bytes, aula utf8). O Lua não aceita acento em nomes, nem depois do ponto.

Como consertar: precos["café"]. Ou use chaves sem acento no programa todo (cafe) e deixe o acento só no texto que o usuário vê.

Chave sem aspas nos colchetes (sem erro nenhum) 
local precos = {pao = 0.50, leite = 4.75}
print(precos[leite])

$ lua erro_semaspas.lua
nil

Saiu nil, e o leite está lá. Sem aspas, leite é uma variável, que não existe e por isso vale nil; a pergunta virou "qual o valor da chave nil?", e a resposta é nil. Nenhuma mensagem avisa. Como consertar: precos["leite"] ou precos.leite.

Conta com uma chave que não existe 
local estoque = {pao = 40, leite = 12}
local total = estoque.pao + estoque.bolo
print(total)

$ lua erro_conta.lua
lua: erro_conta.lua:2: attempt to perform arithmetic on a nil value (field 'bolo')
stack traceback:
	erro_conta.lua:2: in main chunk
	[C]: in ?

"Tentativa de fazer conta com um valor nil (campo 'bolo')". O Lua diz até o nome da chave que faltou: field 'bolo' ("campo" é outro nome para a chave de uma tabela). Como consertar: confira o nome da chave, ou use um padrão: (estoque.bolo or 0).

Maiúscula diferente 
local precos = {leite = 4.75}
print(precos.Leite)
print("Leite: R$ " .. precos.Leite)

$ lua erro_maiuscula.lua
nil

stack traceback:

Para a tabela, Leite e leite são chaves diferentes. A linha 2 só mostrou nil; a linha 3 tentou juntar (concatenate) o texto com esse nil e parou. Como consertar: escreva a chave exatamente como foi guardada. Se ela vem do teclado, padronize antes: precos[item:lower()] (aula Funções de Texto).

Guardar com chave nil 
local precos = {}
local item
precos[item] = 2.50

$ lua erro_nil_chave.lua
lua: erro_nil_chave.lua:3: table index is nil
stack traceback:
	erro_nil_chave.lua:3: in main chunk

"O índice da tabela é nil": a variável item não recebeu valor. Ler com chave nil só devolve nil (cenário acima), mas guardar com chave nil é erro. O mesmo vale para 0/0: lua: (command line):1: table index is NaN. Como consertar: confira de onde vem a chave (um io.read() que chegou ao fim, um nome trocado).

Escrita de outras linguagens: nome: "Ana" 
local ficha = {nome: "Ana", idade: 34}

$ lua erro_doispontos.lua
lua: erro_doispontos.lua:1: <name> expected near '"Ana"'

No JavaScript e no Python a chave se separa do valor com dois-pontos; no Lua é com =. (O dois-pontos no Lua serve para os métodos, aula Métodos e o Dois-Pontos, por isso ele esperava um nome, <name>, depois dele.) Como consertar: {nome = "Ana", idade = 34}.

Chave que é palavra reservada 
local agenda = {inicio = "8h", end = "18h"}

$ lua erro_end.lua
lua: erro_end.lua:1: unexpected symbol near 'end'

end é uma palavra do próprio Lua (fecha blocos) e não pode ser usada como nome, nem como chave na escrita end = …. Como consertar: escolha outro nome (fim = "18h"), ou use colchetes: {["end"] = "18h"} e agenda["end"], que funcionam. A lista das palavras reservadas está em Palavras Reservadas.

Missão final: o balcão da padaria

Missão: o cliente digita o nome de um produto (a caixa já vai responder leite por ele). Use precos[item] para achar o preço. Se ele existir, mostre leite custa R$ 4.75 (com string.format("%s custa R$ %.2f", …)); se for nil, mostre Não temos ….

local precos = {pao = 0.50, leite = 4.75, cafe = 18.90}
io.write("Qual produto? ")
local item = io.read()
print("?")

local precos = {pao = 0.50, leite = 4.75, cafe = 18.90}
io.write("Qual produto? ")
local item = io.read()
local preco = precos[item]
if preco then
  print(string.format("%s custa R$ %.2f", item, preco))
else
  print("Não temos " .. item .. ".")
end

Resumo

  • Um dicionário é uma tabela com chaves que são nomes: {pao = 0.50, ["café"] = 18.90}.
  • t.nome e t["nome"] são a mesma coisa (a chave é o texto); t[nome] usa o que está na variável nome.
  • Chave que não existe dá nil, sem erro; o erro aparece depois, na conta ou no ... Use or 0 ou if t.x == nil.
  • t.x = valor cria ou troca; t.x = nil apaga.
  • t[1] e t["1"] são chaves diferentes; o que vem do teclado é texto.
  • O # conta só a parte de lista; para ver e contar os pares, use o pairs.
