Lua Testes

Toda vez que a Ana muda uma função do módulo de contas, ela roda o programa e confere os números "no olho". Funciona com três contas; com trinta, ela vai esquecer alguma. Um teste automático é um pequeno programa que faz essa conferência por você: chama a função, compara com o resultado certo e avisa se algo mudou. Escreva uma vez, rode sempre que quiser, em um segundo.

Você vai aprender
  • O que é um teste e por que ele vale o trabalho.
  • Testar um módulo só com assert, e ler a mensagem quando um teste falha.
  • Escrever uma mini função de teste, com pcall, que continua depois de uma falha e conta quantos passaram (roda no editor do guia).
  • Testar que uma função dá erro quando deve, e comparar floats.
  • O código de saída: o jeito de um teste avisar "falhei" para outros programas.
  • O busted, a ferramenta de testes mais usada no Lua: como instalar para o 5.5, describe, it, assert.are.equal, e as saídas de sucesso e de falha.

Tudo rodou no Lua 5.5 da máquina da Ana, numa pasta testes. A parte do busted precisa do LuaRocks (aula LuaRocks) e roda só no terminal; o resto roda também no editor do guia.

A ideia: a prova da receita

A padaria tem uma receita de pão de queijo. Toda vez que alguém muda a receita (troca a marca do polvilho, muda o forno), a dona faz uma fornada de prova e confere uma lista: "cresceu? está dourado? o miolo está macio? tem 20 unidades?". Se um item falhar, ela sabe na hora que a mudança estragou alguma coisa, antes de vender para o cliente.

Um teste é essa lista de conferência, escrita em Lua:

Na padariaNo código
A receitaA função ou o módulo (contas.lua)
"Tem 20 unidades?"Uma verificação: contas.desconto(80, 10) == 72
A fornada de provaRodar o arquivo de testes
"Tudo certo, pode vender"todos os testes passaram

O segredo é que você escreve os testes com calma, quando sabe exatamente o resultado certo, e depois eles trabalham sozinhos, toda vez que você mexer no código.

1. O teste mais simples: assert

O módulo das contas da Ana (veja Criando seu Módulo), agora com um cuidado a mais: o desconto recusa porcentagens impossíveis, com error:

local M = {}

function M.somar(a, b)
  return a + b
end

function M.desconto(preco, porcento)
  if porcento < 0 or porcento > 100 then
    error("porcentagem inválida: " .. porcento, 2)
  end
  return preco - preco * porcento / 100
end

return M

O arquivo de teste carrega o módulo e confere os resultados com assert ("afirmar"): assert(condição) não faz nada se a condição for verdadeira, e para o programa com um erro se for falsa.

local contas = require("contas")

assert(contas.somar(2, 3) == 5)
assert(contas.desconto(80, 10) == 72)
assert(contas.desconto(50, 0) == 50)
print("todos os testes passaram")

$ lua teste1.lua
todos os testes passaram

Se a última linha apareceu, é porque nenhum assert parou o programa. (Repare que 72.0 == 72 é verdadeiro no Lua: o desconto devolve o float 72.0 e a comparação com o inteiro 72 passa. Veja Números.)

Quando um teste falha

Para ver uma falha, a Ana escreveu de propósito um resultado errado (6 em vez de 5):

local contas = require("contas")

assert(contas.somar(2, 3) == 6)

$ lua teste3.lua
lua: teste3.lua:3: assertion failed!
stack traceback:
	[C]: in global 'assert'
	teste3.lua:3: in main chunk
	[C]: in ?

"Afirmação falhou!", na linha 3. Funciona, mas não conta o quê falhou. Por isso o assert aceita um segundo argumento, a mensagem:

local contas = require("contas")

assert(contas.somar(2, 3) == 5)
assert(contas.desconto(80, 10) == 70, "desconto de 10% sobre 80 deveria dar 70")

$ lua teste2.lua

2. Uma mini função de teste

O assert tem um problema: na primeira falha, o programa para, e você não fica sabendo se os testes de baixo passariam. Com o pcall, dá para rodar cada teste "protegido": se ele falhar, anotamos e seguimos para o próximo. São poucas linhas:

local contas = require("contas")

local passou, falhou = 0, 0

local function teste(nome, funcao)
  local ok, erro = pcall(funcao)
  if ok then
    passou = passou + 1
    print("ok      " .. nome)
  else
    falhou = falhou + 1
    print("FALHOU  " .. nome .. ": " .. tostring(erro))
  end
end

local function igual(obtido, esperado)
  if obtido ~= esperado then
    error("esperava " .. tostring(esperado) .. ", veio " .. tostring(obtido), 2)
  end
end

teste("somar dois números", function ()
  igual(contas.somar(2, 3), 5)
end)

teste("desconto de 10%", function ()
  igual(contas.desconto(80, 10), 72)
end)

teste("desconto zero não muda o preço", function ()
  igual(contas.desconto(50, 0), 50)
end)

teste("desconto de 25%", function ()
  igual(contas.desconto(20, 25), 16)
end)

teste("porcentagem acima de 100 dá erro", function ()
  local ok = pcall(contas.desconto, 50, 150)
  igual(ok, false)
end)

teste("um teste errado de propósito", function ()
  igual(contas.somar(0.1, 0.2), 0.3)
end)

print(string.format("%d ok, %d falharam", passou, falhou))
os.exit(falhou == 0 and 0 or 1)
local function teste(nome, funcao)
Recebe um nome (para mostrar) e uma função com as verificações. Cada teste é uma função anônima, function () … end, passada como argumento.
pcall(funcao)
Roda a função "protegida": se der erro lá dentro, o programa não para; o pcall devolve false e a mensagem.
passou, falhou
Dois contadores, para o resumo do final.
local function igual(obtido, esperado)
Uma verificação com mensagem pronta: "esperava X, veio Y". O 2 do error faz a mensagem apontar a linha do teste que chamou o igual, e não a linha do próprio igual (veja error).
local ok = pcall(contas.desconto, 50, 150)
Para testar que algo dá erro: chame com pcall e confira que o primeiro resultado é false.
os.exit(falhou == 0 and 0 or 1)
Termina com código 0 se tudo passou, 1 se algo falhou (veja os.exit e o truque do and/or).

ok      desconto de 10%
ok      desconto zero não muda o preço
FALHOU  desconto de 25%: teste_contas.lua:35: esperava 16, veio 15.0

Todos os seis testes rodaram, mesmo com duas falhas no meio. Olhe as duas:

  • desconto de 25%: "esperava 16, veio 15.0". Quem errou foi o teste: 25% de 20 é 5, e 20 − 5 = 15. A função está certa. (Foi um erro de conta real, de quem escreveu esta aula, e o teste o pegou. É assim mesmo.)
  • um teste errado de propósito: "esperava 0.3, veio 0.30000000000000004". É o errinho dos floats da aula math: 0.1 + 0.2 não é exatamente 0.3. Floats se comparam com uma tolerância (seção 3).

Missão: um dos três testes falha. Rode e leia a mensagem. Desta vez o módulo está certo e o teste está errado: faça a conta de cabeça (25% de 20) e conserte o valor esperado.

3. Floats: compare com tolerância

local function perto(a, b)
  return math.abs(a - b) < 1e-9
end
print(0.1 + 0.2 == 0.3, perto(0.1 + 0.2, 0.3))

$ lua perto.lua
false	true

Em vez de "é igual?", pergunte "a diferença é menor que um número minúsculo?" (1e-9 = 0,000000001). Na mini função de teste, isso vira uma verificação a mais, por exemplo local function quase_igual(obtido, esperado), que usa perto no lugar do ~=. Para dinheiro, outra saída é testar o texto já formatado: igual(string.format("%.2f", total), "30.00").

4. O código de saída: "falhei" para quem chamou

O os.exit(falhou == 0 and 0 or 1) do fim parece um detalhe, mas é o que permite automatizar. Outros programas não leem o seu "4 ok, 2 falharam"; eles olham o código de saída, o $? do terminal. Por exemplo, no bash, && só roda o segundo comando se o primeiro terminou com 0:

$ lua teste1.lua && echo "pode publicar"
todos os testes passaram
pode publicar

Com o teste_contas.lua, que termina com código 1, o pode publicar não aparece: lua teste_contas.lua && echo "pode publicar" mostra as seis linhas dos testes e o 4 ok, 2 falharam, e para aí. Ferramentas que rodam os testes sozinhas a cada mudança no código (o que os programadores chamam de integração contínua) funcionam exatamente assim.

5. O busted: a ferramenta de testes do Lua

A mini função da seção 2 é ótima para aprender e para programas pequenos. Projetos maiores usam o busted, uma rock que já traz tudo pronto: organiza os testes em grupos, tem dezenas de verificações e mostra um relatório. Ele não roda no editor do guia; é para o terminal.

Um arquivo de testes do busted

Por costume, os testes do busted ficam numa pasta spec (de "especificação"), em arquivos terminados em _spec.lua. O busted acha e roda todos sozinho:

local contas = require("contas")

describe("contas", function ()
  it("soma dois números", function ()
    assert.are.equal(5, contas.somar(2, 3))
  end)

  it("dá 10% de desconto", function ()
    assert.are.equal(72, contas.desconto(80, 10))
  end)

  it("recusa porcentagem acima de 100", function ()
    assert.has_error(function () contas.desconto(50, 150) end)
  end)
end)
describe("contas", function () … end)
"Descrever": um grupo de testes, com um nome. Pode ter grupos dentro de grupos.
it("soma dois números", function () … end)
"Isto…": um teste. Lido junto com o grupo, vira uma frase: "contas soma dois números". É o teste(nome, função) da seção 2, pronto.
assert.are.equal(esperado, obtido)
"São iguais": o esperado vem primeiro (ao contrário do nosso igual). Este assert é uma tabela cheia de verificações que o busted cria; não é o assert comum do Lua.
assert.has_error(função)
"Tem erro": passa se a função der erro. Substitui o nosso truque com pcall.
$ busted
+++
3 successes / 0 failures / 0 errors / 0 pending : 0.000905 seconds
$ echo $?
0

Cada + é um teste que passou. Depois, o placar: 3 sucessos, 0 falhas, 0 erros, 0 pendentes, e quanto tempo levou (esse número muda a cada vez). O código de saída é 0. Uma falha é uma verificação que não bateu; um erro é o teste quebrar no meio (um nil onde não devia, por exemplo).

O teste passa, mas devia falhar

Um teste que nunca falha não protege nada. Um erro comum é esquecer de comparar: assert(contas.somar(2, 3)) só confere que o resultado não é nil nem false; qualquer número passa. Escreva sempre o resultado esperado: assert(contas.somar(2, 3) == 5). Uma boa prática: quando escrever um teste novo, faça-o falhar uma vez de propósito (troque o 5 por 6) para ver que ele realmente confere alguma coisa.

Resumo

  • Um teste chama o seu código e compara com o resultado certo, automaticamente. Escreva uma vez, rode a cada mudança.
  • assert(cond, "mensagem") é o teste mais simples: para no primeiro erro, com a linha e a mensagem.
  • Uma mini função de teste com pcall roda todos os testes, mostra cada falha ("esperava X, veio Y") e conta o placar. Funciona no editor do guia.
  • Teste também os erros (pcall(f, …) == false), compare floats com tolerância e termine com os.exit(0 ou 1).
  • Quando um teste falha, o erro pode estar no código ou no teste.
  • O busted (describe, it, assert.are.equal) é a ferramenta de testes do Lua. Para o 5.5, instale com o LuaRocks oficial: luarocks --local install busted. O do apt só roda com o 5.4.
