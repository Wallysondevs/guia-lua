Projeto Jogo da Velha

O último projeto do guia é o jogo que todo mundo conhece: um tabuleiro de 3 por 3, X contra O, e vence quem completar uma linha, uma coluna ou uma diagonal. No terminal, o tabuleiro vira uma tabela de tabelas, as jogadas chegam pelo teclado como "linha coluna" (2 3), e na última versão a Ana joga contra o computador.

Você vai praticar
  • Montar uma grade com tabelas aninhadas e laços aninhados.
  • Entender por que tabelas são referências (e o tabuleiro com três linhas iguais).
  • Ler e separar a jogada com io.read e match com capturas.
  • Guardar regras como dados: as 8 trincas da vitória numa lista.
  • Alternar jogadores com o truque do and/or.
  • Escrever um adversário que "experimenta" jogadas e desfaz, com funções e math.random.

O que vamos construir

A versão final, com a Ana (X) contra o computador (O). O que vem depois de "Sua jogada, X (linha coluna):" foi digitado por ela; o resto é o programa. Esta partida ela perdeu:

Antes de começar

O projeto junta muita coisa dos anteriores: o while com break e a validação da Calculadora, os conjuntos e os padrões da Forca. Crie a pasta; o programa vai se chamar velha.lua:

$ mkdir -p projetos/velha
$ cd projetos/velha

Versão 1 · O tabuleiro

Um tabuleiro de 3 por 3 é uma grade: linhas e colunas. No Lua, uma grade é uma tabela de tabelas: tabuleiro[2] é a segunda linha (uma tabela com 3 casas), e tabuleiro[2][3] é a terceira casa dessa linha. Cada casa guarda "X", "O" ou " " (um espaço, a casa vazia). A primeira versão só monta o tabuleiro, põe duas peças e desenha.

-- Jogo da Velha da Ana, versão 1: o tabuleiro

-- Uma tabela com 3 linhas; cada linha é uma tabela com 3 casas.
local tabuleiro = {}
for linha = 1, 3 do
  tabuleiro[linha] = {}
  for coluna = 1, 3 do
    tabuleiro[linha][coluna] = " "
  end
end

local function desenhar(t)
  print()
  print("    1   2   3")
  for linha = 1, 3 do
    print(string.format("%d   %s | %s | %s", linha, t[linha][1], t[linha][2], t[linha][3]))
    if linha < 3 then
      print("   ---+---+---")
    end
  end
  print()
end

Um X só, colocado em tabuleiro[2][2], apareceu nas três linhas. O motivo: { vazia, vazia, vazia } não faz três cópias da linha. As três posições guardam a mesma tabela (o true do fim confirma: tabuleiro[1] == tabuleiro[2], é a mesma). Mudar a casa 2 de "uma das linhas" muda a única linha que existe. No Lua, guardar uma tabela numa variável (ou noutra tabela) guarda uma referência a ela, nunca uma cópia (veja Tabelas São Referências). Cada linha precisa do seu próprio {}, criado dentro do laço, como na versão 1.

Uma linha que não existe: attempt to index a nil value (field 'integer index') 
$ lua -e 'local t = {{}, {}, {}} print(t[4][1])'
lua: (command line):1: attempt to index a nil value (field 'integer index')
stack traceback:
        (command line):1: in main chunk
        [C]: in ?

Não há linha 4: t[4] é nil, e o [1] tenta olhar dentro de nil. O Lua 5.5 avisa que o nil veio de um campo com índice inteiro ('integer index'). É por isso que a versão 2 confere se a linha e a coluna estão entre 1 e 3 antes de usá-las.

Missão (versão 1): este tabuleiro foi montado com o atalho do cenário, e o X do meio aparece nas três linhas. Troque as duas linhas marcadas por laços que criem uma tabela nova para cada linha (e as 3 casas vazias dentro dela). A primeira linha do desenho deve ficar 1 | | O, sem X.

Versão 2 · As jogadas

Agora dois jogadores se revezam no mesmo teclado. Cada um digita a linha e a coluna separadas por espaço (2 3); o programa confere, marca a casa e passa a vez. Por enquanto ninguém ganha: o jogo vai até as 9 casas se encherem.

-- (o tabuleiro e o desenhar da versão 1, e depois:)

local jogador = "X"
local jogadas = 0

while jogadas < 9 do
  desenhar(tabuleiro)
  io.write("Jogador " .. jogador .. ", sua jogada (linha coluna): ")
  local entrada = io.read()
  if entrada == nil then
    print()
    print("Partida interrompida.")
    return
  end

  local l, c = entrada:match("^%s*(%d)%s+(%d)%s*$")
  l, c = tonumber(l), tonumber(c)
  if not l or l < 1 or l > 3 or c < 1 or c > 3 then
    print("Digite a linha e a coluna, de 1 a 3, separadas por espaço. Ex.: 2 3")
  elseif tabuleiro[l][c] ~= " " then
    print("Essa casa já está ocupada.")
  else
    tabuleiro[l][c] = jogador
    jogadas = jogadas + 1
    jogador = (jogador == "X") and "O" or "X"
  end
end

desenhar(tabuleiro)
print("Fim: todas as casas estão preenchidas.")
entrada:match("^%s*(%d)%s+(%d)%s*$")
Um padrão com duas capturas (os parênteses): ^ começo; %s* espaços que sobrarem; (%d) um algarismo, guardado; %s+ um ou mais espaços; (%d) outro algarismo, guardado; %s*$ espaços até o fim. O match devolve as duas capturas ("2" e "3"), ou nil se a entrada não tiver esse formato (22, a b, 2 3 4).
l, c = tonumber(l), tonumber(c)
As capturas são textos; viram números. Se o match falhou, tonumber(nil) dá nil, sem erro.
not l or l < 1 or l > 3 or c < 1 or c > 3
Recusa a entrada fora do formato e os números fora de 1 a 3 (4 1, 0 2). Com o or, se l for nil, o Lua para no not l e não chega a comparar nil < 1 (que daria erro).
tabuleiro[l][c] ~= " "
A casa já tem X ou O: a jogada é recusada e o mesmo jogador tenta de novo.
jogador = (jogador == "X") and "O" or "X"
Passa a vez: se era X, vira O; senão, vira X (o truque do and/or). Só acontece depois de uma jogada válida.
return
No fim da entrada, um return no corpo principal do programa encerra o arquivo inteiro: o Lua trata o arquivo como uma função.

Versão 3 · Quem ganhou?

Há exatamente 8 jeitos de ganhar: 3 linhas, 3 colunas e 2 diagonais. Em vez de escrever 8 ifs parecidos, o programa guarda as 8 "trincas" numa lista (cada trinca é uma lista de 3 casas, e cada casa é {linha, coluna}) e uma função só confere todas. É uma ideia que vale para muitos programas: quando a regra é uma lista de casos, guarde os casos como dados.

-- (o tabuleiro e o desenhar da versão 1, e depois:)

-- As 8 trincas que dão a vitória: 3 linhas, 3 colunas e 2 diagonais.
local TRINCAS = {
  { {1, 1}, {1, 2}, {1, 3} }, { {2, 1}, {2, 2}, {2, 3} }, { {3, 1}, {3, 2}, {3, 3} },
  { {1, 1}, {2, 1}, {3, 1} }, { {1, 2}, {2, 2}, {3, 2} }, { {1, 3}, {2, 3}, {3, 3} },
  { {1, 1}, {2, 2}, {3, 3} }, { {1, 3}, {2, 2}, {3, 1} },
}

-- Devolve "X" ou "O" se alguém completou uma trinca; senão, nil.
local function vencedor(t)
  for _, trinca in ipairs(TRINCAS) do
    local a, b, c = trinca[1], trinca[2], trinca[3]
    local simbolo = t[a[1]][a[2]]
    if simbolo ~= " " and simbolo == t[b[1]][b[2]] and simbolo == t[c[1]][c[2]] then
      return simbolo
    end
  end
  return nil
end

local jogadas = 0

Por que conferir a vitória antes do empate

Na 9ª jogada, o tabuleiro enche, mas essa última jogada pode ser a que completa uma trinca. Se o programa testasse o empate primeiro, diria "deu velha" para uma vitória. A ordem certa é a do código: primeiro vencedor, depois jogadas == 9.

Versão 4 · Contra o computador

A Ana quer jogar sozinha. O computador (O) segue uma estratégia simples, em quatro passos, na ordem:

  1. se houver uma casa que o faça ganhar, joga nela;
  2. senão, se houver uma casa em que o X ganharia na próxima, joga nela para bloquear;
  3. senão, pega o meio, se estiver livre;
  4. senão, sorteia uma casa livre.

Para os passos 1 e 2, o programa experimenta: põe o símbolo numa casa livre, pergunta ao vencedor se alguém ganhou, e desfaz. O programa foi reorganizado em funções:

Esquecer de desfazer a jogada experimentada

Sem a linha t[l][c] = " ", cada casa testada nos passos 1 e 2 ficaria marcada no tabuleiro de verdade: na primeira jogada do computador, todas as casas livres receberiam um "O" e depois um "X", e o tabuleiro se encheria de peças que ninguém jogou. Funções que mexem numa tabela recebida mexem na tabela original. Quando uma função só quer testar, ela precisa desfazer o que fez (ou trabalhar numa cópia; veja Tabelas São Referências).

Missão (versão 4): o computador ainda pula os passos 1 e 2: ele só pega o meio ou sorteia, e não bloqueia a Ana. No lugar do comentário de jogada_do_computador, escreva os dois laços: para cada símbolo de { "O", "X" } e cada casa de casas_livres(t), ponha o símbolo, confira vencedor(t), desfaça, e devolva a casa se alguém teria ganhado. A semente é fixa (42). Depois do 1 1 e do 1 2 da Ana, o computador deve bloquear em 1 3, e a partida deve terminar empatada.

Formas diferentes de fazer

O vencedor sem a lista de trincas

A mesma função vencedor, escrita com laços e ifs, testada em três tabuleiros (uma diagonal do X, um empate e uma coluna do O):

-- O vencedor com laços e ifs, sem a tabela de trincas.
local function vencedor(t)
  for i = 1, 3 do
    if t[i][1] ~= " " and t[i][1] == t[i][2] and t[i][2] == t[i][3] then
      return t[i][1]                                 -- linha i
    end
    if t[1][i] ~= " " and t[1][i] == t[2][i] and t[2][i] == t[3][i] then
      return t[1][i]                                 -- coluna i
    end
  end
  local meio = t[2][2]
  if meio ~= " " and ((t[1][1] == meio and meio == t[3][3]) or
                      (t[1][3] == meio and meio == t[3][1])) then
    return meio                                      -- uma das diagonais
  end
  return nil
end

print(vencedor({ { "X", "O", "O" }, { " ", "X", " " }, { " ", " ", "X" } }))
print(vencedor({ { "X", "X", "O" }, { "O", "O", "X" }, { "X", "O", "X" } }))
print(vencedor({ { "O", "X", " " }, { "O", "X", " " }, { "O", " ", "X" } }))

Ideias para continuar

  • Um placar: várias partidas, revezando quem começa, com "Jogar de novo?" (como no Jogo de Adivinhação).
  • Um computador melhor: depois do meio, preferir os cantos ({1, 1}, {1, 3}, {3, 1}, {3, 3}) às bordas. Com mais algumas regras, ele nunca perde.
  • Aceitar a jogada como um número de 1 a 9 e convertê-la para linha e coluna: l = (n - 1) // 3 + 1 e c = (n - 1) % 3 + 1 (veja Divisão: /, // e %).

Resumo

  • Uma grade é uma tabela de tabelas: t[linha][coluna]. Cada linha precisa do seu próprio {}; guardar a mesma tabela três vezes guarda três referências para uma tabela só.
  • match com capturas separa a jogada; tonumber e a validação (formato, faixa, casa livre) vêm antes de mexer no tabuleiro.
