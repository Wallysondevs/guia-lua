Lua os.remove e os.rename

Você já sabe abrir, ler e escrever arquivos. Falta cuidar deles como você faz no gerenciador de arquivos: apagar o rascunho que não serve mais, renomear a lista de compras do mês, mover um arquivo para outra pasta, guardar uma cópia de segurança antes de mexer. Para isso o Lua tem duas funções na biblioteca os (de operating system, "sistema operacional"): os.remove ("remover") e os.rename ("renomear").

Você vai aprender
  • Como apagar um arquivo com os.remove, e por que não existe lixeira.
  • O que as duas funções devolvem: true, ou nil com a mensagem e o código do erro.
  • Como apagar uma pasta (só se estiver vazia).
  • Como renomear e mover com os.rename, e o perigo: ele passa por cima de um arquivo que já existe.
  • Como saber se um arquivo existe, e como fazer uma cópia de segurança (.bak) antes de gravar.
  • Os erros reais: arquivo que não existe, pasta com coisas dentro, sem permissão, e os enganos de escrita.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), em /home/ana. Os comandos ls (lista os arquivos da pasta) e cat (mostra o conteúdo) do terminal servem para conferir o que mudou.

A ideia: o fichário da secretária

Pense numa secretária com um fichário de pastas. Duas tarefas dela não têm nada a ver com ler ou escrever as folhas:

  • Jogar uma ficha fora. E esta secretária não tem cesto de papel: ela passa a ficha no picotador. Não tem volta.
  • Trocar a etiqueta de uma ficha, ou mudar a ficha de gaveta. A folha continua a mesma; muda o nome ou o lugar.

No Lua, a primeira é o os.remove, e a segunda é o os.rename. Nenhuma das duas abre o arquivo: você não usa io.open nem close com elas.

Quando não dá para apagar

Rodando o mesmo programa de novo, o rascunho já não existe:

$ lua apagar.lua
nil	rascunho.txt: No such file or directory	2

É o mesmo trio do io.open (veja Abrindo Arquivos): nil no lugar do true, a mensagem (o nome e "não existe tal arquivo ou pasta") e o código do erro (2). O os.remove não para o programa; ele só avisa. Um programa bem-feito olha o aviso:

local nome = "rascunho.txt"
local ok, mensagem = os.remove(nome)
if ok then
  print("Apaguei " .. nome)
else
  print("Não apaguei: " .. mensagem)
end

$ lua apagar_tratando.lua
Não apaguei: rascunho.txt: No such file or directory
$ printf 'oi\n' > rascunho.txt
$ lua apagar_tratando.lua
Apaguei rascunho.txt

A primeira vez, não havia o que apagar; a Ana criou o arquivo de novo, e a segunda deu certo.

2. Apagando pastas: só se estiverem vazias

O os.remove também apaga pastas, mas só pastas vazias. A Ana criou duas, com o comando mkdir ("criar pasta"): fotos_velhas, com uma foto dentro, e pasta_vazia, sem nada:

$ mkdir fotos_velhas
$ printf 'x' > fotos_velhas/praia.jpg
$ mkdir pasta_vazia
print(os.remove("fotos_velhas"))
print(os.remove("pasta_vazia"))

$ lua pastas.lua
nil	fotos_velhas: Directory not empty	39
true
$ ls -d fotos_velhas pasta_vazia
ls: não é possível acessar 'pasta_vazia': Arquivo ou diretório inexistente
fotos_velhas

A fotos_velhas foi recusada: Directory not empty, "a pasta não está vazia" (código 39). A pasta_vazia foi apagada: o ls já não a encontra (essa mensagem do ls sai em português, porque o terminal da Ana está em português; as do Lua saem em inglês). É uma proteção: o os.remove nunca apaga um monte de arquivos de uma vez. Para apagar uma pasta com coisas dentro, apague antes cada arquivo (e cada subpasta), e por último a pasta.

E criar uma pasta?

O Lua puro não tem função para criar pastas, nem para listar o que tem dentro de uma. A biblioteca padrão do Lua é pequena de propósito: ela só usa o que existe em qualquer sistema com a linguagem C. Para isso existe a biblioteca LuaFileSystem (lfs.mkdir, lfs.dir), que se instala com o LuaRocks (veja LuaRocks), ou o caminho de chamar o comando mkdir com os.execute (veja Rodando Outros Programas).

4. Movendo para outra pasta

Se o nome novo tiver outra pasta, o os.rename move o arquivo para lá. É o mesmo "trocar a etiqueta", só que a etiqueta inclui a gaveta:

print(os.rename("compras-outubro.txt", "Documentos/compras-outubro.txt"))
print(os.rename("Documentos/compras-outubro.txt", "Documentoss/compras-outubro.txt"))

$ lua mover.lua
true
nil	No such file or directory	2
$ ls Documentos
compras-outubro.txt

O primeiro os.rename moveu a lista para a pasta Documentos. O segundo tentou mover para Documentoss (com dois "s"), uma pasta que não existe: No such file or directory. Foi o caso em que o problema estava no segundo nome, e a mensagem é a mesma de quando o primeiro não existe. Assim como o io.open, o os.rename não cria pastas.

Mover para outro disco

O os.rename só funciona dentro do mesmo disco (o mesmo "sistema de arquivos"). Na máquina da Ana, a pasta /tmp fica em outro (ela mora na memória), e mover para lá falha:

$ printf "oi\n" > x.txt
$ lua -e 'print(os.rename("x.txt", "/tmp/x.txt"))'
nil	Invalid cross-device link	18

"Ligação inválida entre dispositivos", código 18. O mesmo acontece ao mover para um pen drive. Nesse caso, o jeito é copiar (ler o arquivo de um lado e escrever do outro, com io.open) e depois apagar o original com os.remove. (No editor do guia, a /tmp fica no mesmo disco da /home/ana, e esse os.rename dá true.)

5. O perigo: o os.rename passa por cima

Se já existir um arquivo com o nome novo, o os.rename não pergunta: ele substitui. A Ana tinha uma lista velha, importante, e uma nova:

$ printf 'lista NOVA\n' > nova.txt
$ printf 'lista VELHA, importante\n' > velha.txt
print(os.rename("nova.txt", "velha.txt"))

$ lua sobrescreve.lua
true
$ ls nova.txt velha.txt
ls: não é possível acessar 'nova.txt': Arquivo ou diretório inexistente
velha.txt
$ cat velha.txt
lista NOVA

true, sem aviso nenhum. A lista VELHA, importante se perdeu: no lugar dela ficou a nova, com o nome da velha. Isso é o comportamento do Linux (e do macOS). No Windows, o os.rename para um nome que já existe falha em vez de substituir (ilustrativo: não foi rodado num Windows). Nos dois casos, a regra é a mesma: confira antes.

Conferindo se um arquivo existe

O Lua não tem uma função "existe?". O jeito tradicional é tentar abrir o arquivo para ler: se abrir, ele existe (e você fecha logo em seguida).

local function existe(nome)
  local f = io.open(nome, "r")
  if f then
    f:close()
    return true
  end
  return false
end

print(existe("velha.txt"))
print(existe("nova.txt"))

$ lua existe.lua
true
false

Com ela, o programa só renomeia quando não vai estragar nada (o Documentos/compras-outubro.txt já existe desde a seção 4):

local function existe(nome)
  local f = io.open(nome, "r")
  if f then f:close() return true end
  return false
end

local velho, novo = "velha.txt", "Documentos/compras-outubro.txt"
if existe(novo) then
  print("Já existe um " .. novo .. "; não vou passar por cima.")
else
  assert(os.rename(velho, novo))
  print("Pronto.")
end

$ lua renomear_seguro.lua
Já existe um Documentos/compras-outubro.txt; não vou passar por cima.

(Esse existe responde false também para um arquivo que existe mas que você não pode ler. Para o uso de todo dia, serve bem.)

6. A cópia de segurança (.bak)

Um uso clássico das duas funções juntas: antes de gravar a lista nova por cima da antiga, guarde a antiga com outro nome. Se algo der errado, ela está lá. O costume é pôr .bak (de backup, "cópia de segurança") no fim do nome:

local nome = "compras.txt"
os.remove(nome .. ".bak")
assert(os.rename(nome, nome .. ".bak"))

local f = assert(io.open(nome, "w"))
f:write("arroz\nfeijão\n")
f:close()
print("Lista nova gravada; a antiga está em " .. nome .. ".bak")
os.remove(nome .. ".bak")
Apaga a cópia anterior, se houver. Se não houver, devolve nil e a mensagem, e o programa nem olha: aqui, "não existia" está ótimo. (No Linux o rename passaria por cima mesmo; o remove antes deixa claro que a intenção é essa, e evita a falha do Windows.)
assert(os.rename(nome, nome .. ".bak"))
compras.txt vira compras.txt.bak. Com o assert, se não der para renomear, o programa para antes de gravar por cima (veja assert).
io.open(nome, "w")
Agora o compras.txt não existe mais, e o "w" cria um novo, com a lista nova.
$ printf 'pão\nleite\n' > compras.txt
$ lua backup.lua
Lista nova gravada; a antiga está em compras.txt.bak
$ cat compras.txt compras.txt.bak
arroz
feijão
pão
leite

O cat com dois arquivos mostra um depois do outro: a lista nova (arroz, feijão) e, na cópia, a antiga (pão, leite). Rodando de novo, a cópia passa a ser a lista que estava valendo:

$ lua backup.lua
Lista nova gravada; a antiga está em compras.txt.bak
$ cat compras.txt.bak
arroz
feijão

Repare: só existe uma cópia, a da vez anterior. É assim que muitos editores de texto fazem o arquivo ~ ou .bak que aparece ao lado do original.

Formas diferentes de lidar com o erro

O os.remove e o os.rename respondem do mesmo jeito que o io.open, então as formas de tratar também são as mesmas:

FormaO que acontece se falharQuando usar
local ok, msg = os.remove(nome) + if ok then … else … endO programa avisa do seu jeito e continuaQuando a falha é normal ou esperada (o arquivo pode já não existir)
assert(os.rename(velho, novo))O programa para, com a mensagemQuando os passos seguintes dependem desse dar certo (o backup antes de gravar)
os.remove(nome) sem olharNada; ninguém fica sabendoSó quando você não se importa mesmo, como o .bak velho da seção 6

Quando dá errado

Sem permissão

Para apagar ou renomear um arquivo, quem precisa de permissão é a pasta em que ele está (é a pasta que "guarda os nomes"). A Ana criou a pasta trancada com um contrato dentro e tirou dela a permissão de escrita (chmod 555: todos podem ler e entrar, ninguém pode mudar):

$ mkdir trancada
$ printf 'importante\n' > trancada/contrato.txt
$ chmod 555 trancada
print(os.remove("trancada/contrato.txt"))
print(os.rename("trancada/contrato.txt", "contrato.txt"))

$ lua sem_permissao.lua
nil	trancada/contrato.txt: Permission denied	13
nil	Permission denied	13

"Permissão negada", código 13, nos dois. (De novo, o rename sem o nome do arquivo.) É o que acontece também ao tentar apagar arquivos do sistema, como os de /etc (no editor do guia não dá para ver isso: lá não existem os arquivos do sistema). Como consertar: não é coisa do programa; ou o arquivo não é seu para apagar, ou a permissão da pasta precisa mudar.

Dois-pontos no lugar do ponto

Depois de tanto f:read e f:close, a mão escorrega:

os:remove("compras.txt")

$ lua ponto.lua
lua: ponto.lua:1: calling 'remove' on bad self (string expected, got table)
stack traceback:
	[C]: in method 'remove'
	ponto.lua:1: in main chunk
	[C]: in ?

"Chamando remove com um self ruim (esperava uma string, veio uma tabela)". Com os dois-pontos, o Lua entregou a própria biblioteca os (que é uma tabela) como primeiro argumento, no lugar do nome do arquivo. Como consertar: os.remove e os.rename são com ponto: eles são da biblioteca, não de um arquivo aberto. Os dois-pontos são para f:read, f:write, f:close.

Esqueceu o nome novo 
os.rename("compras.txt")

$ lua um_arg.lua
lua: um_arg.lua:1: bad argument #2 to 'rename' (string expected, got no value)
stack traceback:
	[C]: in field 'rename'
	um_arg.lua:1: in main chunk
	[C]: in ?

"Argumento ruim nº 2 para o rename (esperava uma string, não veio nada)". O os.rename precisa dos dois nomes: de e para. Este erro para o programa, porque é um engano de quem escreveu, não um problema com o arquivo.

Resumo

  • os.remove(nome) apaga um arquivo de vez (não há lixeira) ou uma pasta vazia.
  • os.rename(velho, novo) renomeia; com uma pasta no nome novo, move. Não cria pastas, e no Linux substitui sem perguntar um arquivo que já tenha o nome novo.
  • Os dois devolvem true, ou nil + mensagem + código (como o io.open), sem parar o programa. A mensagem do os.rename não traz o nome do arquivo.
  • Para saber se um arquivo existe, tente io.open(nome, "r") e feche logo.
  • Antes de gravar por cima, guarde a versão anterior: assert(os.rename(nome, nome .. ".bak")).
  • os.remove e os.rename são com ponto (são da biblioteca os), e não precisam de io.open nem close.
