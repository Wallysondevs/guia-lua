Lua Lendo Arquivos

Na aula Abrindo Arquivos, você abriu o compras.txt e leu tudo de uma vez com f:read("a"). Mas nem sempre se quer o arquivo inteiro num texto só: às vezes é uma linha por vez (para numerar os itens), às vezes são números (para somar as notas da turma), às vezes é preciso voltar ao começo e ler de novo. Tudo isso é o f:read ("ler"), com um formato diferente para cada caso.

Você vai aprender
  • Os formatos do f:read: "a" (tudo), "l" (uma linha), "L" (uma linha com o Enter), "n" (um número) e um número de bytes.
  • Que o arquivo tem uma posição, como um marcador de página, e que cada leitura anda com ela.
  • O que o f:read devolve quando o arquivo acaba (nil) e como isso vira um laço que lê todas as linhas.
  • Como ler números de um arquivo e somar as notas.
  • Como saber o tamanho do arquivo e voltar ao começo com f:seek.
  • A pegadinha do arquivo que veio do Windows, e os erros reais.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), em /home/ana. O arquivo de sempre é o compras.txt, com três linhas:

$ printf 'pão\nleite\ncafé\n' > compras.txt
$ ls -l compras.txt
-rw-rw-r-- 1 ana ana 17 Oct 18 16:39 compras.txt

São 17 bytes: "pão" tem 4 (o "ã" ocupa 2; veja Acentos e a Biblioteca utf8), "leite" tem 5, "café" tem 5, e cada uma das três quebras de linha (\n) é mais 1. Esse número vai voltar mais adiante.

A ideia: o marcador de página

Quando a Ana lê um livro aos poucos, ela deixa um marcador na página onde parou. No dia seguinte, ela não começa do zero: continua do marcador. E quando chega à última página, não tem mais o que ler.

Um arquivo aberto tem um marcador assim, chamado posição:

  • logo depois do io.open, a posição está no começo do arquivo (no byte 0);
  • cada f:read lê a partir da posição e deixa o marcador logo depois do que leu;
  • quando o marcador chega ao fim, as próximas leituras não acham mais nada e devolvem nil;
  • o f:seek (seção 6) move o marcador para onde você quiser, como pular para uma página.

1. "a": o arquivo inteiro num texto

local f = assert(io.open("compras.txt", "r"))
local texto = f:read("a")
f:close()
print(type(texto), #texto)
print(texto)
print("--- fim ---")

$ lua ler_tudo.lua
string	17
pão
leite
café

--- fim ---

O "a" (de all, "tudo") devolve uma string com os 17 bytes, quebras de linha incluídas. A linha em branco antes do --- fim --- aparece porque o texto já termina com \n e o print pula mais uma linha. O assert em volta do io.open é o que você viu na aula anterior: se o arquivo não abrir, o programa para com a mensagem certa.

Ler tudo de uma vez é o jeito mais simples quando o arquivo é pequeno (uma lista, uma configuração, um texto) e você quer o conteúdo inteiro, por exemplo para procurar uma palavra com string.find ou contar as palavras com gmatch.

2. "l": uma linha por vez

O "l" (de line, "linha") lê do marcador até o fim da linha. Cada chamada pega a próxima linha:

local f = assert(io.open("compras.txt", "r"))
print(f:read("l"))
print(f:read("l"))
print(f:read("l"))
print(f:read("l"))
f:close()

$ lua ler_linhas.lua
pão
leite
café
nil

Três linhas no arquivo, quatro leituras: na quarta, o marcador já estava no fim, e o f:read devolveu nil. É assim que o Lua avisa "o arquivo acabou". Esse nil é a peça mais importante desta aula: é ele que faz o laço da seção 3 saber a hora de parar.

O "l" é o formato padrão: f:read(), sem nada, é o mesmo que f:read("l").

"l" × "L": com ou sem o Enter

O "l" devolve a linha sem a quebra de linha do fim. O "L" (maiúsculo) devolve a linha com ela. Os colchetes abaixo mostram exatamente onde cada texto começa e termina:

local f = assert(io.open("compras.txt", "r"))
local a = f:read("l")
local b = f:read("L")
local c = f:read()
f:close()
print("[" .. a .. "]")
print("[" .. b .. "]")
print("[" .. c .. "]")

$ lua l_e_L.lua
[pão]
[leite
]
[café]

O leite veio com o \n dentro, por isso o ] foi para a linha de baixo. Quase sempre você quer o "l": a linha limpa, pronta para comparar (linha == "leite") ou juntar com outro texto. O "L" serve quando você vai copiar as linhas para outro arquivo do jeito que estavam.

3. Todas as linhas: o laço com while

Você não sabe quantas linhas o arquivo tem. Mas sabe que, quando ele acabar, o f:read devolve nil. Então: enquanto a leitura trouxer uma linha, use a linha e leia a próxima (veja while):

local f = assert(io.open("compras.txt", "r"))
local numero = 0
local linha = f:read("l")
while linha do
  numero = numero + 1
  print(numero .. ". " .. linha)
  linha = f:read("l")
end
f:close()
print("Itens na lista: " .. numero)
local linha = f:read("l")
A primeira leitura, antes do laço, para a condição ter o que testar.
while linha do
"Enquanto houver linha." Um texto (mesmo vazio, "") conta como verdadeiro; só o nil (e o false) contam como falso. Então o laço para exatamente quando o arquivo acaba.
numero = numero + 1
Um contador, para numerar os itens e saber quantos foram.
linha = f:read("l")
A próxima leitura, no fim do bloco. Sem ela o laço repetiria o pão para sempre: o marcador não andaria.
$ lua laco.lua
1. pão
2. leite
3. café
Itens na lista: 3
Existe um jeito mais curto

Ler todas as linhas é tão comum que o Lua tem um atalho que dispensa o while e as duas leituras: for linha in f:lines() do … end, ou até for linha in io.lines("compras.txt") do … end, que abre e fecha o arquivo sozinho. Ele é o assunto da próxima aula, Linha por Linha (io.lines). Vale entender o while primeiro: o atalho faz exatamente isso por dentro.

4. "n": lendo números

A professora da Ana guardou as notas de um aluno no notas.txt, uma por linha. O "n" (de number, "número") lê um número e já devolve o número, não o texto:

$ printf '7.5\n8\n6.25\n10\n' > notas.txt
local f = assert(io.open("notas.txt", "r"))
local soma, quantas = 0, 0
local nota = f:read("n")
while nota do
  print("nota:", nota, math.type(nota))
  soma = soma + nota
  quantas = quantas + 1
  nota = f:read("n")
end
f:close()
print(string.format("Média: %.2f", soma / quantas))

$ lua notas.lua
nota:	7.5	float
nota:	8	integer
nota:	6.25	float
nota:	10	integer
Média: 7.94

O laço é o mesmo da seção 3, trocando "l" por "n". O math.type mostra que o Lua escolheu o tipo certo para cada número: 8 e 10 viraram inteiros (integer), 7.5 e 6.25 viraram float (veja Números). O "n" pula sozinho os espaços e as quebras de linha antes do número; por isso tanto faz se as notas estão uma por linha ou todas na mesma linha separadas por espaço. A média foi formatada com string.format: %.2f = duas casas decimais.

Quando não é um número

Se o próximo pedaço do arquivo não for um número, o "n" devolve nil (e não para o programa). Num arquivo com 7.5 8 dez 6:

$ printf '7.5 8 dez 6\n' > notas2.txt
local f = assert(io.open("notas2.txt", "r"))
print(f:read("n", "n", "n"))
print(f:read("l"))
f:close()

$ lua numero_texto.lua
7.5	8	nil
dez 6

Duas novidades nesse programa. Primeiro: um f:read pode receber vários formatos de uma vez e devolve um valor para cada um (aqui, três "n"). Segundo: o terceiro "n" encontrou dez, devolveu nil e não andou com o marcador além do espaço; o "l" seguinte leu o resto da linha, dez 6. Para o laço da seção 4, isso quer dizer que ele pararia no dez, sem erro, como se as notas tivessem acabado. Confira o arquivo quando a quantidade de notas lidas não bater.

5. Um número: quantos bytes ler

Em vez de um formato com letra, dá para pedir um número de bytes: f:read(2) lê os próximos 2 bytes. Este programa mistura tudo o que você viu, para seguir o marcador de perto:

local primeira, segunda = f:read("l", "l")
print(primeira, segunda)
print(f:read(2))
print(f:read(1))
print(f:read("a"))
print(f:read("a") == "", f:read("l"), f:read(1))
f:close()

O f:read(1) lê 1 byte. Letras com acento ocupam 2 bytes em UTF-8: se o programa tivesse lido 1 byte no meio do "é", sairia um pedaço de letra, que aparece na tela como um símbolo estranho. Ler por bytes é para arquivos binários (imagens, formatos próprios) ou para quando você sabe o tamanho exato; para texto, prefira "l" e "a".

6. f:seek: o tamanho e a volta ao começo

O f:seek ("procurar uma posição") move o marcador e devolve a posição nova, contada em bytes a partir do começo. Ele recebe de onde contar e, se quiser, quantos bytes andar a partir dali:

EscritaVai paraPara que serve
f:seek("set")o começo (byte 0)Ler o arquivo de novo
f:seek("set", 5)o byte 5, contando do começoPular direto para um ponto conhecido
f:seek("cur")fica onde está (current, "atual")Só perguntar "onde estou?"
f:seek("end")o fimSaber o tamanho do arquivo (a posição do fim é o tamanho)
local f = assert(io.open("compras.txt", "r"))
print("tamanho:", f:seek("end"))
print("voltei para:", f:seek("set"))
print(f:read("l"))
print("estou em:", f:seek("cur"))
print(f:read("l"))
f:seek("set", 0)
print("de novo:", f:read("l"))
f:seek("set", 5)
print("a partir do byte 5:", f:read("l"))
f:close()

$ lua seek.lua
tamanho:	17
voltei para:	0
pão
estou em:	5
leite
de novo:	pão
a partir do byte 5:	leite

Os 17 bytes do ls -l lá do começo. Depois de ler pão (4 bytes) e a quebra de linha (1 byte), o marcador ficou no byte 5, que é exatamente onde começa o leite. O f:seek("set", 5) no fim pulou direto para lá.

Cuidado com o seek("end") antes de ler

Depois de f:seek("end"), o marcador está no fim, e um f:read("a") devolveria "". Por isso o programa voltou com f:seek("set") antes de ler. Um jeito comum de escrever "tamanho sem perder o lugar": local atual = f:seek("cur"), local tamanho = f:seek("end"), f:seek("set", atual).

Formas diferentes de ler o mesmo arquivo

Para mostrar a lista de compras, linha por linha, há três caminhos. Os três dão a mesma saída (pão, leite, café):

-- 1) tudo de uma vez, e o texto inteiro na tela
local f = assert(io.open("compras.txt", "r"))
io.write(f:read("a"))
f:close()

-- 2) linha por linha com while
local f = assert(io.open("compras.txt", "r"))
local linha = f:read("l")
while linha do
  print(linha)
  linha = f:read("l")
end
f:close()

-- 3) linha por linha com o atalho (próxima aula)
for linha in io.lines("compras.txt") do
  print(linha)
end

Lua 5.1 e LuaJIT: o asterisco

No Lua 5.1 (e no LuaJIT, do Neovim e do LÖVE), os formatos se escrevem com asterisco: "*a", "*l", "*n". O Lua 5.5 ainda aceita o asterisco (ele é ignorado), então código antigo continua funcionando:

$ lua estrela.lua
pão
leite
café

(estrela.lua fez print(f:read("*l")) e print(f:read("*a")).) O contrário não vale: o "a" sem asterisco não funciona no 5.1. Mais diferenças em Lua 5.1, LuaJIT, 5.4 e 5.5.

Quando dá errado

Leu uma linha a mais: attempt to concatenate a nil value

O programador "sabia" que a lista tinha 4 itens e fez um for de 1 a 4. Mas o arquivo tem 3:

local f = assert(io.open("compras.txt", "r"))
for i = 1, 4 do
  local linha = f:read("l")
  print("Item: " .. linha)
end
f:close()

$ lua nil_concat.lua
Item: pão
Item: leite
Item: café
lua: nil_concat.lua:4: attempt to concatenate a nil value (local 'linha')
stack traceback:
	nil_concat.lua:4: in main chunk
	[C]: in ?

"Tentativa de concatenar (juntar com ..) um valor nil (a variável local linha)". Na quarta volta, o arquivo tinha acabado, o f:read devolveu nil, e o .. não junta texto com nil (veja Juntando Textos). Repare que as três primeiras linhas saíram: o erro só veio quando faltou a quarta. Como consertar: não conte as linhas de antemão; leia até o nil, com o while da seção 3.

Formato que não existe 
local f = assert(io.open("compras.txt", "r"))
print(f:read("tudo"))

$ lua formato_errado.lua
lua: formato_errado.lua:2: bad argument #1 to 'read' (invalid format)
stack traceback:
	[C]: in method 'read'
	formato_errado.lua:2: in main chunk
	[C]: in ?

"Argumento ruim nº 1 para o read (formato inválido)". Os formatos são só "a", "l", "L", "n" ou um número. O Lua olha a primeira letra (por isso "all" funcionaria, e "tudo" não). Como consertar: f:read("a").

Ponto no lugar do dois-pontos 
local f = assert(io.open("compras.txt", "r"))
print(f.read("l"))

$ lua ponto.lua
lua: ponto.lua:2: bad argument #1 to 'read' (FILE* expected, got string)
stack traceback:
	[C]: in field 'read'
	ponto.lua:2: in main chunk
	[C]: in ?

"Argumento ruim nº 1 para o read (esperava um FILE*, veio uma string)". FILE* é o nome, na linguagem C, de um arquivo aberto. Com o ponto, o f não é entregue ao read: o primeiro argumento passa a ser o "l", um texto, e não um arquivo. Como consertar: f:read("l"), com dois-pontos.

io.read no lugar de f:read: o programa fica parado 
local f = assert(io.open("compras.txt", "r"))
local linha = io.read("l")
print(linha)
f:close()

O programa abre o arquivo, mas o io.read (com io.) lê do teclado, não do arquivo (veja io.read()). No terminal, ele para e espera você digitar. A Ana digitou banana:

$ lua io_read.lua
banana
banana

A primeira banana é o que ela digitou; a segunda, o print. O arquivo nem foi lido. Como consertar: para ler do arquivo, use a variável dele: f:read("l").

O arquivo veio do Windows: a linha não é igual a ela mesma

No Windows, as linhas terminam com dois caracteres, \r\n, e não só \n. No Linux, o "l" tira o \n, mas o \r fica grudado no fim da linha, invisível:

$ printf 'pão\r\nleite\r\n' > windows.txt
local f = assert(io.open("windows.txt", "r"))
local linha = f:read("l")
f:close()
print(#linha, string.format("%q", linha))
print(linha == "pão")
linha = linha:gsub("\r$", "")
print(#linha, linha == "pão")

$ lua windows.lua
5	"pão\13"
false
true
4	true

A linha tem 5 bytes em vez de 4. O %q do string.format mostra o texto como ele é por dentro, e revela o intruso: \13, que é o \r (o caractere de número 13). Por isso linha == "pão" deu false, mesmo que na tela pareça igual. Como consertar: tire o \r do fim com linha:gsub("\r$", "") (veja gsub). Depois disso, 4 bytes e true.

Resumo

  • Um arquivo aberto tem um marcador (a posição). Cada f:read lê a partir dele e o deixa logo depois do que leu.
  • Formatos: "a" tudo, "l" uma linha sem o \n (o padrão), "L" com o \n, "n" um número, 5 cinco bytes. Vários de uma vez: f:read("l", "l").
  • No fim do arquivo, "l", "L", "n" e os bytes devolvem nil; o "a" devolve "".
  • Para todas as linhas: leia antes do laço, while linha do … linha = f:read("l") end. O atalho é o io.lines.
  • f:seek("end") dá o tamanho; f:seek("set") volta ao começo; f:seek("cur") diz onde você está.
  • Use sempre f:read (dois-pontos, a variável do arquivo); io.read é o teclado. Arquivo do Windows deixa um \r no fim das linhas.
