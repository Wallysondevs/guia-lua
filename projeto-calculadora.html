Projeto Calculadora

O primeiro projeto do guia: uma calculadora que roda no terminal. Ela pede um número, a operação e outro número, mostra o resultado e pergunta se você quer fazer outra conta. A conta em si é a parte fácil: o Lua já sabe somar. O desafio é fazer o programa não quebrar (nem responder bobagem) quando alguém divide por zero, escolhe uma operação que não existe ou digita "seis" no lugar de um número.

Você vai praticar
  • Escrever a pergunta com io.write() e ler a resposta com io.read().
  • Transformar o texto em número com tonumber() (e descobrir o que ele faz com "seis").
  • Escolher a conta com if e elseif.
  • Recusar a divisão por zero com if e else.
  • Repetir tudo com while e sair com break.
  • Separar o programa em funções que devolvem valores com return (às vezes dois).
  • Limpar e formatar o texto com gsub, match e string.format.

Vamos chegar lá em quatro versões. No fim de cada uma, o programa roda; cada versão acrescenta uma coisa só:

  1. Dois números e um operador (io.read, tonumber, if/elseif).
  2. A divisão por zero (que no Lua não dá erro: dá inf).
  3. Repetir até a pessoa sair (while true e break).
  4. Funções e entrada validada (local function, return, nil como "não deu").

Antes de começar

Você precisa saber criar e rodar um arquivo .lua (Rodando um Programa), usar variáveis com local e juntar textos com ... No seu computador, crie a pasta do projeto; o arquivo vai se chamar calculadora.lua:

$ mkdir -p projetos/calculadora
$ cd projetos/calculadora

Em cada versão há também uma caixa Experimente, que roda o Lua de verdade aqui na página. Nas missões deste projeto, a caixa tem um campo Entrada, já preenchido com as respostas que o programa vai receber, uma por linha, como se alguém as digitasse (a missão diz quais são). O editor mostra essas respostas depois de cada pergunta, como no terminal.

Antes da versão 1: o Lua converte sozinho… às vezes

O jeito mais curto de pedir dois números e somar seria este:

print("=== Calculadora da Ana ===")
io.write("Primeiro número: ")
local a = io.read()
io.write("Segundo número: ")
local b = io.read()
print(a .. " + " .. b .. " = " .. a + b)

$ lua calculadora.lua
=== Calculadora da Ana ===
Primeiro número: 10
Segundo número: 5
10 + 5 = 15

Deu certo! Mas preste atenção: o io.read() sempre devolve um texto (uma string), mesmo que a pessoa tenha digitado só algarismos. Para o Lua, a vale "10" e b vale "5". A conta funcionou porque o Lua tem uma ajuda automática: quando você usa + com dois textos que parecem números, ele os converte e faz a conta (é a coerção, veja Conversão). Repare também no .. a + b: o + é feito antes do .. (veja Precedência), então o texto recebe o resultado 15, e não "105".

Agora, se a Ana digitar um texto que não parece número:

$ lua calculadora.lua
=== Calculadora da Ana ===
Primeiro número: seis
Segundo número: 5
lua: calculadora.lua:6: attempt to add a 'string' with a 'string'
stack traceback:
        [C]: in metamethod 'add'
        calculadora.lua:6: in main chunk
        [C]: in ?

"Tentativa de somar uma string com uma string": o Lua tentou converter "seis" e não conseguiu. A mensagem fala de textos, e não de números, o que confunde quem lê. E há um problema pior, que você vai ver na versão 2: um texto "0" não é igual ao número 0. Por isso a calculadora converte o que foi digitado logo na entrada, com tonumber(), e passa a trabalhar só com números. É o primeiro passo da versão 1.

Versão 1 · Dois números e um operador

A calculadora pede o primeiro número, a operação e o segundo número. Os números passam pelo tonumber() ("para número"), que transforma o texto num número. A operação fica como texto mesmo: "+", "-", "*" ou "/". Para escolher a conta, uma escada de if e elseif.

print("=== Calculadora da Ana ===")
io.write("Primeiro número: ")
local a = tonumber(io.read())
io.write("Operação (+ - * /): ")
local op = io.read()
io.write("Segundo número: ")
local b = tonumber(io.read())

if op == "+" then
  print(a .. " + " .. b .. " = " .. a + b)
elseif op == "-" then
  print(a .. " - " .. b .. " = " .. a - b)
elseif op == "*" then
  print(a .. " * " .. b .. " = " .. a * b)
elseif op == "/" then
  print(a .. " / " .. b .. " = " .. a / b)
else
  print("Operação desconhecida: " .. op)
end

0.1 + 0.2 não dá exatamente 0.3 
$ lua calculadora.lua

Operação (+ - * /): +
Segundo número: 0.2

Não é defeito da calculadora nem do Lua: o computador guarda os números com casas decimais em binário, e alguns, como 0.1, não têm representação exata (como 1/3 não tem em decimal: 0,3333…). Sobra um erro minúsculo na 17ª casa. Quase toda linguagem de programação dá o mesmo resultado. Na versão 4, a calculadora arredonda na hora de mostrar.

Curiosidade: o Lua 5.4 mostrava 0.3 aqui, porque escondia as últimas casas ao transformar o número em texto. O 5.5 mostra o número inteiro, sem esconder. Conferido no computador da Ana:

$ lua -e "print(0.1 + 0.2, 10 / 5, 7 // 2, 2^10)"
0.30000000000000004     2.0     3       1024.0
$ lua5.4 -e "print(0.1 + 0.2, 10 / 5, 7 // 2, 2^10)"
0.3     2.0     3       1024.0

A conta é a mesma nas duas versões; só a forma de mostrar mudou. Mais em As Diferenças entre as Versões.

Versão 2 · A divisão por zero

Na maioria das linguagens, dividir por zero para o programa com um erro. No Lua, com a barra /, não: a conta é feita com floats, e o resultado é um valor especial. Veja a versão 1 recebendo um zero:

$ lua calculadora.lua
=== Calculadora da Ana ===
Primeiro número: 1
Operação (+ - * /): /
Segundo número: 0
1 / 0 = inf
$ lua calculadora.lua
=== Calculadora da Ana ===
Primeiro número: 0
Operação (+ - * /): /
Segundo número: 0
0 / 0 = -nan

inf é "infinito" (de infinity) e nan é "não é um número" (not a number; o sinal de menos na frente não quer dizer nada de útil). O programa não quebrou, mas a resposta não serve para a Ana. Na matemática, dividir por zero não tem resposta: a calculadora deve avisar. A mudança é um if dentro do caso da divisão:

print("=== Calculadora da Ana ===")
io.write("Primeiro número: ")
local a = tonumber(io.read())
io.write("Operação (+ - * /): ")
local op = io.read()
io.write("Segundo número: ")
local b = tonumber(io.read())

if op == "+" then
  print(a .. " + " .. b .. " = " .. a + b)
elseif op == "-" then
  print(a .. " - " .. b .. " = " .. a - b)
elseif op == "*" then
  print(a .. " * " .. b .. " = " .. a * b)
elseif op == "/" then
  if b == 0 then
    print("Não dá para dividir por zero.")
  else
    print(a .. " / " .. b .. " = " .. a / b)
  end
else
  print("Operação desconhecida: " .. op)
end
elseif op == "/" then
O caso da divisão continua o mesmo; o que mudou é o que está dentro dele.
if b == 0 then
Um if comum, dentro do caso: se o divisor for zero, avisa em vez de dividir. Um bloco pode ter qualquer coisa dentro, inclusive outro if (veja Condições Aninhadas).
else … end
Senão, faz a conta como antes. Esse end fecha o if b == 0; o end da última linha continua fechando a escada de fora. Indentar com 2 espaços ajuda a ver qual end fecha o quê.
$ lua calculadora.lua
=== Calculadora da Ana ===
Primeiro número: 1
Operação (+ - * /): /
Segundo número: 0
Não dá para dividir por zero.
$ lua calculadora.lua
=== Calculadora da Ana ===
Primeiro número: 9
Operação (+ - * /): -
Segundo número: 12
9 - 12 = -3

Em vez de inf, uma frase que a Ana entende. Isso é prevenir: o programa confere antes de fazer a conta perigosa.

Por que o tonumber é importante aqui

Sem o tonumber, o b seria o texto "0", e "0" == 0 dá false no Lua: o == nunca converte, um texto nunca é igual a um número. O if não pegaria o zero e a calculadora mostraria 1 / 0 = inf do mesmo jeito. A coerção automática que você viu antes do + só vale para contas, nunca para comparações. Por isso: converta na entrada.

Nem toda divisão por zero dá inf

Com a barra /, o Lua faz a conta com floats e o zero vira inf. Mas a divisão inteira // e o resto % entre dois inteiros param o programa com um erro de verdade:

$ lua -e "print(7 // 0)"
lua: (command line):1: attempt to divide by zero
stack traceback:
        (command line):1: in main chunk
        [C]: in ?
$ lua -e "print(7 % 0)"
lua: (command line):1: attempt to perform 'n%0'
stack traceback:
        (command line):1: in main chunk
        [C]: in ?
$ lua -e "print(7.0 % 0, 7 / 0, 7 // 0.0)"
-nan    inf     inf

"Tentativa de dividir por zero" e "tentativa de fazer n%0" (resto de um número por zero). O (command line):1 quer dizer "na linha 1 do código que veio na linha de comando" (o -e). Com um float no meio (7.0, 0.0), volta o inf/nan. Conclusão: confira o zero antes de qualquer divisão. O desafio do fim da página usa o %, e lá esse cuidado vai fazer falta.

Versão 3 · Repetir até a pessoa sair

Até agora, cada conta exige rodar o programa de novo. A Ana quer fazer várias contas seguidas. A solução é colocar tudo dentro de um laço while ("enquanto") e, no fim de cada volta, perguntar se ela quer continuar.

print("=== Calculadora da Ana ===")

while true do
  io.write("Primeiro número: ")
  local a = tonumber(io.read())
  io.write("Operação (+ - * /): ")
  local op = io.read()
  io.write("Segundo número: ")
  local b = tonumber(io.read())

  if op == "+" then
    print(a .. " + " .. b .. " = " .. a + b)
  elseif op == "-" then
    print(a .. " - " .. b .. " = " .. a - b)
  elseif op == "*" then
    print(a .. " * " .. b .. " = " .. a * b)
  elseif op == "/" then
    if b == 0 then
      print("Não dá para dividir por zero.")
    else
      print(a .. " / " .. b .. " = " .. a / b)
    end
  else
    print("Operação desconhecida: " .. op)
  end

  io.write("Outra conta? (s/n): ")
  local continuar = io.read()
  if continuar ~= "s" then
    break
  end
end

print("Até logo!")
while true do
"Enquanto verdadeiro, faça": um laço que, sozinho, nunca termina. Tudo o que está entre o do e o end dele se repete. Quem decide a hora de parar é o break lá dentro.
(o bloco inteiro andou 2 espaços)
As perguntas e o if agora estão dentro do while. Para o Lua, quem marca o que é do laço é o do … end, e não a indentação; mas indentar deixa isso visível para você (veja Sintaxe e Blocos).
local continuar = io.read()
Lê a resposta. Como está dentro do laço, é uma variável nova a cada volta.
if continuar ~= "s" then
"Se a resposta for diferente de s". No Lua, "diferente" se escreve ~= (não !=). Qualquer outra coisa (n, não, só Enter) encerra.
break
"Quebrar": sai do laço na hora. O programa continua na primeira linha depois do end do while (veja break).
print("Até logo!")

Ela queria continuar, mas digitou S maiúsculo, e "S" ~= "s" é verdadeiro: para o Lua, maiúscula e minúscula são letras diferentes. Na versão 4, a resposta passa por lower() ("mais baixo", minúsculas) antes de comparar.

Por que while true com break?

Dava para usar o repeat … until ("repita … até que"), que testa a condição no fim de cada volta: repeat … until continuar ~= "s". O problema é que continuar precisa ser lido antes do until. O while true com break deixa a ordem natural, faz a conta e depois pergunta, e funciona igual em qualquer versão do Lua. É um padrão muito comum em programas que conversam com a pessoa.

Sair no meio com Ctrl+C ou Ctrl+D

Se a Ana desistir no meio de uma conta e apertar Ctrl+C, que interrompe qualquer programa no terminal:

$ lua calculadora.lua
=== Calculadora da Ana ===
Primeiro número: 10
Operação (+ - * /): ^C
lua: calculadora.lua:7: interrupted!
stack traceback:
        [C]: in field 'read'
        calculadora.lua:7: in main chunk
        [C]: in ?
$ echo $?
1

O ^C é o terminal mostrando a tecla. O Lua responde com interrupted! ("interrompido!") e o traceback mostra onde o programa estava: na linha 7, dentro da função read (o [C]: in field 'read'), esperando a operação. O código de saída 1 (o echo $?) diz "terminou com erro". Não é defeito: é o jeito normal de interromper.

Já o Ctrl+D quer dizer "acabou a entrada". Aí o io.read() não tem linha nenhuma para devolver e devolve nil:

$ lua calculadora.lua
=== Calculadora da Ana ===
Primeiro número: 10
Operação (+ - * /): +
Segundo número:
lua: calculadora.lua:12: attempt to perform arithmetic on a nil value (local 'b')
stack traceback:
        calculadora.lua:12: in main chunk

Versão 4 · Funções e entrada validada

A versão 3 já faz várias contas, mas ainda quebra com seis, com 2,5 e com o Ctrl+D, e não aceita o S maiúsculo. E o programa ficou comprido: está tudo misturado num bloco só. A versão 4 resolve as duas coisas de uma vez: cada tarefa vira uma função com nome, e a função que lê números insiste até receber um número de verdade.

-- Calculadora da Ana, versão 4: funções e entrada validada

  if texto == nil then        -- a entrada acabou (Ctrl+D)

Formas diferentes de escolher a conta

A calculadora usou uma escada de if/elseif. O Lua não tem um comando switch (ou match) como outras linguagens; o jeito "à moda do Lua" de escolher entre vários valores é uma tabela que liga cada símbolo a uma função. Funciona porque, no Lua, funções são valores: dá para guardá-las numa tabela como se fossem números.

local a, op, b = 10, "*", 3

-- Forma 1: if/elseif
if op == "+" then
  print("if/elseif:", a + b)
elseif op == "*" then
  print("if/elseif:", a * b)
end

-- Forma 2: uma tabela de funções
local contas = {
  ["+"] = function (x, y) return x + y end,
  ["-"] = function (x, y) return x - y end,
  ["*"] = function (x, y) return x * y end,
  ["/"] = function (x, y) return x / y end,
}
print("tabela:", contas[op](a, b))
print("existe '%'?", contas["%"])

$ lua formas.lua
if/elseif:	30
tabela:	30
existe '%'?	nil

Na forma 2, contas[op] busca na tabela a função guardada na chave "*", e o (a, b) logo depois a chama com os dois números. Uma operação que não existe dá nil: if not contas[op] then faz o papel do else. (A chave precisa dos colchetes, ["+"], porque + não é um nome válido para escrever contas.+.)

FormaQuando usar
if / elseifPoucas opções, ou condições diferentes entre si (op == "/" and b == 0). É o mais fácil de ler no começo.
Tabela de funçõesMuitas opções que fazem coisas do mesmo formato. Acrescentar uma operação é acrescentar uma linha na tabela, e contas[op] já serve para validar a operação.

Resumo

  • O io.read() sempre devolve texto (ou nil quando a entrada acaba). Converta na entrada com tonumber(): a coerção automática do Lua vale para contas, mas não para comparações ("0" == 0 é false).
  • tonumber devolve nil para o que não é número ("seis", "2,5"): confira antes de fazer conta.
  • if/elseif/else escolhem a conta; uma tabela de funções é a alternativa à moda do Lua.
  • Dividir por zero com / não dá erro no Lua: dá inf ou nan. Com // e % entre inteiros, dá erro. Previna com if b == 0.
  • while true do … end com break repete até a pessoa pedir para sair; match e lower deixam a resposta tolerante.
  • Funções com nomes claros deixam o programa principal curto. Funções locais precisam ser criadas antes de serem chamadas.
  • return nil, "motivo" é o jeito do Lua de dizer "não deu".
  • Nunca rode com load o que a pessoa digita.
