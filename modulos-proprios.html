Lua Criando seu Módulo

Na aula Módulos e require você usou um módulo pronto. Agora é a sua vez de escrever um. A boa notícia: não há nada novo para decorar. Um módulo é um arquivo comum que monta uma tabela com funções e a devolve com return. O que esta aula ensina é a receita que a comunidade usa, e os cuidados que fazem um módulo ser fácil de usar e difícil de quebrar.

Você vai aprender
  • A receita de todo módulo: local M = {}, as funções, return M.
  • A diferença entre o que o módulo mostra (funções públicas, dentro da tabela) e o que ele esconde (funções e variáveis local, privadas).
  • Outras formas de montar a tabela, e um módulo que devolve uma função só.
  • Um módulo que guarda informação entre as chamadas, compartilhada por todo o programa.
  • Como organizar módulos em pastas: require("loja.estoque") e o init.lua.
  • Os erros reais: a função que "vaza" como global, o : no lugar do ., dois módulos que se pedem um ao outro, e o arquivo com nome de biblioteca padrão.

Os exemplos rodaram no Lua 5.5 da máquina da Ana, numa pasta chamada proj. Nas caixas "Experimente", cada módulo é uma aba: clique nela para ver e editar o arquivo.

A ideia: a gaveta com etiqueta e o fundo falso

Pense no módulo como uma gaveta de cozinha que a Ana arruma para emprestar. Na frente da gaveta ficam as ferramentas que qualquer um pode pegar: a faca, a colher, o abridor. Mas a Ana também tem coisas que só ela usa para manter a gaveta funcionando (a pedra de afiar a faca, por exemplo), e essas ficam num fundo falso: quem pega a gaveta emprestada nem sabe que existem.

1. A receita: local M = {} … return M

local M = {}

local function arredondar(valor)
  return math.floor(valor * 100 + 0.5) / 100
end

function M.somar(a, b)
  return a + b
end

function M.desconto(preco, porcento)
  return arredondar(preco - preco * porcento / 100)
end

return M
local M = {}
A tabela do módulo, vazia no começo. O nome M (de "módulo") é um costume muito usado: em qualquer arquivo, M. quer dizer "isto vai para fora". Você também pode usar o nome do módulo (local contas = {}), como na aula anterior; as duas formas são comuns.
local function arredondar(valor)
Uma função privada: ela é local e não foi colocada na tabela M. Só o próprio arquivo contas.lua consegue chamá-la. (Ela arredonda para 2 casas: multiplica por 100, soma 0,5, corta a parte quebrada com math.floor e divide por 100. Veja A Biblioteca math.)
function M.somar(a, b)
Uma função pública: fica dentro da tabela, no campo somar. Quem fizer require("contas") recebe a tabela e chega nela.
return arredondar(…)
Uma função pública pode usar a privada à vontade: as duas moram no mesmo arquivo (é uma closure).
return M
Entrega a gaveta. Sem esta linha, o require devolveria só true (você viu esse erro na aula anterior).

Um programa que usa o módulo e, de curiosidade, tenta chegar na função privada:

local contas = require("contas")
print(contas.desconto(19.99, 15))
print(contas.arredondar)
print(contas.arredondar(3.14159))

$ lua main.lua
16.99
nil
lua: main.lua:4: attempt to call a nil value (field 'arredondar')
stack traceback:
	main.lua:4: in main chunk
	[C]: in ?

O desconto deu 16.99, já arredondado (sem o arredondamento, a conta 19,99 − 15% daria 16,9915). Mas contas.arredondar é nil: de fora, essa função não existe. Chamá-la dá "tentar chamar um valor nil (o campo arredondar)". É exatamente o que a Ana queria: quem usa o módulo só vê somar e desconto.

Por que esconder?

Tudo o que é público vira uma promessa: se outros programas usam contas.arredondar, a Ana não pode mais mudar o nome nem o jeito dela funcionar sem quebrar esses programas. O que é privado ela muda quando quiser. Regra prática: comece com tudo local e só ponha na tabela o que os outros realmente precisam.

Missão: o caixa quer calcular o troco, mas o módulo ainda não tem essa ferramenta: rode e veja o erro. Na aba contas.lua, crie a função pública M.troco(pago, total), que devolve pago - total (escreva antes do return M).

local contas = require("contas")
local total = contas.somar(8, 4.5)
print("Total: " .. total)
print("Troco: " .. contas.troco(20, total))

local M = {}

function M.somar(a, b)
  return a + b
end

-- crie aqui a função M.troco

return M

local M = {}

function M.somar(a, b)
  return a + b
end

function M.troco(pago, total)
  return pago - total
end

return M

2. Outras formas de montar a tabela

A receita da seção 1 é a mais usada, mas você vai encontrar outras. Esta escreve as funções como local e monta a tabela só no final, no próprio return:

local function somar(a, b)
  return a + b
end

local function dobro(x)
  return x * 2
end

return {
  somar = somar,
  dobro = dobro,
}

$ lua -e 'local l = require("literal") print(l.somar(2, 3), l.dobro(21))'
5	42

A vantagem: a lista do return funciona como um índice do que o módulo oferece. A desvantagem: ao criar uma função nova, é preciso lembrar de pôr na lista. (A vírgula depois do último item, dobro = dobro,, é permitida e facilita acrescentar mais um.)

E um módulo nem precisa devolver uma tabela. Pode devolver qualquer valor, por exemplo uma função só:

return function (nome)
  return "Olá, " .. nome .. "!"
end

$ lua -e 'local saudar = require("saudacao") print(saudar("Ana"))'
Olá, Ana!
FormaQuando usar
local M = {} + function M.f() … end + return MO padrão. Use esta quando estiver em dúvida.
Funções local + return { f = f, g = g }Quando você quer ver numa olhada só tudo o que é público.
return function (…) … endQuando o módulo faz uma coisa só (é raro; uma tabela deixa espaço para crescer).

3. Um módulo que guarda informação

Lembra que o require roda o arquivo uma vez só e guarda a tabela em package.loaded? Isso tem uma consequência útil: as variáveis local do módulo continuam existindo entre uma chamada e outra, e todos os arquivos que pedem o módulo enxergam os mesmos valores. A Ana fez um caixa que conta as vendas do dia:

local caixa = {}
local vendas = 0
local total = 0

function caixa.registrar(valor)
  vendas = vendas + 1
  total = total + valor
end

function caixa.resumo()
  return string.format("%d vendas, R$ %.2f", vendas, total)
end

return caixa

O balcão de pães é outro módulo, que também registra vendas no caixa:

local caixa = require("caixa")
local balcao = {}
function balcao.vender_pao()
  caixa.registrar(0.75)
end
return balcao

local caixa = require("caixa")
local balcao = require("balcao")
caixa.registrar(12.50)
balcao.vender_pao()
balcao.vender_pao()
print(caixa.resumo())

$ lua dia.lua
3 vendas, R$ 14.00

Três vendas: uma feita direto pelo dia.lua e duas pelo balcao.lua. Os dois pediram require("caixa") e receberam a mesma tabela, com o mesmo vendas e o mesmo total escondidos lá dentro. E ninguém de fora consegue mexer nesses números sem passar pelo registrar: eles são local. (Esse jeito de esconder dados é o assunto de Privacidade com Closures.)

4. Módulos em pastas: require("loja.estoque")

Quando os módulos ficam muitos, dá para organizá-los em pastas. A Ana criou a pasta loja e, dentro dela, o arquivo estoque.lua:

local estoque = {}
local itens = {pao = 30, leite = 12}
function estoque.quantidade(item)
  return itens[item] or 0
end
return estoque

local estoque, onde = require("loja.estoque")
print(estoque.quantidade("pao"), estoque.quantidade("bolo"), onde)

$ lua usa_estoque.lua
30	0	./loja/estoque.lua

No nome do require, o ponto vira barra: "loja.estoque" vira loja/estoque.lua. O segundo valor do require confirma: ele carregou ./loja/estoque.lua. (O or 0 faz o bolo, que não está na tabela, contar como zero; veja and, or e not.)

Ponto no require, barra no sistema

Escreva require("loja.estoque"), e não require("loja/estoque"). No Linux a barra até funciona, por coincidência, mas o ponto é a forma oficial e é a que funciona em qualquer sistema.

A pasta como módulo: init.lua

E se você quiser que require("relatorio") carregue uma pasta? Ponha dentro dela um arquivo chamado init.lua ("init" de initialize, inicializar). Lembra da linha no file './conta/init.lua' na lista de lugares procurados? É isso:

return { titulo = "Relatório do mês" }

$ lua -e 'local r, onde = require("relatorio") print(r.titulo, onde)'
Relatório do mês	./relatorio/init.lua

Missão: o módulo de estoque está na aba loja/estoque.lua, ou seja, dentro da pasta loja. Rode, leia a linha no file './estoque.lua' do erro e conserte o nome no require.

print("Leite no estoque: " .. estoque.quantidade("leite"))

5. O que o módulo recebe: ...

Um detalhe que às vezes aparece em código de outras pessoas: o require passa ao arquivo do módulo dois valores, que chegam nos ... (os três pontinhos) do arquivo: o nome pedido e o caminho do arquivo.

print("recebi:", ...)
return {}

$ lua -e 'require("args")'
recebi:	args	./args.lua

Alguns módulos grandes usam local nome = ... na primeira linha para saber com que nome foram carregados (e assim carregar os seus "irmãos" da mesma pasta). Para os seus primeiros módulos, você não vai precisar disso.

Quando dá errado

Esqueceu o M.: a função vazou como global 
local M = {}

function somar(a, b)
  return a + b
end

return M

local vaza = require("vaza")
print(somar(2, 3))
print(vaza.somar(2, 3))

$ lua usa_vaza.lua
5
lua: usa_vaza.lua:3: attempt to call a nil value (field 'somar')
stack traceback:
	usa_vaza.lua:3: in main chunk
	[C]: in ?

Sem o M. e sem local, function somar criou uma variável global. Ela não foi para a tabela do módulo (vaza.somar é nil, linha 3), mas apareceu, sem ninguém pedir, no programa inteiro (o somar(2, 3) da linha 2 funcionou!). Isso é perigoso: se outro módulo também tiver um somar global, um apaga o outro, e o erro aparece longe de onde nasceu (veja local × Global). Como consertar: function M.somar(a, b) para a função pública, ou local function somar(a, b) para a privada. Num módulo, nunca deixe uma função sem um dos dois.

Usou : no lugar do . 
local contas = require("contas")
print(contas:somar(2, 3))

$ lua ponto.lua
lua: ./contas.lua:8: attempt to perform arithmetic on a table value (local 'a')
stack traceback:
	./contas.lua:8: in method 'somar'
	ponto.lua:2: in main chunk
	[C]: in ?

O dois-pontos contas:somar(2, 3) quer dizer contas.somar(contas, 2, 3): ele passa a própria tabela como primeiro argumento (isso é útil em objetos; veja Métodos e o Dois-Pontos). Aí o a da função virou a tabela contas, e somar tabela com número dá "tentar fazer conta com um valor tabela (a local a)". O rastro até avisa: in method 'somar' (chamada como método). Como consertar: funções de módulo se chamam com ponto: contas.somar(2, 3).

Dois módulos que pedem um ao outro 
local b = require("b")
return { nome = "a" }

local a = require("a")
return { nome = "b" }

$ lua -e 'require("a")'
lua: error loading module 'a' from file './a.lua':
	C stack overflow
stack traceback:
	[C]: in ?
	[C]: in global 'require'
	./b.lua:1: in main chunk
	[C]: in global 'require'
	./a.lua:1: in main chunk
	[C]: in global 'require'
	./b.lua:1: in main chunk
	...	(skipping 370 levels)                « o rastro segue por dezenas de linhas
	[C]: in global 'require'
	(command line):1: in main chunk
	[C]: in ?

O a pede o b, que pede o a, que ainda não terminou (não chegou no return, então não está no caderninho package.loaded), e o require tenta carregá-lo de novo, que pede o b… até a pilha de chamadas estourar: C stack overflow ("estouro da pilha do C"). O rastro mostra o padrão b.lua:1, a.lua:1, b.lua:1 se repetindo, e pula 370 levels (370 níveis) para não encher a tela; no terminal, o rastro inteiro ainda aparece duas vezes. Como consertar: reorganize: tire o que os dois precisam para um terceiro módulo, que nenhum dos dois pede de volta.

O arquivo com o nome de uma biblioteca padrão 
print("meu math.lua!")
return { dobro = function (x) return 2 * x end }

$ lua -e 'local m = require("math") print(m.dobro, m.pi)'
nil	3.1415926535897931

Não apareceu o meu math.lua!, e m.dobro é nil: o require nem olhou o arquivo, porque math já estava no caderninho package.loaded (é a biblioteca padrão). Ele devolveu o math de sempre (com o pi). Nenhuma mensagem de erro: o seu arquivo simplesmente é ignorado. Como consertar: nunca dê ao seu módulo o nome de uma biblioteca que já vem com o Lua (string, math, table, io, os, utf8, coroutine, debug, package). Chame de matematica.lua, contas.lua…

Missão final: o módulo das notas

Missão: a professora da Ana quer um módulo notas. Na aba notas.lua, crie duas funções públicas: M.media(lista), que devolve a média dos números da lista, e M.situacao(media), que devolve "aprovada" se a média for 7 ou mais, e "reprovada" se não for. Dica: some com um for e divida por #lista. O main.lua já está pronto.

local notas = require("notas")
local media = notas.media({7, 8, 6.5, 8.5})
print("Média: " .. media)
print("Situação: " .. notas.situacao(media))

local M = {}

-- crie aqui M.media(lista) e M.situacao(media)

return M

local M = {}

local function somar(lista)
  local total = 0
  for _, n in ipairs(lista) do
    total = total + n
  end
  return total
end

function M.media(lista)
  return somar(lista) / #lista
end

function M.situacao(media)
  if media >= 7 then
    return "aprovada"
  end
  return "reprovada"
end

return M

A solução tem uma função privada, somar, que só o módulo usa: um bom exemplo do "fundo falso". As notas 7, 8, 6,5 e 8,5 somam 30, e 30 / 4 = 7,5.

Resumo

  • A receita: local M = {}, as funções públicas como function M.nome(), e return M na última linha.
  • O que é local e fica fora da tabela é privado: só o arquivo do módulo enxerga. Deixe público só o necessário.
  • Num módulo, toda função é M.algo ou local: sem os dois, ela vaza como global.
  • Como o módulo roda uma vez só, as variáveis local dele duram o programa inteiro e são compartilhadas por todos que fazem require.
  • Pastas: require("loja.estoque") carrega loja/estoque.lua; require("relatorio") também acha relatorio/init.lua.
  • Funções de módulo se chamam com ponto (contas.somar), não com dois-pontos. Não dê ao módulo o nome de uma biblioteca padrão, e não faça dois módulos pedirem um ao outro.
