Lua LuaRocks

O Lua vem com poucas bibliotecas: string, math, table, io, os e mais algumas. Para mostrar tabelas bonitas, ler JSON, mexer em pastas ou falar com a internet, outras pessoas já escreveram módulos prontos, e eles moram num site chamado luarocks.org. O programa que baixa e instala esses módulos se chama LuaRocks. Cada pacote de lá é uma rock ("pedra", em inglês: um trocadilho com "Lua", que é a lua do céu).

Você vai aprender
  • O que é o LuaRocks e o que é uma rock.
  • A realidade do Ubuntu 26.04: por que o luarocks do apt não serve para o Lua 5.5, e o efeito colateral dele (o comando lua vira o 5.1).
  • Como instalar o LuaRocks oficial (3.13) na sua pasta pessoal, passo a passo, com as saídas reais.
  • luarocks --local install inspect, e os comandos list, show, remove e search.
  • Uma rock escrita em C (luafilesystem), que é compilada na hora.
  • Como o require acha o que o LuaRocks instalou: luarocks path e o ~/.bashrc.

Tudo nesta aula rodou no terminal da máquina da Ana, um Ubuntu 26.04 com o Lua 5.5, em 18/10/2026, com internet. As versões das rocks podem ter mudado desde então. O editor do guia não instala rocks: ele roda só o Lua e os arquivos das abas (seção 7).

A ideia: a loja de aplicativos do Lua

No celular, a Ana não escreve um aplicativo de mapas: ela abre a loja, procura "mapas", toca em "instalar", e pronto. O LuaRocks é a loja de aplicativos do Lua, só que para módulos:

No celularNo Lua
A loja (Play Store)O site luarocks.org
O aplicativo da loja, que baixa e instalaO comando luarocks
Um aplicativoUma rock: um ou mais módulos (veja Módulos e require)
"Este app precisa do Android 12""Esta rock precisa do Lua >= 5.1"
Abrir o applocal inspect = require("inspect")

Depois de instalada, uma rock é só um módulo numa pasta. O trabalho do LuaRocks é baixar, às vezes compilar, e guardar os arquivos numa pasta onde o require consiga achar (lembra do package.path?).

1. A pegadinha do Ubuntu 26.04: o luarocks do apt

O caminho óbvio seria sudo apt install luarocks. No Ubuntu 26.04, não faça isso se você quer usar o Lua 5.5. O pacote do Ubuntu é o LuaRocks 3.8.0, mais antigo que o Lua 5.5, e ele não sabe trabalhar com o 5.5. O lab tem esse pacote instalado; veja o que acontece:

$ luarocks --version

LuaRocks main command-line interface

$ luarocks config lua_version
5.1
$ luarocks install inspect

Error: /usr/local/lib/luarocks/rocks-5.1 does not exist and your user does not have write permissions in /usr/local/lib
-- you may want to run as a privileged user or use your local tree with --local.
$ luarocks --lua-version 5.5 --local install inspect
Installing https://luarocks.org/inspect-3.1.3-0.rockspec

Error: Failed finding Lua header files. You may need to install them or configure LUA_INCDIR.
luarocks config lua_version → 5.1
Por padrão, ele trabalha para o Lua 5.1, não para o 5.5. Tudo o que instalar vai para as pastas do 5.1, que o require do 5.5 nunca olha.
Error: /usr/local/lib/luarocks/rocks-5.1 does not exist…
"A pasta não existe e o seu usuário não tem permissão de escrita em /usr/local/lib. Você pode rodar como usuário privilegiado ou usar a sua árvore local com --local." Além de ser para o 5.1, ele quer instalar numa pasta do sistema.
--lua-version 5.5 … Failed finding Lua header files
Pedindo o 5.5 explicitamente, ele "não acha os arquivos de cabeçalho do Lua". Mesmo apontando o caminho certo deles, o 3.8 continua falhando, porque o jeito de o Lua 5.5 escrever o número da versão nesses arquivos é novo e ele não entende. Não há saída com esta versão.
O efeito colateral: o comando lua vira o 5.1

O pacote luarocks do Ubuntu traz junto o lua5.1. E o Ubuntu escolhe qual programa responde pelo comando lua por prioridade, com o sistema update-alternatives: o 5.1 tem prioridade 110, o 5.5 tem 20. Num Ubuntu 26.04 que só tinha o lua5.5, o sudo apt install luarocks escreveu, no meio das mensagens:

update-alternatives: usando /usr/bin/lua5.1 para fornecer /usr/bin/lua (lua-interpreter) no modo automático

e, depois disso, lua -v respondeu Lua 5.1.5 Copyright (C) 1994-2012 Lua.org, PUC-Rio. Os seus programas passam a rodar no 5.1 sem você perceber (e o //, o math.type, o <const> deixam de funcionar). No lab dá para ver a briga das prioridades:

  secundário lua-manual: /usr/share/man/man1/lua5.1.1.gz

  secundário lua-manual: /usr/share/man/man1/lua5.4.1.gz

"A melhor versão é o 5.1" (pela prioridade), mas o link aponta para o 5.5, porque no lab ele foi fixado à mão ("modo manual"). Se isso aconteceu com você, o conserto é fixar o 5.5 de volta (o mesmo para o luac):

$ sudo update-alternatives --set lua-interpreter /usr/bin/lua5.5
$ sudo update-alternatives --set lua-compiler /usr/bin/luac5.5

(Esses dois comandos não rodaram no lab, que não tem sudo; confira depois com lua -v.) Ou desinstale o pacote: sudo apt remove luarocks.

E as bibliotecas que o Ubuntu oferece pelo apt (lua-inspect, lua-dkjson, lua-filesystem…)? Também não servem: no Ubuntu 26.04 elas são empacotadas só para o 5.1, o 5.3 e o 5.4, e vão para pastas como /usr/share/lua/5.4. Nenhuma vai para /usr/share/lua/5.5. Para o 5.5, o caminho é o LuaRocks oficial.

2. Instalando o LuaRocks oficial na sua pasta

O site do LuaRocks distribui o código-fonte da versão mais nova (a 3.13.0, em outubro de 2026). Você vai baixar, configurar para o Lua 5.5 e instalar dentro da sua pasta pessoal, em ~/.local. Assim não precisa de sudo e não mexe em nada do sistema.

O que precisa estar instalado antes

Para compilar, o LuaRocks precisa dos cabeçalhos do Lua 5.5 (o pacote liblua5.5-dev, que você talvez já tenha instalado na aula Instalar o Lua), do compilador de C (gcc), do make, do unzip e do wget. São os que o lab tem:

$ sudo apt install liblua5.5-dev gcc make unzip wget

(Esta linha não rodou no lab, que não tem sudo; os pacotes já estavam lá.) O make e o gcc também servem para as rocks escritas em C, como a da seção 4.

Por que ~/.local/bin/luarocks e não só luarocks?

Até você configurar o terminal (seção 5), o comando luarocks sozinho ainda pode ser o antigo, do apt (se ele estiver instalado), ou nem existir. O caminho completo garante que é o novo. Num Ubuntu, a pasta ~/.local/bin entra no PATH sozinha a partir do próximo login, se ela existir; até lá, use o caminho completo.

4. Como o require acha as rocks: luarocks path

O próprio LuaRocks sabe quais pastas precisam entrar na lista. O comando luarocks path escreve os comandos que ajustam o terminal:

$ ~/.local/bin/luarocks path
export LUA_PATH='/home/ana/.local/share/lua/5.5/?.lua;/usr/local/share/lua/5.5/?.lua;/usr/local/share/lua/5.5/?/init.lua;/usr/local/lib/lua/5.5/?.lua;/usr/local/lib/lua/5.5/?/init.lua;/usr/share/lua/5.5/?.lua;/usr/share/lua/5.5/?/init.lua;./?.lua;./?/init.lua;/home/ana/.luarocks/share/lua/5.5/?.lua;/home/ana/.luarocks/share/lua/5.5/?/init.lua;/home/ana/.local/share/lua/5.5/?/init.lua'
export LUA_CPATH='/usr/local/lib/lua/5.5/?.so;/usr/lib/x86_64-linux-gnu/lua/5.5/?.so;/usr/lib/lua/5.5/?.so;/usr/local/lib/lua/5.5/loadall.so;./?.so;/home/ana/.luarocks/lib/lua/5.5/?.so;/home/ana/.local/lib/lua/5.5/?.so'
export PATH='/home/ana/.luarocks/bin:/home/ana/.local/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin'

São três export (veja a seção 3 de package.path): a LUA_PATH é a lista padrão mais as pastas ~/.luarocks/share/lua/5.5 (e as do ~/.local); a LUA_CPATH faz o mesmo para as rocks em C; o PATH põe ~/.local/bin (onde está o luarocks novo) e ~/.luarocks/bin (onde as rocks põem os seus comandos) na frente. Ele só mostrou os comandos. Para rodá-los no terminal atual, use eval ("avaliar"):

$ eval "$(~/.local/bin/luarocks path)"

Não aparece nada, mas agora o terminal está ajustado. Teste com um programa:

local inspect = require("inspect")
local cesta = {"pão", "leite", precos = {pao = 0.75, leite = 5.49}}
print(inspect(cesta))
print(package.searchpath("inspect", package.path))

$ lua ver.lua
{ "pão", "leite",
  precos = {
    leite = 5.49,
    pao = 0.75
  }
}
/home/ana/.luarocks/share/lua/5.5/inspect.lua

O inspect mostrou a tabela inteira, até a tabela de dentro (e com as chaves em ordem alfabética, então a saída é sempre a mesma). E o package.searchpath confirma de onde o módulo veio: da árvore local do LuaRocks.

Para valer em todo terminal: o ~/.bashrc

O eval vale só para aquele terminal; fechou, perdeu. Para todo terminal novo já sair ajustado, ponha a mesma linha no fim do arquivo ~/.bashrc, que o bash lê sempre que abre:

$ echo 'eval "$(~/.local/bin/luarocks path)"' >> ~/.bashrc
$ tail -1 ~/.bashrc
eval "$(~/.local/bin/luarocks path)"

O >> acrescenta no fim do arquivo (um > só apagaria o que já estava lá: cuidado!). Num terminal novo, o comando luarocks sozinho já é o 3.13 (porque o ~/.local/bin entrou na frente do /usr/bin no PATH), e o require acha as rocks. No lab, abrindo um bash novo:

$ bash -i -c 'luarocks --version | head -1; lua -e "print(require([[lfs]]).currentdir())"' 2>/dev/null
/home/ana/.local/bin/luarocks 3.13.0
/home/ana

(O lfs é a rock da próxima seção.) Daqui em diante, esta aula escreve só luarocks, já que o terminal está ajustado.

5. Uma rock escrita em C: luafilesystem

Algumas rocks não são arquivos .lua: são escritas em C, porque fazem coisas que o Lua puro não consegue (listar as pastas, por exemplo). O LuaRocks baixa o código e compila na hora, com o gcc. A luafilesystem (o módulo se chama lfs) é a mais usada para pastas e arquivos:

$ luarocks --local install luafilesystem
Installing https://luarocks.org/luafilesystem-1.9.0-1.src.rock


luafilesystem 1.9.0-1 depends on lua >= 5.1 (5.5-1 provided by VM: success)
gcc -O2 -fPIC -I/usr/include/lua5.5 -c src/lfs.c -o src/lfs.o
gcc  -shared -o /tmp/luarocks_build-luafilesystem-1.9.0-1-234566/lfs.so src/lfs.o
luafilesystem 1.9.0-1 is now installed in /home/ana/.luarocks (license: MIT/X11)

$ lua -e 'local lfs = require("lfs") print(lfs.currentdir()) print(package.searchpath("lfs", package.cpath))'
/home/ana
/home/ana/.luarocks/lib/lua/5.5/lfs.so

As duas linhas do gcc são a compilação: a primeira transforma o lfs.c em código de máquina usando os cabeçalhos do 5.5 (-I/usr/include/lua5.5), a segunda empacota tudo num lfs.so. O resultado foi para ~/.luarocks/lib/lua/5.5/lfs.so, e é o package.cpath (a lista dos módulos em C) que o acha. O lfs.currentdir() mostrou a pasta atual. Se o gcc não estiver instalado, é nesta hora que a instalação falha.

7. No editor do guia

A caixa "Experimente" roda o Lua 5.5 no navegador, com os arquivos das abas, e mais nada: não há internet para o LuaRocks, não há gcc, e nenhuma rock vem instalada. Lá, require("inspect") dá module 'inspect' not found, com a mesma lista de pastas do terminal. Para usar uma rock, instale o Lua e o LuaRocks no seu computador (aula Instalar o Lua).

Uma coisa útil que dá para praticar no editor: fazer o programa continuar funcionando quando uma rock não está instalada, com o pcall. O pcall(require, "inspect") tenta carregar e, em vez de parar o programa, devolve false e a mensagem de erro:

Missão: no editor, o inspect não existe e o programa para na linha 1. Use local ok, inspect = pcall(require, "inspect") e, se ok for falso, mostre inspect não está instalado e a lista com table.concat; se for verdadeiro, use o inspect.

local inspect = require("inspect")
local compras = {"pão", "leite", "café"}
print(inspect(compras))

local ok, inspect = pcall(require, "inspect")
local compras = {"pão", "leite", "café"}
if ok then
  print(inspect(compras))
else
  print("inspect não está instalado")
  print(table.concat(compras, ", "))
end

Quando dá errado

Instalou, mas o require não acha

É o caso da seção 3: a lista do module 'inspect' not found não tem nenhuma linha com .luarocks. Faltou o eval "$(~/.local/bin/luarocks path)" nesse terminal (ou no ~/.bashrc). Confira também se você instalou com o LuaRocks do 5.5: luarocks config lua_version tem de dizer 5.5; uma rock instalada para o 5.1 vai para rocks-5.1 e o 5.5 nunca a vê.

O nome da rock está errado 
$ luarocks --local install inspekt

Error: No results matching query were found for Lua 5.5.
To check if it is available for other Lua versions, use --check-lua-versions.

"Nenhum resultado para a busca, para o Lua 5.5. Para ver se existe para outras versões, use --check-lua-versions." Ou o nome está errado (aqui, inspekt), ou a rock existe só para versões antigas do Lua. Use luarocks search para conferir o nome. Atenção: o nome da rock e o nome do módulo podem ser diferentes. Você instala luafilesystem e faz require("lfs"); o luarocks show mostra os módulos.

Usou o luarocks do apt sem perceber

Se aparecer Error: /usr/local/lib/luarocks/rocks-5.1 does not exist… ou Failed finding Lua header files, o luarocks que respondeu é o 3.8 do Ubuntu (confira com luarocks --version: o caminho é /usr/bin/luarocks). Use ~/.local/bin/luarocks, ou ajuste o terminal com o eval da seção 4.

Uma rock em C sem o gcc

Rocks como a luafilesystem precisam compilar. Sem o gcc (ou sem os cabeçalhos do liblua5.5-dev), a instalação para no meio, numa das linhas do gcc. Instale os pacotes da seção 2 e tente de novo. (Este caso não foi reproduzido no lab, que tem o gcc.)

Missão final: faça o que o luarocks path faz

Missão: imagine que o LuaRocks instalou uma rock com o módulo saudacao na árvore local (veja a aba: o arquivo está em .luarocks/share/lua/5.5/, dentro da pasta da Ana). O require não acha, porque essa pasta não está no package.path. No começo do main.lua, acrescente ao package.path o modelo os.getenv("HOME") .. "/.luarocks/share/lua/5.5/?.lua" (lembre do ; que separa os modelos).

local saudacao = require("saudacao")
print(saudacao.ola("Ana"))

local M = {}
function M.ola(nome)
  return "Olá, " .. nome .. "!"
end
return M

package.path = package.path .. ";" .. os.getenv("HOME") .. "/.luarocks/share/lua/5.5/?.lua"
local saudacao = require("saudacao")
print(saudacao.ola("Ana"))

É exatamente o que a LUA_PATH do luarocks path faz: põe /home/ana/.luarocks/share/lua/5.5/?.lua na lista. No terminal, deixe o eval fazer isso por você em vez de mexer no package.path do programa.

Resumo

  • O LuaRocks instala rocks (módulos de outras pessoas) do site luarocks.org.
  • No Ubuntu 26.04, o luarocks do apt (3.8) trabalha para o Lua 5.1, não instala para o 5.5, e faz o comando lua virar o 5.1. As bibliotecas lua-* do apt também não são para o 5.5.
  • O LuaRocks oficial (3.13) instalado em ~/.local funciona com o 5.5: ./configure --prefix=$HOME/.local --lua-version=5.5, make, make install.
  • luarocks --local install NOME instala em ~/.luarocks; list, show, remove e search fazem o resto.
  • O require só acha as rocks depois do eval "$(~/.local/bin/luarocks path)"; ponha essa linha no ~/.bashrc.
  • O editor do guia não instala rocks: lá, use pcall(require, "nome") para o programa sobreviver sem elas.
