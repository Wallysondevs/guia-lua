Lua Parâmetros e Argumentos

Na aula Funções, a função bom_dia() sempre dizia a mesma coisa: "Bom dia, Ana!". Mas a padaria tem muitos clientes. Seria ruim escrever uma função para cada um. Nesta aula a função passa a receber informações de quem a chama: o nome do cliente, o preço, a quantidade. Assim, uma função só serve para todos os casos.

Você vai aprender
  • O que é um parâmetro e o que é um argumento (e por que são coisas diferentes).
  • A criar funções com um ou vários parâmetros, e por que a ordem importa.
  • O que o Lua faz quando você manda argumentos a mais (descarta) ou a menos (viram nil).
  • A dar um valor padrão com x = x or 10, e a armadilha desse truque com false.
  • Que o parâmetro é uma variável local da função.
  • A mandar uma tabela como argumento, para quando há muitas informações.
  • Os erros reais: attempt to concatenate a nil value (local 'nome'), a vírgula esquecida e o tipo errado.

A ideia: a ficha com espaços em branco

Na padaria, a Ana tem um bloquinho de pedidos já impresso: "Pedido de ____ unidades de ____ para ____". Cada folha é igual, mas os espaços em branco mudam: numa, ela escreve "10, pão francês, Bia"; na outra, "1, bolo de milho, Seu Joaquim".

Uma função com parâmetros é esse bloquinho:

No bloquinhoNo LuaOnde aparece
O espaço em branco impresso na folhaParâmetroNa definição: local function saudar(nome)
O que a Ana escreve no espaçoArgumentoNa chamada: saudar("Ana")

Muita gente usa as duas palavras como se fossem a mesma coisa, e tudo bem na conversa. Mas saber a diferença ajuda a ler as mensagens de erro e a documentação.

1. Uma função com um parâmetro

A função saudar recebe o nome de quem vai ser cumprimentado:

local function saudar(nome)
  print("Bom dia, " .. nome .. "!")
end

saudar("Ana")
saudar("Bia")
saudar("Seu Joaquim")

$ lua saudar.lua
Bom dia, Ana!
Bom dia, Bia!
Bom dia, Seu Joaquim!
(nome)
Na definição, dentro dos parênteses, fica o parâmetro: um nome de variável que você escolhe. Ele ainda não tem valor; é o espaço em branco da ficha.
"Bom dia, " .. nome .. "!"
Dentro do corpo, nome é usado como qualquer variável. O .. junta os textos (aula Juntando Textos).
saudar("Ana")
Na chamada, dentro dos parênteses, vai o argumento: o valor de verdade. O Lua faz nome = "Ana" e então executa o corpo.

Cada chamada preenche a ficha de novo: na primeira, nome vale "Ana"; na segunda, "Bia"; na terceira, "Seu Joaquim". Uma função, três resultados diferentes.

O argumento pode ser qualquer valor

Não precisa ser um texto escrito ali na hora. Pode ser uma variável, ou uma conta, ou um texto montado com ..: o Lua calcula o valor antes de entrar na função.

local function saudar(nome)
  print("Bom dia, " .. nome .. "!")
end

local cliente = "Carla"
saudar(cliente)
saudar("Dona " .. cliente)

$ lua variavel_arg.lua
Bom dia, Carla!
Bom dia, Dona Carla!

Repare que a variável de fora se chama cliente e o parâmetro se chama nome. Os nomes não precisam ser iguais: o que passa para a função é o valor ("Carla"), não o nome da variável.

Missão: crie uma função parabens com um parâmetro nome, que mostre Parabéns, NOME!. Chame-a com "Ana" e depois com "Bia".

local function saudar(nome)
  print("Bom dia, " .. nome .. "!")
end

saudar("Ana")

local function parabens(nome)
  print("Parabéns, " .. nome .. "!")
end

parabens("Ana")
parabens("Bia")

2. Vários parâmetros

Uma função pode receber quantas informações precisar. Os parâmetros são separados por vírgula, e os argumentos também:

local function item(produto, preco)
  print(produto .. ": R$ " .. string.format("%.2f", preco))
end

item("Pão francês", 0.80)
item("Leite", 5.50)
item("Bolo", 18)

$ lua dois.lua
Pão francês: R$ 0.80
Leite: R$ 5.50
Bolo: R$ 18.00

(O string.format("%.2f", preco) escreve o número com duas casas depois do ponto; está na aula string.format.)

Quem vai para onde: a ordem

O Lua liga os argumentos aos parâmetros pela posição: o 1º argumento vai para o 1º parâmetro, o 2º para o 2º, e assim por diante. Ele não olha o significado:

local function apresentar(nome, idade)
  print(nome .. " tem " .. idade .. " anos")
end

apresentar("Ana", 30)
apresentar(30, "Ana")

$ lua ordem_args.lua
Ana tem 30 anos
30 tem Ana anos

Na segunda chamada, nome recebeu 30 e idade recebeu "Ana". O Lua não reclamou, porque .. aceita número e texto. O resultado só ficou sem sentido. Quem confere a ordem é você.

3. Argumentos a mais e a menos

E se a quantidade de argumentos não bater com a de parâmetros? Muitas linguagens dão erro na hora. O Lua não: ele ajusta sozinho.

local function mostrar(a, b, c)
  print("a =", a, "b =", b, "c =", c)
end

mostrar(1, 2, 3)
mostrar(1, 2)
mostrar(1)
mostrar()
mostrar(1, 2, 3, 4, 5)

$ lua falta.lua
a =	1	b =	2	c =	3
a =	1	b =	2	c =	nil
a =	1	b =	nil	c =	nil
a =	nil	b =	nil	c =	nil
a =	1	b =	2	c =	3

Argumentos a maisOs que não têm parâmetro são descartados, sem avisomostrar(1, 2, 3, 4, 5): o 4 e o 5 somem
Nenhum argumentoTodos os parâmetros valem nilmostrar()

É como a ficha da padaria: se o cliente não disse o nome, o espaço fica em branco (nil); se ele falou mais coisas do que a ficha tem espaço, o que sobrou não é anotado.

Isso é cômodo, mas tem um preço: o erro não aparece na chamada, e sim mais tarde, quando a função tenta usar o nil:

local function saudar(nome)
  print("Bom dia, " .. nome .. "!")
end

4. Valor padrão: x = x or 10

Às vezes um argumento é opcional: se a pessoa não mandar, a função usa um valor de costume, o valor padrão. O Lua não tem um jeito especial de escrever isso na definição. Usa-se um truque com o or (aula and, or e not):

local function saudar(nome)
  nome = nome or "cliente"
  print("Bom dia, " .. nome .. "!")
end

saudar("Ana")
saudar()

$ lua padrao.lua
Bom dia, Ana!
Bom dia, cliente!
nome or "cliente"
O or devolve o primeiro valor se ele for "verdadeiro"; senão, devolve o segundo. Como nil conta como falso, nil or "cliente" dá "cliente", e "Ana" or "cliente" dá "Ana".
nome = …
O resultado é guardado de volta no próprio parâmetro. Daí para baixo, nome sempre tem um texto.

Com números funciona igual. E aqui o Lua tem uma diferença importante de outras linguagens: o 0 conta como verdadeiro. Só nil e false são falsos (aula Booleanos). Então, mandar 0 é diferente de não mandar nada:

local function repetir(texto, vezes)
  vezes = vezes or 3
  print(string.rep(texto, vezes, " "))
end

repetir("oi", 2)
repetir("oi")
repetir("oi", 0)

$ lua padrao_num.lua
oi oi
oi oi oi
                                                   « linha vazia: 0 vezes

repetir("oi") usou o padrão 3. repetir("oi", 0) respeitou o 0 e mostrou uma linha vazia, porque 0 or 3 dá 0. (O terceiro argumento do string.rep, " ", é o que vai entre as repetições.)

A armadilha: quando o argumento pode ser false

O truque do or trata nil e false do mesmo jeito. Na maioria das vezes isso não importa. Mas, se o parâmetro é um "sim ou não" e o padrão é true, a pessoa nunca mais consegue dizer "não":

local function aviso(texto, com_moldura)
  com_moldura = com_moldura or true
  if com_moldura then
    print("*** " .. texto .. " ***")
  else
    print(texto)
  end
end

aviso("Promoção de pão")
aviso("Promoção de pão", true)
aviso("Promoção de pão", false)

$ lua armadilha.lua
*** Promoção de pão ***
*** Promoção de pão ***
*** Promoção de pão ***                            « pediu false e veio com moldura!

Na terceira chamada, com_moldura chegou valendo false. Mas false or true dá true: o or viu um valor falso e pegou o segundo. O "não" da Ana foi trocado por "sim", sem nenhum erro.

O conserto: perguntar só pelo nil, com == nil. Assim, false passa intacto:

local function aviso(texto, com_moldura)
  if com_moldura == nil then
    com_moldura = true
  end
  if com_moldura then
    print("*** " .. texto .. " ***")
  else
    print(texto)
  end
end

aviso("Promoção de pão")
aviso("Promoção de pão", true)
aviso("Promoção de pão", false)

$ lua armadilha_certo.lua
*** Promoção de pão ***
*** Promoção de pão ***
Promoção de pão
Regra prática

x = x or PADRAO é seguro quando x é um texto, um número ou uma tabela. Quando x pode ser false de propósito, use if x == nil then x = PADRAO end.

Missão: a última chamada pede o aviso sem moldura, mas ele sai com moldura. Conserte o valor padrão para que a última linha da saída seja só Aviso: forno desligado.

  com_moldura = com_moldura or true

  else

  end
end

5. O parâmetro é uma variável local

Todo parâmetro funciona como uma variável local criada no começo da função: ele só existe dentro dela. Fora, o nome não significa nada:

local function saudar(nome)
  print("Bom dia, " .. nome .. "!")
end

saudar("Ana")
print(nome)

$ lua param_local.lua
Bom dia, Ana!
nil

O print(nome) da última linha procurou uma variável nome fora da função, não achou, e mostrou nil. O nome do parâmetro acabou junto com a chamada.

Mudar o parâmetro não muda a variável de fora

O argumento é copiado para o parâmetro. Se a função muda o parâmetro, muda só a cópia:

local function dobrar(n)
  n = n * 2
  print("dentro da função:", n)
end

local estoque = 10
dobrar(estoque)
print("fora da função:  ", estoque)

$ lua copia.lua
dentro da função:	20
fora da função:  	10

O estoque continuou 10. Para a função "devolver" o resultado, existe o return, assunto da próxima aula (return).

Com tabelas é diferente

Uma tabela não é copiada: a função recebe a mesma tabela, e o que ela muda lá dentro aparece fora:

local function adicionar(lista, item)
  lista[#lista + 1] = item
end

local compras = {"leite"}
adicionar(compras, "pão")
adicionar(compras, "café")
print(#compras, compras[1], compras[2], compras[3])

$ lua tabela_param.lua
3	leite	pão	café

Isso é útil (a função arruma a lista para você) e, às vezes, uma surpresa. A explicação completa está em Tabelas São Referências.

6. Muitas informações: uma tabela como argumento

Com quatro, cinco parâmetros, fica difícil lembrar a ordem (e a seção 2 mostrou o que acontece quando a ordem troca). Uma saída comum no Lua é mandar uma tabela só, com campos de nome:

local function cadastrar(dados)
  local nome = dados.nome or "sem nome"
  local idade = dados.idade or 0
  local cidade = dados.cidade or "Recife"
  print(nome .. ", " .. idade .. " anos, " .. cidade)
end

cadastrar({nome = "Ana", idade = 30})
cadastrar{idade = 25, nome = "Bia", cidade = "Natal"}
cadastrar{}

$ lua nomeados.lua
Ana, 30 anos, Recife
Bia, 25 anos, Natal
sem nome, 0 anos, Recife
cadastrar({nome = "Ana", idade = 30})
Um argumento só: uma tabela com os campos nome e idade (aula Tabelas como Dicionários). Os campos podem vir em qualquer ordem.
dados.nome or "sem nome"
O mesmo truque do valor padrão, agora campo por campo. A cidade que não veio fica "Recife".
cadastrar{…}
Quando o único argumento é uma tabela escrita ali na hora, o Lua deixa tirar os parênteses: cadastrar{…} é o mesmo que cadastrar({…}).

O mesmo atalho vale quando o único argumento é um texto entre aspas:

print "Olá, Ana!"
local function saudar(nome)
  print("Bom dia, " .. nome .. "!")
end
saudar "Bia"

$ lua texto_sem_parenteses.lua
Olá, Ana!
Bom dia, Bia!

Você vai ver essa forma em código dos outros (por exemplo, require "modulo"). Neste guia, fora do f{…} com tabela, usamos sempre os parênteses: é mais claro para quem está começando, e só funciona com um argumento, que seja um texto ou uma tabela escritos ali.

Quando dá errado

Faltou um argumento numa conta 
local function total(preco, quantidade)
  print("Total: " .. preco * quantidade)
end

total(2.5, 4)
total(2.5)

$ lua falta_conta.lua
Total: 10.0
lua: falta_conta.lua:2: attempt to perform arithmetic on a nil value (local 'quantidade')
stack traceback:
	falta_conta.lua:2: in local 'total'
	falta_conta.lua:6: in main chunk
	[C]: in ?

A primeira chamada funcionou. A segunda esqueceu a quantidade, que virou nil. attempt to perform arithmetic on a nil value (local 'quantidade'): "tentativa de fazer conta com um valor nil (a variável local quantidade)". O rastro aponta a linha 6 como a chamada culpada. Como consertar: mande os dois argumentos, total(2.5, 1), ou dê um padrão: quantidade = quantidade or 1.

Esquecer a vírgula entre os parâmetros 
local function item(produto preco)
  print(produto, preco)
end

$ lua virgula.lua
lua: virgula.lua:1: ')' expected near 'preco'

')' expected near 'preco': "esperava ) perto de preco". Depois de produto, o Lua esperava uma vírgula (mais um parâmetro) ou o ) (fim da lista). Na chamada, o erro é parecido: item("Leite" 5.50) dá ')' expected near '5.50'. Como consertar: item(produto, preco) e item("Leite", 5.50).

Mandar um tipo que a função não espera 
local function dobro(n)
  print(n * 2)
end

dobro(21)
dobro("21")
dobro("vinte")

$ lua tipo.lua
42
42
lua: tipo.lua:2: attempt to mul a 'string' with a 'number'
stack traceback:
	[C]: in metamethod 'mul'
	tipo.lua:2: in local 'dobro'
	tipo.lua:7: in main chunk
	[C]: in ?

O Lua não confere o tipo do argumento na entrada da função. dobro("21") até funcionou, porque o Lua converte um texto que parece número quando ele entra numa conta (aula Conversão). Mas "vinte" não vira número: attempt to mul a 'string' with a 'number' é "tentativa de multiplicar (mul) um texto por um número". A linha [C]: in metamethod 'mul' é o pedaço interno do Lua que tentou a multiplicação; as linhas de baixo, como sempre, mostram que a chamada culpada foi a da linha 7.

Como se proteger: a função pode conferir o tipo com type e parar com uma mensagem clara usando error (aula error: Lançando Erros):

local function dobro(n)
  if type(n) ~= "number" then
    error("dobro: esperava um número, veio " .. type(n), 2)
  end
  print(n * 2)
end

dobro(21)
dobro({})

$ lua checar.lua
42
lua: checar.lua:9: dobro: esperava um número, veio table
stack traceback:
	[C]: in global 'error'
	checar.lua:3: in local 'dobro'
	checar.lua:9: in main chunk
	[C]: in ?

Agora a mensagem fala em português e já aponta a linha 9, a da chamada errada (é o que o 2 no fim do error pede).

Sem erro, mas errado: a ordem trocada e o false engolido

Dois problemas desta aula não dão mensagem nenhuma: argumentos na ordem errada (30 tem Ana anos, seção 2) e o false trocado por true no x = x or true (seção 4). O programa roda e o resultado sai torto. Como evitar: confira a ordem dos parâmetros na definição antes de chamar (ou use a tabela de opções da seção 6), e use == nil nos padrões de "sim ou não".

Missão final: o pedido da padaria

Missão: rode o programa e leia o erro. Depois, faça a quantidade valer 1 quando ela não for mandada, sem mexer nas chamadas. A saída tem de ser 2x café e 1x pão de queijo.

local function pedido(item, quantidade)
  print(quantidade .. "x " .. item)
end

pedido("café", 2)
pedido("pão de queijo")

local function pedido(item, quantidade)
  quantidade = quantidade or 1
  print(quantidade .. "x " .. item)
end

pedido("café", 2)
pedido("pão de queijo")

Resumo

  • Parâmetro é o nome na definição (function saudar(nome)); argumento é o valor na chamada (saudar("Ana")).
  • Vários parâmetros e argumentos vão separados por vírgula e são ligados pela posição.
  • Argumentos a menos viram nil; a mais são descartados. O Lua não avisa: o erro aparece depois, quando o nil é usado (attempt to concatenate a nil value (local 'nome')).
  • Valor padrão: x = x or PADRAO. Se x pode ser false de propósito, use if x == nil then x = PADRAO end. O 0 é verdadeiro no Lua.
  • O parâmetro é uma variável local; mudar um número ou texto lá dentro não muda a variável de fora (tabelas são a exceção).
  • Muitas opções: mande uma tabela, f{nome = "Ana", idade = 30}.
  • Próxima aula: a função devolvendo um resultado com return.
