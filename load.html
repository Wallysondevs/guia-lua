Lua load, loadfile e dofile

Até agora, o código dos seus programas estava escrito no arquivo .lua antes de rodar. Mas o Lua consegue fazer uma coisa curiosa: pegar um texto que só aparece com o programa já rodando (digitado pela pessoa, lido de um arquivo) e rodá-lo como código. Quem faz isso é a função load ("carregar"), com as irmãs loadfile e dofile. É um recurso poderoso, usado para arquivos de configuração e calculadoras, e também perigoso, como você vai ver no fim.

Você vai aprender
  • Como o load transforma um texto numa função, que você chama quando quiser.
  • O que acontece com um erro de sintaxe no texto: o load devolve a mensagem em vez de parar o programa.
  • Uma calculadora que entende contas digitadas, e o nome do pedaço nas mensagens de erro.
  • O ambiente (env): rodar o texto numa tabela separada, para ler um arquivo de configuração sem bagunçar as suas variáveis.
  • loadfile e dofile, e a diferença para o require.
  • O perigo de rodar código que veio de fora, e como diminuir o risco.

As saídas são do Lua 5.5 da máquina da Ana, numa pasta carga. Esta aula usa funções como valores, pcall e o _ENV; se algum desses ainda for novidade, dê uma olhada antes.

A ideia: o bilhete com a receita

A dona da padaria deixa, todo dia, um bilhete com a receita especial do dia. O padeiro não sabe de antemão o que vai estar escrito: ele lê o bilhete e segue as instruções. Duas coisas podem dar errado:

  • o bilhete está ilegível (um erro de escrita): o padeiro nem começa, e avisa "não entendi o bilhete";
  • o bilhete foi trocado por alguém de má-fé, com "jogue fora todo o estoque": um padeiro que segue tudo sem pensar faria isso.

O load é o padeiro: recebe o texto, confere se ele é Lua válido e, se for, devolve uma função pronta para rodar aquelas instruções. As duas coisas que podem dar errado são exatamente as seções 2 e 6 desta aula.

1. load: do texto para a função

local f = load("return 2 + 3")
print(type(f))
print(f())
local g = load("print('Olá do texto!')")
g()
g()

$ lua soma.lua
function
5
Olá do texto!
Olá do texto!
load("return 2 + 3")
O load lê o texto, confere que é Lua válido e devolve uma função com aquele código dentro. Ele não roda nada ainda.
type(f) → function
Confirmado: o que voltou é uma função (o texto virou um "pedaço" de programa; o manual chama de chunk).
f() → 5
Só agora o código roda. O return do texto vira o valor devolvido pela função.
g() duas vezes
A mesma função pode ser chamada quantas vezes você quiser: o texto foi lido uma vez, e roda a cada chamada.

O texto que vai para o load é um programa Lua completo, como um arquivo .lua em miniatura. Por isso, para receber um valor de volta, ele precisa do return: load("2 + 3") não serve (seção 2).

Passando valores para o pedaço

A função criada pelo load recebe os argumentos nos três pontinhos (...), como um arquivo recebe os da linha de comando:

local f = load("local a, b = ... return a * b")
print(f(6, 7))

$ lua args.lua
42

2. Quando o texto tem erro de sintaxe

Se o texto não for Lua válido, o load não para o programa. Ele devolve nil e, como segundo valor, a mensagem de erro (é o mesmo jeito do io.open):

local f, erro = load("return 2 +")
print(f)
print(erro)
local g, erro2 = load("return 2 +", "=calculadora")
print(erro2)

$ lua sintaxe.lua
nil
[string "return 2 +"]:1: unexpected symbol near <eof>
calculadora:1: unexpected symbol near <eof>
nil
Não deu para criar a função.
[string "return 2 +"]:1:
De onde veio o erro. Num arquivo, aqui estaria o nome dele (main.lua:1:); para um texto, o Lua mostra o começo do próprio texto entre [string "…"], e a linha (1).
unexpected symbol near <eof>
"Símbolo inesperado perto do fim do arquivo" (end of file): depois do + o texto acabou, e faltou o segundo número.
load(texto, "=calculadora")
O segundo argumento é o nome do pedaço, que aparece nas mensagens. Começando com =, ele é usado do jeito que está: calculadora:1:. Dê sempre um nome que ajude a achar de onde o texto veio.

Já um erro que só aparece rodando (não de escrita) acontece quando você chama a função, e para o programa como qualquer erro:

local f = load("local t = nil\nreturn t.x")
f()

$ lua runtime.lua
lua: [string "local t = nil..."]:2: attempt to index a nil value (local 't')
stack traceback:
	[string "local t = nil..."]:2: in local 'f'
	runtime.lua:2: in main chunk
	[C]: in ?

O load funcionou (o texto é Lua válido). O erro veio na linha 2 do texto (o \n é a quebra de linha), quando o runtime.lua chamou f() na linha 2 dele. Como o texto tem duas linhas, o Lua mostrou só a primeira, seguida de .... Para não deixar um erro desses parar tudo, chame com pcall(f).

3. Uma calculadora

Juntando as duas coisas: a Ana quer um programa que pergunta uma conta, em texto, e mostra o resultado. Sem o load, ela teria de escrever um programa que entende +, *, parênteses… Com ele, quem entende a conta é o próprio Lua:

io.write("Conta: ")
local conta = io.read()
local f, erro = load("return " .. conta, "=conta")
if not f then
  print("Não entendi: " .. erro)
else
  local ok, resultado = pcall(f)
  if ok then
    print("Resultado: " .. tostring(resultado))
  else
    print("Deu erro: " .. resultado)
  end
end

$ printf '12 * 3 + 4\n' | lua calc.lua
Conta: Resultado: 40
$ printf '(10 + 5) / 2\n' | lua calc.lua
Conta: Resultado: 7.5
$ printf '2 +* 3\n' | lua calc.lua
Conta: Não entendi: conta:1: unexpected symbol near '*'
$ printf 'x + 1\n' | lua calc.lua
Conta: Deu erro: conta:1: attempt to perform arithmetic on a nil value (global 'x')

(O printf … | "digita" a conta para o programa; por isso ela não aparece depois de Conta:. Veja io.read.) Os três caminhos do programa aparecem: a conta certa, o erro de escrita (o load devolveu nil), e o erro rodando (o pcall devolveu false: a variável x não existe).

Missão: a caixa vai "digitar" 7 * 6. O programa responde "Não entendi", porque o texto vai para o load sem o return, e 7 * 6 sozinho não é um comando Lua. Conserte a linha do load para aparecer Resultado: 42.

io.write("Conta: ")
local conta = io.read()
local f, erro = load(conta, "=conta")
if not f then
  print("Não entendi: " .. erro)
else
  print("Resultado: " .. tostring(f()))
end

io.write("Conta: ")
local conta = io.read()
local f, erro = load("return " .. conta, "=conta")
if not f then
  print("Não entendi: " .. erro)
else
  print("Resultado: " .. tostring(f()))
end

4. O ambiente: rodar o texto numa tabela separada

Quando o texto cria variáveis globais (nome = 'Ana'), onde elas vão parar? Normalmente, nas globais do seu programa, misturadas com as suas. O load aceita um quarto argumento, o ambiente (em inglês, environment, o env): uma tabela que faz o papel das variáveis globais para aquele pedaço (é o _ENV dele).

local config = {}
local f = load("nome = 'Ana'\nidade = 30", "=config", "t", config)
f()
print(config.nome, config.idade)
print(nome, idade)

$ lua env.lua
Ana	30
nil	nil
load(texto, "=config", "t", config)
Os quatro argumentos: o texto, o nome do pedaço, o modo e o ambiente.
"t"
O modo: "t" aceita só texto (código Lua escrito). O padrão, "bt", aceita também código já compilado ("binário", feito pelo luac ou pelo string.dump), que é ilegível e pode ser malformado de propósito. Para textos que vêm de fora, use sempre "t".
config
O ambiente: as "globais" que o texto criou (nome, idade) foram parar dentro da tabela config.
print(nome, idade) → nil nil
As globais do programa continuaram limpas.

Isso também quer dizer que o texto só enxerga o que está na tabela. Se ela está vazia, o texto não tem nem o print. É o começo de uma "caixa de areia" (sandbox), na seção 6.

5. loadfile e dofile: o texto está num arquivo

Um uso clássico: um arquivo de configuração escrito em Lua, que uma pessoa sem experiência consegue editar. A lojinha da Ana tem este:

-- configurações da lojinha
nome_loja = "Doces da Ana"
taxa_entrega = 7.5
bairros = {"Centro", "Vila Nova"}

O loadfile é o load para arquivos: lê o arquivo e devolve a função (ou nil e o erro), com os mesmos argumentos de modo e ambiente:

local config = {}
local f, erro = loadfile("config.lua", "t", config)
if not f then
  print("Problema na configuração: " .. erro)
  return
end
f()
print(config.nome_loja, config.taxa_entrega, #config.bairros)
print(nome_loja)

$ lua le_config.lua
Doces da Ana	7.5	2
nil

Os valores da configuração estão em config, e nada vazou para as globais (nome_loja é nil). Os erros também voltam como valor, sem parar o programa:

$ lua -e 'print(loadfile("nada.lua"))'
nil	cannot open nada.lua: No such file or directory
$ printf 'nome_loja = "Doces\ntaxa = 1\n' > ruim.lua
$ lua -e 'print(loadfile("ruim.lua"))'
nil	ruim.lua:1: unfinished string near '"Doces'

"Não consigo abrir nada.lua: arquivo ou pasta não existe"; e, no arquivo com a aspa que não fecha, "texto não terminado perto de "Doces", com o nome do arquivo e a linha. Com esse if not f then, o programa pode avisar a pessoa e continuar com valores padrão.

dofile: carrega e roda de uma vez

O dofile ("faça o arquivo") é o atalho: carrega e já roda, e devolve o que o arquivo devolver. Mas ele não tem ambiente nem modo, e os erros param o programa:

$ lua -e 'dofile("nada.lua")'
lua: cannot open nada.lua: No such file or directory
stack traceback:
	[C]: in global 'dofile'
	(command line):1: in main chunk
	[C]: in ?
$ lua -e 'dofile("ruim.lua")'
lua: ruim.lua:1: unfinished string near '"Doces'
stack traceback:
	[C]: in global 'dofile'
	(command line):1: in main chunk
	[C]: in ?

dofile × require

Os dois rodam um arquivo .lua e devolvem o resultado. A diferença aparece quando você chama duas vezes:

print("rodando dado.lua")
return { faces = 6 }

local a = dofile("dado.lua")
local b = dofile("dado.lua")
print(a.faces, a == b)
local c = require("dado")
local d = require("dado")
print(c.faces, c == d)

$ lua usa_dofile.lua
rodando dado.lua
rodando dado.lua
6	false
rodando dado.lua
6	true

O dofile roda o arquivo toda vez (duas mensagens, e duas tabelas diferentes: a == b é false). O require roda uma vez e guarda em package.loaded (veja Módulos e require). E o dofile recebe o caminho do arquivo ("dado.lua"), enquanto o require recebe o nome do módulo ("dado") e procura pelo package.path.

Missão: o programa lê a configuração da aba config.lua com loadfile, mas esqueceu de passar a tabela config como ambiente. Então os valores foram para as globais, e config.nome_loja é nil: rode e veja o erro. Passe o modo "t" e a tabela config para o loadfile.

local config = {}
local f, erro = loadfile("config.lua")
if not f then

end

print(string.format("Loja: %s (entrega R$ %.2f)", config.nome_loja, config.taxa_entrega))

6. O perigo: rodar código que veio de fora

Volte à calculadora da seção 3. Ela roda qualquer texto que a pessoa digitar, como Lua, com acesso a tudo o que o seu programa pode fazer. A Ana tinha um arquivo de notas na pasta. Alguém "digitou uma conta":

$ printf 'Ana 9\nBia 7\n' > notas.txt
$ ls
calc.lua
env.lua
notas.txt
preso.lua
runtime.lua
sintaxe.lua
soma.lua
$ printf 'os.remove("notas.txt")\n' | lua calc.lua
Conta: Resultado: true
$ ls
calc.lua
env.lua
preso.lua
runtime.lua
sintaxe.lua
soma.lua

O notas.txt sumiu. O "resultado" true é a resposta do os.remove: "apaguei". No lugar disso poderia estar um os.execute com um comando qualquer do sistema (veja os.execute). A regra é simples: nunca rode com load um texto em que você não confia (que veio da internet, de um formulário, de um arquivo que outra pessoa pode mexer) sem proteção.

Diminuindo o risco: um ambiente com pouca coisa

A proteção é o ambiente da seção 4: o texto só enxerga o que você põe na tabela. Um "visitante" que só pode imprimir:

local cofre = { print = print }
local f = load("print('posso imprimir') os.remove('notas.txt')", "=visitante", "t", cofre)
print(pcall(f))

$ lua preso.lua
posso imprimir
false	visitante:1: attempt to index a nil value (global 'os')

O print funcionou (estava no cofre). O os, não: para o visitante, os é uma global que não existe (nil). E o modo "t" impede que alguém mande código binário:

$ lua -e 'print(load(string.dump(function () return 1 end), "=bin", "t"))'
nil	attempt to load a binary chunk (mode is 't')
Ainda não é uma fortaleza

Um ambiente pequeno tira as ferramentas perigosas, mas não impede tudo: um texto com while true do end trava o seu programa para sempre, e um que monta uma tabela gigante pode acabar com a memória. Ponha no cofre só o necessário (nunca o os, o io, o load, o require, o debug, nem o próprio _G, que dá acesso a tudo), e, para coisas sérias, não rode código de estranhos.

No Lua 5.1 e no LuaJIT

O load de lá só aceitava uma função, e para textos existia o loadstring; o ambiente se trocava com setfenv. No 5.5 os dois não existem (print(loadstring, setfenv) mostra nil nil; no lua5.1, os dois são function). Se você encontrar loadstring(texto) num código antigo, troque por load(texto). Veja as diferenças entre versões.

7. Um detalhe: o load também aceita uma função

Em vez do texto inteiro, o load pode receber uma função que entrega o código em pedaços; ele a chama até receber nil. Serve para código que chega aos poucos (de um arquivo grande, da rede):

local partes = {"return ", "10 ", "* ", "4"}
local i = 0
local f = load(function ()
  i = i + 1
  return partes[i]
end)
print(f())

$ lua pedacos.lua
40

Quando dá errado

Chamou o resultado do load sem conferir

O load(texto)() numa linha só é tentador. Mas se o texto tiver erro de sintaxe, o load devolve nil, e chamar nil dá um erro que esconde o motivo verdadeiro:

$ lua -e 'local r = load("return 2 +")()'
lua: (command line):1: attempt to call a nil value
stack traceback:
	(command line):1: in main chunk
	[C]: in ?

"Tentar chamar um valor nil": a mensagem de verdade (unexpected symbol near <eof>) se perdeu. Como consertar: guarde os dois valores e confira: local f, erro = load(texto) e if not f then print(erro) end. Ou use assert(load(texto)), que para o programa mostrando a mensagem certa.

Esqueceu o return no texto 
$ lua -e 'print(load("2 + 3"))'
nil	[string "2 + 3"]:1: unexpected symbol near '2'
$ lua -e 'print(load("return 2 + 3")())'
5

Um texto para o load é um programa, e um programa não pode começar com um número solto ("símbolo inesperado perto de 2"). Para calcular um valor, comece com return. (O modo interativo do lua aceita 2 + 3 sozinho porque ele mesmo põe o return na frente; o load, não. Veja O Modo Interativo.)

O ambiente vazio não tem nem o print 
$ lua -e 'local f = load("print(1)", "=texto", "t", {}) f()'
lua: texto:1: attempt to call a nil value (global 'print')
stack traceback:
	texto:1: in local 'f'
	(command line):1: in main chunk
	[C]: in ?

Com {} como ambiente, o pedaço não enxerga nenhuma global, nem o print, nem o math. Como consertar: ponha no ambiente o que o texto precisa: { print = print, math = math }.

Missão: a calculadora roda qualquer coisa, e a caixa vai "digitar" os.exit(3): o programa fecha na hora, sem mostrar resultado nenhum (o código de saída vira 3). Proteja a calculadora: passe ao load o modo "t" e um ambiente que só tenha a biblioteca de matemática, { math = math }. Aí o visitante recebe um erro em vez de fechar o programa.

io.write("Conta: ")
local conta = io.read()
local f, erro = load("return " .. conta, "=conta")
if not f then
  print("Não entendi: " .. erro)
else
  local ok, resultado = pcall(f)
  if ok then
    print("Resultado: " .. tostring(resultado))
  else
    print("Deu erro: " .. resultado)
  end
end

io.write("Conta: ")
local conta = io.read()
local f, erro = load("return " .. conta, "=conta", "t", { math = math })
if not f then
  print("Não entendi: " .. erro)
else
  local ok, resultado = pcall(f)
  if ok then
    print("Resultado: " .. tostring(resultado))
  else
    print("Deu erro: " .. resultado)
  end
end

Com a proteção, contas como math.sqrt(81) continuam funcionando, e o os deixa de existir para quem digita.

Missão final: a calculadora com memória

Missão: a Ana quer usar nomes nas contas. A caixa vai "digitar" preco * 3. Monte o ambiente da calculadora com a tabela valores (que já tem o preco) e passe-o ao load, junto com o modo "t". Assim o texto enxerga preco como se fosse uma global, e aparece Resultado: 22.5.

local valores = { preco = 7.5, math = math }
io.write("Conta: ")
local conta = io.read()
local f, erro = load("return " .. conta, "=conta")
if not f then
  print("Não entendi: " .. erro)
  return
end
local ok, resultado = pcall(f)
print(ok and "Resultado: " .. tostring(resultado) or "Deu erro: " .. resultado)

local valores = { preco = 7.5, math = math }
io.write("Conta: ")
local conta = io.read()
local f, erro = load("return " .. conta, "=conta", "t", valores)
if not f then
  print("Não entendi: " .. erro)
  return
end
local ok, resultado = pcall(f)
print(ok and "Resultado: " .. tostring(resultado) or "Deu erro: " .. resultado)

Resumo

  • load(texto) transforma um texto com código Lua numa função; o código só roda quando você a chama. Para devolver um valor, o texto precisa de return.
  • Com erro de sintaxe, o load devolve nil e a mensagem, sem parar o programa. Confira sempre (if not f ou assert), e use pcall(f) para os erros que aparecem rodando.
  • O segundo argumento dá nome ao pedaço ("=calculadora"); o terceiro, "t", aceita só texto; o quarto, o ambiente, é a tabela das "globais" do pedaço.
  • loadfile faz o mesmo com um arquivo (ótimo para configurações); dofile carrega e roda de uma vez, e roda de novo a cada chamada, ao contrário do require.
  • Rodar texto de fora é perigoso: ele pode fazer tudo o que o seu programa faz. Use "t" e um ambiente só com o necessário, e não confie cegamente nem assim.
