Projeto Conta Bancária (Classes)

O Lua não tem a palavra class. Mesmo assim, programas em Lua usam classes o tempo todo: elas são montadas com tabelas e metatabelas. Neste projeto a Ana modela as contas do "Banco da Ana", começando com tabelas e funções soltas e chegando, em quatro passos, a uma classe Conta com métodos, erros de verdade e uma Poupanca que herda da conta. O programa não conversa com o teclado: cada versão faz algumas operações e mostra o resultado.

Você vai praticar
  • Guardar dados em tabelas e mexer neles com funções.
  • Criar uma classe com setmetatable e __index (veja Classes com Metatabelas).
  • Escrever e chamar métodos com o dois-pontos (:) e o self.
  • Avisar problemas com error e tratá-los com pcall.
  • Mostrar um objeto com __tostring.
  • Fazer uma classe herdar de outra (veja Herança).

O que vamos construir

A versão final cria uma conta corrente e uma poupança, faz a poupança render e tenta três saques, um deles grande demais e outro com valor negativo. No terminal da Ana:

$ lua banco.lua
Conta de Ana: R$ 300.00
Conta de Ana: R$ 1000.00 (poupança, 1.0% ao mês)
Rendeu R$ 10.00
Conta de Ana: R$ 1010.00 (poupança, 1.0% ao mês)
Saque de 50.00: ok
Recusado por falta de saldo: saldo insuficiente (saldo R$ 960.00)
Recusado (VALOR): valor inválido: -1
Conta de Ana: R$ 960.00 (poupança, 1.0% ao mês)
  1. Tabelas e funções (cada conta é uma tabela; as funções recebem a conta).
  2. Uma classe (setmetatable, __index, : e self).
  3. Erros de verdade, extrato e __tostring (error, pcall).
  4. Herança e erros como tabelas (a Poupanca).

Versão 1 · Tabelas e funções

Uma conta tem um titular e um saldo: uma tabela com dois campos resolve. Para depositar e sacar, funções que recebem a conta como primeiro argumento.

-- Banco da Ana, versão 1: tabelas e funções soltas

local function nova_conta(titular)
  return { titular = titular, saldo = 0 }
end

local function depositar(conta, valor)
  conta.saldo = conta.saldo + valor
end

local function sacar(conta, valor)
  if valor > conta.saldo then
    print(string.format("%s: saldo insuficiente para sacar R$ %.2f", conta.titular, valor))
    return false
  end
  conta.saldo = conta.saldo - valor
  return true
end

local function mostrar(conta)
  print(string.format("%s: R$ %.2f", conta.titular, conta.saldo))
end

local ana = nova_conta("Ana")
local bia = nova_conta("Bia")
depositar(ana, 100)
depositar(bia, 50)
sacar(ana, 30)
sacar(bia, 80)
mostrar(ana)
mostrar(bia)
nova_conta(titular)
Uma "fábrica": devolve uma tabela nova a cada chamada. ana e bia são duas tabelas diferentes, cada uma com o seu saldo.
conta.saldo = conta.saldo + valor
A função mexe na tabela que recebeu. Como tabelas são referências, é a mesma tabela que o programa principal guarda em ana: a mudança aparece lá.
if valor > conta.saldo then … return false
O banco não deixa o saldo ficar negativo: avisa e devolve false ("não deu"), sem mexer no saldo.
%.2f
Dinheiro com duas casas: 70.00.
$ lua banco.lua
Bia: saldo insuficiente para sacar R$ 80.00
Ana: R$ 70.00
Bia: R$ 50.00

Funciona. Mas repare em dois incômodos. Primeiro, as funções (depositar, sacar) estão soltas no programa, e nada diz que elas são "coisas de conta": se o banco tiver também cartões, com outro depositar, os nomes se misturam. Segundo, a regra do saldo depende de todo mundo usar sacar: nada impede uma linha bia.saldo = -1000. A versão 2 resolve o primeiro; o segundo aparece nos desafios do fim.

Missão (versão 1): a função sacar não confere o saldo, e a Bia termina com R$ -30.00. No lugar do comentário, recuse o saque quando valor > conta.saldo: mostre Bia: saldo insuficiente para sacar R$ 80.00 (com o titular e o valor) e devolva false.

Versão 2 · Uma classe

A ideia de uma classe: reunir num lugar só o "molde" de um tipo de coisa (a conta) e tudo o que ela sabe fazer (os métodos: depositar, sacar, mostrar). Cada conta criada a partir do molde é um objeto, com os seus próprios dados. No Lua, o molde é uma tabela comum, Conta, e a ligação entre cada objeto e o molde é feita por uma metatabela.

-- Banco da Ana, versão 2: uma classe

local Conta = {}
Conta.__index = Conta

function Conta.nova(titular)
  local conta = { titular = titular, saldo = 0 }
  return setmetatable(conta, Conta)
end

function Conta:depositar(valor)
  self.saldo = self.saldo + valor
end

function Conta:sacar(valor)
  if valor > self.saldo then
    print(string.format("%s: saldo insuficiente para sacar R$ %.2f", self.titular, valor))
    return false
  end
  self.saldo = self.saldo - valor
  return true
end

function Conta:mostrar()
  print(string.format("%s: R$ %.2f", self.titular, self.saldo))
end

local ana = Conta.nova("Ana")
local bia = Conta.nova("Bia")
ana:depositar(100)
bia:depositar(50)
ana:sacar(30)
bia:sacar(80)
ana:mostrar()
bia:mostrar()
print(getmetatable(ana) == Conta, rawget(ana, "depositar"), ana.depositar == Conta.depositar)
PeçaO que faz
local Conta = {}A classe: uma tabela que vai guardar os métodos. Nome com maiúscula, o costume para classes.
Conta.__index = ContaA peça-chave. Quando alguém procurar um campo que não existe num objeto (por exemplo, ana.depositar), o Lua olha a metatabela do objeto; se ela tiver __index, procura lá. Aqui, o __index da Conta é a própria Conta (veja __index).
setmetatable(conta, Conta)Faz da Conta a metatabela do objeto novo, e devolve o objeto. A partir daí, ana.depositar é achado na Conta.
function Conta:depositar(valor)Um método. O : na definição acrescenta um primeiro parâmetro escondido, self ("o próprio"): é o mesmo que function Conta.depositar(self, valor).
self.saldoO saldo do objeto que chamou: em ana:depositar(100), o self é a ana; em bia:depositar(50), é a bia.
ana:depositar(100)A chamada com : passa o objeto como primeiro argumento: é o mesmo que ana.depositar(ana, 100) (veja Métodos e o Dois-Pontos).
$ lua banco.lua
Bia: saldo insuficiente para sacar R$ 80.00
Ana: R$ 70.00
Bia: R$ 50.00
true	nil	true

O resultado é o mesmo da versão 1, e é isso que se quer: mudou a organização, não o comportamento. A última linha do programa confere três coisas sobre a ana:

getmetatable(ana) == Conta → true
A metatabela da ana é a Conta.
rawget(ana, "depositar") → nil
O rawget olha só dentro da tabela, sem passar pelo __index: a ana não tem um campo depositar. Ela só tem titular e saldo.
ana.depositar == Conta.depositar → true
Mesmo assim, ana.depositar funciona, e é exatamente a função guardada na Conta: o __index foi buscar lá. Mil contas compartilham os mesmos métodos, sem cópias.

Versão 3 · Erros de verdade, extrato e __tostring

Até aqui, um saque grande demais só mostra um aviso e devolve false, e quem chamou pode nem olhar o false. Num banco, uma operação que não pode ser feita deve parar, a menos que alguém trate o problema. É o papel do error: ele interrompe a função com uma mensagem, e o pcall deixa quem chamou decidir o que fazer. A versão 3 também guarda um extrato e ensina o print a mostrar uma conta.

-- Banco da Ana, versão 3: erros de verdade, extrato e __tostring

local Conta = {}
Conta.__index = Conta

function Conta.nova(titular)
  local conta = { titular = titular, saldo = 0, extrato = {} }
  return setmetatable(conta, Conta)
end

-- Confere o valor; o 3 do error aponta para quem chamou depositar/sacar.
local function conferir_valor(valor)
  if type(valor) ~= "number" or valor <= 0 then
    error("valor inválido: " .. tostring(valor), 3)
  end
end

function Conta:depositar(valor)
  conferir_valor(valor)
  self.saldo = self.saldo + valor
  table.insert(self.extrato, string.format("depósito  +%8.2f", valor))
end

function Conta:sacar(valor)
  conferir_valor(valor)
  if valor > self.saldo then
    error(string.format("saldo insuficiente (saldo R$ %.2f, saque R$ %.2f)", self.saldo, valor), 2)
  end
  self.saldo = self.saldo - valor
  table.insert(self.extrato, string.format("saque     -%8.2f", valor))
end

function Conta:transferir(destino, valor)
  self:sacar(valor)
  destino:depositar(valor)
end

function Conta:imprimir_extrato()
  print("Extrato de " .. self.titular)
  for _, linha in ipairs(self.extrato) do
    print("  " .. linha)
  end
  print(string.format("  saldo      %9.2f", self.saldo))
end

-- print(conta) e tostring(conta) usam esta função
function Conta.__tostring(conta)
  return string.format("Conta de %s: R$ %.2f", conta.titular, conta.saldo)
end

local bia = Conta.nova("Bia")
ana:depositar(100)
ana:transferir(bia, 40)
print(ana)
print(bia)

local ok, erro = pcall(ana.sacar, ana, 500)
print(ok, erro)

ok, erro = pcall(function () bia:depositar(-5) end)
print(ok, erro)

Conta:transferir(destino, valor)Um método que usa outros: saca desta conta e deposita na outra. Se o saque der erro, o error interrompe o transferir também, e o depósito não acontece: o dinheiro nunca "some no meio".

Versão 4 · Herança e erros como tabelas

A Ana abriu uma poupança. Uma poupança é uma conta (deposita, saca, tem extrato), com uma coisa a mais: ela rende juros. Copiar todos os métodos da Conta para uma classe nova seria repetir código. Com herança, a classe Poupanca guarda só o que é diferente, e o que ela não tiver é procurado na Conta.

E os erros mudam de forma: em vez de um texto, o error recebe uma tabela com um código. Assim, quem trata o erro sabe qual problema foi (falta de saldo? valor inválido?) sem ter que procurar palavras na mensagem.

-- Banco da Ana, versão 4: herança (a poupança) e erros como tabelas

local Conta = {}
Conta.__index = Conta

function Conta.nova(titular)
  local conta = { titular = titular, saldo = 0, extrato = {} }
  return setmetatable(conta, Conta)
end

-- Um erro que o programa consegue reconhecer: uma tabela com código e mensagem.
local function falhar(codigo, mensagem)
  error({ codigo = codigo, mensagem = mensagem }, 2)
end

function Conta:depositar(valor)
  if type(valor) ~= "number" or valor <= 0 then
    falhar("VALOR", "valor inválido: " .. tostring(valor))
  end
  self.saldo = self.saldo + valor
  table.insert(self.extrato, string.format("depósito  +%8.2f", valor))
end

function Conta:sacar(valor)
  if type(valor) ~= "number" or valor <= 0 then
    falhar("VALOR", "valor inválido: " .. tostring(valor))
  end
  if valor > self.saldo then
    falhar("SALDO", string.format("saldo insuficiente (saldo R$ %.2f)", self.saldo))
  end
  self.saldo = self.saldo - valor
  table.insert(self.extrato, string.format("saque     -%8.2f", valor))
end

function Conta:descricao()
  return string.format("Conta de %s: R$ %.2f", self.titular, self.saldo)
end

function Conta.__tostring(conta)
  return conta:descricao()
end

-- A poupança é uma Conta com rendimento: o que ela não tiver, procura em Conta.
local Poupanca = setmetatable({}, { __index = Conta })
Poupanca.__index = Poupanca
Poupanca.__tostring = Conta.__tostring   -- metamétodos não vêm pelo __index

function Poupanca.nova(titular, taxa)
  local conta = Conta.nova(titular)       -- monta a parte de Conta
  conta.taxa = taxa
  return setmetatable(conta, Poupanca)    -- e passa a ser uma Poupanca
end

function Poupanca:render()
  local juros = self.saldo * self.taxa
  self:depositar(juros)
  return juros
end

-- Sobrescreve a descrição: mostra também a taxa.
function Poupanca:descricao()
  return Conta.descricao(self) .. string.format(" (poupança, %.1f%% ao mês)", self.taxa * 100)
end

local cofrinho = Poupanca.nova("Ana", 0.01)
ana:depositar(300)
cofrinho:depositar(1000)
print(ana)
print(cofrinho)
print(string.format("Rendeu R$ %.2f", cofrinho:render()))

PeçaO que faz
error({ codigo = …, mensagem = … }, 2)O error aceita qualquer valor, não só texto. O pcall devolve essa mesma tabela. (Com uma tabela, o Lua não acrescenta a posição na mensagem: o nível só importa para erros de texto.)
erro.codigo == "SALDO"Quem trata reconhece o tipo do erro pelo campo, com uma comparação simples.
setmetatable({}, { __index = Conta })A Poupanca é uma tabela cuja metatabela tem __index = Conta: o que não estiver na Poupanca é procurado na Conta.
Poupanca.__index = PoupancaO mesmo truque da versão 2, para os objetos da poupança acharem os métodos na Poupanca.
Poupanca.nova: Conta.nova(titular) e depois setmetatable(conta, Poupanca)Aproveita a fábrica da Conta para montar os campos comuns (titular, saldo, extrato), acrescenta a taxa e troca a metatabela: o objeto passa a ser uma poupança.
Poupanca:render()O método novo. Lá dentro, self:depositar(juros) usa o método herdado da Conta.
Poupanca:descricao() com Conta.descricao(self)Sobrescreve o método da Conta, e ainda aproveita o original: chama a versão da Conta diretamente (com ponto, passando o self) e acrescenta a taxa. %% escreve um % de verdade.
Poupanca.__tostring = Conta.__tostringParece repetido, mas é necessário: veja o cenário abaixo.

A saída está no começo da página. O caminho que o Lua faz para achar cada método, por exemplo em cofrinho:sacar(50): procura sacar no próprio cofrinho (não tem) → no __index dele, a Poupanca (não tem) → no __index da Poupanca, a Conta (achou). Já cofrinho:descricao() para na Poupanca, que tem a sua própria versão.

Metamétodos não são herdados pelo __index

Sem a linha Poupanca.__tostring = Conta.__tostring:

$ lua banco.lua
Conta de Ana: R$ 300.00
table: 0x55f5af8e4620
Rendeu R$ 10.00
…

A conta comum continua aparecendo bem, mas a poupança virou table: 0x55f5af8e4620 (o endereço na memória; muda a cada execução, e no editor do guia sai mais curto). O motivo: para achar um metamétodo como o __tostring, o Lua olha direto na metatabela do objeto (a Poupanca), sem seguir o __index. O __index serve para os campos do objeto (cofrinho.sacar), não para os da metatabela. Cada classe filha precisa ter os seus metamétodos (__tostring, __eq, __add…), nem que seja copiando os da mãe. Veja Metamétodos.

Por que não existe class no Lua

O Lua prefere dar poucos mecanismos gerais (tabelas, metatabelas, funções) a muitos recursos prontos. Com eles, cada programa monta o tipo de classe que precisa. Por isso você vai encontrar outros estilos em código alheio: Conta.new em vez de Conta.nova, o setmetatable dentro de um método Conta:new(o), ou bibliotecas como middleclass e classic. Por baixo, todos usam o mesmo __index. Mais em Classes com Metatabelas.

Desafios extras

  • Saldo protegido. Na versão 4, nada impede ana.saldo = 1000000. Reescreva Conta.nova guardando o saldo numa variável local e devolvendo uma tabela de funções que a enxergam (uma closure). Veja Privacidade com Closures.
  • Limite de saques na poupança. Sobrescreva Poupanca:sacar para recusar (com o código "LIMITE") mais de dois saques; dentro dela, chame Conta.sacar(self, valor) para fazer o saque de verdade.
  • Comparar contas. Dê à Conta um __lt (veja Metamétodos de Operadores) que compare os saldos, e ordene uma lista de contas com table.sort(contas).

Resumo

  • Uma classe no Lua é uma tabela com os métodos; cada objeto é uma tabela com os dados, ligada à classe por setmetatable.
  • Classe.__index = Classe faz o objeto achar na classe os campos que ele não tem: os métodos ficam num lugar só.
  • function Classe:metodo() ganha o parâmetro self; objeto:metodo() o preenche. Definiu com :, chame com :.
  • error interrompe uma operação impossível (nível 2 aponta quem chamou); pcall deixa tratar. Um erro pode ser uma tabela com código.
  • __tostring ensina o print a mostrar o objeto.
  • Herança: a classe filha tem um __index que aponta para a mãe; ela guarda só o que muda, e pode sobrescrever métodos. Metamétodos precisam ser repetidos na filha.
