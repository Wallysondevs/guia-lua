Lua package.path

Na aula Módulos e require, o erro module 'conta' not found mostrou uma lista enorme de lugares onde o Lua procurou o arquivo. Essa lista não é mágica: ela sai de um texto guardado na variável package.path (em inglês, "caminho do pacote"). Nesta aula você vai ler esse texto, entender cada pedaço, e mudá-lo para o require achar os seus módulos onde você quiser guardá-los.

Você vai aprender
  • O que é o package.path: uma lista de modelos separados por ;, com um ? no lugar do nome do módulo.
  • A ordem da procura, e como perguntar "onde ele acharia?" com package.searchpath.
  • Como pôr uma pasta sua (lib) na lista, de dentro do programa.
  • Como fazer o mesmo de fora, com a variável de ambiente LUA_PATH, e o que quer dizer o ;;.
  • Como achar os módulos mesmo quando o programa é rodado de outra pasta.
  • O package.cpath (módulos em C) e o package.preload.
  • Os erros reais de um package.path mal escrito.

Tudo rodou no Lua 5.5 do Ubuntu da máquina da Ana, numa pasta chamada mercado. Os caminhos do sistema (/usr/local/share/lua/5.5/…) são os do Ubuntu; em outro sistema, ou num Lua compilado à mão, eles podem ser outros.

A ideia: a lista de lugares onde a chave costuma estar

A Ana perdeu a chave de casa. Ela tem uma lista, na ordem: "1. no gancho da porta; 2. na bolsa; 3. no bolso do casaco; 4. na gaveta da cozinha". Ela olha o 1; não está. O 2; não está. O 3: achou! Ela para ali e não abre a gaveta. Se não estivesse em nenhum, ela diria: "não achei, e olhei no gancho, na bolsa, no casaco e na gaveta".

O require faz igualzinho. O package.path é a lista; cada item é um lugar; ele para no primeiro que existe; e, se não achar, a mensagem de erro é a lista de lugares onde ele olhou.

1. Lendo o package.path

O package.path é um texto comum. Mostrado de uma vez, é difícil de ler, porque os itens vêm grudados por ;. Este programa quebra o texto em cada ; e mostra um item por linha (o gmatch com "[^;]+" quer dizer "cada pedaço sem ponto e vírgula"; veja gmatch):

for modelo in package.path:gmatch("[^;]+") do
  print(modelo)
end

$ lua caminhos.lua
/usr/local/share/lua/5.5/?.lua
/usr/local/share/lua/5.5/?/init.lua
/usr/local/lib/lua/5.5/?.lua
/usr/local/lib/lua/5.5/?/init.lua
/usr/share/lua/5.5/?.lua
/usr/share/lua/5.5/?/init.lua

./?/init.lua

Cada linha é um modelo (em inglês, template). Para procurar o módulo contas, o require troca o ? de cada modelo por contas e vê se aquele arquivo existe:

ModeloCom require("contas")Para que serve
/usr/local/share/lua/5.5/?.lua/usr/local/share/lua/5.5/contas.luaBibliotecas que você instalou à mão para todos os usuários
/usr/local/lib/lua/5.5/?.lua/usr/local/lib/lua/5.5/contas.luaIdem (outra pasta tradicional)
/usr/share/lua/5.5/?.lua/usr/share/lua/5.5/contas.luaBibliotecas instaladas pelo apt do Ubuntu
./?.lua./contas.luaA pasta onde você está agora
…/?/init.lua…/contas/init.luaUm módulo que é uma pasta (veja Criando seu Módulo)

Repare em duas coisas. Primeiro: as pastas do sistema vêm antes da pasta atual. Segundo: todas têm 5.5 no nome, e é por isso que as bibliotecas que o apt do Ubuntu instala para o Lua 5.4 (em /usr/share/lua/5.4) não aparecem para o 5.5 (a aula LuaRocks conta essa história).

E o ponto no nome?

Antes de trocar o ?, o require transforma cada ponto do nome numa barra: require("loja.estoque") procura ./loja/estoque.lua. Os símbolos usados (a barra, o ;, o ?) estão no package.config, se você tiver curiosidade: lua -e 'print(package.config)' mostra /, ;, ?, ! e -, um por linha.

"Onde você acharia?": package.searchpath

Para fazer a mesma procura do require sem carregar nada, use package.searchpath(nome, lista). Na pasta mercado, a Ana guardou o módulo das contas numa subpasta lib (o arquivo é lib/contas.lua):

$ lua -e 'print(package.searchpath("lib.contas", package.path))'
./lib/contas.lua
$ lua -e 'print(package.searchpath("contas", package.path))'
nil	no file '/usr/local/share/lua/5.5/contas.lua'
	no file '/usr/local/share/lua/5.5/contas/init.lua'
	no file '/usr/local/lib/lua/5.5/contas.lua'
	no file '/usr/local/lib/lua/5.5/contas/init.lua'
	no file '/usr/share/lua/5.5/contas.lua'
	no file '/usr/share/lua/5.5/contas/init.lua'
	no file './contas.lua'
	no file './contas/init.lua'

Quando acha, ele devolve o caminho. Quando não acha, devolve nil e, como segundo valor, a lista de tentativas: é a mesma lista do erro do require. Com o nome lib.contas ele acha; só com contas, não, porque nenhum modelo olha dentro de lib.

2. Pondo a sua pasta na lista

A Ana não quer escrever require("lib.contas") em todo lugar. Ela quer require("contas") e que o Lua procure também dentro de lib. Como o package.path é só um texto, basta juntar um modelo novo na frente, antes do primeiro require:

package.path = "./lib/?.lua;" .. package.path
local contas, onde = require("contas")
print(contas.somar(2, 3), onde)
"./lib/?.lua;"
O modelo novo: "o arquivo ?.lua dentro da pasta lib da pasta atual". O ; no fim é o separador: sem ele, o modelo gruda no próximo (veja Quando dá errado).
.. package.path
Junta (concatena) a lista antiga depois. Assim nada se perde: o Lua continua procurando nos lugares de sempre.
package.path = …
Guarda a lista nova no lugar da antiga. Vale do ponto em diante, para todos os require do programa (inclusive os de dentro dos módulos).
$ lua main.lua
5	./lib/contas.lua

Achou em ./lib/contas.lua, o primeiro modelo da lista nova. Pôr o seu modelo na frente faz a sua pasta ganhar das pastas do sistema; pôr no fim (package.path .. ";./lib/?.lua") faz ela ser a última opção.

Missão: o módulo está na aba lib/contas.lua, dentro da pasta lib. Rode e veja que o require("contas") não o acha. Sem mudar o nome do require, acrescente uma linha no começo do main.lua que ponha ./lib/?.lua no package.path.

local contas = require("contas")
print("Total: " .. contas.somar(2, 3))

local M = {}
function M.somar(a, b) return a + b end
return M

package.path = "./lib/?.lua;" .. package.path
local contas = require("contas")
print("Total: " .. contas.somar(2, 3))

3. De fora do programa: a variável LUA_PATH

Às vezes você não quer (ou não pode) mexer no programa. Para isso existe a variável de ambiente LUA_PATH: um valor que o terminal entrega a todo programa que você roda (veja os.getenv). Quando o lua começa, ele monta o package.path a partir dela. Este usa.lua não mexe em nada:

local contas, onde = require("contas")
print(contas.somar(10, 20), onde)

$ lua usa.lua 2>&1 | head -2               « só as 2 primeiras linhas do erro
lua: usa.lua:1: module 'contas' not found:
	no field package.preload['contas']
$ LUA_PATH="./lib/?.lua;;" lua usa.lua
30	./lib/contas.lua

Escrever NOME="valor" antes do comando cria a variável só para aquele comando. E o ;; no fim? Ele quer dizer "e aqui entra a lista padrão". Veja a diferença:

$ LUA_PATH="./lib/?.lua;;" lua -e 'print(package.path)'
./lib/?.lua;/usr/local/share/lua/5.5/?.lua;/usr/local/share/lua/5.5/?/init.lua;/usr/local/lib/lua/5.5/?.lua;/usr/local/lib/lua/5.5/?/init.lua;/usr/share/lua/5.5/?.lua;/usr/share/lua/5.5/?/init.lua;./?.lua;./?/init.lua
$ LUA_PATH="./lib/?.lua" lua -e 'print(package.path)'
./lib/?.lua

Com ;;, a lista padrão inteira entrou depois do ./lib/?.lua. Sem ele, o package.path ficou só com ./lib/?.lua: o Lua deixaria de procurar na pasta atual e nas pastas do sistema. Quase sempre você quer o ;;.

Para o terminal inteiro: export

$ export LUA_PATH="./lib/?.lua;;"
$ lua usa.lua
30	./lib/contas.lua
$ unset LUA_PATH

Com export, a variável vale para todos os comandos daquele terminal, até você fechá-lo (ou desfazer com unset). Para valer sempre, a linha do export vai no fim do arquivo ~/.bashrc (o LuaRocks usa esse mesmo truque).

LUA_PATH_5_5: só para o Lua 5.5

Quem tem várias versões do Lua no computador pode dar a cada uma a sua lista. O 5.5 procura primeiro a variável LUA_PATH_5_5; só se ela não existir, usa a LUA_PATH:

$ LUA_PATH_5_5="./lib/?.lua;;" LUA_PATH="/nada/?.lua" lua -e 'print(package.path)'
./lib/?.lua;/usr/local/share/lua/5.5/?.lua;/usr/local/share/lua/5.5/?/init.lua;/usr/local/lib/lua/5.5/?.lua;/usr/local/lib/lua/5.5/?/init.lua;/usr/share/lua/5.5/?.lua;/usr/share/lua/5.5/?/init.lua;./?.lua;./?/init.lua

O /nada/?.lua da LUA_PATH foi ignorado: ganhou a LUA_PATH_5_5.

No editor do guia

A caixa "Experimente" não tem um terminal onde você possa criar variáveis de ambiente: lá não dá para usar LUA_PATH. Mudar o package.path de dentro do programa (seção 2) funciona normalmente, e as abas podem ter pasta no nome (lib/contas.lua).

4. O programa rodado de outra pasta

O ./ dos modelos é a pasta onde você está no terminal, não a pasta do programa. Por isso o main.lua da seção 2 só funciona se você estiver dentro de mercado. Para o programa achar os seus módulos de qualquer lugar, ele pode descobrir a própria pasta pelo arg[0], que guarda o caminho do arquivo que o lua está rodando (veja arg):

local pasta = arg[0]:match("^(.*)/") or "."
print("pasta do programa:", pasta)
package.path = pasta .. "/lib/?.lua;" .. package.path
local contas, onde = require("contas")
print(contas.somar(1, 1), onde)

$ lua mercado/app.lua
pasta do programa:	mercado
2	mercado/lib/contas.lua
$ cd mercado
$ lua app.lua
pasta do programa:	.
2	./lib/contas.lua

O padrão "^(.*)/" pega tudo o que vem antes da última barra de arg[0] (veja find e match): de mercado/app.lua, sobra mercado. Quando não há barra (app.lua), o match dá nil e o or "." usa a pasta atual. Nos dois casos o módulo foi achado.

5. Os outros "procuradores": preload e cpath

O package.path não é o único lugar onde o require olha. Ele tem uma lista de procuradores (em inglês, searchers), que ele tenta em ordem: lua -e 'print(#package.searchers)' mostra 4. É por isso que a mensagem de erro tem três blocos:

OrdemOnde procuraNa mensagem de erro
1ºA tabela package.preloadno field package.preload['contas']
2ºOs modelos do package.path (arquivos .lua)no file '…/contas.lua'
3ºOs modelos do package.cpath (módulos em C, .so)no file '…/contas.so'
4ºO package.cpath de novo, para nomes com ponto (a.b procura a.so)As linhas extras que você viu com require("contas.lua")

package.cpath: módulos em C

$ lua -e 'print(package.cpath)'
/usr/local/lib/lua/5.5/?.so;/usr/lib/x86_64-linux-gnu/lua/5.5/?.so;/usr/lib/lua/5.5/?.so;/usr/local/lib/lua/5.5/loadall.so;./?.so

Funciona igual ao package.path, mas para arquivos .so: bibliotecas escritas em C e compiladas, como o lfs (pastas e arquivos) ou o socket (internet). A variável de ambiente dele é a LUA_CPATH (e LUA_CPATH_5_5). Você vai encontrá-los ao instalar bibliotecas com o LuaRocks. No editor do guia não há nenhum módulo em C instalado: lá, só os módulos .lua das abas.

package.preload: um módulo sem arquivo

Um programa pode registrar, em package.preload, uma função que monta o módulo. Quando alguém pedir aquele nome, o require chama a função em vez de procurar arquivo:

package.preload["config"] = function (nome)
  print("montando", nome)
  return { cor = "azul" }
end
local config = require("config")
print(config.cor)
print(require("config") == config)

$ lua preload.lua
montando	config
azul
true

A função rodou uma vez só, e o resultado foi para o caderninho package.loaded, como qualquer módulo. Você quase não vai precisar disso; é coisa de programas que embutem o Lua (jogos, editores) ou que juntam vários módulos num arquivo só.

Resumo

  • O package.path é um texto com modelos separados por ;. O require troca o ? pelo nome do módulo (com os pontos virando barras) e usa o primeiro arquivo que existir.
  • No Ubuntu, a lista padrão do 5.5 tem as pastas do sistema (/usr/local/…/5.5, /usr/share/lua/5.5) e, por último, a pasta atual (./?.lua, ./?/init.lua).
  • Para usar a sua pasta: package.path = "./lib/?.lua;" .. package.path, no topo, antes do primeiro require. Não esqueça o ? nem o ;.
  • De fora: LUA_PATH="./lib/?.lua;;", em que ;; é a lista padrão. A LUA_PATH_5_5 ganha da LUA_PATH.
  • O ./ é a pasta do terminal, não a do programa; o arg[0] resolve.
  • package.searchpath mostra onde ele acharia; package.cpath é a lista dos módulos em C; package.preload registra módulos sem arquivo.
