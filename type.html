Lua type()

A aula Os Tipos de Dados usou o type para mostrar os oito tipos do Lua. Agora é a vez dele: o type (em inglês, "tipo") é a função que responde "que tipo de valor é este?". Ela é a lupa da Ana quando um programa faz uma coisa estranha (uma conta que não sai, um nil que aparece do nada), e é a forma de um programa conferir se recebeu o que esperava.

Você vai aprender
  • A usar type(valor) com qualquer valor, variável ou conta.
  • Que o type devolve um texto: "number", "string", "nil"...
  • A perguntar "isto é um número?" com type(x) == "number", e o erro silencioso de esquecer as aspas.
  • A conferir a resposta do io.read com type e tonumber.
  • Os primos do type: math.type (inteiro ou float) e io.type (arquivo aberto ou fechado).
  • Os erros reais: type() vazio, Type com maiúscula e o type de uma função que não devolve nada.

Todos os programas desta aula foram rodados com o Lua 5.5 na máquina fictícia da Ana (usuária ana, computador notebook). As caixas "Experimente" rodam o mesmo Lua de verdade, no seu navegador.

A ideia: a etiqueta da balança

Na padaria, as encomendas chegam em pacotes fechados. Antes de abrir, a Ana olha a etiqueta do tipo: "frágil", "congelado", "seco". Ela não precisa saber o que tem dentro, só de que tipo é, para decidir onde guardar. O type lê essa etiqueta de qualquer valor do Lua e responde com uma palavra.

1. Usando o type

print(type(42))
print(type("Ana"))
print(type(true))
print(type(nil))
print(type({}))
print(type(print))

$ lua tipo.lua
number
string
boolean
nil
table
function
type
O nome da função, em minúsculas. É uma função global, que já vem com o Lua.
( 42 )
O valor que você quer examinar. Pode ser qualquer coisa: um valor escrito direto, uma variável, uma conta, até outra função.
number, string...
A resposta: o nome do tipo, em inglês e em minúsculas. As palavras possíveis são só oito: nil, boolean, number, string, table, function, userdata e thread.

Com variáveis e contas é igual. O type olha o valor que está na variável (ou o resultado da conta) naquele momento:

local preco = 5
local nome = "Ana"
local pago = false
print(type(preco), type(nome), type(pago), type(desconto))
print(type(preco * 2), type(nome .. "!"), type(preco > 3))

$ lua variaveis.lua
number	string	boolean	nil
number	string	boolean

Repare no type(desconto): ninguém criou desconto, e o type respondeu nil, sem erro (a aula local × Global explica por quê). E na segunda linha: uma conta dá number, uma junção com .. dá string, e uma comparação (preco > 3) dá boolean.

No modo interativo, o type é ótimo para tirar dúvidas rápidas:

$ lua
Lua 5.5.0  Copyright (C) 1994-2025 Lua.org, PUC-Rio
> type(42)
number
> type("42")
string
> type(type)
function
> os.exit()

2. A resposta do type é um texto

O type não devolve um "tipo" mágico: devolve uma string comum, com o nome do tipo dentro. Dá para guardar numa variável, juntar com .., contar as letras:

local t = type(42)
print(t, type(t))
print(type(type(42)))
print(#type(42))

$ lua texto.lua
number	string
string
6

type(42) é o texto "number", de 6 letras; e o tipo desse texto é, claro, string. Isso importa para a próxima seção: para perguntar "é um número?", você compara com o texto "number", entre aspas.

3. Perguntando "é deste tipo?"

O uso mais comum do type não é mostrar o tipo, e sim conferir. Compare a resposta com o nome do tipo usando == ("é igual a") ou ~= ("é diferente de"; aula Comparações). O resultado é true ou false:

local preco = 5
print(type(preco) == "number")
print(type(preco) == "string")
print(type(preco) ~= "nil")

$ lua comparar.lua
true
false
true

Por enquanto, o print só mostra a resposta. Quando você conhecer o if, essa pergunta vai decidir o que o programa faz: "se não for número, avise a pessoa e peça de novo".

Sem aspas, com maiúscula, com outro nome: sempre false, sem erro 
local preco = 5
print(type(preco) == number)
print(type(preco) == "Number")
print(type(preco) == "int")

$ lua sem-aspas.lua
false
false
false

As três respostas deviam ser "sim", e o Lua disse false para todas, sem nenhuma mensagem. Na linha 2, number sem aspas é o nome de uma variável que ninguém criou (vale nil), e "number" == nil é falso. Na 3, o type sempre responde em minúsculas, e "Number" é outro texto. Na 4, "int" é o nome de outras linguagens; no Lua, os nomes são só os oito da lista. Regra: compare com o nome exato, em minúsculas e entre aspas.

Missão: o programa pergunta se o preço é um número e responde false, mas o preço é 5. Conserte a comparação para que ele responda true.

local preco = 5
print(type(preco) == number)

local preco = 5
print(type(preco) == "number")

4. Conferindo o que a pessoa digitou

A aula do io.read avisou: a resposta é sempre texto. O type confirma, e mostra o que o tonumber faz com ela:

io.write("Quantos pães? ")
local resposta = io.read()
print("io.read():", type(resposta))
print("tonumber:", type(tonumber(resposta)))

Com 12 e depois com doze como entrada (mandadas pelo printf, por isso não aparecem depois da pergunta):

$ printf '12\n' | lua leitura.lua
Quantos pães? io.read():	string
tonumber:	number
$ printf 'doze\n' | lua leitura.lua
Quantos pães? io.read():	string
tonumber:	nil

O io.read() deu string nas duas vezes. O tonumber é que separa as respostas: com "12" virou number, com "doze" virou nil. É assim que um programa sabe se recebeu um número: converta com tonumber e veja se o resultado é "number" (ou, mais curto, se não é nil).

Missão: a entrada já vem pronta: 12. O programa mostra string. Converta a resposta com tonumber(...) na linha do io.read, para que o type mostre number.

io.write("Quantos pães? ")
local qtd = io.read()
print(type(qtd))

io.write("Quantos pães? ")
local qtd = tonumber(io.read())
print(type(qtd))

5. Os primos: math.type e io.type

O type responde com os oito tipos gerais. Para detalhes, há duas funções parecidas, cada uma na sua biblioteca.

math.type: inteiro ou float?

Para o type, todo número é number. O math.type diz de qual dos dois jeitos ele está guardado (aula Números):

print(type(7), math.type(7))
print(type(7.5), math.type(7.5))
print(type("7"), math.type("7"))
print(math.type(10 / 2), math.type(10 // 2))

$ lua mathtype.lua
number	integer
number	float
string	nil
float	integer

Para algo que não é número (o texto "7"), o math.type responde nil, e não "string": ele só conhece números. E a última linha mostra de novo que 10 / 2 dá float e 10 // 2 dá inteiro.

io.type: é um arquivo?

Arquivos abertos são do tipo userdata, que é genérico demais. O io.type diz se é um arquivo e se ele ainda está aberto (os arquivos chegam na aula io.open):

local f = io.open("lista.txt", "w")
print(type(f), io.type(f))
f:close()
print(type(f), io.type(f))
print(io.type(42), io.type(io.stdout))

$ lua iotype.lua
userdata	file
userdata	closed file
nil	file

"file" é um arquivo aberto, "closed file" um arquivo já fechado, e nil quer dizer "isto não é arquivo". A própria tela (io.stdout) é um arquivo para o Lua, como você viu na aula do io.write.

Não guarde o tipo numa variável chamada type

Se precisar guardar a resposta, use um nome em português, como local tipo = type("pão") (que mostra O tipo é e string num print). Uma variável chamada type esconde a função, e o próximo type(...) do programa quebra (aula local × Global).

A comparação que sempre dá false

Sem erro nenhum: type(x) == number (sem aspas), == "Number" (maiúscula) ou == "int" (nome de outra linguagem). Seção 3: compare com o nome exato, minúsculo, entre aspas.

Resumo

  • type(valor) diz o tipo de qualquer valor, variável ou conta, com uma das oito palavras: nil, boolean, number, string, table, function, userdata, thread.
  • A resposta é um texto: compare com type(x) == "number", nome exato, minúsculo, entre aspas. Sem aspas ou com maiúscula, dá false sem erro.
  • O io.read() sempre dá string; o tonumber dá number ou nil.
  • math.type: "integer", "float" ou nil. io.type: "file", "closed file" ou nil.
  • type() vazio, ou o type de algo que não devolve valor, dá bad argument #1 to 'type' (value expected).
  • Não use type como nome de variável: ele esconde a função.
