Lua: O Valor nil

Às vezes, a resposta certa é "não tem nada aqui": a variável que ninguém criou, o telefone que o cliente não deu, o número que a pessoa não digitou direito. Para isso o Lua tem um valor especial, o nil (do latim nihil, "nada"). Ele é o único valor do tipo nil, e você vai encontrá-lo o tempo todo, principalmente nas mensagens de erro. Entender de onde ele vem é metade do trabalho de consertar um programa.

Você vai aprender
  • O que é o nil: a ausência de valor.
  • De onde ele aparece: variável que não existe ou sem valor, campo que falta numa tabela, posição além do fim de uma lista, função sem return, tonumber que falha.
  • Como "apagar" uma variável ou um campo dando nil a ele.
  • Como testar se algo é nil: x == nil, x ~= nil e if not x then.
  • O valor padrão com or: nome or "visitante".
  • Os erros reais mais comuns do Lua, todos causados por um nil no lugar errado, e como ler cada um.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com lua arquivo.lua (veja Rodando um Programa). Você pode rodar cada um no editor do guia.

A ideia: a gaveta vazia

Pense numa variável como uma gaveta com etiqueta (veja Variáveis). A gaveta preco guarda 4.50; a gaveta nome guarda "Ana". E se você abrir uma gaveta vazia, ou procurar uma gaveta que nem existe? O Lua não inventa nada: ele responde nil, "nada".

  • nil não é zero: zero é um número (a gaveta tem um papel escrito "0").
  • nil não é o texto vazio "": o texto vazio é um texto (a gaveta tem um papel em branco).
  • nil não é false: false é a resposta "não" a uma pergunta (veja Booleanos).
  • nil é a gaveta sem papel nenhum.

Ninguém criou uma variável sobrenome. Em muitas linguagens isso daria erro; no Lua, uma variável que não existe vale nil, sem aviso nenhum.

Uma variável criada sem valor (sem o =) começa com nil. Ela existe, mas a gaveta está vazia.

O lado perigoso: erro de digitação vira nil

Como uma variável inexistente vale nil em silêncio, um erro de digitação (totl em vez de total, True em vez de true) não é avisado na hora. O programa só para mais adiante, quando tenta usar esse nil. É um dos motivos para usar sempre local e nomes claros (veja local × Global).

2. Dar nil para "apagar"

Guardar nil numa variável é esvaziar a gaveta: o valor antigo some.

local cupom = "DESCONTO10"
print("cupom:", cupom)
cupom = nil
print("cupom:", cupom)

$ lua apagar.lua
cupom:	DESCONTO10
cupom:	nil

Numa tabela (o "fichário" do Lua, que tem aula própria: Tabelas), dar nil a um campo remove o campo. Para o Lua, "o campo vale nil" e "o campo não existe" são a mesma coisa:

local cliente = { nome = "Ana", telefone = "9999-0000" }
print(cliente.telefone)
cliente.telefone = nil
print(cliente.telefone)
for chave, valor in pairs(cliente) do print(chave, valor) end

$ lua campo.lua
9999-0000
nil
nome	Ana

O for … in pairs (que percorre todos os campos; aula pairs) mostrou só o nome: o telefone não está mais lá.

3. De onde vem o nil

Além da variável que não existe, o nil aparece em vários lugares. Reconhecê-los ajuda a achar a origem de um erro:

local cliente = { nome = "Ana", idade = 30 }
print(cliente.nome, cliente.telefone)
local lista = { "pão", "leite" }
print(lista[1], lista[2], lista[3])
local function avisar()
  print("(avisando)")
end
print(avisar())
print(tonumber("doze"), math.tointeger(2.5))
local a, b, c = 1, 2
print(a, b, c)

$ lua origens.lua

Por que o print(avisar()) mostrou uma linha vazia, e não nil?

Uma função sem return devolve, a rigor, nenhum valor. Quando você guarda esse "nenhum valor" numa variável, ela fica com nil. Mas o print(avisar()) recebe zero valores para mostrar, e o print sem nada mostra uma linha vazia. No lab:

local function avisar()
  print("(avisando)")
end
local r = avisar()
print("r =", r)
print(avisar())

$ lua retorno.lua
(avisando)
r =	nil
(avisando)
                «  a linha vazia do print() sem nada

Para quase tudo no dia a dia, "nenhum valor" e nil se comportam igual. A diferença tem aula própria, no nível avançado: select e o Número de Argumentos.

fail: o nil que quer dizer "não deu"

O manual do Lua 5.5 descreve várias funções (tonumber, math.tointeger, io.open, string.find) dizendo que, quando não conseguem, elas devolvem fail ("falha"). E explica: "Currently, fail is equal to nil, but that may change in future versions", "hoje o fail é igual a nil, mas isso pode mudar em versões futuras". A recomendação do manual é testar com not (if not n then), que funciona para nil e para false, em vez de n == nil.

4. Testando se algo é nil

local x
print(x == nil, x ~= nil)
print(nil == false, not nil)
print(type(x) == "nil")

$ lua comparar.lua
true	false
false	true
true
x == nil
"x é nil?" → true.
x ~= nil
"x é diferente de nil?" (o ~= é o "diferente" do Lua; veja Comparações) → false. É o jeito de perguntar "tem alguma coisa aí?".
nil == false → false
Os dois contam como falsos numa condição, mas são valores diferentes.
not nil → true
Como nil conta como falso, o not o transforma em true. Daí o if not x then: "se não houver x".
type(x) == "nil"
Outro jeito, comparando o texto do tipo. Funciona, mas é mais comprido.

5. Valor padrão: x or "outra coisa"

Muitas vezes, quando um valor está faltando, você quer usar um valor "de reserva". A cafeteria da Ana chama o cliente pelo nome; se ninguém disse o nome, chama de "visitante":

local nome_digitado = nil
local nome = nome_digitado or "visitante"
print("Olá, " .. nome .. "!")
nome_digitado = "Ana"
nome = nome_digitado or "visitante"
print("Olá, " .. nome .. "!")

$ lua padrao.lua
Olá, visitante!
Olá, Ana!

O or ("ou") devolve o valor da esquerda se ele existir (não for nil nem false); senão, devolve o da direita. Lê-se: "o nome digitado, ou, se não houver, "visitante"". Como o or funciona por inteiro é assunto da aula and, or e not.

O or também troca o false

Se a variável puder valer false de propósito (por exemplo, quer_sacola = false), o quer_sacola or true vai trocar o false por true. Para esse caso, teste o nil explicitamente: if quer_sacola == nil then quer_sacola = true end.

Formas diferentes de fazer a mesma coisa

Para perguntar "tem valor?":

JeitoExemploQuando usar
Pela condiçãoif x then / if not x thenO mais comum. Quando x nunca vai ser false de propósito (números, textos, tabelas). É o que o manual recomenda para resultados fail.

Pelo tipoif type(x) == "nil" thenRaramente; serve quando você já está olhando o tipo por outro motivo

Quando dá errado

O nil em si nunca dá erro: o erro vem quando alguém tenta usar o nada como se fosse alguma coisa. A mensagem sempre segue o mesmo molde: attempt to ("tentativa de") + o que se tentou fazer + a nil value ("um valor nil") + entre parênteses, onde estava o nil. Essa última parte é a pista mais valiosa.

Conta com nil: o erro de digitação 
local total = 10
local frete = 5
print(totl + frete)

$ lua typo.lua
lua: typo.lua:3: attempt to perform arithmetic on a nil value (global 'totl')
stack traceback:
	typo.lua:3: in main chunk
	[C]: in ?
lua: typo.lua:3:
Arquivo typo.lua, linha 3.
attempt to perform arithmetic on a nil value
"Tentativa de fazer conta com um valor nil".
(global 'totl')
O nil estava numa variável global chamada totl. "Global" aqui é um alarme: você só criou variáveis local, então uma global com nome parecido quase sempre é erro de digitação.
stack traceback:
"Rastro da pilha": a linha 3 do programa principal (in main chunk), que foi chamado pelo próprio lua ([C]: in ?). Mais em Lendo uma Mensagem de Erro.

Como consertar: print(total + frete).

Juntar nil num texto: o campo com nome errado 
local cliente = { nome = "Ana" }
print("Olá, " .. cliente.nme)

$ lua typo2.lua
lua: typo2.lua:2: attempt to concatenate a nil value (field 'nme')
stack traceback:
	typo2.lua:2: in main chunk
	[C]: in ?

"Tentativa de juntar um valor nil, no campo (field) nme". A tabela tem nome, não nme, e um campo que não existe vale nil. Como consertar: cliente.nome.

Usar o nil como se fosse uma tabela 
local pedido = nil
print(pedido.total)

$ lua indexar.lua
lua: indexar.lua:2: attempt to index a nil value (local 'pedido')
stack traceback:
	indexar.lua:2: in main chunk
	[C]: in ?

"Tentativa de indexar um valor nil" ("indexar" é pegar um campo com . ou [ ]), na variável local pedido. Não dá para abrir uma gaveta dentro de uma gaveta que não existe. Acontece muito quando uma função que devia devolver uma tabela devolveu nil. Como consertar: descubra por que pedido ficou nil, ou proteja: if pedido then print(pedido.total) end.

Chamar o nil como se fosse função 
local function somar(a, b) return a + b end
print(Somar(2, 3))

$ lua chamar.lua
lua: chamar.lua:2: attempt to call a nil value (global 'Somar')
stack traceback:
	chamar.lua:2: in main chunk
	[C]: in ?

"Tentativa de chamar um valor nil (a global Somar)". A função se chama somar, com minúscula; Somar não existe. É o mesmo erro do clássico pirnt("oi"). Como consertar: somar(2, 3).

Comparar com nil 
local nota
if nota >= 6 then print("aprovado") end

$ lua cmp.lua
lua: cmp.lua:2: attempt to compare number with nil
stack traceback:
	cmp.lua:2: in main chunk
	[C]: in ?

"Tentativa de comparar número com nil". A variável nota foi criada sem valor. (A ordem "number with nil" sai invertida porque, por dentro, o Lua troca a >= b por b <= a.) Repare que esta mensagem não diz o nome da variável: olhe a linha 2 e procure quem pode estar vazio.

Medir o tamanho do nil 
local cliente = {}
print(#cliente.nome)

$ lua cmp2.lua
lua: cmp2.lua:2: attempt to get length of a nil value (field 'nome')
stack traceback:
	cmp2.lua:2: in main chunk
	[C]: in ?

"Tentativa de pegar o tamanho (com #) de um valor nil, no campo nome". A tabela está vazia, então cliente.nome é nil.

Usar nil como chave de tabela 
$ lua -e 'local t = {} t[nil] = 1'
lua: (command line):1: table index is nil
stack traceback:
	(command line):1: in main chunk
	[C]: in ?

"O índice da tabela é nil". Uma tabela aceita quase qualquer valor como chave, menos o nil (como guardar algo na gaveta "nenhuma"?). Normalmente a chave veio de uma variável que ficou vazia.

Resumo

  • nil é o valor "nada": a ausência de valor. Não é 0, nem "", nem false.
  • Variável que não existe ou criada sem valor, campo que falta, posição além do fim da lista, função sem return e conversão que falhou: tudo dá nil, em silêncio.
  • x = nil esvazia a variável; t.campo = nil remove o campo.
  • Teste com if not x then (o mais comum) ou x == nil / x ~= nil (quando false também é um valor possível).
  • x or "padrão" dá um valor de reserva quando x é nil.
  • Os erros attempt to … a nil value mostram entre parênteses onde estava o nil: global (desconfie de erro de digitação), local ou field.
