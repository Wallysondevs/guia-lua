Lua Metatabelas

Você já sabe que o Lua soma números (30 + 12) e junta textos ("Ana" .. "!"). Mas o que ele faz se você mandar somar duas tabelas? Sozinho, ele não sabe, e para com um erro. As metatabelas são o jeito de ensinar o Lua a fazer coisas novas com as suas tabelas: somar, comparar, mostrar com print, ter valores padrão. Esta aula mostra a peça central de tudo isso: a função setmetatable. Ela é a porta de entrada para as próximas aulas, que vão até as classes e a herança.

Você vai aprender
  • O que é uma metatabela, com uma comparação do dia a dia: o manual de instruções.
  • O erro real que o Lua dá quando você soma duas tabelas sem ensinar como.
  • Como ligar uma metatabela a uma tabela com setmetatable, e como consultar com getmetatable.
  • O primeiro metamétodo, o __add, para somar duas cestas de compras.
  • Por que uma metatabela só serve para muitas tabelas, e como tirar ou proteger uma metatabela (__metatable).
  • Os erros mais comuns: esquecer o setmetatable, esquecer os dois sublinhados, passar algo que não é tabela.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com lua arquivo.lua (veja Rodando um Programa). Para acompanhar, você precisa conhecer tabelas, tabelas como dicionários e funções.

A ideia: o manual de instruções que acompanha a tabela

A Ana comprou uma cafeteira nova. A cafeteira é a coisa em si: tem água, pó, uma jarra. Junto dela veio um manual de instruções, que não é a cafeteira, mas diz o que fazer em situações especiais: "se a luz vermelha piscar, faça isto", "se faltar água, faça aquilo".

No Lua é igual:

  • a tabela é a cafeteira: guarda os seus dados ({ total = 30 });
  • a metatabela é o manual: uma outra tabela, presa à primeira, que diz ao Lua o que fazer em situações que ele não sabe resolver sozinho, como "alguém tentou somar esta tabela com outra";
  • cada instrução do manual se chama metamétodo. É uma função guardada na metatabela com um nome especial, que sempre começa com dois sublinhados: __add ("somar", em inglês), __index, __tostring…

O prefixo "meta" vem do grego e quer dizer "além de", "sobre": a metatabela é uma tabela sobre a outra tabela. Sem manual, a tabela funciona normalmente (guarda e devolve valores); o manual só entra em ação nas situações especiais.

1. O problema: somar duas tabelas

A Ana e a Bia fizeram compras na padaria. Cada cesta é uma tabela com o total gasto. A Ana quer saber quanto as duas gastaram juntas e tenta o mais natural, o +:

local cesta_ana = { total = 30 }
local cesta_bia = { total = 12 }
local juntas = cesta_ana + cesta_bia
print(juntas.total)

$ lua soma_cestas.lua
lua: soma_cestas.lua:3: attempt to perform arithmetic on a table value (local 'cesta_ana')
stack traceback:
	soma_cestas.lua:3: in main chunk
	[C]: in ?

Linha por linha:

soma_cestas.lua:3:
O erro aconteceu no arquivo soma_cestas.lua, na linha 3: a linha do +.
attempt to perform arithmetic on a table value
"Tentativa de fazer aritmética (conta) com um valor do tipo tabela". O + é uma conta, e o Lua só sabe fazer conta com números (e com textos que parecem números, como "10").
(local 'cesta_ana')
O Lua ainda diz qual valor era a tabela: a variável local cesta_ana, o primeiro lado da soma.
stack traceback: … in main chunk / [C]: in ?
O "rastro" de onde o programa estava: no corpo principal do arquivo (main chunk), que foi chamado pelo próprio lua ([C]: in ?). Veja Lendo uma Mensagem de Erro.

O Lua não está errado: o que seria "somar duas cestas"? Somar o total? Juntar os itens? Só quem escreveu o programa sabe. A metatabela é o lugar onde você conta isso a ele.

2. getmetatable e setmetatable

Duas funções cuidam das metatabelas. Os nomes vêm do inglês: get = "pegar", set = "definir".

local cesta = { total = 30 }
print(getmetatable(cesta))

local regras = {}
setmetatable(cesta, regras)
print(getmetatable(cesta) == regras)

$ lua primeira.lua
nil
true
getmetatable(cesta)
"Qual é a metatabela da cesta?" A resposta foi nil (nada): toda tabela que você cria com { } nasce sem metatabela.
local regras = {}
A futura metatabela. Repare: é uma tabela comum, criada com {}. O que a torna "meta" é só o uso que se faz dela. O nome regras é escolha nossa (muita gente usa mt, de metatable).
setmetatable(cesta, regras)
"A partir de agora, a metatabela da cesta é a tabela regras." Primeiro vem a tabela, depois o manual.
getmetatable(cesta) == regras
Perguntamos de novo, e agora a resposta é a própria tabela regras. O == deu true porque é a mesma tabela, não uma cópia (veja Tabelas São Referências).

Por enquanto o manual está vazio: ligar uma metatabela vazia não muda nada. A tabela continua guardando e devolvendo os seus valores como sempre, e o que está dentro da metatabela não vira campo da tabela:

local regras = {}
local c = setmetatable({ total = 1 }, regras)
print(c.total)
print(c.cor)
print(regras.total)

$ lua mtvazia.lua
1
nil
nil

A tabela e o manual são duas tabelas separadas: o total mora na cesta, não em regras. Ligar uma à outra não copia nada.

3. O primeiro metamétodo: __add

Agora vamos escrever a primeira instrução no manual. O nome dela é __add (dois sublinhados + add, "somar"). Quando o Lua encontra um + com uma tabela, ele olha a metatabela dela; se houver um __add lá, ele chama essa função com os dois lados da conta, e o que ela devolver é o resultado do +.

local regras = {}
regras.__add = function (a, b)
  return { total = a.total + b.total }
end

local cesta_ana = setmetatable({ total = 30 }, regras)
local cesta_bia = setmetatable({ total = 12 }, regras)

local juntas = cesta_ana + cesta_bia
print(juntas.total)

$ lua cestas.lua
42
regras.__add = function (a, b)
Guarda uma função no campo __add da metatabela. Ela recebe os dois lados da soma: a é o que está à esquerda do +, b o que está à direita.
return { total = a.total + b.total }
A nossa regra: "somar duas cestas é criar uma cesta nova cujo total é a soma dos totais". Aqui dentro, a.total + b.total é 30 + 12, uma conta entre números, que o Lua sabe fazer.
setmetatable({ total = 30 }, regras)
Cria a tabela e já liga a metatabela, numa linha só. Funciona porque o setmetatable devolve a própria tabela (seção 4).
cesta_ana + cesta_bia
O Lua vê que cesta_ana é uma tabela, procura __add na metatabela dela, acha, e chama regras.__add(cesta_ana, cesta_bia). Você nunca chama o metamétodo com o nome: quem chama é o Lua, na hora do +.

Passo a passo do que aconteceu na linha do +:

  1. O lado esquerdo, cesta_ana, é um número? Não, é uma tabela. Então a conta normal não serve.
  2. O Lua pega a metatabela de cesta_ana (a regras) e procura nela o campo __add.
  3. Achou uma função. Ele a chama com (cesta_ana, cesta_bia).
  4. A função devolveu { total = 42 }, e esse é o valor de cesta_ana + cesta_bia.
E se só um dos lados tiver metatabela?

O Lua procura o __add primeiro no lado esquerdo; se não achar, procura no direito. Basta um dos dois ter o metamétodo. Com c1 ligada às regras e comum = { total = 5 } sem metatabela, tanto c1 + comum quanto comum + c1 deram 35 no lab. Os detalhes (e os outros operadores) estão na próxima aula, Metamétodos de Operadores.

Missão: o manual (regras) já tem o __add, mas as cestas não estão ligadas a ele. Rode para ver o erro attempt to perform arithmetic on a table value. Depois use setmetatable nas duas cestas para a soma funcionar.

local regras = {}
regras.__add = function (a, b)
  return { total = a.total + b.total }
end

local cesta_ana = { total = 30 }
local cesta_bia = { total = 12 }

local juntas = cesta_ana + cesta_bia
print("Total das duas cestas: " .. juntas.total)

regras.__add = function (a, b)
  return { total = a.total + b.total }
end

local cesta_ana = setmetatable({ total = 30 }, regras)

local juntas = cesta_ana + cesta_bia
print("Total das duas cestas: " .. juntas.total)

4. O setmetatable devolve a tabela

O setmetatable(t, mt) liga a metatabela e depois devolve o próprio t. Não é uma cópia: é a mesma tabela.

local regras = {}
local t = {}
local volta = setmetatable(t, regras)
print(volta == t)
print(type(volta))

$ lua retorno.lua
true
table

É por isso que se vê tanto este jeito de escrever, que cria a tabela e liga o manual de uma vez:

local cesta = setmetatable({ total = 30 }, regras)

As duas formas abaixo fazem a mesma coisa:

Em duas linhasNuma linha só
local cesta = { total = 30 }
setmetatable(cesta, regras)		local cesta = setmetatable({ total = 30 }, regras)

5. Uma metatabela para muitas tabelas

O manual não precisa ser um por tabela. Uma loja de cafeteiras não escreve um manual diferente para cada aparelho do mesmo modelo: imprime o mesmo texto para todos. No Lua, o normal é ter uma metatabela e ligá-la a todas as tabelas do mesmo tipo. Uma função que cria cestas deixa isso organizado:

local regras = {
  __add = function (a, b)
    return { total = a.total + b.total }
  end,
}

local function nova_cesta(total)
  return setmetatable({ total = total }, regras)
end

local c1 = nova_cesta(30)
local c2 = nova_cesta(12)
local c3 = nova_cesta(8)
print(getmetatable(c1) == getmetatable(c3))

local juntas = c1 + c2
print(juntas.total)
print(getmetatable(juntas))

$ lua compartilhada.lua
true
42
nil
local regras = { __add = function … end, }
A mesma metatabela de antes, escrita de outro jeito: o __add já vai dentro das chaves, como qualquer campo de dicionário.
local function nova_cesta(total)
Uma "fábrica" de cestas: toda cesta criada por ela já sai com o manual ligado. Isso evita esquecer o setmetatable (o erro mais comum desta aula).
getmetatable(c1) == getmetatable(c3) → true
As três cestas apontam para a mesma tabela regras. Mudou o manual, mudou para todas.
getmetatable(juntas) → nil
Atenção: a cesta que o __add devolveu foi criada com { } puro, então ela não tem manual. A missão final mostra o problema que isso causa e o conserto.

Essa ideia (uma metatabela compartilhada + uma função que cria as tabelas) é exatamente o começo das classes, daqui a algumas aulas.

6. Só tabelas ganham metatabela pelo Lua

O setmetatable só aceita tabelas. Os outros tipos não têm metatabela, com uma exceção curiosa: os textos.

print(getmetatable({}))
print(getmetatable(42))
print(getmetatable(print))
local mt = getmetatable("abc")
print(type(mt))
print(mt.__index == string)
print(("abc"):upper())

$ lua tipos.lua
nil
nil
nil
table
true
ABC

Tabela nova, número e função: nil, sem manual. Mas os textos já vêm com uma metatabela pronta, criada pelo próprio Lua, com um campo __index que aponta para a biblioteca string. É ela que faz ("abc"):upper() funcionar como string.upper("abc") (veja Funções de Texto). Você vai entender o __index em __index e __newindex e o dois-pontos em Métodos.

Só pelo Lua, não pelo seu programa

A metatabela dos textos foi o Lua que pôs. O seu programa não consegue dar metatabela a um texto ou a um número com setmetatable (a seção Quando dá errado mostra o erro). Existe um jeito pela biblioteca debug, mas ele é para ferramentas, não para programas do dia a dia.

7. Tirar e proteger a metatabela

Tirar: setmetatable(t, nil)

Passar nil no lugar do manual desliga a metatabela. A tabela volta a ser comum:

local regras = { __add = function (a, b) return a.total + b.total end }
local c = setmetatable({ total = 5 }, regras)
print(c + c)
setmetatable(c, nil)
print(getmetatable(c))
print(c + c)

$ lua tirar.lua
10
nil
lua: tirar.lua:6: attempt to perform arithmetic on a table value (local 'c')
stack traceback:
	tirar.lua:6: in main chunk
	[C]: in ?

Na linha 3, com o manual, c + c deu 10 (aqui o __add devolve um número, não uma cesta: o metamétodo pode devolver o que você quiser). Na linha 4 o manual saiu, e na linha 6 voltou o erro do começo da aula.

Proteger: o campo __metatable

Às vezes você escreve uma biblioteca e não quer que quem a usa troque ou bagunce o manual das suas tabelas. Para isso existe o campo especial __metatable. Quando ele existe na metatabela:

  • o getmetatable devolve o valor desse campo, e não a metatabela de verdade;
  • o setmetatable se recusa a trocar a metatabela e dá erro.
local regras = { __metatable = "não mexa" }
local cofre = setmetatable({}, regras)
print(getmetatable(cofre))
setmetatable(cofre, {})

$ lua protegida.lua
não mexa
lua: protegida.lua:4: cannot change a protected metatable
stack traceback:
	[C]: in global 'setmetatable'
	protegida.lua:4: in main chunk
	[C]: in ?
não mexa
O getmetatable devolveu o texto guardado em __metatable, escondendo a tabela regras. Poderia ser qualquer valor: um texto de aviso, false…
cannot change a protected metatable
"Não é possível mudar uma metatabela protegida". O setmetatable da linha 4 foi recusado.
[C]: in global 'setmetatable'
A primeira linha do rastro mostra que o erro saiu de dentro da função setmetatable (que é escrita em C, por isso o [C]), chamada na linha 4 do arquivo.

É o que o próprio Lua faz com os textos? Não: com os textos, getmetatable("abc") devolve a tabela de verdade, como você viu na seção 6. O __metatable é para as suas bibliotecas.

Experimente: rode e veja o que cada print mostra. Depois apague a linha do __metatable e rode de novo: o que muda no primeiro print? E o setmetatable da última linha ainda dá erro?

local regras = {
  __metatable = "protegida",
}
local cofre = setmetatable({ moedas = 10 }, regras)
print(getmetatable(cofre))
print(getmetatable(cofre) == regras)
print(cofre.moedas)
setmetatable(cofre, {})
print("trocou o manual!")

Formas diferentes de fazer a mesma coisa

A mesma metatabela com __add pode ser montada de três jeitos:

-- 1) campo por campo, depois de criar a tabela vazia
local regras = {}
regras.__add = function (a, b) return { total = a.total + b.total } end

-- 2) tudo dentro das chaves
local regras = {
  __add = function (a, b) return { total = a.total + b.total } end,
}

-- 3) uma função com nome, guardada depois
local function somar_cestas(a, b)
  return { total = a.total + b.total }
end
local regras = { __add = somar_cestas }

E para ligar o manual às tabelas:

SituaçãoQual usar
Uma tabela só, já criadasetmetatable(t, regras)
Criar e ligar de uma vezlocal t = setmetatable({ … }, regras)
Muitas tabelas do mesmo tipoUma função "fábrica" (nova_cesta) que faz o setmetatable por você: é o começo das classes
Metatabela com poucas funções curtasTudo dentro das chaves (forma 2)
Funções longas, ou usadas também fora do manualFunções com nome (forma 3)

Quando dá errado

Escreveu o __add, mas esqueceu o setmetatable 
local regras = {}
regras.__add = function (a, b)
  return { total = a.total + b.total }
end

local cesta_ana = { total = 30 }
local cesta_bia = { total = 12 }

local juntas = cesta_ana + cesta_bia
print(juntas.total)

$ lua esqueceu.lua
lua: esqueceu.lua:9: attempt to perform arithmetic on a table value (local 'cesta_ana')
stack traceback:
	esqueceu.lua:9: in main chunk
	[C]: in ?

A mesma mensagem da seção 1. Ter uma tabela chamada regras com um __add não basta: o Lua não adivinha que ela é o manual das cestas. Sem setmetatable, as cestas continuam sem metatabela. Como consertar: local cesta_ana = setmetatable({ total = 30 }, regras) (e o mesmo para a outra), ou use uma função fábrica como a nova_cesta.

Esqueceu os dois sublinhados 
local regras = {}
regras.add = function (a, b)
  return { total = a.total + b.total }
end
local c1 = setmetatable({ total = 30 }, regras)
local c2 = setmetatable({ total = 12 }, regras)
print((c1 + c2).total)

$ lua semsublinhado.lua
lua: semsublinhado.lua:7: attempt to perform arithmetic on a table value (local 'c1')
stack traceback:
	semsublinhado.lua:7: in main chunk
	[C]: in ?

Agora o setmetatable está lá, mas o campo se chama add, e o Lua só procura __add, com dois sublinhados (_ _). Um nome errado num metamétodo não dá erro nenhum na hora de escrever: o campo vira um campo comum da metatabela, que o Lua ignora. O erro só aparece quando a conta é feita. Como consertar: regras.__add. Os nomes certos de todos os metamétodos estão em Referência: Metamétodos.

Tentou dar metatabela a um texto 
local nome = "Ana"
setmetatable(nome, {})

$ lua texto.lua
lua: texto.lua:2: bad argument #1 to 'setmetatable' (table expected, got string)
stack traceback:
	[C]: in global 'setmetatable'
	texto.lua:2: in main chunk
	[C]: in ?

"Argumento ruim nº 1 para setmetatable (era esperada uma tabela, veio uma string)". O primeiro argumento (o #1) tem de ser uma tabela. Com um número, a mensagem seria a mesma, com got number. Como consertar: guarde o texto dentro de uma tabela ({ nome = "Ana" }) e dê a metatabela à tabela.

Trocou a ordem ou passou algo que não é tabela como manual 
local c = {}
setmetatable(c, "regras")

$ lua semtabela.lua
lua: semtabela.lua:2: bad argument #2 to 'setmetatable' (nil or table expected, got string)
stack traceback:
	[C]: in global 'setmetatable'
	semtabela.lua:2: in main chunk
	[C]: in ?

"Argumento ruim nº 2: era esperado nil ou uma tabela, veio uma string". O segundo argumento é o manual, e só pode ser uma tabela (ou nil, para tirar a metatabela). Aqui as aspas transformaram o nome da variável num texto. Como consertar: setmetatable(c, regras), sem aspas.

Tentou trocar uma metatabela protegida

Se a metatabela tem o campo __metatable, o setmetatable dá cannot change a protected metatable ("não é possível mudar uma metatabela protegida"), como na seção 7. Não é defeito: quem escreveu a biblioteca quis que aquele manual não fosse trocado. Use a tabela como ela veio.

Missão final: a cesta que soma de novo

Missão: o Dia sai certo, mas a Semana dá erro: a cesta que o __add devolve foi criada com { } puro e não tem manual, então não sabe somar de novo. Troque o return do __add para ele devolver uma cesta criada com nova_cesta. A semana deve dar 210.

local regras = {}

local function nova_cesta(total)
  return setmetatable({ total = total }, regras)
end

regras.__add = function (a, b)
  return { total = a.total + b.total }
end

local manha = nova_cesta(30)
local tarde = nova_cesta(12)
local dia = manha + tarde
print("Dia: " .. dia.total)
local semana = dia + dia + dia + dia + dia
print("Semana: " .. semana.total)

local regras = {}

local function nova_cesta(total)
  return setmetatable({ total = total }, regras)
end

regras.__add = function (a, b)
  return nova_cesta(a.total + b.total)
end

local manha = nova_cesta(30)
local tarde = nova_cesta(12)
local dia = manha + tarde
print("Dia: " .. dia.total)
local semana = dia + dia + dia + dia + dia
print("Semana: " .. semana.total)

No lab, o código inicial mostrou Dia: 42 e depois attempt to perform arithmetic on a table value (local 'dia'), na linha 15. Com o conserto, saiu Dia: 42 e Semana: 210. Repare na ordem do programa: a regras nasce vazia, a nova_cesta vem depois, e só então o __add é guardado. Assim, cada um pode usar o outro.

Curiosidade: por que c1 + c2 + c3 funcionava?

Com o __add antigo (que devolve { } puro), c1 + c2 + c3 deu 50 no lab, sem erro. O Lua faz (c1 + c2) + c3: o lado esquerdo não tem manual, mas o direito (c3) tem, e basta um. Já juntas + juntas falhou, porque nenhum dos dois lados tinha. Devolver tabelas com o manual ligado evita essa surpresa.

Resumo

  • Uma metatabela é uma tabela comum que funciona como o manual de instruções de outra tabela: diz ao Lua o que fazer em situações que ele não sabe resolver sozinho.
  • Cada instrução é um metamétodo: uma função num campo de nome especial, que começa com dois sublinhados (__add, __index, __tostring…). Quem chama é o Lua, na hora certa.
  • setmetatable(t, mt) liga o manual e devolve t; getmetatable(t) consulta; setmetatable(t, nil) tira.
  • Sem __add, somar tabelas dá attempt to perform arithmetic on a table value. Com ele, o + chama a sua função com os dois lados.
  • O normal é uma metatabela para muitas tabelas, com uma função fábrica que já liga o manual.
  • Só tabelas recebem metatabela pelo setmetatable; os textos já vêm com uma, do próprio Lua. O campo __metatable protege o manual contra trocas.
