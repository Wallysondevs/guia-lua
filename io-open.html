Lua io.open

Tudo o que um programa guarda em variáveis some quando ele termina. A lista de compras que a Ana digitou, as notas da turma, o estoque da lojinha: fechou o programa, acabou. Para os dados sobreviverem, eles vão para um arquivo no disco, como o compras.txt que você abre no editor de texto. No Lua, todo trabalho com arquivo começa pela mesma função: io.open (de input/output, "entrada/saída", e open, "abrir").

Você vai aprender
  • A ideia de abrir, usar e fechar um arquivo, e o primeiro programa que lê um arquivo inteiro.
  • O que o io.open devolve quando dá certo (um arquivo aberto) e quando dá errado (nil, a mensagem e um código).
  • As mensagens reais de arquivo que não existe, de arquivo sem permissão e de pasta errada.
  • Duas formas de tratar o erro: com if not f then e com assert.
  • Os modos: "r" (ler), "w" (escrever do zero), "a" (acrescentar), o + e o b.
  • Por que fechar com f:close(), e o que acontece quando você usa um arquivo já fechado.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela (/home/ana) e executados com lua arquivo.lua (veja Rodando um Programa). O arquivo que eles abrem, compras.txt, fica na mesma pasta.

A ideia: o caderno na gaveta

A Ana guarda a lista de compras num caderno, dentro de uma gaveta. Para usar o caderno ela sempre faz a mesma coisa:

  1. Abre a gaveta e pega o caderno, já decidindo para quê: para ler a lista, para começar uma lista nova numa folha em branco, ou para acrescentar um item no fim.
  2. Usa o caderno: lê ou escreve.
  3. Fecha o caderno e devolve à gaveta, para ninguém tropeçar nele nem borrar a tinta.

Às vezes o primeiro passo falha: o caderno não está na gaveta, ou a gaveta está trancada. Uma pessoa sensata percebe isso e não tenta ler um caderno que não está na mão dela.

Um programa faz exatamente isso com um arquivo:

Ler ou escreverf:read(…) e f:write(…) (aulas Lendo Arquivos e Escrevendo Arquivos)
Fechar o cadernof:close()

1. O primeiro programa: ler um arquivo inteiro

Primeiro, a Ana criou o arquivo de texto compras.txt na pasta dela, com três linhas (pode ser no editor de texto; aqui foi pelo terminal):

$ printf 'pão\nleite\ncafé\n' > compras.txt
$ cat compras.txt
pão
leite
café

Agora o programa que abre esse arquivo, lê tudo o que tem dentro e mostra na tela:

local f = io.open("compras.txt", "r")
local conteudo = f:read("a")
f:close()
print("O que está no arquivo:")
io.write(conteudo)
io.open
A função que abre arquivos. Ela mora na biblioteca io (a de entrada e saída, a mesma do io.write e do io.read).
"compras.txt"
O nome do arquivo, entre aspas, porque é um texto. Sem pasta na frente, o Lua procura na pasta em que você está no terminal (aqui, /home/ana).
"r"
O modo: para que você quer o arquivo. "r" vem de read, "ler". A seção 5 mostra os outros modos.
local f = …
O que o io.open devolve é o arquivo aberto, guardado numa variável. O nome f (de file, "arquivo") é o mais comum; arquivo também serve.
f:read("a")
Lê o arquivo. O "a" (de all, "tudo") pede o conteúdo inteiro, de uma vez, num texto só. Os outros jeitos de ler estão na aula Lendo Arquivos.
f:close()
Fecha o arquivo. Depois desta linha, o f não serve mais para ler; o conteúdo já está guardado em conteudo.
io.write(conteudo)
Mostra o texto. Foi io.write, e não print, porque o arquivo já termina com uma quebra de linha; o print poria mais uma e sobraria uma linha em branco no fim.
$ lua ler_compras.lua
O que está no arquivo:
pão
leite
café
Os dois-pontos: f:read

Repare que é f:read(…) e f:close(), com dois-pontos, e não com ponto. A leitura é "do arquivo f": o dois-pontos entrega o próprio f para a função. Por enquanto, guarde a regra: função do arquivo aberto usa :. O porquê fica para a aula Métodos e o Dois-Pontos. Já o io.open é com ponto, porque ele é da biblioteca io, não de um arquivo.

2. O que o io.open devolve quando dá certo

Vale a pena olhar o que fica dentro do f. Este programa abre o arquivo, mostra o f com print e usa o io.type, que diz se um valor é um arquivo:

print(f)
print(io.type(f))
print(f:close())
print(io.type(f))

3. Quando o arquivo não existe: nil, mensagem e código

A Ana digitou o nome errado: compra.txt, sem o "s". Esse arquivo não existe. O io.open não para o programa com um erro; ele devolve três valores que explicam o que houve:

print(io.open("compra.txt", "r"))

$ lua nao_existe.lua
nil	compra.txt: No such file or directory	2

Para ver cada um com calma, guarde os três em variáveis (é uma atribuição múltipla; veja também Vários Retornos):

local f, mensagem, codigo = io.open("compra.txt", "r")
print("f:", f)
print("mensagem:", mensagem)
print("codigo:", codigo)

$ lua tres_valores.lua
f:	nil
mensagem:	compra.txt: No such file or directory
codigo:	2
f → nil
No lugar do arquivo veio nil, o "nada" do Lua (veja O Valor nil). É o aviso de que não abriu.
mensagem → compra.txt: No such file or directory
O nome que você pediu e o motivo, em inglês: "não existe tal arquivo ou pasta". Essa frase vem do próprio sistema operacional (o Linux), por isso é igual em qualquer programa que tente abrir um arquivo que não existe.
codigo → 2
O mesmo motivo, em forma de número. Cada problema tem o seu (o 2 é "não existe"). Quase sempre a mensagem basta; o número serve para um programa decidir o que fazer conforme o tipo de problema.

Se você ignorar o nil

Muita gente escreve o programa da seção 1 sem pensar que o arquivo pode faltar. Com o nome errado:

Linha por linha:

lua: ignorou.lua:2:
O erro aconteceu no arquivo ignorou.lua, na linha 2. Não na linha 1! O io.open da linha 1 funcionou do jeito dele: devolveu nil, sem reclamar.
attempt to index a nil value (local 'f')
"Tentativa de indexar um valor nil (a variável local f)". Indexar é pegar alguma coisa de dentro de um valor; o f:read tenta pegar o read de dentro do f. Mas o f é nil, e de dentro do nada não se tira nada.
stack traceback:
"Rastro da pilha": o caminho que o programa fez até o erro. Aqui é curto: ignorou.lua:2: in main chunk (na linha 2 do programa principal) e [C]: in ? (o próprio lua, que começou tudo). Detalhes em Lendo uma Mensagem de Erro.

O programa terminou com código de saída 1, o código de "deu erro".

A mensagem fala de nil e não de arquivo, o que confunde. Guarde a pista: attempt to index a nil value (local 'f') logo depois de um io.open quase sempre quer dizer "o arquivo não abriu". A seção 4 mostra como o programa pode avisar isso direito.

4. Tratando o erro: o programa avisa e continua

O jeito mais claro é testar o f logo depois do io.open. Se ele for nil, o programa mostra a mensagem e não tenta ler:

local nome = "compra.txt"
local f, mensagem = io.open(nome, "r")
if not f then
  print("Não consegui abrir o arquivo.")
  print("Motivo: " .. mensagem)
else
  io.write(f:read("a"))
  f:close()
end
print("O programa continua.")
local f, mensagem = io.open(…)
Guarda os dois primeiros valores que o io.open devolve. O terceiro (o código) foi descartado: quando há mais valores do que variáveis, os que sobram são jogados fora.
if not f then
"Se não houver f". O not nil dá true, então o bloco roda justamente quando o arquivo não abriu (veja and, or e not).
"Motivo: " .. mensagem
Junta o texto com a mensagem que o io.open deu. Mostrar o motivo de verdade ajuda muito quem usa o programa: "não existe" e "sem permissão" se consertam de jeitos diferentes.
else … f:close()
Só lê e fecha quando abriu. Dentro do else, o f com certeza é um arquivo.
$ lua tratando.lua
Não consegui abrir o arquivo.
Motivo: compra.txt: No such file or directory
O programa continua.

Nada de stack traceback: o programa percebeu o problema, explicou e seguiu até o fim. Com o nome certo (compras.txt), o mesmo programa mostra a lista:

$ sed -i 's/compra.txt/compras.txt/' tratando.lua
$ lua tratando.lua
pão
leite
café
O programa continua.

5. Os modos: ler, escrever do zero, acrescentar

O segundo argumento do io.open diz para que você quer o arquivo. São poucas letras, e cada uma muda muito o que acontece:

ModoVem dePara quêSe o arquivo não existeSe o arquivo já existe
"r"read, lerSó lerFalha: nil e No such file or directoryLê desde o começo; nada muda no arquivo
"w"write, escreverEscrever do zeroCria o arquivo vazioApaga tudo o que havia e começa vazio
"a"append, acrescentarEscrever no fimCria o arquivo vazioMantém o conteúdo; o que você escrever vai para o fim
"r+"ler + escreverLer e alterarFalha, como o "r"Mantém o conteúdo; lê e escreve a partir do começo
"w+"escrever + lerEscrever do zero e relerCriaApaga tudo, como o "w"
"a+"acrescentar + lerLer e acrescentarCriaLê de qualquer lugar; escreve sempre no fim

Sem o segundo argumento, o modo é "r": io.open("compras.txt") é o mesmo que io.open("compras.txt", "r").

O "w" e o "a" lado a lado

Este programa cria um recado com "w", depois acrescenta uma linha com "a" e, por fim, abre com "r" para mostrar o resultado. As linhas em branco no meio só separam as três partes:

local f = io.open("recado.txt", "w")
f:write("Comprar pão\n")
f:close()

f = io.open("recado.txt", "a")
f:write("Pagar a luz\n")
f:close()

f = io.open("recado.txt", "r")
io.write(f:read("a"))
f:close()

$ lua modos.lua
Comprar pão
Pagar a luz
$ cat recado.txt
Comprar pão
Pagar a luz

O f:write escreve no arquivo (os detalhes estão em Escrevendo Arquivos); o \n é a quebra de linha (veja Caracteres de Escape). Repare que a mesma variável f foi reaproveitada, sem local nas vezes seguintes: cada io.open põe nela um arquivo aberto novo.

O "w" apaga sem perguntar

Abrir com "w" um arquivo que já existe zera o arquivo na hora, antes mesmo de você escrever qualquer coisa. Este programa só abre e fecha:

local f = io.open("recado.txt", "w")
f:close()

$ lua apaga.lua
$ ls -l recado.txt
-rw-rw-r-- 1 ana ana 0 Oct 18 16:35 recado.txt

O 0 antes da data é o tamanho: 0 bytes. O recado sumiu. Não existe lixeira nem "desfazer". Quando a ideia é juntar mais coisas num arquivo que já tem dados (um diário, um registro de vendas), o modo certo é o "a".

O b: modo binário

Qualquer modo pode terminar com b (de binary, "binário"): "rb", "wb", "ab", "r+b". Ele diz "trate o arquivo como bytes puros, sem mexer nas quebras de linha". Serve para imagens, músicas, arquivos compactados.

  • No Linux e no macOS, "r" e "rb" fazem exatamente a mesma coisa: lá, ninguém mexe nas quebras de linha.
  • No Windows, o modo texto troca as quebras de linha do Windows (\r\n) por \n na leitura, e o contrário na escrita. Numa imagem, isso estragaria os bytes. Por isso, para arquivos que não são texto, use sempre "rb" e "wb": o programa funciona igual nos dois sistemas.

(O comportamento do Windows vem da biblioteca de C que o Lua usa por baixo; não foi rodado aqui, a máquina da Ana é Linux.)

Modo que não existe: "rw"

"Quero ler e escrever, então "rw"." Parece lógico, mas não é um modo válido:

local f = io.open("compras.txt", "rw")

$ lua modo_rw.lua
lua: modo_rw.lua:1: bad argument #2 to 'open' (invalid mode)
stack traceback:
	[C]: in field 'open'
	modo_rw.lua:1: in main chunk
	[C]: in ?

"Argumento ruim nº 2 para o open (modo inválido)". O argumento nº 2 é o modo. Desta vez o programa para (não é um nil educado), porque o erro é de quem escreveu o programa, não do arquivo. A linha [C]: in field 'open' mostra que o erro foi detectado dentro do io.open, que é escrito na linguagem C. Como consertar: para ler e escrever, "r+". O modo é sempre uma das letras r, w, a, talvez um + e talvez um b, nessa ordem.

6. Fechar o arquivo: f:close()

Quando o programa termina, o Lua fecha os arquivos que ficaram abertos. Então por que se preocupar? Porque, enquanto o programa roda, um arquivo aberto ainda está "na mão" dele:

  • O que você escreveu pode ainda não estar no disco. Para ser rápido, o Lua junta o que você manda escrever num pedaço da memória e só leva para o disco de vez em quando. O close garante que tudo chegou. Se o programa travar ou for interrompido antes, o fim do texto pode se perder.
  • Existe um limite de arquivos abertos ao mesmo tempo. Um programa que abre um arquivo por item numa lista grande, sem fechar, acaba esbarrando nele.
  • É um hábito de quem escreve programa direito: abriu, usou, fechou. Quem lê o seu código vê onde o arquivo começa e termina de ser usado.

Há duas escritas para fechar, que fazem a mesma coisa: f:close() (a mais comum) e io.close(f). As duas devolvem true quando fecham bem.

Usou o arquivo depois de fechar 
local f = io.open("compras.txt", "r")
f:close()
local conteudo = f:read("a")

$ lua fechado.lua
lua: fechado.lua:3: attempt to use a closed file
stack traceback:
	[C]: in method 'read'
	fechado.lua:3: in main chunk
	[C]: in ?

"Tentativa de usar um arquivo fechado", na linha 3. A linha [C]: in method 'read' diz que quem reclamou foi o read. Fechar duas vezes dá o mesmo erro, agora no close:

local f = io.open("compras.txt", "r")
print(io.close(f))
f:close()

$ lua fecha_duas.lua
true
lua: fecha_duas.lua:3: attempt to use a closed file
stack traceback:
	[C]: in method 'close'
	fecha_duas.lua:3: in main chunk
	[C]: in ?

Como consertar: leia tudo o que precisa antes do close (guardando numa variável, como o conteudo da seção 1), e feche uma vez só, no fim.

Fechamento automático: <close>

O Lua 5.4 e o 5.5 têm um jeito de o arquivo se fechar sozinho quando a variável deixa de existir: local f <close> = assert(io.open("compras.txt")). Ele é útil quando o programa pode sair por vários caminhos (um return no meio, um erro) e é fácil esquecer o close em algum deles. Isso tem aula própria: Fechamento Automático (<close>). Até lá, feche com f:close().

7. Caminhos: onde o Lua procura o arquivo

O nome que você passa para o io.open pode ter pastas:

NomeTipoOnde fica
"compras.txt"relativoNa pasta atual, aquela em que você estava no terminal ao rodar lua (não a pasta onde está o .lua!)
"Documentos/lista.txt"relativoDentro da pasta Documentos da pasta atual. No Linux, as pastas se separam com /
"/home/ana/compras.txt"absolutoComeça com /: o caminho completo, a partir da raiz do disco. Vale de qualquer pasta
local f = assert(io.open("/home/ana/compras.txt", "r"))
print(f:read("l"))
f:close()
local g = assert(io.open("Documentos/lista.txt", "w"))
g:write("teste\n")
g:close()
print(io.open("Documentos/lista.txt"))

$ lua caminho.lua
pão
file (0x55db9e6c3300)
$ ls Documentos
lista.txt

O f:read("l") lê só a primeira linha (pão). O "w" criou a lista.txt dentro de Documentos, porque a pasta já existia; e o último io.open conseguiu abri-la (devolveu um file (…), com outro endereço). Esse programa usou o assert, que é o assunto da próxima seção.

E no Windows?

No Windows, os caminhos usam \, que dentro de uma string do Lua precisa ser dobrada: "C:\\Users\\Ana\\compras.txt". A barra normal também costuma funcionar lá: "C:/Users/Ana/compras.txt". (Ilustrativo: não foi rodado num Windows.)

Formas diferentes de tratar o arquivo que não abriu

Você já viu o if not f then. A outra forma, muito usada, é embrulhar o io.open num assert ("garantir"):

local f = assert(io.open("compra.txt", "r"))
io.write(f:read("a"))
f:close()

$ lua com_assert.lua
lua: com_assert.lua:1: compra.txt: No such file or directory
stack traceback:
	[C]: in global 'assert'
	com_assert.lua:1: in main chunk
	[C]: in ?

O assert recebe os três valores do io.open. Se o primeiro for um arquivo, ele o devolve e tudo segue normal. Se for nil, ele para o programa usando o segundo valor (a mensagem) como mensagem de erro. Compare com o ignorou.lua: em vez do confuso attempt to index a nil value, a mensagem agora diz o problema de verdade, compra.txt: No such file or directory, e aponta a linha certa (a 1, a do io.open). O [C]: in global 'assert' mostra quem parou o programa. O assert tem aula própria: assert.

local f = assert(io.open(…))O programa para, com a mensagem certaQuando sem o arquivo não há o que fazer (um programa que só existe para ler aquele arquivo). É curto e a mensagem é boa

Sem modo, o io.open abriu para ler ("r"). O write não parou o programa: ele devolveu nil, a mensagem Bad file descriptor ("descritor de arquivo ruim", o jeito do Linux de dizer "este arquivo não foi aberto para isso"), o código 9 e, no Lua 5.5, um quarto valor: quantos bytes chegaram a ser escritos (0). O arquivo existe, mas o Lua diz que não

Você confere com o ls, o arquivo está lá, e mesmo assim sai No such file or directory. As causas mais comuns:

  • Você rodou o lua de outra pasta. O nome relativo é procurado na pasta atual do terminal, não na pasta do programa. Teste com o caminho completo ("/home/ana/compras.txt") ou entre na pasta com cd antes.
  • Maiúscula e minúscula: no Linux, Compras.txt e compras.txt são arquivos diferentes.
  • A extensão escondida: o arquivo se chama compras.txt.txt, ou só compras. O ls mostra o nome verdadeiro.
Esqueceu as aspas no nome 
local f = io.open(compras.txt, "r")

$ lua sem_aspas.lua
lua: sem_aspas.lua:1: attempt to index a nil value (global 'compras')
stack traceback:

Sem aspas, compras.txt não é um texto: o Lua lê como "o campo txt da variável compras". Não existe variável compras (ela vale nil), e de dentro do nil não se tira o txt. Como consertar: o nome do arquivo é sempre um texto: io.open("compras.txt", "r"), ou uma variável que guarda o texto (local nome = "compras.txt").

Resumo

  • Arquivo é como um caderno: abrir (io.open), usar (f:read, f:write), fechar (f:close()).
  • io.open(nome, modo) devolve o arquivo aberto, ou nil, a mensagem e o código quando não consegue: No such file or directory (2), Permission denied (13), Is a directory (21).
  • Sempre trate o nil: com if not f then (avisa e continua) ou com assert(io.open(…)) (para com a mensagem certa). Ignorar dá attempt to index a nil value (local 'f').
  • Modos: "r" lê (é o padrão), "w" apaga e escreve do zero, "a" acrescenta no fim; + permite ler e escrever; b é para arquivos que não são texto. "rw" não existe.
  • Feche todo arquivo que abrir, uma vez só, e não use o arquivo depois do close (attempt to use a closed file). O <close> fecha sozinho: aula Fechamento Automático.
  • Nome sem pasta = pasta atual do terminal. O io.open cria arquivos, mas não cria pastas.
