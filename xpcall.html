Lua xpcall e debug.traceback

O pcall segura o erro e devolve a mensagem, mas joga fora uma coisa preciosa: o stack traceback, o caminho que o programa fez até o erro. Quando a função protegida chama outras, que chamam outras, saber só "deu erro na linha 4" pode não bastar. O xpcall ("pcall estendido") resolve isso: ele aceita uma função tratadora, que o Lua chama no exato momento do erro, antes de desmontar a pilha. Com a tratadora certa, a debug.traceback, você captura o erro e o rastro.

Você vai aprender
  • Como usar xpcall(funcao, tratadora, args…) e o que ele devolve.
  • O atalho mais usado: xpcall(f, debug.traceback), que devolve a mensagem com o stack traceback.
  • Como escrever a sua própria tratadora: acrescentar texto, tratar tabelas, guardar um registro (log).
  • A debug.traceback sozinha: ver "onde estou" a qualquer momento, com mensagem e nível.
  • O que acontece quando a tratadora também dá erro (error in error handling).

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook) com lua arquivo.lua. Antes, leia pcall e Lendo uma Mensagem de Erro.

A ideia: a caixa-preta do avião

Quando um avião tem um problema, a investigação não quer saber só "onde ele pousou". Ela quer saber o caminho: a rota, a altitude, cada decisão do piloto. Por isso todo avião tem uma caixa-preta, que grava tudo no momento em que as coisas acontecem.

O pcall é a rede de proteção: o avião desce inteiro, mas ninguém sabe o caminho. O xpcall é a rede com uma caixa-preta: no instante do problema, antes de qualquer coisa ser desmontada, ele chama a sua função tratadora, que pode "gravar" o caminho (a pilha de chamadas) enquanto ele ainda existe.

1. pcall × xpcall: o rastro que some e o que fica

O boletim da escola, do jeito que você conheceu em Lendo uma Mensagem de Erro, com uma nota digitada como texto. Primeiro com pcall, depois com xpcall:

local function media(notas)
  local soma = 0
  for _, n in ipairs(notas) do
    soma = soma + n
  end
  return soma / #notas
end

local function boletim(aluno)
  return aluno.nome .. ": " .. media(aluno.notas)
end

print(pcall(boletim, { nome = "Bia", notas = {8, "dez"} }))
print()
print(xpcall(boletim, debug.traceback, { nome = "Bia", notas = {8, "dez"} }))

Três partes: a função a proteger (boletim), a tratadora (debug.traceback) e, depois, os argumentos da função (a tabela da Bia). Como no pcall, as funções vão sem parênteses.

Mesmo com o rastro inteiro na tela, o erro foi capturado: o programa terminou normalmente. Quem imprimiu o rastro foi o seu print, não o lua.

Com o pcall, você sabia que a soma da linha 4 falhou. Com o xpcall, sabe também que ela estava na media, chamada pelo boletim, chamado pela linha 15. É o mesmo rastro que o lua mostraria se o erro não fosse capturado; só que agora ele está numa variável, e o programa continua.

2. A sua própria tratadora

A tratadora é uma função comum, que recebe um argumento (o erro, como foi lançado) e devolve o que o xpcall vai entregar no lugar da mensagem. Ela só é chamada quando há erro:

local function arriscada()
  local t = nil
  return t.campo
end

local function tratador(msg)
  return "[ERRO CAPTURADO] " .. msg
end

local ok, r = xpcall(arriscada, tratador)
print(ok)
print(r)
print(xpcall(function () return "tudo certo", 42 end, tratador))

$ lua x2.lua
false
[ERRO CAPTURADO] x2.lua:3: attempt to index a nil value (local 't')
true	tudo certo	42
local function tratador(msg)
Recebe a mensagem do erro (x2.lua:3: attempt to index …).
return "[ERRO CAPTURADO] " .. msg
O que ela devolver vira o segundo valor do xpcall.
true tudo certo 42
Sem erro, a tratadora nem é chamada, e o xpcall se comporta igual ao pcall: true e todos os resultados da função.

Tratando erros em tabela

A tratadora recebe o erro como ele foi lançado, que pode ser uma tabela (veja error). Ela pode olhar o tipo e montar uma mensagem para cada caso:

local function tratador(e)
  if type(e) == "table" then
    return "Erro " .. e.codigo .. ": " .. e.mensagem
  end
  return "Erro inesperado: " .. tostring(e)
end

local function buscar(codigo)
  if codigo ~= 1 then
    error({ codigo = 404, mensagem = "produto não encontrado" })
  end
  return "pão francês"
end

print(xpcall(buscar, tratador, 1))
print(xpcall(buscar, tratador, 7))
print(xpcall(function () return 1 + nil end, tratador))

$ lua x4.lua
true	pão francês
false	Erro 404: produto não encontrado
false	Erro inesperado: x4.lua:17: attempt to perform arithmetic on a nil value

Os erros "previstos" (as tabelas, lançadas de propósito) viram mensagens bonitas. Os imprevistos (um engano de programação, como o 1 + nil) ficam marcados como "inesperado", com a mensagem original. O tostring(e) garante que a tratadora não quebre se o erro for um número ou nil.

Guardando um registro (log) com o rastro

Num programa de verdade, você não quer jogar um rastro enorme na cara de quem usa, mas quer guardá-lo para investigar depois. A tratadora pode fazer as duas coisas: guardar o rastro completo e devolver só a mensagem:

local log = {}
local function registrar(msg)
  local completo = debug.traceback(msg, 2)
  log[#log + 1] = completo
  return msg
end

for _, valor in ipairs({ 10, "x", 30 }) do
  local ok, r = xpcall(function () return valor * 2 end, registrar)
  print(valor, ok, r)
end
print("--- conteúdo do log ---")
for i, texto in ipairs(log) do
  print(i, texto)
end

$ lua x6.lua

30	true	60
--- conteúdo do log ---

O debug.traceback(msg, 2) monta o rastro começando no nível 2: o nível 1 seria a própria registrar, que não interessa. (A próxima seção explica os níveis.) Num programa maior, o log iria para um arquivo (veja Escrevendo Arquivos).

Por que não chamar o debug.traceback depois do pcall?

Porque aí é tarde: quando o pcall devolve o false, a pilha de chamadas da função que deu erro já foi desmontada. Um debug.traceback() nesse ponto mostra só onde você está agora (o main chunk), não onde o erro aconteceu. A tratadora do xpcall é o único lugar em que o caminho do erro ainda existe.

3. A debug.traceback sozinha: "onde estou?"

A debug.traceback não precisa de erro nenhum. Chamada em qualquer lugar, ela devolve um texto com o rastro daquele momento. É ótima para descobrir quem chamou uma função:

local function onde()
  print(debug.traceback())
end

local function caixa()
  onde()
end

caixa()
print("---")
print(debug.traceback("mensagem no topo"))
print("---")
print(debug.traceback("nível 2", 2))

4. Mais detalhes do xpcall

Argumentos depois da tratadora

print(xpcall(function (a, b) return a + b end, debug.traceback, 2, 3))

$ lua x7.lua
true	5

Tudo o que vem depois da tratadora vai para a função: aqui, a = 2 e b = 3.

No Lua 5.1, não

Os argumentos extras do xpcall só existem a partir do Lua 5.2. No lua5.1 do lab, o mesmo x7.lua ignorou o 2 e o 3, a função recebeu nil, e o resultado foi um erro:

$ lua5.1 x7.lua
false	x7.lua:1: attempt to perform arithmetic on local 'a' (a nil value)
stack traceback:
	x7.lua:1: in function <x7.lua:1>
	[C]: in function 'xpcall'
	x7.lua:1: in main chunk
	[C]: ?

O LuaJIT aceita os argumentos (deu true 5 no lab). Se o seu código precisa rodar no 5.1, use uma função anônima: xpcall(function () return somar(2, 3) end, debug.traceback). Mais em as diferenças entre versões.

A tratadora é obrigatória

local ok, msg = xpcall(function () error("ops") end)
print(ok, msg)

$ lua x9.lua
lua: x9.lua:1: bad argument #2 to 'xpcall' (function expected, got no value)
stack traceback:
	[C]: in global 'xpcall'
	x9.lua:1: in main chunk
	[C]: in ?

"Argumento ruim nº 2 para o xpcall (esperava uma função, não veio nada)". Sem a tratadora, o xpcall nem começa, e esse erro não é capturado. Se não precisa de tratadora, use pcall.

Quando dá errado

A tratadora também deu erro: error in error handling 
local function tratador(msg)
  return msg .. nada_aqui
end
print(xpcall(function () error("primeiro erro") end, tratador))

$ lua x5.lua
false	error in error handling

"Erro ao tratar o erro". A tratadora tentou juntar a mensagem com uma variável que não existe (nada_aqui é nil), e deu um segundo erro dentro dela. O Lua desiste e devolve essa frase genérica, e você perde as duas mensagens: nem o primeiro erro, nem o motivo do segundo aparecem. (O Lua 5.4 e o 5.1 do lab deram a mesma frase.) Como consertar: mantenha a tratadora bem simples e à prova de falhas: use tostring(msg) para juntar textos e teste-a sozinha antes.

Chamou debug.traceback depois do pcall

O rastro mostra só o main chunk, sem a função que deu erro. No lab, com local ok2, msg = pcall(f) (a f da linha 3 indexa um nil) e depois print(debug.traceback(msg)) na linha 5:

$ lua x10.lua
x10.lua:3: attempt to index a nil value (local 't')
stack traceback:
	x10.lua:5: in main chunk
	[C]: in ?

O rastro diz linha 5 (onde está o debug.traceback), e a f sumiu. É o aviso da seção 2: depois que o pcall volta, o caminho do erro já foi desmontado. Como consertar: passe a debug.traceback como tratadora de um xpcall.

Escreveu xpcall(f(), debug.traceback)

O mesmo engano do pcall(f(x)): com os parênteses, f() roda antes, fora da proteção, e o erro derruba o programa. Passe a função sem parênteses e os argumentos depois da tratadora: xpcall(f, debug.traceback, x).

Passou a mensagem errada para o debug.traceback

Na tratadora, se o erro for uma tabela, debug.traceback(e) não sabe juntar a tabela com o rastro e devolve a própria tabela, sem rastro nenhum. Para erros em tabela, monte o texto antes (debug.traceback("Erro " .. e.codigo, 2)) ou trate a tabela como na seção 2.

  end
  estoque[produto] = tem - qtd
  return estoque[produto]
end

  -- devolva "Problema: " seguido da mensagem
end

for _, pedido in ipairs({ {"pao", 2}, {"bolo", 1}, {"leite", 5} }) do
  local ok, r = pcall(vender, pedido[1], pedido[2])

Resumo

  • xpcall(f, tratadora, args…) funciona como o pcall, mas, em caso de erro, chama a tratadora antes de desmontar a pilha, e devolve false e o que ela devolveu.
  • xpcall(f, debug.traceback) é o atalho para capturar o erro com o stack traceback, sem parar o programa.
  • Uma tratadora sua recebe o erro (texto, tabela, número) e pode transformá-lo, guardá-lo num log ou ambos. Mantenha-a simples: se ela der erro, sobra só error in error handling.
  • debug.traceback() também funciona sozinha, para ver "onde estou"; aceita uma mensagem e um nível.
  • Os argumentos depois da tratadora existem desde o Lua 5.2 (o 5.1 os ignora; o LuaJIT aceita).
