Lua Sintaxe e Blocos (do … end)

Sintaxe é a gramática de uma linguagem: as regras de como escrever para ser entendido. A do Lua é pequena, e quase toda ela cabe numa ideia: um bloco de instruções começa com uma palavra (then, do, function…) e termina com end ("fim"). Nesta aula você vai ver como o Lua separa as instruções, como os blocos se abrem e se fecham, por que o recuo (a indentação) é para você e não para o Lua, e as mensagens de erro que aparecem quando um end falta ou sobra.

Você vai aprender
  • O que é uma instrução, e que o Lua não liga para quebras de linha nem para o ;.
  • O que é um bloco, e as palavras que o abrem (then, do, function, repeat) e o fecham (end, until).
  • Como cada end fecha o bloco aberto mais recente, nos blocos dentro de blocos.
  • Por que indentar com 2 espaços, se o Lua ignora o recuo.
  • Que maiúsculas e minúsculas são diferentes, e quais são as 23 palavras reservadas.
  • Os erros de sintaxe mais comuns, com as mensagens reais do Lua 5.5.

Esta aula usa o if ("se") e o for ("para") como exemplos de blocos, só o suficiente para mostrar a forma. Eles têm aulas próprias no Nível 1 (if … then e for Numérico). Todos os programas foram rodados no computador da Ana, na pasta ~/programas.

A ideia: parênteses de palavras

Na matemática, os parênteses agrupam: em 2 × (3 + 4), o ( abre um grupo e o ) fecha. Todo parêntese que abre precisa fechar, e o último que abriu é o primeiro que fecha.

No Lua, os blocos funcionam igual, só que com palavras. Um bloco é um grupo de instruções que andam juntas: "se a nota for boa, faça isto e isto"; "para cada dia, faça isto". Uma palavra abre o grupo e o end fecha:

1. Instruções

Uma instrução é uma ordem completa: "mostre isto" (print("oi")), "guarde isto" (local nota = 8). O jeito normal é escrever uma por linha. Mas, para o Lua, a quebra de linha não tem nada de especial: ele sabe onde uma instrução termina pela forma dela. Por isso, estas formas também funcionam:

print("um") print("dois"); print("três")
print ( "com espaços" )

$ lua mesmalinha.lua
um
dois
três
com espaços
print("um") print("dois")
Duas instruções na mesma linha, separadas só por um espaço. O Lua percebe que print("um") já está completo.
;
O ponto e vírgula é opcional: separa instruções, se você quiser. A comunidade Lua quase não usa.
print ( "com espaços" )
Espaços em volta dos parênteses não mudam nada. Dentro das aspas, sim: lá eles fazem parte do texto.

Poder não quer dizer dever: uma instrução por linha é muito mais fácil de ler, e é o que o guia faz. E lembre da aula O Modo Interativo: num arquivo, uma expressão sozinha (como 2 + 3) não é uma instrução, e dá erro.

2. Blocos: abrir e fechar

Veja um bloco de verdade. O boletim da Ana mostra duas mensagens só se a nota for 7 ou mais:

local nota = 8
if nota >= 7 then
  print("Aprovada!")
  print("Parabéns, Ana.")
end
print("Fim do boletim.")

$ lua blocos.lua
Aprovada!
Parabéns, Ana.
Fim do boletim.

"Se a nota for maior ou igual a 7". É a condição.
then
"Então". Abre o bloco: o que vem a seguir só acontece se a condição for verdadeira.
print("Aprovada!") / print("Parabéns, Ana.")
As duas instruções de dentro do bloco.

"Fim". Fecha o bloco. O que vem depois dele já não depende da nota.

Com nota 5 (o mesmo programa, trocando 8 por 5), o bloco inteiro é pulado, e só a linha de fora roda:

$ lua nota5.lua
Fim do boletim.

Um bloco de repetição tem a mesma forma, com do ("faça") no lugar de then:

for dia = 1, 3 do
  print("Dia " .. dia .. ": abrir a padaria")
end
print("Fim da semana curta.")

$ lua repeticao.lua
Dia 1: abrir a padaria
Dia 2: abrir a padaria
Dia 3: abrir a padaria
Fim da semana curta.

"Para dia de 1 a 3, faça… fim". O que está entre o do e o end se repete três vezes; o print de depois do end roda uma vez só.

O do … end sozinho é o bloco mais simples de todos: ele não repete nem decide nada, só agrupa. Serve para limitar onde uma variável local existe (aula Escopo e Blocos):

3. Blocos dentro de blocos

Um bloco pode ter outro bloco dentro (isso se chama aninhar, como as bonecas russas, uma dentro da outra). A Ana quer anunciar o bolo de fubá só no dia 2:

for dia = 1, 3 do
  print("Dia " .. dia)
  if dia == 2 then
    print("  hoje tem bolo de fubá")
  end
end
print("Pronto.")

$ lua aninhado.lua
Dia 1
Dia 2
  hoje tem bolo de fubá
Dia 3
Pronto.

A regra é a dos parênteses: cada end fecha o bloco aberto mais recente que ainda não foi fechado.

  • Linha 1: o do abre o bloco do for.
  • Linha 3: o then abre o bloco do if, dentro do for.
  • Linha 5: o primeiro end fecha o mais recente, o do if.
  • Linha 6: o segundo end fecha o que sobrou, o do for.

(O ==, com dois sinais de igual, é a pergunta "é igual a?": aula Comparações.) Repare também nos dois espaços dentro do texto " hoje tem bolo de fubá": esses estão dentro das aspas, então aparecem na tela.

4. A indentação: para você, não para o Lua

Indentar é recuar as linhas de dentro de um bloco, com espaços no começo. Nos exemplos acima, as linhas de dentro do if e do for têm 2 espaços; as de dentro do bloco de dentro, 4. Mas atenção: para o Lua, o recuo não significa nada. Quem diz onde o bloco acaba é o end. O mesmo boletim, escrito numa linha só, ou todo torto, roda igual:

local nota = 8 if nota >= 7 then print("Aprovada!") print("Parabéns, Ana.") end print("Fim do boletim.")

local nota = 8
if nota >= 7 then
print("Aprovada!")
      print("Parabéns, Ana.")
    end
  print("Fim do boletim.")

$ lua feio.lua
Aprovada!
Parabéns, Ana.
Fim do boletim.
$ lua torto.lua
Aprovada!
Parabéns, Ana.
Fim do boletim.

Os três arquivos (o bonito, o de uma linha e o torto) fazem exatamente a mesma coisa. Então por que indentar? Porque quem lê o programa é gente: você amanhã, ou outra pessoa. Com o recuo certo, dá para ver de longe o que está dentro de quê. No torto.lua, parece que o "Fim do boletim." está dentro de alguma coisa, e não está.

O recuo errado engana você, não o Lua

No Python, o recuo muda o programa; no Lua, não. Isso tem um lado ruim: se você esquecer um end e o recuo "parecer" certo, o seu olho acredita no recuo e o Lua acredita nos end. O cenário "Um end que fecha o bloco errado", em Quando dá errado, mostra isso acontecendo.

Quantos espaços?

O guia usa 2 espaços por nível, que é o mais comum em Lua. Você vai encontrar código com 3 ou 4 espaços, ou com a tecla Tab; tudo funciona, porque o Lua não liga. O importante é ser constante dentro de um mesmo programa. A aula Estilo de Código volta ao assunto. Configure o seu editor para a tecla Tab inserir 2 espaços.

OndeRecuo
Fora de qualquer bloconenhum
Dentro de um bloco2 espaços
Dentro de um bloco que está dentro de outro4 espaços
A linha do endo mesmo recuo da linha que abriu o bloco

Missão: o programa funciona, mas está todo sem recuo, difícil de ler. Indente: 2 espaços nas linhas de dentro do for (inclusive o if e o end dele) e 4 espaços na linha de dentro do if. A saída não muda; o testador confere o recuo do if e do print de dentro.

print("Dia " .. dia)
if dia == 3 then
print("  sábado: abre só de manhã")
end
end
print("Pronto.")

5. Maiúsculas e minúsculas são diferentes

Para o Lua, print, Print e PRINT são três nomes diferentes. O mesmo vale para as palavras da linguagem: if, then e end só existem em minúsculas. Veja o que acontece com um If maiúsculo:

local nota = 8
If nota >= 7 then
  print("Aprovada!")
end

$ lua s7.lua
lua: s7.lua:2: syntax error near 'nota'

Para o Lua, If não é a palavra "se": é um nome qualquer, como nota. E dois nomes lado a lado (If nota) não formam nenhuma instrução: "erro de sintaxe perto de nota". A mensagem não fala em If, então a pista é a linha: confira as maiúsculas na linha 2.

6. Palavras reservadas

Algumas palavras são da própria linguagem e não podem ser usadas como nomes de variáveis. No Lua 5.5, o manual lista 23:

andbreakdoelseelseifend
falseforfunctionglobal 5.5gotoif
inlocalnilnotorrepeat
returnthentrueuntilwhile

Todas em minúsculas, todas em inglês. Você não precisa decorar: ao longo do guia, cada uma ganha a sua aula, e a lista completa com o significado de cada uma está em Palavras Reservadas. Se você tentar usar uma delas como nome, o Lua reclama. A Ana quis guardar o horário de fechamento numa variável chamada end:

local end = 10

$ lua s9.lua
lua: s9.lua:1: <name> expected near 'end'

"Era esperado um <name> (um nome) perto de end". Depois de local, o Lua esperava o nome da variável, e end não pode ser nome. Use um nome em português, que nunca vai bater com uma palavra reservada: local fim = 10 funciona.

O caso do global 5.5

A palavra global é a novidade do Lua 5.5 (aula A Declaração global), e o manual avisa: "Do not use it as a regular name" ("não use como nome comum"). Por compatibilidade com programas antigos, o Lua 5.5.0 do Ubuntu (e o do editor do guia) ainda aceitaram local global = 1; o manual diz que essas opções de compatibilidade vão sumir no futuro. No 5.4 e nos anteriores, global era uma palavra comum. Simplesmente não use esse nome.

Formas diferentes de escrever o mesmo bloco

Os três jeitos abaixo fazem a mesma coisa. Todos funcionam; só um é o recomendado:

if nota >= 7 then
  print("Aprovada!")
end

if nota >= 7 then print("Aprovada!") end

if nota >= 7 then
    print("Aprovada!")
end

Quando dá errado

Quase todos os erros desta aula são de sintaxe: o Lua os encontra ao conferir o arquivo, antes de rodar, então nenhuma linha do programa roda e não aparece stack traceback (aula Rodando um Programa).

Faltou o end 
local nota = 8
if nota >= 7 then
  print("Aprovada!")
print("Fim do boletim.")

$ lua s1.lua
lua: s1.lua:5: 'end' expected (to close 'if' at line 2) near <eof>
s1.lua:5:
Onde o Lua percebeu: na linha 5, que nem existe no arquivo. É o fim do arquivo (o arquivo tem 4 linhas; depois da última quebra de linha, o Lua já está na 5).
'end' expected
"Era esperado um end".
(to close 'if' at line 2)
"Para fechar o if da linha 2". Esta é a pista boa: qual bloco ficou aberto, e em que linha ele começou.
near <eof>
"Perto do fim do arquivo" (end of file). O Lua chegou ao fim ainda esperando o end.

Como resolver: vá à linha que a mensagem indica (at line 2) e encontre onde o bloco devia terminar. Aqui, o end vai antes do print("Fim do boletim.").

Sobrou um end 
local nota = 8
if nota >= 7 then
  print("Aprovada!")
end
end
print("Fim do boletim.")

$ lua s2.lua
lua: s2.lua:5: <eof> expected near 'end'

O que aconteceu: "era esperado o fim do arquivo perto de end". O end da linha 4 fechou o if; depois disso, não havia mais nenhum bloco aberto, e o end da linha 5 não tinha o que fechar. Fora de qualquer bloco, um end só faria sentido se fosse o fim de tudo, e não é. Como resolver: apague o end que sobrou (o da linha 5).

Um end que fecha o bloco errado 
for dia = 1, 3 do
  print("Dia " .. dia)
  if dia == 2 then
    print("  hoje tem bolo de fubá")
end
print("Pronto.")

$ lua s11.lua
lua: s11.lua:7: 'end' expected (to close 'for' at line 1) near <eof>

O que aconteceu: a Ana recuou o end da linha 5 como se ele fechasse o for. Mas o Lua não olha o recuo: o end fecha o bloco aberto mais recente, que é o do if. O for ficou aberto até o fim: "era esperado um end para fechar o for da linha 1". Como resolver: conte os blocos: cada then e cada do precisam do seu end. Aqui são dois blocos, então são dois end, um em cada nível de recuo.

Esqueceu o then ou o do 
local nota = 8
if nota >= 7
  print("Aprovada!")
end

$ lua s3.lua
lua: s3.lua:3: 'then' expected near 'print'

for dia = 1, 3
  print(dia)
end

$ lua s4.lua
lua: s4.lua:2: 'do' expected near 'print'

O que aconteceu: depois da condição do if, o Lua precisa do then; depois do for, do do. Sem eles, ele dá de cara com o print da linha de baixo: "era esperado um then (ou do) perto de print". O erro de verdade está no fim da linha anterior à que a mensagem indica. Como resolver: if nota >= 7 then e for dia = 1, 3 do.

Chaves e dois-pontos de outras linguagens

Quem já viu um pouco de C, JavaScript ou Python costuma trazer o costume de lá:

local nota = 8
if nota >= 7 {
  print("Aprovada!")
}

$ lua s5.lua
lua: s5.lua:2: 'then' expected near '{'

local nota = 8
if nota >= 7:
  print("Aprovada!")

$ lua s6.lua
lua: s6.lua:2: 'then' expected near ':'

O que aconteceu: no Lua, as chaves { } não agrupam instruções (elas criam tabelas), e os dois-pontos não abrem bloco (eles têm outro trabalho, nos métodos). O Lua esperava o then e achou outra coisa. Como resolver: if nota >= 7 then … end.

END maiúsculo, endif e outros "fins" inventados 
local nota = 8
if nota >= 7 then
  print("Aprovada!")
END

$ lua s8.lua
lua: s8.lua:5: syntax error near <eof>

O que aconteceu: o único "fim" que o Lua conhece é end, em minúsculas. END (ou endif, fi, End) é só um nome qualquer, e o Lua ficou esperando o resto de uma instrução que começava com esse nome, até o arquivo acabar: "erro de sintaxe perto do fim do arquivo". Com endif no lugar de END, a mensagem foi a mesma. Como resolver: end, minúsculo, sempre.

Um = só na condição 
local nota = 8
if nota = 8 then
  print("Nota oito")
end

$ lua s10.lua
lua: s10.lua:2: 'then' expected near '='

O que aconteceu: um = sozinho é "guarde" (atribuição), e não "é igual?". Depois de if nota, o Lua esperava o then (ou uma comparação), e veio um =. Como resolver: para perguntar "é igual?", use dois: if nota == 8 then (aula Comparações).

Resumo

  • Sintaxe é a gramática da linguagem. Erros de sintaxe impedem o programa inteiro de rodar.
  • Uma instrução é uma ordem completa. O Lua não depende das quebras de linha nem do ;, mas o recomendado é uma instrução por linha.
  • Um bloco é um grupo de instruções: abre com then (no if), do (no for, no while e no do … end) ou com a function, e fecha com end. O repeat fecha com until.
  • Cada end fecha o bloco aberto mais recente, como os parênteses.
  • O recuo não muda nada para o Lua, mas é essencial para as pessoas: 2 espaços por nível, o end alinhado com a linha que abriu.
  • Maiúsculas e minúsculas são diferentes; as 23 palavras reservadas (if, end, local…) são minúsculas e não podem ser nomes.
  • As mensagens dizem qual bloco ficou aberto e onde: 'end' expected (to close 'if' at line 2). Um end a mais dá <eof> expected near 'end'.
  • Próximo passo: deixar recados para você mesmo dentro do código, em Comentários.
