Lua break

Os laços que você aprendeu (while, repeat e for) só param quando chega a hora deles: a condição muda, ou a contagem termina. Às vezes, porém, você descobre no meio do caminho que já pode parar: achou o que procurava, o estoque acabou, a pessoa digitou "sair". Para isso existe o break, que em inglês quer dizer "quebrar": ele interrompe o laço na hora e pula para a primeira linha depois dele.

Você vai aprender
  • Como o break funciona num for, num while e num repeat.
  • O uso mais comum: procurar e parar no primeiro que serve.
  • O while true do com break: o laço "infinito" com a saída no meio.
  • Como guardar o resultado antes de sair (a variável do for some depois do laço).
  • Que, com um laço dentro de outro, o break sai só do de dentro.
  • Os erros reais: o break fora de um laço e o continue, que o Lua não tem.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), com lua arquivo.lua. Você pode rodar cada um no editor do guia.

A ideia: procurar a chave na gaveta

A Ana perdeu a chave de casa e vai olhar as 10 gavetas da cômoda, uma por uma. Na gaveta 4, ela acha a chave. O que ela faz?

  1. Abre a gaveta 1: não está. Abre a 2: não está. Abre a 3: não está.
  2. Abre a 4: achou!
  3. Ela não abre as gavetas 5 a 10 "porque o plano era olhar as 10". Ela para ali e vai abrir a porta.

O plano tinha 10 voltas, mas um acontecimento no meio mudou tudo. O break é esse "achei, pode parar".

1. O primeiro break: parar no meio do for

for i = 1, 10 do
  print("olhando o " .. i)
  if i == 4 then
    print("achei o 4!")
    break
  end
end
print("depois do laço")
for i = 1, 10 do
Um laço planejado para 10 voltas.
if i == 4 then
A pergunta "é agora que eu paro?". O break quase sempre fica dentro de um if; sem ele, o laço pararia logo na primeira volta.
break
Sai do laço na hora: o resto desta volta e todas as voltas seguintes são abandonados. O break fica sozinho, sem parênteses nem valor.
end (do if) / end (do for)
O break sai do laço, e não do if: o programa pula para depois do end do for.
print("depois do laço")
A primeira linha depois do laço: é aqui que o programa continua.
$ lua procura.lua
olhando o 1
olhando o 2
olhando o 3
olhando o 4
achei o 4!
depois do laço

O laço iria até 10, mas parou no 4. Os números 5 a 10 nunca foram "olhados".

2. Procurar o primeiro que serve

O uso mais comum do break é a busca: percorrer uma sequência e parar no primeiro item que cumpre uma regra. Qual é o primeiro múltiplo de 7 a partir de 50?

local achado = nil
for n = 50, 100 do
  if n % 7 == 0 then
    achado = n
    break
  end
end
print("O primeiro múltiplo de 7 a partir de 50 é " .. achado)

$ lua multiplo.lua
O primeiro múltiplo de 7 a partir de 50 é 56
local achado = nil
Uma variável criada antes do laço, para guardar a resposta. Ela é necessária porque a variável n do for some depois do end (veja for Numérico).
n % 7 == 0
"O resto de n dividido por 7 é zero?", ou seja, n é múltiplo de 7.
achado = n e depois break
Primeiro guarda, depois sai. Na ordem contrária, o achado = n nunca rodaria: nada do bloco roda depois do break.

Sem o break, o laço continuaria até o 100, e o achado terminaria valendo o último múltiplo (98), e não o primeiro.

E se não achar?

Se nenhum número servir, o break nunca acontece e o achado continua nil. Procurando só de 50 a 55, o programa acima quebra:

$ lua multiplo2.lua
lua: multiplo2.lua:8: attempt to concatenate a nil value (local 'achado')
stack traceback:
        multiplo2.lua:8: in main chunk
        [C]: in ?

Por isso, depois de uma busca, sempre confira se achou:

local achado = nil
for n = 50, 55 do
  if n % 7 == 0 then
    achado = n
    break
  end
end
if achado then
  print("Achei: " .. achado)
else
  print("Nenhum múltiplo de 7 entre 50 e 55.")
end

$ lua semachar.lua
Nenhum múltiplo de 7 entre 50 e 55.

Missão: mude a busca para achar o primeiro múltiplo de 13 a partir de 100 (procure até 200). Ajuste também o texto da mensagem.

3. while true do com break

Na aula while, você viu que while true do é um laço que nunca para sozinho, porque a condição é sempre verdadeira. Com um break lá dentro, ele vira um laço com a saída no meio. Na padaria, a Ana atende até o pão acabar:

local estoque = 3
local clientes = 0
while true do
  clientes = clientes + 1
  print("Atendendo o cliente " .. clientes)
  estoque = estoque - 1
  if estoque == 0 then
    print("Acabou o pão!")
    break
  end
end
print("Clientes atendidos: " .. clientes)

$ lua estoque.lua
Atendendo o cliente 1
Atendendo o cliente 2
Atendendo o cliente 3
Acabou o pão!
Clientes atendidos: 3

A pergunta escrita uma vez só

O caixa da padaria (aula while) lia o primeiro preço antes do laço e os outros no fim do bloco: a pergunta aparecia duas vezes. Com while true e break, ela aparece uma vez, no começo de cada volta:

local total = 0
while true do
  io.write("Preço do item (0 para terminar): ")
  local preco = tonumber(io.read())
  if preco == 0 then
    break
  end
  total = total + preco
end
print(string.format("Total da compra: R$ %.2f", total))

$ lua caixa.lua
Preço do item (0 para terminar): 4.50
Preço do item (0 para terminar): 12.90
Preço do item (0 para terminar): 3.25
Preço do item (0 para terminar): 0
Total da compra: R$ 20.65

A ordem dentro do bloco é: ler, testar se é hora de sair, usar. Quando o preço é 0, o break sai antes do total = total + preco. E a local preco pode ficar dentro do laço, porque ninguém precisa dela depois.

Missão: este caixa esqueceu a saída. A caixa vai "digitar" 4.50, 12.90 e 0; depois disso a entrada acaba, o io.read() devolve nil e o programa quebra. Acrescente o if preco == 0 then break end no lugar certo (antes de somar), para aparecer Total da compra: R$ 17.40.

local total = 0
while true do
  io.write("Preço do item (0 para terminar): ")
  local preco = tonumber(io.read())
  total = total + preco
end
print(string.format("Total da compra: R$ %.2f", total))

  io.write("Preço do item (0 para terminar): ")
  local preco = tonumber(io.read())
  if preco == 0 then
    break
  end
  total = total + preco
end
print(string.format("Total da compra: R$ %.2f", total))

break no repeat

O break também funciona no repeat … until: é uma segunda saída, além da condição do until. Aqui ele protege contra a entrada que acaba sem a senha certa:

local tentativas = 0
repeat
  tentativas = tentativas + 1
  io.write("Senha: ")
  local resposta = io.read()
  if resposta == nil then
    print("(a entrada acabou)")
    break
  end
until resposta == "pao123"
print("Tentativas: " .. tentativas)

$ printf 'abc\n123\n' | lua repeatbreak.lua
Senha: Senha: Senha: (a entrada acabou)
Tentativas: 3

O printf mandou só abc e 123 para o programa (pelo "cano" |, que não aparece na tela; veja io.read()). Na terceira volta não havia mais nada para ler, o io.read() devolveu nil, e o break saiu. Sem ele, o laço pediria a senha para sempre.

4. Laço dentro de laço: o break sai só de um

Quando há um laço dentro de outro (aula Laços Aninhados), o break sai apenas do laço mais de dentro, aquele em que ele está:

for linha = 1, 3 do
  for coluna = 1, 3 do
    if coluna == 2 then
      break
    end
    print("linha " .. linha .. ", coluna " .. coluna)
  end
end

$ lua aninhado.lua
linha 1, coluna 1
linha 2, coluna 1
linha 3, coluna 1

Em cada linha, o laço das colunas parou na coluna 2. Mas o laço das linhas continuou: 1, 2 e 3. Para sair dos dois de uma vez, use uma variável de aviso (local terminou = false, e um segundo if terminou then break end no laço de fora) ou o goto (aula goto e Rótulos).

5. Depois do break, nada daquela volta roda

As linhas que vêm depois do break, no mesmo bloco, nunca rodam:

for i = 1, 3 do
  print("antes", i)
  break
  print("depois", i)
end

$ lua depoisbreak.lua
antes	1

Esse programa não serve para nada (o break sem if sai já na primeira volta), mas mostra a regra. No Lua 5.5, o 5.4 e o LuaJIT ele roda assim.

No Lua 5.1, o break tinha de ser a última linha do bloco

O mesmo arquivo no lua5.1 do lab:

$ lua5.1 depoisbreak.lua
lua5.1: depoisbreak.lua:4: 'end' expected (to close 'for' at line 1) near 'print'

No 5.1, nada podia vir depois do break no mesmo bloco. Na prática isso nunca atrapalha, porque o break fica dentro de um if, e logo depois dele vem o end. (Mais diferenças entre as versões em Lua 5.1, LuaJIT, 5.4 e 5.5.)

Formas diferentes de fazer a mesma coisa

Quase todo break pode ser trocado por uma condição no próprio laço. A busca do múltiplo de 7, sem break:

local n = 50
while n % 7 ~= 0 do
  n = n + 1
end
print("O primeiro múltiplo de 7 a partir de 50 é " .. n)

Funciona (e mostra 56), mas repare que agora você cuida do contador à mão, e não há limite: se nunca achasse, o laço nunca pararia. Com o for e o break, o limite (100) já está garantido.

Quando dá errado

break fora de um laço 
local nota = 8
if nota >= 6 then
  print("aprovada")
  break
end

$ lua fora.lua
lua: fora.lua:4: break outside loop near 'break'

"break fora de um laço, perto de break". O break só sai de laços (for, while, repeat); ele não sai de um if, nem do programa. O Lua recusa o arquivo antes de rodar: o aprovada nem apareceu. Como consertar: se a ideia era só não fazer o resto do if, use um else; se era encerrar o programa, isso é o os.exit() (aula os.getenv, os.clock e os.exit).

Usou continue 
for i = 1, 5 do
  if i == 3 then
    continue
  end
  print(i)
end

$ lua continue.lua
lua: continue.lua:4: syntax error near 'end'

Em muitas linguagens, continue quer dizer "pule o resto desta volta e vá para a próxima". O Lua não tem continue. Para ele, continue é um nome qualquer, como uma variável, e um nome sozinho numa linha não é um comando completo; quando chega o end, ele reclama. Como consertar: inverta o if para envolver o que deve rodar:

for i = 1, 5 do
  if i ~= 3 then
    print(i)
  end
end

Para blocos grandes, existe o goto continue, na aula goto e Rótulos. E repare: trocar o continue por break não serve, porque o break pararia o laço inteiro no 3.

Quis usar a variável do for depois do break 
for i = 1, 10 do
  if i * i > 30 then
    break
  end
end
print("parou em", i)

$ lua breakvar.lua
parou em	nil

Sem erro, mas nil: a variável i do for só existe dentro do laço. Como consertar: guarde o valor numa variável criada antes, antes do break, como o achado da seção 2. (Com while, o contador é criado antes do laço e continua lá: local i = 1 / while i <= 5 do if i == 3 then break end … end termina com i valendo 3.)

O break veio antes de guardar o valor

Se o bloco do if for break e depois achado = n, o achado nunca recebe nada: depois do break, nada daquela volta roda. Sem erro, só um nil (ou o erro de concatenar nil mais adiante). Como consertar: primeiro guarde, depois break.

Resumo

  • break ("quebrar") sai do laço na hora: o resto da volta e as voltas seguintes são abandonados, e o programa segue depois do end (ou do until).
  • Ele quase sempre fica dentro de um if: "se aconteceu tal coisa, pare".
  • Numa busca, guarde o resultado numa variável criada antes do laço e só depois dê o break; no fim, confira se achou.
  • while true do com break é o laço com a saída no meio: ler, testar, usar.
  • O break sai só do laço mais de dentro, e só de laços (fora deles: break outside loop).
  • O Lua não tem continue: use um if em volta do resto do bloco, ou o goto continue da próxima aula, goto e Rótulos.
