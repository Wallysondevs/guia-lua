Lua os.getenv, os.clock e os.exit

Um programa não vive sozinho: ele roda dentro do sistema, chamado por alguém, num terminal. Três funções da biblioteca os fazem a ponte com esse mundo de fora. O os.getenv pergunta ao sistema coisas como "qual é a pasta da usuária?". O os.clock é um cronômetro, para saber quanto o seu programa trabalhou. E o os.exit encerra o programa na hora, avisando a quem o chamou se deu certo ou errado.

Você vai aprender
  • O que são as variáveis de ambiente e como ler uma com os.getenv, com um valor padrão quando ela não existe.
  • Como mudar uma variável de ambiente só para um comando, ou para o terminal inteiro.
  • Como medir quanto tempo um cálculo leva com os.clock, e por que ele não conta o tempo em que o programa fica esperando.
  • Como encerrar o programa com os.exit e um código de saída, e como o terminal usa esse código (echo $?, &&, ||).
  • Como mandar mensagens de erro para o lugar certo, o io.stderr.
  • Os erros reais de cada uma.

Todos os programas desta aula rodaram no Lua 5.5 da máquina da Ana (usuária ana, computador notebook), em /home/ana.

A ideia: o crachá, o cronômetro e a porta de saída

Quando a Ana chega para trabalhar na padaria, três coisas acontecem: ela recebe um crachá com o nome dela, o setor e o idioma em que prefere ser atendida; um cronômetro marca quanto tempo ela passa de fato trabalhando (o cafezinho não conta); e, ao sair, ela deixa um bilhete no balcão: "tudo certo" ou "deu problema no forno".

  • O crachá são as variáveis de ambiente: informações que o sistema entrega a todo programa que começa. O os.getenv lê o crachá.
  • O cronômetro que não conta o cafezinho é o os.clock.
  • O bilhete na saída é o código de saída do os.exit.

1. os.getenv: lendo o ambiente

O os.getenv (de get environment, "pegar do ambiente") recebe o nome de uma variável de ambiente e devolve o valor dela, sempre como texto:

print(os.getenv("HOME"))
print(os.getenv("USER"))
print(os.getenv("LANG"))
print(os.getenv("NAO_EXISTE"))

O echo $HOME do terminal mostra a mesma coisa: é o próprio terminal que entrega essas variáveis ao lua quando o programa começa. Os nomes costumam ser em MAIÚSCULAS, e maiúscula importa: os.getenv("home") dá nil.

O PATH é uma lista de pastas separadas por :. O gmatch separa cada uma:

for pasta in caminho:gmatch("[^:]+") do
  print("  " .. pasta)
end

Um valor padrão para quando não existe

Uma variável que não existe dá nil. Com o or, o programa usa um valor padrão (veja O Truque do and/or). Assim, quem usa o programa pode configurar sem mexer no código:

local nome = os.getenv("NOME_DA_LOJA") or "Lojinha da Ana"
print("Bem-vindo à " .. nome .. "!")

$ NOME_DA_LOJA="Padaria do Zé" lua loja.lua

$ export NOME_DA_LOJA="Mercadinho da Bia"

O programa só lê o ambiente. O Lua puro não tem os.setenv: mudar o ambiente é coisa de quem chama o programa.

2. os.clock: o cronômetro do processador

O os.clock() devolve quantos segundos de processador o programa já usou, com casas decimais. Sozinho, o número não diz muito; o que importa é a diferença entre dois momentos. Quanto tempo leva somar os números de 1 a 10 milhões?

local inicio = os.clock()
local soma = 0
for i = 1, 10000000 do
  soma = soma + i
end
local gasto = os.clock() - inicio
print("Soma: " .. soma)
print(string.format("Levou %.3f segundos de processador.", gasto))

$ lua medir.lua
Soma: 50000005000000
Levou 0.053 segundos de processador.
$ lua medir.lua
Soma: 50000005000000
Levou 0.052 segundos de processador.
local inicio = os.clock()
Aperta o cronômetro: guarda o valor de antes.
os.clock() - inicio
O valor de depois menos o de antes: o tempo gasto no laço.
%.3f
Mostra com 3 casas decimais (milésimos de segundo).

Dez milhões de somas em uns 5 centésimos de segundo. Repare que as duas execuções deram tempos um pouco diferentes: o computador está sempre fazendo outras coisas ao mesmo tempo. Num computador mais lento ou mais rápido, e no editor do guia (que roda no navegador), os números serão outros. Para comparar duas formas de fazer a mesma coisa, rode cada uma algumas vezes.

O cafezinho não conta: os.clock × os.time

O os.clock só anda enquanto o programa está trabalhando. Enquanto ele espera você digitar, o cronômetro fica parado. Este programa mede a mesma espera com os dois relógios:

local clock0, time0 = os.clock(), os.time()
io.write("Espere uns segundos e aperte Enter... ")
io.read()
print(string.format("os.time: passaram %d segundos", os.difftime(os.time(), time0)))
print(string.format("os.clock: passaram %.4f segundos", os.clock() - clock0))

$ lua clock_parado.lua
Espere uns segundos e aperte Enter...
os.time: passaram 4 segundos
os.clock: passaram 0.0001 segundos

Pelo relógio da parede (os.time), passaram 4 segundos. Pelo cronômetro do processador (os.clock), um décimo de milésimo: o programa passou quase todo o tempo parado, esperando o Enter.

3. os.exit: sair na hora, com um código

Todo programa, ao terminar, devolve ao terminal um número: o código de saída. A convenção é: 0 = deu certo; qualquer outro número = deu algum problema. O terminal guarda esse número em $?, e o comando echo $? mostra o código do último programa. O os.exit(n) encerra o programa naquele ponto, com o código n:

print("Começando.")
os.exit(3)
print("Esta linha nunca aparece.")

$ lua sair.lua
Começando.
$ echo $?
3

O programa parou no os.exit; o último print nem rodou. E o código de saída foi 3.

Como o programa terminaCódigo de saída
Chegou ao fim normalmente0
os.exit() ou os.exit(true)0
os.exit(false)1
os.exit(n)n (use de 0 a 255)
Um erro não tratado (lua: … e o stack traceback)1

Cada linha da tabela foi conferida no lab (sair_padrao.lua com os.exit() deu 0; sair_bool.lua com os.exit(false) deu 1; um erro de conta com nil deu 1).

Para que serve: validar e avisar

Um programa que atualiza o estoque recebe a quantidade como argumento (o arg[1], assunto da aula Argumentos da Linha de Comando). Se a quantidade não prestar, não adianta continuar:

local quantidade = tonumber(arg[1])
if not quantidade or quantidade < 0 then
  io.stderr:write("Erro: quantidade inválida: ", tostring(arg[1]), "\n")
  os.exit(1)
end
print("Estoque atualizado: " .. quantidade .. " unidades.")
tonumber(arg[1])
O que foi digitado depois do nome do programa, convertido em número. Se não for um número, dá nil.
io.stderr:write(…)
Escreve na saída de erros (standard error), um segundo canal da tela, só para mensagens de problema. No terminal, aparece igual a um print; a diferença é que, quando alguém manda a saída do programa para um arquivo (lua estoque.lua 5 > log.txt), as mensagens de erro continuam aparecendo na tela, em vez de sumir dentro do arquivo. É lá que o próprio lua escreve os erros dele.
os.exit(1)
Encerra com o código 1: "deu errado".
$ lua estoque.lua 12
Estoque atualizado: 12 unidades.
$ echo $?
0
$ lua estoque.lua -5
Erro: quantidade inválida: -5
$ echo $?
1

Quem usa o código: o && e o ||

Para uma pessoa olhando a tela, a mensagem basta. O código de saída é para outros programas: scripts que rodam vários comandos em sequência, agendadores, ferramentas de teste. No terminal, && roda o próximo comando só se o anterior deu 0, e || só se não deu:

$ lua estoque.lua doze && echo "deu certo" || echo "deu errado"
Erro: quantidade inválida: doze
deu errado
$ lua estoque.lua 7 && echo "deu certo" || echo "deu errado"
Estoque atualizado: 7 unidades.
deu certo

O terminal não leu a frase "Erro"; ele olhou só o número. Por isso um programa que falha deve sair com um código diferente de 0: sem isso, quem o chama acha que deu tudo certo.

Missão: o programa percebe que a quantidade é negativa, avisa, mas continua e termina com código 0, como se tudo estivesse certo. Faça ele sair com o código 2 logo depois do aviso. (A caixa mostra o código de saída no fim.)

local quantidade = -3
if quantidade < 0 then
  io.stderr:write("Quantidade inválida: ", quantidade, "\n")
end
print("Estoque atualizado: " .. quantidade .. " unidades.")

local quantidade = -3
if quantidade < 0 then
  io.stderr:write("Quantidade inválida: ", quantidade, "\n")
  os.exit(2)
end
print("Estoque atualizado: " .. quantidade .. " unidades.")
os.exit(código, true)

O os.exit aceita um segundo argumento. Com true, antes de sair o Lua fecha o estado: roda os fechamentos automáticos (<close>) e os finalizadores (__gc, de Coleta de Lixo). Sem ele, o programa sai direto. Os arquivos abertos têm o que você escreveu levado para o disco nos dois casos (quem faz isso é a biblioteca de C por baixo do Lua), mas o costume de fechar com f:close() antes continua valendo.

Formas diferentes de parar

O os.exit não é o único jeito de "parar". Cada um para uma coisa diferente:

EscritaPara o quêCódigo de saídaQuando usar
return (dentro de uma função)Só a função; o programa continua—A função já fez o que tinha de fazer
breakSó o laço—Achou o que procurava
error("mensagem")O programa, a não ser que alguém capture com pcall1, com lua: … e tracebackAlgo que não devia acontecer (veja error)

Um return dentro de uma função não encerra o programa:

local function verificar(n)
  if n < 0 then
    return
  end
  print("ok: " .. n)
end
verificar(-1)
print("o programa continua depois do return")

$ lua exit_return.lua
o programa continua depois do return
Cuidado com os.exit no meio do código

O os.exit encerra tudo, sem chance de ninguém reagir. Numa função que outro programa vai usar (um módulo, veja Criando seu Módulo), prefira devolver nil e uma mensagem, ou lançar um error: quem usa a função decide se para ou não. Deixe o os.exit para o programa principal.

Quando dá errado

Esqueceu as aspas no nome da variável 
print(os.getenv(HOME))

$ lua sem_aspas.lua
lua: sem_aspas.lua:1: bad argument #1 to 'getenv' (string expected, got nil)
stack traceback:
	[C]: in field 'getenv'
	sem_aspas.lua:1: in main chunk
	[C]: in ?

"Argumento ruim nº 1 para o getenv (esperava uma string, veio nil)". Sem aspas, HOME é uma variável do Lua, que não existe (vale nil). O nome da variável de ambiente é um texto: os.getenv("HOME").

A variável não existe e o programa usa assim mesmo 
print("Olá, " .. os.getenv("NOME"))

$ lua concat_nil.lua
lua: concat_nil.lua:1: attempt to concatenate a nil value
stack traceback:
	concat_nil.lua:1: in main chunk
	[C]: in ?

Não há NOME no ambiente da Ana, o os.getenv devolveu nil, e o .. não junta texto com nil. Funciona no computador de quem criou a variável e quebra no dos outros. Como consertar: sempre um padrão: os.getenv("NOME") or "visitante".

Um texto no os.exit 
os.exit("erro")

$ lua exit_texto.lua
lua: exit_texto.lua:1: bad argument #1 to 'exit' (number expected, got string)
stack traceback:
	[C]: in field 'exit'
	exit_texto.lua:1: in main chunk
	[C]: in ?
$ echo $?
1

"Esperava um número, veio uma string". O os.exit aceita um número, true ou false; a mensagem vai antes, com io.stderr:write. Ironia: o programa saiu com código 1 do mesmo jeito, mas por causa do erro, não do os.exit.

Medir a espera com os.clock

A Ana quis saber quanto tempo a pessoa demorou para responder uma pergunta e usou os.clock. Deu 0.0001 segundo, por mais que a pessoa demorasse (veja a seção 2). Não é erro do Lua: o os.clock só mede o trabalho do processador. Como consertar: para tempo de relógio, os.time() e os.difftime.

Missão final: o programa que se recusa a trabalhar sem configuração

Missão: este programa só funciona com a variável de ambiente ARQUIVO_DE_VENDAS, que diz onde estão as vendas. Sem ela, em vez de quebrar mais adiante com um erro confuso, ele deve avisar Falta a variável ARQUIVO_DE_VENDAS (em io.stderr) e sair com o código 1. Complete o if.

local arquivo = os.getenv("ARQUIVO_DE_VENDAS")
if not arquivo then
  -- avise e saia aqui
end
for linha in io.lines(arquivo) do
  print(linha)
end

local arquivo = os.getenv("ARQUIVO_DE_VENDAS")
if not arquivo then
  io.stderr:write("Falta a variável ARQUIVO_DE_VENDAS\n")
  os.exit(1)
end
for linha in io.lines(arquivo) do
  print(linha)
end

Rode o código inicial primeiro: sem a variável, o io.lines(nil) passa a ler o teclado (veja io.lines) e fica esperando, um comportamento bem mais confuso que uma mensagem clara.

Resumo

  • os.getenv("NOME") lê uma variável de ambiente (HOME, USER, LANG, PATH…) como texto, ou nil. Use sempre com um padrão: os.getenv("X") or "padrão".
  • No terminal, NOME=valor lua prog.lua cria a variável para um comando; export, para o terminal todo.
  • os.clock() é o cronômetro do processador: meça com os.clock() - inicio. Ele não conta a espera; para tempo de relógio, os.time().
  • os.exit(n) encerra o programa na hora com o código n: 0 = certo, outro número = problema (os.exit(false) = 1). O terminal vê o código em $?, && e ||.
  • Mensagens de erro vão para io.stderr:write(…). Erros não tratados já saem com código 1.
